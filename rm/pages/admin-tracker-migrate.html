Activity Ledger → Tracker Migration

What this does

One-shot migration of your userData/{uid}/activityLedger rows into trackerEntries/{uid}/entries (the lab-apps activity tracker). After this, the tracker becomes the single source of truth for daily activity.

Mapping summary: RM categories → lab-apps tree per the table reviewed in chat. Skipped: noise and personal top-level categories. Uncategorized: rows with category=unknown.

Idempotency: each migrated source row is stamped with migrated_to_tracker_id. Re-running this page skips rows that already have that field, so it's safe to retry after a partial run.

1Survey ledger

Reads your activityLedger from Firestore. Counts what would migrate, skip, or land uncategorized. No writes.

2Dry run (no writes)

Applies the mapping to every row and shows you the first 25 translated entries plus the per-target-category distribution. Inspect before committing.

3Migrate for real

Writes one tracker entry per source row, then stamps the source row. Already-stamped rows are skipped.

4Remap previously imported entries

Re-derives both date and categoryPath on every trackerEntries doc with source == 'rm-imported'. Pulls the live source ledger row by original.ledger_id so we can reach year/month/notes; if the source row isn't found, falls back to whatever was preserved under original at first migration. Date precedence: "evidence dated YYYY-MM-DD" in notes → year+month-15 → completed_at (last resort). Categories use the current RM-vocabulary mapping. Idempotent: skips entries already matching.
