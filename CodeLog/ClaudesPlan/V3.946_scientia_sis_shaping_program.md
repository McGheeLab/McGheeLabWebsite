## 1. Decisions already made (Gabe, 2026-11-03)

- The editor bar's Equation button embeds an equation component in the text component (not a separate box).
- The Portfolio layout is synced and remembers where you put things.
- Tidy is rebuilt around links: minimal crossings, close to the origin, far enough apart to read the arrow and its
  label, packed to fit the highest zoom. Folding a component or region reflows what is below (and to the right) by the
  amount folded; unfolding pushes it back.
- /commands start with the proposed set; Settings lets you make your own and bind them to anything that can be
  quick-cast.
- A slim navigation bar at the bottom: grey and nearly invisible, not interactable until clicked or `/` is pressed on
  the canvas (no component focused). It carries a comprehensive command set for the whole notebook (§3.4).
- A Claude Code skill writes macros (a set of actions behind one `/command`) for that bar, importable in Settings, with
  its own macro file format.
- Component kinds: double-click the kind label left of the title to change it; a component with no kind chosen is
  "standard". Kinds are superposed with structures (a Hypothesis component stemming from an Observation structure).
- An Atlas tab: the notebook's terms, structures, kinds and notes and how they link, interactive, modern, with a lens
  (a project, the whole notebook, a set of experiments). Atlas search lives there and is the default search (Ctrl+K).
- Pen button: pressing it enters Pen; pressing it again in Pen goes to the "other" mode (what a double tap on ✎ does).
- Edge pan: the harder you push into the edge, the faster it moves; it should feel natural.

## 2. Phase A — one floating bar, and the text editor bar (V3.946)

### Goal
While a text component is being edited, a bar sits just above its top border with the editing tools; it never gets wider
than the component (it wraps), every button is the same size, and it is the same bar the lasso selection and the
Ctrl+Enter strip use.

### Approach
- **`08b-bar.js` `FBAR`**: one floating bar component: `FBAR.make({anchor, items, max})` → a `.fbar` with `.fbar-b`
  buttons (28 × 28, icon + title), groups separated by a hairline, wraps to new rows within `max` width, an overflow
  ⋯ when a row budget is set. Positioned by `FBAR.place(bar, rect, {above: true})`: above the anchor, or below when
  there is no room. Keyboard: the bar never takes focus from the editor (mousedown preventDefault, as the strip does).
  - The lasso's `.ink-selbar` (13zf, 13zu, 13zv, 13zz2, 13zz3) and the Ctrl+Enter strip (09 `openStrip`) are
    rebuilt on it. Their behaviour is unchanged; the look is one.
- **The text editor bar** (`13zzf-editbar.js` `EBAR`), shown when a text component's editor has the caret
  (`ED.mount` focus → `EBAR.show(el, b)`; blur or Esc → hide after 150 ms unless the pointer is on the bar):
  - **Always:** Bold, Italic, Underline (the `fmt` marks, `WRITE.style`), Bulleted list, Numbered list, Checkbox list
    (apply `WRITE`'s list syntax to the current line or every selected line; toggle off if already that list),
    Make it… (opens the Ctrl+Enter strip for the selection), ∑ Symbols, and the dotted **+** at the end.
  - **Behind +** (each a toggle, saved in `settings().editorBar.extra`): Link to a note (`ED.linkPicker`), Citation
    (`ED.citePicker`), Term (`ED.markTerm`), Equation, Strikethrough (a new `fmt` style `s`), Existing structure
    (`ED.mentionPicker`).
  - **Equation** opens the equation editor (13h) and places the result in the text as an embedded equation component:
    the inline atom (`MATH`) now carries `eqId` → an `equations` record (13n), so it has terms, can be registered,
    wired and solved like any Equation component, while living inside the text.
  - **Symbols (∑):** a popover with tabs: Favourites (first, when any), Greek (α–ω, Α–Ω), Math (± × ÷ ≈ ≠ ≤ ≥ ∞ ∑ ∏ ∫
    ∂ ∇ √ ∝ ∈ ∉ ⊂ ∪ ∩ → ⇒ ⇔ ∀ ∃ …), Scientific (° °C °F µ Å ‰ ℃ ℓ ħ ⁰¹²³ subscripts ₀₁₂ ½ ¼), Arrows, Typography
    (— – … “ ” ‘ ’ § ¶ †). A ☆ on each symbol adds it to Favourites; a ⚡ on a favourite quick-casts it: it becomes its
    own button in the bar, before +. Favourites and quick-cast symbols are in `settings().editorBar.symFav` /
    `.symQuick` (synced with the notebook, like the pills' layout).
  - The buttons that need a selection (styles, Make it…, Link, Term, Citation on a selection) light up when there is
    one and still work with none (styles then set the typing style, `WRITE.typeStyle`).
  - The bar belongs to the pane: it is placed in paper coordinates above the box and moves with pan and zoom (it is
    drawn in the host at screen scale, repositioned on `Paper.apply`).
- Settings → Writing gains "Editor bar": which optional buttons are on, the symbol favourites in order.

## 3. Phase B — commands: in the text, in the navigation bar, as macros, and the skill (V3.947)

### 3.1 One command registry
- **`11b-commands.js` `CMD`**: `CMD.add({id, slash, label, args, scope, run, icon})`. `args` is a list of
  `{name, kind}` with kinds `note | project | component | structure | term | paper | protocol | material | text |
  number | choice:[…]`, each with its own completer. `scope` is `text` (runs in an editor at the caret), `canvas`
  (runs on the note/pane) or `both`. `CMD.run(id, args, ctx)` with `ctx = {pane, doc, el, block, sel}`.
- Every `INSERTS` row registers itself (`/insert <row>` and a friendly alias from its id: `/paper`, `/protocol`,
  `/material`, `/task`, `/plate`, `/run`, `/figure`, `/table`, `/pdf`, `/html`, `/equation`, `/reminder`, …).

### 3.2 In the text: `/` and `@`
- Typing `/` at a word start opens the command menu at the caret (`ED.slashMenu`, replacing the special case
  `slashCite`): rows filter as you type; Enter runs; the typed `/word` is removed (as `/cite` does today).
- The starting set (Gabe: "start with those"): `/cite`, `/link` (note), `/term`, `/claim` `/evidence` `/barrier`
  `/resolution` `/result` `/takeaway` `/decision` `/question` `/idea` `/deviation` `/observation` `/reminder`
  (mark the selection, or the current sentence, as that structure), `/sym` (the symbol popover), `/connect` (wire this
  component to one you pick, relation asked), `/date` (today, or a date you type), `/time`, and every insert alias.
- `@Name`: `@` opens the lab's member list (hub `api/rm/members`, cached in `settings().members` for offline; on a
  notebook with no lab, the people named in the notebook's profiles). Picking one writes a `mention` mark
  `{type: 'person', uid, name}` drawn as a chip; the note's panel lists "People mentioned". No notification (that would
  be a hub change; noted for Alex in §10).

### 3.3 Custom commands (Settings → Commands)
- A table: slash, label, what it does: an insert row (anything quick-castable), a built-in command with preset
  arguments, or a macro. Saved in `settings().commands` (synced). Conflicts with built-ins are refused with the reason.
- Import / Export: macro files (`.sis-macro.json`, §3.5) and a whole command set (`.sis-commands.json`).

### 3.4 The navigation bar

  result ("Opened Day 3 Nov"). It wakes (full opacity, focused input) on a click, or on `/` pressed in a note with no

### 3.5 Macros
- A macro is one `/slash` that runs steps in order. File format `.sis-macro.json`:
  ```json
  { "format": "sis-macro/1", "name": "Start a gel run", "slash": "gelrun",
    "params": [{ "name": "title", "ask": "Title of the run", "default": "Gel run {date}" }],
    "steps": [
      { "cmd": "new", "args": { "type": "experiment", "title": "{title}" } },
      { "cmd": "insert", "args": { "row": "rmprotocol", "pick": "Gel casting" } },
      { "cmd": "timer", "args": { "action": "start" } },
      { "cmd": "flag", "when": "{ask: Flag it for the weekly review?}" } ] }
  ```
  - `{param}` substitution, `{date}` `{time}` `{note}` `{project}` built in; `pick` prefilters a picker and waits for
    the choice; `when` with `{ask: …}` asks yes/no; a failing step stops the macro and says which.
  - Stored in `settings().macros` (synced); listed under `/macros`; editable in Settings → Commands.
- `scripts/scientia_macro.py check <file>` validates a macro file against the registry (it reads the command ids and
  arguments from `scientia/src/11b-commands.js` and the insert ids from `scientia/src`), and `… list` prints the
  vocabulary.

### 3.6 The skill
- `.claude/skills/scientia-macro/SKILL.md`: when Gabe asks for a macro ("make me a /command that…"), the skill:
  1. runs `python scripts/scientia_macro.py list` for the current vocabulary (never from memory);
  2. writes `<name>.sis-macro.json` in the notebook folder's `macros/` (the app lists that folder in Settings →
     Commands → Import, besides a file picker);
  3. runs `check`, fixes what it reports;
  4. says how to import it (Settings → Commands → Import, or `/macro import <file>`), and what the macro does step by
     step.
  - The skill carries the format above, the rules (a macro never deletes without `{ask}`; a `pick` for anything named
    that may not exist; one macro per file), and three worked examples (a run, a meeting note, a reading session).
- The skill is written in this phase, with the feature, so its vocabulary is real.

## 4. Phase C — layout: Tidy by links, dynamic reflow, the Portfolio remembered (V3.948)

### 4.1 Tidy, rebuilt (`12d-layout.js` `LAYOUT`)
- Tidy becomes a link-aware layout; the old flow stays as "Flow in order" (`/tidy flow`), and ordered note types
  (protocols) keep their order.
- The algorithm, on the note's live components, regions and wires:
  1. **Groups:** connected components of the wire graph (mentions and pull-ins count as weak edges). Unconnected
     components form the "loose" group.
  2. **Origin and layers:** in each group the origin is the earliest component among those with the most outgoing
     directed relations (`follows`, `leads`, `causes`, `resolves`, `supports`, `contradicts`, `needs`). Layers by
     longest path from the origin (undirected relations don't add depth). Cycles are broken at the latest edge.
  3. **Order within a layer:** the barycenter heuristic, four sweeps down and up, to minimise crossings.
  4. **Spacing:** horizontal gap ≥ 56 px + the widest relation label between neighbours (labels are drawn on the
     wire, 12b); vertical gap ≥ 42 px; a wire's two ends never closer than 90 px so the arrowhead and label are
     legible.
  5. **Regions:** a region is laid out as a group of its own (its members inside), then placed as one block; folded
     regions are their header.
  6. **Packing:** groups packed into the smallest bounding box (shelf packing by height, widest first; the loose group
     fills the remaining right-hand column), so Fit gives the highest zoom.
  7. Positions snap to the 14 px grid; the move is animated (`.box` transition 240 ms, then removed) and is one undo
     step.
- Runs on the main thread (a 300-component note lays out in well under a frame's budget per sweep; the sweeps are
  bounded) — a Worker is not needed.

### 4.2 Dynamic reflow on fold and unfold
- When a component folds (▾, `b.collapsed`) or a region folds (`REGION.toggle`), the box shrinks by `dh` (and `dw`
  for a region). Every box whose top is below the folded box's bottom and that overlaps it horizontally moves up by
  `dh`; every box to its right that overlaps it vertically moves left by `dw`. Each moved box records
  `b.shift = [{by, dx, dy}, …]` (several openings stack).
- Unfolding pushes them back by the same amounts, in reverse order; a box the user moved meanwhile has its shift
  cleared and is left alone. Shifts are kept in the block (synced), so a note folded on one computer looks the same on
  another.
- Nothing moves when the fold leaves no overlap; nothing moves in a read-only note; ink is never moved.

### 4.3 The Portfolio remembered and synced
- The Portfolio's positions and folds live in `_ls lab:portfolio` (lab-mode §10, per device). The app mirrors that key
  into `settings().portfolio` (synced): a wrapper around `_ls.set` for that key writes both, and on load (and on every
  sync that changes settings) `settings().portfolio` is written into `_ls` before the Portfolio renders. No lab-layer
  edit; one line in §10 would make it direct (noted for Alex).
- The Portfolio's "Tidy up" uses the new layout's packing for the region cards.

### Files
- `scientia/src/12d-layout.js` (new), `12-doc.js` (tidy → LAYOUT; the menu rows), `13v-region.js` (fold hooks),
  `12c-reflow.js` (new), `23d-desktoplab.js` / `13zc-sync.js` (the Portfolio mirror), `20-canvas.css`.

### Done when
- On a note with wired chains, Tidy lays each chain from its origin with readable labels, no crossings where the

- Folding a tall component brings what is below up by its height; unfolding pushes it back; moving one in between

## 5. Phase D — hands, pen, pan and zoom (V3.949)

- **Pen settings follow the hand** (`13zf` + a `SIS_LAB.setHand` wrapper in the app): choosing Pen or Highlighter
  opens the ink bar; choosing Move, Zoom or Lasso closes it. The bar is drawn as the second ring of the ✎ pill's
  expanded form when the pill is expanded (my #2): the palette, widths, eraser, fill and pressure sit around the fan,
  so settings are where the hand is; the top-left bar remains for a docked pill.
- **P = Move** (`11-shell` keymap): in a note with no text focus, `P` switches the hand to Move. (Other hands have
  `/pen` `/hl` `/lasso` in the bar.)
- **Edge hover-pan** (`10-paper.js` `Paper.hoverPan`): in Move mode, with a mouse or a hovering pen (not touch), the
  paper pans when the pointer is within 48 px of the window edge. Speed = 2 + 22 · e² px per frame, where
  e = how far into the zone (0 at the zone's inner edge, 1 at the window edge) — slow to start, fast when pushed, with
  an ease-in over the first 150 ms so a passing pointer doesn't jerk the note. It stops when the pointer leaves the
  window, a drag starts, a popover is open, or the pointer is over a pill, the bar or the reader.
- **Zoom:** notes' `minZ` 0.01 (the zoom pill's "out" steps reach it; the % reads "1%"). Boxes below 10 % draw as
  flat tiles without text (performance, my #9's first half). Switching to Pen or Highlighter zooms to 200 % at the
  pointer (or the centre) when the zoom is under 200 %; leaving Pen returns to 100 % only if that switch changed it
  (`LP.zoomBeforePen`).
- **The Slim Pen's button** (desktop): the tail button is a Windows setting that the browser never sees. The install
  gains `pen-button\ScientiaPen.exe` (compiled at install time from a 20-line C# file with the `csc.exe` every
  Windows ships, so nothing is downloaded) that calls `http://localhost:8766/api/pen-button`. `serve.py` passes it to
  the app (`/api/news`), and the app: not in Pen → Pen; in Pen → the other mode (`lastHand`, what a double tap on ✎
  does). Settings → Pen shows the steps (Windows Settings → Bluetooth & devices → Pen → Pen shortcut button → Launch a
  classic app → ScientiaPen.exe) and a "Test" that lights up when the press arrives. `MANUAL.md` documents it.
- **Esc, one stack** (my #11): `UI.escStack` — every openable thing pushes itself (popover, strip, bar awake, picker,
  maximised view, reader full screen, lasso selection); Esc pops the top one. Modules register instead of each
  listening for Escape.

## 10. Phase I — working together: presence and locks (design, app side, and the parts that are Alex's)

### What the note asks
Two people in one note; icons of who is on the project or note (filled when active, grey after 5 minutes away);
one person at a time in a component; the other's icon colour shaded on the component they are editing.

### The design
- **Presence:** each open note sends a heartbeat every 20 s to the hub: `{docId, uid, name, colour, blockId (the one
  being edited or selected), at}`; the hub keeps `presence/{docId}/{uid}` with a 60 s TTL and answers each heartbeat
  with everyone else's. Away (> 5 min since the person's last input) is sent as `away: true`.
- **Locks:** a component is locked by the person editing it (caret in it, or moving/resizing it): `lock/{blockId} =
  {uid, at}`, TTL 60 s, refreshed with the heartbeat, released on blur or close. The hub refuses a lock held by another;
  the app then shows the component read-only with "Alex is editing" and that person's colour at 12 % over the box,
  and offers "Ask to take over" (a message to the other). Making a new component, or editing another, needs no lock
  from anyone else.
- **Edits in the same component:** with the lock there is one writer at a time; the merge the lab's bridge already
  does (`Bridge.unite`, V3.932) covers edits that crossed in the gap.
- **App side (this program):** `SIS_PRESENCE` in `13zc-sync.js`: the header's avatar row (filled / grey), the box
  shading and read-only state, the lock request/release calls, the heartbeat; all behind
  `window.SIS_LAB && SIS_LAB.presence` so the app runs without it.
- **The lab's parts (for Alex):** the hub routes (`/api/presence`, `/api/lock`), the Firestore docs with TTL, and
  `cloud-sync.js` carrying the heartbeat and answering the app's calls; the desktop goes through `serve.py`'s
  `/api/rm/*` proxy as everything else does.

### Lit Reviews shared to everyone (for Alex)
RM: a lit review (`userData/{uid}/litReviews/{id}`) gets `visibility: 'lab'` by default and `collaborator_uids`
chosen by its creator; the rules let lab members read, the creator and collaborators write; the hub's `collections`
answers list everyone's. Scientia's collection card then offers every lab member's reviews. Scientia changes nothing
until that lands.

### @Name notifications (for Alex)
A hub route that turns a `person` mention into a My Week feed item for that member.

### The Note pill (for Alex, small)
Lab-mode §11 gains `LAB.registerPill(def)` (≈ 15 lines: a fifth entry in `PILLS` and `pillItems` from the def).
Pull in and Flag leave the Quick cast. The app then registers the ▤ Note pill with: Note references (every note this
note references, as a quick list), Pull in…, Collection from the Lab Notebook…, Flag, Atlas search (`/find`).
