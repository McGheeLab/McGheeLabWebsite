# V3.470 — Grant unification R8: creation-flow hand-off + type dedupe

> Eighth release. New grants are now born in the unified Paper editor; the old
> grant-builder page becomes a legacy-drafts list. Plus the `paper_type` validation
> dedupe.

## Creation hand-off

- **`rm/js/grant-builder.js`** — the "+ New grant" button (and the `?new=1` deep-link)
  now redirect to `/rm/pages/paper-builder.html?new=1&type=grant` instead of opening the
  old `grantDrafts` create modal. Existing `grantDrafts` still render in the list and
  still open in this page's editor mode (`grant-editor.js`) — unchanged. The legacy
  `openModal`/`createGrant` flow is left intact but unwired (harmless fallback).
- **`rm/pages/grant-builder.html`** — a `.gb-legacy-note` banner explains that new
  grants are authored in the unified Paper editor and the drafts below are earlier
  grant-writer drafts.
- **`rm/js/paper-builder.js`** — the `?new=1` handler now also reads `?type=` and, when
  present + valid, preselects the document-type dropdown and repopulates the template +
  mechanism selects (so the hand-off lands on the grant templates immediately).

## `paper_type` dedupe

The `['grant','editorial','book-chapter']` validation array (4 inline copies) is
replaced by a single source of truth in **`rm/js/paper-schemas.js`**:
`PAPER_TYPES = ['journal','grant','editorial','book-chapter']` + `normalizePaperType(v)`
(→ the value if known, else `'journal'`). Consumers updated:
`paper-export.js` (`_loadConfig` type resolution + `_bindPaperType` change handler) and
`paper-doc-view.js` (config load). Behavior is identical to the old inline arrays.
