# V3.888 — A literature review built as a Scientia note (prototype + first review)

**Date:** 2026-10-23 · **Status:** built and checked locally; publishing to the lab library and Alex's Scientia hub is
two commands for Alex (the unattended session was not allowed to write to production).

## Goal

Alex: investigate whether somewhere along RAS–RAF–MEK–ERK (or EGFR→ERK) the cytoskeleton breaks down (faster
retrograde flow from less G-actin, weaker integrin binding, Arp2/3 held back by capping protein), so that neighbours
held by junctions are stretched, release EGF into the junction, and relay the pulse — and what the cells' apparent
velocity would look like. Build it as a Scientia note overview with the papers' PDFs on the canvas, quotes and
connections, readable by a person; and formalize the method for later.

## Approach

1. Deep-research workflow on the hypothesis split into links H1a–d / H2 / H3, asked to test (support AND contradict).
2. Citations resolved in Europe PMC; open PDFs from PMC's AWS open data, OpenAlex locations, bioRxiv, arXiv (28 of 35).
3. The review written as a spec (`spec-src.js`: cards, columns → findings → papers, verbatim quotes with what each
   supports); quotes located on their PDF pages (65/65).
4. `build-note.js` turns the spec into Gabe's own records and pushes them through his sync protocol — to a local
   `serve.py` notebook for checking, then (Alex) to his hub. Layout measured in the real app, re-laid out, checked:
   0 overlaps, every box at its spec position, no wire across a PDF.

## Key decisions

- **Scientia, not the RM canvas notebook:** the unification (V3.866) made Scientia where notes live; its `pdf`
  component and quote component already do "PDF in the canvas + quote highlighted on the page".
- **Papers into RM's library** (the one library; the hub mirrors it into Scientia), tagged `litreview:<slug>` with an
  undo manifest; DOI-dedupe reused the 2 papers the lab already had.
- **Gabe's protocol, not a new import path:** records go through `FirestoreHub.push` like any device; deterministic ids
  and a fixed creation time make a re-run an update.
- **No sw.js bump:** nothing under the site changed.
