# V3.290 — Email triage usability pass

Four hands-on follow-ups to the V3.289 rules pre-filter. All four came from
actually using the email tab after V3.288/V3.289 shipped.

## Goal

Make the day-to-day triage loop fast and honest:
1. Sorting an `unknown` email should be **one click, inline** — no expand.
2. A manual scrape should be able to **reach back far enough** to recover
   mail missed during a sync gap.
3. Unsorted mail should be **visually obvious** while scanning.
4. The ✨ disposition button should **work** (it was 404-ing in prod).

## Approach

### 1. Inline one-click quick-sort (issue #1)
- `category-rules.js`: extract the scoring core of `guess()` into a shared
  `scoreEmail(email)`; add `rank(email)` → confidence-sorted
  `[{category, score, confidence}]`. Definite-noise collapses to one `noise`
  candidate; no-rule-match returns `[]`.
- `email-review.js`: `renderQuickCategorize(e)` builds an always-open
  "Sort into:" pill bar appended under every uncategorized row (sibling of the
  `.ch-line`, so it doesn't trip the row's click-to-expand). Ranked candidates
  first (best marked ★ + colored), then the remaining real categories as
  lighter pills, then a "more…" link that opens the full picker.
- One click → `quickSetCategory(e, category)`: sets a **category-only** manual
  override (sub-category stays empty — expand for that + task linking), writes
  `category_overrides`, `refresh()`. The row leaves the unknown state.

### 2. "Days back" backfill (issue #2)
- HTML: `#email-scrape-days` number input (default 7, max 3650) beside
  **Scrape now**.
- Client: `_readScrapeDays()` (clamped int or null). `onScrapeEmailsNow` reads
  it for **manual clicks only** (`quiet ? null : _readScrapeDays()`) and sends
  `days` in the POST body; the background poll stays incremental.
- Server (`scrape-now.js`): `scrapeGmail(db, uid, days)` — when `days` set,
  query `newer_than:${days}d` (ignore `lastSyncEpoch`) and list up to 2000 ids
  via new paginated `listMessageIds()` (follows `nextPageToken`); incremental
  stays one 200-id page. Handler clamps `req.body.days` to 1–3650 and **skips
  the 60-s rate limit** for a gmail backfill (deliberate catch-up, not thrash).

### 3. Uncategorized flag (issue #3)
- `renderEmailEntry`: `uncategorized = !hasRealCategory(e.category)` →
  red inset left tab (`box-shadow: inset 3px 0 0 #dc2626`, no layout shift) +
  a small red dot before the category cell.

### 4. ✨ disposition button (issue #4)
- The button called `/api/refine-disposition`, which lives only on the local
  Python dev server → 404 in production + an `alert()`. Replaced the fetch with
  `guessDisposition(e)`: a local heuristic (category + subject regex signals)
  returning actionable / reminder / info. Instant, offline, no API key. Stored
  as a `source:'rule'` suggestion that highlights the matching chip; clicking
  the chip confirms. Tooltips say "Suggested (rule)" for rule-sourced hints.

## Key decisions
- **Quick-sort writes category only.** Keeps the inline action to a single
  click; sub-category + task linking stay in the full picker (the "more…"
  link). Same `category_overrides` store the future LLM learns from.
- **Backfill is manual-only and bypasses the rate limit.** The 10-min poll
  must stay cheap/incremental; a deliberate "go back N days" is the user's
  call and shouldn't be silently swallowed by a poll that ran 30 s ago.
- **✨ stays rule-based, not removed.** The user wants guesses; a working
  offline heuristic beats a dead button and matches the rules-only direction.
  The Haiku few-shot disposition refiner remains the deferred next step.
