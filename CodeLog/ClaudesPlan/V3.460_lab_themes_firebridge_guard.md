# V3.460 — Lab Themes always showed "Not signed in"

## Goal

Fix the Lab Themes tab (`rm/pages/library.html?tab=themes`) prompting
signed-in lab members to sign in, every time, for every user.

## Root cause

`rm/js/library-themes.js` gated boot and every identity lookup on
`window.firebridge`, same mistake as the already-fixed V3.392 citation
bug: `firebridge` is `const firebridge = (function(){…})()` in
`rm/js/firebase-bridge.js:4` — a lexical global, reachable by bare name,
**never** assigned to `window`. `window.firebridge` is therefore
permanently `undefined`, so:

- `_start()` (line 755) computed `member` from `window.firebridge && …` →
  always falsy → always hit `if (!member)`, showed the `#lt-auth-hint`
  "Not signed in" banner, and returned before loading anything —
  regardless of actual auth state.
- The `DOMContentLoaded` boot listener's `window.firebridge && firebridge
  .onAuth` check (line 803) was also always false, so it silently fell
  back to raw `firebase.auth().onAuthStateChanged` instead of
  `firebridge.onAuth` (harmless here since both call `_maybeBoot`, but
  the same dead branch).
- `_me()` (line 75) and `_isAdmin()` (line 82) silently lost the
  firebridge profile/admin lookups, degrading `_canEditTheme` for every
  theme note.

This is the same class of bug tracked in memory
`project-window-firebridge-deadchecks` and documented as a pending
follow-up in `V3.392_citation_family_firebridge_guard.md` — confirmed via
`grep -rn "window\.firebridge =" ` returning zero hits repo-wide.

## Fix

`rm/js/library-themes.js` — all five `window.firebridge` guards (lines
75, 82, 755, 798, 803) now test the bare lexical binding
(`typeof firebridge !== 'undefined' && firebridge.X`), matching the
already-fixed `paper-cite-style.js` template and the bare `firebridge.db()`
calls this same file already makes elsewhere. No other logic changed.

## Verification

Reload `mcgheelab.com/rm/pages/library.html?tab=themes` (or `?tab=themes`
equivalent) while signed in as a lab member: the "Not signed in" banner
should not appear, themes should load immediately. Sign out and confirm
the banner still correctly appears for a genuinely signed-out session (a
`firebase.auth().currentUser` of `null`), so the fix didn't just invert
the bug.
