# V3.310 — Reference-driven citation localization + DOI full refresh + audit harness

> Source: `CodeLog/Feature requests/FuturePlan_01_library_paper_reader.md` Release 3
> (moved into production 2026-07-11).

## Goal

The paper reader's citation panel becomes trustworthy: inline markers are
located by searching for each *known* reference's expected forms (not blind
token scanning), a new "All refs (N)" tab means the panel is never empty when
references exist, failures explain themselves with one-click fixes, and a
stored-library audit harness measures coverage across every paper so the
detector is tuned against real styles. Plus `fullRefresh` — one action that
re-pulls metadata, tries an OA PDF, and re-enriches references.

## Problem

- `_scanPage` runs six style scanners blindly on every page, then
  reverse-maps tokens to refs. Wrong-style noise surfaces as bogus rows
  ("(Boltzmann 1877)" prose, enumerations), and unmatched tokens render as
  "No matching reference parsed" clutter.
- **Numbering drift (found in review):** stored Semantic Scholar refs get
  `n = array index + 1`, but `normalizeReference` DROPS entries with no
  title/DOI — so stored numbering shifts vs the paper's printed numbering
  and `[12]` maps to the wrong reference. This alone explains much of
  "citations are often incorrect in the left sidebar".
- Panel is page-scoped only: nothing on this page → empty panel even with
  60 stored refs. Failures are silent.
- No refresh path: fixing a DOI (V3.309) doesn't re-pull refs/PDF.

## Approach

### rm/js/paper-citations.js — invert to reference-driven

1. **Refactor** `_scanPage`'s body into `_matchItemsOnPage(items, pageNum,
   wrapRect)` (pure over flat text items; `wrapRect=null` → the existing
   `_rectForRangeViaFraction` math path) so the viewer flow and the headless
   audit harness share one core.
2. **`_detectStyle()`** — sweep all pages once, tally VALIDATED candidates
   per family (numeric-bracket / numeric-paren / super / author-year):
   numeric validates `n ∈ [1, refCount]`, author-year validates
   surname+year against the stored ref set. Dominant family wins (≥3 hits;
   two families within 20% → 'mixed' allows both). No refs stored → no
   validation, legacy behavior.
3. **`_alignRefNumbers()`** — for numeric families with SS-sourced refs:
   regex-parse the PDF's own printed reference list (existing
   `_parseReferences`) and re-stamp stored refs' `n` by DOI, then
   surname+year, then title-prefix alignment. Fixes the numbering drift.
4. **Validated scanning** — `_scanPage` keeps only matches in the detected
   family that resolve to a stored ref (`_matchedRef` promoted to a gate);
   with no stored refs, old permissive behavior is kept.
5. **`_buildRefIndex()`** — one full-document sweep → `ref → [{page, rect,
   token}]`. Powers the new **"All refs (N)" tab**: one row per stored
   reference with located-page chips (click → `viewer.gotoPage` + flash);
   "not located" muted rows are visible instead of silently missing.
6. **Diagnostic card** replaces empty panels: "references retrieved but no
   inline markers located — unrecognized citation style" or "no stored
   references — add a DOI", with actions ↻ Re-detect, ⚡ Enrich from
   Semantic Scholar, ＋ Add DOI… (→ fullRefresh).
7. **`analyzeDocument({items, refs})`** export — headless entry returning
   `{style, refCount, locatedRefs, markerCount, perRef}` for the harness.

### NEW rm/js/library-refresh.js

`LIBRARY_REFRESH.fullRefresh(item, {doi, interactive})`:
identifier lookup (param DOI → stored DOI/PMID/arXiv → **title-search
fallback** with confirm, which can *discover* a DOI for an identifier-less
item) → merge biblio fields (fetched wins; tags/star/pdf/id/citation_key
preserved) → targeted `items/{id}.set` (V3.309 pattern) → if no PDF,
Unpaywall attempt via `LIBRARY_UPLOAD.unpaywallLookup/fetchPdfBlob`
(**newly exported** from library-upload.js instead of duplicating; CORS
block stamps `pdf_candidate_url`) → `enrichItemFromSemanticScholar` →
`parseAndCacheRefs` when a blob is in hand → summary toast. Reader sidebar
gets **↻ Refresh from DOI** next to Edit metadata.

### NEW rm/pages/citation-audit.html + rm/js/citation-audit.js

Admin-gated, read-only dev harness (the user's "use the papers we already
have stored to debug and test"): iterates stored papers having PDF + refs,
downloads each PDF, extracts text items, runs `analyzeDocument`, and renders
per-paper rows — style detected, refs located ≥1 marker (%), total markers —
with totals. No schema writes. Linked from nowhere (direct URL) to keep nav
clean.

## Data model changes

None. (`pdf_candidate_url`/`pdf_candidate_source`/`pdf_candidate_note`
already exist from the fromDoi path; V3.309's rules clause covers member
writes.)

## Out of scope

GROBID/server-side ref parsing (no prod server); missing-PDF queue (R4);
writing alignment corrections back to the stored refs (in-memory only —
cheap to recompute, avoids schema churn).

## Release ritual

1. This plan doc. 2. FTP only (no functions/rules). 3. CHANGELOG V3.310 +
ARCHITECTURE + CACHE_VERSION 281.

## Rollback

Client-only: git revert + re-FTP + CACHE bump. No data writes to undo
(alignment is in-memory; fullRefresh writes are user-initiated).

## Verification

- Open stored papers spanning numeric-bracket, superscript, and author-year
  styles: inline hovers land on real citation points; no bogus rows from
  other styles; "All refs (N)" lists every stored ref with page chips that
  jump-and-flash.
- A numeric paper whose SS refs dropped entries now maps `[n]` correctly
  (alignment log in console).
- Paper with refs but odd style → diagnostic card, not silence; ↻ Re-detect
  reruns; paper with no refs → card offers Enrich / Add DOI.
- ↻ Refresh from DOI on a sparse item: metadata fills, OA PDF lands or
  `pdf_candidate_url` is stamped, refs appear after enrich; summary toast.
- `citation-audit.html` (admin): table over the whole library with
  style + coverage; totals give the baseline number to tune against.
