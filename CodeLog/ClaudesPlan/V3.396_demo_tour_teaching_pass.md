# V3.396 — Demo tours teaching pass: orientation, why, no auto-next, page-level card, nav rings

## Context

Alex's five-point review of the guided demos after V3.394:
1. orient the user to the OBJECTIVE of the protocol being built;
2. larger text; the card should stay at the top-right of the PAGE and
   not be disturbed by canvas zoom;
3. no auto-advance — the user presses Next to move on;
4. buttons in the nav bar should light up too;
5. the WHY of every action needs to be explained well.

## Design

### Engine (`rm/js/protocol-graph-tours.js`)
- **Body-level fixed overlay (2, 4).** `ensureEls` appends `.pgt-ring` +
  `.pgt-card` to `document.body` (were children of the canvas viewport).
  Both are `position: fixed`, so canvas pan/zoom/remount can't move or
  clip them, and the ring can circle anything on the page. `positionCard()`
  pins the card top-right of the window, tucked just below the chrome
  above the canvas (`max(12, viewportRect.top + 12)`), refreshed per
  frame (tracks page scroll) and on every renderCard (covers the
  loop-less prebuilt/done cards). `positionRing` now uses client coords
  directly: hides when the target is off the window, and canvas-internal
  targets additionally clip to the canvas box (panned/zoomed away) while
  page chrome does not. `targetEl` searches `hostEl` first, then
  `document` — steps can now target the view segment / topbar.
- **No auto-advance (3).** `flashDone` (650 ms auto-advance timer)
  deleted. `st.advancing` → `st.satisfied`. The loop flips the card
  between waiting ⇄ "✓ step complete — press Next" as the condition
  turns true/false (undoing re-arms the step), and the satisfied state
  shows a primary **Next ▸** (skip hidden). Advancing happens ONLY via
  Next. `activate(i, fast)` keeps the INSTANT resume fast-skip (that's
  positional restoration after a remount, not teaching); a step already
  satisfied at activation renders directly in the satisfied state.
- **Why rendering (5).** Steps gain an optional `why`; renderCard shows
  it as a tinted `.pgt-why` strip ("WHY …") under the instruction.

### Content (same file)
All four build tours rewritten (step counts/conditions unchanged —
the V3.394 resume indices and every `when` stay identical):
- Step 0 of each is now **"The goal"** (1): what protocol we're
  building, what the finished document does, which names are
  load-bearing, plus a why for the pattern itself.
- **Every step carries a `why`** (5): wires-as-permission, naming-as-
  contract, constants-as-policy, modifier-vs-math wiring, list-as-
  crossing-machine, declare-then-return for code outputs, etc.
- Final "see it in the document" steps now **target the 📄 Document
  nav button** (`#pre-viewseg a.pre-viewseg-btn`) so it lights up (4);
  copy notes that opening it leaves the tour.

### CSS (`rm/css/protocol-graph-editor.css`)
`.pgt-ring`/`.pgt-card` → `position: fixed; z-index: 9500` (clears the
popout modal at 9000). Card 380px wide, base font 14px (was 12.5),
step title 15.5px, bigger Next button, `max-height` + scroll for short
windows. New `.pgt-why` / `.pgt-why-tag` strip. Ring border 3px with a
stronger pulse.
