# V3.380 — Code node (drop in a JavaScript snippet)

## Goal

A new `design` node type — **code** — for the calculation that's clearer
as a line of JavaScript than a formula. Variables wired in become named
arguments; the script returns an object whose keys match declared output
variables; those outputs flow into the symbol table reactively, exactly
like an equation's output.

## Design

### `rm/js/protocol-graph.js`
- `'code'` added to `NODE_TYPES`; `_defaultParams('code')` seeds
  `{ label, body:'return { out_<s>: 0 };', outputs:[{name,label,unit,decimals}] }`.
- `producedVars('code')` = one var per named `outputs[]`.
- `inputSlots` gives code a dynamic `math` argument slot;
  `paramTargets('code')` = none; `edgeRole(…, 'code')` = `'math'`.
- `validateGraph`: dup-checks each code output name against the global
  name pool; warns on empty body / no named outputs.
- `compile`: a **scalar-scope** code node emits ONE multi-output entry
  `{blockId,label,expression:'',variables:[],output:null, code, argNames,
  outputs}` — `argNames` are the wired math-edge source vars (edge order,
  deduped), placed after their producers by the existing topo sort. A
  per-item-inferred code node is skipped with a warning (v1 scalar-only).
- `designInputsOutputs` expands a code entry's `outputs[]` into one output
  card each, so the doc view + notebook render them with no extra code.

### `rm/js/protocol-formulas.js`
`buildSymbolTable` pass 2 gains a branch before the equation guard:
`if (f.code != null && Array.isArray(f.outputs) && f.outputs.length)` →
`_evalCodeEntry`. It builds the numeric scope, compiles the body once via
a memoized `new Function(...argNames, '"use strict";\n'+body)`
(`_codeFn`, caches syntax errors too), invokes it with the args, and
maps the result to the declared outputs (bare number allowed when exactly
one output). Every failure mode — syntax error, thrown script, wrong
return shape, missing key, non-finite value — lands as a per-output
`error` row; nothing escapes the table build.

**Trust model:** protocols are lab/admin-authored (same trust as the
shipped interactive-HTML gold standard). Scripts run via `new Function`
in a try/catch; a CSP that forbids eval surfaces as a per-output error,
not a crash.

### `rm/js/protocol-graph-editor.js`
Palette button + label/icon/hint for `code`; the equation operand-row
branch now also renders code argument rows (+ a trailing open "argument"
dot); a `_configFields` `code` branch with a monospace `<textarea>` body
editor (shows the live argument list) + an outputs grid
(name/label/unit/decimals, renaming an output rewrites outgoing wires);
"+ add modifier" → "Add script argument…" / "Add output".

### `rm/js/protocol-import.js`
The design-block branch scans `attrs.nodes` for a `code` type and emits a
transparency **warning** ("contains a script (code) node — its
JavaScript runs when the protocol is viewed"). Not an error.

Nothing else changes: `renderDesign`, notebook `_runMountDesign`, and
`collectFormulasFromPlainTree` are entry-shape-driven; prose `[!var:]`
tokens resolve code outputs automatically.
