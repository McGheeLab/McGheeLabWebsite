# V3.111 — Paper reader: drop abstract, add Cited-by panel

## Goal

Reported:
> *"on the left context menu we dont really need the papers abstract
> to show up there. Instead lets make a new pannel that does a search
> for cited by. These are citations attached to this paper found via
> google scholar."*

Two coupled changes:

1. Remove the abstract section from the left side rail of the paper
   reader at [rm/pages/library-paper.html](../../rm/pages/library-paper.html).
   The field still lives on the item — it just doesn't render here
   anymore.
2. Add a new **Cited by** panel in the slot the abstract used to
   occupy: a list of papers that cite the open one.

## Approach

### Data source — Semantic Scholar, not Google Scholar

Google Scholar has no public API and aggressively blocks automation,
so we can't pull cited-by inline from Scholar itself. **Semantic
Scholar's free Graph API** surfaces the same "papers that cite this
one" relationship via a structured, no-key endpoint:

```
GET https://api.semanticscholar.org/graph/v1/paper/{ID}/citations
    ?fields=title,authors,year,venue,externalIds&limit=100
```

where `{ID}` is `DOI:10.x/y`, `ARXIV:1234.5678`, or `PMID:12345`.
Returns up to 100 citing papers per request, each with structured
title / authors / year / venue / externalIds (DOI, ArXiv, etc.). Free
tier has rate limits but they're far higher than the few requests per
paper-open we generate.

Per-row Google Scholar fallback link is preserved — when Semantic
Scholar returns a citing paper that has no DOI / arXiv id, the
panel falls back to a `Look up` button that opens Scholar with the
title as the search query (same pattern as V3.105's reference panel).

### New module — `rm/js/paper-cited-by.js`

Same shape as the other paper-* modules (paper-citations,
paper-overlays, paper-search): a self-contained IIFE exposing
`window.PAPER_CITED_BY = { init, refreshLibraryStatus }`.

- `init({ paperItem, mountEl, getAllItems, onLibraryChanged })` —
  renders skeleton, picks the best identifier (`DOI` → `arXiv` →
  `PMID`), fetches Semantic Scholar, renders rows.
- `_libraryHitForCitingPaper(p)` — checks `getAllItems()` for an
  existing library entry matching the citing paper's DOI or arXiv
  id, so the row's button flips to `Open paper →` instead of `+ Add`.
- `_onAddClick` — reuses the existing `LIBRARY_UPLOAD.fromDoi(doi)`
  helper (the same one paper-citations.js uses for its
  `+ Add to library` action) so the import flow stays consistent.
- In-memory cache only for v1 (`Map<idKind:idValue, citations>`);
  persistent caching on the item (like V3.93's references cache) is a
  future enhancement when the call volume warrants it.

### Layout / styling

- The `<div id="lp-cited-by">` lands right where `<div id="lp-abstract">`
  was (after `#lp-metadata`, before the script tags).
- New `.lp-cb-*` CSS class family in `rm/css/style.css`, parallel to
  the existing `.lp-cite-*` family but flatter (each row inlines
  author/year + title + venue + actions; no expand/collapse).
- Hover tint is sky-blue rather than amber to visually distinguish
  Cited-by from the existing Citations-on-page panel above it.

### Empty / error states

- **No DOI / arXiv / PMID on the open paper** — the panel renders
  "No DOI / arXiv / PMID on this paper — Semantic Scholar can't
  resolve cited-by." (Title-search fallback would be a fuzzier
  extra round-trip; out of scope for v1.)
- **API call fails** — error message rendered inline; non-fatal.
- **Zero citations returned** — "No citations found via Semantic
  Scholar." (The paper genuinely has none yet, or Semantic Scholar
  hasn't indexed any.)

## Files changed

- **`rm/js/paper-cited-by.js`** (new) — module + Semantic Scholar
  fetch + render.
- **`rm/pages/library-paper.html`** — `<div id="lp-abstract">` →
  `<div id="lp-cited-by">`; new `<script src="/rm/js/paper-cited-by.js">`
  tag added before `library-paper.js`.
- **`rm/js/library-paper.js`** — abstract render block removed (the
  comment in its place explains the swap); new init call to
  `PAPER_CITED_BY.init` in the load flow, sharing the
  `getAllItems` / `onLibraryChanged` plumbing with PAPER_CITATIONS so
  both panels refresh together when a paper is added via either's
  `+ Add` button.
- **`rm/css/style.css`** — new `.lp-cited-by`, `.lp-cb-list`,
  `.lp-cb-row`, `.lp-cb-author`, `.lp-cb-title`, `.lp-cb-venue`,
  `.lp-cb-actions`, `.lp-cb-action`, `.lp-cb-doi`, `.lp-cb-empty`
  styles.
- **`sw.js`** — `CACHE_VERSION` 85 → 86.

## Out of scope

- Persistent cache on the item (like V3.93's references). One fetch
  per paper-open is fine; revisit if rate limits start to bite.
- Title-only fallback when no DOI/arXiv/PMID is present. Two-step
  flow (search → citations) is fuzzier and slower; the current empty
  state tells the user why and we can add it later if many papers
  hit the no-id path.
- "Load more" pagination beyond 100. The API supports it; for v1 the
  list is capped at 100 with a `100+` chip suffix when the cap is
  hit.
- A "Refresh" button to bypass the in-memory cache. The cache only
  lives for the page session, so a hard reload already refetches.

   no error.
