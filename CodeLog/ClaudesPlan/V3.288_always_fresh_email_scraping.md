# V3.288 — Always-fresh email scraping (zero-button + hardened + inline connect)

## Goal

Make email scraping "just work" so a first-time user never has to think about it,
and never hits a silent dead button:

1. **Background, page closed** — server scrapes Gmail every **10 min** (was 15).
2. **On page load** — auto-scrape immediately, render, then poll every **10 min**
   while the tab is open, visible, and online.
3. **Manual** — keep the "Scrape now" button, hardened.
4. **Robust** — offline guard, resilient wiring (button responds even if `boot()`
   bailed), and clear status at every step (no more silent no-op).
5. **First-time inline connect** — when Gmail isn't connected, the Email tab shows
   a self-contained "Connect Gmail" card that runs the OAuth popup, then auto-scrapes
   and renders — the user never leaves the page.

## Root cause this supersedes (diagnosed first)

The "Scrape now" button did nothing because the handler (`onScrapeEmailsNow` /
`wireScrapeEmailsNowButton`) was **uncommitted local work, never deployed** — and the
test was run **offline**, so the network-first service worker served stale JS without
the handler. Runtime probe: `boot` defined (old code) but `onScrapeEmailsNow`
undefined (new code absent). Shipping this version + the deploy discipline below
fixes the immediate bug; the hardening prevents the silent-dead-button class entirely.

## Approach

### Server (background, page closed)
- `functions/gmail-scraper.js`: `schedule: 'every 15 minutes'` → `'every 10 minutes'`;
  update the header comment + cost note. Already iterates **all** users with a
  `gmailCredential` via a `collectionGroup('private')` query, so no logic change.
- Deploy: `firebase deploy --only functions:scrapeGmailForAllUsers`.

### Client (email-review.js)
- **Refactor `onScrapeEmailsNow(opts)`** to take `{ quiet }`:
  - `quiet:false` (manual click) — disable button, "Scraping…", toasts (current behavior).
  - `quiet:true` (auto/poll) — no button disable, subtle status only ("Checking for new
    email…" → "Up to date" / "N new"), no error toast (log + status instead).
  - **Offline guard first**: if `!navigator.onLine`, show "You're offline — reconnect to
    sync Gmail" and return (covers the exact failure that was just hit).
  - **Network-error catch**: a `TypeError`/`Failed to fetch` shows "Couldn't reach the
    server — check your connection", not a raw stack.
- **Resilient wiring**: register a single **delegated** click listener at top-level of
  the script (module-eval time, not inside `boot()`), so a click on
  `#email-scrape-now-btn` always routes to `onScrapeEmailsNow` even if `boot()` threw.
  Keep the existing direct wire as a no-op-safe second path (idempotent `dataset.wired`).
- **Auto-scrape on load**: after the first render in `boot()`, if online + Gmail
  connected, fire `onScrapeEmailsNow({quiet:true})` then refresh.
- **10-min poll**: `setInterval(POLL_MS=600000)` guarded by
  `document.visibilityState==='visible' && navigator.onLine`. Pause/resume on
  `visibilitychange`; clear on `pagehide`. Each tick = quiet scrape → clear year cache →
  reload current year → refresh. (scrapeNow's 60s server-side rate-limit makes this
  self-protecting; a rate-limited tick just re-reads Firestore — cheap, no Gmail API.)
- **Connection state**: read `userData/{uid}/private/gmailCredential`; treat
  `refreshTokenStored === true` as connected (same flag oauth-connections.js renders on).
- **Inline Connect empty state**: when not connected (or zero emails + not connected),
  render a card into `#content`: "📨 Connect your Gmail to start triaging." +
  [Connect Gmail] → `OAUTH_CONNECTIONS.connectGoogle({onDone})` → on success, scrape +
  re-render. Offline → show offline notice instead of the connect button.

### oauth-connections.js
- Expose a reusable connect entry point on the existing `window.OAUTH_CONNECTIONS`:
  `connectGoogle({ onDone })` — runs the same combined Gmail+Calendar GIS code-client
  popup + exchange + first sync the Settings card uses, then calls `onDone(result)`.
  Also expose `isGmailConnected()` reading the cached credential snapshot.
- No behavior change to the Settings page — just refactor the private `connect()` body
  into a callable that both the Settings button and the email tab use.

### activity-overview.html
- Add to the **email** tab's script list (so inline connect works there):
  `https://accounts.google.com/gsi/client` and `/rm/js/oauth-connections.js`
  (both already used by the tracker tab / Settings; origins are authorized).

## Key decisions / tradeoffs

- **Both server poll and client poll at 10 min** is intentional (user asked for both).
  They're not redundant in practice: the server keeps Firestore fresh when the page is
  closed; the client poll mostly re-reads Firestore (scrapeNow rate-limits to ≥60s) so
  the open page reflects server scrapes without extra Gmail API cost.
- **Poll pauses when tab hidden / offline** — avoids quota burn and offline error spam.
- **Quiet vs loud modes** — background activity must not nag; manual clicks get full
  feedback. One function, one flag, no duplicated fetch logic.
- **Delegated wiring** hardens against `boot()` bailing, but NOT against a fully stale
  cached file (that's a deploy-discipline problem) — hence the mandatory CACHE_VERSION
  bump + the deploy checklist below.
- **Inline connect adds the Google GIS SDK to the email tab** (~tracker already loads
  it). Accepted cost for a one-page first-time flow.

## Manual test

- **Manual button**: online, signed in, Gmail connected → click "Scrape now" → button
  shows "Scraping…" → status "Scrape complete: N emails" → list refreshes.
- **Offline**: DevTools → Network → Offline → click "Scrape now" → "You're offline…"
  status, no silent no-op, no stack trace.
- **On-load**: open the email tab online → within a few seconds a quiet
  "Checking for new email…" → "Up to date / N new" with no button press.
- **Poll**: leave the tab open 10 min → it refreshes; switch to another tab for 10 min →
  no polling; come back → resumes.
- **First-time connect**: disconnect Gmail in Settings → open email tab → see the inline
  "Connect Gmail" card → click → OAuth popup → on success, emails appear without leaving
  the page.
- **Background, closed**: connect, close the tab, wait ~10 min, reopen → new mail present
  (server scheduled run).
