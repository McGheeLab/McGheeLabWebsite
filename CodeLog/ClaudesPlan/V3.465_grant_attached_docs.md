# V3.465 — Grant unification R3: attached-document plumbing + upload slot

> Third release. Makes the 18 grant attached kinds behave like real separate
> submission documents: excluded from the main manuscript, each compilable/downloadable
> on its own, and each carrying an upload slot for the final externally-produced PDF.

## Manuscript exclusion (rm/js/paper-export-tex.js)

- The `SUBMISSION_DOC_KINDS` skip-guard in `resolveSectionCommand` is generalized to
  `_manuscriptExcludedKinds()` = the static submission-doc kinds **∪** the grant
  attached kinds (read lazily from `PaperSchemas.GRANT_ATTACHED_KINDS` — one source of
  truth, no second hardcoded copy). An attached-kind section that the active template
  doesn't map → `{type:'skip'}` (excluded from both the compiled manuscript and the
  Document view, via the shared resolver). The main-manuscript `.bib` exclusion
  (`collectCitationKeys`) uses the same combined set.
- Loads without `PaperSchemas` (e.g. the harness) fall back to the static set only —
  the harness now loads `paper-schemas.js` into its sandbox to exercise the grant path.

## Attachment compile template (rm/data/paper-templates/rm-grant-attachment.json)

- New minimal single-column `article` template (11pt, 1in margins, `section_star` +
  natbib), mapping every grant attached kind. Fetched by id like `rm-cover-letter`
  (NOT in `KNOWN_TEMPLATES`). One shared template for all attachments to start;
  agency-specific formatting (NSF PAPPG fonts/margins) is deferred.

## Subdoc registry (rm/js/paper-subdocs.js)

- `DOCS` entries added for all 18 grant attached kinds (docKind === section kind,
  `templateId: 'rm-grant-attachment'`, `types: ['grant']`); the four externally-produced
  artifacts (biosketch, current_pending, collaborators_coa, budget) are flagged
  `uploadOnly: true`. Existing cover_letter/rebuttal gain `types`. New
  `docsForType(type)` selector. `buildSubdocBundle` already handles any entry, so .zip
  source download works today for the prose-bearing attachments (PDF compile stays
  behind the existing `DOC_KINDS` server gate — a later redeploy).

## Generic upload slot (rm/js/paper-editor.js + rm/css/paper-editor.css)

- Any grant attached-doc section renders a `.pe-upload-slot` in its header:
  upload / replace / remove a **PDF** (the final SciENcv biosketch, Research.gov
  budget, signed departmental letter, …). Reuses `PAPER_FIGURES.uploadImage`
  (already accepts PDF; the `paper-figures/{paperId}/` Storage path + rules already
  allow PDF — **zero storage-rules change**; V1 is PDF-only). The pointer
  (`{filename, storage_path, download_url, mime, size_bytes, uploaded_at}`) rides the
  section Y.Map as a scalar `uploaded_file`, round-tripped through all three section-
  tree functions (append/snapshot/hydrate) so it syncs to collaborators and survives
  section moves — the `ref_label`/`revision_by` pattern.
