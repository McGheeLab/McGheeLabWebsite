# V3.835 — A QR label for every inventory item, printed at the lab's label printer, scanned in the app to use it — per use or per package

**Date:** 2026-10-22 · **Builds on:** V3.646 (scannable inventory, blocks 0–2 shipped; blocks 5–6 never did) ·
**Backend:** `firestore.rules` one clause, DEPLOYED from a scratch copy on top of the live ruleset (the local file
also carries another session's undeployed V3.806 users hunk and V3.834 chat-group hunks — neither shipped) ·
**Site files:** auto-upload at turn end, `sw.js` 814 → 815 · **Other repos:** LabelPrinter (Queue tab), OurlabMobile
(camera permission; ships with the next TestFlight build)

Alex: *"for each item in the inventory, i want to add a qr code. this qr code should be able to be linked to the label
printer so the physical item can get the qr link. also the phone app should get the ability to read the qr code to use
the item. some items need to be scanned per use like antibodies, matrigel, and others that we designate. Other items
should be replaced as a package like conical tubes, pipette tips etc."*

## 1. What existed, and what did not

V3.646 built the registry (`labels/{CODE}`), the code format (`label-id.js`, a port of the printer's `ids.js`), the
scanner (`scan.js`: typed / USB gun / camera with jsQR), the resolver (`scan-resolve.js`), the quantity ledger
(`inventory-qty.js`, `inventoryUsage`) and the rules for all of it — and then **no page loaded any of the three scan
files**, the print-queue consumer on the printer PC was never written, and the iOS camera key never shipped (the
scanner's own gate, `window.__OURLAB_CAPS`, was never set by anyone). Live rules already held every block; verified
against the fetched ruleset before touching anything.

## 2. The QR, and where it goes

- `rm/vendor/qrcode/qrcode.js` — the printer's own encoder (`LabelPrinter/web/core/qrcode.js`, versions 1–4) as a
  mechanical ESM→IIFE port plus `toSvg()`; the node test imports both and compares matrices bit for bit.
- Payload `MCGHEELAB.COM/L/MG-A7K2X`: uppercase so the symbol stays in alphanumeric mode (31 chars → version 2, the
  largest the 111-dot strip takes — the V3.646 measurement). A phone camera opens `https://mcgheelab.com/l/MG-A7K2X`;
  `l/.htaccess` (Apache; `l/**` added to `deploy/site.json`) rewrites it to `inventory.html?code=…`, `l/index.html`
  is the typed fallback. The app's scanner and a USB gun read the same string; `normalize()` keeps the last path
  segment, so every reader ends at one code.
- `rm/js/inventory-labels.js` — `ensureCode(item)` mints through `SCAN_RESOLVE.mintAndBind` (race-free, never
  twice, never deleted) and writes `label_code` on the item; `cellFor(item, code)` is a cell in the printer's
  `emptyCell()` shape with `qr.payload` + `qr.force`; `queue(items)` writes `labelQueue` jobs (≤ 200 cells each, the
  rules cap); `sheetUrl(items)` → `rm/pages/inventory-labels.html`, a browser print page with label-stock presets
  (Avery 5160, DYMO 30252, 2×2, the Zebra strip, custom) for any other printer.
- Inventory page: a "QR label" block in every detail panel (the QR itself, the code, copy link, **✓ Use / take**,
  **🏷 Print label**, **🖨 Sheet**, manager's **Make code**); toolbar **📷 Scan** (camera / typed / USB) and **🏷 Print
  labels** (every item in the current list, one queue job); `?code=` opens the item and its use sheet.

## 3. The printer pulls the queue (LabelPrinter repo)

`web/core/queue.js` (Firebase compat from the CDN; two single-field `status` queries — an equality + orderBy would
need a composite index the project lacks; `validateJob`, `normalizeCells`, `sortJobs` pure and tested) and
`web/ui/queue.js` (a **Queue** tab: sign in once with a lab Google account; **Load into Design** claims the job and
fills the grid with its cells; the normal **Print** button prints and a successful spool marks the job `printed`
through `design.onPrinted`; Mark printed / Release / Cancel by hand). `127.0.0.1` added to the project's Auth
authorised domains (localhost already was) so the sign-in popup works from the agent's origin. The printer's own
`layout.js` still computes every coordinate — the queue carries content, never geometry.

## 4. The phone reads it (OurlabMobile)

`Info.plist` gains `NSCameraUsageDescription`; `TabBridgeViewController.capacitorDidLoad` injects a document-start
user script `window.__OURLAB_CAPS = { camera: true }` — the flag `scan.js` `cameraAvailable()` waits for, because
iOS answers a missing plist key with process termination, not a denied promise (old builds never set it, so they keep
the typed field). Android: `CAMERA` in the manifest (untested; not the shipped target). Alex then asked for Inventory
**built into the app**: `TabKey.inventory` in `TabRoute.swift` + the `inventory*.html` family, the web tab bar entry in
`mobile-shell.js` (`archive-box`, before More) and `tab-lifecycle.js`; the app now opens Inventory → 📷 Scan directly.
Shipped as m-v0.4.0 (build 13) through `release_push.py --verified --minor` — simulator-verified to compile and launch;
the signed-in tap-through is Alex's.

## 5. Two ways a scan consumes

`inventory/{id}.use_mode` ∈ `per_use | package`, a manager's designation (rules: `qtyControlsUnchanged` now
includes it — a member cannot flip it; a consumable with no designation defaults to package; anything else asks on
the sheet). `rm/js/inventory-use.js`:
- **per_use** (antibodies, Matrigel): one scan = one `inventoryUsage` row (`event 'use'`, unit `use`, delta 0 —
  allowed by the existing ledger rules) + `use_count` / `last_used_*` on the item; the vial count only drops when
  **Finished this one** takes one unit off.
- **package** (tubes, tips): one scan = N packages off. Tracked items go through `INV_QTY.consume` (the ledger, low
  alerts, reorder point); an untracked item decrements the legacy `quantity` scalar and still writes a ledger row
  (`legacy: true`) so nothing is lost, with a hint to switch tracking on.
- `plan(item, action)` is pure (node-tested); `run()` is one transaction reading the server's numbers; the sheet
  shows on-hand, the mode, a note field, "Running low / That was the last one → Request a reorder".
