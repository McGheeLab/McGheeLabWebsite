# V3.503 — Protocol "Cheat Sheet" condensed view

## Goal

After a protocol is authored in the RM Protocols Builder, give an experienced
user — someone who already knows the protocol and finds the full document
cluttered — a **cheat sheet**: the same protocol boiled down to bare-minimum
actionable steps plus the live numbers they check at the bench (volumes, temps,
times), dense enough to paste into a lab notebook or print on one page.

## Approach

A fourth Protocols mode, `?protocol=<id>&view=cheat`, exactly parallel to the
read-only doc view (`&view=doc`). It reuses the doc view's plumbing
(`protocols.html` mode dispatch, the shared `ProtocolDocRender` renderers, the
`ProtocolWidgets`/`ProtocolFormulas` symbol table) but renders a **filtered,
condensed** version.

### Condensing steps (decisions confirmed with the user)
- **Authored cheat line + auto fallback.** Each step gains an optional
  `attrs.cheat` string. The sheet shows it when set; when blank it auto-extracts
  the step body's first line/sentence (`condenseStepText`). Deterministic, free,
  and works on every existing protocol immediately via the fallback.
- **Keep-set** (explicit, adjustable map in `protocol-cheat.js`):
  - KEEP: `step`, `heading`, `timeline`, `figure`, `layoutMap`, and `callout`
    where `attrs.type === 'timing'`.
  - DROP: `materials`, `callout` critical/note/assume, legacy `note`/`safety`,
    `formula`, `calculator`, `builder`, `design`, `table`, `kv`, `docHeader`.
  - Dropped widgets' OUTPUTS still resolve inside kept steps (the symbol table
    is built from the whole tree), so `[!var:]` numbers stay live.
  - Per the user's selection this omits materials + critical/safety callouts;
    both are one-line flips of `KEEP_KINDS` / `KEEP_CALLOUT_TYPES`.
- **Output:** in-shell `?view=cheat` page with a 🖨 Print / PDF button, same
  chrome-stripping `@media print` approach as the doc view.

## Key decisions

- **Reuse over re-implement.** Only the step renderer is bespoke; figures,
  plate maps, timelines, and timing pills go through the existing shared
  renderer, and the whole boot sequence mirrors the doc view.
- **No new persistence surface.** `attrs.cheat` lives inside the existing
  owner-writable `protocols/{id}` doc, carried by the generic Yjs
  hydrate/dehydrate. **No Firestore rules / indexes / functions change.**
- **`prd-doc` + `prc-doc` dual class** on the article to inherit shared block
  styling while layering compact overrides (loaded after `protocol-doc.css`, so
  `.prc-doc` wins on conflicts).

## Deploy

**FTP-only** (RM static tree). No Firebase deploy. Service worker bump forces
clients to pick up the new SW (RM files are served network-first, not
precached, so the new files are not added to `SHELL_URLS`).

## Known limitations

- A kept `layoutMap` whose assignments come from a dropped `builder`/`design`
  dataset renders without them (those datasets register only when the widget
  renders, which the cheat view skips). Static plate maps and
  formula/calculator-derived `[!var:]` values are unaffected.

Run `RM_WRITE_ALLOWLIST=mcgheealex@gmail.com python3 rm/server.py`, open
`http://localhost:8000/rm/pages/protocols.html`, sign in, open a protocol with
steps + figures + a plate map + timing callouts + materials + note callouts:
1. Editor shows the per-step cheat-line input; typing one persists across reload.
2. 📋 Cheat sheet → compact header, continuous numbered condensed steps
   (authored line where set, else auto first-line), figures + plate map + timing
   + timeline present; materials / note-assume-critical callouts / widgets absent.
3. `[!var:]` values resolve live in cheat lines.
4. 🖨 Print / PDF strips chrome, uses letter/0.4in, keeps rows/figures unsplit,
   visibly denser than the doc view.
5. Edge cases: no authored cheat lines (fallback only); no steps; single-token
   step body — no crash, clean console. `?view=doc` + editor/list unchanged.
