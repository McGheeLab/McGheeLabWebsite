# V3.425 — Ratio units decompose (mg/mL × volume finally cancels to mass)

## Context

Alex's browser repro against V3.422: volume input + mass input →
result1 = mass/volume → result2 = result1 × volume "still carries the
mixed units but should be just mass."

## Root cause (reproduced in harness)

The undeclared path DID cancel (mass/volume × volume → mg). The break
was **declaring result1's unit as `mg/mL`** — the natural dropdown
choice for a concentration. The catalog treated `mg/mL` (and `g/L`,
and the whole molar family) as an ATOMIC 'amount' unit: quantity
{dim:{amount:1}, units:{'mg/mL':1}}, so the algebra had no volume in
its denominator to cancel — result2 became `µL·mg/mL`
({amount:1, volume:1}), a pie-mixed variable forever.

## Fix (`rm/js/protocol-graph.js`)

1. **`quantityOfUnit` decomposes ratio units** into their true
   quotient — dims, unit names, and scale:
   - generic `A/B` where both halves are dimensional catalog units:
     `mg/mL` → {dim:{mass:1,volume:-1}, units:{mg:1,mL:-1}, scale
     s(A)/s(B)} (matches the existing UNIT_SCALES entries exactly:
     mg/mL = 1, g/L = 1). Hand-typed compounds (µg/µL) now work too;
     `mL/mL` nets to nothing; non-dimensional halves (AU/min) stay
     atoms as before.
   - molar family M/mM/µM/nM/pM → {dim:{amount:1,volume:-1},
     units:{mol:1,L:-1}} at their existing scales — so
     **mM × µL → mol at 1e-9 (nmol) scale**: dilution math
     (C×V → moles) composes and cancels correctly.
   - `categoryOfUnit` is UNTOUCHED: colors, the Type→Unit dropdown,
     and dimension letters for declared inputs stay 'amount'.
2. **`unitsCollapse(units)`** (exported): when one category holds
   names of OPPOSITE signs (…·µL / mL), the dim algebra already
   cancelled — fold to the net exponent on the dominant name (net 0 →
   gone); magnitude differences live in `scale` and surface through
   the existing ×N warnings. Same-sign names (µL·mL) never collapse.
   Applied inside `qMulOp`, so it works mid-expression and across
   node chains.
3. **Amount-family kinds retired** (molar/moles/massconc removed from
   UNIT_KINDS): post-decomposition their dims differ
   ({amount,volume⁻¹} vs {amount} vs {mass,volume⁻¹}), so dimension
   checks distinguish them EXACTLY — and a lingering 'molar' kind
   would have been wrong (M×L IS mol, but kinds would fight mmol).
   Temperature kinds stay (°C/K/°F share a dim; offset scales).
   Warning texts updated in kernel + editor pad.
4. **`equationAliases`: declared-unit override** — a declared unit
   keeps its single catalog category/letter (mg/mL wires in as C1,
   amount-colored, no pie) even though the algebra sees its
   decomposition; only COMPUTED quantities letter by their dims.
   Bonus fix: the pad's declared-vs-computed check no longer
   false-warns "mg/mL is amount but the math computes mass / volume"
   when you declare a computed concentration as mg/mL — dims now
   match, and only a real magnitude gap warns.
