# V3.875 — Custom inventory: three kinds, a units row, groups, and "made from" that never miscounts

**Date:** 2026-10-23
**Builds on:** [V3.873](V3.873_lab_made_aliquots.md) (lab-made items are `kind:'item'` + `lab_made:true`, QR at save).

**Request (Alex):** *"clean up the inputs for the custom inventory for example the what is it dropdown should be: custom
alliquot, custom material, custom media / for how many, we need units dropdown. / there should also be an option for a
group of items for example a user could me 4 15mL tubes of LLS these should all be palced in the same locaiton. / we
should be able to consume something in the inventory to make an alliquot of something or to make custom media etc. so
we need a consumed items with units option somewhere. Be careful about consumption since some things we have qr codes
for packs of items, but here the user may mark down 4 15mL tubes were consumed, that should not mean 4 packs of 15 mL
tubes."*

## What changes for the person

- **What is it?** — *Custom aliquot* / *Custom material* / *Custom media* (`lab_made_type` `aliquot` | `material` |
  `media`; V3.873's `made_in_lab` reads as *Custom material*).
- **How many** is one row: `[4] [tubes ▾]  each holds [15] [mL ▾]`. The unit list is containers (tubes, vials,
  aliquots, bottles, plates, slides, boxes, pieces) and measures (µL, mL, L, mg, g). *Each holds* applies only to a
  container. Changing the kind changes the starting unit (media starts on bottles) until the person picks one.
- **A group** is that row: 4 × 15 mL tubes is ONE entry at ONE location, counted in tubes (`qty_unit: 'tube'`,
  `qty_made: 4`), with `each_amount: 15, each_unit: 'mL'`. A line under the row says so: *4 tubes of 15 mL each,
  together at fridge/box/001; the same QR code on every tube*. One label per tube, as before.
- **Made from**: search the inventory (items, other custom items and chemicals), pick what was used, give the amount
  and a unit. Every row says in words what will happen before anything is saved: *Takes 50 mL off · 400 mL left*, or
  *Noted only: counted in packs; single tubes from an open pack don't change the pack count*.
- The item's panel lists what it was made from (*taken off* / *noted*) and *Each holds 15 mL*. A tube's printed label
  carries *15 mL* (the line a purchased item uses for vendor and catalogue #).

## Why the planner may refuse to subtract

The inventory counts an item in ONE unit (`qty_unit`). A pack of 50 conical tubes is usually counted in `pack` (or
`ea` meaning a pack), and it carries the QR code. "I used 4 tubes" against it must never become "4 packs". So
`INV_MADE_CORE.planIngredient(item, amount, unit)` only subtracts when the amount is exact in the item's own unit:

| the item is… | the person says… | result |
|---|---|---|
| tracked in a measure (mL) | a unit of the same family (µL, mL, L) | **take** the converted amount |
| tracked in a container (vial, tube, bottle…) | that container | **take** that many (whole numbers only) |
| tracked in a container with `each_amount` (a V3.875 group) | a measure of that family that is a whole number of containers | **take** that many containers |
| ″ | a measure that is part of a container | **noted**: "the count changes when a tube is finished" |
| tracked in `pack` / `box` / `ea` | **single pieces** (the default) | **noted**: the pack count changes when someone takes the last of a pack |
| ″ | whole packs (as counted, chosen on purpose) | **take** that many, whole numbers only |
| not tracked | **whole packages, as the Qty column counts them** (offered only when Qty is a number) | the legacy `quantity` drops through `INV_USE.run` (`via:'legacy'`), as a package scan does |
| ″ | anything else | **noted** |
| anything | a unit from another family (mL against vials) | **noted** |

The unit list per row is built to match (`unitChoices(item)`): a pack/box/ea item offers *single pieces* first and
*whole packs* second; a measure item only its family; an untracked item *pieces* first. So the default is always the
choice that cannot over-subtract.

**Taken** goes through `INV_QTY.consume` (one ledger row, low-stock alerts, the user's action). The quantity is passed
already in the item's unit; `write()` would refuse a cross-family unit anyway. **Noted** is a delta-0 `inventoryUsage` row
(`event 'use'`, the person's own amount and unit, `before == after` read live), which every member may write today.
Every row carries `purpose: 'lab-made:<newId>'` and `note: 'Used to make <name>'`. Going below zero is allowed and said
in amber in the preview ("it will read below zero until someone recounts"), the stock-take sheet's V3.646 rule.

The new item keeps the recipe as `composition: [{itemId, name, kind, qty, unit, taken, taken_qty, taken_unit, note}]`
(the name V3.646 reserved for it).

## Shape

- **New** `rm/js/inventory-made.js`: `INV_MADE_CORE` (DOM-free, node-tested: `TYPES`, `typeOf`, `typeLabel`,
  `unitWord`, `unitChoices`, `planIngredient`, `buildItem`, `labelCount`, `search`) and `INV_MADE.open({items,
  create, opened})`, a form of its own (a desktop modal with the fields scrolling and the buttons pinned; the app's
  bottom sheet in the app). Errors appear beside their field, never in a browser dialog. After save it closes, then
  takes or notes each ingredient, queues the labels (or mints the code), and reports in one toast.
- `rm/js/inventory.js`: `addLabMadeItem()` becomes a thin call; the V3.873 form, `_invLabelNewItem` and its constants
  go; chip, tab, subtabs and panel read `INV_MADE_CORE`; *Each holds* and *Made from* in the panel; `qtyCell` adds
  "15 mL each".
- `rm/js/inventory-labels.js`: `cellFor` puts `each_amount each_unit` on a lab-made label's second line.
- `rm/pages/inventory.html`: the button reads **+ Custom item**; loads `inventory-made.js`.
- No rules, index or function change: `inventoryUsage` create already admits a member's delta-0 `use` row and a
  delta < 0 one; `inventory` create admits the new fields.
