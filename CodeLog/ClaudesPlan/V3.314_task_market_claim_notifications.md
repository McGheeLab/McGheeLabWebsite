# V3.314 — Task Marketplace: claim materialization + notifications (FuturePlan 04, Release A2)

## Goal

Make claiming real: when a member claims an offer or accepts a directed
handoff, the post's `task_payload` is copied into **their own**
`userData/{uid}/tasks/{taskId}` queue (bucket `assigned`, stamped with
`marketPostId`), and Cloud Function triggers push the three market
notifications: post directed at you, your post claimed/answered, and
directed post declined.

## Approach

### Client — materialization reuses task-assign internals

- [rm/js/task-assign.js](../../rm/js/task-assign.js) grows
  `TASK_ASSIGN.writeTaskFor(assigneeUid, fields)` — the payload-build +
  Firestore-write core extracted from `_submit` (V3.313 planning noted
  lines 82–135). `_submit` now routes through it. Returns a Promise
  resolving the written payload (with `id`).
- `rm/js/task-market.js`'s `materialize(post)` (feature-detect shipped in
  V3.313) calls it on claim/accept with the claimant as assignee,
  `createdByUid` = the post creator (legal: the claimant writes into
  their *own* subcollection, covered by the owner wildcard rule), and
  `marketPostId` = the post id; the post gets `marketTaskId` back.
  PMR backrefs in `source_ref` are translated to the `source:'pmr'` +
  `pmrPeriodId/SectionId/TargetId` fields PMR already renders.
- `kind:'request'` claims materialize nothing (claiming a request means
  "I'll find you work", not "give me a task").

### Server — functions/task-market.js

- `onMarketPostCreated` (`taskMarket/{postId}` onCreate):
  - `targetUid` set → push the target ("🤝 handoff ask" when `open`;
    "task sent" phrasing when admin pre-`accepted` — the V3.317 direct
    flow, where the legacy per-task push is suppressed, see below).
  - else `kind == 'request'` → push all admins ("🙋 X is asking for work").
  - undirected offers stay quiet (the board is the discovery surface —
    plan locks only three notification types).
- `onMarketPostUpdated` (onUpdate): fires only on the `open →
  claimed/accepted/declined` edge → pushes the creator ("your offer was
  claimed" / "your handoff was accepted" / "X is on it" for requests /
  "declined"). Other transitions (creator's own withdraw/complete) are
  self-inflicted, no push.
- Both use `sendToUsers` (helpers/notify.js) with appKey `tasks`.
- **functions/tasks.js `onTaskAssigned` now skips tasks carrying
  `marketPostId`** — market-materialized copies are written by the
  claimant themselves (or accompanied by a market onCreate push in the
  A3 admin flow); the legacy per-task push would be duplicate noise.
- Three new test types in functions/test-notifications.js:
  `task-market-directed`, `task-market-claimed`, `task-market-request`.
- Also fixes a latent crash in test-notifications.js: the response
  referenced an undefined `staleDeletes` (should be `staleOps`).
