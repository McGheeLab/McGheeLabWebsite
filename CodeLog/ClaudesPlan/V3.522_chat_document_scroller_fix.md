# V3.522 — Chat: open-at-bottom fixed for real (document is the scroller)

**Bug fix** — Alex re-reported after the V3.518 fix: chat still opened at
the TOP of history from both the RM sidebar and the chat page.

## Actual root cause (deeper than the V3.518 diagnosis)

`rm/pages/chat.html` mounts chat into `#chat-root`, which has **no CSS
anywhere** — the app-viewport rule in chat.css (`#app { display:flex;
overflow:hidden }`) targets the LEGACY lab-app container id that doesn't
exist in RM. With no height constraint on the chain
(`body → .page → #chat-root → .chat-layout → .chat-main → .chat-feed`),
`.chat-feed`'s `overflow-y: auto` never engages: the feed grows to full
content height and the **document** is what actually scrolls — on
desktop AND mobile. Every `feed.scrollTop = feed.scrollHeight` since the
V3.52 port (including the original code's and V3.518's image-load fix)
was a silent no-op on a non-scrolling element. V3.239's comment even
says it: "the ≤700px block lets .chat-layout flow into document scroll".

## Fix — target the real scroller, keep the layout untouched

Deliberately NOT restoring an internal-scroller layout: V3.239 chose
document-scroll for the iOS keyboard behavior, and users know the
current layout. Instead all scroll logic goes through two helpers:

- `pageScroller()` → `document.scrollingElement`.
- `pinFeedToBottom()` — pins the feed (no-op today, future-proof) AND
  the document. `scrollToBottom()` double-rAFs it.
- `feedAtBottom()` — bottom-ness of whichever scroller is real (feed if
  it overflows internally, else the document); used by `renderMessages`'
  `wasAtBottom` and the scroll handlers.
- `handleFeedScrollState(scrollTop)` — the shared handler (autoscroll
  tracking, "New messages" pill removal, load-older near the top,
  history-mode load-newer near the bottom), guarded on `#chat-feed`
  being on screen. Wired to BOTH the feed's own scroll event
  (future-proof) and a new window-level scroll listener
  (`wirePageScroll`, attached once in bootstrap, removed in destroy()).
  Previously the feed scroll listener NEVER fired — meaning autoscroll
  tracking and scroll-to-top load-older have been dead since the port;
  they now work.
- The capture-phase image `load` re-pin now calls `pinFeedToBottom()`.
- `updateMobileContent`'s thread open/close scroll preservation
  captures/restores the PAGE position instead of the feed's.

Bonus from the document being the scroller: native browser scroll
anchoring keeps the view stable when `loadOlderMessages` prepends.

## Verification

Desktop + phone, from the RM sidebar and a direct URL: chat opens with
the newest message right above the composer, including channels with
image posts. Scroll to the very top → older messages load. Scroll up,
have someone send → "New messages" pill (no yank); at bottom → follows.
History jump → banner → "Jump to latest ↓" lands at the composer.
