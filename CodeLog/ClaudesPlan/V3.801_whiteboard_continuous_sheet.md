# V3.801 — Whiteboard: continuous sheet (default) + exact scroll follow

**Asked (Alex, 2026-10-05):** "when I am writing notes in class, I want a mode for
continuous vertical sections. This will be the default mode, and thus snap-to
section should be off in this continuous mode. Instead of having a gap between
sections, I want a light grey dashed line separating page sections. I still want
the page sections to be the same on the left panel, but they should be
continuously scrolled, and the follower should still follow exactly where the
scroll is. The problem is that during lecture I write towards the end of the page
and students find it hard to keep up, so when I click on a new page they cannot
finish writing that equation."

## Goal

A board can be laid out two ways:

| | **Continuous** (new, default) | **Pages** (V3.730 snap-sheet) |
|---|---|---|
| Between pages | no gap — a light grey dashed line | desk-coloured gap |
| Scroll | stops where you let go | snaps to the nearest page |
| What the room follows | the leader's exact scroll position | the leader's page |
| ＋ page | extends the sheet below; nobody's view moves | snaps everyone to the new page |
| Rail | same thumbnails; selection tracks the page under the middle of the view | unchanged |

The point of continuous mode: the end of the page Alex just filled stays on the
students' screens while he scrolls into the next page, instead of vanishing on a
page flip.

## Decisions

1. **The mode lives on the board doc** (`sheetMode: 'pages'`; absent or
   `'continuous'` = continuous). It cannot be per-device: a follower can only
   reproduce a scroll position in the same geometry the leader scrolled in.
   Absent = continuous makes it the default for every board, existing ones
   included — page-local stroke coordinates are unchanged, so no data moves.
   Toggle: a `⇵ Continuous | ▤ Pages` pair in the drawing toolbar (whoever may
   draw). Switching deletes `viewY` so nobody jumps to a stale position.
2. **Geometry.** `pageTop(i) = i·(BOARD_H + pageGap())` with `pageGap()` 0 in
   continuous mode. Same 1.5-page stage framing and the same clamp (first page
   centred ↔ last page centred) as pages mode, so toggling never rescales the
   ink. Dashed separators drawn on the background canvas after the page fills,
   dash and width proportional to the page width so the projector looks the same.
3. **Sync = `viewY` on the board doc** — the sheet y (page-width units) at the
   MIDDLE of the leader's stage. Centre alignment: every landscape screen is
   height-limited and shows exactly 1.5 page heights, so framing is identical;
   taller/portrait screens show extra margin above and below. The leader
   publishes while scrolling (throttled, `SCROLL_SYNC_MS` 250) and once on
   release, together with `activePageId` = the page under the centre. Followers
   ease to each update (`FOLLOW_TWEEN_MS` 240) so 4 updates/s read as a
   continuous scroll. Board-doc fields need no rules change (class admins and
   notes owners already write the whole doc) → FTP-only release.
   *Budget:* ≤4 board-doc writes/s only while the leader's fingers are moving;
   each fans out a ~1 KB snapshot to viewers. Bursts, not sustained load.
4. **Pause semantics** (V3.740 rule kept at page granularity): a follower who
   scrolls by hand pauses following; the pause ends when the leader's
   *page* changes (so a student can look back for a while, but not forever),
   or on ⟳ Sync / "Jump to live". The projector never pauses. Tween frames from
   a rail click do NOT publish (the target is published once), so followers
   never receive positions behind the target.
5. **No snap anywhere a finger/wheel scrolls** in continuous mode; overscroll
   eases back to the clamp. Explicit navigation (rail thumb, ↑/↓, ＋ Simulation,
   page move/delete) still centres a page — that is a deliberate jump.
6. **Resize** keeps the view centre (continuous) instead of re-centring the
   nearest page; an in-flight tween is retargeted by its centre.
7. **Recording/replay:** the recorder logs `scroll {y}` (≤ every 400 ms) and
   `page` events carry `y` when the board has one; replay scrolls continuously
   instead of page-snapping. Replays use the board's *current* mode (known gap,
   noted below).

## Known gaps / follow-ups

- A replay recorded in one mode and played after the board switched modes uses
  the new geometry (pages mode ignores `viewY` and centres pages instead).
- While the drawer is pinch-zoomed, a two-finger drag pans the lens (existing
  V3.730 rule), so scrolling the sheet still needs a zoom-out first.
- Real-iPad + projector check owed: scroll on the iPad, watch the laptop track it.
