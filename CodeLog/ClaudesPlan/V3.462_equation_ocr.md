# V3.462 — ✨ Auto-read: equation snips parse straight to LaTeX

> Alex: "I want to be able to take an equation from a journal paper and directly parse
> it to LaTeX, not have to build it myself." Completes the E3 capture flow (V3.445) —
> the snip was already there; only the transcription was manual. (OCR was explicitly
> deferred in the Paper Builder III planning; this un-defers it.)

## Design

No AI provider existed in production (the email classifier's Anthropic key is
local-Python only), so this adds ONE small Cloud Function that reuses the exact
`paperCompile` proxy pattern (Bearer-token verify + lab-member role gate) and calls the
Anthropic Messages API with the snip image:

```
capture modal (snip JPEG data-URI, ≤600px — already produced by E3)
  → POST equationOcr { image }   (Authorization: Bearer <Firebase ID token>)
  → Claude vision, transcription-only system prompt
  → { latex } → fills the LaTeX field + the MathLive visual field
```

**Gate-aware like V3.452:** the modal GETs the function's health probe once per page
load; the ✨ button only appears — and fresh captures only auto-read — after it answers
200. FTP before the function deploy is safe (manual transcription unaffected).

## Server (staged — Alex deploys)

- **NEW functions/equation-ocr.js** — `equationOcr` (v2 onRequest, cors, 256MiB, 60s,
  maxInstances 2, secret `ANTHROPIC_API_KEY` via defineSecret):
  - GET → `equationOcr ok` (the client's gate probe).
  - POST → verify Firebase token → users/{uid}.role ≠ guest → validate
    `{image: data:image/(jpeg|png|webp);base64,…}` ≤ ~1.5MB → Anthropic Messages
    (model `claude-sonnet-5`, const at top; transcription-only system prompt: bare
    LaTeX, amsmath commands, preserve every sub/superscript/accent, `aligned` for
    multi-line, omit printed equation numbers, `UNREADABLE` sentinel) →
    `cleanLatex()` strips fences/$$/\[ wrappers → `{latex, model}`;
    UNREADABLE/empty → 422. Usage tokens logged per call (uid + in/out counts).
  - Node 20 global fetch — zero new npm dependencies.
- **functions/index.js** — require + export `equationOcr`.

## Client

- **rm/js/equation-capture.js** — module-level `OCR_URL` + memoized `_ocrAvailable()`
  health probe + `_ocrTranscribe(snip)` (ID token → POST → latex or thrown error).
  In `_openModal`: `✨ Auto-read` button in the tabs row (hidden until the probe
  passes) + a status line under it. Fresh captures (empty field) auto-read on open;
  the button re-runs on demand (edit flow included — existing captures don't
  auto-overwrite). The auto run never clobbers text the user typed while it was in
  flight; results land in BOTH the LaTeX textarea and the mounted math-field
  (Visual-tab mounts copy `ta.value` themselves). Success note says "check it against
  the snip before saving" — the human verifies, the model types.
- **rm/css/style.css** — `.eqcap-ocr-btn` (teal, right-aligned; `.eqcap-tabs`
  inline-flex→flex) + `.eqcap-ocr-note` ok/err variants.

## Alex's deploy steps (server)

1. One-time secret: `firebase functions:secrets:set ANTHROPIC_API_KEY` (paste an
   Anthropic API key — the same account the local classifier scripts use is fine).
2. `firebase deploy --only functions:equationOcr`
3. FTP order doesn't matter — the ✨ UI self-unlocks once the probe answers.

Cost: one capture ≈ one small image + ~100 output tokens on Sonnet — fractions of a
cent; calls are lab-member-gated.
