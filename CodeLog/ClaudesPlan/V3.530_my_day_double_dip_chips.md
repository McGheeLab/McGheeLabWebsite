# V3.530 — My Day R5: double-dip chips on every input surface

Part of the **My Day program** — see `V3.526_my_day_program.md`.

## Goal
Program decision 3: entering something on ANY surface offers one-tap
cross-posts to the related surfaces — the same engine, driven from the
native composers.

## Approach
`DAY_DISTRIBUTE.renderChipsFloating(ctx)` — a dismissible bottom-center
panel ("Also add to: 🔬 Equipment · 📓 Notebook · ⏱ Tracker …") shown
after a native create succeeds. First tap imports the native doc as a hub
`dayPlans` item (`origin` backref; the origin surface's distribution
record is pre-marked created with `meta.native` so the cascade governs
the native doc and never double-creates). Later taps fan the same item
to more surfaces. `ctx.draft` may be a FUNCTION (notebook passes one so
the title being typed is captured at tap time). The tracker adapter
skips update/remove on `meta.native` records — an imported manual entry
is the user's own record and must never be duplicated by the
deterministic-id upsert.

### Hooks (each ~10 fail-silent lines, guarded `window.DAY_DISTRIBUTE &&`)
- `rm/js/huddle.js` — composer create success.
- `rm/js/lab-notebook.js` — `onNewEntry` (draft-as-function).
- `rm/js/activity-tracker.js` — single-task manual add.
- `rm/js/tasks-buckets.js` — `renderAddSubtask` Enter (no native doc path
  — subtasks live inside bucket docs; the hub item simply fans out).
- `rm/js/equipment.js` — booking modal create success.

Pages gained `day-distribute.js` (+ `activity-signals.js` /
`notebook-schemas.js` where missing): huddle, lab-notebook,
activity-overview, tasks, equipment.

## Deploy
FTP only.

## Verify
Create a huddle plan natively → chip panel appears → tap "📓 Notebook" →
hub item exists with origin = the huddle doc + a notebook stub; editing
that item from My Day updates the original huddle plan. Chips absent →
pages behave exactly as before (fail-silent).
