# V3.378 — Mark section complete → final-form preview in the editor

## Goal

On the protocol editor page, let the author **mark a section complete**,
which flips that section from the editable (markdown-looking) blocks into
a read-only preview where every block renders in its **final form** — the
same output as the read-only document view.

## Design

The read-only "final form" already exists in the doc view
(`protocol-doc.js`). To guarantee the editor preview *is* that final form
(not a diverging copy), the doc-view block renderers were **extracted**
into a shared module both surfaces call.

### Shared renderer (new `rm/js/protocol-doc-render.js`)
`window.ProtocolDocRender.renderBlock(plainBlock, ctx, opts)` — the
read-only renderers for step / callout / materials / figure / heading /
table / kv / timeline / design, plus dispatch to the shared
`ProtocolWidgets` for formula / calculator / builder / layoutMap
(planner) / design. Every renderer takes a `ProtocolWidgets` `ctx`
(prose via `PW.bindProse(ctx,…)`) instead of a module-global, so any
surface can mount it. `protocol-doc.js` keeps only its masthead + boot
and now delegates its block switch to `ProtocolDocRender.renderBlock`
(behavior-preserving; the ~290 lines of inline renderers were removed).

### Editor (`rm/js/protocol-editor.js`)
- Each section carries a `completed` boolean. A **✓ Mark complete /
  ✎ Edit section** toggle in the section header flips it (Yjs
  `ySec.set('completed', …)` → `markDirty` → `render`).
- When `completed`, the section renders a read-only preview: each block
  is dehydrated (`ProtocolBlocks.dehydrateBlock`) and rendered via
  `ProtocolDocRender.renderBlock` into a `.prd-doc.pre-section-preview`
  wrapper (so the doc view's inline-vocabulary styles apply), using a
  whole-protocol read-only preview `ctx` (`buildPreviewCtx`:
  `createContext({readOnly:true})` + formulas from the dehydrated tree +
  `state._math`). The editable inputs and the "+ add block" row are
  hidden; the label input is disabled.
- `state._math` is captured on boot via
  `ProtocolFormulas.ensureMathjs()`, with a one-time re-render so an
  already-complete section resolves its widgets/tokens.

### Persistence + schema
`completed` round-trips through `hydrateSectionToYjs` /
`dehydrateSection` (`protocol-blocks.js`), `newSection` +
`normalizeTree` default it to `false` (`protocol-schemas.js`).

### Loading + CSS
`protocols.html` editor scripts now also load `protocol-widgets.js` +
`protocol-doc-render.js` (doc scripts load `protocol-doc-render.js`
before `protocol-doc.js`). `protocol-editor.css` styles the toggle
(`.pre-section-donebtn.is-complete`), the completed section
(`.pre-section-complete`), and resets the document-page chrome for the
inline `.pre-section-preview.prd-doc` wrapper. `protocol-doc.css` is
already linked in the editor.

## Verification
- `node --check` on all six touched JS files; `newSection`/`normalizeTree`
  default `completed:false` confirmed; doc-view delegation compiles.
- Adversarial review workflow found 4 confirmed defects — all fixed:
  (critical, latent since V3.375) `renderDesign` recursed via the
  refresher bus (registerDataset re-fires it) → fingerprint guard,
  harness-proven to converge; (major) the editor preview mounted no
  refresher bus → materials/forward-dataset stayed stale → bus now
  mounted with cleanup; (minor) remote `completed` toggle didn't
  re-render → section observer handles it; (minor) section label
  observer leaked → now cleaned up each render.
- Pending (browser): open a protocol in the editor, click **✓ Mark
  complete** on a section → blocks render in final form (prose resolved,
  callouts styled, calculators as cards); **✎ Edit section** flips back;
  reload persists `completed`; the doc view is unchanged.

## Note
The completed-section preview is a snapshot at render time (re-renders on
structural edits); it is not live-wired to sliders in other still-editing
sections. Faithful to the final form; full cross-section liveness is a
possible follow-up.
