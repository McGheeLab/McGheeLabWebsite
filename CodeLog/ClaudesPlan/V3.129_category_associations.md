# V3.129 — Category associations on the task-builder card

## Why

Phase 2 of V3.128. The user wants each task-builder card to declare a
small set of *associated categories* (drawn from the seven canonical
categories in [rm/js/yr-shared.js](../../rm/js/yr-shared.js): research,
service, teaching, admin, personal, noise, unknown), and from those
associations a "Suggested from category" panel surfaces every
`proposed:true` subtask whose containing sub-bucket sits in one of the
selected categories. One click pins that suggestion into the current
card. This makes the inbox-pinning workflow card-scoped instead of
forcing a trip to the full inbox view.

## Schema

Add an optional field to the task-builder shape:

```
associated_categories?: ['research', 'service', ...]   // any subset of CAT_ORDER
```

Default: empty array. Absent on existing docs is fine — UI treats it as
empty. Stored alongside the rest of the task-builder doc under
`userData/{uid}/buckets/{id}` via the same `scheduleSave()` path. No
Firestore rules change (the existing `userData/{uid}/{document=**}` rule
covers it). No new index needed (the suggestion walk is in-memory).

## UI

In `renderTaskBuilderHead`:
- Below the existing rollup + buttons row, add a `.tb-cat-chips` row.
- Render seven chips, colored via `CAT_COLOR[c]` when active, gray when
  inactive. Click toggles membership in `tb.associated_categories` and
  triggers `scheduleSave()` + `render()`.

Below the head (still in `renderMain`, above the buckets list):
- If `associated_categories.length > 0`, render
  `renderSuggestedFromCategories(tb)` — a collapsible accordion panel
  styled like the existing buckets accordion.
- Header: "Suggested from {categories}" + count of matches +
  hide-when-empty toggle.
- Body: list of proposed subtask rows. Each row shows the subtask text,
  a `cat:sub_cat` chip (using the source bucket's category), and a
  crumb of the source task-builder + sub-bucket. Right side: a small
  `+ add to…` button.

Picker on `+ add to…`:
- Reuses `openPinMenu` infrastructure but pinned to the current
  task-builder. Renders a popover with the current task-builder's
  sub-buckets + a `+ new sub-bucket` entry.
- Clicking a target invokes the existing `moveNodeTo` (which clears
  `proposed`, reassigns the subtask, and re-renders) — no new
  data-mutation logic.

## Implementation outline

1. **Helpers (top of `tasks-buckets.js`):**
   - `getAssociatedCats(tb)` — returns `Set<string>`; treats missing
     field as empty.
   - `setAssociatedCat(tb, cat, on)` — toggles membership + schedules
     save.
   - `walkProposedByCats(catSet)` — yields `{ subtask, bucket, project,
     parentPath }` for every `proposed:true` subtask whose
     `bucket.category` is in `catSet`. Walks
     `state.doc.taskBuilders → buckets → subtasks` (recursing children).

2. **`renderTaskBuilderHead` extension:**
   - After the existing buttons block, append `renderCatChipsRow(tb)`.

3. **`renderSuggestedFromCategories(tb)`:**
   - Mirror of `renderBucket` styling (uses `.buk-accordion` class).
   - Body uses a stripped-down `renderProposedRow(row, tb)`.

4. **`renderProposedRow(row, tb)`:**
   - Subtask text, source crumb, source category chip, and an
     `+ add to…` button that calls `openAddToTaskBuilderMenu(btn, row,
     tb)`.

5. **`openAddToTaskBuilderMenu(anchor, row, tb)`:**
   - Lightweight version of `openPinMenu`: lists `tb.buckets[]`, plus
     a `+ new sub-bucket` row. Each click resolves to a target bucket
     and invokes `moveNodeTo(row.subtask, row.bucket, tb, target)`.

6. **CSS:** add a small block to [rm/css/style.css](../../rm/css/style.css)
   for `.tb-cat-chips` (flex row, gap, small pill chips) and
   `.tb-suggested-row` (flex row, ellipsis, right-aligned action). Keep
   it minimal — most styling can piggyback on existing `.buk-*` rules.

7. **Hook into `state`:**
   - New `state.suggestedCollapsed: Set<taskBuilderId>` to remember
     accordion open/closed state per card. Default open.

8. **`sw.js`** — `CACHE_VERSION` 105 → 106.

## Out of scope

- Persisting per-card chip color overrides (the existing dashboard color
  swatch is unrelated).
- Filtering by `sub_category` (just by top-level category for now).
- Showing suggestions sourced from outside `proj-inbox/buk-inbox-unfiled`
  (the walker is intentionally generic — any `proposed:true` row counts —
  but in practice today they all live in inbox).
