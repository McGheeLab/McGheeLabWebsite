# V4.80 — the Library keeps a DOI's RIS record, exports .ris, imports .ris

## Why
Gabe: "Library captures .ris from DOI lookup."

The lookup asked doi.org only for CSL-JSON and threw the rest away; a paper could not leave the Library as a reference-manager file, and a .ris file (Zotero, EndNote, Mendeley, a publisher's download) could not come in except one record pasted as text.

## What changed
- **Capture** (`07-library.js`): `LIB.resolveDoi` asks doi.org a second time with `Accept: application/x-research-info-systems` and keeps the record on the item as `ris` (LF lines, ending `ER  - `). Best effort: offline, refused, or an answer that is not a record — the paper still comes from the CSL answer, no error. A paper already in the library without a record gets it when its DOI is looked up again (`LIB.attachRis`), and the paper's sheet has *Get RIS record*.
- **Export .ris**: a paper's sheet (*Export .ris*, ✓ when the publisher's record is kept; otherwise a record is made from its fields by `LIB.toRis` — type, authors, title, journal, year, volume, issue, pages as SP/EP, publisher, ISSN, DOI, URL); the results header (*Select* ticks papers; *Export .ris · n selected*, or with nothing ticked everything listed, so an open search or shelf exports as it reads); a shelf's and a focus's ⋯ menu (*Export as .ris*). The file has CRLF lines and a blank line between records.
- **Import .ris**: *Import .ris…* in the Add panel (one or many files, one or many records each; BOM and CRLF fine), and RIS pasted in the paste box goes the same way. A record makes a new paper; the one with the same DOI (with no DOI: the same title and year) is filled in where it was blank and keeps the record, never overwriting what is there; items from the lab's library (`rm: true`) are left as they are. One undo step; a toast says what happened.
- `LIB.parseRis` now normalises a `https://doi.org/…` DOI and keeps the record text; `LIB.parseRisMany` splits a file (at ER, or where the next TY starts).
- **Features → Library → RIS records** (a switch, on by default): off, the lookup asks doi.org for the data only and the .ris buttons go. The Library description and preview are extended (a sample record and the buttons).
- The Add panel and its lookup are shared by the lab's Library page, so the web build gets the same.
