# V3.289 — Free client-side rules pre-filter for email categories

## Goal

Stop newly-scraped (and existing uncategorized) email from dumping into a single
`unknown` bucket. Sort it into real categories — research / teaching / service /
admin / personal / noise — **for free, at render time**, using a faithful JS port
of the lab's existing Python rules pre-pass. No LLM, no API key, no Cloud Function,
no Firestore writes, no ongoing cost. Manual category overrides always win.

This is the "rules pre-filter only" option the user chose over the (deferred) Haiku
few-shot LLM guesser. The LLM guesser remains the documented next step (the user's
stated preference for it is **auto-on-scrape + a one-time Batch backlog pass**); see
the V3.288 investigation + the `email-ml-categorizer-map` workflow output for that
design.

## Context (why this is the right shape)

The lab already has a complete categorizer — rules → sklearn LogReg → Haiku LLM,
with a train-as-you-correct loop on `category_overrides` — but it is **local-only
Python** (`ResearchManagement/server.py` + `scripts/email_classify_*.py`), run when
the user clicks Import/Run-suggester on `localhost`. None of it is deployed; the
production Gmail scraper writes raw metadata with **no category**, so scraped mail
lands `unknown` (surfaced by V3.288's `_coerceLegacyEmailShape` default).

The **rules pre-pass** (`email_classify_rules.py` + `email_noise_rules.py`) is the
one piece that is pure regex/dict logic — trivially and faithfully portable to JS,
and free to run in the browser on every render. It's the cheapest win.

## Approach

### New file: `rm/js/category-rules.js`
A faithful 1:1 port of the Python rules, exposed as `window.CATEGORY_RULES`:
- `classifyNoise(subject, sender)` → port of `email_noise_rules.classify_noise`
  (`DEFINITE_NOISE_SUBJECTS` + `DEFINITE_NOISE_SENDERS`).
- `guess(email)` → port of `classify_one`:
  1. Noise override first → `{category:'noise', confidence:0.95}`.
  2. `DOMAIN_HINTS` over `from[].email` (one hit per pattern) + `SUBJECT_HINTS`
     over `subject`, accumulating per-category weight.
  3. No hits → `{category:'unknown', confidence:0, needs_llm:true}`.
  4. Else top category by summed weight; `confidence = top/total`;
     `needs_llm = conf < 0.6` (or top/second within 0.25).
- Same category set, same domain/subject patterns, same weights, same noise
  patterns as the Python — preserved verbatim (adversarially verified against the
  source).

### Wire into `rm/js/email-review.js` → `_coerceLegacyEmailShape`
Replace the V3.288 `category: m.category || 'unknown'` line with: if the doc has no
category (no manual/backfill category), run `CATEGORY_RULES.guess()` on the parsed
`from`+`subject`; a real guess sets `category` + `category_source = 'rule'`,
otherwise `'unknown'`. `applyOverrideToEmail` still runs afterward, so a manual
override (`category_source = 'manual'`) overrides any rule guess. `hasRealCategory()`
treats a rule guess as a real category (rule guesses are legitimate buckets, exactly
as the Python pipeline's `final_category` flows them through).

### Render hint: `rm/js/email-review.js` row badge
Next to the category tag, show a small **"guess"** badge when
`category_source === 'rule'` (alongside the existing **"edit"** badge for
`'manual'`), so the user can see at a glance which categories are rule-guessed vs.
confirmed and correct any that are wrong (a correction persists via the existing
`saveCategoryOverrides()` path).

### Load order: `rm/pages/activity-overview.html`
Add `/rm/js/category-rules.js` to the email tab's script list, before
`email-review.js`.

## Key decisions

- **Client-side at render, not a Cloud Function.** Rules are deterministic and free;
  running them in `_coerceLegacyEmailShape` covers both the existing backlog and new
  scraped mail with zero deploy plumbing and zero writes. (A server-side persisted
  version is only worth it once the LLM guesser lands.)
- **Faithful port, not a redesign.** Same patterns/weights/thresholds as the Python,
  so behavior matches the lab's established rules and a later server-side reuse stays
  consistent. Verified adversarially against the source files.
- **Guesses are visibly tentative** ("guess" badge) and never overwrite a manual
  override; correcting one feeds the same `category_overrides` store that the future
  LLM few-shot guesser will learn from.
- **`unknown` still exists** for mail no rule matches — honest, and the target pile
  for the future LLM pass.

## Manual test

- Open the email tab: previously-`unknown` mail from known senders (d2l, nih.gov,
  editorialmanager, amazon, linkedin, mailer-daemon…) now appears under
  teaching/research/service/personal/noise with a small "guess" badge; the
  category chips show non-trivial counts beyond `unknown`.
- A newsletter / shipping / OOO email lands in **noise** (hidden by the default
  filter, which excludes noise).
- Correcting a wrong guess persists (badge flips to "edit") and survives reload.
- Mail matching no rule stays **unknown**.
