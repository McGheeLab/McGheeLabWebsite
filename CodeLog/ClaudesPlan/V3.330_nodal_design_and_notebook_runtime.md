# V3.330 — Nodal design definitions + live notebook runtime (FuturePlan 06)

## Goal

Make a protocol a *reactive definition* authored as a node-based
dataflow graph, and make it "come alive" when opened in a lab-notebook
run: live inputs, a computed item list, assignment of items into grids,
and aggregate totals — frozen into an immutable record when the run
completes. Abstract/domain-agnostic throughout (variables + attributes →
graph → item list → grid assignment → aggregation).

## What shipped

### Phase 0 — shared foundation
- **`rm/js/protocol-widgets.js`** (new) — the interactive widgets
  (`renderFormula/Calculator/Builder/LayoutMap/List` + new
  `renderGridAssignment`/`renderPrepTotals`) lifted from the doc view
  into a per-mount `ctx` model (`createContext`, `recompute`,
  `bindProse`, `mountRefresherBus`). `ctx.onChange` is the persistence
  seam; `ctx.builderState` seeds/persists list-builder session state so
  a run can save it.
- **`rm/js/protocol-doc.js`** refactored to consume `ProtocolWidgets`
  (doc-only chrome stays; interactive kinds delegate). Regression gate:
  the read-only view must behave identically.
- **`rm/js/protocol-formulas.js`** — added `collectFormulasFromPlainTree`
  (consolidates the doc + notebook walkers; handles formula/calculator/
  builder/design) and `aggregatePrep` (pure extensive aggregation:
  per-item quantity × count × factor, grouped by a key, + grand total).

### Track A — node-graph authoring
- **`rm/js/protocol-graph.js`** (new, headless, pure) — node/edge model
  (`input`/`constant`/`choices`/`ordered`/`equation`/`list`), `compile`
  (topological sort, cycle detection, scope inference — per-item iff
  downstream of a generator — emitting the kernel's formula-entry +
  dataset shapes), `assembleRows` (the single source of truth for
  cartesian expansion + per-row derived + declarative dedupe),
  `wouldCycle`, `cartesianPicks`, `rowKey`.
- **`design` block kind** — full add-a-kind across `protocol-schemas.js`
  (factory/normalize/export), `protocol-blocks.js` (`renderDesign` mounts
  the canvas editor over the block's `{nodes,edges}` attrs + raw-JSON
  escape hatch), `protocol-doc.js` (compiles + renders inputs/list),
  `protocol-editor.js` (add-block menu), `protocol-import.js`
  (KNOWN_KINDS/validate/summarize), `protocols.html` (script + CSS).
- **`rm/js/protocol-graph-editor.js` + `rm/css/protocol-graph-editor.css`**
  (new) — vanilla pan/zoom canvas, palette, drag-create, SVG wires,
  socket wiring with cycle + input-only rejection, per-node inspectors,
  equation "insert wired input" helper, live scope shading + error strip.
  Node positions commit once on pointerup; pan/zoom is localStorage only
  (never touches the stored blob).

### Track B — live notebook runtime
- **`rm/js/notebook-schemas.js`** — new `protocol_run` field
  (empty/hydrate/indexRow: `has_protocol_run`, `run_items`,
  `run_frozen`).
- **`rm/js/lab-notebook.js`** — a run panel (rendered outside the
  sanitized body, like the DOE panel): load a referenced protocol into
  the run → mount the definition's live inputs + item lists → grid
  assignment (multi-grid, click-to-assign, replicates, spares) → live
  prep totals (grouped pools + grand total, × multiplier). Reactivity
  rides the existing debounced save + echo-guard. `freezeProtocolRun()`
  on `⏹ End run` snapshots the state immutably and renders a read-only
  record thereafter.

## Storage / deploy

- `design` graph is a plain-JSON `{nodes,edges}` blob on the block attrs
  (single-author, coarse-grained; round-trips through the existing
  generic hydrate/dehydrate branches). `protocol_run` is a field on the
  existing `userData/{uid}/notebook/{entryId}` doc.
- **No Firestore rules/indexes/collections.** Client-only. `sw.js`
  CACHE_VERSION 301 → 302. FTP-only.
