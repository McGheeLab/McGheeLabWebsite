# V3.234 — External Links (Synology integration, Phase 1)

## Goal

Let lab members paste arbitrary URLs (Synology share links, Drive links,
SharePoint, anything) onto four RM surfaces and have them render as a
clickable list. This is **Phase 1 of the Synology integration**: the
zero-infra fallback that ships before any DSM API work.

Phase 2 (folder-convention auto-list via Synology File Station API from
the browser) layers on top of this without re-doing the data model.

## Why now

Students need to reference NAS-stored data (raw microscopy stacks, CAD
files, large datasets) from their lab-notebook entries, task buckets,
project pages, and paper drafts. The current options are "paste the URL
into the rich-text body" (which gets lost) or "describe the path in
prose" (which rots). A first-class `externalLinks[]` field on every
relevant doc makes the references structured + discoverable.

DSM stays off the public internet at UA — the share URLs only resolve
when the user is on UA VPN. Phase 1 acknowledges that with a manual
`private: true` toggle that renders a "🔌 VPN" badge per link. Auto-
detection by hostname is deferred to Phase 2 once the production NAS
hostname is locked in.

## Approach

### Schema

Add this field to four existing doc shapes (no new collection, no rule
change — the field is just additive on docs that lab members already
write):

```js
externalLinks: [{
  id: string,           // 'lnk_' + base36 timestamp + 4 random chars
  url: string,          // raw URL
  label: string,        // human-readable name (filename or description)
  private: boolean,     // true → render "🔌 VPN" badge; default false
  addedAt: string,      // ISO timestamp
  addedByUid: string,   // who pasted it (so admin can see attribution)
}]
```

The four target docs:

| Surface | Firestore path | Field added to |
|---|---|---|
| Lab notebook | `userData/{uid}/notebook/{entryId}` | the entry doc (added to `notebookEmptyEntry()` + `notebookHydrate()`) |
| Task project bucket | `userData/{uid}/buckets/{taskBuilderId}` | the **taskBuilder** object (tier 1, not sub-bucket or subtask) |
| Project / item | `items/{itemId}` | the item doc |
| Paper draft | `papers/{paperId}` | the top-level paper meta doc (NOT the Yjs body) |

Bucket level (tier 1, not tier 2/3) was chosen because files are
typically project-scoped, not sub-bucket-or-subtask-scoped. Adding at
tier 1 also avoids cluttering the Subtask schema, which already carries
~10 fields.

For papers, the meta doc was chosen over the Yjs body because Yjs
schema mutation is heavyweight (needs a Y.Array of Y.Maps + crash-safe
init guards) and external links don't need CRDT — they're not edited
collaboratively at the character level.

### Shared UI component

New file `rm/js/external-links.js` exporting `window.EXTERNAL_LINKS`
with one entry point:

```js
EXTERNAL_LINKS.mount({
  container,        // HTMLElement to render into
  getLinks,         // () => array
  setLinks,         // (newArray) => void; caller persists + re-renders
  readOnly,         // bool; hides Add + Delete affordances
  title,            // optional override; defaults to "🔗 Linked files"
})
```

Mirror precedent: [rm/js/section-comments.js](rm/js/section-comments.js)
parameterizes a chat-thread primitive over `(collectionPath, scope)`.
`EXTERNAL_LINKS` parameterizes the link-list primitive over
`(getLinks, setLinks)` so each caller plugs in its own persistence.

UI:
- Header: `🔗 Linked files (N)` with a chevron toggle (collapsed by default if N === 0).
- Body: list of `[label] [↗ open] [🔌 VPN?] [🗑]` rows.
- Add row: `url` input + `label` input + `🔌 private` checkbox + `+ Add` button.
- Empty state: "No linked files yet."
- Single CSS class prefix `.ext-links-*` in `rm/css/style.css`.

### Each surface

1. **Lab notebook** — [rm/js/lab-notebook.js](rm/js/lab-notebook.js)
   `renderEditor()` mounts the block after `renderAttachmentsHtml()`.
   `setLinks` writes `state.doc.externalLinks` + calls `scheduleSave()`.

2. **Task buckets** — [rm/js/tasks-buckets.js](rm/js/tasks-buckets.js)
   Render in the task-builder header (next to title), wired to
   `taskBuilder.externalLinks`. Save via `scheduleSave()`.

3. **Projects** — [rm/js/projects.js](rm/js/projects.js)
   Render inside the expanded card detail body, wired to
   `item.externalLinks`. Save via `saveItemSurgical(item)`.

4. **Paper drafts** — [rm/js/paper-editor.js](rm/js/paper-editor.js)
   Add a small `🔗 Linked files (N)` button in the topbar (next to the
   existing chrome). Clicking opens a transient popover hosting the
   shared component. Save via direct `firebridge.db().collection('papers').doc(id).set({externalLinks:[...]}, {merge:true})`.

### Gating

- Notebook: owner-only, no admin cross-user view yet — `readOnly: false` always for the current user.
- Buckets: same; no admin cross-user write surface today.
- Items / paper drafts: `_canEditPaper(item)` and equivalent gates are reused — `readOnly` flips when the user can't edit the rest of the doc.

### What gets bumped

- `sw.js` CACHE_VERSION 202 → 203
- New file: `rm/js/external-links.js`
- `rm/css/style.css` — `.ext-links-*` styles appended
- Touched files: lab-notebook.js, notebook-schemas.js, tasks-buckets.js, projects.js, paper-editor.js
- Host pages get a new `<script src="/rm/js/external-links.js">`: lab-notebook.html, tasks.html, projects' research/teaching/service pages, paper-builder.html

## Out of scope (Phase 2)

- Auto-list of NAS folder contents (Synology File Station API).
- Hostname-based auto-detection of `private: true`.
- DSM API token storage at `labConfig/synology`.
- CORS configuration on the DSM side.
- "Open in Synology" deep links / share-URL generation.
- Per-student DSM account model.

## Open questions for Phase 2

- Final production NAS hostname (drives both auto-detect + CORS allowlist).
- Lab-root path on the NAS (`/volume1/lab/projects/`?).
- Shared service-account DSM token vs per-student DSM credentials.
- Do students already have UA VPN as part of their normal workflow, or is "first time on VPN" a friction point we need to handhold?
