# V3.375 — Protocol document view: gold-standard render + full GELS demo

## Goal

User feedback: an imported protocol "looks nothing like" the hand-authored
GELS HTML page, and the polished HTML should become **the standard every
protocol renders in**. This makes the read-only document view
(`protocol-doc.js` + `protocol-doc.css`) mirror that page, and rebuilds
the GELS demo so all of its text is present and it renders as an
almost-perfect replica.

## What changed

### Rendering / theme (applies to every protocol)
- **`protocol-doc.css` retheme** to the GELS design system (CSS vars
  `--prd-ink #17324D`, `--prd-blue`, callout/size palette):
  - **Dark navy full-bleed masthead** (brand name + uppercase tagline,
    white title/subtitle, mono translucent chips) instead of the old
    light cardinal band.
  - Stage headings: blue mono code on a 2px ink top rule.
  - Steps: white circle + blue ring + blue mono number, row separators.
  - Callouts: critical (red rule + tint), note (slate), **assume as a
    boxed blue panel**, timing as a green mono pill.
  - **Calculator card**: dark head bar (title + optional formula key),
    two-panel body (inputs left on a tinted panel with a divider,
    outputs right); hero cards get a functional-orange top border.
  - **Plate map**: dark `#20303F` panel with **circular** wells, mono
    sublabels, tinted size-keyed fills.
  - Print rules keep the dark masthead / plate / head bar
    (`print-color-adjust: exact`).
- **`protocol-doc.js`**: masthead renders brand name + `attrs.tag`
  tagline; `renderDesign` no longer double-wraps in a card and passes
  a `formula` key + clean list columns (dim labels + derived fields).
- **`protocol-widgets.js` `renderCalculator`**: restructured to the
  head-bar + `.prd-calc-body2` two-panel layout (`.prd-calc-inpanel` /
  `.prd-calc-outpanel`); an empty input panel collapses so a
  table-only calculator spans full width. Accepts `attrs.formula`. All
  driver/reseed logic preserved.
- **`ProtocolGraph.designInputsOutputs(res)`** (new, exported): maps a
  compile result to calculator input/output specs shared by the doc
  view and the notebook run — **ordered sets now expand to one slider
  per member** (previously only the first member showed), param
  overrides attach as `drivers`. Both `renderDesign` and the notebook
  `_runMountDesign` use it.
- **Live datasets**: `renderDesign` (doc) and `_runMountDesign`
  (notebook) now reassemble + re-register their compiled lists on every
  recompute (pushed as a refresher before downstream list/plate/table
  consumers), so moving an input slider updates the condition list, the
  plate map, and the per-condition table live.

### Content — full GELS demo
`Data/protocols/gels-granule-coating.protocol.json` rebuilt as an
almost-complete replica of the HTML page:
- **13 sections = the 13 HTML stages** (each section auto-renders one
  stage heading), carrying all prose: design rationale + the n_F
  derivation, both consequences, the full assumptions panel; materials
  (reagents + equipment tables) + critical callout; the node calculator;
  the plate map; the per-condition table; equilibration, pools, coating
  (with the coating timeline), ratio mixing, plating, assembly,
  maintenance, collection stages; and the derivation/validation
  appendix (kv + validation + polydispersity notes).
- The **design (node) block** is the live engine: an ordered S/M/L size
  set, ratio + inert-size choices, per-item equations (n_F, F vol, I
  vol, cell suspension), three scalar loading equations (hero cards),
  and a `conditions` list that de-dupes f=1 across inert size
  (coat-once/split-later). A constant drives the bed-volume slider max
  (param binding). The list feeds the plate map and per-condition table.
