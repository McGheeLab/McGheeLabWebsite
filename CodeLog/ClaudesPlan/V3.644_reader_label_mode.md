# V3.644 — Label mode in the reader + a multi-type page classifier

## Goal

Two asks, one release.

**Alex (algorithms):** *"try some new algorithms to classify the parts of a
paper. Make many candidate feature detectors. treat the paper as an image
maybe then look at it as a textured landscape or send it through image
feature detection algorithms. by the way some of my custom labels were
abstract, title, authors, special notes."*

**Alex (product):** *"on the paper reader on the real site, i want a mode
that allows me to see all the labels on a paper. I should also be able to
correct the labels, for training purposes later, and to fix the current
paper that im reading. this will allow us to get better and better over
time. This toggle should be at the bottom of the left side column."*

The second is the answer to the first. Nine labelled papers is not enough
to train anything; a correction loop inside the reader is how the training
set actually grows.

## Part 1 — the measurement (training lab, LOCAL ONLY)

New Python lab at `ResearchManagement/data/figure-training/lab/`. Nothing
here is deployed.

| file | what it does |
|---|---|
| `render.py` | `pdftoppm` every training PDF to 150-DPI PNGs + a `meta.json` recording the exact per-page scale (labels are PDF points, pixels are points × dpi/72). Verified by overlaying labels on a raster. |
| `featbank.py` | **103 candidate feature detectors** in two families (below). |
| `dataset.py` | labels + rasters + `feat-*.json` → a feature matrix; samples background regions so a classifier learns "none of the above". |
| `retag.py` | splits the 36 bare `custom` labels into title / authors / affiliation / abstract / keywords / note. |
| `bakeoff.py` | per-class one-vs-rest AUC per feature, family ablation, leave-one-**paper**-out report. |
| `perclass.py` | the honest version of the ablation: per class, top-K features from TEXT / IMAGE / BOTH. |

### The IMAGE family — the page as a textured landscape

49 features, none of which read the text layer: ink statistics; **row-profile
autocorrelation** (body text is a comb — a sharp peak at the line pitch;
figures have none); column rhythm; connected-component statistics (count,
density, height median/CV, aspect, largest-blob fraction); **stroke width**
via distance transform (text keeps one pen, line art does not); 8-bin edge
orientation histogram + entropy; an **8-filter Gabor bank** (4 orientations
× 2 frequencies); colour saturation; grey-level entropy; Laplacian energy;
black/white run-length statistics; left-edge raggedness; projection peaks.

### The TEXT family

54 features: font height relative to the page median, height CV, line pitch
and its regularity, alignment (left/right edge CV, centeredness), glyph-class
ratios (digit / upper / alpha / **math** / punctuation / space), word length,
normalised geometry, `is_first_page`, and 16 lexical triggers.

### What the measurement said

**Does the image idea pay off?** In bulk, no — dumping 49 image columns in
*lowers* leave-one-paper-out macro-F1 (TEXT 0.739, IMAGE 0.397, BOTH 0.678).
That is dilution, not a verdict. Curated per class, it clearly pays:

| class | TEXT | IMAGE | BOTH |
|---|---|---|---|
| **figure** | 0.923 | **0.939** | **0.977** |
| **abstract** | 0.446 | 0.688 | **0.806** |
| **affiliation** | 0.725 | 0.589 | **0.943** |
| **authors** | 0.958 | 0.142 | **1.000** |
| equation | 0.985 | 0.978 | **1.000** |
| reference / table | **1.000** | — | 1.000 |

(leave-one-paper-out average precision, top-10 features per set)

BOTH wins 6 of 10 classes, and the two largest lifts — abstract +0.36,
affiliation +0.22 — come from image features. The single best separator for
**figure** is `cc_h_cv`, the coefficient of variation of connected-component
heights: text is uniform glyph heights, artwork is not. That is exactly the
"textured landscape" intuition, and it is measurable.

Two findings about the labels themselves:

- **`reference` means the INLINE citation marker** — "(1–4)", "[7]" — not the
  bibliography. Size alone separates them (`w_rel`, `col_span`, `area_rel`,
  `h_rel` all at AUC **1.000**). An earlier detector aimed at the reference
  *list* proposed 336 boxes for 24 real ones.
- **`text` means a COLUMN RUN**, not a paragraph. Alex's boxes span several
  paragraphs and swallow section headings.

## Part 2 — `rm/js/page-regions.js` (new)

`PAGE_REGIONS.detect(items, {pageWidth, pageHeight, pageNum, numPages,
inkProbe})` → `[{x,y,w,h,t,label,conf}]` in **natural coordinates**, over 13
types. It reuses `PAGE_LAYOUT.figureRegions` for figure/table (the two
classes V3.643 already does well) and adds column-aware blocking, inline
citations, equations, front matter and running heads.

Scored per type against Alex's labels (`score-regions.mjs`, IoU ≥ 0.5; ≥ 0.3
for the tiny citation boxes):

```
figure     31/37 (84%) recall   84% precision   IoU 0.92
table        3/4 (75%)           75%            IoU 0.88
affiliation  4/5 (80%)           80%            IoU 0.70
title        5/7 (71%)           63%            IoU 0.83
text       37/87 (43%)           18%            IoU 0.80
equation    5/19 (26%)           17%            IoU 0.66
reference   6/24 (25%)            5%            IoU 0.84
```

Structural bugs the scorer caught and the fixes:

1. **Lines interleave between columns.** Sorted by y, a 2-column page
   alternates left/right, so every block-merge overlap test fails and every
   paragraph comes out as a stack of one-line blocks (2601 predictions for
   87 truths). Fixed with a gutter histogram + per-column blocking.
2. **Full-width lines hide the gutter.** A title or spanning caption bridges
   it, so a zero-coverage scan finds nothing — angelini page 1 came back as
   one 2-column-wide "text" run 579px tall. Only column-width lines vote.
3. **A spread-out author line is one row, not three.** `_lines` splits at any
   gap wider than a gutter, which is right for columns and wrong for
   "Zaman Ataie¹    Sulin Zhang²…". Stitched back — **page 1 only**, because
   the same stitch glues the scattered pieces of a display equation into one
   row and destroys them.
4. **Display equations arrive as confetti.** pdf.js emits superscripts,
   denominators and fraction bars at their own y, so one equation shreds into
   a dozen fragments (187 predictions). `_mergeNear` glues neighbours back and
   drops the strays; 187 → 28.
5. **The headerless-abstract guess fires on body columns.** Allowed once per
   page and only in the upper half.

## Part 3 — Label mode in the reader

- **`rm/js/paper-label-mode.js`** (new) — the toggle, palette and overlay.
- **`rm/css/label-mode.css`** (new).
- **`rm/pages/library-paper.html`** — stylesheet, the two new scripts, and a
  `.plm-host` div at the **bottom of `.lp-side-inner`**, as asked.
- **`rm/js/library-paper.js`** — `init` beside the other per-paper modules,
  `destroy` in `_detachActive`, and an `onPageReady` hook that repaints when
  the mode is on and otherwise just `prime()`s the stored labels.
- **`rm/js/figure-capture.js`** — snip hotspots prefer corrected labels.
- **`firestore.rules`** — `papers/{paperId}/pageLabels/{pageId}`.

Storage `papers/{paperId}/pageLabels/{page}`:
`{page, nw, nh, boxes:[{id,x,y,w,h,t,src,by,label}], updatedAt, updatedBy}`.
Natural coordinates, so boxes survive zoom and re-render. `src` is `auto`
(detector output, untouched), `edited` (an auto box a human moved or
retyped) or `human` (drawn from scratch) — that distinction is what makes
the export useful for scoring.

**Why a correction fixes the paper.** `PAPER_LABEL_MODE.regionsFor(page)`
returns corrected figure/table boxes, or **null** when no human has touched
the page — so every untouched paper still runs on live detection, and one
correction re-points the click-to-snip hotspots for everyone.

**Why it feeds training.** `⤓ Export labels` writes the same JSON shape the
offline harness reads, filtered to boxes a human vouched for.

UI: 13-type palette with counts and per-type show/hide; click a chip to
retype; 8 drag handles to resize; `×` to delete; arm a type and drag to
draw. Autosaves ~0.9s after a change.

## Bugs found by testing, not by reading

- **A tiny box under a big one is unclickable.** The inline-citation box sits
  inside a body-text run; painted in store order it is unreachable. Boxes now
  paint **largest first**. (The same class of bug as V3.643's harness ✓
  button.)
- **You could not draw over an existing box.** Arming a type now puts the
  layer in `plm-drawing` mode and existing boxes drop `pointer-events`.
- **`_flush()` read module state after its first `await`.** `destroy()` calls
  it and then immediately clears `_paperId`/`_pages`, so page 2+ of a
  multi-page save would have written the outgoing paper's labels into the
  incoming paper — exactly the tab-switch bug figure-capture hit in V3.621.
  Everything is snapshotted synchronously now; `_load`/`refreshPage` bail if
  the paper changed mid-await.

## Next

The background workflow's `det-text.mjs` scores **text 77% recall / 64%
precision / IoU 0.95** against the same labels — far better than the 43%/18%
in `page-regions.js`. Its transferable ideas: body size = the height carrying
the most **ink width** (not the median item height, which halves on a page
full of 4px tick labels); an asymmetric keep-window `[0.92, 1.30]·bodyH`;
cut the reference list at the first numbered-citation opener; reject a run
unless ≥40% of its lines share a left edge. Fold those in, then re-score.
