# V3.423 — Pass-through connectors (bound vars re-export on the right)

## Context

Alex: "in any node, any variable that we connect with on the left side
should also get a connection point on the right side so we have access
to that variable downstream — this avoids unnecessary clutter for the
line tracing in the panel." I.e. chain the NEXT node from the nearest
card instead of dragging a wire all the way back to the producer.

## Design decision

A pass-through wire is a REAL edge whose `from` is the re-exporting
node and whose `sourceVar` names a variable that node merely receives.
This keeps topo ordering correct for free (re-exporter sits after the
true producer, so the consumer still compiles after both) and needs no
schema change — only resolution: anywhere the kernel/editor matched
`e.sourceVar` against `producedVars(e.from)`, it now falls back to the
graph-wide name table (names are validated unique). producedVars
itself is untouched, so duplicate-name validation can't false-fire.

## Kernel (`rm/js/protocol-graph.js`)

- **`passThroughVars(graph, node)`** (exported): vars arriving on math
  + param edges, resolved to their true definition (via `_varsByName`),
  in edge order, deduped, minus names the node itself produces.
  Chained re-export works (a pass-through edge in → re-exported out
  again) because resolution is by name. STRUCTURAL feeds are excluded:
  compile reads a list generator's node TYPE from `e.from`, so
  generators must wire from their true producer.
- Pass-through-aware resolution fallbacks in `equationAliases` (pad
  aliases resolve the true var), `nodeSockets` (labels/categories),
  and compile's code-node `argNames`. Constant value-drivers and
  paramOverrides already used the stored sourceVar verbatim — correct
  as-is. `wouldCycle`/topoSort/inferScopes operate on the node graph
  and needed nothing.

## Editor (`rm/js/protocol-graph-editor.js` + CSS)

- **`_passDot(n, sv)`** — a right-side out-dot for a received var,
  rendered on its bound row: equation/code OPERAND rows and
  driven SETTING rows (min/max/…); the constant's value row is skipped
  (the card's own out-dot already mirrors the driven value; two dots
  would overlap). One per variable per card (socketOut dedupe);
  rendered for read-only viewers too, since pass-through wires anchor
  on it. Colors resolve through V3.422's qtysCache — mixed vars wear
  the conic pie on the ring.
- `.pge-socket-pass` (CSS): the dot renders as a RING of the
  variable's color (white ::after center) = "passes through, not
  produced here". Dragging it wires exactly like any out-dot
  (`makeOutDot` registers `_out` + socketOut, so drawWires, candidate
  marking, and addBinding all work unchanged).
- `_edgeSourceVar`/`_edgeCategory` accept pass-through names via a
  per-render `ptCache` (`_ptVars`), so existing render/draw paths
  resolve pass-through edges without falling back to the wrong var.
- Cheatsheet gains the "Chain onward" line; the exploratory equation
  tour gains a **"Units travel — and cancel"** step teaching both
  V3.422 (composite units chain + collapse; doc prints them) and the
  ring dots.
