# V3.318 — Protocol builder: calculator upgrade (FuturePlan 03, Release 3)

## Goal

Third release of FuturePlan 03: a `calculator` block with rich inputs
(sliders / number rows with range hints), hero-card outputs, and a
computed table whose columns are expressions evaluated per row over a
named dataset. This is the gold-standard calculator stage.

## Block shape

```
kind: 'calculator'
body: '' (unused)
attrs: {
  label, description,
  inputs:  [{name, label, widget:'slider'|'number', min, max, step,
             unit, rangeHint, default}],
  outputs: [{name, label, expr, unit, decimals}],        // hero cards
  table:   {dataset:'', columns:[{label, expr, align, mono, decimals}]}
           // dataset names a registered dataset (Release-4 builder
           // output); empty dataset ⇒ table hidden
}
```

All attrs are plain JSON values on the attrs Y.Map (Release-2
precedent).

## Engine extension (the one real addition)

- `collectFormulas` (Y walker) + the doc view's plain walker now ALSO
  visit `calculator` blocks: `inputs[]` become symbol-table variables,
  each `outputs[]` entry becomes a formula entry
  `{expression: expr, output: {name, label, unit, decimals}}`. So
  `buildSymbolTable` is reused unchanged, calculator outputs land in
  the same table, and `[!var:]` prose tokens / docHeader chips see them.
- **Named datasets registry** (`ProtocolFormulas`):
  `registerDataset(name, rows)` / `getDataset(name)` /
  `listDatasets()`. Registering re-emits `protocol-vars-changed` so
  computed tables refresh. Release 4's builder writes here; nothing
  registers datasets yet in this release (the seam ships first).
- `evalExpression(expr, table, math, extraScope?)` — evaluates a mathjs
  expression under the numeric symbol-table scope with an optional
  per-row scope merged on top (row fields shadow globals). Returns
  `{value}` or `{error}`. This powers computed-table cells.

## Rendering

- **Editor** (`protocol-blocks.js` `renderCalculator`): config grids
  for inputs / outputs / table columns + dataset name, plus a live
  outputs preview strip that refreshes on `protocol-vars-changed`
  (mirrors the formula block's preview). Sliders themselves render in
  the doc view; the editor stays an authoring surface.
- **Doc view** (`protocol-doc.js`): slider rows (`<input type=range>` +
  live value + unit + rangeHint) and number rows per `widget`; edits
  write session-local overrides and recompute; hero cards grid for
  outputs; computed table evaluates each column expr per dataset row.

## Rollback

Client-only; old clients coerce `calculator` to `step` on render.
