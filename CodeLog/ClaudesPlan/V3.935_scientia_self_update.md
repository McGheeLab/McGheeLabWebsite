# V3.935 — The installed Scientia updates itself

## Goal

Gabe (27 Oct 2026): any change to the lab's Scientia should reach the installed app on its own, without downloading the
zip again. The same day showed why: the lab's V3.932 bridge (computer and cloud joined, never replaced) was in the
site's download within the hour, but an installed computer kept the old bridge until someone installed the download by
hand. (First numbered V3.930; renumbered, the lab's session had taken V3.930–V3.934 meanwhile.)

## Approach

- **service.py updates the app** (it already keeps the server running): two minutes after it starts, then every hour, or at
  once from Settings → The lab → Check for updates now (an `update-now` file next to the app folder), it reads the site's
  `rm/scientia/desktop/version.json`. When `app` differs from the installed `VERSION.txt`: download the zip, check it
  against `sha256` (a deploy caught half way fails here and is tried again in ten minutes), unpack it beside the app
  (`update/`), check it is that version, stop the server through `/api/lab/quit` (which now saves a pending change first —
  `serve.py` `shutdown()`), put the new files in place (files the new app no longer has are removed; the app folder's own
  `images`, `recordings`, `backup` stay), and start again from the new `service.py`. About six seconds. `update.json`
  says what it is doing; a checkout (no `VERSION.txt`) never updates.
- **The open tab** (`23c` `THISPC.watch`): it asks its server for the version every minute; a new one reloads the tab when
  it is in the background, or shows "Scientia was updated — Reload".
- **The download never lags the site**: `deploy.py` `scientia_build_if_stale` also rebuilds when the lab layer, the bridge,
  RM's recorder scripts, the app's server, installer or icons are newer than the web build or the download. So a lab-layer
  or bridge change reaches every installed computer within the hour.
- `version.json` carries the full `sha256` of the download.

## Tested

A scratch install of the current download, a stand-in site offering a repacked "version 2", the real `service.py`: updated
and running again in seconds; a note written seconds before the update survived; the app's own `images` kept; status
"updated"; a download with a wrong checksum refused with the reason, the app left as it was.
