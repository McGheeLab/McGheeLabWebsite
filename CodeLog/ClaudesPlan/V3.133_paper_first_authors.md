# V3.133 — First-author marking on papers (Phase 1: data + UI)

## Why

User report: "on research\papers\personnel I want to be able to select
one or two people that are first authors of the paper, they will have
higher administrative rights to the paper than others."

Two parts:

1. **Mark 1-2 personnel as first authors** of a paper item — schema +
   UI work, scoped to `item.type === 'paper'`.
2. **First authors get higher admin rights to the paper** — access
   control work; needs a clear definition of *which* actions are
   first-author-only before I wire `firestore.rules` and the in-page
   gate. Deferred to V3.134 pending user clarification.

V3.133 ships Phase 1 in full so the user can mark first authors today.

## Schema

New optional field on paper items:

```
first_author_uids?: string[]   // values match entries in personnel[]; cap 2
```

- Each entry is a string id (legacy slug or Firebase uid) — same shape
  as `personnel[]` so the cross-reference is direct.
- Cap: 2 entries (per the user's "one or two"). UI enforces; helper
  silently truncates if a programmatic write violates.
- Default missing → empty. No migration of existing items needed.

## UI

In `renderPersonnelSection(item)`:

- When `item.type === 'paper'`, render a star button **before** each
  personnel chip's name. Filled gold star = first author, hollow gray
  star = not.
- Click toggles membership in `first_author_uids`. If adding a third
  star would exceed the cap of 2, alert and abort.
- Clickable only for admins. Non-admins see the same icons (so the
  status is visible to everyone) but the click is a no-op + a tooltip
  reads "Only admins can change first authors". This matches the
  existing pattern around shared-doc admin actions (see V3.126's
  Members section gating via `firebridge.isAdmin()`).
- Add a section-level helper text under the chips when at least one
  first author exists: `"⭐ First authors have higher admin rights to
  this paper. (V3.134)"` — explicit forward-pointer to the gating work.

New global handler:

```js
window.toggleFirstAuthor = async function (itemId, pid) {
  // admin gate, cap of 2, mutate _allItems in place, saveItemSurgical(it).
}
```

CSS additions:

- `.first-author-star` — filled, gold, click target
- `.first-author-star.off` — hollow, gray
- `.personnel-chip.first-author` — subtle gold tint to make the row pop

## Out of scope (Phase 2 / V3.134)

- The actual *enforcement* of "higher administrative rights":
  - Should first authors (and only first authors + admins) be allowed
    to edit paper metadata?
  - Should first authors be the only ones who can add/remove other
    personnel?
  - Should first authors gate the V3.126 Members assignment too?
  - Should first authors be the only non-admin role allowed to delete
    the paper?
  - All of the above? Some combination?
- The corresponding `firestore.rules` changes (would require an
  `isFirstAuthor()` helper at the top of the file alongside `isAdmin()`,
  `isLabMember()`, etc., plus per-write conditional logic for `paper`
  items).

V3.134 will land once the user clarifies the rule set.
