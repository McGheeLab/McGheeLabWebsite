# V3.312 — Alumni Grouped by Type (main site)

> Implements [FuturePlan 02](../Feature%20requests/FuturePlan_02_alumni_by_type.md) in full (single release).

## Goal

The public team page shows one flat Alumni section. Subdivide it by what
the member was *before* they graduated (`priorCategory`), and add
`masters` as a first-class category so current MS students get their own
active section and MS alumni group correctly.

## What exploration confirmed (2026-07-11)

- `content.json` has **no** `team` key — the team page is rendered
  entirely by the Firestore overlay in `app.js` (Pass 3, ~line 965+),
  which groups `users` docs by `category`. The static `renderTeam()`
  categories list only matters as a fallback/labels source.
- `priorCategory` is already stamped by the **admin** user editor when a
  category flips to alumni (`user-system.js` ~4824), but:
  - it is **not** stamped by the self-service profile save (~1664) — gap;
  - it is **not editable** anywhere — spec says add it to the admin editor.
- `masters` is missing from `CATEGORIES` / `CATEGORY_DEFAULT_ROLE` /
  both app.js category lists.

## Locked decisions (from FuturePlan 02)

- Alumni subdivide by `priorCategory`, display order:
  postdoc → grad ("PhD") → masters → undergrad → highschool;
  missing/unknown → generic "Alumni" bucket (rendered last).
- One-time manual reclassification of existing MS alumni via the admin
  editor — no migration script.
- Team page keeps reading `users` (not `teamProfiles`).

## Decisions made in this plan

- `CATEGORY_DEFAULT_ROLE.masters = 'editor'` — masters students are
  graduate students; matches `grad`/`postdoc`, not `undergrad`.
- Subsection labels: Postdoctoral / PhD / Masters / Undergraduate /
  High School / Alumni (unknown bucket) — matches existing section-label
  style.
- Admin editor gets an explicit "Prior category" dropdown in the edit
  panel (non-guest rows). An explicit selection wins over the flip-to-
  alumni auto-stamp; empty selection keeps the auto-stamp behavior.
- Self-service profile save also stamps `priorCategory` on an
  active→alumni flip (same rule as the admin path) so self-flipped
  alumni don't all land in the generic bucket.
- Each alumni subsection gets its own `.team-grid` + detail panel wired
  through the existing `wireTeamDetailPanel` — no changes to the panel
  machinery.

## Verification (from the spec)

- Flip a test user to alumni from each prior category → right subsection.
- Alumnus with no `priorCategory` → generic "Alumni" bucket, no crash,
  no empty headers.
- Active `masters` user → "Masters" section among active members,
  ordered after Graduate.
- Reclassify one real MS alumnus via the admin editor's new dropdown →
  public page regroups them.

## Rollback

Client-only: git revert + re-FTP + CACHE_VERSION bump. `priorCategory`
edits are ordinary user-doc fields, harmless to leave.
