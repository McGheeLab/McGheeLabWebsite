# V3.608 — Default highlight palette (the real "students can't highlight" bug)

## Symptom

Cason Hancock (role `editor` — a full lab member since at least 2026-07-26)
could not create highlights in the paper reader, but COULD select text and
capture equations. Alex assumed a permissions gap and granted V3.605
capabilities — which didn't change anything.

## Diagnosis (server-side forensics, 2026-08-07)

- Deployed firestore.rules (Aug 1 AND Aug 7 rulesets) already allowed
  `isLabMember()` to create annotations — the server never blocked him.
- Cason has ZERO annotation docs anywhere; lab-wide, ONLY Alex has ever
  created annotations (2 docs). No student highlight ever landed in prod.
- `library/highlight_colors.json` is a **per-user** route
  (`userData/{uid}/libraryPrefs/highlightColors`, rm/js/api-routes.js:440).
  Alex has a 6-color doc; Cason — and every other member — has none.
- `library-paper.js _loadColors()` set `_colors = (data && data.colors) || []`
  — an empty/missing doc yields `[]` WITHOUT throwing, so the yellow
  fallback (throw-only) never fired.
- `annotation-overlay.js _showToolbar()` renders one button per color. With
  zero colors the create toolbar contains ONLY the ƒ equation-capture
  button and ×. **No highlight buttons exist for any user without a saved
  palette.** Equation capture doesn't need colors — hence the exact
  symptom split.

Permissions were never involved. (Side finding: Alex's capability grant on
the Permissions page never wrote to Firestore — Cason's `userPermissions`
updateTime is still 2026-07-27 — worth re-testing the caps save flow, but
irrelevant to this bug since members don't need caps.)

## Fix

`DEFAULT_COLORS` — the lab's canonical 6-color palette (identical to Alex's
saved doc and the dev seed JSON: Note/Evidence/Critique/Method/Investigate/
Quote) — baked into:

- [rm/js/library-paper.js](../../rm/js/library-paper.js) `_loadColors()` —
  used when the loaded list is empty OR the load throws.
- [rm/js/library-comments.js](../../rm/js/library-comments.js)
  `_loadColors()` — same fix (empty palette blanked the legend, color
  filter, and color-change dropdown there). Keep both constants in sync.

A user's saved palette still overrides the default. No Firestore writes, no
rules change — **FTP-only**. sw → 578 (concurrent sessions took 575-577).

## Manual test

1. As any lab member with no saved palette (Cason), open a library paper,
   select text → the toolbar now shows 6 color swatches + ƒ + ×.
2. Click a color → highlight saves and appears in the panel (verify a doc
   lands under `papers/{id}/annotations`).
3. As Alex (has a saved palette) → toolbar unchanged (his 6 colors).
4. Comments tab: color legend and per-card color dropdown populated for
   palette-less users.
