# V3.237 — Calendar / activity-row phone card layout (Phase 3b of mobile compatibility)

> Phase 3b of the broader RM mobile-compatibility plan (full plan: `~/.claude/plans/i-want-to-make-rosy-scott.md`). V3.232 shipped tokens; V3.233 shipped the shell; V3.235 shipped paper-builder + library-paper drawers; V3.236 anchored the page on phone. **V3.237** fixes the worst remaining mobile breakage: the `.yr-line` and `.ch-line` activity rows used by `activity-overview.html`, `calendar.html`, and `email-review.html` overflow phone screens by ~280px because they're hardcoded to a desktop 7-column / 6-column grid.

## Goal

Convert the two activity-row patterns to a phone-friendly 2-row card layout at ≤640px while keeping the desktop grid byte-identical above 640px. Plus housekeeping: round three more scattered breakpoints (huddle 700×2, year-review 900, email-review 900) to the canonical 640/1024 set.

## Problem

The current `.yr-line` rule (`rm/css/style.css:1064`):

```css
.yr-line {
  display: grid;
  grid-template-columns: 28px 16px 110px 1fr 160px 120px 90px;
  ...
}
```

The columns are select / caret / date / main / meta / stars / actions. Minimum content width: 28 + 16 + 110 + ~100 (main) + 160 + 120 + 90 + 6×gap = ~684px. A 390px iPhone shows the first 3-4 columns and the rest is clipped or pushed off-screen (V3.236 `overflow-x: hidden` clips it cleanly but the user can't see meta/stars/actions).

`.ch-line` (`rm/css/style.css:1140`) has the same problem with 6 columns totaling ~660px minimum.

## Approach

CSS-only `@media (max-width: 640px)` block per rule using `grid-template-areas` to remap the same child elements into a 2-row card:

**`.yr-line` phone layout:**
```
| select | main (title + sub)    | actions |
|        | date                  | stars   |
|        | meta                  | meta    |
```

3-column grid (`var(--tap-min-compact) 1fr auto`):
- Row 1: select (left) + main (center) + actions (right)
- Row 2: date (under main) + stars (right)
- Row 3: meta (full width under main)

The caret column is hidden (the row-expand interaction is already triggered by tapping the row itself; the caret is redundant on touch). Title + sub `.col-main` text loses its `white-space: nowrap` so it wraps to 2 lines instead of ellipsis-truncating — more useful on a narrow screen.

**`.ch-line` phone layout:**
```
| main (title + sub)         | actions |
| date              | meta   | stars   |
| cat (chip)        | cat    | cat     |
```

3-column grid (`1fr auto auto`):
- Row 1: main + actions (actions spans full right edge)
- Row 2: date + meta + stars
- Row 3: category chip (full width)

## Why this fix vs. horizontal scroll or larger column hiding

Three patterns were considered:

1. **Hide secondary columns on phone** — only show main + actions. Simple but throws away date/meta/stars entirely. User can't see date of an activity, which is the single most useful field after the title. Rejected.
2. **Allow horizontal scroll within `.yr-line`** — `overflow-x: auto` on the row. Works but users hate horizontal scroll in vertical lists; they don't discover the hidden columns. Rejected.
3. **Stack into a card** — what this version does. Same data, just two rows instead of one. Each row is still scannable; the user reads top-to-bottom instead of left-to-right. Adopted.

## Verification

1. **Desktop ≥1024px** — `/rm/pages/activity-overview.html`, `/rm/pages/calendar.html`, `/rm/pages/email-review.html`: pixel-identical to V3.236.
2. **iPhone 14 Pro (390px) emulation** — every `.yr-line` and `.ch-line` row renders as a clean 2-row card with title wrapping at the natural word break, no horizontal scroll, all metadata visible.
3. **Tap interaction unchanged** — tapping anywhere on the row still expands the detail panel (the row click handler hasn't moved; only `display: grid` template changed).
4. **Bulk-select still works** — `.col-select` is still in the DOM and clickable; phone users can still multi-select rows.

## Out of scope

- **`.arc-row` archive layout** — V3.233 already added a phone block for `.arc-row` so it's good.
- **Calendar tab bar** — the `.cal-tabs` row that hosts History / Outlook Events / Availability / Analytics will stay horizontal-scroll; the desktop layout already has `flex-wrap: wrap` so it's adequate on phone.
- **Outlook events grid** — separate component, not touched here.
- **Tasks inbox / chat / lab notebook** — JS-touching changes, separate ship (V3.238+).
- **Training breakpoints** — training.css has 7 scattered breakpoints (420/520/600/720×3/820/900). Standardizing those touches many feature surfaces; deferred to a focused training cleanup ship.
