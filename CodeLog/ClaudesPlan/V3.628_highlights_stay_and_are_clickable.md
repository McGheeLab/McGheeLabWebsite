# V3.628 — Highlights stay put, are clickable, and the drafts control is one control

Three items from Alex's test pass on the V3.619-622 program:

1. *"when i highlight something on the paper it should stay there.
   currently if i select add to draft or link draft the highlight goes away.
   it moves to the comment page correctly, but the highlight gets dropped
   from the paper."*
2. *"why is there a link to drafts dropdown and a link to drafts button
   right next to each other on the highlight card"*
3. *"any highlight that is on the page should be a clickable surface to
   edit the comment or see the comment."*

## 1. Filing a highlight no longer hides it (regression from V3.619)

`cite_in_drafts` does double duty: it's both "which draft is this evidence
for" AND the key the draft-overlay lens filters on. `getFilterFn` was:

```js
if (!ids.length) return true;              // no drafts → always show
return ids.some(id => _active.has(id));    // has drafts → needs its overlay ON
```

So the instant a highlight got filed to a draft it stopped matching the
"always show" branch and started *requiring* that draft's overlay to be
active — otherwise it vanished from the page. This was dormant before
V3.619 only because the create path wrote the dead `bucket_ids` field, so
hand-made highlights always had an empty `cite_in_drafts`. Making filing
work switched the hiding on. (V3.619 also stopped clobbering the saved
overlay set to all-on, which made an inactive draft more likely.)

**Fix** — the lens must be opt-in, never silently destructive:

- `_isNarrowed()` — true only when at least one **linked** draft has been
  switched off. The default state (all linked drafts active) means "no
  lens", and `getFilterFn` returns true for everything. Turning an overlay
  off still narrows exactly as designed.
- `activateDraft(draftId)` (new export) — filing a highlight to a draft
  brings that draft into the lens, so even mid-narrowing the thing you just
  filed cannot disappear. Called from `onCiteToggle` (panel dropdown) and
  from `onCreate` for the popover's "File to:" chips.

Regression-tested in a real page: with no lens engaged,
`getFilterFn()({cite_in_drafts:['x']})` now returns `true` (it returned
`false` before — that was the bug).

## 2. One drafts control, not two

The card's Drafts row carried a `+ add draft…` **select** (files THIS
highlight → `cite_in_drafts`) next to a visually identical
`+ Link draft…` **button** (links a draft to the PAPER →
`meta.library.linked_drafts`, which is what makes it offerable in the
select). Two different scopes, indistinguishable side by side.

The link action is now the **last option inside the same dropdown**
("＋ Link another draft to this paper…", value `__link__` → opens
`PAPER_OVERLAYS.openLinkPicker()`). The separate button and its handler are
deleted. The dropdown now always renders when the user can write, so the
link affordance survives even when every draft is already filed.

## 3. Page highlights are clickable

`.ann-rect` stays `pointer-events:none` — making the rects clickable is
what caused the original "blinky selection" bug (they sit over the text
layer and swallow drag starts). So the click is resolved **geometrically**,
reusing the `annotationAt(page, x, y)` hit-test the touch reader has used
since V3.613:

- `annotation-overlay.js` — `_onContainerClick` on the viewer: bails if the
  create popover is open or geom-selection reports a live selection (so a
  click that ended a drag is ignored), resolves the page wrap, hit-tests,
  and fires the new `onAnnotationClick(annId)` callback.
- `_onContainerMove` — rAF-throttled hit-test that sets
  `cursor: pointer` over a highlight, so the surface looks clickable.
  Skipped entirely when there are no annotations. Both listeners and the
  pending rAF are torn down in `destroy()`.
- `annotation-panel.js` — new `openComment(annId)`: for the owner it opens
  the comment editor (seeding `_commentForm` so text survives snapshot
  re-renders) and focuses the textarea; for everyone else it just scrolls
  to + flashes the card, where the comment already renders.
- `library-paper.js` wires `onAnnotationClick` → `focus()` + `openComment()`.

## Verify
- Highlight text → file it to a draft from the card dropdown → **the
  highlight stays on the page** (and the draft chip appears).
- Turn one draft overlay off → the lens narrows as before; file a highlight
  to the off draft → it turns that overlay on rather than hiding the work.
- The card's Drafts row shows ONE dropdown, whose last entry opens the
  paper-level link picker.
- Click any highlight on the page → panel scrolls to that card, comment
  editor opens (your own) or the card flashes (someone else's); cursor
  turns to a pointer over highlights.
- Drag-select still works and does not trigger the click handler.
