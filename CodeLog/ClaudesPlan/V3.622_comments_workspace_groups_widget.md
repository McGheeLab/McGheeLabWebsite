# V3.622 — Comments page becomes the categorization workspace + reader Groups widget

**Release 4 of 4** in the paper-reader highlight→comment overhaul. Alex's
model (2026-08-12 planning answers): *quick note in the reader while
reading; the deep categorization happens on the comments page* — and the
"group picker" everyone kept looking for in the reader was really "save
this PAPER to one of my library groups", which never existed there.

## Changes

### Library → Comments = the categorization workspace (rm/js/library-comments.js)
- **Grouped by paper** — rows render inside collapsible per-paper
  `<details>` sections (title + highlight count), ordered by most recent
  annotation. Open/closed choices persist across the live snapshot
  re-renders (`_groupToggles`).
- **Triage queue first** — "📥 To categorize" (highlights with no
  `cite_in_drafts` and no claim evidence, i.e. not yet reaching any paper
  we're writing) renders above "🗂 Categorized". Triage groups default
  open; categorized ones closed.
- **The claims/evidence flow lives here now** (`⚖ Evidence for a
  claim…` in each row's edit panel): draft select → claim radio list
  (lazy-loaded per draft) → "+ new claim" → stance → tag, via
  `CLAIMS.addEvidence`; on success the draft is auto-linked to the source
  paper via `LIBRARY_LINKS.toggleDraftLink` (the V3.475 behavior, now
  owned by this page). claims.js + library-links.js added to the
  comments-tab script loader.
- **Category badge** on every row (the color's NAME in the color's hue —
  same ANNOTATION_COLORS palette as the reader).
- **Inline comment editor** — replaces the `window.prompt()`; text lives
  in `_commentForm` (survives re-renders), save closes only on success.
- **"Move to Information" fixed** — it now unlinks the claim docs' own
  evidence arrays via `CLAIMS.removeEvidenceForAnnotation` (V3.621)
  before clearing the annotation's stance/claim ids; previously the
  claims kept dangling pointers forever (the self-documented drift).

### Reader panel: quick capture only (rm/js/annotation-panel.js)
- The evidence form is deleted from the panel (`_renderEvidencePanel`,
  `_evidenceForm`, claim loaders, all handlers, `onEnsureDraftLinked`
  option + host wirings). Cards with existing evidence show an
  "⚖ evidence — manage in Comments" link in the `⋯` panel. Stance badges
  and the stance filter chips stay (display only). Applies to the mobile
  notes drawer too (shared module).

### Reader sidebar: Groups widget + Lab focus (rm/js/library-paper.js)
- **📁 My groups** (new widget after the roadmaps block): shows which
  library shelf groups the open paper is in; `＋ Add to a group…` opens
  LIBRARY_GROUPS' picker (create-and-add works too). Powered by new
  library-groups.js exports: `groupsForPaper(paperId)` (manual groups,
  mine + lab-shared) and `onChanged(cb)` (widget repaints after picker
  mutations); the picker now falls back to `firebridge.isAdmin()` when
  library.js's callbacks aren't injected (standalone/reader mode).
  library-prefs.js + library-groups.js + library-groups.css now load on
  library-paper.html; `LIBRARY_PREFS.load()` + `loadShared()` run once
  per session on first widget paint.
- **🧭 Lab focus** — the "On these roadmaps" widget is retitled to the
  vocabulary Alex uses; same ROADMAP_ATTACH mechanism (researchFoci refs),
  no data change.
