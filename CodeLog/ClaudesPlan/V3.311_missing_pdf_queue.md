# V3.311 — Missing-PDF queue

> Source: `CodeLog/Feature requests/FuturePlan_01_library_paper_reader.md` Release 4
> (moved into production 2026-07-11). Closes the rm/wishlist.md "no-pdf-found queue" item.

## Goal

Metadata-only library entries (DOI-added papers whose OA fetch failed,
extension captures without PDFs) become a workable queue instead of dead
rows: filter to them in one click, retry the open-access fetch, upload the
PDF manually, or mark a paper unobtainable — from the list AND from the
reader's no-PDF dead end.

## Problem

`fromDoi` and capture-sync create items with `pdf: null` (sometimes with a
CORS-blocked `pdf_candidate_url` already stamped). The list shows a passive
"no PDF" label; the reader shows "No PDF attached to this paper." and stops.
There's no way to see how many are missing, retry, or attach the file
without the generic upload zone creating a NEW item.

## Approach

### rm/js/library.js
- `_pdfStatus(item)` → `ok | missing | unobtainable`
  (`meta.library.pdf_status === 'unobtainable'` is the reversible flag).
- Toolbar chip **"Missing PDFs (N)"** (new button in library.html next to
  Add-by-DOI): toggles `_missingOnly`; `_render` filters
  `_pdfStatus(p) !== 'ok'` and keeps the count label current every render.
- Row actions replace the passive "no PDF" label: **↻** Retry (only when a
  DOI exists — `LIBRARY_UPLOAD.unpaywallLookup`/`fetchPdfBlob` exported in
  V3.310; stamps `pdf_retry {attempts, last_at, last_error}`; CORS block
  also stamps `pdf_candidate_url`), **⬆** Upload (hidden file input →
  `uploadPdf` into the same `papers/{id}/{hash}.pdf` path family → stamps
  `lib.pdf` → import-time ref parse + SS enrich, mirroring `_ingestOne`),
  **🚫** Mark unobtainable / **↩** clear (toggle).
- `_saveOne(item)` — targeted `items/{id}.set` with serverTimestamp
  `updatedAt` (V3.309 pattern; single-row updates stop rewriting the
  collection).

### rm/js/library-paper.js
- The cold-tab no-PDF dead end renders an action pane instead of only a
  status line: same three actions + a link to the known
  `pdf_candidate_url` when present ("open in a new tab, download, ⬆ upload
  here"). Successful attach reloads the page (the reader's viewer state
  assumes a PDF from boot).

## Files modified

`rm/js/library.js`, `rm/js/library-paper.js`, `rm/pages/library.html`
(toolbar button), `sw.js` CACHE_VERSION 281 → 282, CHANGELOG +
ARCHITECTURE.

## Data model changes

New light fields on `meta.library`: `pdf_status` ('unobtainable' | absent),
`pdf_retry {attempts, last_at, last_error}`. Covered by V3.309's rules
clause (lab-member library-entry updates). No rules/index changes.

## Out of scope

Server-side headless fetch of CORS-blocked candidates (no prod server);
automatic periodic retries (manual queue first — see how far Unpaywall +
manual upload get).

## Release ritual

1. This plan doc. 2. FTP only. 3. CHANGELOG V3.311 + ARCHITECTURE +
CACHE_VERSION 282.

## Rollback

Client-only: git revert + re-FTP + CACHE bump. `pdf_status`/`pdf_retry`
fields on items are inert to old clients.

## Verification

- Add a paywalled paper by DOI (no OA) → chip shows Missing PDFs (1) →
  filter shows the row with ↻ ⬆ 🚫.
- ↻ on an OA-able DOI attaches the PDF and the row flips to Read; on a
  CORS-blocked one, `pdf_retry.last_error` + candidate URL are stamped and
  the toast says to fetch manually.
- ⬆ attaches a local PDF to the SAME item id (no duplicate row), refs
  parse + SS enrich fire, reader opens it.
- 🚫 removes the row from the missing filter; ↩ restores it. Reader
  dead-end shows the same actions and a candidate-URL link when present.
