# V3.937 — Scientia: the lab's whiteboard as part of the app (desktop too, offline)

## Goal

Gabe (28 Oct 2026), after V3.936 put the Lab Notebook's whiteboard in Scientia's image panels: "Have the whiteboard be
a standalone port from the website into Scientia (as a duplicate for the local desktop to have it too)."

V3.936 embedded the lab's board page (`/rm/pages/notebook-board.html`), which needs the lab sign-in and Firestore, so
the desktop app could only send people to the website. Now the same board runs inside the app, on both targets, with no
network.

## Approach

- **The lab's code, unchanged.** `scripts/scientia_build.py` builds `board.html` (beside `scientia.html`, both targets,
  and in the desktop download) from `rm/pages/notebook-board.html`: every stylesheet and script the page loads from the
  repo is inlined as it is (`rm/css/tokens.css`, `style.css`, `whiteboard-board.css`, `rm/css/notebook-board.css`,
  `rm/js/icons.js`, `whiteboard.js`, `whiteboard-replay.js`, `rm/js/notebook-board.js`). `BOARD_SKIP` leaves out what
  the port does not carry: the PDF picker behind ＋ From paper (`page-layout.js`, `pdf-viewer.js`, its CSS), the lab's
  Firebase sign-in (`firebase-config.js`, the gstatic SDKs) and the RM deploy check (`runtime-mode.js`). A change to
  any of them rebuilds the board (`deploy.py`'s staleness list), so the port follows the lab's board instead of
  forking it. Nothing is copied into git.
- **A Firestore of its own** — `scientia/board/store.js`, the first script in `board.html`: the compat API the engine
  uses (`collection` / `doc` / `get` / `set` (merge) / `update` (field paths) / `delete` / `add` / `where` / `orderBy`
  / `limit` / `onSnapshot` with `docChanges()` / `batch`; `FieldValue.serverTimestamp / delete / arrayUnion /
  arrayRemove / increment`; timestamps with `toMillis` / `toDate`), documents in memory. `firebase.auth()` and
  `McgheeLab.Auth` say the person is the board's owner (`me`), so `notebook-board.js` and the engine behave exactly as
  for the owner on the site; `?view=1` (the board in its cell) is someone else, so nothing can be drawn or saved.
  `firebase.storage()` keeps a file (an image card, a recording's minute) as the note's media.
- **Where the board lives** — a new store `boards` (`02-schema.js`, `DB_VERSION` 11): row `<id>` =
  `{docs: {path: document}, parts, title, docId}` holding the board's documents by path under the board (`''`,
  `strokes/…`, `items/…`, `wires/…`, `recordings/…`, `recordings/…/events/…`). Large boards continue in rows `<id>~1`,
  `~2`… of at most 450,000 characters, ordered (board, cards, wires, recordings, ink by `seq`, events by `t`) so a new
  stroke rewrites only the last row: every row syncs whole through the desktop record and the lab hub (a Firestore
  document ≤ 1 MB). Saves (600 ms after the last change, and when the board closes) are not undo steps; the board has its
  own undo. Files are saved as `"sis-media:<id>"` in the documents and turned back into the file's address
  (`MEDIA.url`) when the board opens; a recording's `.m4a` minutes are saved as `.mp4` (what `serve.py` and the hub
  accept). `MEDIA.add(file, {quiet, extra})` (13d) keeps them out of the undo history.
- **The app's side** — `13zzd-board.js`: `cell.board = {id: 'wb…_me', title}`; ✎ Whiteboard on every empty image (the
  website and the desktop); the cell shows the board read-only (`board.html?…&view=1`); a click opens it full-window
  (Remove whiteboard, Done). `window.SIS_BOARDS` = `{load, save, media}` for `store.js` (same origin, the app is the
  board's parent window). Remove deletes the rows unless another panel shows the same board; Ctrl+Z brings both back.
  V3.936 boards kept in the lab (`cell.board.lab`) still open there.
- `board.html?v=<hash of the built board>` (`window.SIS_BOARD_V`, set by the build in both apps' flags) so a rebuilt
  board is never an old cached one.

## Files

`scripts/scientia_build.py` (`build_board`, `BOARD_*`, the bundle, the flags), `scripts/deploy.py` (staleness sources),
`.gitignore` (`scientia/board.html`, `rm/scientia/board.html`); new `scientia/board/store.js`, `scientia/board/board.css`;
`scientia/src/01-util.js` (BUILD), `02-schema.js`, `13d-media.js`, `13x-figure.js`, `13zzd-board.js`;
`CodeLog/features.json` (`scientia.media` paths). The shared lab layer is not edited.

## Not in the port

＋ From paper (it reads the lab's library and opens its PDFs; hidden). Two people drawing on one board on two devices at
once: the last save wins (each board is one person's, as in the Lab Notebook).

## Tested

Headless Chrome, the desktop build with the demo data, a fake microphone, as a static page and through `serve.py` (a
throwaway config, port 8792): ✎ Whiteboard → the lab's board full-window as its owner (pills, Record); two mouse
strokes saved into the note (not undo steps); Record → Stop → a ready recording, its minute saved as
`images/<id>.mp4`; Done → the cell shows both strokes read-only; kept in IndexedDB with no `blob:` addresses; reopened,
the strokes and the recording are back and the audio loads; Recordings → ▶ → the replay plays to 0:04 and draws the
stroke; a 400-stroke board → 5 rows ≤ 450 KB read back whole, a new stroke changing only the last row; Remove → rows
gone, Ctrl+Z → back. Lab-mode harness 271/275 (the four known), notes harness 13/13. The notebook harness (v3864) fails
0/4 on this branch and identically on `main` (4a28507): not this change.
