# V3.160 — Seamless cross-page activity + task integration for RM

## Goal

Every meaningful user action and every scheduled item on every RM page
should auto-create a **pending tracker entry** the user just has to confirm
hours on. PMR becomes the weekly accountability surface where that work
rolls up visibly. Admin-assigned tasks become impossible to miss.

## Why

Today the only thing that produces a tracker entry is a subtask being
marked done ([rm/js/tasks-buckets.js:167-247](../../rm/js/tasks-buckets.js)
`logTaskCompletionToTracker`). Everything else a user does in RM — writing
in the paper editor, adding a lab notebook entry, attending a meeting,
getting assigned a task from PMR — leaves no trace unless the user logs it
manually. They don't. The activity tracker stays empty; PMR has no visibility
into what work actually happened that week.

## Approach

**Schema (additive, backward-compatible):**

`trackerEntries/{uid}/entries/{entryId}` gains:
- `status: 'pending' | 'confirmed' | 'dismissed'` (absent = `'confirmed'`)
- `scheduled_for: 'YYYY-MM-DD' | null` (set for future-dated auto-creates)
- `source_ref: { kind, id, path }` (discriminated provenance for idempotency)
- `auto_hours_estimate: number | null` (prefill for one-tap confirm)
- `confirmed_at`, `dismissed_at` timestamps

Tasks in the `assigned` bucket gain `assigned_seen_at` so the Inbox badge
can count unread assignments.

**Shared helper module: [rm/js/activity-signals.js](../../rm/js/activity-signals.js) (NEW)**

Single import-and-call API every page uses. Eliminates the need to repeat
firestore plumbing in every consumer:
- `ActivitySignals.recordWork({source, sourceRef, date, text, categoryPath, hoursEstimate?})`
- `ActivitySignals.recordSchedule({source, sourceRef, date, text, categoryPath, hoursEstimate?})`
- `ActivitySignals.removeSchedule(sourceRef)`
- `ActivitySignals.confirm(entryId, {hours, dates?})`
- `ActivitySignals.dismiss(entryId)`
- `ActivitySignals.listPending(uid, {from, to})`
- `ActivitySignals.showToast(entryId, text)`

Idempotency: composite key `(uid, source_ref.kind, source_ref.id, date)`.
Re-call with same `sourceRef.id` updates in place — moving a due_date
moves the entry, doesn't duplicate.

**Producer hooks (per-page calls into the helper):**

| Page                    | When                                          | Helper                |
|-------------------------|-----------------------------------------------|-----------------------|
| lab-notebook.js         | entry save                                    | `recordWork`          |
| meetings.js             | action item create with deadline              | `recordSchedule`      |
| tasks-buckets.js        | subtask create / due_date change              | `recordSchedule`      |
| library-paper.js        | first edit of day                             | `recordWork`          |
| paper-editor.js         | first edit of day (Y.Doc observer)            | `recordWork`          |
| protocols.js            | protocol save                                 | `recordWork`          |
| calendar.js             | event create / date change                    | `recordSchedule`      |
| important-people.js     | event_date set                                | `recordSchedule`      |
| grants.js               | submit_deadline set                           | `recordSchedule`      |
| task-assign.js          | admin assigns task                            | `recordSchedule` (on assignee) |

**Consumer surfaces:**

1. **Tracker daily view** — inline pending banner ("3 entries waiting on
   hours") with one-tap confirm + Coming up lane for future-dated entries
   surfacing on the day.
2. **Tasks page** — pinned "Assigned to me" section at top of Dashboard
   tab + `(N)` badge on Inbox tab counting unseen assigned tasks.
3. **Per-page toast** — non-blocking "Logged to tracker — confirm hours
   [Undo]" appears on every auto-create.
4. **PMR Activity block** — read-only roll-up of student's tracker entries
   in the PMR period, grouped by week and category. Pending entries shown
   with distinct styling so admin can ask "how long did this take?"
5. **PMR Stats block** — browser-side aggregation of hours by top-level
   category + daily sparkline across the period.

**firestore.rules:** Extend the `trackerEntries/{userId}/entries`
read rule to allow admin cross-user reads (PMR Activity needs them — the
existing `shareActivity` flag stays as an opt-in for non-admin viewers).

**firestore.indexes.json:** Add composite index for `(status, date)` so
the pending-queue query is cheap.

## Migration

Existing tracker entries with no `status` → readers treat absent as
`'confirmed'`. No backfill required to ship. Composite index works on
new entries from day one.
