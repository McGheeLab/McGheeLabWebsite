# V3.195 — Link-to-draft picker shows no paper drafts

## Symptom

In the paper reader (`/rm/pages/library-paper.html`), clicking **+ Link to
draft…** opens the picker modal but the "Paper drafts" section is empty
even when `paper-builder` lists three drafts. Grant drafts may or may not
appear depending on whether the user has any in the legacy `items.json`
path.

## Root cause

`rm/js/paper-overlays.js` `_loadAllDrafts()` opened with:

```js
async function _loadAllDrafts() {
  if (!window.api || !window.api.load) return [];
  ...
}
```

`api` is declared in `rm/js/util.js` as:

```js
const api = { async load(path) { ... }, async save(path, data) { ... } };
```

This is a top-level `const` in a regular (non-module) `<script>`. In ES
spec terms it creates a binding in the script's lexical environment but
NOT a property of the global object. So `window.api === undefined`, the
guard short-circuited, and `_loadAllDrafts()` returned `[]` immediately.
The Paper drafts section then rendered the empty-state copy ("None yet —
create one in the projects page.").

The function body itself uses bare `api.load(...)` (resolved through
lexical scope), so the loader logic was fine — only the guard was wrong.
That's why no other call site noticed: every other place in the codebase
calls `api.load` directly, never `window.api.load`.

V3.106 fixed the data-source path (read paper drafts from
`projects/papers.json` instead of filtering `items.json` for the
nonexistent `type:'paper' && !is_library_entry` shape), but did not
touch the guard. The fix shipped a working loader behind a guard that
always evaluated to true → return.

## Fix

`rm/js/paper-overlays.js`:

```js
async function _loadAllDrafts() {
  if (typeof api === 'undefined' || !api.load) return [];
  ...
}
```

`typeof` is safe against undeclared identifiers; the rest of the
function continues to use bare `api.load`.

`rm/js/yr-shared.js` had the same pattern in `mergeSeedsIntoTree`
(category-seed merger called by every picker loader — email-review,
calendar, etc.). It was silently bailing on seed merge for the same
reason. Fixed identically.

## Files touched

- `rm/js/paper-overlays.js` — guard at top of `_loadAllDrafts()`.
- `rm/js/yr-shared.js` — guard at top of `mergeSeedsIntoTree()`.
- `sw.js` — `CACHE_VERSION` 162 → 163.
- `CodeLog/Updates/CHANGELOG.md` — V3.195 entry.

## What "done" looks like

1. Open `/rm/pages/library-paper.html?id=<any-paper>`.
2. Click the overlays-popover button (top right of the reader).
3. Click **+ Link to draft…**.
4. The "Paper drafts" section lists every paper from
   `projects/papers.json` (the same set `paper-builder` shows).
5. The "Grant drafts" section lists items.json `type:'grant'` proposals
   AND `grantDrafts/{id}` collection entries (V3.192 behavior).
6. Checking a draft + Save links it via `meta.library.linked_drafts` on
   the library paper.
