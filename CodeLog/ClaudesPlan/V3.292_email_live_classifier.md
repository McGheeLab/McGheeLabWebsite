# V3.292 — Live-learning email category classifier

## Request
"On the API page I want to review all the training data used to predict email
categories. Every email I hand-categorize should be added to the training set
(sender, title, content keywords, other key info). Build a robust classifier
from all this data." + follow-up: "every time I categorize an email, recheck
all the other uncategorized/guessed emails."

## Decisions (confirmed with the user)
- **Engine:** in-browser Multinomial Naive Bayes — free, no API key, no backend,
  retrains live, interpretable. (Not the server sklearn / LLM options.)
- **Wiring:** powers the live guesser — blended ahead of the deterministic rules.

## Why client-side NB
The whole arc of this work has been free / client-side / no-API-key / "learns as
you correct." The api-usage page's existing suggester is **local-Python-only and
404s in production**, so anything server-dependent would be dead in prod. NB
trains in milliseconds on hundreds of examples, is interpretable (top tokens per
class), and literally learns from each correction.

## Data model
- **Labels + features in one doc:** `email_archive/classifier_training.json`
  → `userData/{uid}/emailArchive/classifierTraining`,
  `{ examples: { <emailId>: { label, sub, s(sender), subj, snip, ts } } }`.
  A feature snapshot per hand-label means the classifier and the API-page review
  need only this one doc — no join with `emailMessages`. Subject/snippet
  truncated to 160 chars to stay well under Firestore's 1 MB doc limit.
- The `userData/{uid}/{document=**}` rule already covers it — no rules change.

## Classifier (`rm/js/email-classifier.js`)
- Features: `from:<sender>`, `dom:<domain>`, `s:<subject token>`, `b:<snippet
  token>` (lowercased, stopworded, len≥3, ≤40 tokens/field).
- Multinomial NB, Laplace α=1. `predict()` returns the top class only when
  `ready()` (≥`MIN_EXAMPLES=12` total, class has ≥`MIN_PER_CLASS=2`) and softmax
  confidence ≥ `MIN_CONFIDENCE=0.6`; else null → caller falls back to rules.
- `rank()` (ranked candidates for the quick-sort pills), `topTokens()` (log-odds
  vs. the rest; adaptive singleton filter), `trainingAccuracy()` (resubstitution
  — optimistic, labeled as such), `stats()`.

## Guesser integration (`rm/js/email-review.js`)
- `guessCategory(email)` — single source of truth: **model → rules → unknown**.
  Used in `_coerceLegacyEmailShape` (load) and `_recheckGuesses` (recheck).
- `_recheckGuesses()` — re-runs `guessCategory` over every NON-manual row,
  updating category + source in place. Manual labels are never touched.
- On every hand-categorization (`quickSetCategory`, full-picker `onChange`,
  `bulkReassignCategory`): record training example → retrain → `_recheckGuesses`
  → refresh. So a correction retrains the model and propagates to all guesses
  immediately (the user's explicit "recheck everything on each label").
- `boot()`: `loadClassifierTraining()` (train) before `loadYear`; after first
  render, `_backfillTrainingFromLoaded()` captures pre-existing manual overrides
  into the store, retrains, rechecks.
- Badges: green **learned** (model) / indigo **guess** (rule) / amber **edit**
  (manual). Quick-sort pills rank via the model when ready, else rules.
- Fixed "Clear override": dropped the legacy `by_year/<y>.json` fetch (404 in
  prod) + bogus `'rules'` source; now removes the training example and re-guesses.

## Review UI (`rm/js/classifier-review.js` + api-usage.html)
Top card on the API Usage page (production-working, unlike the Python suggester
cards below). Loads the training store, trains the model, shows: example count,
active/warming status, optimistic training accuracy, vocabulary size,
per-category counts, most-predictive signals per category, and the full training
set (date / label / sender / subject / top features) with per-row delete
(removes the training signal; the email keeps its category on the Email page).

## Deploy
Client-only: FTP `rm/` + `sw.js` (CACHE_VERSION 264 → 265) + hard-reload. No
function or rules redeploy.

## Limits / future
- Content features = Gmail **snippet** only (scraper uses `format=metadata`).
  Storing more body text would need a scraper change.
- Training accuracy shown is resubstitution (optimistic). A held-out / k-fold
  number would be more honest but needs more examples to be meaningful.
- The LLM few-shot guesser (needs the Anthropic key as a Functions secret)
  remains the optional heavier next step for novel/ambiguous mail.

## Manual test
1. Email page → categorize several emails across categories. After ~12, the
   "learned" badge starts appearing on guesses; correcting one reshuffles the
   other guesses (toast: "rechecked N guesses").
2. API Usage page → top card shows your examples, per-category counts, top
   signals, accuracy; delete a row → model retrains, table updates.
