# V3.366 — Cited-in-draft sync + citation-popover scoping

**FuturePlan 13, Release 2** (see `CodeLog/Feature requests/FuturePlan_13_associations_lab_themes.md`).

## Goal

Two halves of the same idea: the builder should (a) tell the rest of RM
which library papers a draft actually cites — populating the previously
writer-less `meta.library.cited_in_drafts` field so the V3.365
association pills can show their "not yet cited" dot outside the builder
— and (b) default its citation picker to papers **associated** with the
current draft instead of dumping the whole library.

## Design

### Cited sync (NEW `rm/js/library-cited-sync.js`, `window.CITED_SYNC`)

Diff loop, not a log:
- desired = `getCitedKeysInPaper()` (live Yjs `[@key]` scan) → citation
  index → library item-id set. Unknown keys are ignored (never written).
- current = each index entry's `citedInDrafts` (NEW projection field in
  `loadCitationIndex`, deliberately patched in place by CITED_SYNC after
  each successful write so the next diff needs no refetch).
- diff → `LIBRARY_LINKS.setCitedInDraft(itemId, paperId, bool)` — NEW
  atomic arrayUnion/arrayRemove (shared `_toggleArrayField` refactor in
  library-links.js; no read-back to halve reads). Only THIS draft's
  membership is ever touched.

Triggers: debounced 30 s on **local** Yjs update (`conn.yDoc.on('update')`
registered in paper-editor's connect path; origin ≠ `'remote'` is the
provider's own echo convention — there is no autosave callback to hook,
Yjs flushes fire-and-forget); one backfill pass ~15 s after connect (old
drafts populate organically, **no migration**); best-effort `runNow()` on
pagehide. Guards: read-only sessions never write (init gates on
`state.editable`); index-refresh failure aborts the run (never diff
against unknown state); removals re-scan the doc first (race guard);
50-op cap per run with re-arm; idempotent ops make multi-editor
convergence and retries safe. Steady state = zero ops.

### Popover scoping (`paper-editor.js`)

- `citationPopoverState` gains `scopeAll` (session-sticky) and
  `citedNowSet` (computed once per popover open, reset in
  `openCitationPopover`).
- `refresh()` filters the pool to `linkedDrafts ∋ paperId OR key ∈
  citedNowSet` unless scopeAll — already-cited keys always stay in scope
  so the edit/remove flow finds its own key.
- NEW scope chip row ("Linked to this draft (N) | All library (M)") under
  the search input; `onclick` assignment (refresh runs per keystroke, no
  handler stacking). Scoped empty state points at the References tab
  search / the reader pills.
- Kill switch if scoping annoys: default `scopeAll: true`.

### Indicator surfaces

- LIBRARY_ASSOC pills already render the amber hollow dot from
  `cited_in_drafts` (`showCited: true` at both call sites since V3.365).
- References-tab "linked" rows get the same `.pe-ref-uncited-dot` glyph
  (paper-equations.js `_buildRefRow`).

## Edge cases

- Citation-key rename with same itemId: self-heals immediately (diff is
  on item ids).
- Two editors, one idle: converged Yjs doc → identical desired sets →
  idempotent duplicate ops.
- Popover keyboard flow (activeIdx / selected-bar dedup) unchanged —
  scoping only shrinks `src` before the existing pipeline.
- No firestore.rules change: `cited_in_drafts` rides the V3.309 items
  branch exactly like `linked_drafts`.

## Verification

1. Insert a citation, wait ~35 s → items doc gains
   `meta.library.cited_in_drafts: [paperId]`; the paper's pill dot clears
   in the reader/library after their next data refresh.
2. Delete the citation token → entry removed on next run.
3. Reopen an already-synced draft → console shows no stamped ops.
4. Read-only viewer produces zero writes.
5. Popover: default scope lists associated+cited only with counts;
   All-library chip restores the old behavior; empty-scope hint on an
   unassociated draft; typing/keyboard/multi-pick unchanged.
6. `node --check` all touched JS. No Firebase deploy.
