# V3.624 — Mentor visibility + the PMR "My Day ledger"

**Release 2 of 4** in the My Day outcomes → PMR health program. Program
plan (context, decisions, data model):
[V3.623_myday_outcomes_pmr_health_program.md](V3.623_myday_outcomes_pmr_health_program.md).

## Goal

The PMR stops being something the student fills out: a derived, read-only
**My Day ledger** section shows every plan in the period and what came of
it (the V3.623 outcomes), week by week — and the same reviewer set that
can already read the PMR (assigned mentors + the PI) can finally see the
underlying plans and activity.

## Changes

### Backend (deploy `--only firestore:rules` BEFORE FTP)
- NEW `userData/{userId}/dayPlans/{itemId}` block — read
  `isOwner ∥ isShared ∥ isMentorOf ∥ isAdmin`, write owner-only (the
  V3.517 notebook precedent verbatim). `_prefs` rides along; readers
  filter it.
- `trackerEntries/.../entries` read gains `|| isMentorOf(userId)` — the
  existing PMR Activity/Stats blocks light up for non-admin mentors with
  zero client changes (`ActivitySignals.listEvents(uid, …)` already does
  direct cross-user refs).

### Client — [rm/js/pmr.js](../../rm/js/pmr.js)
- Section key `myday_ledger` (label "My Day ledger") registered after
  `focus_review` in `DEFAULT_SECTION_ORDER` / `SECTION_LABELS` /
  `SECTION_RENDERERS`.
- `renderMyDayLedgerBlock()` — the focus_review derived-block pattern:
  async load, degrades quietly on permission-denied. Data via new
  `dayPlansCollRef(uid)` range query over the period
  (`loadDayPlansForPeriod`, cached per uid+period against
  keystroke-save re-renders, ↻ button to force). Weeks grouped by
  `mondayStr(date)` desc, 12 shown + "Show all N weeks".
- Per week: `✅/🚧/◌` outcome tallies + `◇ n` unaccounted + `📅 n planned`
  chips; owner-only "My Day →" deep link. Per item: type icon, title,
  weekday, 🎯 focusTitle chip, ↻ follow-up marker, outcome line
  (summary + 🖼 image + 📓 notebook links) or
  `◇ unaccounted — <why>` (`isUnaccounted` mirrors the V3.623 nudge
  filter). Amber row tint for unaccounted.
- Section-level `buildCommentToggle` thread (`section_id:
  'myday_ledger'`).
- Mirrored constants `MYDAY_OUTCOME_META` / `MYDAY_TYPE_ICONS` (keep in
  sync with day-distribute.js / my-day.js — loading the fan-out engine
  on pmr.html for two lookup tables would be worse).
- **Bug fix:** `const escHTML = escapeHtml` — `renderFocusReviewBlock`
  referenced an undefined global since V3.541 and the whole block
  silently degraded to "Focus areas unavailable."

### CSS — [rm/pages/pmr.html](../../rm/pages/pmr.html)
`.pmr-lg-*` block styles (week card, head chips, item rows, missing
tint).

## Deliberately NOT done
- `⤓ Assemble` and weekly_entries untouched — the curated narrative stays
  human-authored; the ledger is the factual record beside it.
- No outcome editing from the PMR — capture lives on My Day.
- `buckets` (tasks) stays owner-only; only dayPlans + trackerEntries
  relaxed.

## Rollback
`git revert` + re-FTP; redeploy the previous firestore.rules from git —
mentor ledgers go blank again, nothing else changes. No data written.
