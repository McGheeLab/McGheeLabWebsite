# V3.636 — Teachers can view their class as one of their own students

## The ask

> "Teachers should be able to view as student as well, as long as the student
> belongs to them."

## Why it belongs here

V3.632 gave *you* (admin) a way to see every external-user screen. A teacher
has the same problem one level down: they hand out a code, a student says "I
can't see anything", and the teacher has no way to check. They also can't
confirm the opposite — that a student they removed is actually locked out. The
roster shows a name and a status chip; it doesn't show what that person's
browser shows.

This is also the prerequisite for R3 (teacher reorders/hides modules, chosen in
V3.634): the moment a teacher can hide a module, "what does my class actually
see now?" stops being a nice-to-have.

Precedent: the class-builder View-as toolbar (V3.248) does exactly this for the
lab's own classes (Admin / Student / Public).

## Scope — a preview, not impersonation

The distinction carries the entire security argument:

- **Every read it performs is one the teacher already owns.** The roster comes
  from `rosterForTeacher(ownerUid)` (the `enrollments` list rule admits the
  class's teacher), and the per-student status from a single
  `getEnrollment(scheduleId, studentUid)` — a doc whose `teacherUid` is the
  caller. Forging `_viewAs` from the console gains nothing: an enrollment the
  teacher may not read returns null and the handler bails, and the "student
  view" only ever renders the class's own modules, which the teacher owns.
- **It never writes as the student.** The only write on the student-facing
  class page is the join form; while previewing it is short-circuited with
  "Preview only — <name> would enter their code here. Nothing was submitted."
  Verified in the headless pass: zero writes reach the data layer.
- **firestore.rules is unchanged.** Nothing here needs a new permission, which
  is the point — if it did, it would be impersonation.

**One class page, deliberately.** There is no "view as this student's
dashboard": a teacher cannot list a student's *other* enrollments (the read
rule only admits enrollments where they are the teacher), and that boundary is
correct — a teacher shouldn't see which other schools' classes their student
belongs to. So the preview is scoped to "my class, as seen by my student".

## Implementation

Module-scope state in [teacher-classes.js](../../teacher-classes.js), mirroring
class-builder's `_adminViewOverride`:

```js
let _viewAs = null;   // { scheduleId, studentUid, studentName, status }
```

It carries its `scheduleId` and is read through `viewAsFor(scheduleId)`, so a
stale preview cannot leak onto another class after navigation.
`canViewAsStudent(schedule)` re-checks ownership on **every** render, so a
sign-out or account switch drops the preview automatically.

| Piece | Behavior |
|---|---|
| `tcCanViewModules` | Consulted first: while previewing, answers as the student (`status === 'active'`). The preview therefore carries into the **module viewer**, not just the class page. |
| `wireTeacherClassPage` | `isOwner`/`isAdmin` are forced false while previewing, so the owner strip and "Manage in your dashboard" disappear — otherwise the preview would show something no student ever sees. |
| `viewAsStripHTML` | Renders in **every** state including the locked-out one (that IS the thing being checked after a Remove). Lists the whole roster, active and removed, marking removed students. |
| Roster button | `👁 View as` on each roster row jumps straight to that student's view; status comes from the row already loaded, so it costs no extra read. |

Two entry points, one going each way: from the dashboard roster into the class
page, and the switcher on the class page itself (including "Myself (teacher)"
to come back).

## Verification

Headless pass through the `teacher-busy` demo persona (a real teacher identity
with a real roster, from fixtures) — all green, zero console errors:

- 15 `View as` buttons on the roster
- as an active student: strip present, preview note shown, **owner strip
  hidden**, 17 modules
- as the removed student (Jordan Blake, added to the fixtures for this):
  **code gate, 0 modules**, strip still present
- submitting the join form while previewing: refused with the preview message,
  still gated, **zero writes logged**
- back to "Myself (teacher)": owner strip and modules restored
