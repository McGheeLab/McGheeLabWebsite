# V3.613 — Library on Ourlab: native 📚 tab + dedicated mobile pages + touch paper reader

## Goal

Students can use the full Library and paper reader on desktop, but the Ourlab
phone app surfaced neither. Alex's direction: **desktop stays untouched** —
build a **new mobile version** that ties into the desktop version by reusing
its underlying modules and data, making concessions where desktop features
would be clunky on a phone. **At the end of the day it is a paper reader, and
that is what mobile must excel at.** The ＋ FAB + APP_SHEET bottom-sheet theme
is the interaction language.

Confirmed scope decisions (Alex):
- New **native tab** (📚, 6th slot before More) — requires a TestFlight build.
- **One complete release**, not phased.
- **Single-paper reader** on phone (no tab strip) — removes the iOS
  canvas-memory problem the desktop 10-warm-tab model would cause.
- Reader parity: highlights/colors/comments + **annotation groups** +
  **evidence tagging to drafts**. List page: search/star/pin + **groups-shelf
  chips**, **tag chips**, **comments feed**, ＋ sheet (add by DOI/PMID/arXiv,
  upload PDF).
- **Cut (desktop-only)**: equation/figure capture, in-PDF search, bulk tools
  (re-check metadata, fetch missing PDFs, bookmarklet, extension), reference
  bulk import, Lab Themes management, customize view, roadmap attach, draft
  association editing, send-to-teammate, delete, metadata edit. Smart groups
  (search-grammar) resolve desktop-only.

## Approach

Two new thin pages orchestrate the SAME shared modules and Firestore data the
desktop uses — annotations round-trip live in both directions. Desktop pages
get only 3-line app-only redirect shims (Capacitor-gated `location.replace`).

### New files
| File | Role |
|---|---|
| `rm/pages/library-mobile.html` + `rm/js/library-mobile.js` | list page: search, recently-read row, group/tag chips, cards (★ / ⋯ sheet), ＋ FAB quick-add, comments feed (one-shot paged reads, 6-way concurrency pool — NOT the desktop listener fan-out) |
| `rm/pages/library-mobile-paper.html` + `rm/js/library-mobile-paper.js` | single-paper touch reader: slim bar `[←][title][🖍][📝]`, post-selection APP_SHEET (color names WITH meanings + group + comment + visibility), full-height Notes panel hosting the unmodified ANNOTATION_PANEL, transient page pill, `#ann-` deep links, no-PDF fallback (notes only) |
| `rm/js/viewer-touch.js` | pinch (CSS transform on `.pv-content` during gesture → ONE real `setZoom` on release + midpoint scroll re-anchor), double-tap fit↔2×, tap-a-highlight hit-test |
| `rm/css/library-mobile.css` | all mobile chrome, scoped `body.lib-m` |

### Shared modules — additive, desktop-inert edits
- **`geom-selection.js`** — mouse trio replaced by one Pointer Events state
  machine. Mouse branch reproduces the old behavior verbatim (button 0, 4px
  threshold, document listeners, no capture); legacy mousedown fallback when
  `!window.PointerEvent`. Touch: **long-press (380ms/8px slop) → drag**
  extends with pulsing preview + 48px edge auto-scroll; second finger always
  cancels (pinch wins); one non-passive `touchmove` preventDefaults ONLY
  while selecting (touch-action can't change mid-gesture). New
  `setArmed/isArmed` (🖍 mode: `body.lp-hl-armed` → `touch-action:none`,
  one-finger drag selects immediately).
- **`pdf-viewer.js`** — opt-in `dprCap` / `maxCanvasPixels` (phone: 2 /
  4.2e6 ≈ ≤16 MB per canvas; CSS size unchanged so item/anchor geometry is
  untouched), `lowResProbe` (ink-probe grid 360→180), `virtualize`
  (scroll-window canvas recycling: free backing stores beyond ±2 viewport
  heights, keep textLayer+items, canvas-only re-render on approach;
  zoom resizes out-of-window shells via `--scale-factor` only), 
  `contentWrapper` (`.pv-content` pinch-transform target, position:static so
  offsetTop math holds), `pause()/resume()` for the tab shell, and
  outward-from-current-page render order in setZoom/renderAll (boot order
  degenerates to 1..N — desktop unchanged).
- **`annotation-overlay.js`** — `annotationAt(page,x,y)` coordinate hit-test
  (`.ann-rect` is pointer-events:none by design); `_onDocClick` ignores taps
  inside `.app-sheet-back` (iOS synthesizes mousedown in the sheet).
- **`annotation-panel.js`** — `focusCard(annId)` (scrollIntoView + flash).
- **`firebase-bridge.js`** — `PAGE_ALIASES` maps the mobile slugs onto the
  desktop grant/cap identities (`library-mobile→library`,
  `library-mobile-paper→library-paper`, caps `library-paper:*`) in
  `_guestHasCurrentPageAccess` + `canAccessPage`, so one V3.605 admin grant
  covers both surfaces.
- **`style.css`** — `.pv-content`, `.pv-canvas-empty`, `pv-sel-pulse`
  keyframes, `.ann-card-flash`, `(pointer:coarse)` touch-action rules.

### Native tab (5 lockstep sites, all edited)
1. `rm/js/mobile-shell.js` TABS — `{key:'library', icon:'📚',
   href:/rm/pages/library-mobile.html, match:/\/library[a-z-]*\.html$/}`.
2. `OurlabMobile ios/App/App/TabRoute.swift` — `library` in TabKey +
   startPaths + `key(forPath:)` prefix-family branch.
3. `OurlabTabsPlugin.swift` — valid-keys error string.
4. `rm/js/tab-lifecycle.js` selfCheck map — `/^library[a-z-]*\.html$/ →
   'library'` (without this the webview self-pauses at boot).
5. `TabShellViewController.swift` — comment only: library deliberately NOT
   preloaded (lazy on first tap), LRU-evictable.

Redirect shims in `library.html` / `library-paper.html` heads
(`Capacitor.isNativePlatform()` → replace to the mobile page, preserving
`?id=` + `#ann-` on the reader) so push deep-links land on the touch reader
inside the library tab.

## Key decisions

- **Two pages, not an adapted desktop page** — Alex explicitly wants desktop
  untouched; the mobile pages are ~⅕ the surface and reader-first.
- **Sheet-first annotation create** — color rows show name + meaning
  (students learn the palette semantics); group/comment/visibility fold out;
  tapping a color saves. Same `ANNOTATION_SYNC.create` payload as desktop.
- **Recently-read** in `localStorage` (`rm_libm_recent`) — only the library
  tab's webview writes it, so the shared-localStorage hazard (V3.599) does
  not apply.
- **PDF fetch in the app**: Capacitor's origin is localhost, which reads
  "local" to RM_RUNTIME — `_isDeployRuntime()` in the mobile reader counts
  native as deploy (direct signed URL, disableRange/Stream) so the viewer
  never chases the nonexistent `/api` proxy.
- **Lazy pdf.js on the list page** — page-layout + the viewer module inject
  on first upload only (metadata first-page sniff), keeping list boot light.
- **Comments feed** = one-shot paged gets over papers ordered by
  `updated_at` desc (proxy for recently-annotated), 12 papers/page, 6
  queries in flight — rules-shaped per-paper subcollection reads.

## Deploy

- **★ ONE-TIME PREREQ (Alex, before the app build is useful): Storage bucket
  CORS must allow the Capacitor origin.** Found in simulator verification:
  every PDF fails with "Load failed" because the iOS webview's origin is
  `capacitor://localhost` and the bucket only allows mcgheelab.com +
  localhost dev ports. This also means NO in-app XHR download from Storage
  has ever worked (uploads go through the SDK API host and are unaffected).
  Fix (GET/HEAD only, additive):

  ```bash
  # current config (backup — restore with `gsutil cors set` of this JSON):
  # [{"maxAgeSeconds": 3600, "method": ["GET", "HEAD"],
  #   "origin": ["https://mcgheelab.com", "https://www.mcgheelab.com",
  #              "http://localhost:8000", "http://localhost:3000", "http://localhost:5000"],
  #   "responseHeader": ["Content-Type", "Content-Length", "Content-Range", "Accept-Ranges"]}]
  cat > /tmp/cors-new.json << 'EOF'
  [{"maxAgeSeconds": 3600, "method": ["GET", "HEAD"],
    "origin": ["https://mcgheelab.com", "https://www.mcgheelab.com",
               "http://localhost:8000", "http://localhost:3000", "http://localhost:5000",
               "capacitor://localhost", "ionic://localhost", "http://localhost"],
    "responseHeader": ["Content-Type", "Content-Length", "Content-Range", "Accept-Ranges"]}]
  EOF
  gsutil cors set /tmp/cors-new.json gs://mcgheelab-f56cc.firebasestorage.app
  ```

- **No `firebase deploy`** — zero rules/indexes/functions changes.
- Web + app ship in one `release_push.py` batch (Swift edits → minor `m-v`
  bump + TestFlight build). sw.js CACHE_VERSION 583 → 584.
- `sync-rm.mjs` needs no edits (new files ride the rsync; gstatic Firebase
  URLs in the new pages get vendored).

## Verification

1. Desktop regression: library + reader behavior identical (mouse selection,
   bubble, zoom, 10 tabs, panel flows); no `.pv-content` in desktop DOM.
2. `?mobileShell=1` browser preview at iPhone widths: 6-slot bar, cards,
   ⋯ sheet, ＋ quick-add DOI round-trip, long-press → sheet → highlight,
   🖍 armed, pinch/double-tap, tap-highlight → Notes at card, evidence tag,
   read-only guest (no 🖍/sheet), comments feed pagination.
3. iOS Simulator: library tab lazy-creates with no self-pause
   (`__OURLAB_TAB_VISIBLE === true`), eviction/recreate, reader back →
   intact list, deep-link redirect into the library tab, Files-picker
   upload, long-PDF scroll with freed canvases.
4. Real device before shipping (lab rule; release_push.py gates on it):
   full student workflow + live desktop round-trip both directions,
   40+ page PDF on cellular, 20-minute thermal sanity.
