# V3.96 — Library list: "Go to source" button

## Goal

Replace the per-row `DOI` button on the library list at
[rm/pages/library.html](../../rm/pages/library.html) with a clearer
`Go to source` button that:

- Uses plain language (no jargon — "DOI" was opaque to anyone outside
  academia).
- Shows up for **every** item that has any source identifier, not just
  ones with a DOI.

Reported on the wishlist:
> *"in the library, there should be a button that says go to source to
> download the paper and is a link to the journal to be able to
> download it."*

## Approach

One-file change in [rm/js/library.js](../../rm/js/library.js).

**1. New helper `_sourceUrl(lib)`** — picks the best source URL with a
fallback chain:

1. `lib.doi` → `https://doi.org/{doi}` *(canonical publisher-resolved
   link; populated for almost all CrossRef/PubMed imports)*
2. `lib.arxiv_id` → `https://arxiv.org/abs/{arxiv_id}`
3. `lib.pmid` → `https://pubmed.ncbi.nlm.nih.gov/{pmid}/`
4. `lib.url` → that URL verbatim *(catch-all for items captured from a
   journal page that lacks any of the above)*
5. None of the above → `null` (no button rendered)

Returns `{ url, host }` so the button title attribute can show the
host (e.g. "Open at doi.org") — useful when the chain falls through to
`lib.url` so the user knows where the link goes before clicking.

**2. Replace the DOI conditional** in `_renderRow` with a single
`Go to source` `<a>` driven by the helper. Same `.btn.btn-sm` class,
same `target="_blank" rel="noopener"` — visual style and security
posture unchanged.

URL templates match those already in
[rm/js/library-paper.js:64-66](../../rm/js/library-paper.js#L64-L66)
so the list view and paper-reader metadata pane stay consistent.
