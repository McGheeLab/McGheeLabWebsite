# V3.299 — Optics Foundations (interactive course)

## Goal

Build a five-lesson interactive course teaching **optics foundations**, aimed at
high-school students, with each lesson escalating to a sophomore-undergraduate
level by its final tab. Every physical concept is paired with a **live canvas
simulation** the student drives, plus lightweight **self-check** questions with
instant feedback (formative only — nothing stored). Undergraduate tabs are
quantitative (real governing equations, worked examples that compute).

The five lessons map 1:1 onto the requested topic sequence:
1. How light interacts with atoms → absorption, why some wavelengths pass, and
   how collections of atoms (crystals) absorb bands. Light as an EM wave underpins it.
2. Color = reflected (un-absorbed) light; angle matters; total internal
   reflection; frustrated TIR via index-mismatch contact → fingerprint scanners.
3. Curved surfaces bend light → lenses; lens types; compound lenses; lens
   spacing shifts the focal plane; ray tracing.
4. Scattering from index mismatch; index matching to see deeper (optical
   clearing); layered scattering; engineered surface asperities → metamaterial lenses.
5. Light self-interaction at coherence; laser interference patterns; resolution
   enhancement; the microscope light path with regular vs laser light.

## Approach

- Reuse the existing, documented module pattern in `modules/` — self-contained
  HTML per [`modules/AUTHORING.md`](../../modules/AUTHORING.md). No framework, no
  build step; MathJax CDN only; no SPA header/Firebase (standalone course modules).
- New course folder `modules/optics/`, registered in
  [`modules/manifest.json`](../../modules/manifest.json) as folder `optics`
  (label "Optics Foundations").
- Copy the house CSS and the shared JS helper library **verbatim** from a built
  reference module. Reference used: `modules/heat_transfer/01-heat-is-jiggling-atoms.html`
  (has the `requestAnimationFrame` loop optics needs for waves/interference) and
  `modules/solid_mechanics/01-atoms-as-springs.html`.
- Add one small **new reusable component**: `self-check` (CSS + `wireSelfChecks()`),
  since the existing modules have no quiz system. Formative MCQs with
  `data-answer` + per-option `data-explain-{opt}`; instant correct/wrong feedback;
  no persistence. 2–3 per lesson + a challenge in each undergrad final tab.
- Add a shared `wavelengthRGB(nm, alpha)` helper (Bruton) to the helper library
  for physically-motivated color swatches/spectra across the optics lessons.
- Build order: authored Lesson 1 by hand as the verified gold-standard reference
  (validated in headless Chrome), captured the reusable machinery in a build kit
  (`scratchpad/optics-kit.md`), then authored Lessons 2–5 against that reference
  with mandatory per-file validation (JS syntax, DOM-id consistency, headless
  render, no console errors). Added `overview.html` landing page.

## Key decisions

- **Location:** public `modules/` course system (not RM training). Confirmed with user.
- **Assessment:** formative self-checks + end-of-lesson challenge, no stored grades. Confirmed.
- **Math depth:** quantitative undergrad tabs — Snell/critical angle, thin-lens &
  lensmaker, `E=hc/λ` & `λc=1240/E_g`, Rayleigh `1/λ⁴` & generalized Snell,
  `d=0.61λ/NA` (widefield vs confocal). Confirmed.
- **ID naming** kept load-bearing per AUTHORING.md (`s-/v-/st-/vd-/cv-{tab}`) so
  the shared `wireAll`/`setScen`/`DRAW` machinery works unchanged.
- Registration into a specific Firestore class (`schedules.modules[]`) is done in
  the class-builder admin UI at runtime — out of scope for this code change; the
  manifest entry makes the files pickable there.
