# V3.880 — Scientia Portfolio: assigned projects from RM, region cards, quick notes

**Ask (Alex, 2026-10-23):** "the portfolio should come from the research / projects and can also have custom projects.
These project are assigned by the PI to the user, and they should show up at the top of the page. each project should
be in a region card that is collapsable and are moveable on the canvas. also we should also have a section for quick
note page which starts blank, and users can use a template or continue with blank page."

Part of the Scientia ↔ RM unification ([V3.866](V3.866_scientia_rm_unification.md)); web build only, `scientia/src`
untouched.

## What "assigned by the PI" is in RM

The PI assigns people in two places, both a `member_uids[]` the PI writes:

| RM source | What it is | Live today (2026-10-23) |
|---|---|---|
| `researchFoci` (Research → Research Foci) | the lab's map: specialty → concept → grant → aim → output | 7 cards with members: 3 grants, 3 aims, 1 concept |
| `projects` (Research → Projects) | papers, courses, tools, infrastructure | 3 with members, all papers; one is the CAREER grant draft that the `gels-career` card already points at (`source_draft_id`) |

Proposed or declined cards (`approval.status`, V3.851) are not assignments; absent or `approved` is.

## Approach

### The hub mirrors assignments into Scientia's own `projects` / `themes`

The same move as the library mirror (V3.869): `functions/scientia-hub-core.js` turns the person's assignments into
Scientia records and pushes them as device "RM projects", so every device (the web app and the desktop bridge) has
them through ordinary sync, and a note filed under one works like any other note.

- `rmAssigned({ foci, projects, uid })` (pure) → `{ projects, themes }`:
  - every approved focus card with the person in `member_uids` → a project `rm-f-<id>`;
  - **an aim under an assigned grant becomes a theme of that grant's project** (`rm-a-<id>`, question = the aim's
    one-liner) — Scientia's themes are lines of attack inside a project, which is what an aim is. An aim whose grant
    is not assigned to the person stays a project of its own;
  - every RM project with the person in `member_uids` → a project `rm-p-<id>`, **except** one an assigned focus card
    already stands for (`source_draft_id`, `links.draft_refs[].id`, `grant_meta.promoted_draft_id`) — that one folds
    into the card (`rmDraftId`), so the CAREER grant shows once;
  - fields: `name`, `rm: true`, `rmSource` (`focus` | `project`), `rmId`, `rmKind` (level or type), `rmStatus`,
    `rmRole`, `rmLine` (one-liner), `rmParents` (titles of the cards it builds on), `rmUrl`, `rmDraftId`, `rmOrder`,
    `rmAssigned`.
- `planAssigned({ state, rows, themeRows, assigned })` → ops. The mirror owns only `PROJECT_FIELDS` / `THEME_FIELDS`;
  everything else on the row survives a re-mirror.
- **Unassigned is not deleted.** Notes point at the project, so a project the PI takes the person off keeps its row
  with `rmAssigned: false` (shown under "Earlier assignments", collapsed); an aim theme is retired with the reason
  "No longer assigned in RM" and comes back to active if the person is put back. A theme the person re-shaped or merged
  keeps its own status.
- `FirestoreHub.syncProjects` (two `array-contains` queries + the hub's `projects` / `themes` rows), throttled to five
  minutes (`projSyncAt`), runs in `quietSyncs` as `projects`, so hello, state, every pull and
  `POST api/rm/sync?only=projects` reach it. `MemoryHub` mirrors `rmFoci` / `rmProjects` for the fixtures.

### The lab layer redraws the Portfolio as region cards (`rm/scientia/lab-mode.js` §10)

`PortfolioView.render` is replaced (Gabe's map and his General section, 15b, both read the same records):

1. **Assigned by the PI** — the RM projects, first. Each region's header: kind and status, the person's role, the
   one-liner, what it builds on, *Open in RM*, *+ Note*.
2. **Quick notes** — Gabe's General notes (no project), with *+ Quick note*.
3. **My projects** — the person's own Scientia projects (*+ Project*, Gabe's), then earlier assignments.

Each region is a card on the canvas: themes as columns, notes stacked under their theme (Gabe's `tcard` / `dcard`
markup), the dashed note-to-note links drawn between them. **The header is the handle**: drag it to move the region
(edge panning near the border); the chevron collapses it to its header and a one-line count. Until the first move the
regions flow in a column; the first move pins every region where it is, so later collapses leave the others in place,
and *Tidy up* returns to the flow. Positions and open/closed are per device (`_ls` `lab:portfolio`, like Gabe's own
canvas view), because a layout made on a wide screen is not the phone's.

### Quick notes start blank

*+ Quick note* makes a General note of type *Note* with one empty component and opens it — no dialog. While the page
is still blank a bar offers the templates (every enabled template by type, plus the person's own saved ones) and
*Continue blank*. Picking a template turns the note into that type in place (its components replace the empty one, the
default title follows the type); typing, or *Continue blank*, puts the bar away. A quick note is an ordinary General
note: Gabe's ⋯ → *Project & theme…* files it into a project later.

## Decisions

- Aims are themes, not projects (one region per grant, its aims as columns).
- A paper project the focus card already stands for is folded, never shown twice.
- Unassignment keeps the project (notes stay reachable), shown apart and collapsed.
- Layout is per device; the records stay Gabe's shape.
- Quick notes are General notes (Gabe's 15b), not a new kind.
