# V3.651 — Table builder: room to work in, and real styling

## The asks (Alex, 2026-08-20, on V3.650)

1. *"the table is now srunched up in the table area it needs some buffer area
   to feel better when we are making it."*
2. *"also we should be able to style it."*

## (1) Buffer

V3.650 put the ＋/− controls on the grid's borders, and those buttons poke 8 px
*outside* their gutter head cells — into 2 px of padding. Combined with cell
metrics inherited from the read-only doc-side preview (`min-height: 22px`,
`padding: 6px 8px`), the thing you build a table in was tighter than the thing
that only shows you one.

- `.pe-tblgrid` becomes a **padded canvas**: `18px 20px 16px` inside a hairline
  card, `12px` above. The buttons now have room to sit on a border without
  touching the panel edge.
- Editor cells get typing metrics — `min-height: 30px`, `padding: 8px 10px` —
  scoped to `.pe-tab-editor-body` so the compact doc-side preview is unchanged.
- Air before the alignment row and before the Caption label.

## (2) Styling

The only styling a table had was `booktabs` (one checkbox), `header_row`,
per-column align and per-column width. Everything a real table needs — a
bolded row, a shaded cell, an extra rule, a smaller font, roomier rows — had
nowhere to live.

**Four surfaces draw a table**: this editor grid, the doc-side block preview,
Document view, and the compiled `.tex`. They must not drift, so the model is
parsed in exactly one place — `paper-layout-rules.js`, next to
`parseTableMerges` — and all four read it.

### Storage: two scalar attrs
Scalars, not Y types, for the same reason `merges_json` and `widths_json` are:
a table block gets moved between sections and placed/unplaced, and a scalar
survives every one of those paths.

```
style_json        {rules, size, density, zebra, rule_after:[r,…]}
cell_styles_json  {"<r>-<c>": {b:1, i:1, al:'l'|'c'|'r', bg:<fill>}}
```

New shared helpers: `parseTableStyle(json, booktabsAttr)`,
`tableStyleIsDefault(st)`, `parseTableCellStyles(json)`,
`shiftTableCellStyles(...)`, `shiftTableRuleAfter(...)`, plus the
`TABLE_FILLS` / `TABLE_DENSITIES` / `TABLE_SIZES` tables (each fill carries
both a CSS colour and a TeX colour expression, so the swatch you click is the
colour that compiles).

**Back-compatibility is load-bearing.** `parseTableStyle` falls back to the
pre-V3.651 `booktabs` boolean when there is no `style_json`, and every default
is a no-op, so an untouched table's `.tex` is byte-identical to what V3.650
emitted. Writers go through `_tblStoreStyle`, which **deletes** `style_json`
when nothing is off-default and keeps the legacy `booktabs` flag in step
(`rules === 'booktabs'`) for any consumer that predates this release.

### Table-level controls (the style bar)
`booktabs` as a lone checkbox was a strange way to ask "what should the lines
look like" — the three real answers are journal rules, a full grid, or nothing:

| control | values | LaTeX |
|---|---|---|
| lines | booktabs / grid / none | `\toprule…` / `\|` colspec + `\hline` / nothing |
| text | normal / small / footnotesize / scriptsize | `\small` etc. inside the float |
| rows | compact / normal / roomy / airy | `\renewcommand{\arraystretch}{…}` |
| striped | on / off | `\rowcolors{n}{}{black!4}` |

### Cell-level controls (the floating bar)
V3.650 built a cell selection for merge. Formatting is the other thing you
want a block of cells for, so it rides the same gesture instead of growing a
second surface: **B**, *I*, three alignment overrides, five fill swatches, a
clear-shading button, and — for a whole-row selection — the rule that goes
under it. Every button reflects the current state of the selection and toggles.

Clicking a **row or column gutter head** now selects that whole band, which is
what makes "bold this row" one gesture instead of a drag the width of the
table.

### The two LaTeX traps
- **`\multicolumn` must be the ENTIRE cell**, and `\cellcolor` must be first
  *inside* it. `\cellcolor{…}\multicolumn{1}{c}{x}` is a "Misplaced
  \multicolumn" error, not a cosmetic difference — so the alignment override
  wraps **last**, with the shading inside. Asserted both ways round.
- **A rule under the last row doubles the `\bottomrule`.** `ruleAfterTex`
  drops it when a closing rule is coming, and the UI does not offer the button
  there, so it never promises something the export discards.

Striping starts at row 2 when there is a header row (`\rowcolors` counts from
the first body row) or the header takes the tint and the whole table reads off
by one. Shading pulls in `\usepackage[table]{xcolor}` on demand via a new
`_usedColortbl` flag — plain `xcolor` would compile the preamble and then fail
on the first `\cellcolor`. `longtable` is not a float, so its size/stretch/
striping commands are wrapped in `\begingroup…\endgroup` or they leak into the
body text that follows.

### Structural ops carry the styling
`_tblStructOp` already re-keyed cells, merges, align and widths. It now also
shifts `cell_styles_json` and `rule_after` **in the same transact** — otherwise
inserting a column leaves the table bold in the column that used to be there.
