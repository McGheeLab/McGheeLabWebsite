# V3.626 — Activity signals (annotations · comments · task completion) + presence strips

**Release 4 of 4** in the My Day outcomes → PMR health program. Program
plan: [V3.623_myday_outcomes_pmr_health_program.md](V3.623_myday_outcomes_pmr_health_program.md).

## Goal

Close the "the PMR reports everything they've been doing" loop: the three
surfaces that left no activity trace — annotating a paper, posting in a
discussion thread, completing a task — now emit ActivitySignals work
events, and the ledger shows per-week Mon→Sun presence dots so anyone can
see when the student was active.

## Changes

### Producers (all fire-and-forget, deterministic ids → idempotent)
- [rm/js/annotation-sync.js](../../rm/js/annotation-sync.js) —
  `_recordAnnotationSignal(paperId)` after `create()`:
  `source 'rm-library'`, `sourceRef {kind:'annotation', id: paperId}`
  (one event per paper per day), text `Annotated: <title>` (title
  fetched once per paperId per session, fallback "a paper"),
  categoryPath `['research','reading']`. `activity-signals.js` added to
  [library-paper.html](../../rm/pages/library-paper.html),
  [library-mobile-paper.html](../../rm/pages/library-mobile-paper.html),
  and library.html's comments-script list; the producer no-ops where
  the helper is absent.
- [rm/js/section-comments.js](../../rm/js/section-comments.js) — on
  successful post: `source 'rm-comments'`, `sourceRef {kind:'comment',
  id: opts.collectionPath}` (one per thread per day), text
  `Discussed: <opts.label>`, categoryPath `['research','discussion']`.
  Covers PMR blocks, paper comments, figure-board threads — every
  SECTION_COMMENTS mount.
- [rm/js/tasks-buckets.js](../../rm/js/tasks-buckets.js) —
  `recordPlainDoneSignal(bucket, st)`: `sourceRef {kind:'subtask-done',
  id: st.id}`, date from `done_at`, text `Completed: <text>`. Fires ONLY
  where `logTaskCompletionToTracker` previously wrote nothing (no bucket
  category / no hours estimate / "skip" in the hours modal) so
  hours-logged completions are never double-counted.

### Presence — [rm/js/pmr.js](../../rm/js/pmr.js)
- `ensureActivityForPeriod()` — one-flight period activity fetch shared
  by the ledger and the Activity/Stats blocks (`loadActivityForBlock`
  now consumes it; renderBody mounts them near-simultaneously, so the
  promise is keyed and reused).
- `activeDaySet(entries)` — days with ≥1 real WORK event (schedule
  markers + legacy pending excluded, same filter as the V3.321
  heatmap).
- Ledger week headers render 7 Mon→Sun dots (green = active, dashed =
  future). The Activity block's existing per-day heatmap already covers
  the period view. CSS `.pmr-lg-presence` / `.pmr-lg-pd` in pmr.html.

## Deliberately NOT done
- No tracker-page changes — new events render there through the existing
  event pipeline (unknown categoryPaths group as their own category).
- Assigned-task completion (userData/{uid}/tasks flow) not instrumented —
  buckets subtasks are the workspace; revisit if the gap shows.

## Deploy
FTP only. (trackerEntries writes stay owner-only; producers run as the
acting user.)

## Rollback
`git revert` + re-FTP. Already-written events are plain tracker entries —
harmless, deletable from the tracker page like any entry.

## Verification
1. Annotate a paper → tracker shows "Annotated: <title>" under
   research/reading (one per paper/day even after multiple highlights).
2. Post a PMR comment + a figure-board comment → two "Discussed: …"
   events.
3. Complete a subtask with no hours estimate → "Completed: …" event;
   complete one WITH hours → only the hours entry (no double count).
4. PMR ledger week heads show green dots on active days; Activity block
   unchanged otherwise; mentor view shows the same.
