# V3.640 — Caption-anchored figure detection (replaces the ink-blob method)

## Goal

V3.616's hotspot detection did a poor job on real papers: it fragmented
multi-panel figures into per-panel hotspots (nobody wants sub-figures) and
its extents didn't match the actual figure. Alex's direction: every figure
has a caption that starts with its figure number — detect from captions,
and capture the region around the ENTIRE figure up to the surrounding text.
Confirmed choices: the snip includes the caption; tables ("Table 1.") get
hotspots too.

## Approach

### `rm/js/page-layout.js` — new `PAGE_LAYOUT.figureRegions(items, opts)`

Pure geometry in the shared engine (headless-testable; pdf-viewer is a thin
caller). Per page:

1. **Anchors** = clusters typed `caption` by `classifyBlocks` whose leading
   text matches `RE_NUMBERED_CAPTION` (Fig/Figure/Table/Scheme/Extended
   Data/Supplementary + a number). Body prose "Figure 3 shows…" can't
   anchor (body blocks aren't typed caption); "Figure legends" can't (no
   number). One caption → one region → sub-figure fragmentation is
   structurally impossible.
2. **Growth**: obstacles = every item outside the caption's cluster (other
   captions included, so stacked figures separate). Grow UP from the
   caption's x-range to the nearest overlapping obstacle bottom (else page
   top), then widen left/right within the span until obstacles block (else
   page margins) — a single-column figure stops at the gutter because the
   other column's text is an obstacle; a full-width caption spans the page.
   Two passes (widening can expose wider obstacles above).
3. **Direction flip**: with `opts.inkProbe` (the viewer's pixel probe), if
   the up-region is blank (<0.008 mean ink) the same growth runs DOWN and
   the inkier side wins — tables and below-caption layouts. Headless (no
   probe) → up only.
4. **Output** `{x, y, w, h, label}` per caption (region ∪ caption bbox,
   4px pad, clamped); degenerate regions (<40px of space) are skipped —
   a caption with no figure produces nothing.

### `rm/js/pdf-viewer.js`

The V3.616 ink-blob `_detectFigureRegions` (≈125 lines of grid/CC/merge
code) is **deleted**; the function is now a thin call into
`PAGE_LAYOUT.figureRegions` with `_makePixelProbe` supplying the ink probe.
Regions still stored natural-scale on the node; `getFigureRegions()` now
passes `label` through.

### `rm/js/figure-capture.js`

- Hotspot tooltip shows the caption ("Click to snip — Figure 3. …").
- `open()` takes an optional `name`; the hotspot passes the caption opener
  ("Figure 3" / "Table 1", regex-trimmed) so the capture dialog's name
  pre-fills. (Coexists with V3.621's open-time paperId binding.)

Unchanged: `refreshHotspots` wiring/gating, click-vs-drag guard, marquee /
Alt-drag fallback, capture dialog, Storage upload, board picker,
`.fc-hotspot` CSS.

## Verification done at build time

Headless synthetic-page test (node, no DOM): two-column page → exactly one
region for "Figure 1." spanning the empty band above the caption, bounded
by the left column's body text above and the right column at the gutter
(tolerance = the 4px pad), label correct; body prose starting "Figure 3
shows" → 0 regions; caption block "Figure legends" (no number) → 0 regions;
full-width caption → region spans the page width under the body text.

## Open questions

- Journals whose caption sits BESIDE the figure (side captions) will grow
  up/down and may catch a partial region — marquee covers those; revisit if
  a lab-relevant journal does this.
- `classifyBlocks` caption typing (small type / <12 items) is the load-
  bearing dependency; if a specific paper's captions are typed `body`, add
  a fixture to the layout harness and tune there, not in figureRegions.

## Verification (manual, after FTP + hard reload)

1. A figure-heavy lab PDF: ONE hotspot per numbered figure covering the
   whole multi-panel figure + caption, stopping at surrounding body text.
2. Single-column figure stops at the gutter; full-width figure spans both
   columns.
3. Tables get hotspots; a table with content below its caption captures
   downward.
4. Capture dialog name pre-fills "Figure N"; tooltip shows the caption.
5. No hotspots on caption-less pages or from body "Figure 3 shows…" prose.
6. Marquee/Alt-drag and normal highlighting still work over hotspots.
