# V3.587 — Voice call TURN relay (fixes "no relay server" on campus WiFi)

## Context

First real test (Alex + Gabriel, one on the app): Join worked (signaling
is fine — the roster/participant tiles came up), but audio never
connected. The exact "no TURN relay" toast the V3.525 MVP was designed
to surface fired: `ICE_SERVERS` only had free Google STUN, and STUN
alone cannot traverse university WiFi's client isolation / symmetric
NAT. This was the documented, accepted MVP limitation — now the
follow-up.

While tracing the failure, found a real bug in the signaling code that
made it worse than the "expected" no-TURN case: **ICE candidates arriving
before their peer's `RTCPeerConnection` existed were silently dropped**
(`handleSignal`'s `candidate` branch returned early when `!entry`).
Firestore gives no cross-document ordering guarantee and a pending
`serverTimestamp()` sorts as `Infinity` (newest) in the client sort, so a
candidate racing ahead of the `offer` it depends on was a live
possibility, not a corner case — and every dropped candidate is a
potential connection path that never gets tried.

## Approach

**TURN, resolved at call-join time, admin-overridable, no redeploy
needed for changes:**

1. `voiceCallConfig/turn` Firestore doc (new, admin-write / lab-member
   read) — `{ iceServers: [{urls, username, credential}, ...] }`. Checked
   once per page load (`loadIceConfig()`, cached promise), before the
   first `RTCPeerConnection` is constructed (ICE servers are
   constructor-only — can't be swapped after).
2. If that doc is empty/unreadable/missing, fall back to **Open Relay
   Project's free public TURN** (`openrelay.metered.ca`, no signup) on
   ports 80/443/turns:443 — chosen specifically because 443 punches
   through firewalls that block the default 3478. This is a stopgap:
   free tier, rate-limited, best-effort uptime. Alex should get real
   TURN credentials (Metered's free 50GB/mo tier, or Cloudflare/Twilio)
   into `voiceCallConfig/turn` when convenient; nothing code-side blocks
   on that.
3. STUN servers are ALWAYS included alongside TURN — a direct connection
   is still tried first/in-parallel when the network allows it; TURN is
   the guaranteed fallback path, not a replacement.

**Bug fix — orphan candidate buffer:** `_orphanCandidates: Map<peerUid,
candidate[]>`. A `candidate` signal for a peer that doesn't exist yet is
queued there instead of dropped; `createPeer` drains it into the normal
per-peer `pending` queue on creation. Combined with the existing
pre-remote-description queue, no candidate is ever discarded regardless
of arrival order.

**ICE-restart retry:** on `connectionState === 'failed'`, rebuild that
one peer connection once (`MAX_PEER_RETRIES = 1`) — fresh candidate
gathering sometimes succeeds where the first attempt raced a slow TURN
allocation. Only the initiator (smaller uid) re-offers; the answerer
detects a re-offer against a dead pc (`handleSignal`'s offer branch) and
replaces it rather than throwing. If the retry also fails, the toast now
says something DIAGNOSTIC instead of a canned line: whether a `relay`-
type ICE candidate was ever obtained (`entry.sawRelay`, set in
`onicecandidate`) distinguishes "TURN unreachable" from "TURN reachable
but still failed" (the latter usually means the two peers' NATs disagree
even through the relay, or the TURN server itself is overloaded/rate
limiting the free tier).

**Diagnostic:** `VOICE_CALL.testIce()` — buildable/runnable from any
browser console without a second caller. Gathers ICE candidates against
the resolved server list and reports whether a `relay` candidate came
back. This is the tool for Alex/Gabriel to run on their own networks
next time something doesn't connect, instead of a live two-person call
being the only way to find out.

## Deploy

1. `firebase deploy --only firestore:rules` (adds the config-doc rule;
   the fallback TURN works even before this deploys, since the config
   read just fails closed to the default list)
2. FTP the repo.
3. **Recommended, not blocking:** get free/cheap TURN credentials (e.g.
   Metered.ca's free tier) and write them into `voiceCallConfig/turn` via
   the Firebase console or a one-off script, so calls aren't depending on
   a public best-effort relay long-term.

## Verification

1. `VOICE_CALL.testIce()` in the console on the campus network that
   failed before → expect `relay: true`.
2. Repeat the real two-person call (one on university WiFi) that failed
   — audio should now connect through the relay.
3. Confirm the fallback path: temporarily rename/empty
   `voiceCallConfig/turn` (or just don't create it) and re-run
   `testIce()` — should still report `relay: true` via the public
   Open Relay fallback.
4. Force a one-time failure (e.g. airplane-mode one peer for 2s mid-call)
   and confirm the single retry attempts a rebuild before giving up.
