# V3.740–742 — Papers list: activity order, bundle checkout lock, import-in-place

Alex: *"on the papers page, please sort the papers on the page by type status and put the
most recent worked on papers (by anyone) at the top. Papers should get a zip for updates
button on the top right. The export zip should be paperbundle.zip. we will use the
paperbundle.zip in the vscode repo for that paper to update its contents then push that
bundle back to the paper draft to update its content. When we export a paper in this way
it must be locked for editing until we come back with the new paperbundle.zip"*

Three releases, one program. Decisions from the clarifying round: button lives on **each
card AND the toolbar** (picker); lock = **read-only for everyone, admins included, admin
can force-unlock**; activity signal = **the existing `updatedAt`** (no new field);
grouping = **by document type only**, newest activity first inside each, status as a pill.

## Goal

1. The list stops being slug-alphabetical: grouped Papers / Grants / …, most recently
   worked on at the top of each group, with "edited 2h ago" on every card.
2. A paper can be **checked out** — `⇩ Export for updates` downloads
   `<slug>.paperbundle.zip` and locks the draft — edited in its VSCode repo, and
   **imported back into the same paper**, which releases the lock.

## The finding that shaped V3.740

`updatedAt` was not a record of work. Manuscript edits go to
`papers/{id}/yjs_updates` and never touched `projects/{id}`; the whole-collection
`api.save('projects/papers.json')` re-stamps *every* row; the zip importer stamped
nothing. Sorting on it as-is would have ordered papers by "whoever last saved the
shared array". Kept as the sort key (per the decision) and made truthful with a
**throttled touch** in `paper-yjs.js`: after a successful Yjs flush, at most once per
5 minutes per session, `projects/{id}.set({updatedAt: serverTimestamp()}, {merge:true})`
— a single-doc merge, never the array save (the V3.729 trap).

## Approach

### V3.740 — sort + group (`paper-builder.js`, `paper-editor.css`)
- `sortAndGroup()`: group key `paper_type || 'journal'` in a fixed order
  (journal → grant → editorial → book-chapter → presentation → patent → other), within a
  group `updatedAt` desc then title. `toMillis()` accepts a Firestore `Timestamp`, the
  IndexedDB-cloned `{seconds, nanoseconds}` (no `.toMillis()` after structured clone),
  an ISO string, or nothing (→ 0, sorts last).
- `.pb-list.pb-grouped` stacks `.pb-group` sections each holding a `.pb-grid`; the
  modifier is scoped because `protocols.html` and `grant-builder.html` reuse `.pb-list`
  as a flat grid. Headers only when >1 group.

### V3.741 — checkout + lock
- **State** on `projects/{id}`: `checked_out_by_uid / checked_out_by / checked_out_at /
  checkout_token`. `functions/paper-author-sync.js` mirrors `checkedOutByUid` +
  `checkedOutAt` onto `papers/{id}` (the doc `isPaperAuthor` already `get()`s, so the
  rule check is free).
- **Rules** (`firestore.rules`): `isPaperCheckedOut()` / `isPaperCheckoutHolder()`;
  `yjs_updates` create requires `!checkedOut || holder` — admins included (they unlock,
  they don't bypass); the holder exception is how the edited bundle gets back in.
  `/projects` update gains a coauthor clause limited by `affectedKeys().hasOnly([...])`
  to the four lock fields + `updatedAt`.
- **Client**: `firebridge.canEditPaper` tests checkout before the admin short-circuit;
  new `isPaperCheckedOut()` / `canCheckOutPaper()` (the pre-lock author test).
  `PaperYjs.connect(id, {locked})` drops local updates (+ `setLocked()`); the editor
  passes it and shows `showCheckoutBanner()` with "Import updated bundle" and a two-tap
  "Unlock without importing". `paper-equations.js`'s four hardcoded `readOnly:false`
  bindings (table cells/caption, figure captions) now ask `PaperEditor.isEditable()`.
- **Export**: `PaperExportBundle.buildForPaper(id, {meta, checkout})` — headless connect
  (`touchActivity:false`), raw `paperExports/{id}` minus `grantDocs`, citation map from
  `items.json`; stamps `manifest.checkout`, `paper.paper_id`, `references[]` and a
  `README.md`. Deps lazy-load on first click (`paper-export-tex.js` optional, with an
  in-file fallback key collector). **Zip first, lock only on success.**
- **List UI**: hover ⇩ at `right:34px` beside the trash; locked cards get an amber lock
  row with "Import update" (authors/admin) and "Unlock" (admin/holder/lead); toolbar
  picker. All dialogs are in-page `.pi-dialog` on the existing `.pi-*` chrome — never
  `confirm()`.

### V3.742 — import-in-place
- `importBundleFile` reads `paper.json` first; a `checkout.paper_id` that names an
  existing row opens **Update / Import as new copy**. Token mismatch or an already
  unlocked paper requires an explicit "update anyway" tick. Non-authors get copy only.
- `_runImport(mode:'update')`: ensure we are the holder (claim if none; take over and
  `_waitForMirror` if someone else), `PaperImportEngine.run({mode:'update'})`, then
  clear the lock (+ title if it changed; best-effort for coauthors). A failed import
  leaves the paper locked.
- Engine: `replace:true` into `PaperTreeBuild.buildInto` (clear five libraries + title
  in the same transact → ONE Y update), comments phase skipped.
- **Round-trip fidelity** (required, since replace deletes what the builder ignores):
  `skeleton_items`, `style_overrides`, `value_library` now rebuild in
  `paper-tree-build.js` AND the mirrored `paper-editor.js` builders; the exporter emits
  `references[]`. Side effect fixed: `blockMapToTree` never captured `skeleton_items`,
  so **a section move dropped every paragraph outline** — now round-trips.
