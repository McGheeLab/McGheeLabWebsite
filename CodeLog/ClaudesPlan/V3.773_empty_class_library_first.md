# V3.773 — A class starts empty, and the library comes first

**Alex:** *"On the modules tab I want the Available to your students section to
be empty until the teacher fills it out, switch the order so the cards go up
top and the selected modules are below it."*

## Two changes, one idea

The Modules tab is a workflow: **choose from the library → it appears in your
class**. V3.771 printed those two steps in the wrong order and started every
teacher at step two with 36 lessons already in it.

### 1. The library is the top card

Straight swap of the two cards in `renderModulesTab`, with the copy turned
round: the chosen list now says *"Add or drop lessons from the library above"*,
and its empty state reads *"your class starts empty. Open a course above,
preview a lesson, and press Make available; what you pick shows up here, and
here is exactly what your students get."*

### 2. Nothing is pre-filled any more

A provisioned class used to arrive carrying a module list the teacher never
chose — `tc-tuc-gnr8` had **36 lessons across 7 courses** on its students'
class page before its teacher had opened the dashboard once. Three places did
this; all three stop:

| Where | Was | Now |
|---|---|---|
| Admin approve modal (`rm/js/admin-teachers.js`) | `modules: buildModulesFromCatalog(granted)` from folder checkboxes | `modules: []`; the checkboxes are gone, replaced by a line saying the class is created empty (any folders the teacher *asked about* are still shown, as context for the admin) |
| `redeemTeacherInvite` (`functions/teacher-invite.js`) | expanded `invite.prefillFolders` from the published catalog | `const modules = []`; the invite form no longer collects folders |
| Legacy "edit granted folders" modal | `modules: buildModules(granted)` — **overwrote whatever the teacher had curated** | writes `grantedFolders` only |

`approveBlockedReason()` also relaxes: it existed because approving without the
manifest would "create a class with no modules", which is now the intended
outcome. Approvals and invites work with no manifest at all; only the legacy
folder-grant modal still needs it.

## The existing class

`schedules/tc-tuc-gnr8` was carrying the 36 pre-filled lessons. Backed up to
the session scratchpad (`tc-tuc-gnr8.modules.backup.json`) and cleared, so the
class matches the new behaviour: 0 modules, teacher picks. Zero students were
enrolled, and every lesson is one click away in the library.
