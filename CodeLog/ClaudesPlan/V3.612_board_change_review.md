# V3.612 — Figure board change review + single collapsed notification (program R4 of 4)

## Goal

When your mentor (or coauthor) works on your figure board while you're away,
you get exactly ONE live "🧭 Figure board updated" notification — no matter
how many edits — and when you open the board, everything that changed since
your last visit is highlighted, with a ▶ Review button that steps through
the changed cards. Alex's spec verbatim: "only one notification that
something has changed, it doesn't matter how many changes; changes should be
highlighted somehow for review."

## Approach

### Change highlighting (client-only — `rm/js/paper-figure-board.js`)
- Baseline per user per board in **`userSettings/{uid}.figure_boards[paperId]`**
  (ISO string; owner-write rule already exists — no rules change).
- On board open: read the baseline into memory, THEN stamp now (and re-stamp
  on `pagehide`/teardown) — the in-memory value drives this visit's
  highlights while the stored one resets for next time.
- A card is "changed" when `updatedAt > baseline` by someone else
  (`updated_by !== me`) or its newest **other-author** board comment is
  newer than the baseline (own comments never flag your own cards).
- Changed cards get an amber ring + "· changed" chip; toolbar **▶ Review N
  changed** pans the canvas card-to-card with a flash.

### One live notification (new `functions/figure-board-notify.js`)
- Triggers: `boardItems` onWritten + `boardComments` onCreated; registered
  in `functions/index.js` as `onBoardItemWrite` / `onBoardCommentCreate`.
- Recipients = `papers/{id}.authorUids ∪ mentorUids` minus the actor.
- **Noise guards:** position-only writes (x/y/z/w/updatedAt/updated_by)
  never notify (dragging is constant); deletes never notify (deleter is
  unattributable from the doc).
- **Unread gate — the "only one" mechanism:** a recipient who already has
  an UNREAD feed item with tag `figboard-{paperId}` is skipped entirely
  (equality-only query on tag+readAt — no composite index). Combined with
  `recordFeedItems`' tag-collapse, each person holds at most one live
  board signal.
- **Re-arming:** opening the board marks your own `figboard-*` feed items
  read (client `_markFeedRead()`, own-`userData` write) — so the next
  edit after your visit notifies again. `notifyUsers` (push + feed) with
  the push presence-gated as usual (V3.596).
- Deep link: `/rm/pages/paper-builder.html?paper=<id>&page=figure-board`.

## Rollback

Delete the two triggers; revert client + re-FTP. `figure_boards` stamps in
userSettings are inert.

## Open questions

- The unread-gate probe is per-recipient serial (boards have ~2-4 people —
  fine). Revisit if boards ever grow big rosters.
- Deletes don't notify (by design); if that proves confusing, add a
  tombstone-style actor stamp before delete.

## Verification

1. User A edits a mentee-shared board (add a card, edit text, comment).
   User B receives ONE push + one My Day feed item.
2. A makes five more edits before B looks — B receives nothing further
   (function logs show the unread gate skipping).
3. B opens the board: the changed cards carry amber rings, ▶ Review N
   changed steps through them, and B's feed item flips to read.
4. A's next edit after B's visit notifies B again (re-armed).
5. A drags cards around only — nobody is notified.
6. B editing their own board never notifies B.
