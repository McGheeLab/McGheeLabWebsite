# V3.383 — "✓ Complete" section: lock + final document form

## Goal

Marking a builder section complete **locks it** (no editing) and swaps it
to its **final form**: resolved prose rendered like a manuscript on
screen — citations typeset in the journal's style with correct global
numbers, KaTeX math, resolved Fig./Tab./Eq. cross-references, figures
with "Figure N." captions, display equations with right-aligned (N) —
inline in the editor, NOT the PDF export. Reopen restores editing.

## Key insight (why this is small)

The final-form renderer already existed per block: every read-only
paragraph body renders through `renderParagraphHtml` (citations via
PaperCiteStyle global first-appearance numbering, KaTeX, cross-ref
resolution, markdown), and figure/table captions already bind read-only
through the same renderer. So "final form" = force the section's blocks
into the read-only path + hide the edit chrome + manuscript CSS + restore
the numbers that lived in the now-hidden toolbars.

## Implementation (rm/js/paper-editor.js + rm/css/paper-editor.css)

- **Data**: `completed_at` (ISO, null = open) + `completed_by` (name) on
  the section Y.Map; `status` stamped 'complete'/'draft' for consistency
  with the dormant field. **Round-tripped through all three tree
  functions** (`appendSectionFromTree`, `sectionMapToTree`,
  `hydrateSectionFromTree`) — without this, a section reorder
  (snapshot → delete → rehydrate) silently drops completion.
- **Toggle**: `✓ Complete` / `✎ Reopen` button in the section-header
  actions cluster (gated on `state.editable`); `_setSectionCompleted`
  writes via `yDoc.transact(..., 'section-complete')` and dispatches
  `paper-panel-changed` (cite numbers / word badges refresh). The
  **Delete ✕ button hides while completed** — reopening is required
  before deletion.
- **Re-render propagation**: the `sectionsArr` observer is shallow and
  never sees a scalar set on a child map, so `renderSection` registers a
  per-section `secMap.observe(render)` (tracked in
  `state.blockSubscriptions` for cleanup) — local AND remote completion
  toggles re-render.
- **Lock + final form in `renderSection`**: `sectionLocked =
  !!secMap.get('completed_at')` →
  - section ctx gets `editable: false` (every block binding flips to
    `readOnly` — contentEditable off, no popovers, no Yjs writes) and
    `viewFilter: 'body'` (prose, never skeleton);
  - block inserters skipped; the **status filter is bypassed** (final
    form always shows every block);
  - section label binding locked; `.pe-section-final` class +
    `data-completed` + a 🔒 banner ("completed by X · YYYY-MM-DD").
- **`_decorateFinalBlock`** (per block, after render): rewrites the
  figure/table "Caption" label to **"Figure N." / "Table N."** and
  appends a right-aligned **`(N)`** to numbered display equations —
  numbers from the document-order walkers (`getNumberedFigures/Tables/
  Equations`), so they match the whole manuscript. Cosmetic — wrapped in
  try/catch so it can never break render.
- **Outline**: completed sections get a green ✓ in the sidebar.
- **CSS** (`.pe-section-final`): parchment card; hides
  `.pe-block-toolbar` / skeleton / presence / lock badges; strips block
  borders; serif (Georgia) justified prose at 15px/1.75; serif captions
  with bold "Figure N."; centered images; `.pe-final-eqnum` absolute
  right; `.pe-section-complete-btn` green→amber toggle styling;
  `.pe-final-banner`.

## Known limitations (documented, acceptable)

- The **side panels** (Equations / Figures / Tables editors in
  paper-equations.js) edit blocks by id and are not section-aware — a
  determined user can still edit a completed section's figure caption
  from the panel. The document surface is fully locked; panel-level
  gating is a follow-up if it proves needed.
- Completion does not gate export — completed and open sections export
  identically (completion is a workflow state, not content).

## Verification

1. `✓ Complete` on a section with citations + a figure + a numbered
   equation → section locks (no caret anywhere, label included), prose
   renders serif/justified with typeset citations (superscript/[1]/(1)/
   author-year per the paper's template), "Figure N." caption, (N) on
   the equation; inserters/toolbars/skeletons gone; banner shows
   completer + date.
2. Status filter set to "draft" → completed section still shows all
   blocks; other sections filter normally.
3. Reorder the completed section (▲/▼) → stays completed (tree
   round-trip).
4. Second browser on the same paper → sees the section flip to final
   form live (secMap observer); Reopen from either side restores.
5. Read-only viewer → sees final form, no Reopen button.
6. Outline shows ✓; Delete ✕ absent while completed.
7. `node --check rm/js/paper-editor.js` passes. No Firebase deploy.
