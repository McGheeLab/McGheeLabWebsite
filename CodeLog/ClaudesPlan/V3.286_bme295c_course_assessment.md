# Plan — Course Assessment tab (V3.286)

## Context

BME 295C is a one-week intensive course (Mon 2026-06-08 → Fri 2026-06-12). The admin wants to ask students for structured end-of-course feedback so the next cohort's course can be improved. The class ends Friday, so this needs to ship in time for students to fill it out before they leave on Friday afternoon.

Three confirmed product decisions:

1. **Scope**: 8 course-level questions (Likert / 3-way pick / free-text) + a per-speaker block (1-5 stars + optional comment per speaker). ~10 minutes to fill out.
2. **Gate**: new `assessmentState: 'closed' | 'open' | 'locked'` field, default `closed`. Admin opens it Friday at the right moment. Same pattern as V3.269 discussion gates.
3. **Anonymity**: opt-in checkbox per submission. UID is still the docId (so the student can edit their own draft), but the admin UI hides name + photo when the flag is set. Honor-system — fine for a 22-student cohort.

## Approach

### Data model

One doc per student at `schedules/bme295c/assessments/{auth.uid}`:

```js
{
  classId: 'bme295c',
  ratings: { overall: 4, prepared: 5, groups: 3 },                  // 1-5 ints
  picks:   { pace: 'just_right' },                                  // discrete
  texts:   { liked_most: '...', improve: '...',
             recommend_text: '...', staff_shoutout: '...' },
  perSpeaker: {
    'Jennifer_Barton': { stars: 5, comment: 'best talk' },
    // ...one entry per rated speaker
  },
  anonymous: false,
  status: 'draft' | 'submitted',
  submittedAt: serverTimestamp,
  lastEditedAt: serverTimestamp,
  lastEditedBy: auth.uid,            // always uid, even when anonymous
  lastEditedName: 'Mitchell, Lilly', // from roster.name; admin sees it regardless of anonymous flag
  campusAtWrite: 'Tucson',           // effective campus at submit (V3.272-style)
  rosterIdAtWrite: '24121995',       // for admin cross-check
  gateStateAtWrite: 'open',          // V3.285-style audit field
  testMode: true | undefined,        // V3.250 wipe-tests tag
  appVersion: 'V3.286'
}
```

### Question set (hardcoded in class-builder.js — course-shaped, not content-shaped)

Course-level:
- `overall` — 1-5 stars — "Overall, how would you rate this course?"
- `prepared` — 1-5 stars — "How prepared do you feel for a college-level BME class?"
- `pace` — 3-way pick — "The pace was..." (Too slow / Just right / Too fast)
- `groups` — 1-5 stars — "How well did the small-group discussions work for you?"
- `liked_most` — free text — "What was the best part of the week?"
- `improve` — free text — "What would you change about the course?"
- `recommend_text` — free text — "Anything you'd want a future student to know?"
- `staff_shoutout` — free text — "Any shout-outs for the instructors or organizers?"

Per-speaker (one collapsible section grouping the 10 speakers by day, mirroring the schedule tab layout):
- 1-5 stars (optional, neutral default)
- One free-text comment (optional)

Submit footer:
- Anonymous checkbox (default off; honor-system, matches the V3.251 chat anonymous-toggle pattern at [class-builder.js:8042-8045](class-builder.js#L8042-L8045))
- Submit button (flips `status: 'draft'` → `'submitted'`)
- Per-section completion indicator + word count
- "You can edit any time before the deadline" disclaimer

### Save path

New `saveBmeAssessment(payload, statusOverride)`. Mirrors [class-builder.js:5279-5564](class-builder.js#L5279-L5564) (`saveBmeGroupResponsePrompts`), adapted for a single-doc-per-student write:

- Preconditions, each surfaced via the V3.285 `showDropReason` UX (visible reason + red button flash):
  - Not signed in → "session expired"
  - Not on roster → "you're not on the roster"
  - `assessmentState !== 'open'` → "course assessment is `<state>` — check back later"
  - `_adminViewOverride?.type === 'student'` → "admin preview can't submit on behalf of a student" (guards against writing under the admin's uid with a student's name)
- Payload: full doc (not partial — single-doc autosave model). Adds `gateStateAtWrite: 'open'`, `appVersion`, `testMode` tag if in test mode.
- Firestore: `set({ ...payload }, { merge: true })` to `schedules/bme295c/assessments/{auth.currentUser.uid}`.
- 800ms debounced autosave on every form mutation (mirrors `_bmeResponseSaveTimers` at [class-builder.js:5174-5175](class-builder.js#L5174-L5175)); explicit submit flips `status: 'submitted'` and stamps `submittedAt`. The submit button reuses the V3.285 in-flight guard (`_bmeSubmitInFlight` + `btn.disabled` + `clearTimeout` on pending autosave) — both the autosave-race-clobber and double-click-clobber fixes apply identically here.

### Firestore rules

Add inside `match /schedules/{scheduleId}` in [firestore.rules](firestore.rules), after the `classQA` block at line 281:

```
// V3.286 — end-of-course assessment, per-student doc keyed by uid.
// Read: own doc + admins (global isAdmin() OR classAdminEmails on the schedule).
// Write: self only. Delete: admin only.
match /assessments/{uid} {
  allow read: if request.auth != null && (
    request.auth.uid == uid
    || isAdmin()
    || (request.auth.token.email != null
        && request.auth.token.email in
            get(/databases/$(database)/documents/schedules/$(scheduleId))
              .data.get('classAdminEmails', []))
  );
  allow create, update: if request.auth != null
    && request.auth.uid == uid
    && request.resource.data.lastEditedBy == request.auth.uid;
  allow delete: if isAdmin();
}
```

Stricter than `groupResponses` (which is `allow read: if true`) because free-text feedback is sensitive. The `request.resource.data.lastEditedBy == request.auth.uid` check is cheap paranoia preventing spoof writes.

Deploy with `firebase deploy --only firestore:rules`.

## Verification

Local dev: `python3 -m http.server 8000`, then `http://localhost:8000/#/classes/bme295c`.

1. **Tab visible / hidden by state.**
   - Signed-out viewer: assessment tab shows, body shows "sign in" callout.
   - Non-roster signed-in user: body shows "you're not on the roster" callout.
   - Roster student with `assessmentState = 'closed'`: body shows "opens Friday afternoon" placeholder.
   - Admin: dashboard tab shows the new gate panel + (after submissions) histograms / free-text / per-speaker panels.

2. **Open the gate.** As admin, click "Open assessments" in the gate panel. Confirm `_classData.assessmentState` flips to `'open'` and persists (refresh — gate stays open).

3. **Student fills form.** Sign in as a roster student. Type in `liked_most`, click stars on `overall`, click "Just right" on `pace`. Confirm:
   - Status footer flips to "Saving..." then "Saved" after 800ms debounce.
   - Hard-reload — answers come back; doc shape in Firestore console matches the data model above.

4. **Submit + lock-out.** Click Submit. Status flips to "Submitted ...". As admin, flip gate to `'locked'`. Reload as student — form goes read-only with the V3.285 lock callout. No save path accepts writes.

5. **Anonymous toggle.** Tick anonymous, type a comment, submit. As admin, confirm the free-text panel shows "anonymous" in place of the student's name. Admin DevTools: the doc's `lastEditedName` field still holds the real name (honor-system caveat).

6. **Snapshot propagation (V3.285 onSnapshot).** Two browser tabs. Tab A (admin) flips gate Open. Within ~2s Tab B (student) sees the form unlock without a reload. Same test for `'open'` → `'locked'`.

7. **Adversarial edges:**
   - As admin in "View as student" mode (V3.248 `_adminViewOverride`), clicking Submit bails with the `showDropReason` "admin preview can't submit" banner. The admin's uid never gets a feedback doc written under it.
   - 22 docs × 1 per student × ~5 KB each is well inside Firestore quotas.

8. **CSV exports.** As admin, click each CSV button. Both files open in a spreadsheet cleanly (proper escapes, headers, no leakage from anonymous toggles into the numeric CSV).

9. **Rules deploy.** After `firebase deploy --only firestore:rules`, confirm in the Firebase console rules playground:
   - A student's auth.uid cannot read another student's `assessments/{otherUid}` doc.
   - An admin auth can read all assessment docs.
   - An unauthenticated client cannot read any assessment doc.
