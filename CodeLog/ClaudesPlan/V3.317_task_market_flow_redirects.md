# V3.317 — Task Marketplace: existing flows redirect through the market (FuturePlan 04, Release A3)

## Goal

The marketplace becomes the *only* cross-user task channel. "Send to
teammate" creates a directed handoff post (auto-accepted for admins so
the PI direct-assign UX is unchanged); the Tasks workspace can offer a
subtask to the board or ask a teammate for help on it; the legacy
Sharing page's Sent/Assigned tabs fold into the market page as an
Assignments view; members get the "I need work" one-click request
(button shipped in A1 — the full loop closes here). Huddle
help-requests stay separate (different domain).

## Changes

### rm/js/task-assign.js — Send-to-teammate goes through the market
`_submit` now writes a `taskMarket` post (kind `handoff`, directed at
the assignee, `task_payload` = the full task fields it used to write
directly):
- **admin sender** → post is born `status:'accepted'` +
  `claimedByUid = assignee` + a pre-generated `marketTaskId`, and the
  task is *also* written into the assignee's queue via `writeTaskFor`
  (stamped `marketPostId`) — identical end state to today plus a board
  paper-trail. The A2 function pushes the "Task from X" notification
  (the legacy tasks.js push skips `marketPostId` docs).
- **non-admin sender** → post is born `open`; NO task write. The target
  gets the handoff push, and accepting on the board materializes it.
  `opts.onCreated` only fires when a task doc actually exists (admin
  path) — PMR's back-link chip appears on accept for non-admin sends
  (follow-up niche; documented in the file header).

### rm/js/task-market.js
- **Embeddable**: `ensureBoot()` (auth + members) is separated from the
  board wiring, so pages without `#tm-board` (tasks.html) can load the
  script purely for `TASK_MARKET.openComposer` — no stray Firestore
  listener.
- **Claim/accept restructure**: `marketTaskId` is pre-generated and
  written **in the same update** as the status transition — the rules'
  transition machine (correctly) rejects a second patch after the post
  leaves `open`. Task write follows with that id.
- **Assignments view** (folds rm/js/sharing.js's tabs in): top-level
  view tabs Board | Assignments (`?view=assignments` deep-link). The
  Assignments view carries the three feeds as filters — Sent by me
  (collectionGroup `tasks` where `createdByUid==me`), Assigned to me
  (`api.subscribe('tasks/assigned.json')`), Lab-wide (admin) — plus the
  open/all/done status filter, paper/task kind chips, overdue chip, and
  →tasks/→paper links. (Paper-comment lazy expansion from sharing.js is
  intentionally dropped — it belongs to the library comments surface.)
- Composer accepts `prefill.due`.

### rm/js/tasks-buckets.js — workspace → market
Subtask rows gain a `⇄ market` button (next to `→ task builder` /
`＋ PMR`) opening a mini-menu: **📋 Offer to market** (kind `offer`) and
**🤝 Ask for help** (kind `handoff`) — both open the market composer
prefilled with the subtask text/notes/due and
`source_ref {projectId, bucketId, subtaskId}`. tasks.html loads
task-assign.js + task-market.js.

### Retirement of the Sharing page
- rm/pages/sharing.html → `<meta refresh>` redirect to
  `task-market.html?view=assignments` (V3.53 wrapper-redirect precedent).
- nav.js: 'Sharing' entry removed; `_WF_DEFAULT_SEEDS` task-scheduling
  workflow swaps pageId `sharing` → `task-market` (mirror updated in
  page-registry.js — the two lists must stay in sync).
- rm/js/sharing.js stays on disk (orphaned; delete after the fold is
  verified in prod — noted in CHANGELOG).
