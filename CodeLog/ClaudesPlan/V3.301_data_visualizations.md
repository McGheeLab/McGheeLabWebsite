# V3.301 — Data Visualizations section + embeddable 3D viewer

## Goal

Surface the self-contained WebGL2 viewer `DataIllustrations/viewer3d.html` (4.3 MB,
raw WebGL2, all data base64-embedded, zero external deps) on the public site:

1. **Collection page** at `#/data`, reached from a gateway card on the Research
   page (deliberately not a top-level nav item). Registry is the static
   `DataIllustrations/manifest.json` (FTP deploy, same pattern as
   `modules/manifest.json`).
2. **Full viewer page** at `#/data/{vizId}?view={viewId}` where lab members
   (contributor+, i.e. signed-in non-guest) arrange camera/toggles/sliders and
   **save named view presets** — config JSON + an auto-captured WebP poster set —
   to the new Firestore `vizViews` collection.
3. **Story/news embeds**: a third section-media type beside image/video. Feeds
   show the saved poster instantly; an IntersectionObserver swaps in the live,
   animating, chrome-less viewer when scrolled into view. Clicking anywhere goes
   to the full viewer with that saved view applied.

Projects are out of scope this version — a project's linked stories carry the
embeds. Extension point: `projectPackages` could gain an optional `viz` field
rendered by `buildProjectExpandedHTML()` with the same `.viz-embed` markup.

## Key decisions

- **Centralized viz folders**: everything visualization-related lives under
  `DataIllustrations/` — a viz is a single HTML file at the root or its own
  subfolder (e.g. `DataIllustrations/granular-flow/index.html`; folder-per-viz
  is the convention going forward). The manifest `file` field accepts relative
  subpaths; `vizViewerUrl()` sanitizes per-segment and drops `..`/`.`. The
  standalone `granular-flow/` folder moved from repo root accordingly.

- **Config-in via URL hash** (`viewer3d.html?embed=1#cfg=<base64 JSON>`): no
  load-timing handshake (config applies before the first painted frame), works
  under `file://`, and gives shareable deep links. Read-back (`__getConfig`,
  `__snapshotBlob`) uses same-origin `iframe.contentWindow` calls; the saved-view
  strip applies views in place via `__applyConfig` (no iframe reload).
- **Denormalized embeds**: the picked view's `{vizId, viewId, name, file, poster,
  config}` is copied into the story/news section. Public feeds render with zero
  extra Firestore reads, and published stories keep a frozen "as-cited" look if
  the view is later edited or deleted (`viewId` is kept for click-through; a
  missing view doc just opens the viewer at defaults). Re-picking refreshes.
- **Poster pipeline reuse**: `__snapshotBlob()` (a refactor of the existing
  Snapshot button into `bakeSnapshot()`) feeds the site's standard
  `processImage()` → `uploadImageSet()` WebP `{thumb, medium, full}` contract at
  `vizViews/{viewDocId}/poster/`.
- **Resource discipline**: at most `MAX_LIVE_VIZ = 2` live embeds; the iframe is
  destroyed when it leaves the viewport (frees the WebGL context — browsers cap
  ~8–16 per page — and the decoded ~50 MB of typed arrays). The viewer pauses its
  rAF loop on `visibilitychange`. `viewer3d.html` is NOT precached by the SW.
- **No composite index**: `getVizViews`/`getAllVizViews` use `where()` only and
  sort client-side by `createdAt`.
- **Collapsed-card timing**: embeds sit inside `.expandable-details[hidden]`; a
  hidden element has zero rect → not intersecting; expanding fires the observer
  naturally. If a browser misbehaves, the fallback is one line in
  `wireExpandable`'s expand path re-poking the observer.

## Deploy

- FTP the static tree (viewer3d.html, manifest.json, app.js, user-system.js,
  styles.css, user-styles.css, sw.js) to godaddy.
- `firebase deploy --only firestore:rules,storage` from repo root.

   resolves a PNG blob.

4. Save view as contributor (doc + posters + strip thumb; strip click swaps view
   without reload; `?view=` cold-load works; guest sees no Save control and rule
   blocks a forced write).
5. Story + news editors: picker → poster preview → draft persists → publish.
6. Public feed: poster → live on scroll-in → click-through → iframe removed on
   scroll-out; ≤2 live at once; phone-width OK.
