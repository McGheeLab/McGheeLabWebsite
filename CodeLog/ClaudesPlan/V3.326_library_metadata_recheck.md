# V3.326 — Bulk metadata re-check for the whole library

> Follow-up to FuturePlan 01 (V3.308–V3.311), user request 2026-07-11:
> "we also need the ability to re check papers already in the library for
> all meta data." The per-paper tools shipped in V3.309/V3.310 (✎ editor,
> ↻ Refresh from DOI) fix one paper at a time; the backlog of papers
> imported before V3.308 (broken prod lookup era) needs one sweep.

## Goal

One toolbar action re-checks EVERY library paper's metadata: identifier-
holding papers are re-looked-up and their gaps filled (optionally fully
refreshed), papers missing references/abstract get Semantic Scholar
enrichment, and identifier-less papers get a title-search match queued for
per-row human review (never auto-applied). Progress, counters, and a
review list live in one focused modal.

## Problem

Papers ingested while prod lookup was broken sit with `title=filename`,
empty authors, no DOI, no abstract, no references. V3.310's `fullRefresh`
repairs one paper per click; there is no way to sweep the ~whole library.

## Approach

**New `rm/js/library-recheck.js`** — `LIBRARY_RECHECK.open(items, {onItemSaved})`:

- **Modal** (self-contained, V3.309 modal style): counts up front — total
  papers, with/without identifiers, "incomplete" (missing authors, year,
  journal, DOI, abstract, or refs). Options:
  - Scope: **Only incomplete** (default) | All papers.
  - ☐ Overwrite existing fields with fetched values (default OFF — fill
    missing fields only; identifier lookups are authoritative but bulk
    silent overwrites of hand-fixed fields are worse than gaps).
  - ☑ Fetch references + abstract via Semantic Scholar where missing
    (default ON; 3 s spacing — SS rate-limits unauthenticated clients).
- **Run loop** (sequential, cancellable):
  - Identifier papers (`doi`→`pmid`→`arxiv_id`): `LIBRARY_METADATA.lookup`
    (V3.308 function, metadataCache-backed) → merge (fill-blanks; full
    fetched-wins when Overwrite is checked; title only updates when
    Overwrite is on or the current title is empty) → **targeted
    `items/{id}.set` only when something changed** (V3.309 pattern —
    unchanged papers produce zero writes). Abstract fills the
    `details/main` extras subdoc when missing.
  - Refs/abstract missing + option on → `LIBRARY_UPLOAD.
    enrichItemFromSemanticScholar` (existing; "SS wins" logic untouched).
  - **No-identifier papers → title search** (Crossref bibliographic via
    the same lookup function), but the hit is only QUEUED — fuzzy matches
    are never bulk-applied. Live counters: updated / enriched / unchanged
    / needs-review / failed.
- **Review list** (after the sweep, same modal): one row per candidate —
  current title vs matched title/authors/year/journal/DOI — with
  **Apply** (fetched-wins merge incl. adopting the discovered DOI,
  `source:'manual'`→`'manual-edited'`) / **Skip**.
- `onItemSaved(updated)` lets library.js swap rows in `_libraryPapers`
  live; one `_render()` on close.

**Integration**: toolbar button "⟳ Re-check metadata" in library.html
(next to Missing PDFs), `_wireRecheck()` in library.js, module included in
`papersScripts` before library.js.

## Data model changes

None. Writes reuse V3.309's member-update rules clause; `metadataCache`
absorbs repeat lookups (identifier queries are cached 30 days — a re-run
of the sweep is nearly free upstream).

## Out of scope

Bulk Unpaywall PDF fetching (that's the V3.311 missing-PDF queue's job —
keeps the sweep light); scheduled/automatic re-checks (manual button
first); writing SS alignment data back to stored refs.

## Release ritual

1. This plan doc. 2. FTP only (no functions/rules). 3. CHANGELOG V3.326 +
ARCHITECTURE + CACHE_VERSION 298.

## Rollback

Client-only: git revert + re-FTP + CACHE bump. Writes are per-item and
identical in shape to V3.309 editor saves; no migration to undo.

## Verification

- Library with a mix of complete papers, DOI'd-but-sparse papers, and
  filename-titled `source:'manual'` rows: run with defaults → sparse DOI'd
  rows gain year/journal/authors/abstract/refs; complete rows report
  "unchanged" (no Firestore writes — check network tab); manual rows show
  up in the review list; Apply on one adopts the matched record + DOI,
  Skip leaves the other untouched.
- Re-run immediately: everything unchanged, upstream calls served by
  metadataCache.
- Cancel mid-run stops the loop; already-saved updates persist.
- Overwrite mode on a test paper replaces edited fields with fetched ones.
