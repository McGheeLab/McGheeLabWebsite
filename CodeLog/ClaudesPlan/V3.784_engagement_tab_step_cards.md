# V3.784 — Engagement tab as seven step cards

Alex (2026-09-29): *"on the teacher hub, I want to make the engagement tab easier to walk
through, make multiple cards for each section, so teachers can walk through it without
losing their minds."*

## Goal

The Engagement tab (`#/teach/{id}/engagement`) mounts `engage-hub.js`'s teacher panel. Before
this release it was one long page: pending requests on top, then one card holding a nine-field
listing form (name, school, city, grades, subjects, size, topics, activity checkboxes, format
checkboxes) with the school address folded into a `<details>` under it, then availability, then
the request history. A teacher opening it for the first time had to work out the order for
themselves.

The goal is a walkthrough: one section per card, one card open at a time, and every card ending
in Back / Save & continue.

## Approach

Seven numbered cards in two groups:

| # | Card | Holds | Done when |
|---|------|-------|-----------|
| 1 | You and your school | name, school, city | name + school |
| 2 | Your class | grades, subject, class size | any of the three |
| 3 | Kinds of visit you want | activity + format choice cards (with a one-line hint each), topics | ≥1 activity and ≥1 format (enforced on Continue) |
| 4 | Where visitors go | private address, room, phone, arrival notes | an address (only *required* if "In person at the school" is ticked, otherwise marked Optional) |
| 5 | Send it to the lab | the listing rendered exactly as researchers see it + status + Send | approved |
| 6 | When your class is free | times grouped Every week / Particular dates / Skipped dates, a "what researchers see" preview of the next 4 weeks, add form with a 3-way segmented kind | ≥1 opening in 4 weeks; **Later** until approved |
| 7 | Visit requests | Waiting on you / Coming up / Past and declined (collapsed) | — (shows *N new* when requests are pending) |

A collapsed card is a single row: number bubble (✓ when done), title, one-line summary of what's
saved, and a state chip (To do / Waiting / Optional / Later / N new). The stack therefore doubles
as the checklist. The set-up group header shows *N of 5 done* with a bar.

**Which card opens:** a pending request beats everything, then the first unfinished set-up step,
then step 5 while it's with the lab, then step 6 if nothing is posted, else step 7. A callout at
the top points to step 7 whenever requests are waiting and a different card is open.

## Key decisions

1. **When the listing writes depends on its status.** It is still one doc
   (`engageProfiles/{uid}`) spread over cards 1–3. An owner write can only land `draft` or
   `pending` (rules), so:
   - *not sent yet* (none/draft): each card saves a draft on Continue, so leaving half-way loses
     nothing;
   - *pending or approved*: cards 1–3 do **not** write, because a per-card save would pull a live
     listing off the hub. Edits are held in a module-level `listingDraft`, and card 5 then says
     "You have changes to send", explains that the class is hidden until re-approved, and offers
     **Send changes for review** or **Discard changes**.
2. **paint() never writes; every write is followed by reload().** The panel renders from loaded
   state plus two drafts (`listingDraft`, `contactDraft`). Every keystroke lands in a draft, so a
   repaint (a card opening, a time added, a request decided) can't lose typing. A test covers
   this: type an address, press Back, reopen card 4, and the address is still there.
3. **Only a request decision refreshes the host.** It changes the tab badge (pending count). A
   listing, contact or slot write repaints just the panel, which avoids a full-hub rebuild and
   scroll jump on every Continue.
4. **Open-card state lives outside the render** (`openStep`, same pattern as
   `openLibFolder`). A remount caused by our own decision keeps its place (`keepPlace`), and a
   fresh visit to the tab re-picks automatically.
5. **Status messages land in the open card** (`[data-step-status]`), not at the top of a long
   page. `setStatus` runs **after** the refresh, the V3.771 lesson: the refresh rebuilds the
   element it writes to. The pre-V3.784 panel set status before `onChange()`, so in the embedded
   tab no teacher had ever seen "Visit confirmed", "Draft saved" or "Availability added".
6. **One listing renderer.** `listingHeadHTML(t)` is shared by the researchers' browse view and
   card 5's preview, so the preview can't drift from what researchers see.
7. **No data-model, rules, index or function change.** The same keys are written to the same
   docs.

## Also fixed

- **Subject pre-filled with the school name.** `teacher-teach.js` passed
  `classHint.subject = schedule.subtitle`, but the approve modal and `redeemTeacherInvite` both
  write the *school* into `subtitle`. The slot form now pre-fills from the teacher's step-2
  answers, falling back to the host hint only for size, where the hint is the online roster and
  is often not the physical class.
- The intro card's **"See the public hub"** link is removed: for a teacher, `#/engage` renders this
  same panel, not the researchers' view, so the link went back to where they already were.
- Slot form: rejects an end time at or before the start, and a date in the past; past dated or
  skipped slots are no longer listed (they no longer expand into openings).
- `.eh-teacher [hidden]{display:none !important}`: `.form-group` is `display:flex` and would
  otherwise beat `hidden` on the slot form's swapped fields (the third time this trap has come up).

## Verification

Headless against the demo fixtures (persona seeded in `sessionStorage`):

- **Hub tab, 36 checks.** A fresh teacher (`teacher-live`) walks 1→5: validation stays in its
  card, Enter continues, "Saved." appears in the next card, summaries update, the location
  becomes required once "in person" is ticked, the draft survives Back, Send → Waiting, and
  availability stays locked. An approved teacher (`teacher-engage`) gets step 7 auto-opened with
  a badge of 1, the callout appears once step 7 is closed, an edit advances without a write, card
  5 spells out the unlisting and Discard restores the listing, an end-before-start time is
  rejected, a time is added, Skip-a-date swaps the fields, and Confirm keeps step 7 open through
  the host refresh with the status visible and the badge cleared. No horizontal scroll at 375px.
- **Standalone `#/engage`, 8 checks.** The browse card is rendered through the shared head, the
  request form opens, the teacher panel works un-embedded, and Decline shows its status.
- 0 console errors. Desktop, mobile and per-card screenshots read.

Not covered: real Firestore writes. The data calls are unchanged, but the first real teacher
listing should still be watched.
