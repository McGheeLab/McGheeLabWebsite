# V3.944 — Scientia: on the desktop, a lab paper's Read opens in Scientia's reader beside the note

## Goal

In V3.943 I listed lab features that work on the website but not in the desktop app, and Gabe picked item 2 ("Incorporate 2"):

> **Opening a lab paper in the lab's reader.** On the website it opens over your note, with your highlights from the lab.
> On the desktop it opens the paper's page on mcgheelab.com in your browser instead. It could open in Scientia's own
> reader beside the note, with the same highlights.

## How the lab layer reads a paper today

`rm/scientia/lab-mode.js` `readPaper(r, focus)` asks its host (the Lab Notebook page around the web app) with
`hostRequest('rm-read', …)`. If no host acknowledges, it calls `openRM(RM.paper(id))`, which does
`window.open('/rm/pages/library-paper.html?id=…')`.

- On the desktop nothing hosts the app, so every Read opens the site.
- `serve.py` redirects `/rm/…` to mcgheelab.com.
- **Open in RM** calls the same `openRM` with the same address.

## Approach (no lab-layer change)

All of it is in `scientia/src/23d-desktoplab.js` (`RMREAD`), wired in `SIS_DESKTOP_AFTER_LAB`, so it runs only on the
desktop, after the lab layer.

1. **Telling a Read from Open in RM.**
   - `hostRequest` records each ask in `SIS_LAB.host.sent` before it waits, and Open in RM asks nothing.
   - `window.open` is wrapped. A `library-paper.html?id=` address, opened while the newest entry in `host.sent` is an
     `rm-read` nobody has taken yet, is a Read and stays in the app. Anything else goes to the browser as before.
   - A document capture `click` notes which card the click came from (`.box[data-id]`) and which RM highlight
     (`[data-ann]`). The lab layer's own handlers run after it.
   - The card's ⋯ menu "Read" is wrapped to say where the read comes from.
2. **The PDF.**
   - The hub already has `/api/rm/library/pdf?id=`, which returns a Storage download URL.
   - The lab's bucket only allows the lab site's origins (`storage-cors.json`), not `localhost:8766`. So `serve.py`
     gets a new route, `GET /api/rm-pdf?id=`, that fetches the file:
     - it accepts requests from this computer only;
     - it asks the hub as this computer's key;
     - it fetches only from `firebasestorage.googleapis.com`, up to 200 MB, and checks the bytes are a PDF;
     - it returns the PDF itself, or `{ok: false, error}`.
   - The file goes into the notebook's media (`MEDIA.add`, `rmPaper` on the record). The PDF card is placed beside
     the paper card (`rmPaper` on the block), else in the note on screen. With no note open (the Library's page of the
     paper), it goes in the paper's **Reading:** note (`READER.litDoc`), which opens.
   - The next Read opens the same card, and another note reuses the same file, so it also works offline.
3. **The reader.** `RDOCK.open` (13zzb) is the reader beside the note, as for any PDF card.
4. **RM's highlights.**
   - `api/rm/annotations?paperId=` (the same route the paper card uses) is read-only and cached for a minute.
   - The rows have the page and the quoted words, not positions. So each highlight is found by its words on the drawn
     page (letters and digits only, case-folded), then turned into rectangles with `RD2.rects`. This is measured once
     per drawn page.
   - The marks are drawn after the note's own quotes (a `QUOTE.paintMarks` wrapper) as `.rm-hl`: RM's colours (the
     lab layer's `HL`), with an underline.
   - The reader's side panel gets **From RM** under the note's own highlights (an `MXHL.open` wrapper; a
     MutationObserver puts the list back after each redraw). Clicking a row scrolls there and flashes it.
   - The **Highlights** button counts them (`… · RM n`). A highlight clicked on the paper card opens the paper at it.
5. **Falling back to the site.** When RM has no PDF of the paper (`rmPdf` false), the download fails, or the window is
   phone-sized, Read opens the paper's page on the site as before, with a message saying why.

## Decisions

- **Scientia's reader, not RM's.**
  - Gabe chose the item as worded.
  - RM's reader page needs the lab sign-in, which the desktop doesn't have. Running it locally would mean a port like
    the whiteboard's (V3.937) with a Firestore stand-in for annotations.
- **Highlights made here are quotes in the note; they don't go to RM.** Writing RM annotations would need a hub write
  route, which is a lab change. The side panel says so.
- **The detection relies on two lab-layer details:** the `rm-read` message name and `LAB.host.sent`.
  - Both are part of the host protocol, which the Lab Notebook page also depends on.
  - If they change, Read falls back to opening the site, which is today's behaviour.
- **For Alex (optional):** a one-line hook in `readPaper`, e.g. `if (LAB.readHere && LAB.readHere(r, focus)) return;`
  before `hostRequest`, would replace the `window.open` wrapper. Not done: the lab layer is not edited without asking.
