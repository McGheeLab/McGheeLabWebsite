# V3.853 — My Week: every step ends in a result (a specific card, by edit time)

Alex, 2026-10-23, three messages in one turn:

1. *"for all the items a user has added to myday, they need to add a result."*
2. *"results in myday can be links to figureboards, or links to notebooks. both
   of these hold the plots or images that would be the result."*
3. *"it should point to something specific in the figureboard or notebook. we
   will do this by item edit time. for example if i have a myweek input on
   monday, and wednesday i put a result into the canvas, when i select results
   on the myweek task, it shows up as a thing to point to. The whole point of
   this is to keep track of progress. as always barriers or not done is also
   an option."*

(Numbered V3.853 — V3.851 is the student-focus-proposals session, V3.852 the
notebook mobile sheet; all three ran in parallel on 2026-10-23.)

## Goal

A My Week step (`userData/{uid}/dayPlans/{itemId}`) is never closed without a
result, and a result is **evidence**: the specific card — a plot, a panel, a
photo, a note — that the student put on a paper's figure board or in their
notebook after planning the step. Barrier and no-result stay as the honest
alternatives. V3.623 made outcomes *available* (◇ chip, next-day nudge) but ✓
wrote `done` and only toasted, so the PMR ledger (V3.624) and project health
(V3.625) read mostly "✓ done" with nothing behind it.

## Approach

1. **The dialog is the confirm step.** ✓ on the day timeline, ✓ on the week
   row and "Did it" on a Waiting-on-you card open the outcome dialog with
   Result preselected; "Skipped" opens it with Barrier preselected. The step
   stays `planned` until Save: `DD.saveOutcome(item, payload, { closeAs })`
   writes outcome AND status in one update (`closedStatusFor`) and cascades
   exactly as `confirmDone` / `confirmSkipped` did. Cancel leaves it planned
   (info toast). Focus-task and meeting/chore loop-closure run after the save
   when the item became done.
2. **"Where is the result?" lists cards by edit time.** `loadResultSources`
   enumerates my boards — the figure boards of papers I'm an author on
   (`papers/{pid}/boards/main/items`) and my notebook entries with a board
   (`notebook/_index` rows with `board_id` → `userData/{me}/notebookBoards/
   {bid}/items`) — and runs one query per board:
   `where('updatedAt', '>=', step.created_at).orderBy('updatedAt', 'desc')
   .limit(40)` (a single-field index; no deploy). Widgets only (regions,
   instances and ink text are not results). The cards are picture tiles (thumbnail
   or a 📊/📓 glyph, two-line title, "kind · weekday", a check badge when
   chosen) grouped under the board or entry they live on, newest group
   first; a "Find a card…" box past six cards; a quiet "Show older cards"
   link re-lists without the time filter (choices kept). The dialog itself:
   an eyebrow ("Done ✓ · planned Fri, Oct 23") over the step's title, one
   segmented Result · Barrier · No result choice, and for a Barrier or No
   result the text leads while the cards fold into "＋ Attach a card" —
   Alex rejected the first cut's checkbox rows as "terrible and confusing".
   Nothing since the step was planned → the list
   says so and links the notebook and the Paper builder.
3. **The link lands on the card.** A tick saves `outcome.links[] = {kind:
   'figure_board_item'|'notebook_item', boardId, itemId, paperId|entryId,
   boardTitle, item_kind, title, thumb, url}` with `url` = `figure-board.html?
   paper=…&item=<id>` / `notebook.html?entry=…&item=<id>`. Both hosts read
   `?item=` after mounting and call the engine's new `inst.focusItem(id)`
   (`focusItemById`: animate the plane to the card's centre at the current
   zoom, pulse `.wb-item-flash`; retries while the items snapshot arrives).
   The PMR ledger renders the same deep links with thumbnails.
4. **Required fields, inline.** Result: at least one of {card, image,
   sentence}. Barrier: the reason. No result: nothing. The error renders in
   the pinned Save row — no browser popups
   ([[feedback_no_browser_input_popups]]) and nothing hidden under a phone
   fold.
5. **The nudge counts the same day, four weeks back.** `needsResult(it,
   today)`: done/skipped without a result with `date <= today`; planned with
   `date < today`; never cancelled. PMR's `isUnaccounted` agrees.

## Key decisions

- **Status flips on Save, not on click.** Done and the result are one act; a
  misclick costs nothing (Cancel = still planned).
- **✓ + "No result" stays done** (`closeAs:'done'`): "ran it, nothing came
  out" is a done step with a null result. V3.623's inference (no_result →
  skipped) is kept only when there is no click intent (the ◇ chip).
- **Edit time, not creation time**: a figure card planned last month and
  filled in on Wednesday is exactly the result; `updatedAt` catches it.
  `created_at` of the step is the floor; a step without one (pre-V3.526)
  uses the start of its day.
- **Cards, not boards or entries.** Alex's third message: the point is to
  track progress, so the link names the thing that changed. Whole-entry
  `notebook_entry_ids` from V3.623 outcomes are preserved but no longer
  offered.
- **A sentence still passes** ("ordered the reagent — arrived" needs no
  card); the empty-handed save is what's gone.

## Verify

- Day view: ✓ on a planned step → "Done — what's the result of …" with the
  cards touched since the step was planned, newest first; Save with nothing
  → inline error, nothing written; tick a card → "Save & mark done" → ✅
  Result 📊 chip, status done, copies cascade, focus task checks off.
- The chip's link / the PMR ledger link opens the board and the card pulses
  in the centre of the view (figure board and notebook).
- "Show everything" lists older cards; a tick survives the re-list.
- Cancel → still planned, info toast. "Skipped" → Barrier, empty reason →
  inline error.
- Nudge: a step marked done yesterday on an older build shows "1 step needs a
  result" today.
- `node scripts/tests/myweek-needs-result.test.mjs`; the harness via the
  browser skill (`python3 -m http.server` from the repo root).
