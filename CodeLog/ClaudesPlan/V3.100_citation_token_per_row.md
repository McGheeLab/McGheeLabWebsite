# V3.100 — Citation panel: per-row token shows `[n]`, not the cluster

## Goal

Follow-up to V3.99. After clusters were expanded into one row per ref,
the panel rendered:

```
[1, 2, 3]   Bing 2009 …
[1, 2, 3]   Hubert 2009 …
[1, 2, 3]   …
```

Reported:
> *"these [1,2,3] needs to just be [1] Bing 2009 etc"*

The cluster token was correct in V3.99 (the literal text in the PDF),
but as a per-row label it reads as duplicated noise — the user already
knows the row corresponds to ref 1 from the preview, so the token
should be `[1]`. The narrowed flash rect from V3.99 still anchors the
row to its specific digit in the PDF.

## Approach

One-line change in [rm/js/paper-citations.js](../../rm/js/paper-citations.js)
inside `_scanPage`'s numeric loop: synthesize `'[' + exp.n + ']'`
instead of using `m[0]` (the cluster). Author-year matches are
unchanged — they're already one ref per token.

## Files changed

- **`rm/js/paper-citations.js`** — `pushMatch` for numeric kind passes
  `` `[${exp.n}]` `` as the token.
- **`sw.js`** — `CACHE_VERSION` 74 → 75.

## Verification

1. Hard reload (evict SW `mcgheelab-shell-v74`).
2. Open a paper with cluster citations like `[1, 2, 3]`.
3. Panel shows three rows labelled `[1]`, `[2]`, `[3]` — not three
   rows all labelled `[1, 2, 3]`.
4. Hover each row — flash still lands on the correct digit inside
   the original cluster (V3.99 behavior preserved).
