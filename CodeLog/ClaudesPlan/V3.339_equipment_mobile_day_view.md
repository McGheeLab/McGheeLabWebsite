# V3.339 — Equipment Scheduler: mobile single-day calendar + touch UX

**Phase 2a of the FuturePlan 08 equipment-scheduler upgrade**
(`CodeLog/Feature requests/FuturePlan_08_equipment_scheduler.md`).

## Goal

Students book equipment from their phone while standing in front of the
instrument. The week view crammed 7 columns × 48 half-hour rows onto a
phone screen (unusably small drag targets), and the page carried the
non-canonical 768px breakpoint flagged since the V3.51 port.

## Approach

### Single-day view on narrow screens (`rm/js/equipment.js`)

- New `isNarrowScreen()` helper — `matchMedia('(max-width: 640px)')`,
  RM's canonical mobile breakpoint (22 uses across rm/css vs one 768px).
- New `_dayIdx` state (0–6, Mon–Sun). On narrow screens `renderWeekView`
  renders **one** day column (time gutter + single wide column,
  `.eq-week-grid--day`) with a `.eq-day-pager` strip of 7 day chips
  above it; first entry defaults to today when viewing the current week.
  All existing cell/block/drag logic operates on the 1-element `days`
  array unchanged — drag-to-book, zoom, the time slider, closed-slot
  greying (V3.336), and multi-day booking segments all work as before.
- Month-view day click now also sets `_dayIdx` so narrow screens land on
  the tapped day.
- A `matchMedia` change listener re-renders the calendar when the
  viewport crosses the breakpoint (rotation, window resize).

### CSS (`rm/css/equipment.css`)

- `.eq-day-pager` / `.eq-day-chip` (44px minimum touch targets, active +
  today states), `.eq-week-grid--day` column template.
- The mobile media block moves 768px → 640px and gains 44px minimum
  touch targets for the calendar chrome (nav/view/zoom buttons, device
  select, New Booking) plus slightly larger block/label type.

## Key decisions

- **ScheduleUtils adoption dropped** (was a roadmap line item): the
  module isn't loaded by equipment.html, its `getWeekDays` returns label
  objects rather than Dates (every call site would change), and its
  `getMonday` jumps to *next* week's Monday when today is Sunday —
  adopting it would trade a working Sunday-safe helper for a regression.
  Rationale recorded in a comment next to the local helpers.
- Single-day (not 3-day) on narrow screens: booking a slot needs precise
  vertical taps; one wide column maximizes target size.

## Files modified

- `rm/js/equipment.js` — `_dayIdx` state, `isNarrowScreen`, day-pager in
  `renderWeekView`, chip wiring, month-click day landing, breakpoint
  listener
- `rm/css/equipment.css` — day pager/chips, `--day` grid, 640px block
- `sw.js` — CACHE_VERSION 310 → 311

## Verification

- `node --check` on equipment.js.
- Local server: shrink the window under 640px on the Calendar tab —
  grid collapses to one day with chips; tap chips to switch days;
  drag-to-book a slot; rotate/resize across the breakpoint re-renders;
  month → day tap lands on that day. Desktop width unchanged.
