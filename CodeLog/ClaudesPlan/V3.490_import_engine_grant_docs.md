# V3.490+ — Import-at-list engine + Grant Docs PDF page + full-parity checklist

> A program (multiple releases). Three user asks: (1) importing a .zip shows
> live progress for every phase and does **not** auto-open the paper; (2) grant
> PDF attachments live on a dedicated **Grant Docs page**, not as manuscript
> sections; (3) that page carries a **submission checklist** at full parity
> with `GELS CAREER/Working docs/admin/submission_checklist.html`.

## Decisions (from Alex)

1. **All at import, no open.** The whole materialization pipeline (unzip →
   build sections → upload figures → attach PDFs to grant docs → place + link
   references) runs at import with a progress modal on the LIST page; the
   finished paper then sits in the list to open manually.
2. **Retire section PDF slots.** Every grant PDF becomes a row on the Grant
   Docs page (per-paper store); the manuscript holds only narrative +
   references. The per-section `uploaded_file` upload slot is removed.
3. **Full-parity checklist.** Add callout cards (returned-without-review /
   do-not-include), legend, two-table manifest grouping, deadline banner,
   sticky progress — matching submission_checklist.html. State stays per-paper
   (`paperExports/{id}.checklist`).

## Design

### New per-paper PDF store
`paperExports/{paperId}.grantDocs = [{ id, kind, label, filename,
storage_path, download_url, mime, size_bytes, uploaded_by, uploaded_at }]`.
Reuses the existing per-paper shared config doc (rules: lab-contributor write,
`firestore.rules:1033`) — **no rules change**. PDF bytes via
`PAPER_FIGURES.uploadImage(paperId, blob)` (same Storage path as today).

### Bundle format change
Grant docs no longer travel as `tree.sections` with `uploaded_file`. The
bundle carries a top-level `grant_docs: [{ kind, label, filename, asset:
{hash, ext, relpath, storage_path_original, mime} }]`. The manuscript tree
keeps only narrative + references sections. (`references[]` from V3.484 stays.)

### Isolation choice (risk control)
A **NEW** `rm/js/paper-tree-build.js` (`window.PaperTreeBuild`) holds a
self-contained bundle-tree → Yjs builder (section/block/deep-attr), used by the
import engine. **paper-editor.js's own builders are left untouched** — the
editor file has been fragile across recent work; a shared-refactor is higher
risk than a second, harnessed builder. A harness round-trips a bundle through
`PaperExportBundle.serialize` shape → `PaperTreeBuild` → re-serialize to prove
fidelity + equivalence with appendBlockFromTree's contract.
