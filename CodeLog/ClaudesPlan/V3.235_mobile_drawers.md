# V3.235 — Mobile side-drawer pattern (Phase 3a of mobile compatibility)

> Phase 3a of the broader RM mobile-compatibility plan (full plan: `~/.claude/plans/i-want-to-make-rosy-scott.md`). V3.232 shipped design tokens; V3.233 standardized shell breakpoints + adapted top-nav + dropdowns. V3.235 makes the two **side-context-menu-heavy** pages (paper-builder editor, library-paper reader) phone-usable by converting their left + right panes into swipe-in drawers.

User direction: "*paper writer still needs some work. think about the left and right context menus becoming swipe in from the side when we are on the phone version. paper reader and probably other pages can also do the same thing where if there is a set context menu that would otherwise overshadow the phone screen, we can make it appear via swip in from the left or the right.*"

## Goal

Build a reusable opt-in pattern any RM page with side context menus can adopt. Land it on the two highest-impact targets first:

1. **Paper-builder editor** — `.pe-sidebar` (outline + paragraph mirror) → left drawer; `.pe-comments-pane` (comments list + composer) → right drawer.
2. **Library-paper reader** — `.lp-side` (paper metadata, citations, tags) → left drawer; `.lp-annotations` (PDF nav + annotation list) → right drawer; PDF takes the full viewport.

Above 640px the drawer classes are inert — panes render in their natural flex/grid flow exactly as today on desktop and tablet. At ≤640px they fly off-screen until activated by topbar/toolbar buttons; a backdrop + Escape + the existing close-X all retract them.

## The reusable pattern

**CSS** (in [rm/css/style.css](../../rm/css/style.css)): opt-in class set —

- `.rm-mobile-drawer-host` — the container holding both panes (and `data-drawer="left"|"right"` attribute as open state)
- `.rm-mobile-drawer-left` / `.rm-mobile-drawer-right` — the two panes
- `.rm-mobile-drawer-backdrop` — backdrop element (JS-injected as first child of host)
- `.rm-mobile-drawer-toggle` — toggle button styling (display:none above 640px; inline-flex below)
- `.rm-mobile-drawer-toggle-badge` — optional count badge inside the toggle (used by the Comments toggle to show open-comment count)
- `body.rm-mobile-drawer-locked` — scroll-lock body while any drawer is open

At ≤640px the panes get `position: fixed; top: 0; bottom: 0; width: 85vw; max-width: 360px`, slide off via `transform: translateX(±100%)`, slide back to `translateX(0)` when host has matching `data-drawer="left|right"`. Backdrop fades in via `opacity: 0/1`. Body scroll lock saves `window.scrollY` and uses iOS-friendly `position: fixed; top: -<scrollY>px`.

**JS helper** ([rm/js/mobile-drawers.js](../../rm/js/mobile-drawers.js), ~100 lines, self-contained IIFE):

```js
window.MOBILE_DRAWERS.init(host, {
  leftToggle:  document.getElementById('pe-mobile-left-toggle'),
  rightToggle: document.getElementById('pe-mobile-right-toggle'),
  onOpen:  function (side) { /* page-specific hook */ },
  onClose: function (side) { /* page-specific hook */ },
});
// → returns { open(side), close(), toggle(side), host }
```

Injects backdrop if not present; wires backdrop click + Escape to close; toggles `data-drawer` on host; locks/unlocks body scroll with iOS Safari fix. Cached on the host element so `init()` is idempotent. Above 640px the wiring still installs but the CSS makes everything inert.

## Paper-builder

**HTML changes** ([rm/pages/paper-builder.html](../../rm/pages/paper-builder.html)):

- `.pe-page` gains `.rm-mobile-drawer-host`.
- `.pe-sidebar` gains `.rm-mobile-drawer-left`.
- `.pe-comments-pane` gains `.rm-mobile-drawer-right`.
- Two new `<button class="rm-mobile-drawer-toggle pe-mobile-toggle">` injected into `.pe-topbar`: `☰ Outline` (id `pe-mobile-left-toggle`) and `💬 Comments` (id `pe-mobile-right-toggle`) with a count badge `<span class="rm-mobile-drawer-toggle-badge" id="pe-mobile-right-toggle-badge" hidden>`.
- Script load list grows by `/rm/js/mobile-drawers.js` (in editor mode only).

**JS changes** ([rm/js/paper-editor.js](../../rm/js/paper-editor.js)):

- `recomputeCommentCounts()` also calls `_updateMobileRightBadge()` which renders the total-open count into the toggle badge (`99+` if >99, `[hidden]` if 0). Phone users see the count without opening the drawer.
- `closeComments()` extended to also call `host._rmMobileDrawersWired.close()` so the close-X inside the pane retracts the drawer (otherwise `[hidden]` would hide the pane while data-drawer="right" stuck around with an empty backdrop).
- New `_wireMobileDrawers()` runs on DOMContentLoaded. Wires the two toggle buttons via `MOBILE_DRAWERS.init`. `onOpen('right')` ensures the pane is `hidden=false` and defaults the filter to `'view'` (so the drawer is never empty even with no block focused), then calls `renderCommentsList()`.

**CSS changes** ([rm/css/paper-editor.css](../../rm/css/paper-editor.css)):

- Phone block tightens `.pe-topbar` spacing (gap 8px, padding 8/12px) and shrinks `.pe-title-input` to font-size 15px with `min-width: 0` so the four topbar items (☰ Outline, ← back, title, 💬 Comments) wrap cleanly. Existing `.pe-topbar { flex-wrap: wrap }` does the wrapping itself.

## Why side-drawers (vs the V3.231 plan's "bottom sheet + tabs" option)

The original Phase 3 plan called for paper-builder's comments as a bottom sheet and library-paper as a 3-tab view. Side-drawers are better because:

- **Consistent pattern across pages.** Two right-edge contexts (Comments, Annotations) and two left-edge contexts (Outline, Info) — same gesture, same affordance.
- **PDF stays full-bleed.** Tabs in library-paper would mean only one of {PDF, Details, Notes} is visible at a time; with drawers, PDF stays underneath and the user can reach metadata/annotations without losing the page they're reading.
- **Reusable.** The pattern is now a generic opt-in for any future page with side context menus.

## Verification

1. **Desktop ≥1024px unchanged.** Open `/rm/pages/paper-builder.html?paper=<id>` and `/rm/pages/library-paper.html?id=<id>` at 1440px — pixel-identical to V3.234. Toggle buttons in topbar / mobile-bar are `display: none`.
2. **Phone 390px** (Chrome DevTools iPhone 14 Pro):
   - Paper-builder editor: only the main editing pane visible; `☰ Outline` + `💬 Comments` buttons in topbar. Tap ☰ — sidebar slides in from left with backdrop. Tap backdrop — closes. Tap 💬 — comments pane slides in from right; if no block is focused the filter is `view` so paragraphs-in-view comments render. Tap the close-X inside the pane — pane retracts AND drawer slides out.
   - Library-paper reader: only PDF visible; toolbar bar at top with ℹ️ Info / title / 📝 Notes. Tap ℹ️ — left drawer slides in with paper metadata. Tap 📝 — right drawer slides in with annotations + PDF nav controls. Backdrop click or Escape closes.
3. **Comments badge live updates.** Add/resolve a comment on paper-builder — the `💬 Comments` count badge re-renders without opening the drawer.
4. **Body scroll lock works.** With a drawer open on phone, swipe the backdrop area — page behind doesn't scroll. Close drawer — page scrolls again at the original scroll position.
5. **No JS errors in console.** `mobile-drawers.js` is idempotent; reloading the page or navigating between papers doesn't double-wire.

## Out of scope (Phase 3b+)

- **Other Tier A pages** (tasks inbox sticky composer, calendar `.yr-line` 2-row card, chat sticky composer, lab notebook capture, huddle/training/people column stacking) — still pending. Drawer pattern doesn't apply to those; they get per-page CSS.
- **Tier C desktop-only interstitial** (split-view, workflow-shell, admin tools, budget/finance/analytics, grants editor, cv-editor, lab-tasks) — still pending.
- **Touch swipe gestures** — drawers open via button tap, not gesture. Adding edge-swipe-to-open could come later; needs careful tuning to avoid stealing horizontal-scroll inside the PDF viewer.
- **Tablet drawer mode.** On tablet (641–1024px) library-paper still uses the V3.233 stacked layout. Could be promoted to drawers later if user feedback shows the stacked layout is awkward — easy follow-up by changing the breakpoint in style.css's phone block to 1024px.

## Rollback

`git revert` of this commit restores V3.234. The drawer classes on `.pe-page`, `.pe-sidebar`, `.pe-comments-pane`, `.lp-split-3`, `.lp-side`, `.lp-annotations` are inert above 640px — removing the CSS rule + JS file is enough to fully undo. No data-model changes.
