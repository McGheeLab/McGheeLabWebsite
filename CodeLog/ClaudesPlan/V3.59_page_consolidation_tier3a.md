# V3.59 — Page consolidation Tier 3a: library-comments → library tab

## Goal

Tier 3a of the V3.57–V3.62 sweep. The cross-paper Annotations feed
merges into the main Library page as a tab. Reduce 2 pages → 1.

## Approach

Same `?tab=<name>` shell pattern V3.58 established for the Task hub,
adapted for Library. The Library page has substantially different DOM
between the two views (papers list vs annotations feed), so the shell
embeds **both** DOM blocks and uses CSS to hide the inactive one. Only
the active tab's renderer scripts are loaded — the inactive one
doesn't boot, doesn't query Firestore.

### Key design decisions

- **Both DOM blocks are static HTML** in [rm/pages/library.html](../../rm/pages/library.html). Wrapped in `.lib-papers-block` and `.lib-comments-block`. CSS rule `html[data-lib-tab="comments"] .lib-papers-block { display: none; }` (and inverse) hide the inactive block. The early `<script>` in `<head>` sets `document.documentElement.dataset.libTab` from the `?tab=` query so the CSS applies before first paint.
- **Per-tab scripts load via `document.write`** (same V3.58 pattern). Renderer's existing `DOMContentLoaded` boot fires at the natural time. The inactive tab's scripts never load → no wasted Firestore queries.
- **Inlined `.lc-*` styles** from the former library-comments.html into the unified shell. Scoped to `.lc-*` selectors so they're harmless on the papers tab.
- **The `<title>` element** is rewritten by the head script based on the active tab, matching the prior page-specific titles.

## Files modified

- **Rewritten:** [rm/pages/library.html](../../rm/pages/library.html) — unified shell. Was 188 LOC for the papers-only page, now ~290 LOC including the embedded comments DOM, the `.lc-*` styles inline, and the per-tab script loader.
- **Replaced with `<meta refresh>`:** [rm/pages/library-comments.html](../../rm/pages/library-comments.html) → `library.html?tab=comments`. Bookmarks survive.
- **Changed:** [rm/js/nav.js:41](../../rm/js/nav.js#L41) — "Comments" link under Research group repointed.
- **`sw.js`** — CACHE_VERSION 33 → 34.

## Untouched

- **`rm/js/library.js`** (1206 LOC) and **`rm/js/library-comments.js`** (877 LOC) — renderer scripts unchanged. Each still queries its own DOM IDs (`#library-tbody` for papers, `#lc-rows` for comments). With document.write loading only the active tab's scripts, only one renderer boots per page hit.
- **`rm/js/library-tags.js`** — common dependency loaded eagerly for both tabs (used by both renderers).
- **`rm/pages/library-paper.html`** — single-paper detail viewer. Unrelated, opened from a row click. Stays separate.
- **`rm/pages/library-public.html`** — anonymous read-only shared view. Different access model. Stays separate.
- **`rm/js/annotation-sync.js`** + **`rm/js/annotation-groups.js`** — required by `library-comments.js`. Loaded only when tab=comments.

## Trade-offs

- **Both DOMs in HTML adds ~150 LOC of static markup that never renders on the inactive tab.** Acceptable: the savings come from one fewer page in the nav + the user gets in-page tab swap (faster than separate-page navigate).
- **Tab switch is still a full page reload** (same as V3.58). The `?tab=` query change forces a navigation. With SW caching, this is fast (~150ms).
- **`html[data-lib-tab]` attribute selector approach** chosen over `body.lib-tab-X` class because the early head script can set the dataset before body parses, avoiding any flash of papers-block content when arriving with `?tab=comments`.
