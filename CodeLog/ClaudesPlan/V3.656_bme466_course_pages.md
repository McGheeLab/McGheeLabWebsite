# V3.656 — BME/AME 466/566 course pages (syllabus · schedule · learning modules)

> Approved plan (verbatim source): `~/.claude/plans/resilient-drifting-thacker.md`

## Goal

Give BME/AME 466/566 Biomechanics a presence on the site for F26: a syllabus page, a schedule
page, and a learning-modules page whose modules open to students only when the instructor
releases them.

## Why now

F26 classes started 2026-08-25 and the course had no page. `modules/bme466/` already existed
(HW-01 module + prompt, V3.655) but nothing linked to it — the folder was reachable only by
typing a URL.

## Key finding: this was configuration, not new machinery

`SECTION_REG` (class-builder.js) already carried generic **`syllabus`**, **`schedule`** and
**`modules`** section types, and `modules[].published` was already the release flag the public
renderer filters on. What was missing was the class document itself. So no new page, no new
route, no new gating mechanism — a `DEFAULT_SCHEDULES` seed plus content.

Notably we did **not** copy the BME 295C approach: that is ~7,000 lines self-documented as
"not generalized to other courses". BME466 uses the generic section types only.

## Decisions (Alex, 2026-08-25)

| Question | Decision |
|---|---|
| Scope | Existing generic sections; no bespoke BME466 surface |
| Access | Fully public — syllabus, schedule, released module list |
| Security | Store nothing sensitive; do not touch `firestore.rules` |

## Two bugs found by verifying rather than assuming

**1. `renderRichText()` could infinite-loop and hang the class page.** The paragraph branch
advanced `i` only inside a condition-guarded loop. A line that matched none of the block
branches would leave `i` unchanged and spin forever. The trigger is real and was in our own
content: a table whose header row is empty (`| | |`) satisfies `isTableSep()`, so the table
branch skips it, and every other branch declines it. Fixed by making the paragraph branch
**consume `lines[i]` before looking further**, so progress is structural rather than
conditional. Caught by a Node harness over the actual syllabus/schedule strings.

**2. `wireModuleViewer()` bailed out blank for any code-seeded class.** It read Firestore
directly — `.doc(classId).get()`, `if (!doc.exists) return;` — with no `DEFAULT_SCHEDULES`
fallback, unlike `renderClassPage`/`wireClassPage`. Net effect: the class page rendered from
the seed, but every module link opened a silently empty iframe until someone saved the doc to
Firestore. This would have hit students in production, not just localhost. Now routed through
`resolveSchedule()`, which already handles demo classes, Firestore, and the seed fallback, so
the two paths agree.

## Also fixed: `scripts/scan_modules.py` clobbered curated folder labels

The script re-derived `label` from the directory name on every run, so regenerating replaced
"Lab Foundations" with "Foundations", "TFM (Biomechanics 466/566)" with "TFM", and so on —
six folders. That is why the manifest was being **hand-edited** instead, and why
`modules/heat_transfer/` (7 lessons) had silently never made it into `manifest.json` and was
invisible to every picker, grant form, and approve modal.

The script now **preserves existing labels** and auto-derives only for new folders, printing a
line naming any new folder so its label can be curated. Regenerating is now safe, and
`heat_transfer` is registered.

## Known issue, deliberately not fixed here

`firestore.rules:424` is `match /schedules/{scheduleId} { allow read: if true; }` — the class
document is world-readable to anonymous callers over the REST API. Consequences:

- Release gating is **cosmetic**: an unreleased module's title and filename sit in the public
  document; `published:false` only stops the UI rendering the link. Module HTML under
  `modules/` is likewise a public static asset (accepted trade-off, V3.304 plan).
- **BME 295C stores `studentRoster[]` (names, emails, high schools, pronouns),
  `dailyAttendance` and `grades` on that document**, so those are publicly fetchable today.

BME466 therefore carries **no** roster, attendance, or grades — a comment in the seed says so
and why. Fixing the underlying rule is its own change: the model to follow is the
`assessments/{uid}` subcollection rule (`firestore.rules:493-506`), which does gate reads by
identity and does a parent-doc `get()` for the class-admin list.
