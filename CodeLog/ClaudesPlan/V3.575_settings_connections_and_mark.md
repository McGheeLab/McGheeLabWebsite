# V3.575 — Settings consolidation + Ourlab mark propagation

Two requests in one message: (1) redesign Settings to a single Connections
tab + a single Notifications tab, with no separate Calendar Sync tab; and
(2) finish the Ourlab logo mark — turned 90° CCW with the inlet as an "L".

## Part 1 — Settings: three tabs (Profile · Notifications · Connections)

### Problem

Settings had **two overlapping calendar systems** and connectors scattered
across the UI:

- A separate **Calendar Sync** tab (`renderCalendarSync`) driving the
  `CalendarService` singleton — Google (GIS), Outlook (Azure OAuth / ICS),
  Apple (ICS), plus Huddle blackout.
- The **`oauth-connections.js`** account cards (Gmail / Google Calendar /
  Outlook .ics), which the page mounted into a **page-level**
  `#integrations-host` div that rendered under *every* tab — so it looked
  like "connections at the bottom of the Profile tab."
- Five **per-type registry filter tabs** (Email / Calendars / Repositories
  / Messaging / Finance) plus "All Connections."

Net effect: "many redundant sign ins for various calendars," connectors
appearing on Profile, and a Calendar Sync tab duplicating the OAuth cards.

### Approach

Collapse to **Profile · Notifications · Connections**.

- `rm/pages/settings.html` — remove the page-level `#integrations-host`
  div; it is now created *inside* the Connections tab, so the OAuth
  connectors only appear there.
- `rm/js/settings.js`:
  - `TABS` = `[profile, notifications, connections]`. `_isConnectionTab()`
    ⇒ `activeTab === 'connections'`. Removed `_isConnectionTabKey`.
  - New `renderConnectionsTab(content, connections)` builds three stacked
    sections: (1) `#integrations-host` → `OAUTH_CONNECTIONS.render()`
    (Gmail / Google Calendar / Outlook .ics); (2) a collapsed `<details>`
    ("More calendar sync options — Apple Calendar, .ics files, Huddle
    blackout") wrapping `#conn-calsync` → `renderCalendarSync(...)` (folds
    the old tab in, de-emphasized to cut the Google/Outlook redundancy);
    (3) `#conn-registry` → `renderConnections(...)` under an "Other
    connections" heading.
  - `renderConnections` now always shows the full registry (no per-type
    filter) with a friendlier empty state.
  - The 8 `renderCalendarSync(document.getElementById('content'))`
    self-re-render calls now target the nested host via `_calSyncHost()`
    (`#conn-calsync` || `#content`).
- `rm/css/settings.css` — `.settings-conn-more` (details), `.settings-conn-
  registry`, `.settings-conn-h`.

No data-model, Firestore-rules, index, or Cloud-Function change — same
collections, same `settings/connections.json` route. Purely UI.

### Deliberately NOT done

The two calendar backends (`CalendarService` and the Cloud-Function-backed
`oauth-connections`) are both **kept** — deleting either risks breaking
existing users' connected syncs, which I can't test headlessly. The
redundancy is reduced by tucking CalendarService into a `<details>`; if
Alex confirms one backend is dead, a follow-up can remove it.

## Part 2 — Ourlab mark (CCW 90° + L inlet)

The brand SVGs (`brand/ourlab-mark.svg`, `ourlab-icon.svg`,
`ourlab-lockup.svg`, `ourlab-icon-1024.png`) were **already redrawn** to the
final geometry (well opens downward, inlet reads as an "L": the channel is
the L's stem rising into the amber droplet). What remained:

- Propagate the new paths/gradient into the **inlined** `OURLAB_MARK_SVG`
  used by the full-screen sign-in gate — `rm/js/mobile-shell.js` — and the
  orphaned `rm/js/app-shell.js` (kept in sync though it's now dead code).
- Regenerate every app icon + splash from `brand/ourlab-icon-1024.png`:
  `cp brand/ourlab-icon-1024.png assets/{icon-only,logo}.png` then
  `npx @capacitor/assets generate --iconBackgroundColor '#0A1730'
  --splashBackgroundColor '#0A1730'` (+ dark variants). iOS (8) + Android
  (86) + PWA (14) regenerated.
