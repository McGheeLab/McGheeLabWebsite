# V3.770 — Module Catalog: picking is the primary action, and every module opens

**Alex:** *"on RM/Teachers/Module Catalog I want to be able to: 1) select the
modules that are available for teachers to select 2) I want a link for myself
to click on and open each module to ensure it looks how i want it to."*

## Goal

The catalog tab (`rm/pages/admin-teachers.html?tab=catalog`, V3.669) is the
gate between the 69 modules in `/modules/manifest.json` and what teachers can
assign from `#/teach`. It already carried the gate — a `published` checkbox —
but the tab was built as a metadata editor that happened to have a tick in it,
and there was no way to look at a module before deciding.

Two asks, both about the same act: **decide whether a module is good enough to
hand a classroom, then say yes.**

## What was wrong

- **The tick was the smallest thing in the row.** Each of the 69 rows read
  `[ ] published | Title | [subjects] | [grades] | [one-line description]` —
  three text inputs surrounding an 11px checkbox. The control that changes what
  every teacher sees looked like a row label.
- **Nothing linked to the module.** The only way to check a lesson before
  publishing it was to know the folder and file name and type the URL.
- **69 rows, always all of them.** Twelve folders expanded at once, no search,
  no way to see "what haven't I decided about yet".
- Every tick re-rendered all 69 rows (`saveRow(...).then(renderCatalog)`), so
  the list jumped under the cursor while curating, and each folder bulk button
  re-read all fourteen Firestore collections (`loadAll()`).

## Approach

No data-model change, no rules change, no new collection — the field stays
`teacherCatalog/{folder--basename}.published`, which is what
`TC_DB.publishedCatalog()` queries (`where('published','==',true)`) to fill the
teacher's picker. This is a rewrite of `renderCatalog()` plus the tab's markup
and styles.

**The row becomes a decision.** A 16px tick labelled **Available** at the left,
the title with its file name beside it, any subjects/grades as a muted tag
line, then **↗ Open** and **✎ Details**. A ticked row is tinted and carries a
green left edge, so "what is switched on" is readable by scanning, not by
comparing checkboxes.

**↗ Open** is `/modules/<folder>/<file>` in a new tab (`rel="noopener"`) — the
module exactly as a student gets it, from the same manifest entry the catalog
row was built from, so a row can never point at a different file than it
publishes.

**Metadata moves to a second line behind ✎ Details** (`flex-wrap` puts the
full-width child on its own row). Subjects, grade levels and the description
are authored once per module; the tick is used constantly. They save on
`change` exactly as before.

**Finding things:** a bar above the list with a live count
(*N of 69 modules available to teachers*), filter chips **All / Available /
Not available**, **Collapse all**, and a search box over folder, file, title,
subjects, grades and description. The bar is static markup wired once — a
re-rendered search input would lose focus and the half-typed query on every
keystroke.

**Ticking repaints in place** (row class, folder header count, summary) instead
of rebuilding the list, so nothing moves under the cursor; the filter is only
applied on the next render, deliberately, because rows vanishing mid-click
would be worse than a momentarily stale filter. **A failed save reverts the
tick** and says so on the status line — the previous code left the box showing
a state Firestore had rejected.

Folder bulk **Select all / Clear all** keep their one batched commit but now
patch the local `catalog` array instead of re-reading all fourteen collections.

## Key decisions

- **Field name stays `published`; the label says "Available".** Renaming the
  field would orphan every existing catalog doc and `publishedCatalog()` with
  it. The UI word matches what the tick does — appear in a teacher's picker.
- **Open in a new tab, not an inline preview.** `#/teach`'s Modules tab already
  previews inline for teachers (V3.769); here the question is "does this page
  look right", which wants the whole viewport and the browser's own reload.
- **`[hidden]` needs an explicit CSS guard.** `.tcadm-cat-details` is
  `display:flex`, which beats the `hidden` attribute — `.tcadm-cat-details[hidden]
  { display:none }` is load-bearing, not tidiness.
- **Counts are recomputed from `catalog`, never incremented.** One source of
  truth for the header and the summary, so a failed save can't leave a count
  that disagrees with the ticks.
- **The `&amp;` fix belongs in the manifest, not the renderers.** Reading the
  new rows revealed 13 titles rendering as *Gradients &amp;amp; Encounters*:
  `scan_modules.py` stored the `<title>` tag's raw HTML and every consumer
  escaped it a second time. Decoding at each render site would be
  whack-a-mole across the catalog, the teacher picker and the student class
  page — the data should hold text. Regenerating changed those 13 titles and
  nothing else, which also proves the scan is idempotent against the current
  tree.

## Verification

Self-driving headless harness (scratchpad `qa-catalog.html` + `qa-serve.py`,
Chrome `--headless=new --dump-dom`): the real `admin-teachers.html` markup and
styles plus the real `admin-teachers.js`, with `firebridge`/`firebase` stubbed
in front of it and `/modules/` served from the repo. **40 assertions, all
passing:**

- 12 folders / 69 rows rendered; every row has an Open link, `target="_blank"`
  + `noopener`, shaped `/modules/<folder>/<file>.html`; **all 69 links fetched
  200** against the real tree.
- A seeded published module renders ticked, tinted, with its tag line; folder
  header reads *1 of 4 available*; summary *1 of 69*.
- Ticking writes `teacherCatalog/{folder--basename}` with `published:true`,
  repaints without rebuilding (row identity survives), moves the summary to
  *2 of 69*, and names the module on the status line.
- A forced save failure reverts the tick and reports it.
- Filters: 2 / 67 / 69 rows. Search: narrows to matching rows only, drops empty
  folders, keeps its value across re-render, explains an empty result, restores
  on clear.
- Collapse all / expand all / single-folder toggle, including that collapsed
  rows are actually not visible.
- Details open on ✎ (computed `display:flex`), subjects save as an array, close
  again.
- Folder Select all → 6 writes for a 6-module folder, all rows on, header *6 of
  6 available*, summary *8 of 69*; Clear all reverses it.
- No `prompt`/`alert`/`confirm` fired, no console errors, no unhandled
  rejections.

## Deploy

**FTP only.** No rules, indexes or functions — `teacherCatalog` read/write
rules are unchanged from V3.669. `sw.js` → 742 (RM is network-first in the
service worker, so the bump is ritual, not the delivery mechanism).

## Out of scope

Editing module HTML; the `order` field (`publishedCatalog()` sorts by title
when it is absent, which it always is); per-teacher or per-class catalog
subsets; the three legacy `alert()` calls in this file's **approve-class modal**
path (pre-existing project-rule violations, untouched here — they are not on
the catalog tab).
