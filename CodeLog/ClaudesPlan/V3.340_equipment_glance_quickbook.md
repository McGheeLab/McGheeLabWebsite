# V3.340 — Equipment Scheduler: availability at a glance + quick-book

**Phase 2b of the FuturePlan 08 equipment-scheduler upgrade**
(`CodeLog/Feature requests/FuturePlan_08_equipment_scheduler.md`).
Companion to V3.339 (mobile single-day calendar).

## Goal

A student deciding which instrument to use shouldn't have to open the
calendar: the Equipment tab should answer "is it free right now, and
until when?" per device. Once booking, common durations should be one
tap, and repeating a past session should not require re-entering
everything.

## Approach (`rm/js/equipment.js`)

### Glance chips on equipment cards

- New `_todayCache` + `ensureTodayBookings()` — one-shot fetch of
  today's confirmed bookings across ALL devices (`date` in
  [today−30d, today], client-filtered `endDate >= today`,
  `status === 'confirmed'`). Needed because `_bookings` (the calendar
  subscription) only covers the currently viewed range, so the old
  "today count" went stale when the user browsed other weeks — this
  fixes that too. Cache is invalidated in the `EDB`
  create/update/cancel wrappers so a booking made in this session
  refreshes the chips.
- New `computeDayGlance(equip, todaysBookings, now)` returns
  `{label, cls}`: `Closed today` / `Opens at 8 AM` / `Closed for today`
  (from the V3.336 availability window), `In use until 1 PM` (walks
  chained back-to-back bookings to the true free point),
  `Booked until close` / `Booked all day`, `Free until 2 PM`,
  `Free until close (6 PM)` / `Free rest of day`.
- `renderEquipmentTab` renders the chip first in the card meta row
  (`.eq-ecard-glance--free|busy|off`); until the one-shot fetch lands it
  falls back to `_bookings` for the today-count and omits chips, then
  re-renders.

### Duration quick-picks in the booking modal

- `.eq-dur-chips` row under the end date/time: 30 min / 1 hr / 2 hr /
  4 hr / Max (device's `maxDurationMin`). A tap sets end date + end time
  from the start (rolls the end date across midnight, snaps to the
  select's 30-min grid) and re-runs the V3.336 availability line +
  conflict check.

### Rebook in My Bookings

- Past/cancelled rows for devices still in the catalog get a `Rebook`
  button → opens the booking modal prefilled with that device and the
  same start/end times on today's date. `openBookingModal`'s prefill
  now accepts `equipId`.

## Verification

- `node --check` on equipment.js.
- 12-case unit suite over `computeDayGlance` (extracted helpers run in
  Node with stubs): free/busy/chained/closed/opens-at/after-close/
  booked-to-close/multi-day/maintenance-null/other-device-ignored —
  all pass, plus the V3.336 availability suite re-run green.
- Local server: Equipment tab shows chips; book something now and the
  chip flips on return to the tab; duration chips set the end fields and
  trigger the availability/conflict lines; Rebook on a past row opens
  the prefilled modal.

## Notes / accepted limits

- Glance is computed at render time; it doesn't live-tick as minutes
  pass (re-entering the tab recomputes). Real-time chips would need a
  today-scoped `onSnapshot` — deferred until it proves needed.
- The one-shot query reuses the `equipmentId+date`-free pattern (no new
  composite index: single range filter on `date` only).
