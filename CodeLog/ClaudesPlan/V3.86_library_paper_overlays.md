# V3.86 — library-paper: citations panel + bucket overlays + .md import + search

## Goal

Turn the RM paper reader at [rm/pages/library-paper.html](../../rm/pages/library-paper.html) from a metadata + PDF + annotations triptych into a *literature-review workbench*. Wishlist source: [rm/wishlist.md](../../rm/wishlist.md) lines 3–11.

Four capabilities, one version:

1. **Citations on this page** — left sidebar lists inline citations on the visible page; hover-to-flash works in both directions; expand for full reference; "Add to library" stubs the cited paper into `items.json` via DOI lookup.
2. **Project-bucket overlays** — annotations carry an optional `bucket_ids[]`; a popover in the right toolbar toggles which overlays render; multiple overlays stack with per-bucket left-edge stripes; new highlights are stamped with the active set.
3. **`.paper-overlay.md` drag-drop import** — Claude (running in a sibling VSCode lit-review repo) authors a markdown file that maps cleanly to per-paper highlights for one bucket. The user drops the file onto the open paper; an in-browser parser validates each quote against the PDF text layer, shows a per-highlight match preview, and writes the matched ones to Firestore.
4. **In-paper search** — keyword search across the paper's text layer; hits inside existing highlights rank first.

Project buckets ([rm/js/links.js](../../rm/js/links.js)) are already a stable concept with bidirectional paper↔bucket linking — overlays use them as the scope key, no new entity.

## Approach (high level)

Each phase is a discrete module that the existing reader composes with — no rewrite of `library-paper.js`'s core flow.

| Phase | New module | Wire-in points |
|---|---|---|
| 1 | `rm/js/paper-citations.js` | `_onPageChange`, `onPageReady`, `<div id="lp-citations">` slot |
| 2 | `rm/js/paper-overlays.js` | `_applyFilter`, `onCreate`, `<div id="lp-overlays-anchor">` slot, annotation-overlay stripe, annotation-panel info-panel chips |
| 3 | `rm/js/paper-overlay-import.js` + `.claude/skills/paper-overlay/SKILL.md` | dragenter/drop on `#lp-viewer`, banner, modal, `ANNOTATION_SYNC.create` |
| 4 | `rm/js/paper-search.js` | `<div id="lp-search-anchor">` slot, `_flashRectOnPage` helper, jump → `_viewer.gotoPage` |

The existing pieces it leans on:

- `_viewer.getTextItems(pageNum)` from [rm/js/pdf-viewer.js](../../rm/js/pdf-viewer.js) gives per-glyph items in reading order — same data path used by geom-selection. Phases 1, 3, 4 all consume it.
- `_viewer.ready()` resolves when every page has rendered — phase 1 awaits it before parsing references.
- `window.LINKS` ([rm/js/links.js](../../rm/js/links.js)) — `linkedBucketsForItem(item, bucketsDoc)` and `addLink(itemId, bucketId)` are exactly what phase 2 + 3 need.
- `window.ANNOTATION_SYNC.create(paperId, payload)` — phase 3 calls it once per matched highlight.
- `window.LIBRARY_METADATA.lookup({doi})` and `buildPaperItem(meta, null, user)` — phase 1's "Add to library" reuses the same DOI lookup the upload modal already uses.

## Key decisions

- **Project buckets, not free-form tags, are the overlay key.** Tags are colon-prefix strings; buckets are stable IDs already wired into the dashboard, evidence ledger, and Send-to-teammate flow. One less type to invent.
- **Active-overlays state is localStorage, not Firestore.** Per-paper toggle state is ephemeral UI preference; loading a `paperPrefs` Firestore subcollection on every paper open isn't worth it. (The plan-mode sketch had this as a Firestore route; we simplified.)
- **Drag-drop, not a file picker.** Drag-drop is the natural gesture from VSCode; the banner UI hides until a file is over the viewer.
- **Quote-match is loose-whitespace, case-insensitive — but everything else is strict.** Paper-id mismatch hard-fails; missing quote hard-fails. The user picks per-highlight whether to include unmatched ones.
- **References parser runs once per paper open, cached on `_item.meta.library.references` if present.** Pages render sequentially; we kick off the parse on `_viewer.ready()` and re-render the citations panel once it lands.
- **Idempotent imports.** Re-dropping the same `.md` doesn't duplicate annotations: the importer checks for an existing annotation with the same `(quote, page, bucket)` triple and skips.
