# V3.995 — Settings as features, each with its live preview

## Goal
Gabe (14 Nov 2026): "Rewire the settings to be a feature on/off to declutter a notebook for people that want a more simplistic look and feel to the notebook. The tunability of some features should be extended for more personalization. Give some suggestions on how to wire the settings and make it a page that is more organized and modern with an ease to browse through." From the proposals (a published page, three layouts) he chose **C** — a sidebar and a feature board — and asked for each feature's settings to go as far as the feature does (the bridge bar down to 0 most-used bridges; the editing bar's size, fixed or following the zoom, not its position), for an opened tile to show its whole text, for "a live preview for every different feature, and it follows the user as you scroll down the settings", and that "any new feature added should be fully wired in the settings tab with a live preview".

## Approach
- **One register, every feature declares itself (`02b-feat.js` FEAT, `20a-features.js`).** The page is drawn from it; the code asks `FEAT.on(id)`; `body.f-off-<id>` lets CSS hide what it can. Switches live in the notebook (only what differs from the preset), settings in `settings().tune` (only what differs from the default); settings that existed keep their key (`get`/`set`), so nothing is migrated. A device can keep its own switches.
- **Off hides tools and decorations, never content.** Each guard is wrapped round the feature's own function in `20a-features.js` (not spread through the modules — fewer places to read, fewer conflicts in Gabe's standalone sync), or is CSS. Where hiding would lose content it doesn't: folded regions stay (they hide their members), a running timer stays, an empty synthesis box goes but a written one stays, the + Insert rows keep their place in `INSERTS` (a getter on `when`) so the code that finds them still does.
- **Previews are small scenes in the app's own look (`PV`)**, reusing the app's classes where they are safe outside a note (structure colours, terms, the bridge band, chips, Portfolio dots), and reading the feature's settings live (a slider's value through `FEAT.live` before it is saved).
- **The preview follows the scroll:** a sticky pane beside the board; on scroll, the top-most tile in view becomes the preview (or the one open). On a narrow screen the pane gives way to a preview inside the opened tile.
- **Phase 1 of the settings in the proposal:** the switches, the settings that existed, the two Gabe named. The others (183 in the proposal) need code in each feature and come group by group.
- **Not registered yet:** the iteration deck (spreading its versions out rewrites saved positions), highlighting a page or PDF (its selection menu can't be put back once replaced), the day note (capture has six ways in) — each needs its own change first.
- **The rule kept:** the /scientia-push skill's ritual has the step, the repo's `scientia/CLAUDE.md` has the rule (so the lab's session follows it too), and `FEAT.audit()` is checked by the version's test.
