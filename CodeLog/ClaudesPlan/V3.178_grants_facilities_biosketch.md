# V3.178 — Grants Workflow Phase 1: Facilities + Biosketch

## Goal

First slice of the Grant Writing workflow for RM. Mirrors the Paper Writer
architecture (paper-builder.html + paper-* JS stack) but for proposal
artifacts. This phase ships the **cheapest two artifacts** — both surface
existing data already in the lab's Firestore:

1. **Facilities & Other Resources doc** — auto-generated boilerplate
   ("Facilities and Other Resources" + "Equipment") pulling from
   `inventory`, `equipment`, and `people` collections, editable by lab
   members, attachable to a future grant draft.
2. **Biosketch generator** — NIH 5-page and NSF biosketch templates
   populated from `cvData/{uid}` (the same doc the public-site CV builder
   and `rm/js/cv-schemas.js` already share). Per-proposal variants store
   the user's tailored Personal Statement + Contributions narrative; the
   rest (Positions, Honors, Publications) is pulled live from `cvData`.

This phase has **no Yjs**, **no scraper**, **no Cloud Functions**. Pure
client-side render over existing Firestore data + two small new
collections for editable overlay state. Subsequent phases (V3.179–V3.182)
add the grant portal, Yjs grant writer, budget editor, and AI matcher
respectively. See [just-like-we-have-jiggly-cupcake.md](../../../../.claude/plans/just-like-we-have-jiggly-cupcake.md)
for the full 5-version roadmap.

## User-locked decisions (2026-05-11)

- **Drafts data model:** separate `grantDrafts` collection (NOT
  `funding/{id}` reuse). Drafts get their own Yjs subcollections in
  V3.180; this phase reserves the collection name but does not write to it.
- **Pivot-RP integration:** per-saved-search RSS ingestion + deep-link
  buttons. Pivot does not enter the picture in V3.178.
- **Phasing:** V3.178 → V3.182 incrementally.
- **PDF export (biosketch):** client-side `window.print()` against a
  styled print stylesheet + DOCX via a vendored `docx.js` lib. NIH
  form-fill is deferred to V3.183+.
- **AI calls:** out of scope for V3.178 (lands in V3.182).

## Firestore schema

```
biosketches/{uid}
  defaultVariantId
  /variants/{variantId}
    label                      // user-supplied, e.g. "NSF CAREER 2026"
    mechanism: 'NIH-5pg'|'NSF'|'DOD'
    personalStatement          // 4000-char user-edited textarea
    contributions: [{ title, narrative, citations: [pubId] }]  // ≤5 for NIH
    positions: [{ start, end, title, org }]    // optional override of cvData
    productsOverride: [pubId]  // optional curated list (defaults to top-15 by year)
    synergisticActivities: [string]   // NSF only, ≤5
    generatedAt, sourceCvSnapshotHash
    grantDraftIds: [grantId]   // backrefs (for V3.180+)

facilitiesDocs/{docId}
  label, scope: 'all'|'lab-only'|'mri-only'
  sections: {
    facilities,     // HTML string, editable
    equipment,      // HTML string, auto-generated from inventory+equipment, editable
    computing,      // HTML string, editable
    office,         // HTML string, editable
    otherResources  // HTML string, editable
  }
  generatedAt, sourceHashes: {inventory, equipment, people}
  attachedTo: [grantId]
  createdBy, createdAt, updatedAt
```

## Firestore rules

Inserted before the closing brace of `match /databases/{database}/documents`
(around line 931 of [firestore.rules](../../firestore.rules)):

```
match /biosketches/{userId} {
  allow read:  if isLabMember();
  allow write: if request.auth.uid == userId || isAdmin();
  match /variants/{variantId} {
    allow read:  if isLabMember();
    allow create, update: if request.auth.uid == userId;
    allow delete: if request.auth.uid == userId || isAdmin();
  }
}

match /facilitiesDocs/{docId} {
  allow read:   if isLabMember();
  allow create: if isLabMember()
                && request.resource.data.createdBy == request.auth.uid;
  allow update: if isLabMember();
  allow delete: if isAdmin() || resource.data.createdBy == request.auth.uid;
```

## Biosketch renderer (grant-biosketch.js)

Public API (all attached to `window.GRANT_BIOSKETCH`):

```javascript
GRANT_BIOSKETCH.loadCvSnapshot(uid)   // → resolved cvData doc
GRANT_BIOSKETCH.listVariants(uid)     // → [{id, label, mechanism, generatedAt}]
GRANT_BIOSKETCH.loadVariant(uid, variantId)
GRANT_BIOSKETCH.saveVariant(uid, variantId, patch)
GRANT_BIOSKETCH.createVariant(uid, {label, mechanism})  // → variantId
GRANT_BIOSKETCH.deleteVariant(uid, variantId)
GRANT_BIOSKETCH.renderNIH5pg(cv, variant)  // → HTMLElement
GRANT_BIOSKETCH.renderNSF(cv, variant)
GRANT_BIOSKETCH.renderDOD(cv, variant)
GRANT_BIOSKETCH.cvSnapshotHash(cv)    // → string for stale-warning
```

### NIH 5-page sections (in order)

1. **A. Personal Statement** — user-edited textarea + auto-included list
   of 4 most relevant pubs (mechanism docs let user override via
   `productsOverride`).
2. **B. Positions, Scientific Appointments, and Honors** — from
   `cv.profile` + `cv.service` (Type ∈ {Department, University,
   Professional Society}) + `cv.awards`. User can override with
   `variant.positions`.
3. **C. Contributions to Science** — up to 5 entries, each with a
   narrative (≤2000 chars) and citation list. Free-form.
4. **D. Scholastic Performance** — only for fellowship/training (F/K)
   biosketches. Optional in V3.178 (toggle in the variant editor).

### NSF biosketch sections (NSF PAPPG sections)

1. **Identifying Information** — name, ORCID from `cv.profile`.
2. **A. Professional Preparation** — from `cv.courses` filtered to
   degrees, plus profile institution.
3. **B. Appointments and Positions** — from `variant.positions` (override)
   or derived from profile + service.
4. **C. Products** — 5 closely related + 5 other significant, pulled from
   `cv.journals` + `cv.conferences` (or `variant.productsOverride`),
   sorted by year desc.
5. **D. Synergistic Activities** — up to 5 free-form entries from
   `variant.synergisticActivities`.

### DOD biosketch

Minimal V1 — same data, DOD-formatted header. Detailed DOD-specific
fields deferred to V3.183+ (DOD CDMRP template ships then).

## Facilities renderer (grant-facilities.js)

Public API (`window.GRANT_FACILITIES`):

```javascript
GRANT_FACILITIES.loadAll()  // → [{id, label, scope, generatedAt}]
GRANT_FACILITIES.load(docId)
GRANT_FACILITIES.create({label, scope})  // → docId
GRANT_FACILITIES.regenerate(docId)
  // Re-runs the aggregator. Computes hashes of (inventory, equipment,
  // people); if any source has changed since last gen, regenerates that
  // section's HTML. User-edited sections are preserved by hash-equality
  // check on the previous auto-generated HTML.
GRANT_FACILITIES.save(docId, patch)
```

### Aggregation logic

- **Equipment section (auto):**
  - Pull `inventory` items where `category === 'equipment'` OR
    `unit_price >= 5000`. Group by `subcategory`. Render as a structured
    paragraph: instrument name, vendor, location, brief specs.
  - Pull `equipment` collection (bookable shared instruments) and append
    those with descriptions + locations.
- **Facilities section (boilerplate + edit):**
  - Renders a default paragraph: "The McGhee Lab is located in BSRL at
    the University of Arizona…" with personnel counts derived from
    `people` (count by category: postdocs, grads, undergrads).
- **Computing, Office, Other Resources:** boilerplate seeded text the
  user edits.

### Print/Export

- "Print → PDF" button uses `window.print()` against
  [rm/css/grant-doc.css](../../rm/css/grant-doc.css) which has an `@media
  print` block sizing to 8.5×11 with NIH-compliant margins (0.5" all
  sides, 11pt Arial body).
- DOCX export via JSZip + minimal OOXML template (in
  `grant-biosketch-export.js`). Both biosketch and facilities use the
  same exporter — it accepts a section tree.
