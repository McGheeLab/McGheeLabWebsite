# V3.981 — Scientia: node bridges

**Date:** 2026-11-11 · **Branch:** `scientia/node-bridges` · **Gabe:** "The link to a note should be merged with pulled in components
or excerpts (what I mean is that a pulled in component, in the original note automatically has the little up arrow). These should
become known as node bridges. When you copy and paste components or excerpts from one note to another, it now is labelled as a bridge
component kind that asks you to state the purpose of why you bridged this component in a little caption underneath the component.
Inside of the Ctrl+Enter space, add the bridge to note button, and for other components such as image panels, HTMLs, etc... a
right-click option with bridge to another note should appear. Bridge should be a / command with the first component from the original
note and the second note as the recipient. Remove all areas that had the previous systems. Also, instead of leaving just an arrow in the
original note, make the text that is bridged have a green underline (changeable in settings) and the other components need to have a
label mentioning that they are bridged (next to the component kind), and double clicking on it allows you to either travel to the
recipient note or open it side-by-side with the original note."

## Reading of the request

- "The little up arrow" is the ↗ a link mark draws after linked words (`10-base.css` `.ed .ln.end::after`). Merging: a bridge is both
  the pulled-in copy in the other note *and* the link from the original's words to it — so the original marks what was bridged
  automatically, with no link to make.
- A bridge is the existing pulled-in component (`kind: 'ref'`, `refBlockId`) or excerpt (`refSpan`, V3.972) — same records, so old
  pulled-in components and excerpts are bridges at once, the V3.980 kept-box logic and the live widgets (13zx) work unchanged. A
  pulled-in *structure* (`refItemId`: a barrier resolved elsewhere, the Synthesis's gathered claims) is a different thing and stays.
- "Remove all areas that had the previous systems": every way to make a link (Ctrl+Enter L, the editing bar, right-click, /link, Link
  all), to embed (Embed in another note, a region's Embed) or to pull a component in (Pull into…, the pull dialog's Component tab, the
  ↗, the "⇲ in N other notes" chip) is now a bridge or gone. **Links made before are kept** (they are the person's data): they still
  open, underlined like bridged words, and take the same double-click. The Synthesis's own buttons (Gather, The rest → Pull in) are
  its workflow and keep their words; what they make shows as bridges.
- "Asks you to state the purpose": a bridge made by choosing a note (the strip, right-click, /bridge, the selection bar) asks why
  before it is made (Cancel bridges nothing; an empty answer is allowed). A pasted or dragged one lands with an empty caption that
  pulses — the caret is not moved into it, so a second Ctrl+V still pastes on the canvas, not into the caption.

## Approach

New module `13zzu-bridge.js` (`BRIDGE`), one place for making, drawing and opening bridges; the old entry points call it.

- **The original's underline:** `ED.render` takes extra marks (`BRIDGE.marks(b)`) when the element is the component's own editor
  (`data-own` = its id, set by `DocView.box`) — not when the same component is drawn inside a bridge card elsewhere. They render as
  `span.br` with no `data-m`, so `ED.read` (which keeps only marks named by `data-m`) never stores them. Positions come from
  `EXCERPT.locate`, so words added before a passage keep it underlined.
- **The tag:** `DocView.box` wrapped (after 13zzi's kind label): a component that isn't text gets "⇄ bridged" after `.num`.
- **Double-click:** a capture listener on `.ed .br`, `.br-tag`, `.ed .ln`; the second mousedown of a double-click is cancelled there so
  no word is selected. The menu lists each recipient with *Go to the note* (`App.openBlock`, which reveals the bridge) and *Open it
  beside this note* (`App.openSide`).
- **The caption:** a textarea at the bottom of the box (inside it, so "boxes never overlap" measures it), saved on change / Enter / blur
  with `changed()`; its text is a child node, so V3.980's `shape` sees a changed reason and redraws a kept box.
- **Colour:** `settings().bridgeColor` → `--bridge` in `applyKindCSS` (dark mode mixes it 70 % with white, as the kinds do).
