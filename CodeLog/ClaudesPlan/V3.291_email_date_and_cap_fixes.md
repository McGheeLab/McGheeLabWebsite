# V3.291 — Email date + display-cap fixes

Three reported bugs on the email tab. Diagnosed to one shared root cause
(date format) plus a fetch cap.

## Symptoms
1. "Monthly email volume by category — 2026" chart wrong/empty; "Top
   activities by volume" empty.
2. "Scraped 1000 emails, but only 150 showed up in unknown."
3. Email list not sorted correctly by date and time.

## Root cause
- **Dates:** the Gmail scraper (`scrape-now.js` / `gmail-scraper.js`) writes
  `date: headers.date` — a raw RFC-2822 string like
  `"Wed, 25 Jun 2026 14:30:00 -0700"`. The renderer assumes ISO:
  - timeline buckets by `date.slice(0,7)` (`YYYY-MM`) / `date.slice(0,4)` →
    got `"Wed, 25"` / `"Wed,"` → no bucket matched → empty 2026 chart.
  - date column shows `date.slice(0,10)` → `"Wed, 25 Ju"`.
  - sort used `localeCompare` on the raw string → non-chronological.
  `internalDate` (epoch ms) was already stored and reliable but unused for
  these paths.
- **Cap:** `_fetchEmailMessagesForYear` does `.limit(EMAIL_PAGE_LIMIT)` with
  `EMAIL_PAGE_LIMIT = 250`. A backfill writes ~1000+; only the newest 250
  loaded; the rules pre-filter sorted most into other categories, leaving
  ~150 under `unknown`.
- **Top activities:** scraped mail has no `activity_type`, so every row fell
  into `(unspecified)`, which the rollup filters out → empty panel.

## Fixes (all in `rm/js/email-review.js`)
1. `_coerceLegacyEmailShape` — normalize `date` to ISO from `internalDate`
   (fallback: `Date.parse(headers.date)`; last resort keep raw). One place;
   the Firestore-paged production path always coerces, so timeline + column +
   sort all get ISO. Legacy ISO archive rows (no internalDate) pass through
   unchanged.
2. `filterEmails` — date sort uses numeric `emailTime(e)` (`internalDate` ms,
   else `Date.parse(date)`), so order is correct to the minute.
3. `EMAIL_PAGE_LIMIT` 250 → 2000 (matches `scrape-now.js` backfill cap);
   `renderEmails` display cap 500 → 1000 with an accurate "showing first N of
   M" note.
4. `renderActivityRollup` — bucket key falls back to category when
   `activity_type` is absent, so the panel populates for un-sub-categorized
   mail and refines once activity types are assigned.

## Why no extra cache-bust
The IndexedDB per-year cache stores raw docs and re-coerces on every load, so
the date fix applies to cached data immediately. The always-fresh scrape
(`onScrapeEmailsNow` → `_clearEmailMessageCaches` + `_reloadEmailAfterScrape`)
fires on page load and rebuilds the cache at the new 2000 cap, so the raised
limit takes effect on the next load.

## Deploy
Client-only: FTP `rm/` + `sw.js` (CACHE_VERSION 263 → 264) to godaddy +
hard-reload. No function redeploy for V3.291.

## Manual test
- Open email tab on 2026 → Monthly chart shows bars in the right months;
  Top activities lists categories with counts.
- Date column reads `2026-06-25`; Newest/Oldest sort orders correctly incl.
  same-day time.
- Scrape (or reload) → the `unknown` chip count and visible list reflect the
  full set (up to 1000 rendered, with the "showing first 1000 of N" note past
  that).
