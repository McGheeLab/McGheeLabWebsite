# V3.121 — Protocols Builder Phase 3: inventory linking

## Goal

Phase 3 of the Protocols Builder roadmap. Wire the lab-shared `inventory`
collection into protocol materials rows + step prose so the student
authoring or running a protocol can see real reagent / equipment links
with live stock status. The schema already reserved `attrs.rows[i].item_ref`
in V3.113 — Phase 3 just lights it up.

## Approach

### New file

- `rm/js/protocol-inventory.js` (~250 lines) — clone-and-modify of
  the lab-notebook V3.114 pattern. Public surface:
  - `PROTOCOL_INVENTORY.ensureList()` → Promise<[entry]> (cached after
    first call; merges items + chemicals from
    `inventory/items.json` + `inventory/chemicals.json`).
  - `PROTOCOL_INVENTORY.findById(id)` → entry | null.
  - `PROTOCOL_INVENTORY.openPicker({ onPick, anchorEl })` — opens a
    floating popover with search + keyboard nav. `onPick(entry)` fires
    on selection.
  - `PROTOCOL_INVENTORY.formatLabel(entry)` → "Agarose (Sigma, cat. A9539)".
  - `PROTOCOL_INVENTORY.formatStockChip(entry)` → "in stock" / "low" /
    "out" / "" (drives the colored chip).
  - `PROTOCOL_INVENTORY.renderTextWithTokens(text, getById)` — substitutes
    `[!inv:<id>]` in body text with a chip span. Mirrors V3.117's
    `[!var:<name>]` token grammar.

  Tech debt: a follow-on cleanup can extract a shared
  `rm/js/inventory-picker.js` consumed by paper-editor + lab-notebook +
  protocol-editor. Three live callers is the right time to dedupe.

### Materials row behavior

Each materials row currently has `{qty, unit, free_text, item_ref}`.
Phase 3 adds a `🧪` cell button next to the free_text input. Clicking
it opens the picker. On selection:
- `item_ref` is set to the inventory id.
- `free_text` is auto-filled with the item's name + vendor/cat parens
  (so de-linking later still leaves human-readable text).
- The cell renders a **chip** with the item's name + a stock chip;
  clicking the chip's × clears `item_ref` (free_text stays — back to
  free-text mode).

### Step body inline tokens

In step / note / safety / figure-caption bodies, students can type
`[!inv:<id>]` — same grammar as `[!var:…]`. The dual-mode binding
(`bindYTextWithVars`) substitutes the token with a chip on blur and
shows the raw token on focus. Hover tooltip shows vendor / catalog #.

A typical use:

```
Aliquot 1 mL of [!inv:lab-3] into each well.
                     ^^^^^^^^^
                     resolves to
                     [Agarose (Sigma, cat. A9539, in stock)]
```

The author-time UX is: pick the item once via the picker (it inserts
the token at caret), then carry on typing.

### Reuse callouts

- The `[!inv:<id>]` token implementation pattern mirrors V3.117's
  `[!var:<name>]` — same TOKEN_RE shape, same `renderTextWithTokens`
  signature, same dual-mode behavior on focus/blur.
- The popover styling matches the existing `.ln-inv-popover` class set
  used by lab-notebook V3.114 (different class names — `.proto-inv-pop` —
  but similar layout).
- `inventory/items.json` + `inventory/chemicals.json` routes are already
  registered in `rm/js/api-routes.js` since V3.108. No new routes.
- No new Firestore rule, no new index, no new Storage block. The
  inventory collection's existing rules cover read access.

## Acceptance test

1. Open the Agarose LLS protocol. Materials block shows existing rows.
2. Click `🧪` on row 1. Picker opens. Search "agarose". Pick
   "Agarose (Sigma)". Row 1 now displays a chip "Agarose (Sigma, cat. …)
   ✓ in stock". Reload — chip persists.
3. Click chip's × → reverts to free-text "Agarose (Sigma, cat. …)" with
   `item_ref` cleared.
4. In a step body, type `Add 0.1 g of [!inv:` then pick from the picker.
   On blur, the token renders as the inventory chip.
5. Open the protocol in a second tab — inventory chips render the same
   way; live edits to a different row in tab A don't churn rendered
   chips in tab B.
6. Sign in as a non-owner — picker still opens (any lab member can
   see inventory) but the chip cells are read-only.
