# V3.588 — Equipment booking criticality (Soft / On time / Hard)

First release of the **smart equipment schedule-change notification**
program (V3.588–V3.592, implements FuturePlan 08 Phase 3). This one is
client-only groundwork: give every booking a meaningful criticality so
the adjacency notification engine in V3.589 has something to weight on.

## Goal

A student booking the confocal should be able to say *how critical* the
booking is, and the person booked right before them should be able to
see it. Three levels:

| Stored `priority` | Equipment page | My Day composer | Meaning |
|---|---|---|---|
| `normal` | Soft | "Soft book" | Flexible — running late has no downstream effect |
| `high` | Firm | "Needed on time" | Must start on time; duration flexible; high importance |
| `urgent` | Hard | "Hard book" | Zero flexibility — mission critical |
| `maintenance` | Maintenance | *(not offered)* | Admin-only device block |

## Problem

Two problems, one of them a real bug.

1. **`priority` was cosmetic and unlabeled.** Every booking already
   carried a rules-validated `priority` enum
   (`firestore.rules:745-750`), but it only drove the block border color
   and a raw-enum badge that read "normal" / "urgent". Nothing told a
   student what picking it would *do*, and nothing downstream consumed
   it.
2. **My Day bookings were silently flattened to Soft.** The equipment
   adapter in `day-distribute.js` hardcoded `priority: 'normal'` on
   create and **omitted `priority` from the update patch entirely** — so
   a criticality set anywhere could never survive an edit. Both fixed
   here.

## Approach

**Reuse the enum, relabel the UI.** The stored values stay
`normal|high|urgent|maintenance`, so existing bookings keep rendering,
`firestore.rules` needs no edit, and the admin-only `maintenance` carve-
out is untouched. Only the student-facing strings change.

Three copies of the label table exist by design (the repo already
accepts this pattern — see `equipment-availability.js`'s V3.527 header):

- `rm/js/equipment.js` — closure-local (`equipment.html` does not load
  the availability helper).
- `rm/js/equipment-availability.js` — exported on `window.EQUIP_AVAIL`
  for My Day and future consumers.
- `functions/helpers/equipment-adjacency.js` — server copy, arrives in
  V3.589.

Keep all three in sync. Each carries a comment saying so.

**Quiet by default.** The My Day card shows a criticality chip *only*
for `high`/`urgent`; a Soft day stays visually clean. This is the same
principle the V3.589 notification engine runs on — Soft bookings neither
exert handoff pressure nor receive nudges.

## Files modified

- **`rm/js/equipment.js`** — `PRIORITY_LABELS`/`PRIORITY_HINTS` +
  `priorityLabel()`/`priorityHint()` next to `getPriorityColors()`.
  Booking modal: label → "How critical is this booking?", options
  relabeled, new `#eq-bk-priority-hint` line that `updatePriorityDot()`
  refreshes on change. Detail row → "Criticality: **Hard** — Zero
  flexibility…". Calendar legend shows labels + hint tooltips. Admin
  settings panel → "Criticality Colors" with `Soft (normal)`-style
  labels. Both GCal descriptions now write `Criticality: Hard`.
- **`rm/js/equipment-availability.js`** — same label table exported as
  `EQUIP_AVAIL.priorityLabel` / `.priorityHint` / `.PRIORITY_LABELS`.
- **`rm/js/my-day.js`** — `priority: 'normal'` in `freshComposer()`;
  new `renderCriticalityField()` + `criticalityHint()` appended to
  `renderEquipmentField()` (so it only renders when the equipment
  ingredient is on); `onChange` special-cases `priority` to patch the
  hint text in place rather than re-render (a full render would close
  the select and drop the availability strip); `submitComposer()` writes
  `details.priority`; `i-edit` repopulates it; card combo line shows an
  "On time" / "Hard" chip for non-Soft bookings only.
- **`rm/js/day-distribute.js`** — new `normalizePriority()` helper
  (clamps to the three student-writable values; `maintenance` is
  admin-only and would get the whole write rejected). Equipment adapter
  `create()` uses `normalizePriority(det.priority)` instead of the
  hardcoded `'normal'`; `update()` patch now includes `priority`.
- **`rm/css/equipment.css`** — `.eq-priority-hint`, `.eq-detail-hint`,
  `.eq-label-sub`.
- **`rm/css/my-day.css`** — `.md-crit*` block (label, select, hint, and
  the `--high`/`--urgent` chips).

## Data model changes

**None.** No new collection, no new field, no rules change, no index.
`equipmentBookings.priority` already existed and was already validated.
The only behavioral change is that My Day now writes a value other than
`'normal'` to it.

## Out of scope

- Anything that *acts* on criticality — adjacency notifications land in
  V3.589. Criticality still does not affect displacement, approval
  routing, or conflict resolution.
- Retro-labeling existing bookings: they all read `normal` → Soft, which
  is the correct default.

## Release ritual

FTP-only. No `firebase deploy` of any kind. `sw.js` CACHE_VERSION
561 → 562.

## Rollback

`git revert` the six files + re-FTP + bump `sw.js` again. Data written
under the new build is indistinguishable from data written under the old
one (same enum, same field), so there is nothing to clean up.

## Verification

1. Equipment → Calendar → drag a slot → the modal reads "How critical is
   this booking?" with Soft / Firm / Hard and a hint that changes as you
   switch. Legend reads Soft/Firm/Hard/Maintenance.
2. Book as Hard → click the block → detail row reads
   "Criticality: **Hard** — Zero flexibility — mission critical".
3. Admin tab → panel reads "Criticality Colors", rows labeled
   `Soft (normal)` … `Maintenance (maintenance)`; saving colors still
   works.
4. My Day → composer → add the 🔬 Equipment ingredient → criticality
   select appears under the date/time row with a live hint. Add with
   "Needed on time" → check `equipmentBookings/{dayPlanId}` in Firestore
   has `priority: 'high'` (this is the bug fix — it used to be
   `'normal'`).
5. Edit that My Day item → the select shows "Needed on time" → change to
   "Hard book" → save → booking doc now reads `priority: 'urgent'`
   (previously an edit could never change it).
6. My Day card shows a "Hard" chip; a Soft booking shows **no** chip.
