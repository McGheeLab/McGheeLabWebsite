# V3.810 — Quick contexts: Chat (left) and Tasks (right) on every page

**Date:** 2026-10-19
**Alex** (after V3.809's one-bar redesign): *"i still want chat and tasks to be on the sides of the
page as quick contexts"*.

## What exists

`rm/js/shell-popouts.js` (V3.85, V3.89 persistence, V3.90 single pill) already gives the workflow
shell and the split shell a left and a right overlay — Chat and Tasks by default, any page via the
header picker, resizable, open/closed + page remembered in localStorage, iframes loaded with
`?embed=1` + `name="rm-shell-popout-<side>"` so nav.js draws no bar inside them. It was only ever
mounted by those two shell pages, anchored to their `#shell-root`.

## The change

nav.js mounts the same module on every ordinary page, in a new **page mode**:

| Shell mode (unchanged) | Page mode (new) |
|---|---|
| anchored to `#shell-root`, `position:absolute` | `position:fixed`, top 56px → bottom, z 90 (`body.rm-page-popouts`) |
| open by default | **closed by default** — a pill at each screen edge, mid-height |
| state in URL params + `mcgheelab.shellPopout.state` | localStorage only, own key `mcgheelab.pagePopout.state` (`urlState:false`) so page urls stay clean and a bookmark's `?leftOpen=1` can't pop a panel on an unrelated page |
| page list from `PAGE_REGISTRY` | falls back to nav.js's `_wfBuildPageMap()` (page-registry.js isn't loaded on ordinary pages); icons are the NAV_ITEMS Heroicons |
| — | `hideFor: <current page id>` — the side that would show the page you are on is hidden (Chat inside Chat) |

Mounted by `_navInitPagePopouts(wfState)` at the end of `_navBuildBar`, only when: not an embed
(renderNav already returned — and a popout's own iframe IS an embed, which is what stops recursion),
not the two shells / app-shell / library-mobile pages, not the phone app runtime (Capacitor, the
`?mobileShell=1` preview, inside app-shell), viewport wider than 1024px, signed in and a lab member.
`shell-popouts.js` + `workflow-shell.css` load on demand. The picker's "This workflow" group is the
bar's chips (the active workflow's pages, else the user's pins + recents).

## Files

`rm/js/shell-popouts.js` (page-mode options), `rm/js/nav.js` (`_navInitPagePopouts`,
`_navLoadPopouts`, `_navIsAppRuntime`), `rm/css/workflow-shell.css` (page-mode rules), `sw.js` 795 → 796.
No rules, no functions, phone app untouched.
