# V3.321 — Activity overhaul: consumers (FuturePlan 04, Release B3)

## Goal

Point every consumer of activity data at the event model. Hours
disappear from PMR, the dashboard, and the lab-wide stats table.

## Changes

- **PMR Activity block** ([rm/js/pmr.js](../../rm/js/pmr.js)):
  `renderActivityList` now opens with a **heatmap strip** — one shaded
  cell per period day (same 5-level green scale as the tracker page) —
  and the per-entry rows drop the hours column + pending badge. The
  week-grouping + "✓ discussed" archive flow is unchanged.
- **PMR Stats block**: aggregates **event counts** by top-level
  category (was: confirmed minutes). Sparkline = events/day. Schedule
  markers excluded. The "confirm hours to populate stats" dead-end is
  gone.
- **Dashboard card** ([rm/js/dashboard.js](../../rm/js/dashboard.js)):
  the lab-wide "Lab Activity (7d) Nh" card becomes **My Activity** —
  personal current streak (empty today tolerated) + this-week event
  count, linking to the tracker tab. One 60-day read of the signed-in
  user's own entries (no shareActivity fan-out on every dashboard load).
- **Lab stats table** ([rm/js/activity-summary.js](../../rm/js/activity-summary.js)):
  columns become Events / Active Days / Breakdown (counts); summary
  cards become Total Events / Active Members / Top Category. The
  `shareActivity` opt-in gate is unchanged (firestore.rules
  trackerEntries clause); the "not sharing" notice now points at the
  Settings page Profile tab (the tracker's own settings died in B2).
