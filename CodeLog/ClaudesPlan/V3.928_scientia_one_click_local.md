# V3.928 — Scientia on this computer: one button, always in step

## Goal

Gabe (27 Oct 2026): launching and syncing the local Scientia is hard (launch.bat, a separate bridge window, a key typed in
a terminal). One button on the lab site should open the notebook running on the person's computer in a new tab, syncing
the local notebook folder and the cloud on its own. The first click walks the person through setup; after that it is
permanent until they uninstall, survives restarts, and several devices on one account (computers, the website on a
tablet) see each other's changes within seconds. For every lab member; tested with Gabe first; the button in the website's
Scientia (Gabe's code); a plain download. The shared lab layer (`lab-mode.js`, `cloud-sync.js`, `scientia-cloud.py`) is
not edited.

## Approach

- **Always-on sync in the app's server** (`scientia/labsync.py`, a thread `serve.py` starts): runs the lab's own bridge
  (`scientia/vendor/scientia_cloud.py`, a byte-for-byte copy of `rm/scientia/scientia-cloud.py` that
  `scripts/scientia_build.py` refreshes, as V3.901 does for RM's detectors). Paced for seconds: a change here wakes it at
  once (it waits on the local hub's long-poll); the cloud is asked every 1.5 s while a window of the app is open here or
  something changed in the last 2 minutes, every 15 s otherwise, every 60 s after half an hour of quiet (the hub is a paid
  function and does not hold requests open). Offline: it backs off to a minute and catches up. Its known failure — "this
  computer's history no longer reaches the last sync" (any restart after unsynced local edits) — is answered by
  `realign()`, the three-way catch-up against `shadow.json` (the V3.927 merge script, made part of the app), so it never
  asks; "both sides hold different notebooks" (a new account) waits for the person's choice in the app.
- **Pairing** (hub, `functions/scientia-hub*.js`): `POST /api/cloud/pair/new` (the signed-in site) → a one-time code
  (12 characters, 10 minutes, kept as a hash in `scientiaPairs`); `POST /api/cloud/pair/claim` (no sign-in: the code is
  the proof) → that computer's own key (`keyMake`); `POST /api/cloud/key/self/remove` (a key removes itself).
- **The app's server** (`serve.py`): `/api/lab/ping` and `/api/lab/offer` answer only `https://mcgheelab.com` (CORS +
  `Access-Control-Allow-Private-Network` for Chrome's local-network check); the site hands over a code with `offer`, and
  nothing is connected until the person confirms in the app (`/api/lab/connect`, refused from any other page).
  `/api/lab/status`, `choose`, `sync-now`, `disconnect`, `uninstall`, `quit` are for the app on this computer only.
  Every response is sent whole (`sendall`): the stock write could cut a large reply (the 243 MB state, the 5 MB page).
- **The button and the walkthrough** (`scientia/src/23c-thiscomputer.js`, shown on mcgheelab.com only): ping →
  connected: open the tab (same note); installed but stopped: `scientia://start`, then open; not connected: hand over a
  code and open `#/connect`; not installed: the walkthrough (download → install → allow → confirm), which watches for the
  app and finishes on its own. `#/connect` and Settings → The lab show the state and offer Connect / a typed code /
  Sync now / Disconnect / Remove from this computer.
- **The download** (`scripts/scientia_build.py` → `rm/scientia/desktop/ScientiaInSitu-Windows.zip` + `version.json`,
  git-ignored, deployed; stored, fixed dates, so the bytes are the same on every computer): `Install Scientia.cmd` →
  `install.ps1` (no administrator): the app to `%LOCALAPPDATA%\ScientiaInSitu\app`; Python 3.9+ with tkinter from the
  computer, else the official installer silently into `…\ScientiaInSitu\python`; a notebook folder (kept, or
  `Documents\Scientia Notebook`); `HKCU\…\Run` → `service.py` (keeps `serve.py` alive, restarts it on a crash, ends
  with it on Quit / Remove); `HKCU\Software\Classes\scientia` → `open_local.py`; a Start menu entry and an uninstaller.
  `uninstall.ps1` disconnects, removes all of that and the private Python, and keeps the notebook folder.

## Several devices, one account

Each computer pairs with its own key; the website (a tablet, a phone) is a device of the cloud hub with a Firestore
listener. Measured with the dev hub (`scripts/scientia_hub_dev.js`): computer → cloud 0.45 s; tablet → computer 1.6 s.

## Not in this version

Mac (the installer and a LaunchAgent; the Python app itself already runs there); updates of an installed copy (run the
new installer — it replaces the app and keeps everything else); a signed installer.
