## Goal

external certificate uploads, but there is no place inside RM for lab

- How to write a scientific paper (V3.163)

V3.162 stands up the shared infrastructure (nav entry, landing page,
shared CSS, page-shell convention) and ships **one** prototype training:
**The Three Pillars of a Good PhD** — a lecture-style page with an
interactive SVG triangle (Communication / Creativity / Grit vertices,
Knowledge at the center), self-assessment sliders, milestone timeline,
and lab-support mapping.

## Approach

### Pedagogy
The PhD triangle is a conceptual lesson, not a math/model lesson, so it
uses a *simpler* format than [Data/trainings/MODULE_TEMPLATE.md](../../Data/trainings/MODULE_TEMPLATE.md)
prescribes for interactive notebooks. Single-scroll page, no tab bar,
one inline SVG instead of multiple canvases. Section 10 of MODULE_TEMPLATE
("When This Template Doesn't Apply") explicitly endorses this. The
microscopy + image-analysis modules (V3.164 – V3.170) WILL use the full
interactive template.

### Pillar copy (locked)
- **Scientific Communication** — writing papers + grants, presenting,
  teaching, defending. Failure mode: clear thinking that never reaches
  another human; brilliant work no one finds.
- **Creativity & Synthesis** — generating novel questions, connecting
  ideas across disciplines, designing experiments that actually
  discriminate. Failure mode: technically competent but derivative; only
  asks questions other people have already framed.
- **Grit** — persistence through failed experiments, rejected papers,
  scooping, funding rejections, the years-long arc. Failure mode: bright
  but fragile; first hard "no" ends the project.
- **Knowledge (center)** — the substrate that makes the other three
  possible. Communication without knowledge is style. Creativity without
  knowledge is invention without traction. Grit without knowledge is
  stubbornness. Knowledge is the join between all three.

### Lab-support mapping
- Communication → [Paper builder](/rm/pages/paper-builder.html), [Library](/rm/pages/library.html),
  conference travel, journal club presentations
- Creativity → PMR brainstorming blocks, [Protocols](/rm/pages/protocols.html),
  cross-project group meetings
- Grit → [PMR](/rm/pages/pmr.html) weekly reflection + barriers block,
  1:1s with Alex, peer support among the lab
- Knowledge → [Lab Notebook](/rm/pages/lab-notebook.html), Library
  annotations, the lab's recommended reading lists

### Auth gate
- All training pages declare `gate: 'lab-member'` in `NAV_ITEMS`.
- Each page's JS calls `firebridge.whenAuthResolved()` then bails if
  `!firebridge.isLabMember()` — the global pending-access overlay handles
  the visual.

### No Firestore writes this session
The PhD triangle's self-assessment scores live in component state only.
No persistence, no profile write. If a future iteration wants progress
tracking, add `userData/{uid}/trainingProgress/{moduleId}` and a rule;
deferred until requested.

### Interactive triangle implementation notes
- Inline SVG (viewBox `0 0 600 540`), three vertices at canonical positions:
  - Top: Communication (300, 60)
  - Bottom-left: Creativity (60, 480)
  - Bottom-right: Grit (540, 480)
  - Centroid (Knowledge label): (300, 340)
- Outer triangle = ideal (stroke #2563eb, fill rgba(37,99,235,.04))
- Inner triangle = student's scores, computed as a 1–5 scaled inset
  toward the centroid: `inner_v = centroid + (outer_v - centroid) * (score/5)`
- Vertex click → swap side-panel content via class toggle on three
  pre-rendered `.training-pillar-panel` divs
- Verdict text generated from three integers (score map → templated
  diagnosis + prescription)
- All event listeners attached after `firebridge.isLabMember()` returns
  true; before that the page DOM is hidden behind the pending-access
  overlay
