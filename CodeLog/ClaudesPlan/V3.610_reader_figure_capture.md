# V3.610 — Reader figure capture + Figure board library picker (program R2 of 4)

## Goal

Students reading papers in the library can now grab any figure as a reference
image: drag a box over it (⬚ Snip mode or Alt-drag), hit 🖼, name it — the
snip uploads to Storage and saves as a `kind:'figure'` annotation. On the
paper editor's 🧭 Figure board (V3.609), a new **＋ 📚 From library** picker
browses those captures across the reading library and places them as
reference cards that link back to the source paper.

## Problem

The reader's selection engine is text-item driven — `geom-selection.js`
bails when the drag doesn't start on a text item, and its rects come from
text bounding boxes. Figures have no text items, so there was literally no
way to select one. The only snip flow (equation capture) also inlines a
≤600px JPEG data-URI into the Firestore doc — too small and too heavy for
figure reference images.

## Approach

- **`rm/js/geom-selection.js`** — marquee mode. `setMarquee(on)`/`isMarquee()`
  public API + per-gesture Alt-drag. A marquee drag draws one free rect
  (clamped to the start page) and commits a single anchor
  `{page, rects:[r], saved_scale, marquee:true}` with **no selectors**.
  Downstream is safe: `annotation-anchor.js` renders pure rects × zoom
  factor (no text re-anchoring), and `selectedText()` already null-guards
  missing selectors.
- **`rm/pages/library-paper.html`** — ⬚ Snip toggle button in the viewer
  toolbar; loads `paper-figures.js` (the builder's Storage uploader — first
  time on the reader page) + new `figure-capture.js`.
- **`rm/js/annotation-overlay.js`** — 🖼 button on the selection toolbar
  (beside the ƒ equation button), wired via a new `onCaptureFigure` init
  option.
- **NEW `rm/js/figure-capture.js`** — snips the region from the rendered
  pdf.js canvas at up to **1200px** wide, uploads the JPEG blob via
  `PAPER_FIGURES.uploadImage(libraryItemId, blob)` →
  `paper-figures/{itemId}/{hash}.jpg` (storage rule already allows
  `image/*` on that prefix — zero storage.rules changes), and saves the
  annotation via `ANNOTATION_SYNC.create` with
  `{kind:'figure', annotation_type:'figure', name, comment,
  image:{storage_path, download_url}, snip_data_uri:<≤240px thumb>,
  target:{pages:anchors}}`. Reuses the eqcap-* modal CSS.
- **`rm/js/paper-overlay-types.js`** — `figure` added to the closed
  `annotation_type` enum (pink #ec4899) so captures get their own filter
  pill instead of falling into `note`.
- **`rm/js/annotation-panel.js`** — figure captures render in the
  annotation cards (image from `image.download_url`, thumb fallback).
- **`rm/js/paper-figure-board.js`** — `＋ 📚 From library` opens a capture
  browser cloned from `paper-equations._openCaptureBrowser` (papers from
  `PaperEditor.getCitationList()`, linked-to-this-draft first; the standard
  two equality-only queries `kind=='figure' && visibility=='lab'` plus
  `creator.uid==me && visibility=='private'` — no composite index).
  "Place on board" creates a `snip` card carrying
  `source:{item_id, ann_id, page}` — its ↗ link opens the source paper.

## Data model

No new collections. Figure captures are ordinary
`papers/{libraryItemId}/annotations/{annId}` docs (rules are
field-agnostic — **no firestore.rules change**). Image bytes live at
`paper-figures/{libraryItemId}/…` (existing rule).

## Open questions

- Touch devices can't marquee (selection engine is mouse-event based, as
  before) — capture stays desktop-first like equation capture.
- 1200px cap vs full-resolution: revisit if snips look soft on retina.
