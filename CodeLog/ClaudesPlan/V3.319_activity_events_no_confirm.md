# V3.319 — Activity overhaul: kill the confirm loop (FuturePlan 04, Release B1)

## Goal

Hours are dead. Activity auto-capture stops writing `hours` /
`status:'pending'` and stops demanding a ✓-confirm on every entry. New
entries are lightweight **events** — `{date, source, categoryPath,
text, kind:'work'|'schedule'}` — in the same
`trackerEntries/{uid}/entries` collection, with the deterministic doc
ids kept for idempotency (`auto-<kind>-<id>-<date>` for work,
`auto-<kind>-<id>` for schedule). Legacy hours-era entries are never
rewritten and stay readable (year-review / PMR / lab-stats read paths
treat missing-status docs as valid, which new events are).

## Changes

### rm/js/activity-signals.js (rewritten)
- `upsert` writes the event shape only — no `status`, `duration`,
  `milestone`, `auto_hours_estimate`. `hoursEstimate` in opts is
  accepted and ignored (producer call sites don't need same-release
  edits). Docs whose legacy `status` is `confirmed`/`dismissed` are
  left untouched by re-fires (the user's old decision survives).
- **Deleted**: `confirm()`, `dismiss()`, `listPending()`,
  `renderPendingBanner()` (the nagging banner), `renderComingUp()`.
  Their only caller is activity-tracker.js, rewritten in B2 (same FTP).
- `removeSchedule` now **deletes** the event doc (was: status
  'dismissed') when the doc is an event or legacy-pending; legacy
  confirmed/dismissed docs stay.
- New canonical reader `listEvents(uid, {from,to})` — everything not
  legacy-dismissed. `listConfirmed` / `listForPeriod` stay as
  compatibility aliases (PMR still calls them until B3).

### rm/js/page-time-tracker.js (presence signal, kept)
Write shape drops `status`/`duration`/`auto_hours_estimate`/`milestone`;
keeps `logged_windows` (10-min-window idempotency across tabs) and the
freeze guard for legacy confirmed/dismissed docs. `kind:'work'`.

### Producers reintroduced (removed in V3.226 because of confirm burden)
- **lab-notebook.js**: successful `saveEntry()` →
  `recordWork({source:'rm-notebook', sourceRef:{kind:'notebook',
  id:<entryId>}, text:'Notebook: <title>',
  categoryPath:['research','notebook']})` — one event per entry per day.
- **protocol-editor.js**: first input of the day in the builder →
  `recordWork(kind 'protocol', id <protocolId>,
  categoryPath ['research','protocols'])`.
- **paper-editor.js**: first input of the day in the editor →
  `recordWork(kind 'paper', id <paperId>,
  categoryPath ['research','paper-writing'])`.

## Rollback
Old entries are never rewritten — only new writes change shape;
reverting the client restores hours-writing.
