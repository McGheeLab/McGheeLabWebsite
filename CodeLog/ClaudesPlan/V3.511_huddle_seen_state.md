# V3.511 — Huddle R4: per-user seen state, "new" markers, nav badge

## Goal

The Huddle pushes notifications (a new help request pings the whole lab) but
gave users nothing in-app to answer "what's new since I last looked?" — a key
reason taps didn't convert to engagement. This release adds per-user seen
tracking with in-page "new" markers and a nav badge.

## Design

- **Storage**: `huddleSeen/{uid}` → `{ weekSeenAt, helpSeenAt, updatedAt }`,
  own-read/write only (mirrors the `huddleSettings/{userId}` pattern).
  Written (debounced 800ms; immediate on `visibilitychange: hidden` /
  `pagehide`) on bootstrap, tab switch, and page exit.
- **Baseline freeze**: "new" is computed against the timestamps loaded at
  page open (`_seenBaseline`), NOT the live values — dots stay visible for
  the whole visit and clear on the NEXT visit. No per-item read receipts.
- **"New" definition**: someone else's doc with `updatedAt >` baseline
  (`isNewDoc`); for help, additionally your OWN request with a response
  newer than the baseline (`isNewHelp`). Caveat (accepted): `updatedAt`
  moves on any edit, so "new" ≈ "changed since your last visit".

## What shipped

1. **[rm/js/huddle.js](../../rm/js/huddle.js)**: `loadSeenState`/`markSeen`/
   `isNewDoc`/`isNewHelp`/`countNewWeekItems`/`countNewHelpItems`. Markers:
   `.hud-new-dot` on anytime cards + help cards, `.hud-block-new` ring on
   grid/all-day blocks, `.hud-new-badge` counts on the This Week / Help
   sidebar tabs.
2. **[rm/js/huddle-badge.js](../../rm/js/huddle-badge.js)** (new): decorates
   `a[href="/rm/pages/huddle.html"]` (retry loop for nav render) with a count
   from two `Query.count()` aggregates — `huddlePlans (weekId==current,
   updatedAt>weekSeenAt)` + `huddleHelpRequests (status=='open',
   updatedAt>helpSeenAt)`. Loaded ONLY on [rm/index.html](../../rm/index.html)
   and [rm/pages/huddle.html](../../rm/pages/huddle.html). Counts include
   your own edits (a third filter can't share the index) — accepted
   overcount. Every query is try/catch'd so the badge no-ops while indexes
   build or before rules deploy.
3. **[firestore.rules](../../firestore.rules)**: `huddleSeen/{userId}`
   own-read/write.
4. **[firestore.indexes.json](../../firestore.indexes.json)**: composite
   indexes `huddlePlans (weekId ASC, updatedAt ASC)` and
   `huddleHelpRequests (status ASC, updatedAt ASC)` — required because the
   count queries combine an equality with an `updatedAt` range.
5. **CSS**: `.hud-new-dot`/`.hud-new-badge`/`.hud-block-new` in
   [rm/css/huddle.css](../../rm/css/huddle.css); `.huddle-nav-badge` in
   [rm/css/style.css](../../rm/css/style.css).

## Deploy — ORDER MATTERS

1. `firebase deploy --only firestore:rules`
2. `firebase deploy --only firestore:indexes` (composite indexes take
   minutes to build; badge no-ops until ready)
3. FTP (huddle.js, huddle-badge.js, huddle.html, index.html, huddle.css,
   style.css, sw.js)

## Verify

Two accounts: B posts/edits a plan and a help request → A (fresh page load)
sees dots on the cards, a ring on the grid block, counts on the sidebar tabs,
and a badge on the nav link from rm/index.html. A visits the tabs, reloads →
markers gone. Deep-link tap still flashes the exact item (V3.504 behavior
unchanged).
