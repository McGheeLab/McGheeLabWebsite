# V3.845 — The Figure board tab fills the editor

**Date:** 2026-10-22
**Alex:** *"the figureboard is not filling the width of the screen"* — after V3.841 had already
"stretched the Figures tab to the editor's full width".

## Goal

The paper editor's 🧭 Figure board tool page (`paper-builder.html?paper=…&page=figure-board`) shows the
canvas board (`figure-board.html?paper=…&embed=1`) in an iframe. That iframe must span the window and
take the height below the pill bar, on every screen width.

## What was actually wrong (measured, not guessed)

1. The standalone `figure-board.html` layout was measured first (the V3.837 harness DOM at a 1600 px
   window with its 1100 px test constraint lifted): the sheet was 1584 px wide. The engine and the
   `.nbc-*` frame were never the narrow part.
2. A replica of the editor's tool-page DOM, exactly as `paper-equations.js` builds it
   (`#pe-toolpage-root` → `aside.pe-tabbed-pane.pe-equations-pane.pe-toolpage-pane` →
   `.pe-tab-content[data-tab=figure-board]` → `#pe-figure-board-root` → `.pfb-canvas-wrap` →
   `iframe.pfb-canvas-frame`) with the editor's real stylesheets measured the iframe at **470 px in a
   1280 px window**, with `html.pe-wide-tab` set.
3. Cause: `.pe-page` is a column flex container and `.pe-toolpage` is a flex item with
   `margin: 0 auto`. Auto margins on the cross axis of a flex item absorb the free space, so the item is
   **not stretched — it is sized to fit its content** (fit-content). The content is a flex column whose
   only wide thing is an iframe at `width: 100%`; a percentage width on a replaced element inside a
   shrink-to-fit parent is treated as auto for intrinsic sizing, so the iframe contributes its intrinsic
   300 px, the bar's text decides the width (~470 px), and the iframe then becomes 100 % of that.
   V3.841 removed the 1100 px `max-width` and set `width: auto` — neither touches fit-content sizing, so
   the tab looked exactly as before.

## Approach

- `html.pe-wide-tab .pe-toolpage` — `width: 100%; max-width: none; margin: 0` (a definite width and no
  auto margins), plus `flex: 1 1 auto; min-height: 0; display: flex; flex-direction: column` so the tool
  page takes the height below the bars.
- The pane (`.pe-toolpage-pane.pe-equations-pane`), the figure-board `.pe-tab-content`,
  `#pe-figure-board-root` and `.pfb-canvas-wrap` become `width: 100%` flex columns with `min-height: 0`.
- `.pfb-canvas-frame` — `width: 100%; flex: 1 1 auto; height: auto; min-height: 420px` (fills the
  remaining height instead of the `calc(100vh − 150px)` guess).
- `paper-editor.css` `.pe-toolpage` gets `width: 100%` for every tool page (box-sizing is border-box
  globally), so a near-empty References or Tables page is a definite 1100 px column rather than
  shrink-to-fit. Centring is unchanged.

## Files

- `rm/css/paper-figure-board.css` — the wide-tab block (V3.841 → V3.845).
- `rm/css/paper-editor.css` — `.pe-toolpage { width: 100% }`.
- `scripts/tests/v3845-figure-board-width-harness.html` — new, 6 checks (see below).
- `sw.js` → 825. CHANGELOG, ARCHITECTURE, PENDING_RELEASE.

## Verification

- `v3845-figure-board-width-harness.html`: iframe ≥ window − 40 px with the class (1264 of 1280), the tool
  page spans the window, the remembered 420 px side-pane width is ignored, the frame fills the height
  (546 px on a 720 px window vs the old fixed 520), the other tool pages stay ≤ 1100 px without the class,
  toggling the class back restores the width. 6/6.
- Live `paper-figure-board.css` and `paper-equations.js` were byte-identical to local before the fix, and
  RM assets are network-first in `sw.js`, so this was not a stale-cache report.

## Decisions

- Fix the sizing chain rather than switching the tool page off flexbox: the editor's column layout is
  load-bearing for the write page.
- The frame fills the remaining height now; the old `calc(100vh − 150px)` assumed a bar height that
  changes with wrapping on narrow windows.

## Lesson (recorded in memory)

Measure the element in a replica harness before blaming a `max-width`. A flex item with `margin: 0 auto`
in a column container is fit-content wide; `max-width: none` / `width: auto` change nothing.

## V3.846 — the Huddle uses the whole window (2026-10-23)

**Alex:** *"the huddle page also needs the wide-tab rule."*

The Huddle (`rm/pages/huddle.html`) sits in the RM page shell, `.page { max-width: var(--page-max-w) }` = 1200 px,
centred. The canvas pages go wide through their own page classes (`.nbc-page`, `.grantdoc-page`, chat), so there was
no shell-level modifier. Added `.page.page-wide { max-width: none }` to `rm/css/style.css` (padding unchanged) and gave
the Huddle's shell `page page-wide`. Measured in a scratch page with the Huddle's three stylesheets: the shell is the
window's width. `sw.js` → 826, FTP only.
