# V3.916 — Open RM tabs follow each deploy; compiles stop looking dead

**Reported (Alex, 2026-10-25, after V3.915 went live):** "it is still building wrong in the document view, also when i
try to compile pdf it says it was sent to the cloud functions, but it doesn't do anything after" — then: "ensure we
don't run into browser cache problems like this again".

## Diagnosis (diagnose skill)

1. **The server had V3.915.** Every V3.915 file hashed identical live and local; `/rm/` answers `Cache-Control:
   no-cache` (V3.902) and the service worker revalidates `/rm/` (network-first, `cache: 'no-cache'`). A reload always
   gets the newest code.
2. **What a reload cannot reach is a tab opened before the deploy.** Its scripts are in memory. The root SPA
   (`index.html`) reloads on the worker's `controllerchange`; RM pages have no such listener, so a paper builder left
   open keeps running the previous build until someone reloads it. That is "still wrong" a few hours after a fix.
3. **The compile did run.** Cloud Run logs: one compile at 23:55 UTC, 200 after 46.8 s (proxy 48 s). After the
   page prints "Sending bundle to …paperCompile…" nothing on screen changes until the response, so 47 s reads as
   "nothing happens". The Paper Lab compile (local Tectonic, 2.9 s) mounts the PDF in the viewer; bucket CORS allows
   mcgheelab.com. The page path works; the wait is the problem.
4. **Why 47 s:** the image ships no Tectonic cache, Cloud Run scales to zero, so a compile after a quiet spell lands
   on a fresh instance that fetches every package and font. Measured locally: a real paper 38.1 s from an empty cache,
   2.8 s warm. The service's timeout is 90 s (the proxy's 120 s), so a paper with more fonts/figures could fail cold.

## Changes

- **`rm/js/build-check.js`** (new): reads `/rm/build.json` when the page starts, on `visibilitychange` → visible,
  focus, `online`, and every 5 min. A new stamp → reload if the tab is hidden or was just brought back and nothing is
  held; otherwise a small bottom bar ("RM was updated. Reload to use the new version." Reload / Later). Held: a focused
  input/textarea/select/contenteditable, a live `MediaRecorder` or `getUserMedia` stream (it wraps both to watch them —
  lecture recordings, notebook recordings, voice calls), `window.RM_HOLD_RELOAD`. Off on localhost/`*.local` and in
  the app (bundled `rm/`); top window only. Loaded by `runtime-mode.js` (87 pages) and a direct tag on the 20 pages
  without it.
- **`scripts/deploy.py` `stamp_build`**: every upload that changes a site file rewrites `rm/build.json`
  (`{build, head, sw, files}`) and sends it LAST, so an open page sees a new stamp only once every new file is on the
  server. `ftp`, `stage` and `autodeploy` (via `ftp`) all stamp. Git-ignored; the manifest tracks it.
- **Export page compile** (`paper-export.js`): elapsed seconds in the status, a sentence in the log about a cold
  server, `Open PDF` (the signed link) as soon as the response arrives, before the viewer mounts; `AbortController`
  stops the wait at 180 s with a message pointing to Compile history.
- **Compile service image** (`functions/paper-compile/Dockerfile`): `TECTONIC_CACHE_DIR=/opt/tectonic-cache`; the build
  fetches every file in `warmup/tex-files.txt` (`tectonic -X bundle cat`) and compiles `warmup/papers.tar.gz` (one
  synthetic paper per template and page look — format file). `scripts/paper-lab/warmup.py` writes both: the synthetic
  paper through the real Export page for every template, then the names of every file Tectonic fetched compiling that
  set and every Paper Lab paper (118 compiles, 485 files, 27 MB). Simulated build (the RUN line verbatim under `sh`):
  0 failures; afterwards every corpus paper, the NSF proposal and the MEBP copy compile with `--only-cached`
  (2.5–8.5 s). **Needs a Cloud Run redeploy** (command below); `--timeout 120` matches the proxy.

## Found on the way

- `paper-export-config.js`: an author whose `affiliationIdx` is a number (the paper-bundle skill's own example wrote
  `0`) crashed the Export page ("`(a.affiliationIdx || []).map is not a function`"); the PDF and the Document view
  dropped that affiliation. All readers accept a number or a list; the skill example writes `[0]`.
- `paper-look.js` `applyToTemplate`: under a published (spec) look, `section_kind_to_command` entries of type
  env/macro/placeholder become unnumbered sections, the rule special sections already followed — an APS paper with
  Acknowledgements stopped with "Environment acknowledgments undefined".

## Deploy

```bash
cd functions/paper-compile
gcloud run deploy paper-compile --source . --region us-central1 --port=8080 --no-allow-unauthenticated \
  --memory 1Gi --timeout 120 --max-instances 3 \
  --set-env-vars FIREBASE_STORAGE_BUCKET=mcgheelab-f56cc.firebasestorage.app
```

(Also ships the V3.914 server change: `grant_<doc>` compile kinds.) The site half deploys with the turn.

## Manual test

- Open the paper builder, leave the tab, deploy anything, come back: the page reloads (or shows the bar if a field
  has focus). Tested in a browser on a mapped hostname: idle → reload; typing → bar, no reload; back idle → reload;
  recording → bar until the recorder stops, then reload.
- Compile a paper on the Export page: the status counts seconds; Open PDF appears with the response; after the
  redeploy a compile takes a few seconds.
