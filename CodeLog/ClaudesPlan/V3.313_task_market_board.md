# V3.313 — Task Marketplace: model + board (FuturePlan 04, Release A1)

## Goal

One lab-scope board (`taskMarket/{postId}`) that carries every cross-user
task flow: PI posts claimable work (`offer`), members ask for work
(`request`), and owners ask a named teammate for help/take-over
(`handoff`). This release ships the data model, the security rules, and
the board page with working status transitions (claim / accept / decline
/ withdraw / complete). Claim **materialization** into the claimant's
task queue and push notifications land in V3.314 (Release A2); folding
the legacy flows (task-assign, sharing tabs) into the market lands in
V3.317 (Release A3).

## Data model — `taskMarket/{postId}` (lab-scope, top-level)

```
kind:        'offer' | 'request' | 'handoff'
status:      'open' → 'claimed'/'accepted'/'declined' → 'completed'
             terminal alternates: 'withdrawn' (creator), 'declined' (target)
title, description
createdByUid, createdByName
targetUid    (null = anyone; set = directed at a named teammate)
targetName
claimedByUid, claimedByName   (stamped on claim/accept)
task_payload { text, due_date, hours_estimate, self_importance, notes }
source_ref   { pmrPeriodId?, pmrSectionId?, pmrTargetId?,
               projectId?, bucketId?, subtaskId? }  (null when free-form)
created_at   ISO string   ·  createdAt/updatedAt serverTimestamp
resolved_at  ISO | null   (stamped on any terminal transition)
```

## Rules (firestore.rules)

- read: `isLabMember()`
- create: `isLabMember()` && `createdByUid == auth.uid` && status `'open'`
  — **plus** an admin-only carve-out for status `'accepted'` so V3.317's
  "Send to teammate" can keep the PI-assigns-directly UX (post is born
  pre-accepted). Shipping the carve-out now avoids a second rules deploy.
- update enforces the status *transition*, not free writes:
  - creator: `open→open` (edit), `open→withdrawn`,
    `claimed/accepted→completed`
  - claimant: `open→claimed/accepted` stamping `claimedByUid == auth.uid`,
    only when the post is undirected or directed at them
  - target: `open→declined`
  - `createdByUid` and `kind` are immutable on every path.
- delete: creator or admin.

## Index decision (resolves FuturePlan 04 open question 3)

The board attaches **one** listener: `taskMarket` ordered by
`created_at desc`, limit 300, filtered into columns client-side (lab
scale makes this trivially cheap, and one listener keeps every column
live for free). Single-field orderBy needs **no composite index** —
firestore.indexes.json is untouched this release.

## Key decisions

- **Direct `firebridge.db()` refs, not `api.save`** — the lab-scope
  adapter path does whole-list saves, which would rewrite other users'
  posts and violate the transition rules. Per-doc writes are the only
  shape the rules accept. Same precedent as sharing.js / task-assign.js.
- Board columns: **Open offers · Requests · Directed to me · My posts**
  (my posts shows open first, resolved in a collapsed section).
- Directed handoff accept/decline is fully usable end-to-end this
  release (the transition is the contract); the task-copy write lands
  in A2 so acceptors get the task in their queue.
