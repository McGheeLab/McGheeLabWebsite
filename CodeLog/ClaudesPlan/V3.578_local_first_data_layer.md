# V3.578 — Local-first data layer (mobile responsiveness)

## Problem

Every page in the Ourlab mobile app (and the web RM) feels slow. The
data-layer audit (2026-07-27) found the perceived latency is **two
independent problems**:

1. **No Firestore offline persistence.** `firebase.firestore().settings()`
   in `rm/js/firebase-bridge.js` sets long-polling + merge, but never
   enables IndexedDB persistence. Every cold read is a network round-trip.
   A hand-rolled IndexedDB stale-while-revalidate cache exists in
   `rm/js/api-firestore-adapter.js`, but it only covers `api.load` routes
   tagged `cache:`. The many **direct `.get()` calls** that bypass the
   adapter (dashboard's ~30–45 reads incl. an N+1 schedule-participant
   loop; chat's serial config/users/meta gets) get **zero** local caching.

2. **Full-document reload per navigation** (the MPA teardown). Out of
   scope for this pass — tracked separately.

This plan addresses **Problem 1 only** (chosen scope: "data layer only").

## Goal

Make repeat reads across the whole app serve from local disk instantly,
then reconcile with the server in the background — which is exactly the
"save all relevant data locally + refresh on change + push external
changes" model requested. Use Firestore's native offline persistence
(the local mirror) + `onSnapshot` (the change push) rather than a custom
sync layer or manual polling.

### R1 — Enable Firestore offline persistence  ★ foundational, lowest risk
`rm/js/firebase-bridge.js`: after `.settings()` and **before any read**,
call `firebase.firestore().enablePersistence({ synchronizeTabs: true })`.
- Guard in try/catch; on `failed-precondition` (multi-tab w/o sync) or
  `unimplemented` (browser unsupported) log + continue — app still works,
  just without the local mirror.
- Must run synchronously inside `_init()` before `_loadProfile()`'s first
  `.get()`. Returns a promise; we don't await it (persistence arms
  immediately; the promise only reports late failures).
- Effect: **all** `.get()` / `onSnapshot` reads — including the raw
  direct-ref reads that bypass the route cache — serve from IndexedDB when
  cached, reconciling in the background. This is the single highest-leverage
  change and touches one file.

### R2 — Skeleton paint on the hot pages  ✅ DONE (V3.580, My Day)
`rm/js/my-day.js` (+ `rm/css/my-day.css`):
- ✅ **My Day** (the app's landing tab — the priority for mobile, not the
  dashboard which isn't even a mobile tab): `init()` reordered so URL-param
  parsing + `renderSkeleton()` run BEFORE `await firebridge.whenAuthResolved()`.
  The auth await was the actual slow part — painting after it left the content
  blank for that whole window (confirmed by an early-launch screenshot).
  Now the real tabs/date-bar + shimmer placeholders show instantly; `render()`
  swaps in data on arrival. Verified in the simulator (early = skeleton, late
  = data, no blank).
- ✅ **R1 re-added, platform-gated to web** (see firebase-bridge change).
- ⏳ **Remaining R2 candidates** (not yet done): extend the skeleton pattern
  to Tasks + Team Focus tabs; the dashboard N+1 schedule-participant loop
  (`dashboard.js:210-217`) — deprioritized since the dashboard is a web-only
  surface, not a mobile tab.

### R3 — External-change push where it matters
For surfaces where another user's edits should appear without a manual
refresh (tasks, my-day roll-ups), attach lightweight `onSnapshot`
listeners. With persistence on, the listener fires from cache instantly
(free) and only bills a read when the server actually reports a change —
so we get the "ping for external changes" behavior WITHOUT polling reads.
Respect the deliberate read-cost budget dashboard.js documented (do not
blindly restore all 27 retired listeners).

## Key decisions
- **Native persistence over extending the hand-rolled cache** — it's the
  only thing that covers the raw `.get()` reads that dominate dashboard
  latency, and it's ~5 lines vs. rewriting every direct ref through the
  adapter.
- **`synchronizeTabs: true`** — RM web can have multiple tabs open; without
  it, persistence silently disables in all but one tab.
- **`onSnapshot` over polling** for external changes — push, not pull; no
  wasted reads; fires instantly from cache once persistence is on.
- Keep the existing hand-rolled route SWR cache — it still adds value
  (TTL semantics + the cheap-freshness probe) and layers cleanly on top.
