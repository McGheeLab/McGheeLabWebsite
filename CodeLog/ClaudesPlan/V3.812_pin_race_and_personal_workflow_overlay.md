# V3.812 — Pins that stick, and your own version of a default workflow

**Date:** 2026-10-19
**Alex:** *"the star doesnt work for me when i try to pin it. also i want to be able to customize my
workflow pages without haveing to make a custom type."*

## 1. The star

**Bug.** `NavPins.loadCloud()` runs once per page after sign-in resolves and overwrites the local
mirror with the cloud doc. A star pressed before that read lands — the first second or two of a
page, exactly when someone who just arrived presses it — is reverted when the stale read arrives.
The toggle also gave no feedback, and the star was hover-only, so on an iPad it never appeared.

**Fix.** The mirror carries a `dirty` flag: a user toggle sets it, a successful cloud write clears
it, a cloud pull (silent set) writes clean. `loadCloud()` **pushes** the local list when the mirror
is dirty — checked before the read and again after it resolves — instead of pulling. A toggle
before sign-in stays dirty and is pushed by `loadCloud()` once the user is known. Every toggle
toasts ("★ Pinned Tasks to your bar" / "Unpinned Tasks"), adding "you'll see it once you leave this
workflow" while a workflow is active (the chip row shows workflow pages then). The active chip's ★
is always visible, not hover-only, and the ★/× hit targets grow under `(hover: none)`.

## 2. Customize a default workflow without forking

The session state already carried `addedPageIds / removedPageIds / orderOverride` on top of the
lab's `pageIds` (V3.65/V3.66) — but only in sessionStorage, and the only way to keep them was
"Save as mine", which creates a separate custom workflow. Now the overlay is **persisted per user,
per default workflow**:

```
userData/{uid}/workflowPrefs/{workflowId} = { workflowId, addedPageIds, removedPageIds, orderOverride, updatedAt }
```

- Written 400 ms after each × / + / drag (`_navQueueWorkflowPrefsSave` → `_navSaveWorkflowPrefs`);
  deleted when the overlay is empty again.
- Read into a fresh session state the first time the bar renders that workflow
  (`_navHydrateWorkflowPrefs`, before the chip list is computed — no flash of the lab default;
  `state.prefsLoaded` marks it; edits already made in the tab win over the saved overlay).
- Effective pages stay `lab pageIds ∪ added − removed` in override order with new admin pages
  appended (`_wfEffectivePageIds`, unchanged) — so the admin's edits still reach everyone.
- **Custom** workflows: the same queue folds edits straight into the user's own
  `customWorkflows/{id}.pageIds` (what the Save button did) and clears the session overlay.
- The **Save chip is gone**. The Workflows ▾ trigger shows an amber dot when the active default is
  customized; the menu header says "· customized for you" and offers **Reset to lab default**
  (clears the overlay, deletes the doc). **Save as my workflow…** stays as the way to get a
  separate copy.

Blanket `userData/{userId}/{document=**}` owner rule covers the new subcollection — no rules change.
