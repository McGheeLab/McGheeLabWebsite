# V3.915 — LaTeX written in prose (papers imported from .tex)

**Asked (Alex, 2026-10-25):** "I looked at the document view for some of my papers on the website and it looks
terrible. The training on papers seems to have made it so our content can't be easily formatted into shape … a ton of
issues with 'Microscope Enabled 3D Bioprinting'; all of the various journal formats all have issues."

## Reproduction

The production paper could not be read (the read of the lab database was refused), so the Paper Lab ran the April RM
copy of the same paper (`ResearchManagement/data/paper-imports/mebp-paper.json`, imported from the MEBP-Paper LaTeX
repo) with `MEBP-Paper/references.bib`: `PaperLab-corpus/mebp-april/` (unpublished; outside every repo, built by the
session's `tools/make_mebp.py`). Every journal template was previewed and compiled.

The paragraphs carry the LaTeX they were written in: `[X]~\si{\micro\metre} (n~=~[X])`, `\cref{fig:…}`,
`\Cref{tab:bom}`, `[X]\%`, `\$[X]`, `H\textsubscript{2}O`, run-in heads as whole-bold paragraphs, and the bill of
materials as a `table` block holding only `attrs.raw_tex`.

## What was wrong

## Approach

One reader for both sides, `rm/js/paper-prose-tex.js` (pure, Node-tested), so the preview and the PDF cannot disagree:

- `readCommand(s, i)`: a control sequence with its arguments (known arities, optional `[…]` only where the command takes
  one, balanced groups, `\{` skipped).
- `tildeAt(s, i)`: a `~` is the builder's subscript only when short and word-like (letters, digits, `+ - . , ' *`, no
  spaces, brackets, backslashes or placeholders) right after a non-space; between two non-space characters it is a tie
  (no-break space); beside a space it is the character ("~5 µm").
- `toHtml(cmd, ctx)`: siunitx (`\si`, `\SI`, `\num`, `\qty`, ranges, lists — siunitx's own symbols, `\per` as a −1
  power, thin spaces), references through the builder's own chips (`\cref` → "Fig. N" with the journal's prefix,
  `\ref` → "N"), `\cite` → citation chips, `\footnote`, formatting (`\textbf`, `\emph`, `\textsubscript` …), accents,
  text symbols. An unknown command prints as its source.
- `toTex(cmd, ctx)`: verbatim for every known command (as before V3.906); `\cref`/`\Cref` follow the template's
  reference prefix unless cleveref is on; `\cite` takes the template's command; math symbols written outside math get
  `\ensuremath`; free-standing `\micro`/`\degree` (undefined outside `\si` in siunitx v3) become `\textmu`/`\textdegree`;
  an unknown command is escaped as text, so it can never break a compile.
- `packagesFor(tex)` + `preambleLoads`: siunitx, cleveref, booktabs, float, ulem are added to the preamble when the
  paper's own LaTeX uses them and the preamble does not load them.
- `parseTabular(raw)`: an imported `table`/`tabular` → caption, label, column alignment, rows of cells, midrule
  positions, `\small`.
- `decodeAccents(s)`: BibTeX accents → Unicode, for `bibEscape` and the preview bibliography.

Elsewhere: `layoutParagraph` re-wraps each cut line in shallow copies of the elements between it and the paragraph;
the Document view prints an unknown reference as LaTeX does ("Fig. ??", label on the tooltip); `getAllFigures` /
`getAllTables` fall back to the `\label{}` inside `raw_tex`; `collectCitationKeys` also reads `\cite{…}`.

Editing is unaffected: a focused paragraph shows its source (`renderChipsOnlyHtml`); only the display renderer changed.

## Result

The April MEBP copy in all eleven journal templates: no raw LaTeX and no text in the margins in any preview; every
template compiles (mebp-journal failed before); no backslash in any PDF's text; units, ties, run-in heads and the bill
of materials as in the PDF.

Corpus regression (`run.py all --tag p7`): every published paper and the NSF proposal identical to V3.914 — page
counts, line ends and page starts unchanged (NSF 16/16 page starts); the corpus's `~subscripts~` (`EC~50~`,
`OVA~257–264~`, `MgCl~2~`) all still read as subscripts.
