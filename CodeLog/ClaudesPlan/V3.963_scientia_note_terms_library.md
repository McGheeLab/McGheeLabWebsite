# V3.963 — Scientia: terms in one note, the lab's Library adds / pulls / pushes papers, shelves and foci

## Goal (Gabe, 2026-11-09)

1. **Temporary terms inside a note.** It looks like an Atlas inside the note and you can dive into it. You type the ways the term is written and pull it from the theme, the project or the notebook. It lives in the note and is not updated automatically: you fetch by hand. Reload brings the atlas back to its original state.
2. **The RM library.** Papers can be downloaded or pulled into your notebook. Papers can be pushed to RM's library from local downloads, so the DOI lookup comes back on the McGheeLab website version.
3. **Shelves and foci.** Make paper shelves, import them from the RM website, and make paper foci that are grouped in shelves (two layers).

## Decisions (asked)

- **The lab layer and the hub change in this PR, Alex reviews.** Covers lab-mode §3/§4, the harness's "no DOI box" check, and two hub routes. Gabe's rule is to ask before touching the lab layer; he chose this. The hub needs `firebase deploy --only functions:scientiaHub`, which only goes out with his go-ahead.
- **RM keeps no stored shelves.** Its "Shelves" block holds flat groups. **An RM group becomes a focus**, on a shelf named for its source: "My RM groups" or "Lab groups". Smart groups are saved searches in RM's grammar, so they stay in RM.
- **Reload = as at the last Fetch.** It clears the dive, the focus and dragged dots. Only Fetch changes what the map holds.
- **Pull brings the PDF in, and the paper stays RM's.** It is a media record with `rmPaper`, the one RMREAD reads; there is no second library row, so no duplicate in /cite.

## Approach

### Note terms (`scientia/src/14c-noteterm.js`, new)
- **Storage.** Widget `nterm`. The block holds `nterm { name, forms, scope, snap }`. It is not a `terms` row, because `TERMSCAN` would then mark it across the whole notebook.
- **Fetch.**
  - Matches with `TFORMS.rx` (smart case), over `body.text` of the scope's live blocks.
  - Keeps the 150 that use the term most.
  - Builds nodes: the term, components, their notes, the terms and papers they carry.
  - Builds edges: uses, in, mentions, cites, wires.
  - Lays them out once with `ATLAS.tick` and stores positions, so the map opens as it was fetched.
- **Drawing reuses the Atlas.** `NTERM.as(I, fn)` swaps ATLAS's drawing state (`G`, `cv`, `ctx`, `T`, `alpha`, `st`, `lit`) for the map's own. `fit`, `draw`, `hit` and `tick` then run unchanged. Building a second graph renderer would mean "two of anything", which the lab avoids.
- **View state** (dive, focus, dragged dots) lives in a module map. It survives `changed()` redraws and dies on Reload, Fetch or an app reload.
- **Highlighting.** The forms are underlined in the note with the CSS Custom Highlight API. Nothing is saved.

### Shelves and foci (`17d-libgroups.js`)
- The app already had the two layers, library themes holding groups holding papers. They are renamed shelves and foci in the UI.
- Records are unchanged: `libsets` kind `theme`/`group`. That keeps sync and old notebooks as they are.

### The lab's Library (`rm/scientia/lab-mode.js` §3)
- **Adders.** `LibraryView.adders()` is factored out of the app's view and used on the lab page.
- **Pull.**
  - Website: `api/rm/library/pdf` gives the URL, then `fetch` downloads it (storage CORS takes mcgheelab.com).
  - Desktop: `api/rm-pdf` through serve.py.
  - The file is saved with `MEDIA.add` and `rmPaper`. **Read here** opens it with `RMREAD.read`, now usable on the website too.
- **Push.**
  1. `api/rm/sync?only=up` (the existing V3.927 syncUp).
  2. Wait for the row's `rmSync`.
  3. `api/rm/library/pdf-up`.
- **Import.** `api/rm/library/groups` → foci with `rmGroup`, on shelves with `rmShelf`. Importing again updates them.

### Hub (`functions/scientia-hub-core.js`, `scientia-hub.js`)
- **`rmGroupsPlan`.**
  - Manual groups: kept as they are.
  - Draft groups: become their `linked_drafts` papers.
  - Smart groups: counted, not imported.
- **`pdfUpPlan`.**
  - Only for a library entry without a PDF.
  - RM's path, `papers/<id>/<sha256[:16]>.pdf`.
  - RM's record fields, with `source: 'scientia'`.
- **Routes.** `GET /api/rm/library/groups` and `POST /api/rm/library/pdf-up`. The second takes only `images/<id>.pdf` from the hub's own media; nothing is uploaded twice.
- **MemoryHub** implementations, for tests and the dev hub.
