# V4.88 — Scientia: Code — a compendium of your .py scripts, and the Code kind that runs one on your data

## Why
Gabe, 20 Nov: "In Atlas, add Code tab where you can upload .py with title and user description of what it is. Allow the user to input a new kind called code which asks the input data (from the data tree), and reflects with the output result as a figure, plot, table, etc..." (The Atlas's galleries are the Compendiums since V4.85.)

## What changed (`14fg-code.js`, `CODE`; `47-code.css`)
- **The `scripts` store** (`02-schema.js`; `DB_VERSION` 12 → 13, as the calendar's `events` store was added in V4.57): `{title, desc, file, code, lang, created, modified}`. It keeps the text of the file, never the file; it syncs like the other stores (the hub takes any store).
- **Compendiums → Code**, after Topic syntheses:
  - **＋ Upload a .py** asks for its title and what it does, with a look at its first lines.
  - Each script is a card: the file, how many lines, how many components run it, what it does, and its first lines.
  - Its actions: **Use in a note…** (the move panel; a Code component with this script in the note picked), View, Edit, Delete. A deleted script leaves its components' outputs.
  - A search over titles, descriptions and code.
- **The Code kind** (13zzi's kinds: double-click a component's label → Code). It produces a result, figure, evidence or anything. Under the component's text is a panel:
  - **Script:** one of the compendium's, or ＋ Upload a .py…, with View.
  - **Input — ＋ From the data tree**, from the whole notebook, this note's first:
    - a file logged in a data tree, read from its folder where this device keeps it (`DTREE.handle`), else chosen again on this device;
    - a table, as CSV;
    - an image of an image panel.
  - **▶ Run.** Python runs in this browser: Pyodide 0.26.4 from cdn.jsdelivr.net, in a worker, loaded on the first run; it needs the network then. The script sees `INPUT` (the first input's path) and `INPUTS`, in `/data`.
  - **The output comes back into the component** (`b.code.out`):
    - the figures matplotlib drew (kept as images in the notebook);
    - a table: a pandas DataFrame or rows named `result`, the first rows shown;
    - what it printed;
    - or the error.
    - It says when it ran and how long it took, and whether the script changed since.
  - **＋ As an image panel** and **＋ As a table** put a figure or the table beside it, connected ("produces").
- **Settings → Canvas & notes → Code** (`code`):
  - *A table shows* (10 / 20 / 50 / 200 rows) and *Show what the script prints*;
  - a live preview.
  - Off: the compendium and the panel go; scripts and outputs stay.
- **Not an Insert row:** a new "+ Insert" row needs its icon mapped in the lab layer (`lab-mode.js`, `INS_PICS`) or the lab harness fails. The kind and the compendium's *Use in a note…* make a Code component instead, and nothing in `rm/` changed.
- **Fix to V4.87:** the instrument guess now comes only from instruments' formats (.nd2, .czi, .lif, .lsm, .oib, .oir, .vsi, .ims, .fcs), not from .csv or .tif (`DFLOW.MAKERS`).
