# V3.385 — Guided interactive tours for the node canvas

## Goal

A guided demo mode: a **gently pulsing ring** highlights the exact next
control (palette button, node dot, config panel), and an **instruction
card in the top-right** says what to do and — more importantly — how to
**think** about it. One tour per node type plus pattern tours. "Do"
steps advance **when the user actually does the thing**, not on a Next
click.

## Design

### New `rm/js/protocol-graph-tours.js` (`window.ProtocolGraphTours`)

**Engine** (`attach({hostEl, viewport, getGraph}) → {start(id), stop,
active, destroy}`):
- Steps are `{title, text, target?, targetLast?, when?, next?}`.
- **Ring**: a `.pgt-ring` in viewport space, repositioned every frame
  from the target's `getBoundingClientRect()` — selectors are
  re-resolved per frame because the editor tears down and rebuilds all
  cards on each render, and rect-based positioning tracks pan/zoom/drag
  for free. Hidden when the target is missing or off-viewport;
  `pointer-events:none`; pulse animation with a `prefers-reduced-motion`
  fallback.
- **Card**: `.pgt-card` top-right in the viewport — tour title, step
  title, instruction prose (inline HTML), progress `N / M`,
  `Next ▸` (explanation steps), a small `skip` link (do-steps, in case
  the user is stuck), `×` exit. Success flashes green "✓" before
  advancing.
- **Advancement**: do-steps carry `when(graph, base, H)` evaluated
  ~4×/s on the rAF loop against the live graph — the tour advances the
  moment the graph shows the action, however it was performed. `H`
  helpers: `count/added/addedAtLeast` (vs the per-step baseline
  snapshot), `fresh/freshEdge` (vs the tour-start snapshot — "made
  during this tour"), `some`, `anyEdge`, and `wiring()` (the
  `body.pge-wiring` armed state, for the bindings tour's arm step).
- **Auto-skip**: a step whose condition is already true at activation
  flashes "✓ already done" and advances — prerequisite steps ("you need
  an input") melt away on graphs that already have the pieces.
- Self-healing: the loop stops itself if the viewport leaves the DOM.

**Content — 11 tours.** *Meet the nodes* (one per type, each opening
with a mental model): Inputs ("a question you ask the runner"),
Constants ("a decision you've already made — named, with a unit"),
Equations ("every derived number is an equation, never mental math"),
Choices ("one node = one categorical axis"), Ordered ("graded levels
that keep their order; members are numbers"), Lists ("the experiment
table — design backward from it"), Code ("the escape hatch; prefer
equations"). *Patterns & thinking*: **From protocol to nodes** (the four
decomposition questions — runner-decided → inputs; already-decided →
constants; varies-by-design → sets→list; computed → equations/code),
**Bench math: dilution** (want→inputs, do→equations, via the recipe),
**Drive settings** (bindings walkthrough: + add modifier arms the max
dot → click the constant's out-dot), **Design an experiment grid**
(choices × ordered → list, both wires condition-checked separately, then
per-item columns + plate planner pointers).

### Editor + loading + CSS
`protocol-graph-editor.js`: a **🎓 Tours ▾** palette dropdown (same
pattern as Recipes, grouped, with a "tours build real nodes — practice
freely, delete after" note); picking a tour closes the cheatsheet,
lazily `attach`es, and `start`s; `destroy()` tears the tour down.
`protocols.html` loads `protocol-graph-tours.js` before the editor.
CSS: `.pgt-ring` pulse, `.pgt-card`, `.pge-tours-note/-group`.

## Verification
- `scratchpad/test-tours.js` (73 asserts): data validation (11 tours,
  unique ids, every step titled + advanceable, node-type coverage,
  `list()` shape); all 26 conditions smoke-tested on the empty graph (no
  throws); helper-kit semantics (added vs baseline, fresh vs tour start,
  freshEdge role/type matching, `wiring()` safe headless); scripted
  happy-path chains for the equation tour (input→add→wire→expr), the
  grid tour (choices-wire and ordered-wire fire independently), the
  bindings tour (param/max edge satisfies arm + complete, covering the
  drag path), the dilution tour (+2 equations via the recipe), and the
  auto-skip semantics. Full regression suite green.
- Pending (browser): start "Equations" from 🎓 Tours → ring pulses on
  the palette button → adding the node advances with a ✓ → ring moves to
  the open math dot → completing the wire advances; exit mid-tour; run
  a tour inside the popout modal.
