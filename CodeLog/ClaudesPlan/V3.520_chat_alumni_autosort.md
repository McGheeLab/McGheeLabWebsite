# V3.520 — Chat: alumni auto-sort in People lists

**Alex request** (chat upgrade follow-up): lab users whose
`users/{uid}.category` moved to `alumni` kept appearing under their old
grouping in chat's People lists.

## Why it was stale

The desktop sidebar "People" section and the mobile Overview People
section render the user's CURATED contact groups
(`chatUserMeta.dmContacts` — raw uid arrays saved once and never
re-checked against live categories). The New DM and Manage Contacts
modals were never affected — they group by live category already.

## Fix — render-time regrouping (no data migration)

New `splitContactsForRender()` walks the curated groups against live
`_allUsers` data: anyone whose category is now `alumni` (`isAlumniUid`)
is pulled OUT of their curated group and collected into an automatic
**Alumni (N)** section rendered after the groups — collapsed by default
(native `<details>` on desktop; the existing `_collapsedSections`
mechanism with key `'alumni'`, seeded collapsed, on mobile). Curated
groups that end up empty are hidden. Because the regrouping happens at
render time against live data, correcting someone's category pops them
straight back into their original curated group — `dmContacts` is never
mutated, and the Manage Contacts modal still shows/edits the raw groups.

Both list renderers were also deduplicated into item helpers
(`renderDmItemHTML` / `renderOverviewDmItemHTML` + `renderDmGroupHTML`)
while touching them.

## Files

- `rm/js/chat.js` — `isAlumniUid`, `splitContactsForRender`, sidebar +
  overview People sections, `_collapsedSections` seeded with `'alumni'`.
- `rm/css/chat.css` — `.chat-sidebar-alumni` details styling (dimmed
  items, chevron).
- `sw.js` — CACHE_VERSION bump.

FTP-only.

## Verification

Set a test user's category to `alumni` (Lab Members page) → they leave
their curated group in the chat sidebar + mobile Overview and appear
under collapsed "Alumni (1)"; expanding it shows them dimmed, DM still
works. Set the category back → they return to the curated group.
Manage Contacts modal still lists them in the raw group either way.
