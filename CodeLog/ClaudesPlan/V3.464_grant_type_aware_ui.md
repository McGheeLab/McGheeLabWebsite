# V3.464 — Grant unification R2: type-aware Add Section + creation flow

> Second release. Makes the R1 schema visible: the creation modal filters templates by
> document type and captures a grant mechanism; the in-editor Add Section menu shows
> grant-appropriate groups for grant papers.

## Creation flow (rm/pages/paper-builder.html + rm/js/paper-builder.js)

- **Template picker now filters by document type** — `populateTemplateSelect()` uses a
  new `templatesForType(type)` (mirrors the export page's `KNOWN_TEMPLATES.types[]`
  filter): a template with no `types` defaults to journal-only; an empty result falls
  back to the full list (never a dead picker). Picking "Grant" instantly swaps the
  picker to the four grant starters (nih-r01/nih-r21/nsf-standard/nsf-career + blank).
- **New "Grant mechanism" select** (`#pb-new-subtype`, shown only when type = grant):
  options are the grant starter templates (a starter's id doubles as its mechanism id,
  which the checklist keys off) + a "General / other (no checklist)" escape. Follows
  the template selection unless overridden.
- The new paper row stamps **`grant_subtype`** (`nsf-career` | `nih-r01` | … | null).
  Non-grants and "general" grants get null. The existing `seedFromTemplate` path
  (paper-editor.js) already seeds the right sections because R1 registered the grant
  starters in `PAPER_TEMPLATES`.
- Document-type hint reworded (grant support is real now, not "coming").

## In-editor Add Section menu (rm/js/paper-editor.js)

- The flat `ADDSEC_BODY_KINDS`/`ADDSEC_SUBMISSION_KINDS` arrays are now selected by a
  type-keyed `_addSecGroups(paperType)` reading `state.meta.paper_type` (already in
  scope). Grant papers see **Attached documents** (the 18 `GRANT_ATTACHED_KINDS`, read
  lazily from PaperSchemas so script eval-order can't empty them) + **Submission
  documents** (cover letter / suggested reviewers) instead of the journal Body/
  Submission groups. Editorial/book-chapter/unknown fall back to the journal groups.
- Every grant attached kind is a singleton (`_isSingleton` unions the static
  `ADDSEC_SINGLETONS` with the grant kinds) — greys out once present.
- The Custom row is relabeled "Narrative / custom section" for grants (the narrative —
  Overview, Background, Aims, … — is authored as plain custom sections by design) with
  a grant-flavored placeholder.

## Verification

- `node --check` clean (paper-builder.js, paper-editor.js); harness 227 green.
- Browser (Alex): New paper → pick "Grant" → the Grant mechanism select appears, the
  template picker shows only grant starters; pick NSF CAREER → create → editor seeds
