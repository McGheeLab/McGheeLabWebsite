# V3.154 — Full insertion-path audit + drop the stale `savedRange` gate

## What was reported

User: "lets get a full diagnostic for all of the various inline and
reference items to add. most are still not working right."

V3.143 / V3.152 fixed the **leaf** insertion function
`_insertAtSavedCaret`, but only audited the five toolbar buttons. The
panel-side "Insert" buttons in the four right-side tabs each had their
own copy of the gate-on-savedRange-and-fall-back-to-activeElement
boilerplate, and that boilerplate was broken in the panel-button case
(when `document.activeElement` is the button itself, not a
contenteditable).

## Diagnostic — every insertion entry point

There are **13** insertion entry points in the paper builder. For each,
we now know the path and the status post-V3.154:

### Right-click context menu (in any paragraph)

| Action | Path | Status |
|---|---|---|
| Insert inline equation | `_saveCaretFromEvent(e, el)` → `_openInlinePicker` → `_insertAtSavedCaret('[!eqi:<slug>]')` | Works (V3.152) |
| Insert equation reference | same → `_openRefPicker` → `_insertAtSavedCaret('[!eqr:<label>]')` | Works |
| Insert figure reference | same → `_openFigRefPicker` → `_insertAtSavedCaret('[!fig:<label>[:<panel>]]')` | Works |
| Insert citation | calls into `PaperEditor.openCitationPopover` (different code path; uses PaperEditor's own char-offset tracker) | Works |

The right-click path is healthy because `_saveCaretFromEvent` is called
synchronously inside the contextmenu handler, while the contenteditable
is still focused and the selection is live.

check was failing first and the user often saw the picker open with
the wrong caret state, leading to `_insertAtSavedCaret` finding
inconsistent state.

## The fix — uniform gate

All five sites now look like this:

```js
if (!_state.savedEl || !document.body.contains(_state.savedEl)) {
  _saveCaretFromCurrentFocus();
}
if (!_state.savedEl || !document.body.contains(_state.savedEl)) {
  alert('Place the cursor in a paragraph first…');
  return;
}
_insertAtSavedCaret('[…]');
```

`_saveCaretFromCurrentFocus()` is the V3.140-extended caret-recovery
function: tries `document.activeElement.isContentEditable` first, then
falls through to PaperEditor's `lastFocusedEditable` +
`lastFocusedCaret` tracker (which survives blur because it's set on
keyup/mouseup/input). The fallback path is what makes panel-side
buttons work — at the moment the user clicks the button, `activeElement`
is the button itself, so only the lastFocusedEditable tracker can
recover the user's prior caret position.

## The fix — `_openCitationPopoverFallback`

Citations don't go through `_insertAtSavedCaret`. They go through
PaperEditor's `openCitationPopover` → `insertCitationAtFocus`, which
uses PaperEditor's own char-offset tracker. But the toolbar fallback
was setting up the contenteditable's selection BEFORE opening the
popover, using the stale Range:

```js
_state.savedEl.focus();
sel.addRange(_state.savedRange);  // ← stale, addRange silently fails
window.PaperEditor.openCitationPopover({ anchorEl: _state.savedEl });
```

V3.154 rebuilds the Range fresh from `(savedEl, savedCaret)`:

```js
_state.savedEl.focus();  // focus handler swaps to source-text DOM
var freshRange = _rangeFromCharOffset(_state.savedEl, _state.savedCaret);
if (freshRange) sel.addRange(freshRange);
window.PaperEditor.openCitationPopover({ anchorEl: _state.savedEl });
```

## Verification

1. Click into a paragraph, type "hello world", caret between hello
   and world.
2. Open the side panel → Figures tab → click "Insert reference" on
   any placed figure. Token `[!fig:<label>]` inserts at the caret in
   the correct paragraph.
3. Same for Tables tab "Insert reference", References tab "Insert
   citation".
4. Toolbar `+ Eq`, `+ Fig`, `+ Table`, `+ Cite`, `+ Inline Eq` all
   insert at the caret.
5. Right-click → Insert inline equation / equation reference / figure
   reference / citation all insert at the caret.
6. Click into a paragraph, type, then click somewhere on the side
   panel header (focus moves out of paragraph), then click a panel
   "Insert reference" button — the insert still lands at the LAST
   caret position in the paragraph (recovered via PaperEditor's
   lastFocusedEditable tracker).
7. Click a panel "Insert reference" button without ever having focused
   a paragraph → alert "Place the cursor in a paragraph first…"
   appears.
8. Hard-reload to evict SW cache `mcgheelab-shell-v129`.

## Out of scope (deferred)

- **Mousedown handlers on panel-side Insert buttons.** Could be added
  for belt-and-suspenders (save caret BEFORE the contenteditable
  blurs), but the lastFocusedEditable fallback already covers this
  cleanly. Would only matter if a future change broke that fallback.
- **Visual indicator of which paragraph "owns" the active caret.**
  Could light up the paragraph block when a panel insert button is
  hovered. Useful for UX clarity but not blocking insertion.
