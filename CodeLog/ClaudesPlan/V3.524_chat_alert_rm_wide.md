# V3.524 — Chat corner alert: RM-wide + burst/visibility fixes

**Alex's test feedback on V3.521**: read receipts worked but the corner
alert never appeared. Three causes addressed:

## 1. The alert only existed on the chat page (v1 scope)

New **`rm/js/chat-alert-watch.js`** — a self-contained watcher loaded on
**every RM page except chat** (bails when `#chat-root` exists; chat.js
runs its own richer version). Waits for `firebridge.whenAuthResolved()`
(skips guests, no-ops without the SDK), then listens to `chatChannels`
+ own `chatUserMeta`, diffs `lastMessage.timestamp` against per-channel
baselines (first snapshot seeds only), and pops the same
one-card-per-burst corner alert: in-place updates, × dismiss, 8s
auto-fade, 3-min post-hide cooldown, hidden-tab queueing. Click →
`/rm/pages/chat.html?channel=<id>`. Styles are injected by the script
(chat.css isn't loaded elsewhere). Script tag added after
`firebase-bridge.js` on **68 pages** (all of `rm/pages/*.html` except
chat.html, plus `rm/index.html`).

## 2. Hidden-tab cooldown burn (real bug)

If the chat tab was hidden when the message arrived, the card rendered
invisibly, auto-faded after 8s, and burned the 3-minute cooldown — the
user returned to nothing. Both the chat-page version and the watcher now
QUEUE alerts while `document.visibilityState !== 'visible'` and show
them on the visibilitychange back to visible (chat.js reuses the
presence visibility handler).

## 3. Suppression was too broad on the chat page

The active channel suppressed alerts even when the user was scrolled up
reading history (the new message wasn't actually in view). Suppression
now also requires `_autoScroll` (following the tail).

## 4. Entry alert for existing unread chats (Alex follow-up)

On arriving in RM with UNREAD chats (any eligible channel whose
`lastMessage.timestamp` is newer than the user's
`chatReadState.lastReadAt`), the watcher pops the card immediately —
labeled "Unread message(s) in …" and lingering 15s instead of 8s.
Guarded by `sessionStorage['rmChatUnreadAlerted']` so it fires ONCE per
tab session — navigating dashboard → tasks → papers doesn't re-alert on
every page load; a new tab/window re-arms it. The watcher fetches own
`chatUserMeta` + `chatReadState` before attaching the channels listener
so the first snapshot can evaluate unread state with real data.

## Bonus fix: `?channel=` deep links

chat.js NEVER handled the `?channel=` query param — FCM push clicks have
always landed on whatever channel was last open. The auto-select now
prefers the URL param over the remembered channel, which both fixes push
taps and gives the watcher its click target.

Files: `rm/js/chat-alert-watch.js` (new), `rm/js/chat.js`,
`rm/pages/*.html` (68 script tags), `rm/index.html`, `sw.js`. FTP-only.

In chat scrolled up in the same channel → card appears; at the bottom
