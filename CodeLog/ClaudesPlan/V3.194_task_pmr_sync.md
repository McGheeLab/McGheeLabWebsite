# V3.194 — Tasks ↔ PMR: Add to PMR + bidirectional completion sync

## Goal

Two user-reported flows:

1. **"Add to PMR" button on every subtask row.** Click → the subtask gets
   copied into the current week of the user's most-recent PMR period as
   a weekly-entry item, with a `source_subtask_id` back-link.

2. **Completion sync.** Marking a task done in EITHER view marks it done
   in the OTHER. Closing the gap is bidirectional: tasks-page subtask
   → PMR weekly item (via `source_subtask_id` match); PMR weekly item
   with `source_subtask_id` → tasks-page subtask (lookup across all
   bucket docs).

## Architecture

New shared bridge module **[rm/js/task-pmr-sync.js](rm/js/task-pmr-sync.js)** exposes
`window.TASK_PMR_SYNC`:

- `addSubtaskToCurrentWeek(subtask, project, bucket)` — picks the most
  recent PMR period from `userData/{uid}/pmr/_index`, loads the period
  doc, finds the week containing today (or auto-creates a Mon–Sun week
  spanning today if none matches), picks a destination subsection
  (preferring "Reading/Writing" for writing-category buckets,
  "Experimental update" otherwise), pushes an item with
  `source_subtask_id = subtask.id`. Idempotent — re-clicking on a
  subtask already in this week shows a toast saying so.
- `syncSubtaskDoneToPMR(subtaskId, isDone)` — scans the current PMR
  period's `weekly_entries[*].subsections[*].items[]` for items with a
  matching `source_subtask_id` and flips their `status` to `'done'` /
  `'in_progress'`. Writes the PMR doc if anything changed.
- `syncPMRItemDoneToSubtask(sourceSubtaskId, isDone)` — walks all of
  `userData/{uid}/buckets/{projectId}` docs looking for a subtask with
  the matching id (recursing into `children[]`), flips its `done` /
  `done_at` fields, writes that single bucket doc.

All three use direct `firebridge.db()` refs so the helper doesn't depend
on either page's lazy route registrations.

## Wiring

- **[rm/js/tasks-buckets.js](rm/js/tasks-buckets.js)** — `renderSubtaskRow` gains a
  `＋ PMR` button next to `→ task builder`. The checkbox `change` handler
  + the inline edit body's `Mark complete` / `Undo completion` buttons
  all fire `TASK_PMR_SYNC.syncSubtaskDoneToPMR(st.id, done)` after the
  existing scheduleSave + tracker-completion handlers.
- **[rm/js/pmr.js](rm/js/pmr.js)** — `renderItem` (the weekly-entry item row) gains a
  guard around `stat.addEventListener('change', …)`: if the item has a
  `source_subtask_id` AND the change crosses the done/not-done line,
  call `TASK_PMR_SYNC.syncPMRItemDoneToSubtask(item.source_subtask_id, isDone)`.
- **[rm/pages/tasks.html](rm/pages/tasks.html)** + **[rm/pages/pmr.html](rm/pages/pmr.html)** — load
  `/rm/js/task-pmr-sync.js` after `task-assign.js`.

## Edge cases handled

- **No PMR period yet** → toast asks the user to open the PMR page and
  create one.
- **Subtask already in week** → toast says so, doesn't dupe.
- **No weekly_entries in the period** → auto-create a Mon–Sun week for
  the current date.
- **No subsections in the week** → auto-create "Experimental update".
- **Subtask deleted between PMR linkage and Tasks-page completion** →
  syncPMRItemDoneToSubtask silently no-ops when the id isn't found.
- **Multiple PMR items reference the same subtask** → all get synced.

## Out of scope (V1)

- **Cross-period sync.** Completion only mirrors to the *current* PMR
  period. Items in older periods may diverge; that's fine since older
  periods are archives.
- **Admin cross-user.** All sync paths use the signed-in uid; admin
  viewing a student's PMR doesn't reach their `userData/{uid}/buckets`
  (rules block it), so the syncPMRItemDoneToSubtask path is a silent
  no-op in that case. Add-to-PMR is owner-only by definition.

## Verification

1. Open Tasks page → click `＋ PMR` on any subtask → toast confirms.
   Open PMR → the subtask appears as an item in this week's first
   matching subsection with `source_subtask_id` set.
2. Re-click `＋ PMR` on the same subtask → toast says "Already in this
   PMR week".
3. On Tasks page, check the subtask done → PMR weekly item's status
   pill flips to `done` within a beat (live-sync).
4. On PMR, change the weekly item's status from `in_progress` to `done`
   → Tasks-page checkbox ticks on the source subtask within a beat.
