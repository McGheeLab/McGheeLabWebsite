# V3.448 — S-α of Paper Builder III: submission-document section kinds + manuscript exclusion (invisible release)

> Foundation for cover letter / suggested reviewers / rebuttal living IN the section map
> ("these pages could be in the section map" — Alex) while never leaking into the
> manuscript. Deliberately invisible: no creation UI yet (S-β) — this MUST deploy first or
> `normalizeTree` would coerce the new kinds to `custom` on load (the ordering hazard).

## Changes

- **`rm/js/paper-schemas.js`** — `cover_letter`, `suggested_reviewers`, `rebuttal`
  registered in `PAPER_SECTION_KINDS` + labels ("Cover Letter", "Suggested Reviewers",
  "Response to Reviewers") + `SECTION_STYLE` (prose-only; the rebuttal allows subheadings
  for Reviewer 1/2 + point-by-point lists).
- **`rm/js/paper-export-tex.js`**
  - `SUBMISSION_DOC_KINDS` + a guard at the TOP of `resolveSectionCommand`: an unmapped
    submission kind resolves `{type:'skip'}` — manuscript templates (none map these kinds)
    exclude the sections from BOTH the export and the Document view (shared resolver);
    the S-β subdoc templates map them, so the same sections render there. Zero
    manuscript-template edits.
  - `buildBundle` gains **`opts.sectionFilter`** — one filter over the projected tree;
    citations, figureAssets, and the placeholder stash all follow the filtered tree
    automatically (the S-β subdoc builder's primitive).
  - `collectCitationKeys(tree, excludeKinds)` — the MANUSCRIPT bundle (no sectionFilter)
    excludes submission kinds from its `.bib`; subdoc bundles (filtered trees) collect
    normally, so a rebuttal's `[@cite]`s land in the rebuttal's own refs.bib.
