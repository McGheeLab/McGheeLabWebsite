# V3.391 — "Start from scratch" option when choosing a demo

## Context

After V3.390, a demo you'd already opened would *resume* your copy, and
"rebuild from scratch" only appeared once you were inside the editor (on
the tour's already-built card). Alex wants that choice **at the moment of
choosing the demo** — pick a lesson and decide right there whether to
continue your copy or start the build over on a blank canvas.

## Design

### Modal offers the choice (`rm/js/protocols.js`)
The 🎓 Demos modal rows became `div`s (were single buttons) with the
title/description on the left and action buttons on the right:
- **No copy yet** → one primary button **"▶ Start guided build"** (a
  fresh copy is born empty, so it's already from-scratch).
- **You already have a copy** → **"Open my copy"** (resume where you left
  off) *and* **"↺ Start from scratch"** (wipe the copy and walk the build
  from an empty canvas).

`_demoEditorUrl(id, d, opts)` gains `&reset=1` when `opts.reset`;
`loadDemo(d, opts)` threads `opts` through the reuse-existing path
(navigate with the reset flag) — the create path is unchanged (fresh
copies need no reset).

### Editor empties the copy on load (`rm/js/protocol-editor.js`)
Init reads `&reset=1` alongside `&tour=` → `state._resetTourGraph`
(both params stripped via `replaceState`). `renderNodesView`, right
before mounting the canvas, empties the design block once
(`attrs.transact(set nodes/edges → [])` + `markDirty`) so the canvas
comes up blank; the debounced `startTour` (V3.390) then walks the build
from an empty graph. Clearing `attrs` is a map change (not a Y.Array
delta) so it triggers no structural re-render/remount, and it's one-shot.

### CSS (`rm/css/protocol-editor.css`)
`.pr-demo-item` is now a flex row (`.pr-demo-item-main` +
`.pr-demo-item-actions` stacked buttons).

  by browser testing; the tour engine + lesson↔tour cross-checks are
