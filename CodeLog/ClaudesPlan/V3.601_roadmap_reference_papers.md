# V3.601 — Research Roadmap R2: reference papers, with a reason

## Goal

Let anyone in the lab attach a library paper to a roadmap item — from the
library table, from the paper reader, or from the roadmap itself — and record
**why that paper is appropriate there**.

Alex's ask: *"I want to add papers to this as a reference list. I want to be
able to do this from the library or from the paper reader. As I add a paper,
it should allow me to add context to why the paper is appropriate."*

The note is the point. Before this, no link type in RM carried a per-link
free-text reason: `linked_drafts`, `themes`, and `cited_in_drafts` are all bare
id arrays. The closest prior art was `labThemes/*/groups.note` (a note on a
derived research group) and `TASK_ASSIGN`'s "Why this paper, what to focus
on…" field.

## Approach

`researchFoci/{fociId}/refs/{refId}` (created in V3.600) is the store. R2 is
entirely the UI, plus the reverse index that makes the reverse question cheap.

### Three entry points, two modals

| Where | Missing half | Modal |
|---|---|---|
| Library row 🗺 / reader sidebar | the *target* | `ROADMAP_ATTACH.open({item})` — every card's roadmap expanded into checkable targets |
| Roadmap item ＋ Paper | the *paper* | `ROADMAP_ATTACH.openForTarget({fociId, target})` — a search list over the library |
| An existing pill's ✎ | neither | `ROADMAP_ATTACH.openNoteEditor()` — just relevance + note |

`open()` pre-checks what the paper is already attached to and diffs on save, so
one modal both attaches and detaches. Ticking a target reveals **its own**
relevance select and note field — per-attachment, not per-paper, because the
same paper is often relevant to two analyses for entirely different reasons.

`openForTarget()` renders the 60 most recently added papers and lets search
reach the rest rather than laying out a multi-thousand-row library on open.

### The reverse index

`meta.library.roadmaps: [fociId]`, written by `LIBRARY_LINKS.toggleRoadmap()`
(added in V3.600). Without it, "which roadmaps is this paper on?" would be a
`collectionGroup('refs')` query — a new rule, a new index, and a scan across
every card. With it, it's a field read the library row already has in hand.

`removeRef()` only clears the mirror when the detached ref was the paper's
**last** one on that card, since a paper may be attached to several analyses of
the same roadmap.

## Files

**New** — `rm/js/roadmap-attach.js` (`window.ROADMAP_ATTACH`): `open`,
`openForTarget`, `openNoteEditor`, `renderPaperChips`, `snapshotOf`.

**Modified**
- `rm/js/library-paper.js` — `_renderRoadmapEditor(item)`, modelled on
  `_renderThemeEditor`, inserted after `#lp-theme-editor` and called from
  `_attachActive`. Guards on `_item.id === item.id` so a slow read never paints
  into the sidebar of a paper the user has since tabbed away from.
- `rm/js/library.js` — 🗺 row button (with an attachment count off the reverse
  index, so no extra read per row) + its `_onTableClick` branch + the settings
  label for the new widget key.
- `rm/js/library-prefs.js` — `widgets_enabled.roadmap` (default on). The
  settings panel enumerates `DEFAULTS.widgets_enabled`, so the checkbox appears
  with no HTML edit.
- `rm/js/research.js` — `onRoadmapRefAct()` handling `roadmap-add-ref` /
  `roadmap-ref-edit` / `roadmap-ref-remove`. These touch only the refs
  subcollection, so they re-hydrate the section rather than reloading the map.
- `rm/pages/{library,library-paper,research}.html` — script tags.
  **`research.html` also gains `library-links.js`**: attaching from the roadmap
  side must write the reverse index too, or the reader would never show a chip
  for a paper attached there.
- `rm/css/style.css` — `rmap-at-*` and `rmap-chip*` (shared by all three
  pages, so not `research.css`).

## Key decisions

- **Per-target note, revealed on tick.** A shared note across several targets
  would either clobber existing per-ref notes or force an awkward "only apply
  to new ones" rule.
- **The note renders inline on the roadmap**, not as a tooltip. Reference lists
  that hide their rationale become unreadable within a month.
- **Snapshot title/authors/year onto the ref.** The roadmap renders its pills
  without loading the library, and the citation stays as it was understood when
  someone decided the paper belonged there.
- **Deterministic `refId`** means re-attaching updates the note instead of
  creating a second row — the modal is idempotent by construction.
