# V3.57 — Page consolidation Tier 1: orphan deletions

## Goal

Start of a 4-tier sweep (V3.57–V3.62) reducing the RM page count from
**51 → 38**. Tier 1 deletes pages whose renderers were already
orphaned or superseded — pure cleanup, no user-visible feature loss.

## Background

After V3.40–V3.56 migrated 12 lab apps + dashboard/admin into RM, the
nav accumulated 51 pages, several of them duplicates or legacy:

- [rm/pages/funding.html](../../rm/pages/funding.html) was already a
  `<meta refresh>` redirect to grants.html (the V3.45 migration), but
  the renderer [rm/js/funding.js](../../rm/js/funding.js) (269 LOC)
  was left behind unreferenced.
- [rm/pages/purchase-requests.html](../../rm/pages/purchase-requests.html)
  + [rm/js/purchase-requests.js](../../rm/js/purchase-requests.js)
  (256 LOC) was the original student purchase-request review UI. V3.44
  built procurement.js (844 LOC) which provides the full request →
  approve → order → receive → place lifecycle. The V3.44 plan doc
  flagged purchase-requests as legacy but didn't delete it.

## Changes

### Deleted

- **`rm/js/funding.js`** — orphan, unreferenced anywhere. Verified
  with `grep -rn "funding\.js" rm/ --include="*.js" --include="*.html"`
  showing only the file itself in the comment header. The data routes
  (`funding/proposals.json`, `funding/awards.json`,
  `funding/accounts.json`) stay registered in
  [rm/js/api-routes.js](../../rm/js/api-routes.js) — they're consumed
  by [rm/js/grants.js](../../rm/js/grants.js) and
  [rm/js/dashboard.js](../../rm/js/dashboard.js).
- **`rm/js/purchase-requests.js`** — superseded by procurement.js.
  Wrote against legacy `purchaseRequests` Firestore collection;
  procurement.js writes to `procurementTickets`. Different collections
  by design — V3.44 was a greenfield rewrite, not a rename.

### Changed

- **`rm/pages/purchase-requests.html`** — replaced with a
  `<meta refresh>` redirect to `/rm/pages/procurement.html`. Bookmarks
  survive. Pattern matches funding.html.
- **`rm/pages/funding.html`** — fixed the broken redirect URL
  (`/pages/grants.html` was missing the `/rm/` prefix; only worked
  because godaddy serves a 404 page that some clients tolerate).
  Drive-by fix.
- **`rm/js/nav.js`** — removed the "Purchase Requests" entry from the
  Lab Admin group (was line 64 between "Receipts & Budget" and
  "Grant Accounts"). Procurement is the single entry point now.
- **`sw.js`** — `CACHE_VERSION` 31 → 32 to evict stale references.

### Untouched

- **`firestore.rules`** — the legacy `purchaseRequests` rule block
  stays in place. No active writers, but data may exist; preserving
  read access is harmless.
- **`functions/`** — no Cloud Function references either name.

   `mcgheelab-shell-v32`.

## Net impact

- **51 → 49 user-facing pages** (purchase-requests is now a redirect;
  funding.html was already a redirect).
- **~525 LOC of unused JS removed** (269 + 256).
- **No data migration, no rules changes, no functions deploy.** Pure
  frontend file cleanup.
