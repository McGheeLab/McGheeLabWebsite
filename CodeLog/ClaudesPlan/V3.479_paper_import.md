# V3.479 — Bidirectional import/export E2: import a paper bundle

> Second release. Import a `.paperbundle.zip` (from E1) as a NEW paper — full tree
> (with preserved ids), equations, unplaced libraries, config, and figure images.
> Comments round-trip lands in E3 (a Cloud Function). One scoped rules change.

## List page (rm/js/paper-builder.js + rm/pages/paper-builder.html)

- **"📥 Import paper"** button + hidden file input in the list-mode header; JSZip CDN
  tag added (was only on the export page).
- `importBundleFile(file)`: `JSZip.loadAsync` → parse `paper.json` (+ `comments.json` +
  `assets/*` as base64) → allocate a **fresh unique slug** (`_freshSlug` = `slugify`
  + dedupe against `papers[]`) → stash `{manifest, comments, assets}` in IndexedDB
  (`LOCAL_CACHE.scope('paperImport::'+slug)`) → create the `projects/{slug}` row as a
  **direct single-doc write** (`firebridge.db().collection('projects').doc(slug).set`,
  with `type:'paper'` + `lead_author_uid` + `import_seed` + `import_source:'upload'`) —
  NOT the whole-array `api.save`, which would rewrite other papers' docs and fail the
  owner-scoped rule → navigate to the editor.

## Editor hydration (rm/js/paper-editor.js)

`hydrateFromImport` generalized: `_loadImportPackage` sources the bundle from IndexedDB
(uploads) or the fixed server path (built-in grant bundles), then `_hydrateBundle`:
1. **Tree** — `appendSectionFromTree` per section **passing `id` through** (the fix — the
   V3.472 hydrate dropped it) plus all section metadata (status/completed_*/revision_*/
   uploaded_file); block ids + deep `{__ytype}` attrs already round-trip via
   `appendBlockFromTree`. Preserving ids is what lets E3's comments re-bind.
2. **Equation library** — appended to `paperMap.equation_library` (id/name/latex/type).
3. **Unplaced figure/table libraries** — appended via `appendBlockFromTree`.
   (1–3 in one `seed-import` transact.)
4. **Config** — `bundle.config` written to `paperExports/{slug}` (merge), after figure
   remap so `graphicalAbstract` points fresh; best-effort (guarded).
5. **Figures** — `_reuploadImportedAssets`: base64→Blob→`PAPER_FIGURES.uploadImage`
   (dedup by hash) building `{oldStoragePath→new}`, then `_patchStoragePointers`
   rewrites every block/composed-panel/section-attachment pointer in a transact.
   No-op for the caption-only built-in bundle.
6. Clears the IndexedDB stash. Tolerant of the older/minimal bundle shape (missing
   fields skipped), so the built-in GELS import still works.
   (Comments hook `_restoreImportedComments` is E3 — `typeof`-guarded, skipped now.)

## Rules (firestore.rules) — REQUIRES DEPLOY

`projects/{projectId}` write relaxed from admin-only to also allow a lab member to
create/update/delete their **own** paper row, **scoped to the `type=='paper'`
discriminator** (`request.resource.data.type == 'paper' && lead_author_uid ==
request.auth.uid`) so courses/infrastructure/tools stay admin-only. Dry-run compiled
OK. `paperExports` (contributor) + `yjs_updates` (admin-or-author) already permit the
owner; admins bypass the async `authorUids` materialization, non-admin owners hydrate
lazily on first open (after the author-sync function has run).

Known v1 limitation: a non-admin owner's later title-sync uses the whole-array
`api.save` and will fail (routing owner metadata writes to single-doc is a follow-up);
admin (Alex) is unaffected.
