# V3.141 — Protocols Builder: admin override for author + creation date

## Goal

V3.119 made `author_uid` + `author_name` immutable after creation and
`created_at` set-once. Useful for the audit trail in normal use, but
brittle for two real cases:

1. **Imported historical protocols** (V3.139) credit the *importer*,
   not the original author. Admin should be able to reassign credit
   to the actual author after upload.
2. **Author handoff** when a lab member leaves and the admin wants
   to consolidate credit / authorship cleanly.

The fix: an admin-only edit affordance that lets admins (and only
admins) override `author_uid`, `author_name`, and `created_at` on any
protocol. Non-admins see the byline as before with no edit button.

## Approach

### UI

- A small `✏️` icon button appears at the right end of the
  `Created by [Name] · YYYY-MM-DD · vN` byline in the editor topbar,
  rendered conditionally on `firebridge.isAdmin()`.
- Clicking opens a modal with: a roster dropdown (auto-loaded from
  the existing `lab/users.json` route, sorted by display name with
  guests filtered out), a text override for the cached `author_name`
  (auto-filled from the picker), and a `<input type="date">` for
  `created_at`.
- Save → `firestore.update` on `protocols/{id}` with
  `{author_uid, author_name, created_at, updated_at}`; local
  `state.doc` patch + `renderByline()` re-render.

### No rule changes

The existing `firestore.rules` block:

```
allow update: if request.auth != null && isLabMember()
              && (request.auth.uid == resource.data.ownerUid || isAdmin());
```

…already permits admin updates of any field on any protocol doc, so
no rules deploy is required. The "immutability" of `author_uid` /
`created_at` was an application-layer convention enforced only in
`protocolEmptyDoc`. This change layers a deliberate admin-only escape
hatch on top.

### No schema migration

`author_uid`, `author_name`, `created_at` already exist on every
protocol doc since V3.113 + V3.119. No new fields, no new indexes.

## Acceptance test

1. Sign in as admin. Open any protocol. Confirm a small `✏️` button
   appears at the end of the "Created by …" byline.
2. Click → modal opens. Roster dropdown populates with all non-guest
   lab members; current author is preselected. Name + date are
   prefilled from the doc.
3. Pick a different lab member → display name auto-fills from the
   picker but is still text-editable.
4. Change the creation date to an earlier YYYY-MM-DD. Click Save.
5. Toast confirms; byline updates immediately to "Created by [New
   Name] · [new date]". Reload — change persists.
6. From a notebook entry that references this protocol, the chip
   tooltip shows the new author name (V3.116 chip reads
   `author_name` cached on the protocol doc).
7. Sign in as a non-admin lab member. Open the same protocol. The
   `✏️` button is NOT rendered. Trying to call
   `firebridge.db().collection('protocols').doc(id).update({...})`
   directly from console succeeds for ownerUid match (existing
   behavior) but the new modal is gated behind `firebridge.isAdmin()`
   in `openAuthDateModal` AND `saveAuthDate` for defense-in-depth.

If all 7 steps pass, V3.141 is done.

## Out of scope

- **Provenance log** — we don't record "admin X reassigned author at
  Y date". The Firestore audit log captures the write at the
  Firestore level if the admin needs forensics. A future phase can
  add an explicit `author_change_log: []` array on the doc if the
  team wants it visible in the UI.
- **Multiple authors / co-authors UI** — the existing `authorUids[]`
  array is still set at create-time only. This phase only edits the
  primary `author_uid` + cached `author_name`.
