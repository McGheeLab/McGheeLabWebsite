# V3.650 — Table builder: edge ＋/− controls, live re-render, drag-to-merge

## The three complaints (Alex, 2026-08-20)

1. *"there is no way to delete rows or columns after they are made. instead of
   the +row, +col there should be a +- that comes up at the edge of any
   border."*
2. *"the table does not update responsively, i have to click off of it to see
   any updates."*
3. *"i cant click drag multiple cells to do merge. once multiple cells are
   selected the merge option should arise, if a merged cell is clicked on the
   unmerge should arise."*

All three live in the panel-side table editor —
`_buildTableEditorBody()` in [rm/js/paper-equations.js](../../rm/js/paper-equations.js),
reached from the **Tables** page (the doc-side block in
`paper-blocks.js` has been a read-only preview since V3.127).

## Root causes

**(1) Append-only structure.** The only structural controls were `+ Row` /
`+ Col` in the style bar, and both only *appended*: they wrote
`cells[rows-c]` and bumped `rows`/`cols`. There was no delete and no insert
in the middle, because doing either means **re-keying** the `cells` Y.Map
(`"<r>-<c>"` string keys) and simultaneously shifting `merges_json`, `align`
and `widths_json`, which nothing did.

**(2) Nothing re-rendered until blur.** Every structural write landed in
`attrs`, which fires the `observeDeep` in `_installSubscriptions` ->
`_refreshPanel` -> `_refreshTablesSection` -> **`_deferWhileEditing`
(V3.647)**, which *parks* the refresh whenever focus is inside the tables
list. Clicking `+ Row` moves focus to that button — which is inside the
list — so the refresh parked itself and only ran on the next `focusout`.
That is exactly "I have to click off of it to see any updates". V3.647 was
right to park a **whole-list** rebuild (it fixed one-letter-at-a-time typing);
the mistake was having no cheaper path for a structural change.

**(3) Merge was shift-click + two always-on buttons.** `mousedown` set
`_tblSel`; only `shiftKey` extended it. `Merge` / `Unmerge` sat in the
style bar permanently and `alert()`ed when the selection was wrong
(`'Select cells first...'`, `'Select more than one cell to merge.'`,
`'The selection overlaps an existing merge — unmerge it first.'`) — three
browser popups on the exact surface Alex has already ruled out
(see `feedback_no_browser_input_popups`).

## Approach

### Structural ops that actually re-key
New module-level helpers in `paper-equations.js`:

- `_tblReadGrid(attrs, rows, cols)` -> 2-D array of **strings**. Cell text is
  plain source (`renderParagraphHtml` parses the markdown-ish syntax), and a
  `Y.Text` can only be integrated once — it cannot be moved to another key —
  so re-keying clones by string.
- `_tblWriteGrid(blk, attrs, grid, merges, alignArr, widthsArr, origin)` —
  one transact that rewrites `rows`, `cols`, a fresh `cells` Y.Map, plus
  `merges_json` / `align` / `widths_json`.
- `_tblShiftMerges(merges, axis, op, at)` — the piece that did not exist.
  On insert: anchors at/after the line move by 1; a merge that *straddles*
  the new line grows its span by 1. On delete: anchors after the line move
  back by 1; the anchor line itself keeps the anchor and loses a span;
  straddling merges lose a span; anything that decays to 1x1 stops being a
  merge.
- `_tblStructOp(blk, attrs, axis, op, at)` — splices the grid, the align
  string and the widths array, then writes.

### +/- on the borders
The grid is rendered as a table with a **gutter row and gutter column**
rather than an overlay, so the controls inherit the browser's own column
geometry — no measurement code, and merged cells stay aligned:

```
+------+-----------+-----------+
|      |  - col 0  |  - col 1  |   <- gutter row (one head per column)
+------+-----------+-----------+
| - r0 |  cell     |  cell     |
```

Each head cell is `position:relative`, so a `+` at `left:-9px` sits exactly
**on** the border between two columns, and the last column carries a second
`+` at `right:-9px` for the outer edge. Same for rows, top/bottom. They fade
in when the grid is hovered. `-` deletes the band; when the band has text it
**arms first** (turns into a checkmark, band goes red, 4 s timeout) instead
of a `confirm()`.

### Live re-render
`_watchTableAttrs()` registers a **shallow** `attrs.observe` per table
(registry keyed by blockId, previous handler unobserved, self-unregisters
once `rootEl` leaves the DOM). It re-runs `_buildTableEditorBody` only when a
key in `TBL_STRUCT_KEYS` changed (`rows`, `cols`, `cells`, `merges_json`,
`align`, `widths_json`, `header_row`, `booktabs`). Typing in a cell mutates a
`Y.Text` *inside* `attrs.cells`, which a shallow observe never sees — so
V3.647's caret fix is untouched and structural changes now paint
immediately. A `_tblRebuilding` re-entrancy flag stops the defensive
`attrs.set('caption', ...)` migration from looping.

### Drag-to-select, contextual merge
- `mousedown` anchors the selection (no `preventDefault`, so the caret still
  lands); `mouseenter` on a *different* cell while the button is down extends
  it, clears the DOM text selection and puts `pe-tbl-dragging` on the table
  (`user-select:none`) so the browser does not paint a cross-cell text drag.
  Shift-click still extends.
- The rect is expanded until it fully contains every merge it touches, so
  dragging across half a merged cell still yields a legal target.
- A floating `.pe-tbl-actbar` appears **over the selection** and carries only
  what applies: `Merge` when the rect is bigger than one cell, `Unmerge`
  when it contains a merge anchor. Merging over existing merges now absorbs
  them instead of refusing. Zero alerts.
- Escape, or a mousedown outside any grid, clears the selection.

### Also
- `header_row` now renders bold in the editor grid (it was invisible before).
- The grid gets its own horizontal scroller so a wide table stops stretching
  the panel.
- `+ Row` / `+ Col` are removed from the **doc-side** read-only preview
  toolbar in `paper-blocks.js` — structural edits on a surface where you
  cannot type the content are the thing Alex was objecting to; that toolbar
  keeps `Edit on Tables page`.
