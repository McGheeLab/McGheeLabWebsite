# V3.377 — GELS graph wiring fix + interactive Plate planner

## Goal

User report on the imported GELS protocol: (1) "multiple variables are
not connected"; (2) "the math wasn't correct … prep excess does
nothing". Plus a feature: in the final document the user should be able
to **pick the experiments they lay out and how many plates**, and assign
the node-workflow's experiments to plates **manually or programmatically**.

## Root cause (bugs)

The node graph modeled the per-condition math but:
- `nF`/`Fvol`/`Ivol`/`cellSusp` referenced the scalar inputs
  (`phi`/`cov`/`Vtot`/`AF`/`stock`) **by name only** — they resolved
  globally so the numbers were right, but with no wires the node view
  read as "not connected."
- `reps` (wells/condition) and `excess` (prep excess) fed **nothing** —
  they only matter for the master-batch prep totals (per-well × wells ×
  excess), which the doc view never computed. Hence "prep excess does
  nothing."

## Changes

### Fix 1 — connect the scalars (`Data/protocols/gels-granule-coating.protocol.json`)
Added scope-safe math edges from the scalar inputs into their equations:
`phi`/`cov`/`Vtot`/`AF` → `nF`; `Vtot` → `Fvol`/`Ivol`; `stock` →
`cellSusp`; `phi`/`cov`/`AF` → `loadS`/`loadM`/`loadL`. Only *scalar*
sources are wired (wiring an item-scoped source like the ordered set
into a scalar `load*` equation would wrongly make it per-item), so the
loading cards stay scalar and the list stays 30 rows (harness-verified).

### Fix 2 + feature — the Plate planner (`rm/js/protocol-widgets.js`)
New `renderPlatePlanner(ctx, b)` — an interactive layout surface that
composes the existing `renderGridAssignment` + `renderPrepTotals`:
- **Pick experiments** — the palette lists every condition the node
  workflow produced; you assign the ones you want.
- **How many plates** — each grid is a plate; "+ Add grid" adds one,
  "× grid" removes one, per-plate rows/cols editable.
- **Assign manually** — click a palette experiment, then click wells.
- **Assign programmatically** — an **Auto-fill** button lays every
  experiment across the plates, replicated ×`reps` (wells/condition),
  and warns if they overflow the plates. This is the "via the nodes"
  route: the replicate count comes from the graph's `reps` input.
- **Master batch** — live prep totals grouped by pool (`poolBy`),
  summing the per-item quantities × well count × **`excess`** (the
  `factorVar`). This is where prep excess finally does something.

State lives in `ctx.builderState[blockId]` so a notebook run persists the
layout; the read-only doc view is ephemeral. Activated by a `layoutMap`
block with `attrs.assign === true` (+ `keyFields`, `replicateVar`,
`factorVar`, `poolBy`, `quantityFields`); a plain `layoutMap` still
renders the static plate. The GELS demo's plate block now sets these.

Wired into both mount points: `protocol-doc.js` `renderDocument` and
`lab-notebook.js` `mountProtocolRunWidgets` dispatch `layoutMap` to the
planner when `assign` is set.

### CSS (`rm/css/protocol-doc.css`)
`.prd-planner` controls/note/warn; the assignment grids get the dark
plate backing (`#20303F`) so the white-on-dark wells stay legible
outside the static map wrapper.

## Verification
- Harness: GELS compiles clean, `loadS/M/L` still **scalar**
  (26154/12554/7133), list still **30 rows**; a simulated auto-fill →
  `aggregatePrep` groups into Small/Medium/Large pools and scales totals
  ×1.2 (excess). `node --check` all files; CSS balanced; all suites green.
- Adversarial review workflow found 5 confirmed defects — all fixed:
  (critical) notebook double-mounted a legacy grid so a frozen run
  snapshotted the wrong empty grid → `_computeRunTotals`/freeze now read
  the planner's `run.graph_state[blockId]` and the legacy block is
  skipped when a planner exists; (major) manual assignment didn't repaint
  totals → `onAssignChange` now `_refreshAll`s; (major) shrinking a plate
  left orphaned wells counted by `slotCounts` → guarded by grid size;
  (minor) all-items-removed showed an empty totals table → hint instead;
  (minor) GELS pooled `Ivol` by functional size → dropped from
  quantityFields.
- Pending (browser): import → doc view → node view shows the scalars
  wired; Plate planner: pick + "+ Add grid" + Auto-fill + watch master
  batch scale when excess changes.
