# V3.421 — True per-column flow in the Document view (Layout Mode)

> Alex's test feedback (2 of 3 items): "text flow around figures is still
> wrong. (1) text should go all the way to the figure boundary. (2) text is
> currently not recognizing the two column nature of the text fields — even
> though the figure is in the left column, the text on the right column still
> stops at the same place as the left if it encounters a figure." (Item 3 —
> section-boundary handles + move — is the follow-on release V3.422.)

## Root cause

Both symptoms are the **same** limitation. The packer's page model was:

```
page = [ top float BAND ] → [ CSS column-count:2 text ] → [ bottom float BAND ]
```

- Text was one `column-count:2` element that the browser **auto-balances** to a
  single height — the two columns always end level.
- Every float (even a single-column figure) claimed a **full-width horizontal
  band** stacked above/below that text block.

So a column-width figure at a page's foot reserved a full-width strip: the
balanced text ended above it in **both** columns (symptom 2), and because the
balance point sat above the reserved band there was a wide gap before the
figure (symptom 1). This is not how LaTeX two-column floats work — a
single-column `figure` sits in **one** column's area and the other column
flows past it independently.

## Approach — a COLGRID segment (constraint-based, LaTeX-honest)

Replace the 2-col text run with a **colgrid**: two independent columns, each an
ordered stack of flow nodes with an optional single-column float reserved at its
top and/or bottom. Text fills **column 0 to the page's remaining height, then
column 1** (LaTeX `twocolumn` fill order), splitting the crossing paragraph at a
line boundary (reusing V3.419's `_splitColItem`). A single-column float reserves
a slot in a column; the other column is untouched.

- **1-column layouts: byte-identical.** The old `run` → `{type:'cols'}` path is
  untouched; only `cols === 2` takes the new grid path.
- **Spanning floats stay banded.** `figure*`/`table*` (span `page`) and every
  1-col float keep their full-width top/bottom bands — they genuinely span.
- **Constraint-based, per Alex's earlier choice.** No absolute x/y; the levers
  are still anchor / span / width / height / spacing. Fill order and in-column
  float placement are derived, not pinned.

## What changed — `rm/js/paper-doc-view.js`

**Packer (`_packPages`)**
- Page gains `grid` (the open colgrid) beside `run` (the 1-col run).
- New helpers: `colObj`/`newGrid`/`ensureGrid`, `fTopH`/`fBotH`/`colContentH`,
  `gridProjH`/`gridIsEmpty`/`gridFloatArea`, `colTextCap`.
- `openRunH` → **`openFlowH`** (projects the 1-col run OR the 2-col grid so a
  mid-page float reserves the right space).
- `closeRun` now dispatches: 2-col → **`closeGrid(fillToBottom)`**; 1-col →
  the old accounting. `closeGrid(true)` (a page break forced the close) claims
  the page's remaining height so columns fill and `[b]` floats bottom-anchor;
  `closeGrid(false)` (spanning item / end-of-doc) uses natural height.
- **`addColItem(item)`** fills col 0 then col 1, splits a crossing paragraph at
  the column boundary and returns `{split: partB}` (spliced back into the work
  queue), and breaks the page when both columns are full. An empty column always
  accepts (guarantees progress).
- **`tryPlaceColFloat(f)`** reserves a single-column float's top/bottom slot in
  column 0 then 1 (so two `[t]` floats pair across the two column tops); honors
  the `FLOAT_MAX_FRAC` starve budget (locked/empty-page force through); defers to
  the pending queue → next page otherwise.
- **`placeFloat`** routes on drain: `cols === 2 && span === 'column'` →
  `tryPlaceColFloat`, else the banded `tryPlaceFloat`.
- **`newPage()`** now closes the outgoing page's open flow first — the
  trailing-float drain opens grids on fresh pages and relies on this (plus a
  final `closeRun()` after the drain loop) to emit them as segments.
- Full segments now carry `height` (so `_recordRects` can walk segment Y).

**Rects (`_recordRects`)** — walks the text region's segments and records each
in-column float at its true Y (column top for `[t]`, column foot for `[b]`) into
the same `floats` array the overlay colors and `_pageIndexOfFloat` scans.

**Mount (`_mountSheets` + new `_mountColGrid`/`_mountColFloat`)** — a colgrid
segment renders as a flex row of two `.pdv-col` flex-columns; each stacks its
`.pdv-col-flow` nodes and, when present, a `.pdv-col-float` at top (margin-bottom
gap) and/or bottom (`margin-top:auto` → column foot). The strip's `min-height`
lets bottom floats align to the text-region foot.

**Drops** — `_resolveDropTarget` reads `slotEl.dataset.floatRegion` (stamped on
in-column float slots) so a float dragged onto an in-column figure resolves the
right region; band floats still fall back to which band they sit in. In-column
figures keep `.pdv-figure[data-block-id]` and `.pdv-float-slot[data-block-id]`,
so the layout popover, area-boundary resize (V3.420), and float↔float reorder
all work unchanged.

## What changed — `rm/css/paper-doc-view.css`

`.pdv-cols-strip` (flex row, `align-items:stretch`), `.pdv-col`
(flex column), `.pdv-col-flow`, `.pdv-col-float`, `.pdv-col-float-bottom`
(`margin-top:auto`). Removed the `column-count` styling from the mount (colgrid
supersedes it for 2-col; 1-col `.pdv-cols` stays a plain stack).
