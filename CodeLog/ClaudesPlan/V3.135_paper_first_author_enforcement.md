# V3.135 — First-author enforcement on papers (Phase 2)

## Why

V3.133 shipped the data + UI for marking 1-2 personnel as first authors
on a paper. V3.135 wires the enforcement. User-decided rules:

| Action | Allowed by |
|---|---|
| (a) Edit paper metadata (title, status, journal, etc.) | first author OR admin |
| (b) Add / remove personnel on the paper                | first author OR admin |
| (c) Add / remove project Members (V3.126 access list)  | admin only |
| (d) Delete the paper                                   | admin only |
| (e) Set / unset other first authors                    | admin only (status quo) |

(c) is already admin-only via the existing `projects/{id}` rule. (d) is
the only behavioral change at the rule level for items — item deletes
were lab-member-allowed pre-V3.135. (a)+(b) both write to the same
`items/{id}` doc, so we gate at the doc level for paper items. (e)
keeps the V3.133 admin-gate but additionally requires the Firestore
write to preserve `first_author_uids` byte-for-byte for any non-admin
update — that way a first author can update other paper fields but
cannot self-promote a co-author or remove a co-first-author.

## Schema

No schema changes. `first_author_uids: string[]` (V3.133) is the only
new field; this version reads it.

## Helpers

### Client-side ([rm/js/projects.js](../../rm/js/projects.js))

```js
function _myUid() {
  return (typeof firebridge !== 'undefined' && firebridge.getUser)
    ? (firebridge.getUser() || {}).uid
    : null;
}

function _isAdminUser() {
  return typeof firebridge !== 'undefined' && firebridge.isAdmin && firebridge.isAdmin();
}

// Whether the current user can edit a given item's metadata + personnel.
// Non-paper items: any lab member (status quo). Paper items: admin OR
// uid in first_author_uids.
function _canEditPaper(item) {
  if (!item) return false;
  if (_isAdminUser()) return true;
  if (item.type !== 'paper') return true;          // non-papers unchanged
  var uid = _myUid();
  return !!uid && Array.isArray(item.first_author_uids) && item.first_author_uids.indexOf(uid) !== -1;
}

// Whether the current user can delete a given item.
function _canDeleteItem(item) {
  // V3.135 — paper deletes are admin-only. Non-paper items follow the
  // existing lab-member rule. The Firestore rule below enforces the
  // server side; this is the matching client-side gate.
  if (!item) return false;
  if (_isAdminUser()) return true;
  return item.type !== 'paper';
}
```

### Firestore ([firestore.rules](../../firestore.rules))

New helper alongside the existing top-of-file helpers:

```
function isFirstAuthor(itemId) {
  return request.auth != null &&
    exists(/databases/$(database)/documents/items/$(itemId)) &&
    get(/databases/$(database)/documents/items/$(itemId)).data.first_author_uids != null &&
    request.auth.uid in get(/databases/$(database)/documents/items/$(itemId)).data.first_author_uids;
}
```

Updated `match /items/{itemId}`:

```
match /items/{itemId} {
  allow read: if isLabMember()
    || (resource.data.meta != null
        && resource.data.meta.library != null
        && resource.data.meta.library.public == true);

  // Create: any lab member (no resource.data yet, so per-paper FA gate doesn't apply).
  allow create: if isLabMember();

  // Update:
  //   - admins always pass
  //   - non-paper items: any lab member (status quo)
  //   - paper items: a first author may update, BUT the
  //     first_author_uids field itself must be unchanged (preserves
  //     the V3.133 admin-only ownership of who-the-first-authors-are).
  allow update: if isAdmin()
    || (resource.data.type != 'paper' && isLabMember())
    || (resource.data.type == 'paper'
        && isFirstAuthor(itemId)
        && request.resource.data.first_author_uids == resource.data.first_author_uids);

  // Delete: admin only (was lab-member; the V3.135 user decision is admin-only).
  allow delete: if isAdmin();
}
```

## UI gates

- `renderHeroActions(item)` — Edit button hidden when `!_canEditPaper(item)`; Delete button hidden when `!_canDeleteItem(item)`.
- `renderPersonnelSection(item)` — `+ Add` button hidden, remove `×` glyph hidden, when `!_canEditPaper(item)`. Star toggle stays admin-only (V3.133 behavior; matches rule (e)).

## Handler-time guards

Each gate also checks at the entry to the handler (defense in depth in case a stale render leaves a clickable button behind).

```js
window.editItemById = function (itemId) {
  var item = _allItems.find(...);
  if (!_canEditPaper(item)) { alert('You don't have permission to edit this paper.'); return; }
  // ... existing logic
};
```

Same shape for `deleteItemById`, `addPersonnel`, `removePersonnel`.

## Tightening `toggleFirstAuthor`

V3.133's handler accepts any pid that's in `personnel[]`. For the
rights gate to actually work, the pid must be a Firebase UID (the
Firestore rule compares `request.auth.uid` against the array). V3.135
adds a check: when adding a first-author, the pid must resolve to a
roster entry with `_firebaseUid: true`. If it doesn't, alert and
abort with a hint pointing the admin at the V3.126 Members workflow.

## Out of scope

- A roster-side UI to surface "I'm a first author on N papers" — would
  be a useful consumer of the new rule but isn't blocking enforcement.
- Cross-page enforcement (`/rm/pages/library.html`, the paper builder
  at `/rm/pages/paper-builder.html`) — they edit different docs, and
  V3.135 is scoped to the projects page. Flag for V3.135+ if needed.
