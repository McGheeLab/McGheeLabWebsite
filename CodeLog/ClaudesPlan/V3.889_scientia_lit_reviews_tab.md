# V3.889 — Scientia: a Lit reviews tab (a canvas per topic, linked to any number of projects)

**Ask (Alex, 2026-10-24):** "Add a Scientia tab for literature reviews, this is a tab specifically for researching
various topics. these are a canvas of notes that can be linked to one or more projects. The first lit review to add is
Research/ERK_mechanochemical_waves_litreview.md"

Builds on [V3.888](V3.888_litreview_to_scientia_note.md) (the ERK review built as a Scientia note by
`scripts/litreview/build-note.js`, not yet published) and follows the V3.885 / V3.886 rule: simple up front, details on
the thing once it is in.

## What a review is

One of Gabe's notes (a canvas) of type `literature`, outside any project (`projectId: null`, `scope: 'global'`), carrying
a lab-layer field:

```
review: { topic: 'the question it asks', projectIds: ['rm-f-…', 'p_…', …] }
```

His desktop sees an ordinary literature note (unknown fields ride along, as `share` / `quick` / `tpl` do). A per-paper
*Reading:* note (his reader's, `libId`) has no `review` and stays what it is.

## Web Scientia (`rm/scientia/lab-mode.js` §13)

- **Tab** *Lit reviews* right after Portfolio (`TABS`, `VIEWS.litreviews`): a page of review cards (title, topic,
  *N papers · N quotes · N notes* from the canvas: `pdf` components, quote components, the rest), the linked
  projects as pills, a project filter (only projects some review is linked to), **+ New review**.
- **+ New review** makes the canvas at once (`newReview`: `M.createDoc` type literature, no template) and opens it.
  Its first block (`headFields` → `reviewFields`) holds Title, **Topic**, **Projects** (chips with ×, *+ Link a
  project…* grouped Assigned / Your projects, any number) and *Seen by* once an RM project is linked. No type or
  template to pick.
- **Where it shows**: every linked project's Portfolio region (a *Lit reviews* column; the header counts them), every
  linked project's page (*Literature reviews*), never among Quick notes (`GENERAL.docs` wrapped). Open, the review
  lights the Lit reviews tab (`App.renderTabs` wrapped: `TABOF.doc`), and its meta line reads *Lit review for …*
  instead of Gabe's *General · not tied to a project*.
- Linking / unlinking an RM project asks the hub for RM's notes list (the V3.880 `noteSig` kick now includes the
  review's project ids).

## Hub (`functions/scientia-hub-core.js`, `scientia-hub.js`)

`noteProjects(doc, projects)` = the note's own project + (a review) every linked project, RM ones only;
`noteLink({ …, projects })` lists a review under all their `rmId`s (+ grant drafts), `projectName` joined, plus
`review: true` and `topic`; a plain note is unchanged (only its own project). The shared-preview read uses
`noteProjects`. RM's research / projects pages label it *Lit review* (`rm/js/scientia-notes.js`).
