# V3.854 — ✓ on every card: report a result to My Week from the canvas

Alex, 2026-10-23: *"when a user places something into the canvas or figureboard
there should be a little check mark on the top left of an item or region that
allows the user to quick report results to a myweek item. this way we have the
ability to report from both surfaces."*

## Goal

V3.853 made every My Week step end in a result that points at a specific card.
That flow starts on My Week. This closes the other direction: standing on the
notebook canvas or a paper's figure board with the plot in front of you, tap
the ✓ at the card's top-left, pick the step it answers, done — the same
`outcome.links[]` entry lands on the step, the step is marked done, and the
card shows a filled ✓ so you can see what has been reported.

## Approach

1. **Engine (`whiteboard.js`)** — `mountBoardView(..., { report: { onReport(item,
   btn, api) } })` makes `reportBtnHTML` render a `button.wb-report[data-wb-report]`
   as the FIRST child of every widget header (`.wb-wh`) and region header
   (`.wb-rh`). Filled (`.wb-report-on`, `aria-pressed`) when `item.myweek[]`
   has entries; its tooltip names the steps. `wireReportBtn` stops
   `pointerdown` propagation (no drag, no mobile tap-sheet) and calls the
   host's `onReport` on click. `itemSig` carries the linked ids so a card
   re-renders when a link lands. Instances (`regionref`) get no ✓ — they are
   mirrors of a card elsewhere.
2. **`rm/js/myweek-report.js` (`window.MYWEEK_REPORT`)** — the picker, an
   anchored `.cw-pop` like the ＋ Insert menu: the card's name and thumbnail,
   then the user's steps from four weeks back through this week
   (`DAY_DISTRIBUTE.listRange`), newest first, in two groups — "Needs a
   result" (no outcome) and "Already has an outcome — add this card"; a
   "Find a step…" box past six rows; rows already linked to this card are
   disabled. Picking one calls `DAY_DISTRIBUTE.saveOutcome(step, {kind:
   'result', …existing, links: existing − this card + this card}, {closeAs:
   'done'})` — the V3.853 writer, so status, cascade and activity signal
   behave exactly as from My Week — then `onReported(step, link)` and a
   toast ("… — marked done ✓" / "— added to its result ✓").
   `describeCard(item)` gives the link's title / thumb / kind from the
   engine item (title · caption · note text · widget summary · kind).
3. **Hosts** — `notebook-canvas.js` and `figure-board-canvas.js` pass
   `report`, build the card (`notebook_item` with entryId / `figure_board_item`
   with paperId, url with `&item=<id>` so the link lands on the card,
   V3.853 `focusItem`), and on `onReported` write `myweek: [{itemId, title,
   date}]` on the card via `inst.updateItem`. The ⋯ menu (and so the phone's
   card sheet) gains "Report as a My Week result…".
4. **Pages** load `day-distribute.js` + `myweek-report.js` (figure-board also
   `activity-signals.js`); day-distribute's other helpers are guarded.

## Key decisions

- **One writer.** The canvas never writes an outcome itself; it calls the
  same `saveOutcome` My Week uses, so a step reported from the canvas is
  indistinguishable from one reported on My Week (ledger, health, cascade).
- **The ✓ is a report button, not a "done" toggle** — the card's state is
  "linked to N steps", shown filled, never a checkbox that could be unticked
  by accident. Unlinking is done on My Week (edit the outcome).
- **Steps that already have an outcome are offered too** (second plot for
  the same step), under their own heading, so the default list stays the
  steps that need a result.

## Verify

- Notebook: every card and region shows a hollow ✓ at the top-left; an
  instance does not. Tap → picker; pick a planned step → toast, the step is
  done on My Week with the card as its result (the My Week chip 📓 and the
  PMR ledger link open the card, centred and pulsing), the ✓ is filled and
  its tooltip names the step.
- Figure board: same with 📊; a co-author reports to their OWN My Week.
- Phone: the ✓ tap opens the picker and not the card sheet; a drag from the
  ✓ does not move the card.
- Harness: `v3854-canvas-report-harness.html` (desktop) and `?mobile=1`.
