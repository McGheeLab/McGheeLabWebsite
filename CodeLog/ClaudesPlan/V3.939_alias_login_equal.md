# V3.939 — arizona.edu is an equal way into the PI's account

> **Status: BUILT 2026-10-29.** Alex, after signing in with mcgheealex@arizona.edu now that `aliasSignIn` is live:
> *"i land with Alexander McGhee · mcgheealex@gmail.com · admin. I should be able to also sign in as
> mcgheealex@arizona.edu as an equal and equivalent method."*

## What was true

V3.806 already makes the two logins the **same account**: an arizona.edu Google sign-in is swapped (custom token from
`functions/auth-alias.js`) for a session on the gmail account's uid, so My Week, papers, admin role and everything
keyed by uid are identical. Firebase cannot attach two Google identities to one user, so the swap is the mechanism,
and the session's own email is the account's (gmail). Three things still made arizona.edu read as second-class:

| Where | What happened |
|---|---|
| RM account panel | Always printed the session email — `mcgheealex@gmail.com · admin` — so an arizona.edu sign-in looked like "you were moved to gmail". |
| Capture extension | Signs in through its own REST code (`chrome.identity` → `signInWithIdp`) with **no swap**: Chrome signed in as arizona.edu put the extension in the empty arizona.edu guest account, so captures, the capture log and procurement captures went where the site never shows them. |
| Main-site Google sign-in | `googleLogin()` and the redirect leg bootstrap a guest `users/{uid}` doc for whoever signed in — including the alias uid, keeping the orphan arizona.edu guest profile alive. |

Checked and left alone: every email → person lookup (class rosters, BME 466 staff) uses the gmail address or does
not involve the PI; the course homework modules sign in with `hd: 'arizona.edu'` on purpose and key datasets by
NetID, so they must NOT swap.

## Approach

- **Remember which login opened the session.** Both `_aliasSwap`s (RM `firebase-bridge.js`, main site
  `user-system.js`) write `localStorage['mcghee-signin-via'] = {email, uid}` **before** `signInWithCustomToken` (the
  SDK fires `onAuthStateChanged` for the account before that promise resolves). `uid` is read out of the custom
  token's payload. The bridge trusts the note only while the current user is that uid, and drops it once
  `getIdTokenResult().signInProvider` turns out not to be `'custom'` (a later direct gmail sign-in). Sign-out and a
  failed swap clear it. Display only — nothing authorises on it.
- **Panel**: `getSignInEmail() · role`, then "Same account as mcgheealex@gmail.com" (signed in with the alias) or
  "Also signs in with mcgheealex@arizona.edu" (signed in with gmail). `_ALIASES` maps alias → the account's own
  address for that line; `functions/auth-alias.js` stays the authority on who an alias becomes. Panel text is now
  HTML-escaped. `firebridge.getSignInEmail()` is public.
- **Extension 0.4.3**: `swapAliasSession(idToken)` = `aliasSignIn` → `accounts:signInWithCustomToken` →
  `accounts:lookup`; the cached session (and its refresh token) is the account's; `profile.signedInAs` keeps the
  address Chrome used (popup tooltip). A failed swap THROWS instead of caching the guest session. Rebuilt into
  `rm/downloads/mcgheelab-capture-extension.zip` (the zip was already stale at 0.4.2 by a README-only change).
- **Main site**: `Auth._isAlias(user)` skips `_ensureGuestDoc` for the alias in `googleLogin()` and on the redirect
  return leg.
