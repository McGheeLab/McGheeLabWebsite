# V3.367 — Lab Themes foundation (collection, membership, third library tab, reader chips)

**FuturePlan 13, Release 3** (see `CodeLog/Feature requests/FuturePlan_13_associations_lab_themes.md`).
**REQUIRES `firebase deploy --only firestore:rules` BEFORE FTP.**

## Goal

Give literature reviews a shared home: "Lab Themes" — member-created
clusters around the lab's high-level concepts (TFM, bioprinting rheology,
…). Papers carry multiple themes; a third library tab lists theme cards
and a detail view; the reader gets theme chips; the library search gets a
`theme:` token. (Synthesis notes + voting land in V3.368, same batch.)

## Data model

- `labThemes/{themeId}` — `{name, description, created_by, creator_name,
  created_at, updated_at, archived}`; kebab-slug id with collision suffix.
  **Deliberately NOT an api route**: the adapter's lab-scope save is a
  whole-collection batch replace — exactly the last-write-wins hazard
  co-edited data must avoid. Direct `firebridge.db()` refs (PMR /
  SECTION_COMMENTS precedent).
- Membership: `items/{id}.meta.library.themes: [themeId]` via
  `LIBRARY_LINKS.toggleTheme` (added in the V3.366 `_toggleArrayField`
  refactor) — rides the V3.309 items rule, no items rules change.
- **firestore.rules**: new `labThemes` block after `librarySharedGroups`
  — read lab; create lab member with `created_by == uid` (user decision:
  any member creates); update/delete creator-or-admin. Subcollection
  rules for `notes` (member read/create/update, delete creator-or-admin),
  `votes/{uid}` (own-doc write — reactions/presence pattern), `comments`
  (SECTION_COMMENTS thread) ship in the SAME deploy so V3.368 needs none.
- **No firestore.indexes.json entries**: all reads are whole-collection /
  subcollection gets or snapshots with CLIENT-SIDE sort; SECTION_COMMENTS
  is orderBy-only by design. Do not add where+orderBy queries later
  without expecting a composite-index demand.

## Files

- **`rm/pages/library.html`** — third hub tab: head `?tab=` parse accepts
  `themes` (+ title case); visibility CSS matrix covers `.lib-themes-block`;
  HUB array entry + href builder generalized to a ternary; new
  `.lib-themes-block` (page header + "+ New theme" + intro + `#lt-cards`
  + `#lt-detail`); `themesScripts = [library-links.js,
  section-comments.js, library-themes.js]` in the per-tab loader;
  library-themes.css link; search placeholder mentions `theme:`.
- **NEW `rm/js/library-themes.js`** (`window.LIBRARY_THEMES`) — tab
  renderer (boot gated on `__LIB_TAB === 'themes'`, auth via the
  library-comments.js `onAuthStateChanged` recipe) + standalone lookup
  API for other pages: `loadThemes(force)` / `getThemes()` /
  `getThemeNameById(id)`. Cards grid (name, description, paper count
  from `library/papers.json` membership, creator), archived section with
  restore; detail view (edit-meta modal creator-or-admin, archive,
  "+ Add papers" checkbox picker cloned from the group-picker/link-picker
  pattern with diff-apply via toggleTheme); `?theme=<id>` deep link
  (used by the reader chips).
- **NEW `rm/css/library-themes.css`** — `.lt-*` (violet accent — distinct
  from indigo drafts / teal grants) + `.lp-theme-chip` for the reader.
- **`rm/js/library-paper.js`** — `_renderThemeEditor(item)`: "Lab themes"
  chips block after the associations block (chips link to
  `library.html?tab=themes&theme=<id>`; × removes; select+Add for the
  remaining themes); called in `_attachActive`. `_renderShareWidget`'s
  insert-after chain already prefers it (V3.365).
- **`rm/pages/library-paper.html`** — library-themes.js + CSS.
- **`rm/js/library.js`** — `theme:` search token (`_parseQuery` +
  `_matches` against ids + `_themeNameById`, loaded fire-and-forget via a
  direct labThemes get in `_load`; empty map on failure).

## Verification

1. Rules deploy, then: student creates a theme; edits own meta; CANNOT
   edit another student's (permission-denied); admin can.
2. `?tab=themes` boots only themesScripts; papers/comments tabs unaffected;
   tab bar shows all three everywhere.
3. Add papers via picker → counts update; remove from detail; reader
   chips reflect membership both ways; chip click deep-links to detail.
4. `theme:` token filters by name and id; composes with `tag:`/`draft:`.
5. Guest role sees the auth hint, no data.
