# V3.328 — Re-scan PDF from the metadata editor

> Follow-up to FuturePlan 01 / V3.309 + V3.326, user request 2026-07-11:
> rows like "paper-1baa424e / anonnduntitled" survive every existing
> repair tool, and the user wants a per-paper button that "pops out a
> metadata field that I can edit and hit resubmit for".

## Goal

Any paper's ✎ Edit metadata modal can pull its OWN stored PDF, re-read the
first page (DOI/arXiv sniff + largest-font title guess — the V3.308
client-side extraction), look the result up, and feed it into the existing
per-field diff → Apply → Save flow. Broken-ingest rows with PDFs become
one-click-fixable.

## Problem

The worst rows (`title = "paper-<hash>"` or "Untitled", citation key
`anonnduntitled`) have a PDF but no identifier and a garbage title, so:
- V3.309's ⇣ Fetch-from-identifier needs a typed DOI;
- V3.310's fullRefresh and V3.326's bulk re-check title-search the
  *stored* title — and "paper-1baa424e" matches nothing.
Nothing re-consults the PDF itself, even though ingest-time sniffing has
worked client-side since V3.308. (Separately: the ✎ button isn't visible
on prod yet — V3.309+ is still awaiting the FTP push; the user's screenshot
shows the pre-V3.309 action set.)

## Approach

**`rm/js/library-edit.js`** — new "📄 Re-scan PDF" button beside
⇣ Fetch-from-identifier, rendered only when `lib.pdf.storage_path` exists:

1. `LIBRARY_UPLOAD.downloadUrl` → fetch blob →
   `LIBRARY_METADATA.extractFirstPage` (client-side pdf.js; requires
   `PDF_VIEWER`, present on library.html + library-paper.html — friendly
   toast when absent).
2. DOI guess → lookup; else arXiv guess → lookup; else title guess (or
   first long line) → CrossRef title lookup.
3. Hit → existing `_renderDiff` (blank fields pre-checked → Apply →
   Save/resubmit as usual).
4. No database hit but the PDF yielded something → synthesize a diff from
   the raw sniff (`{title: title_guess, doi/arxiv guesses}`) so the row
   can at least adopt the paper's real title; info toast explains.
5. Nothing extractable (scanned PDF, no text layer) → explanatory error
   toast.

## Files modified

`rm/js/library-edit.js`; `sw.js` CACHE_VERSION 299 → 300; CHANGELOG +
ARCHITECTURE. No functions/rules changes; no new includes (both host
pages already load library-upload + pdf-viewer).

## Out of scope

OCR for scanned PDFs (no text layer → still manual); auto-rescan inside
the V3.326 bulk sweep (downloading every PDF in bulk is heavy — evaluate
after the manual flow proves the extraction quality).

## Release ritual

1. This plan doc. 2. FTP only. 3. CHANGELOG V3.328 + ARCHITECTURE +
CACHE_VERSION 300.

## Rollback

Client-only: git revert + re-FTP + CACHE bump.

## Verification

- On a "paper-1baa424e"-style row (after the FTP push): ✎ → 📄 Re-scan PDF
  → diff appears pre-filled from the PDF's DOI (or its title match) →
  Apply → Save → row shows real title/authors; citation key regenerates
  only if the checkbox was ticked.
- A PDF with no first-page identifier but a clear title → title-search
  diff; declining a bad match leaves fields untouched.
- A scanned/no-text PDF → explanatory toast, modal still usable manually.
- Paper reader sidebar ✎ has the same button (shared modal).
