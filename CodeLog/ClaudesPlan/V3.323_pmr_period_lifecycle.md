# V3.323 — PMR period lifecycle (FuturePlan 04, Release C2)

## Goal

Periods can be archived so the select stops growing forever, and a
period can carry an optional 1:1 `meeting_date` (feeds FuturePlan 05's
meeting-reminder push).

## Changes ([rm/js/pmr.js](../../rm/js/pmr.js) + [rm/pages/pmr.html](../../rm/pages/pmr.html))

- **`archived` flag on `_index` period rows**: `setPeriodArchived(id,
  flag)` mutates the row + saves `pmr/_index.json`. `saveIndexEntry`
  already preserves unknown row fields, so status/label mirroring
  can't clobber it.
- **Period select**: archived rows are hidden unless
  `state.showArchivedPeriods`; a `🗃 N archived` toolbar toggle
  (rendered only when archived periods exist) flips visibility;
  archived options carry an `· archived` suffix; the currently-open
  period always stays listed even when archived.
- **Archive action**: `🗃 Archive` button next to Submit-for-1:1
  (self-view only), flips to `↶ Unarchive` when the open period is
  archived.
- **`meeting_date`** (optional, `YYYY-MM-DD`) on the period doc: 🗓
  date input in the toolbar, hydrateDoc backfills null, read-only in
  admin/mentor view. Consumed later by FuturePlan 05.
