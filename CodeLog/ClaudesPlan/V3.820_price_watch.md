## 1. "Can't read this page"

The popup said so when the tab's content script did not answer `request-items`. Both tabs were open before the 0.2.0
extension was loaded, so they still ran the 0.1.0 script. Fixes:

- `get-items` falls back to **injecting** `scrape-items.js` with `chrome.scripting.executeScript` (the manifest already
  holds `scripting` + `<all_urls>`) and calling the scraper in the same isolated world. The popup's message now says
  what cannot be read (Chrome pages, the Web Store, PDF viewers, `file://`) and to reload a normal page once.
- **VWR** (Spartacus app, no structured data): one item per pack-size row — `variantRows()` walks up from every
  `.display-price` to the row carrying a `76520-944`-style catalogue number and reads its pack ("Carton of 1,000").
  Verified on the live page from a headless browser: name, prices and rows are there once the app has rendered.
- **Sigma** (unreachable from this machine's headless browser, so unverified here): the product number is taken from
  the URL (`/product/aldrich/753084`) when the page shows none, and the SKU table is read row by row.
- **The page as printed text** (Alex's "print then scrape" idea, done without a PDF): when no source yields a price,
  `fromText()` reads `document.body.innerText` the way a person reads a print-out — every line with a price, with the
  catalogue number and pack size from the same or the few lines above. The scrape result now also carries `text`,
  the page as printed (≤ 40 KB), which is what gets saved with a price.

## 2. Price watch

**One record per product URL** — `priceWatch/{watchId}`, where `watchId` = a slug of the host + two FNV-1a hashes of
the **normalised** URL (host without `www`, path, Amazon collapsed to `/dp/ASIN`, only product-identifying query keys
kept). The same two functions live in `extension/price-watch-core.js` and `rm/js/procurement-core.js` and must stay
identical (like the paper-index key).

| field | meaning |
|---|---|
| `url`, `normUrl`, `host`, `vendor`, `catalogueNumber`, `name`, `currency` | what is watched |
| `latest {price, at, method, by}` | the newest observation |
| `history [{at, price, method, by}]` | **append-only** (rules), one entry per observation |
| `lastCheckedAt`, `nextCheckAt`, `checkEveryDays` (90) | the schedule |
| `status` (`active` · `error` · `paused`), `failures`, `lastError` | health; four failures in a row → `error` |
| `claimedAt`, `claimedBy` | a 2-hour lease so two browsers do not re-scrape the same page |
| `inventoryItemId`, `ticketIds[]`, `createdAt/By`, `updatedAt`, `lastActorUid` | links and audit |

`priceWatch/{watchId}/snapshots/{id}` — **the page it came from**, as printed text (`text` ≤ 40 KB, `title`, `url`,
`at`, `price`, `method`, `by`), one per observation that had a page. Methods: `capture` (the extension's + Add),
`request` (a ticket submitted on the site with a link and a unit cost, and each comparison row with a link and price),
`rescrape` (the quarterly check).

**Who writes:** any lab member (rules: `createdBy`/`lastActorUid` = caller, history `hasAll` the old one, `createdBy`
frozen; snapshots create-only by their author; delete admin). No allowlist: anyone who can request can watch.

**The three-monthly re-check runs in the extension**, not in a Cloud Function: vendor pages block server-side fetches
(VWR answered curl with a 2 KB wall, Sigma not at all) and render in the browser. `chrome.alarms` fires every six hours;
when signed in, the background worker queries up to ten watches with `nextCheckAt ≤ now` (single-field range, no
index), skips ones leased in the last two hours, leases up to three, and for each opens the URL in a **background tab**,
waits for load plus a settle, injects the scraper, picks the item whose catalogue number matches (else the first with
a price), records the observation + a snapshot, sets `nextCheckAt` +90 days, and closes the tab. A page that yields no
price pushes `nextCheckAt` out by 7 × failures days (≤ 30) and marks `error` after four misses. The popup shows
"Price watch: N due" with **Check now**.

**On the site:** the Procurement card shows a **Price watch** row (latest list price, when, how many checks, the page
it came from, a history line); the *Reorder existing* rows and the reorder summary show "list $X (checked *date*)"
beside the last paid price; submitting a request with a link and a unit cost records a `request` observation.

## Decisions

- **Text snapshot, not a PDF.** A PDF needs the debugger API (scary banner) or a print dialog; the rendered text is
  what a person would read off the print-out, costs 40 KB, and is searchable.
- **Browser-side re-scrape** because that is where vendor pages actually render; the lease keeps N lab browsers from
  doing the same work; three per run keeps background tabs rare.
- **A request's typed price counts as an observation** (method `request`) — it is a price with a page, which is what
  Alex asked to keep — but it never reschedules a watch the extension already owns.
- **No cap on history**: four entries a year, ~80 bytes each.
