# V3.216 — Paper editor: visual highlight on commented text

Wishlist item from `rm/wishlist.md` (Paper editor section).

## Goal

V3.204 added text-range anchors (`anchorStart` / `anchorEnd` / `anchorText`)
to each `papers/{paperId}/comments/{commentId}` doc. Until now the only
signal that a particular sentence is being discussed was the comment in
the side panel. Make the anchored prose visibly highlighted in the body
text, hoverable (tooltip with comment count), clickable (opens the
thread filtered to that specific anchor), and live-updating as comments
are added / resolved / deleted.

## Approach

1. **Merge overlapping anchors per block.** `_mergedAnchorRangesForBlock`
   in `rm/js/paper-editor.js` walks `commentsState.docs`, drops
   comments without numeric `anchorStart`/`anchorEnd`, sorts by `start`,
   and merges overlaps into a flat non-overlapping list. Each merged
   range carries the union of comment IDs covering it plus a `hasOpen`
   flag (open beats resolved when both intersect the same span).
2. **Wrap text-node segments.** `applyCommentHighlightsToBlock(rootEl,
   blockId)` does a single document-order DOM walk, counting
   source-space char offsets the same way as the V3.191/V3.204 chip-
   aware walker (text-node `nodeValue.length`, chip
   `data-src.length`, `<br>` = 1). Text nodes intersecting a merged
   range are split and the middle slice replaced with a wrapping
   `<span>`:
   - `.pe-comment-highlight` (amber fill) when the range has at least
     one open comment.
   - `.pe-comment-highlight-resolved` (thin underline) when all
     overlapping comments are resolved.
   The wrapper carries `data-comment-ids` (semicolon-joined) and
   `data-block-id`, plus a `title` like `"3 comments"`.
3. **Repaint on every render.** `bindYTextToContentEditable` grew an
   `opts.onRendered(el)` callback that fires after every `applyRendered`
   call (initial bind, blur, remote update while unfocused,
   equation-library refresh). `paper-blocks.js` passes a callback that
   delegates to `PaperComments.applyHighlights(el, blockId)`. The
   function is idempotent — existing wrappers are unwrapped before
   re-wrapping.
4. **Repaint on comment-counts-changed.** The existing
   `paper-comment-counts-changed` event (fired from the comments
   subscription's `onSnapshot` callback) now also triggers
   `applyHighlights`, so adding / resolving / deleting a comment
   updates highlights live without needing the paragraph to re-render.
5. **Click → filtered thread.** New
   `openCommentsForBlockWithAnchorIds(blockId, label, ids)` opens the
   comments pane, forces the filter dropdown to `block`, and sets
   `commentsState.anchorFilterIds` so `renderCommentsList` shows only
   the union of comments backing the clicked highlight. The pane
   renders a yellow "Anchored to highlighted text — N comment(s) ✕"
   chip; clicking the × clears the anchor filter back to the full
   block thread.
6. **Skip while editing.** Highlights are skipped when
   `document.activeElement === rootEl` (the binding is in chip-source
   mode and the user is actively typing). They reappear on blur via the
   `onRendered` hook.

## Files modified

- `rm/js/paper-editor.js`
  - Extended `commentsState` with `anchorFilterIds`.
  - Extended `renderCommentsList` to honor `anchorFilterIds`; renders the
    `.pe-comments-anchor-scope` chip with the clear-`×` button.
  - Added `_mergedAnchorRangesForBlock(blockId)`.
  - Added `applyCommentHighlightsToBlock(rootEl, blockId)`.
  - Added `openCommentsForBlockWithAnchorIds(blockId, label, ids)`.
  - Added one delegated document-level click handler for
    `.pe-comment-highlight` / `.pe-comment-highlight-resolved`.
  - `bindYTextToContentEditable` accepts `opts.onRendered(el)` and
    `applyRendered` accepts a matching `onAfterRender` callback.
  - Filter dropdown change + `closeComments` clear `anchorFilterIds`.
  - `window.PaperComments.applyHighlights` exported.
- `rm/js/paper-blocks.js`
  - `renderParagraph` passes `onRendered: el => PaperComments.applyHighlights(el, blockId)`.
  - `paper-comment-counts-changed` listener now also repaints highlights.
- `rm/css/paper-editor.css`
  - New `.pe-comment-highlight`, `.pe-comment-highlight-resolved`,
    `.pe-comments-anchor-scope`, `.pe-comments-scope-clear` rules.

## Done when

- A paper with anchored comments renders amber-tinted spans on the
  exact prose the comments target.
- Hovering a highlight shows a title tooltip with the comment count.
- Clicking a highlight opens the side panel filtered to those exact
  comment IDs; the clear-`×` in the scope chip restores the full block
  thread.
- Resolving a comment drops its highlight (or thins it to the dotted
  underline if other comments still cover the same span); deleting a
  comment removes it from any wrapper; adding a new anchored comment
  paints a fresh highlight without requiring a paragraph re-render.
- Focusing the paragraph (entering chip-source mode) hides the
  highlights; blurring re-applies them.

## Reuses

- `commentsState` + comment subscription in `paper-editor.js` (V3.204).
- The chip-aware offset walker pattern (V3.191) for source-space
  offsets.
- `paper-comment-counts-changed` event already dispatched by the
  comments subscription.
- The existing comment side-pane rendering (block filter, anchor
  preview, resolve/delete actions).
