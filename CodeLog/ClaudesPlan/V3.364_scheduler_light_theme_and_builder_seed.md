# V3.364 — Scheduler fixes: light-theme ink sweep + builder day-seeding

## Goal

Two bug fixes from Alex's 2026-07-14 report: (A) the scheduler page's
grid skeleton, buttons, inputs, and checkboxes are invisible on RM; (B)
the freeform builder is dead on first editor load until the mode is
toggled away and back.

## Root causes (diagnosed, confirmed in source)

**A — white ink on white paper.** RM is a light theme (`rm/css/style.css`:
`--surface:#ffffff`, `--bg:#f5f6fa`), but `rm/css/scheduler.css` was
lifted verbatim from the dark-themed lab app: ~50 rules draw borders,
grid seams, hover fills, form-input backgrounds, checkbox outlines, and
the mode toggle in `rgba(255,255,255,…)` — invisible on white. This is
why V3.349's "stronger" skeleton lines changed nothing visible (they were
stronger white-on-white), why no FTP/cache-clear could help, and the
root of the long-standing "can't tell where to click" complaint. The
public site (`user-styles.css`) IS dark — it stays untouched.

**B — builder never seeded with saved days.** `wireBuilder`
(`scheduler.js:518`) hardcodes `let selectedDays = []` and has no
parameter for the schedule's saved `selectedDays`; `builderHTML`'s
`selectedDays` argument is dead code. First load of a configured
freeform scheduler therefore renders an unselected calendar and NO
paintable grid (`rebuildGrid()` with zero days clears it and shows the
"Select days on the calendar" hint) — clicks land on nothing. It
"works after toggling" only because the user re-picks calendar days
along the way. Saved freeform cells also never round-trip into the
editor for the same reason.

## Fix

**A (`rm/css/scheduler.css` only):** systematic substitution of
white-alpha with ink-alpha (`rgba(15,23,42,α)`) at slightly raised
alphas (e.g. .06→.08, .12→.14, .18→.28 for the hour line). Exceptions
kept white (they sit on colored/dark elements): `.ff-block.ff-selected`
inset ring (accent bg), `.ff-count` + `.ff-legend-swatch` text (heat
colors), the toggle knob (`#fff` on track/accent). Two directional
fixes: `.ff-block` cell lift now mixes toward ink not white
(`color-mix(… 96%, #1f2937)`), and `.ms-block:hover` brightness goes
darker (.95) instead of lighter (1.2 faded the light-tinted blocks).

**B (`scheduler.js` engine):** `wireBuilder` gains a trailing
`initialDays` param (`selectedDays = [...(initialDays || [])]`);
`wireSetupForm.mountBuilder` passes `initSelectedDays`. Trailing param =
no other callers affected (verified: only wireSetupForm calls it). With
days seeded, the first mount renders the pre-selected calendar AND the
paintable grid with saved cells — clicks work immediately, and saved
freeform availability finally displays when reopening the editor.

## Out of scope

Full visual redesign; `heatColor()`'s inline zero-count cell color
(engine-inline, white .03 — cells are now outlined by ink seams so
acceptable); dark-mode support for RM (RM has no dark mode).
