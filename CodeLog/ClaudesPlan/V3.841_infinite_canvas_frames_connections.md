# V3.841 — Infinite canvas (no pages), cards that move and connect by their dots, drop images, HTML frames, an eraser in the pen set

**Alex (2026-10-22):** *"a canvas should be infinite in all directions, and should not have pages. pages are for
whiteboards · i need an eraser in the pen buildout, the clear really clear click doesnt currently look good · i need
to be able to move tools around after they are placed · i need to be able to drag and drop images in to the notebook
· i need to be able to add html files in, these html files behave as independent frames the can be resized, for
example simulations could be added and play in the lab notebook… the html must be less then 25 Mb · from any item
added to the canvas, there should be a dot at mid points for us to make connections between items. these
connections show the workflow between items."*

Follows V3.839. Engine first (`whiteboard.js`, `whiteboard-board.css`), gated on `isNotebook()` so class whiteboards
keep their pages; the hosts only register the HTML frame and answer drops / wire taps.

## 1. The plane: `infinite()` = every host board

- **One plane, no pages.** The board doc keeps its `pages[]` (class code and old data need it) but a host board
  shows none: no page edges, no divider, no pages bar, no rail, no auto-grow. Graph paper covers the whole stage,
  aligned to the plane (`paintPlaneGrid`), and thins out when zoomed far out.
- **Coordinates.** Strokes and items stay page-local docs on `pages[0]` — the plane — with unbounded x/y (negative
  allowed). Legacy docs on later pages are **folded on read** (`foldToPlane`: `y += pageTop(idx)`, `pageId =
  pages[0].id`), idempotently, in the three listeners and in replay; a card's next move writes the folded position.
- **Pan everywhere.** `S.sheet.originX` joins `originY` (`sheetToPx` / `normPoint`); `scrollPlaneBy(dx, dy)` is the
  one scroll for wheel, two-finger drag, a viewer's finger, the ✋ pan tool and the lens spill. Zoom (`zoomAt`) still
  anchors under the pointer, then `clampView` folds the lens offset into the origin (`origin −= t / s`) so `tx = ty =
  0` always — items layer, ink and background agree by construction. `sheetViewH/W` are the visible plane at the
  current scale; `clampOriginY` is the identity. The last origin per board is remembered on the device.
- ⌂ home = content's top-left at 100 %; ⊡ fit = the content's bounding box; ⤢ fit a region frames the box.
- Export = one image of the content's bounding box (+ margin).
- Recordings log `x` with the scroll; replays restore it.

## 2. Pen set: eraser as a kind; the two-tap clear

`kind: 'eraser'` with its own size (`S.eraserW`, screen-relative like `ERASE_TOL`); the default set has one; the
editor's kind row is Pen / Highlighter / Eraser (no swatches for an eraser). The fan's ⌧ keeps its glyph when armed:
red ring + caption "Tap ⌧ again to clear all the ink", instead of a label squeezed into the circle.

## 3. Cards move by their header

Outside Arrange the header (grab glyph ⋮⋮, kind label, stamp, blank space — never a button or the title field)
starts a move; the corner grip resizes (V3.839). Arrange stays for images and text cards under the ink.

## 4. Drop files

`opts.onDrop(files, { pageId, x, y, clientX, clientY })` from the board (`dragover` / `drop`), skipped when the drop
lands on a card (the card's own zone). Notebook: images → Figure cards (uploaded through `NOTEBOOK_FIGURES`), `.html`
→ an HTML frame. Figure board: images → a Planned-figure card carrying the image (`PAPER_FIGURES`), `.html` → frame.

## 5. HTML frames

`CANVAS_WIDGETS.basic.registerHtmlFrame({ upload, toast })` + `basic.uploadCanvasFile(file, uid)` → Storage
`canvas-files/{uid}/{id}/{name}` (text/html or image, **< 25 MB**, rule deployed before the client). The card body is
a sandboxed iframe (`allow-scripts allow-same-origin allow-forms allow-pointer-lock allow-downloads allow-modals`)
at the card's width with a stored aspect (`data.ar`), a ↕ handle for the height, ⟳ reload, ⤢ open, Replace. Both
hosts register it, so a simulation runs inside the notebook or on a figure board.

## 6. Connection dots → workflow

Four ports at the mid-points of every card (`.wb-wport`, owner, boards with wires on — the notebook now has them).
Drag from a port, drop on another card: `addWire(from, to, '', { fromSide, toSide })`; the wire is drawn as a cubic
from port to port with an arrow and the label; the host's `onWire` menu names the step (notebook: then / feeds /
uses / result / compare / related, Reverse, Remove).

## Decisions
- Fold legacy pages on read rather than migrate in place: zero writes, idempotent, the first drag persists it.
- Keep `pages[0]` as the plane's id so every rule, export and replay path still sees a page id.
- The file limit is enforced twice: the client refuses > 25 MB before uploading; the Storage rule refuses it anyway.
- Ports only on cards (widgets): images / text under the ink cannot take a pointer without Arrange.
