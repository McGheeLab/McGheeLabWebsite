Rather than guess a third time, we built a measuring stick first: a local
labeling harness over 20 real library papers, Alex drew ground-truth boxes,

## The training harness (local only — never deployed, never FTP'd)

`~/Documents/GitHub/ResearchManagement/data/figure-training/` (sibling repo,
outside this tree by design):

- `server.py` — serves the McGheeLabWebsite repo (so `/rm/js/*` and the
  vendored pdf.js load unmodified) plus `/training/*`, with a save endpoint.
- `harness.html` — the labeling viewer: 20 PDFs, six label types
  (figure / table / reference / equation / text / custom-tagged), modal
  tools so normal scrolling still works, autosave to `labels.json`, a live
  overlay of what the algorithm currently predicts, per-paper IoU scoring,
  a batch scorer, and (V3.643) a **review mode** where each algorithm box
  can be marked ✓ correct / ✗ wrong / ✎ redraw.
- `score.mjs` — offline scorer. Grades any candidate against the labels at
  IoU ≥ 0.5, counting only pages Alex actually reviewed.
- `feat-<id>.json` — per-page features dumped **from the real browser
  pipeline** (`harness.html?dump=1`): text items with cluster/column/
  blockType plus an ink grid. This is what makes offline iteration
  faithful — same inputs the production code sees.
- `algo1..algo9.mjs` — the iteration trail; `algo9` is what shipped.

## What the labelled data proved wrong (and the fixes)

1. **Figures contain text.** Truth boxes hold 34–3500 text items (axis
   labels, panel letters, plot annotations). Growing a region "until the
   nearest text item" collapses it instantly — this is why the V3.640
   detector found almost nothing. Obstacles are now **prose lines only**.
2. **Real captions aren't typed `caption`.** `classifyBlocks` requires
   small type *and* <12 items; real captions are long, so nearly every one
   is typed `body`. Anchoring on `blockType` was doomed. Captions are found
   by regex over **line-joined** text.
3. **Lines must be split at column gutters** — otherwise a 2-column page
   joins left+right text into one line whose text begins with the left
   column's words, and no caption regex can ever match (this alone hid
   every caption in the 2-column papers).
4. **…but not too aggressively**: `"FIGURE | 1 | Formation"` must stay
   joined across a 16px gap while a 19px gutter must split. Solved with
   **two line groupings** — loose for caption text, tight for prose
   obstacles — plus a re-split wherever a mid-line caption opener appears.
5. **Band chaining**: comparing each item to a band's *growing* bounds let
   a band walk down the page (bell-1979 merged body text 20px away into
   its caption line). Bands now compare to a fixed centre.
6. **Caption position gives direction** — figure captions sit *below*
   their figure, table captions *above* their table.
7. **Tables end at whitespace, not at prose**: a table's own wrapped cells
   read as prose line-by-line, so prose-bounded growth stopped one row in.
   Table captions now grow to the first white band wider than the table's
   own row spacing (agarwal: 4/7 → 7/7).
8. **Single-column figures must not merge**: neighbouring captions are
   obstacles, absorption can't cross a locally-detected gutter, and growth
   is clamped to the caption's column (bhattacharjee: 2/4 → 4/4).
9. **Cross-reference filter was too greedy** — `"FIG. 2 (a) The Bingham
   model…"` is a real caption that matched a "Fig. N … the" prose pattern.

## Known-weak cases (documented, not overfitted)

- **1970s scans** whose text extraction interleaves columns (bell-1979,
  0/2). The marquee / Alt-drag fallback covers these.
- **bi-2015 p4** — two single-column figures whose captions share a band;
  still merges. Needs more labelled examples of that layout.
- Tables where the caption sits beside (not above) the table.
