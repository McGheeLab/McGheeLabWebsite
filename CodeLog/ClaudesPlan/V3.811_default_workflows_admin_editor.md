# V3.811 — Default workflows: an editor, not a matrix

**Date:** 2026-10-19
**Alex:** *"I want a cleaner way to set the default workflows as the admin, so what are the main
workflows, and what pages should show up"*.

## What was there

`admin-permissions.html?tab=workflows` — the V3.63/V3.77 "Default Workflows × Pages" matrix: one
row per workflow, 57 checkbox columns (every nav page), and inside each row's header an icon field, a
name field, a description field, a landing-page `<select>`, the id and a delete button; an "Add a
workflow" row at the bottom; a first-run "Seed defaults" box above. Right data, wrong shape — the
two questions ("which workflows?", "which pages, in what order?") are lists, not a grid, and the
order of pages (= the chip order in the bar since V3.809) was not even editable there.

## The editor — `rm/pages/admin-workflows.html` + `rm/js/admin-workflows.js` + `rm/css/admin-workflows.css`

Two columns. **Left rail: the main workflows**, in the order everyone sees them (Workflows ▾, Home,
palette): icon, name, page count, a *hidden* badge; drag or ▲▼ to reorder; select to edit;
**+ New workflow** is an inline name field (no browser prompt). **Right: the selected workflow** —
icon button (grid of the 100 Heroicons with a filter, or type an emoji), name, one-line blurb, a
**Visible to the lab / Hidden** switch, the id, then **Preview** (real `.nav-chip` markup in a
`top-nav--workflow` bar — what the bar draws), **Pages in this workflow** (ordered rows: drag or ▲▼
for chip order, ★ *landing* radio, × remove; a page the nav no longer knows is flagged) and **Add
pages** (filterable grouped list of the pages not yet included; Enter adds the first match). Delete
is an inline confirm strip.

One **Save changes** (⌘S) writes the whole `labConfig/defaultWorkflows` doc; the header counts
unsaved changes; **Revert** restores the saved copy; leaving with unsaved changes asks via
`beforeunload`. First run (no doc): the editor shows the built-in set and says so — Save writes it.

## Model

Unchanged shape, one new optional field: `workflows[].enabled` (default true). `false` keeps a
workflow in the doc but hides it from the Workflows ▾ menu, Home and the palette, so an admin can
draft one before launching it. Consumers filter `w.enabled !== false` (nav.js menu + palette
context, workflow-chooser.js). Array order and `pageIds` order are now first-class in the UI.
labConfig is already admin-write — no rules change.

## Permissions page

The "Default Workflows × Pages" tab becomes a **Default workflows ↗** link in the tab bar, the tab
body a pointer card, the seed box is gone; `renderWorkflowGrid` returns when its table is absent and
the two seed-box references are null-guarded. The grid/save code stays inert rather than being
excised from a 2,000-line file.

## Discoverability

NAV_ITEMS: Settings → **Default Workflows** (admin, `rectangle-stack`) + blurb. Workflows ▾ footer:
**Edit default workflows** for admins. Home → Workflows heading: **Edit defaults →** for admins.
