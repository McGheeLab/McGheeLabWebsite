# V3.508 — Huddle IA redesign: 4 tabs, inline composers, unified weekly feed (R2)

## Goal

The structural release of the Huddle UX program (R1 = V3.504 quick wins).
The old layout spread the feature across **11 sidebar tabs** — viewing
(Plan Feed / Help Feed / Rundown / Team Availability), creating (Add Plan /
Request Help / Add Task), and "my stuff" (My Plans / My Help / My Tasks) were
all separate destinations, and Plans vs. Rundown were two overlapping
"what I'm doing this week" concepts. This release collapses everything into
**4 tabs** and merges the two concepts at the UI level (data migration = R3).

## New information architecture

| Tab | Contents |
|---|---|
| **This Week** (default, id `week`) | member filter chips (All · Mine · per-member) → inline expanding plan composer → Day/Week/Month view toggle + time grid (timed plans, everyone) → **"Anytime this week"** card list (untimed plans + legacy rundown tasks) → **open-help strip** (top 3, "See all →") |
| **Help** (id `help`) | inline help composer → all **open** requests across ALL weeks (carry-over fix) with All/Mine chips → "Resolved this week" collapsed `<details>` |
| **Team Availability** (`teamavail`) | unchanged |
| **Settings** (`settings`) | unchanged |

Old section ids alias onto the new tabs (`SECTION_ALIASES` + `normalizeSection()`)
so V3.504 deep links and any bookmarks keep working.

## Key changes (all in [rm/js/huddle.js](../../rm/js/huddle.js) + [rm/css/huddle.css](../../rm/css/huddle.css))

- **Merged plan concept**: a `huddlePlans` doc is *timed* (`plannedDay`+`startTime`
  → grid block), *all-day* (`plannedDay` only → all-day row), or *untimed*
  (no `plannedDay` → "Anytime" card). `buildTimeGrid` no longer dumps
  untimed plans into day 1's all-day row — it skips them (they render in the
  Anytime list). `createPlan` gains `categoryId/categoryLabel/projectId/
  projectName` + a `joinRequests: []` field.
- **Inline plan composer** (`planComposerHTML`/`wirePlanComposer`, repurposed
  from the old Add Plan page): collapsed one-liner "＋ What are you planning
  this week?" that expands in place. Category + Project selects (lifted from
  Add Task). Day/time optional. **Recurrence controls only appear when a Day
  is set** — untimed+recurring is unrepresentable because
  `generateRecurringInstances` requires `plannedDay` (guards against the
  recurrence self-mint loop). Editing (grid popup ✎ or anytime-card ✎) opens
  the composer prefilled and scrolls to it. Drag-to-create on the grid
  prefills+expands the composer instead of leaving the feed.
- **Anytime cards** (`renderAnytimeCard`/`wireAnytimeCards`): one renderer for
  both untimed plans (`kind='plan'`) and legacy `huddleRundown` docs
  (`kind='task'`). Non-owners get Request-to-Join (plans →
  `requestJoinPlan`/`respondToPlanJoinRequest`, new — same joinRequests[]
  shape as rundown); owners get edit/delete/Mark-Done + inline accept/decline.
  Accepting on a **plan** opens `showSchedulePlanModal` which sets
  `plannedDay/startTime/endTime` on the SAME doc + arrayUnions the joiner
  (no second doc); legacy tasks keep the old create-plan+`scheduledPlanId` flow.
- **Help carry-over**: `subscribeHelp` now subscribes
  `where('status','==','open')` (no weekId — single-field, no index needed);
  open requests survive week rollover and show a "week of …" tag
  (`weekTagLabel` via `weekIdToOffset`). Resolved requests load one-shot per
  current real week (`loadResolvedHelp`, client-filtered from the weekId
  query to avoid any composite-index need). `createHelpRequest` stamps
  `getWeekId(0)` (the real current week) regardless of grid navigation.
- **Filter chips replace the filter panel + My-Stuff tabs**: `chipsRowHTML`
  drives the existing `_filterMembers`/`applyFilters`; "Mine" = filter to
  self. Month view is personal by design (own plans only).
- **Grid safety**: blocks are only `draggable` when `ownerUid === _user.uid`
  (the feed grid is now everyone's plans and drag-drop edits the dragged doc).
- **Sidebar badges**: This Week shows pending join-request count on anything
  you own (plans + legacy tasks); Help shows open-from-others count.
- Week nav no longer resubscribes help (not week-scoped anymore).

## Deliberately left in place (deleted in R5)

`renderPlanFeed/renderMyPlans/renderHelpFeed/renderMyHelp/renderRundownFeed/
renderAddRundown/renderMyTasks` + wires are now unreachable dead code. Kept
this release to keep the diff reviewable; R5 removes them and their CSS.

## Deploy

FTP only (rm/js/huddle.js, rm/css/huddle.css, sw.js). No Firebase deploy —
`huddlePlans`/`huddleRundown` rules already allow any-auth update.

## Verify (browser pass)

- Composer: create timed / all-day / untimed plans; untimed appears under
  "Anytime this week"; recurrence section only visible once a Day is set.
- Drag-create on the grid prefills + expands the composer in place.
- Chips: Mine filters grid + anytime list; member chips toggle.
- Second account: Request-to-Join an untimed plan → owner sees pending badge
  + inline accept → schedule modal puts it on the grid (same doc).
- Help: composer posts; responses/resolve work; a request left open last week
  still shows (with week tag); Resolved-this-week details populates.
- Deep links: `?kind=plan&item=` (timed → popup+flash; untimed → anytime-card
  flash), `?kind=help&item=`, old `?tab=planfeed`-style params alias correctly.
- Phone: pinch zoom, time slider, sidebar tab strip still work.
- Rapid week nav: no listener leaks (console clean).
