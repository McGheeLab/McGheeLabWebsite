# V3.374 — Nodes as a first-class protocol viewing mode + canvas layout fixes

## Goal

User feedback on V3.369: the node workflow should not live inside a
"Design (node graph)" block within the protocol document. Instead the
protocol editor gets **three viewing modes**:

1. **⬡ Nodes** — the whole-protocol node design workflow, full height.
2. **✎ Editor** — the existing block editor.
3. **📄 Document** — the existing read-only `?view=doc` page.

Plus two canvas fixes: **every node is collapsible**, and **input/output
sockets must not overlay the node's content**.

## Design

**Segmented switcher** (`.pre-viewseg`, built by protocol-editor.js into
`.pre-topbar-actions`): Nodes and Editor swap what renders inside
`#pre-content` (`state.view`, persisted per protocol in localStorage
`pre-view:{id}`); Document links to the existing doc-view URL (the old
📄 Doc view button is hidden — superseded). `render()` dispatches on the
mode at the top, so every existing re-render path (structural
observeDeep, seed waiters) respects the mode for free.

**Storage stays the design block.** The Nodes view finds the protocol's
first `design` block and mounts `ProtocolGraphEditor` on its attrs
(same getGraph/setGraph transaction + markDirty as before), auto-creating
the block (and a section if the tree is empty) on first entry for
editors. Compile, doc view, and notebook-run paths are untouched — they
already walk blocks for `kind === 'design'`. In the Editor view the
design block renders as a **compact stub** ("N nodes · M wires — edited
in the Nodes view" + an ⬡ Open Nodes view button that dispatches
`pre-open-nodes`), not an inline canvas.

**Collapsible nodes.** Each card header gets a ▾/▸ toggle; collapsed
state persists on the node (`n.collapsed` — `normalizeGraph` preserves
unknown keys) when editable, session-local otherwise. Collapsed cards
keep their header, output rows, and binding chips (so wires stay
attached and draggable) and hide the inspector fields and binding
dropdowns. A ▤ palette button collapses/expands all.

**Socket layout fix.** The absolutely-positioned left/right rails (which
overlaid the inspector fields) are gone:

- Output sockets are **in-flow rows** right under the header
  (`.pge-outs` / `.pge-orow`), label inside the card, dot protruding
  from the right edge.
- **Each binding row is its own input socket** — the dot sits on the
  card's left edge of that row. Inputs and outputs can never overlap
  content because they occupy normal layout flow.
