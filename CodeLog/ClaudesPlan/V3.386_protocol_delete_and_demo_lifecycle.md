# V3.386 — Delete protocols + demo copies that don't stick around

## Goal

(1) A way to **delete protocols** from the protocols list page. (2) Demo
lesson copies **shouldn't be kept**: they stay off the main list, loading
a lesson you already have opens your existing copy instead of minting
another, and there's one-click cleanup.

## Design

### Delete (owner-or-admin)
- **Rules** ([firestore.rules](../../firestore.rules), `protocols/{id}`):
  `delete` was admin-only → now **owner-or-admin**. New scoped
  `isProtocolOwner()` helper (parent-doc `get()`) extends the cascade to
  the subcollections: `versions` delete (was admin-only), `yjs_updates`
  delete, and `presence` delete (stale docs from other users). The
  client deletes subdocs FIRST, then the parent, so the ownership get()
  still resolves. ⚠ **Deploy before FTP:**
  `firebase deploy --only firestore:rules`.
- **Client** (`rm/js/protocols.js`): `deleteProtocolDeep(id)` — for each
  of `versions / yjs_updates / yjs_snapshot / presence`, get + batch-
  delete (400/chunk), best-effort (a subcollection failure never blocks
  the doc delete; orphans are unreachable once the parent is gone), then
  delete the doc. `confirmDeleteProtocol(p)` = confirm dialog ("removes
  the protocol and its version history for the whole lab") → delete →
  drop from the local list → re-render.
- **UI**: a 🗑 button on each card (reveals on hover), shown when the
  viewer is the owner (`p.ownerUid === uid`) or `firebridge.isAdmin()`.
  Click is `preventDefault`/`stopPropagation`ed (cards are `<a>`).

### Demo lifecycle ("should not be kept")
- **Flagged**: `createFromJson` gains `opts.extraFields` (merged into the
  doc root); the demo loader stamps `{is_demo: true, demo_of: slug}`.
  Pre-flag copies are recognized by id (registry slug exact or `-N`
  suffixed) via `isDemoRow`.
- **Hidden by default**: `applyFilters` excludes demo rows unless the new
  "show demos (N)" checkbox (visible only when demo copies exist) is
  ticked. Revealed demo cards carry a blue `demo` chip.
- **Reuse, don't duplicate**: `loadDemo` first checks `myDemoCopyOf(d)`
  (my `demo_of` match or id match) → navigates to the existing copy. The
  modal row shows "your copy — opens it". The suffix-retry create path
  only runs when you have no copy.
- **Bulk cleanup**: the 🎓 Demos modal gains "🗑 Remove my demo copies
  (N)" → confirm → `deleteProtocolDeep` each of mine → refresh list +
  modal (failure message preserved across the refresh).

## Verification
- `node --check` on protocols.js / protocol-import.js; import-touching
  suites (test-demos / test-code / test-import) still green (extraFields
  is additive; validate/summarize untouched).
- Pending (browser, after rules deploy): hover a protocol you own → 🗑 →
  confirm → card disappears and the doc + versions are gone in Firestore;
  a non-owner lab member sees no 🗑 on others' cards (and rules deny);
  load a lesson → it's flagged + hidden from the main list until "show
  demos"; load the same lesson again → opens the SAME copy; 🎓 modal →
  Remove my demo copies → list is clean.
