# V3.335 — Link-annotation citation scanner (coverage R3)

> Coverage-expansion R3 of 5 (2026-07-12). Publisher PDFs encode inline
> citations as internal GoTo links (marker → reference entry). V3.333 made
> those links extractable; this release turns them into authoritative
> citation markers — regex-independent localization for the majority of
> modern journal PDFs.

## Changes (rm/js/paper-citations.js + harness)

- Printed reference entries now carry their list position (`listY` beside
  the existing `firstPage`) from `_parseEntriesFromHeading`.
- **`_linkMatchesFromAnnotations(links, printed)`** (pure, shared): an
  internal link whose target lands within the printed reference-list page
  span maps to the entry with the greatest `listY ≤ targetY` on the target
  page (first entry of the page when the dest points above it / has no y).
  Emits standard match objects with `kindLabel:'link'`. Known limitation:
  page-granular dests (no y) resolve to that page's first entry.
- **`_buildLinkIndex()`** (viewer flow): collects `viewer.getLinkAnnotations`
  across pages → `_linkMatchesByPage`. Runs in `_onAllPagesReady` and the
  ↻ Re-detect action, before style detection.
- **`_scanPage`** merges the page's link matches ahead of textual ones,
  dropping textual matches that overlap a link on the same refKey (links
  are authoritative).
- **`_detectStyle`** short-circuits to `family:'link'` when links cover
  ≥50% of stored refs; `_filterValidated` then skips family gating —
  textual matches survive purely on resolve-to-a-ref validation, acting as
  supplements for link-less mentions. `_buildRefIndex` includes link
  matches, so the "All refs" tab and coverage stats see them.
- **`analyzeDocument`** accepts `opts.annotations`; the audit harness
  extracts with `{withAnnotations:true}` and passes them, so link coverage
  is measured corpus-wide.
