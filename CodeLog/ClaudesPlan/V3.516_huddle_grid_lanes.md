# V3.516 — Huddle time grid: side-by-side lanes for overlapping plans

## Goal

User report: the Huddle's "This Week" time grid correctly shows every lab
member's plans, but when two or more people have plans in the same or
overlapping time slot, their blocks render directly on top of each other
(same `grid-column`/`grid-row`) — unreadable, and effectively hides that
multiple people are doing different things at once. Two asks:

1. Make it easy to tell whose block is whose.
2. Support multiple different people, each with a different activity, in
   the same time slot, without them obscuring each other.

The data model already supports #2 (`huddlePlans` is one doc per owner, so
different people already can and do post distinct plans in the same slot —
that's exactly what was causing the overlap). The fix is rendering, not schema.

## Approach

**Side-by-side lanes** (`rm/js/huddle.js` `computeDayLanes`, new): the same
collision-clustering / greedy-column-packing algorithm calendar UIs (Google
Calendar, Outlook day view) use. Per day column:
1. Sort that day's timed plans by start slot (ties broken by longer duration
   first).
2. Sweep through them, grouping contiguous overlaps into "clusters" so a
   cluster of 2 overlapping plans doesn't waste width just because 5 other
   non-overlapping plans exist elsewhere in the same day.
3. Within each cluster, greedily place each plan into the first lane whose
   last occupant has already ended (classic activity-selection greedy
   packing) — reuses lanes whenever possible instead of always growing.
4. Every plan gets `{lane, laneCount}`; `laneCount` is only final once the
   whole cluster has been swept (lanes can still be added by later events in
   the same cluster), so it's read from the shared `colEnds` array length
   after the sweep completes, not inline during placement.

Verified in isolation against 5 scenarios (full overlap, no overlap,
nested/partial overlap, two independent clusters in the same day, and
open-ended plans with no `endTime`) — all produce the expected lane
assignment (see the plan's implementation notes; test script was throwaway).

**Rendering** (`buildTimeGrid` in [rm/js/huddle.js](../../rm/js/huddle.js)):
each block keeps its existing `grid-column`/`grid-row` (day + time position)
but now also gets inline `width: calc((100/laneCount)% - 4px)` and
`margin-left: calc((100/laneCount)% * lane + 2px)`, so N overlapping plans
split that day-column's width into N side-by-side strips instead of
stacking. `z-index` increases per lane so left-to-right visual layering is
consistent, and hover still promotes a block above its neighbors
(`box-shadow` added since a thin lane can make the brightness-only hover
cue hard to see against neighbors).

**Identification** (both this release's asks feed into the same fix):
- Each block now shows a small colored initials avatar (`.hud-block-avatar`)
  next to the owner name, matching the same `getUserColor()` tint used for
  the border/background — consistent with how "Anytime this week" and Help
  cards already show avatars.
- Every block gets a native `title` tooltip (`"Name: activity (time)"`) so
  even a lane squeezed too narrow to show readable text is still
  identifiable on hover, and the existing click-to-open-popup still shows
  full details.
- **Member chips double as a color legend**: `chipsRowHTML()` now renders a
  small color dot (`.hud-chip-dot`) on every chip, using the exact same
  `getUserColor(uid)` value as that member's grid blocks — answers "whose
  color is whose?" without a separate legend widget, and the chips were
  already there (filter row).
- All-day blocks (`planBlockHTML`, plans with a day but no time) get the
  same small avatar + tooltip for consistency, though they weren't
  overlapping to begin with (that row already wraps via flexbox).

## Files touched

- `rm/js/huddle.js` — `computeDayLanes` (new, near the TIME GRID HELPERS
  section), `buildTimeGrid` overlay-block loop, `planBlockHTML`,
  `chipsRowHTML`.
- `rm/css/huddle.css` — `.hud-block-head`, `.hud-block-avatar` (+ `--inline`
  variant), `.hud-chip-dot`, `.hud-grid-block` min-width/gap tweaks, mobile
  avatar sizing.
- `sw.js` — CACHE_VERSION bump.

No data model, rules, or Cloud Functions changes — this is purely a
rendering fix on top of the existing `huddlePlans` schema.

## Deploy

FTP only.

## Verify

- Create 3+ plans from different accounts (or seed docs) at the same/
  overlapping time on the same day → all render side-by-side, each legible,
  clicking any one opens its own popup.
- A plan that doesn't overlap anyone still renders full-width (laneCount 1).
- Member chips show a color dot matching each person's blocks on the grid.
- Zoom in/out and drag-to-create still work (lane math doesn't touch the
  drag/zoom/pinch code paths).
- Mobile: blocks remain tappable and readable at the smaller avatar size.
