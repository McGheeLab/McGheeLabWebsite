# V3.519 — Chat: derived read receipts (readBy retired)

**Release 7 of 7** in the chat upgrade program.

## Problem

Every channel open ran `updateReadReceipts()`: a batch `arrayUnion` of
your uid onto up to 20 recent `chatMessages` docs — O(20·members) doc
churn per busy channel per day, each write fanning out to every open
listener. And `readBy[]` grew unbounded per message.

## Design

A message is "seen by" M iff M's `chatReadState.lastReadAt` (already
written by `markChannelRead` on every channel open — that single write
IS the receipt now) is ≥ the message's `createdAt`.

- New `subscribeChannelReadStates(channelId)` — one listener on
  `chatReadState.where('channelId'==X)` (single-field auto index; reads
  allowed by the R4 rules), attached in `subscribeMessages` and
  `enterHistoryMode`, feeding `_channelReadStates` (uid → lastReadAt).
  Receipts update live as others read.
- `getSeenByUids(msg)` — readers = anyone (minus author) with
  `lastReadAt >= createdAt`. `getSeenByDenominator(msg)` — "everyone" =
  DM `members` / channel `subscriberUids` minus author (better than the
  old all-chat-users heuristic; legacy fallback kept).
- Three consumers switched: the last-own-message eyeball label, the
  "Seen by" modal, the mobile stats-bar reader count.
- DELETED: `updateReadReceipts()` + its `markChannelRead` call, the
  `readBy: [uid]` seed in `msgData`, `READ_RECEIPT_BATCH` /
  `MAX_VISIBLE_RECEIPTS` consts. Historical `readBy` arrays are ignored
  — no migration.
- Semantics shift slightly: "read the channel since this message" vs
  "had it in their last-20 window" — more correct, and receipts now work
  on ALL historical messages.
- Channel open cost: up to 21 writes → exactly 1.

## Rules follow-up (staged, NOT yet removed)

The three transition carve-outs in firestore.rules (`readBy` in the
message-update hasOnly, the thread-counter clause, the channel
`lastMessage/lastActivityAt/messageCount` clause) stay ACTIVE so the
rules deploy that ships R4/R5 cannot break tabs still running older
cached clients. Each clause carries a "DELETE a few days after the FTP"
comment — that removal + one `firebase deploy --only firestore:rules`
is the program's final cleanup step (see the deploy checklist).

## Files

## Verification

Two browsers: A sends; B opens the channel → A's eyeball flips to "Seen
by 1" within ~1s WITHOUT any `chatMessages` writes from B (check the
network tab / console — only the single `chatReadState` set). "Seen by"
modal lists B. New messages carry no `readBy` field. Old messages still
show sensible receipts (derived). Denominator: a channel where only 2 of
5 lab members subscribe shows "Seen by everyone" after those 2 read.
