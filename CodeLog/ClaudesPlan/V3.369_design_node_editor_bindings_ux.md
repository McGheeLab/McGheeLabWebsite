# V3.369 — Design node editor: variable bindings, typed unit sockets, popout + UX pass

## Goal

Upgrade the `design` block's inline node editor (V3.330) from a cramped,
untyped canvas into a Blender-geometry-nodes-style workflow builder:

1. **Bindings, not inferred wires.** Dragging a variable (an output
   socket) onto any block creates an explicit *binding* — an edge
   `{id, from, to, sourceVar, role, paramField?}` — and a row inside the
   target block declares what the variable does there:
   - `math` — the name becomes usable in the target equation's typed
     expression (insert-bound-var helper lists them).
   - `param` — the variable's **live value drives a chosen block
     setting** (input `min`/`max`/`step`/`default`, constant `value`,
     equation `decimals`) at render/run time.
   - `none` — plugged in, visible, consumed by nothing (documents intent).
   - list targets show the binding as a structural feed.
2. **Per-variable sockets, unit-typed and color-coded** — outputs
   stacked down the right edge, one input socket per binding down the
   left edge, each colored by the variable's physical dimension
   (volume / length / area / mass / temperature / time / amount /
   ratio / categorical). Case-sensitive unit map so molar `mM` ≠ metric
   `mm`. Soft amber warning when an equation mixes dimensions.
3. **Popout editor** — ⤢ button or double-click the canvas opens a
   94vw×90vh modal hosting the *same* `mount()` on the same
   getGraph/setGraph; closing re-reads the graph into the inline canvas.
4. **UX pass** (user request: "more user friendly … build nice workflows
   for dynamic protocols"):
   - Palette buttons get icons + plain-language tooltips per node type.
   - **⚡ Build a starter workflow** button on the empty canvas seeds a
     wired example (two inputs + constant → equation; choices → list).
   - **✤ Tidy** auto-layout (columns by longest-path depth, left→right
     data flow), **⌖ Fit**, ⊕/⊖ zoom buttons; 8px snap-to-grid drag.
   - **Live value badges** in node headers (`= 360 µL`) recomputed on
     every edit (best-effort; needs mathjs on the page), `per-item`
     badge for item-scoped equations.
   - Wire tooltips (`vol → total · click to remove`).

## Runtime wiring (the correctness half)

`ProtocolGraph.compile` returns `paramOverrides:
[{targetNode, paramField, sourceVar}]`. Consumers:

- **protocol-doc.js `renderDesign`** and **lab-notebook.js
  `_runMountDesign`** map them to a `drivers` object
  (`{field → sourceVar}`) attached to each compiled input/output spec.
- **protocol-widgets.js `renderCalculator`** reads `v.drivers`: driven
  `min`/`max`/`step` re-apply to the control on every recompute; a
  driven `default` tracks the driver while the control is untouched
  (pre-existing override = user's saved choice, always wins), folding
  the new value into the symbol table on the next tick (converges).
  Driven `decimals` on outputs formats live.
- **Constant `value` driven by a binding** upgrades at compile time to a
  computed output entry whose expression is the source variable — a
  fully reactive mirror through the existing kernel (topo order
  guarantees the source is defined first). Undriven constants emit
  exactly as before.
