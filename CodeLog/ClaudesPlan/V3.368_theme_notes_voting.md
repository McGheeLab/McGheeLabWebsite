# V3.368 — Theme synthesis notes + "helped me" voting + discussion

**FuturePlan 13, Release 4** (see `CodeLog/Feature requests/FuturePlan_13_associations_lab_themes.md`).
No Firebase deploy — the V3.367 rules block already covers notes / votes /
comments.

## Goal

Make each Lab Theme a living document: co-written synthesis notes the
whole lab reads and edits simultaneously, a per-paper "👍 helped me" vote
so the reading list self-ranks, and a threaded discussion — so new
students land on a theme page and know exactly where to start.

## Design decisions (user)

- **Per-note block docs**, not Yjs: `labThemes/{id}/notes/{noteId}`
  `{order, body_html, created_by, creator_name, created_at, last_editor,
  modified_at}`. Live `onSnapshot` (no orderBy — client sort by order
  then created_at). Two people editing DIFFERENT notes never conflict;
  the SAME note is block-level last-write-wins: a focused/dirty note
  defers remote repaints (compared via a `data-mtime` stamp) and shows
  "✏ X edited this note — your version saves over theirs on blur"
  instead of clobbering the caret. protocol-yjs.js is the documented
  upgrade path.
- **Simple "helped me" vote** (user picked over 1–5 stars):
  `labThemes/{id}/votes/{uid}` `{helped: [itemId], updated_at}` — one doc
  per user (reactions/presence pattern), toggled with set-merge
  arrayUnion/arrayRemove on the OWN doc only. Aggregation is client-side;
  papers sort by count desc then title; **"Start here" badge on the top
  3 with ≥2 votes**. Orphan votes (paper removed from theme) are simply
  ignored at render.

## Implementation (all inside `rm/js/library-themes.js` + `library-themes.css`)

- `_mountNotes(themeId)` — onSnapshot; per-card incremental render keyed
  on `data-note-id` (only unfocused, non-dirty cards repaint, and only
  when `modified_at` moved); deleted docs drop their cards; unsubscribed
  on theme close (`_closeTheme`).
- Editing: contentEditable body per card; container-level delegated
  `input` (800 ms per-note debounce → field-patch `update({body_html,
  last_editor, modified_at})`, never a whole-doc set) and `focusout`
  (flush + clear pending-remote notice). Save failures toast and retry
  on the next edit.
- Sanitizer `_sanitizeHtml` — allowlist (b/i/u/em/strong/a[href https?]/
  ul/ol/li/p/br/div/code/sub/sup), attributes stripped except safe href
  (+ target/rel added); applied on SAVE and on RENDER (defense against a
  peer's bad paste).
- `_addNote` — order = max+1 (midpoint floats reserved for future
  insert-between), focus the new card when the snapshot lands.
- Voting: `_loadVotes` (one subcollection get per theme open) →
  `_voteCounts` + `_myVotes`; `_toggleVote` set-merge on own uid doc,
  local counts patched, list re-sorted. Vote button highlights when mine.
- Discussion: one `SECTION_COMMENTS.mount({container: #lt-discussion,
  collectionPath: 'labThemes/{id}/comments', scope: {theme_id},
  label: 'Theme discussion'})` per detail open; unmounted on close.

## Verification

1. Two browsers, same theme: A types in note 1, B in note 2 — both
   persist, both see each other live (~1 s).
2. Both in the SAME note: later blur wins; the focused client shows the
   "edited by X" notice instead of losing its caret; no crash.
3. Paste styled HTML / a script tag → sanitized on save and render.
4. Two users vote on papers: counts + "Start here" badges correct; own
   vote toggles off; writing another uid's vote doc is denied by rules.
5. Discussion thread posts/replies; delete restricted to author/admin.
6. Close theme / switch tab → no snapshot leaks (unsub verified).
