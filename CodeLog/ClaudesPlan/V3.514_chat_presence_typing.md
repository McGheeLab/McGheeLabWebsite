# V3.514 — Chat: presence dots + typing indicators

**Release 5 of 7** in the chat upgrade program. The biggest "feels
alive" gap vs Slack/Teams: no way to tell who's around or mid-reply.

## Design

**New collection `chatPresence/{uid}`** — one doc per user carries both
signals: `{ uid, lastActiveAt, typingChannelId|null, typingAt|null }`.
ONE collection listener (10–30 docs at lab scale) serves every presence
dot and the typing row.

Rejected alternatives (why a new collection):
- `chatUserMeta` is owner-only-READ in rules; widening it would leak
  sidebar layout / contacts / notification prefs to everyone.
- `users/{uid}` is world-readable AND live-subscribed by equipment.js /
  people.js / chat — heartbeat writes there would fan out to every open
  RM page and make presence public.

Rules addition (the release's one Firebase deploy):
```
match /chatPresence/{uid} {
  allow read: if request.auth != null;
  allow write: if request.auth != null && request.auth.uid == uid;
}
```

## Write cadence / cost

- **Heartbeat**: merge-write `lastActiveAt` every 2 min while the tab is
  visible + immediately on visibilitychange→visible. Buckets: online
  < 5 min (green), away < 30 min (amber), else no dot.
- **Typing**: on composer input, throttled to one write per 4 s; cleared
  on send / blur / channel switch / 8 s inactivity / destroy. Renderer
  shows entries with `typingChannelId === active && age < 8 s`; a 3 s
  re-evaluate timer expires stale entries without extra reads.
- Cost at lab scale (≈8 concurrent users × 4 h/day): ~1.5k writes +
  ~10k listener reads per day — well inside the free tier, pennies at
  worst. Mitigation levers if the lab grows: heartbeat 2→5 min,
  throttle 4→6 s.

## Implementation (rm/js/chat.js)

- `subscribePresence()` (registered in the R2 `_unsubs` registry),
  `writePresence()`, `heartbeatPresence()`, `startPresence()` (interval +
  visibilitychange), `writeTyping(channelId|null)`,
  `getPresenceBucket(uid)`, `renderPresenceDotHTML(uid, inline)`,
  `updatePresenceUI()`, `updateTypingRow()`.
- `updatePresenceUI()` toggles classes on `[data-presence-uid]` nodes IN
  PLACE — zero region re-renders (this is why R1's stable DOM came
  first). Called after sidebar renders and at the end of `render()`.
- **Dot placements**: sidebar DM rows, mobile overview DM rows, New DM
  modal, thread panel header avatar, and an inline dot in the channel
  header for 1:1 DMs (`.chat-avatar-wrap` + absolutely-positioned
  `.chat-presence-dot`).
- **Typing row**: `#chat-typing-row` sits between feed and composer in
  both the desktop content slot and the mobile chat tab. "Alex is
  typing…" / "Alex and Sam are typing…" / "3 people are typing…" with
  animated dots. Channel-level only (no per-thread typing).
- destroy() additions: heartbeat interval, typing timers,
  visibilitychange handler, best-effort `writeTyping(null)`.
- Typing clears on `selectChannel` so you never stay "typing" in a
  channel you left.

## Deploy

`firebase deploy --only firestore:rules` + FTP. (If deploying together
with R4, one rules deploy covers both — but respect R4's saturation
gate; the chatPresence block itself is safe to ship any time.)

## Verification

Two browsers/accounts: typing in A shows the row in B within ~1–4 s and
expires ~8 s after A stops; sending clears it immediately. A's dot is
green in B's sidebar; background A's tab >5 min → amber. Switching
channels while typing clears the indicator. Mobile: typing row visible
above composer; overview DM rows show dots. No dot flicker on sidebar
re-renders (classes toggled in place).
