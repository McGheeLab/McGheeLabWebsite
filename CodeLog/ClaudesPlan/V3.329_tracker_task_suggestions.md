# V3.329 — Tracker suggestions come from tasks, not page activity

## Why
User: "any page activity should not be a part of the list of activity
that is suggested. instead suggestions come from tasks."

The Daily view flagged entries with an empty `categoryPath` as
"uncategorized" and drove the "ML/AI Categorize (N)" prompt. Auto
page-time entries write an empty `categoryPath`, so page activity was
exactly what got suggested for categorization — wrong: presence isn't
loggable work. Suggestions should instead point at the user's real
tasks.

## Changes (rm/js/activity-tracker.js)

1. **Exclude auto-presence from the categorize suggestion.** New
   `_isAutoPresence(e)` = `source` starts with `rm-` (page-time +
   notebook/protocol/paper producers). Applied to `uncategorizedCount`,
   the ML-categorize loop, and `aiCategorize`'s uncategorized set.
   Manual / huddle / task / AI entries are unaffected.

2. **Task suggestion panel.** `loadTaskSuggestions()` (called from
   `loadData`) reads `tasks/buckets.json`, walks projects → buckets →
   subtasks (skipping `proj-inbox` / `buk-inbox-unfiled` and `proposed`
   items), and collects open subtasks assigned to the user (or
   unassigned) with the bucket's `category`, soonest-due first, capped
   at 12, into `_taskSuggest`. renderDaily shows an "open tasks" panel
   (hidden when a task is already logged today by text, or skipped this
   session); each row has "Log it" (creates a `source:'task'` manual
   entry with the bucket category mapped via `getCategoryPath`,
   duration 0 for inline entry) and "Skip". Mirrors the Huddle "Log it"
   pattern; wired in `wireDaily`.

## Notes
- Auto page-time entries still appear in the day's entry list and on the
  Overview heatmap (they're real activity) — they're just no longer
  *suggested* for categorization.
- Reads the existing `tasks/buckets.json` route; no rules/schema change.
