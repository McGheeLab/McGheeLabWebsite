# V3.309 — Library metadata editor + fetch-from-identifier diff

> Source: `CodeLog/Feature requests/FuturePlan_01_library_paper_reader.md` Release 2
> (moved into production 2026-07-11, immediately after V3.308).

## Goal

Any manually-loaded or failed-lookup paper can be repaired in place: edit
every metadata field, or paste a DOI/PMID/arXiv id and pull the authoritative
record with a per-field diff — from both the library list and the paper
reader.

## Problem

There is no metadata-edit UI at all. A paper that misses its lookup at
ingest keeps `title=filename`, empty authors, and `source:'manual'` forever;
the only "fix" is deleting and re-adding. The wishlist calls this out
directly ("when i load in a paper manually I have no way to edit the meta
data for it, and i cant even put in a doi so it can auto update everything").

Additionally, firestore.rules only lets **admin or first-author** update
`type=='paper'` items — and library entries never have `first_author_uids`,
so non-admin lab members can't repair (or even star) library rows.

## Approach

### New module rm/js/library-edit.js

`LIBRARY_EDIT.open(item, {onSaved})` — a self-contained modal:

- Form fields: title, authors (textarea, one `Family, Given` per line —
  `Given Family` accepted too), year, journal, journal ISO, volume, issue,
  pages, DOI, PMID, arXiv id, URL, tags (one per line), abstract (textarea —
  loads from and saves to the `items/{id}/details/main` extras subdoc via
  `LIBRARY_EXTRAS`, never the main doc).
- **Fetch from identifier**: uses the form's DOI → PMID → arXiv (first
  filled), runs `LIBRARY_METADATA.lookup` (V3.308 — works on prod), renders
  a per-field diff table: checkbox · field · current · fetched. Empty
  current + non-empty fetched → pre-checked; conflicts → unchecked.
  "Apply selected" copies into the form; nothing is saved until Save.
- **Save = targeted single-doc write** `items/{id}.set(payload)` with
  `updatedAt: serverTimestamp()` (the api adapter's cache probe keys off
  MAX(updatedAt), so other clients invalidate) and `updated_at` (display
  date). Never a collection rewrite. Abstract changes go through
  `LIBRARY_EXTRAS.savePatch`.
- `item.id` and `citation_key` never change implicitly (annotations key
  off the id). Opt-in "regenerate citation key" checkbox recomputes via
  `LIBRARY_METADATA.citationKey`. `meta.lead_author` is kept in sync with
  the first author (dashboard/CV consumers read it).
- The deep-copied item drops any adapter-injected `updatedAt` before
  rewriting it as a fresh serverTimestamp.

### Entry points

- `rm/js/library.js` `_renderRow`: ✎ edit button in the actions cell for
  every row + an inline "⚠ Fix metadata" button under the title when
  `source==='manual'` or authors are empty. `_onTableClick` handles
  `data-act="edit-meta"` → `LIBRARY_EDIT.open` → onSaved replaces the row
  in `_libraryPapers` and re-renders (no reload).
- `rm/js/library-paper.js` `_renderMetadata`: "✎ Edit metadata" button at
  the bottom of the sidebar metadata block; onSaved updates `_item` and
  re-renders the block.
- Script includes: `library-edit.js` added to library.html's
  `papersScripts` (before library.js) and to library-paper.html (with
  `library-metadata.js`, which the paper page didn't load before — needed
  for lookup + citationKey).

### firestore.rules — items update clause

Append one clause to the existing `items` update rule: lab members may
update a `type=='paper'` doc when it *is a library entry* and the write
neither touches `first_author_uids` (compared via `.get(...,[])` — the key
is normally absent on library entries) nor flips `type` /
`is_library_entry` (pinned so the doc can't escape paper governance).
Existing admin / first-author / non-paper clauses unchanged. This also
un-breaks starring for non-admin members. **Deploy rules before the FTP
push and test with a non-admin account** — this is the one
escalation-sensitive change.

## Data model changes

None (all fields already exist). Rules change only.

## Out of scope

Full DOI-driven refresh (Unpaywall PDF, SS re-enrich, ref re-parse) — that's
Release 3 (`fullRefresh`). The editor's fetch-diff touches metadata only.

## Release ritual

1. This plan doc. 2. `firebase deploy --only firestore:rules`. 3. FTP.
4. CHANGELOG V3.309 + ARCHITECTURE + CACHE_VERSION 280.

## Rollback

Client: git revert + re-FTP + CACHE bump. Rules clause is additive —
revert + redeploy restores admin/first-author-only writes; nothing breaks.

## Verification

- Non-admin member on prod: open a `source:'manual'` row → ⚠ Fix metadata →
  paste DOI → Fetch → diff shows pre-checked empty fields → Apply → Save →
  row updates in place; reload confirms persistence; annotations still
  attach (id unchanged).
- Star a row as non-admin (was rules-blocked before) — now persists.
- Attempt to include `first_author_uids` in a member write (devtools) → rules
  reject. Admin editing still works. Guest account: modal save rejected.
- Paper reader sidebar: ✎ Edit metadata opens the same modal; saved changes
  re-render title/subtitle immediately.
