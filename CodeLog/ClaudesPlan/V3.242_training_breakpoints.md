# V3.242 — Training breakpoint standardization (Phase 3b housekeeping)

> Final housekeeping ship of the mobile-compatibility plan. After V3.241 (desktop-only interstitial) closed Phase 4, the master plan still listed `training.css` as carrying 7+ scattered non-canonical breakpoints — leftover from before V3.232's two-breakpoint discipline (640 phone / 1024 tablet). V3.242 standardizes them.

## What changed

10 non-print `@media` queries in `rm/css/training.css` rounded to the canonical 640/1024 set. Old breakpoints: 420×2, 520, 600, 720×3, 820, 900×2.

| Line | Selector | Was | Now |
|---|---|---|---|
| 371 | `.scenario-bar` flex-column | 420px | **640px** |
| 387 | `.panel` 1fr collapse | 900px | **1024px** |
| 466 | `.chart-row` 1fr | 720px | **640px** |
| 584 | `.training-layout` 1fr + TOC static | 900px | **1024px** |
| 831 | `.arc-controls` compact range sliders | 600px | **640px** |
| 1120 | `.voice-grid` 1fr | 720px | **640px** |
| 1256 | `.triangle-layout` 1fr | 820px | **1024px** |
| 1353 | `.assessment-row` 1fr+36px | 520px | **640px** |
| 1385 | `.milestone-timeline` 2 cols | 720px | **1024px** |
| 1388 | `.milestone-timeline` 1 col | 420px | **640px** |

The `.milestone-timeline` pair preserves its 3-tier waterfall (5 cols desktop → 2 cols tablet → 1 col phone) by mapping 720→1024 and 420→640 in sync. A comment is added explaining the intent so future passes don't accidentally collapse the two-step waterfall into one rule.

## Behavior changes

Most rules tighten the phone/tablet edge slightly:

- **Phone (≤640px)**: every rule that fired in 521-720px now fires at ≤640px. `.scenario-bar`, `.chart-row`, `.voice-grid`, `.assessment-row` collapse a bit earlier on the largest phones (e.g. iPhone 14 Pro Max landscape 932px — never affected; iPad mini portrait 744px — now stays 2-col instead of collapsing). Acceptable; large phones in landscape don't need the aggressive collapse.
- **Tablet (641-1024px)**: rules at 820/900 now fire at the standard 1024 — broader tablet support. `.panel`, `.training-layout`, `.triangle-layout` collapse on iPad Pro 11" portrait (1194px wide — still desktop) but trigger on iPad standard portrait (1024px — now collapses).
- **`.milestone-timeline` on iPad portrait** (1024px) loses its 5-column desktop layout and becomes 2 cols. This is the one place where tablet density drops noticeably. Acceptable trade-off: 5 milestones across 1024px = ~200px per card with gap — workable but cramped. 2 cols at ~500px each is roomier and matches the V3.233 "tablet is a real target" theme.

## Verification

1. **No remaining non-canonical training.css breakpoints** — `grep "^@media\|@media (" rm/css/training.css | grep -v print` returns only 640 and 1024 (plus the `@media print` rule).
2. **`.milestone-timeline` 3-tier still works** — `grid-template-columns` cascade: base 5, ≤1024 → 2, ≤640 → 1. Tested in DevTools at 1280 / 900 / 500 px viewport widths.
3. **No CSS brace imbalance** introduced — every edit was a value-only swap on a `@media (max-width: Npx) {` line.
4. **Other training rules unchanged** — `.training-layout` collapse, `.panel` grid, `.chart-row`, etc. retain their bodies; only the `@media` `max-width` value changed.

## Out of scope

- **Other page-specific CSS files** (chat.css 600/700/400; equipment.css 768; lab-notebook.css 720; meetings.css 700; procurement.css 700; scheduler.css 600; activity-tracker.css 700) still carry their own non-canonical breakpoints. The mobile-compatibility plan is now in maintenance mode — each gets standardized when its page is rewritten, not on a separate breakpoint-cleanup pass.
