# V3.648 — No browser input popups in the paper writer

Alex, on the V3.647 inline-value flow:

> "when i make a new value inline, i dont want the options to be popups from
> the browser, it want all the options to be in the 'insert a value' menu that
> drops down. **Never have an input popup anywhere i hate it**"

V3.647 made *defining* a value inline possible, but it did it by chaining
`window.prompt()` boxes — key, then number, then unit, then sig-figs, then
note. Five modal interruptions, no way back, no field visible while answering
the next one, and validation delivered as an `alert()`.

## The build

### One primitive: form mode on the existing picker

`_openPicker` in `paper-equations.js` already owned a positioned dropdown with
search, keyboard nav, Esc-to-close and outside-click dismissal. Rather than
add a second popover implementation, it grew the ability to **swap its list
for a declarative multi-field form**:

```js
handle.showForm({
  title, fields: [{ key, label, value, placeholder, hint }],
  note,                              // prose above the fields; with fields:[]
                                     // this is a confirm panel
  submitLabel, backLabel, danger,
  validate(vals) -> null | { field, message },
  onSubmit(vals, handle),
})
```

Three seams make it work in both directions:

- **`entry.keepOpen`** — `pickIdx` no longer closes the popover for such a
  row; it hands `handle` to `onPick`, which calls `showForm`. The "＋ New …"
  rows use this, so the form appears **in the dropdown the writer already had
  open** rather than on top of it.
- **`opts.form`** — opens straight into form mode with no list behind it.
  That is how page-level buttons (the Values page's add / edit / delete) get
  the same editor without a browser dialog.
- **Errors land in the form**, next to the field that caused them, and focus
  that field. That is the whole point of not being an `alert()`.

Keyboard: while the form is up it owns the keys — Enter saves, Esc steps
**back to the list** rather than discarding half-typed input, and the arrow
keys stop moving a list the user cannot see. A second Esc closes.

Layout detail worth keeping: only the *fields* scroll. The error line and the
buttons are pinned below them. The first cut had the whole form in one
`overflow-y: auto` box, and a five-field form is taller than the popover — so
the Save button sat below the fold of an inner scroll pane. A screenshot
caught it; nothing in the assertions would have.

### paper-values.js: one form definition, three callers

`formSpec(kind, existing, seedKey)` / `validateForm` / `applyForm` replace the
prompt chain. Splitting *describe* from *apply* lets the picker
(create-and-insert) and the Values page (add / edit in place) share one
definition so they cannot drift.

Validation gained something the prompts never had: a **duplicate-key check**.
Two entries answering to the same token silently shadow each other at render
time, so it is caught at the field.

Every remaining browser dialog in the module went too:
- `+ Text value` / `+ Number & unit` / `Edit` → the form, anchored under the
  button that was clicked.
- The inventory flows asked for a key in a prompt after you picked a row →
  now the same form, seeded from the item's name, with the print-format field
  alongside it.
- `alert()` → corner toast (`TOAST.warn` / `TOAST.error`).
- Delete's `window.confirm` → a `danger` panel built from the same primitive.
  **The guard stays** — a key in use is load-bearing and the usage count is
  the thing worth reading before agreeing — it just is not a browser box.

### The rest of the writing flow

The same treatment for the prompts Alex would hit next while writing:

- **`+ Note` (footnote insert)** — `paper-equations.js`.
- **Clicking a footnote chip to edit it** — `paper-editor.js`. Clearing the
  field and saving removes the footnote, as before.
- **Table column width in mm** — `paper-equations.js`. The select is now put
  back to its previous value before the form opens, so cancelling never
  leaves the dropdown claiming a width the column does not have.

not a bug fix, and is listed here so it is not mistaken for finished:

## Verification

`scripts/tests/v3647-selftest.html` grew to **51 assertions**;
`v3647-caret.html` to **18**. Both stub `window.prompt` / `alert` / `confirm`
to record-and-refuse, so a regression to a browser dialog is a hard failure
rather than a hung headless run — and both assert the recorder stayed empty.

Driven against the **real** picker, not a stub: the form replaces the list in
the same popover; the list and search box hide; the title changes; every
option that used to be a prompt is a labelled field; the key is pre-filled
from the search text; a bad number is reported in the form and writes nothing;
saving writes every field and inserts the token; Esc goes back to the list and
a second Esc closes. The footnote case clicks a real rendered chip on a real
`bindYTextToContentEditable` paragraph and asserts the source text after save.

Also checked by screenshot — the field layout, the pinned buttons, the inline
error, the list mode, and the red delete panel.

Regression: V3.646 selftest 18/0, V3.646 UI journey 42/0, label-id parity
35/0, `gen-icons --scan` clean.
