# V3.60 — Page consolidation Tier 3b: paper-builder + paper-editor merge

## Goal

Tier 3b of the V3.57–V3.62 sweep. The Papers list page and the
per-paper Yjs collaborative editor live as separate pages
([rm/pages/paper-builder.html](../../rm/pages/paper-builder.html) and
[rm/pages/paper-editor.html](../../rm/pages/paper-editor.html)). Merge
them into a single page where the presence of `?paper=<id>` switches
to editor mode. Reduce 2 pages → 1.

## Approach

Same dual-block pattern from V3.59 (Library / Comments). The
shell embeds **both** DOM blocks (`.paper-list-mode` and
`.paper-editor-mode`); CSS hides the inactive one; only the active
mode's renderer scripts load.

### Why `?paper=<id>` instead of `?tab=editor`

The id needs to be in the URL for the editor to know which paper to
load (the renderer reads it via `URLSearchParams.get('paper')`). Using
the same param for both the mode switch AND the paper id is cleaner
than `?tab=editor&paper=<id>` — one param does both jobs.

### Why a JS redirect for paper-editor.html instead of `<meta refresh>`

Old bookmarks like `paper-editor.html?id=foo` need to land on
`paper-builder.html?paper=foo`. A `<meta refresh>` URL is static —
can't carry the id through. A small inline `<script>` reads
`?id` from `location.search`, builds the new URL, and uses
`location.replace` to redirect. Bookmarks survive without a redirect-
loss step.

The renderer also accepts `?paper=` (new) or `?id=` (legacy) so even
direct hits to `paper-builder.html?id=foo` (which shouldn't happen
but might from in-browser typed URLs) load the right paper.

## Files modified

- **Rewritten:** [rm/pages/paper-builder.html](../../rm/pages/paper-builder.html) — unified shell. Was 80 LOC for the list-only page, now ~145 LOC including the embedded editor DOM and the per-mode script loader.
- **Replaced with JS redirect:** [rm/pages/paper-editor.html](../../rm/pages/paper-editor.html) → `paper-builder.html?paper=<id>` (carries the id over from `?id=` legacy form).
- **Changed:** [rm/js/paper-editor.js:23](../../rm/js/paper-editor.js#L23) — accepts `?paper=` or `?id=`.
- **Changed:** [rm/js/paper-builder.js:63,184](../../rm/js/paper-builder.js) — list-card link and post-create navigation point at `paper-builder.html?paper=<id>`. Header doc-comment updated.
- **`sw.js`** — CACHE_VERSION 34 → 35.

## Untouched

- **Both renderers' main code** (`paper-builder.js` 209 LOC,
  `paper-editor.js` 2181 LOC) — only the URL-reading + URL-emitting
  sites changed. The Yjs CRDT layer, comments pane, autosave
  indicator, outline sidebar, all unchanged.
- **`rm/css/paper-editor.css`** (567 LOC) — already covers both `.pb-*`
  list classes and `.pe-*` editor classes; the unified shell uses both
  selectors as-is.
- **Firestore paths** — `papers/{paperId}/draft` (Yjs CRDT) and
  `papers/{paperId}/comments` are unchanged.
- **`rm/js/nav.js`** — Research → "Papers" link still points at
  `paper-builder.html` (the new unified shell). No change.

## Trade-offs

- **Both DOMs in HTML adds ~85 LOC of static markup** that never
  renders on the inactive mode. Same trade-off as V3.59. Acceptable.
- **The new-paper modal lives inside the `.paper-list-mode` block**.
  When in editor mode, the entire `.paper-list-mode` div is
  `display: none` — the modal is hidden too, which is what we want.
- **KaTeX CSS link** is loaded eagerly (cost: one CSS request). The
  KaTeX JS module is still lazy-loaded by paper-editor.js when needed.
- **Old `paper-editor.html?id=foo` bookmarks** redirect through one JS
  step. Slight cost vs `<meta refresh>` (which would lose the id), but
  preserves user's existing bookmarks.

Smoke flow:

1. Open `paper-builder.html` (no params) → list view loads. Tab bar
   not shown (this page doesn't have one — list/editor switch is
   navigation-driven, not tab-driven). DevTools → Network shows
   `paper-builder.js` loaded; **NOT** `paper-editor.js` / `paper-yjs.js`.
2. Click a paper card → URL becomes
   `paper-builder.html?paper=<slug>`, page reloads, editor mode
   renders. DevTools → Network shows `paper-editor.js`, `paper-yjs.js`,
   `paper-blocks.js`, `paper-export-tex.js`; **NOT**
   `paper-builder.js`.
3. From editor, "← All papers" link → `paper-builder.html` (no query)
   → list view.
4. Hit `paper-editor.html?id=<slug>` directly (legacy bookmark) →
   redirects to `paper-builder.html?paper=<slug>`. Editor renders the
   right paper.
5. Hit `paper-builder.html?id=<slug>` directly → editor renders the
   right paper (legacy `?id` fallback path in paper-editor.js).
6. From dashboard.js Papers card → goes to `paper-builder.html` →
   list view (unchanged).
7. New paper flow: click "+ New paper" → modal opens → fill form →
   Create → page navigates to `paper-builder.html?paper=<new-slug>`.
8. DevTools → Application → Cache Storage shows
   `mcgheelab-shell-v35`.
