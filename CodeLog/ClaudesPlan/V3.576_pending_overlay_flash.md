# V3.576 — Fix the "pending access" overlay flashing after sign-in

## Goal

On a fresh sign-in the app lands on My Day, then briefly shows the
full-screen "your account is still pending lab access — reach out to the
PI" overlay before settling. For an actual lab member / admin that screen
should never appear. Remove the flash.

## Problem

`rm/js/firebase-bridge.js` gates guests behind a full-screen overlay
(`_renderPendingOverlay`), driven by `_updatePendingOverlay()`:

```js
if (_profile.role === 'guest') _renderPendingOverlay();
else _removePendingOverlay();
```

The `users/{uid}` doc is **public-read** (`allow read: if true`) and
`isLabMember()` is `role != 'guest'`, so `_loadProfile()`'s server `.get()`
reads the member's real role reliably. But `_attachProfileLiveSync()`
subscribes with `onSnapshot`, and Firestore can deliver a **cached**
snapshot first:

- a stale `users/{uid}` doc from a prior session whose cached copy has
  `role:'guest'`, or
- the brief window where `profile-bootstrap` has just created the
  `role:'guest'` doc and `refreshProfile()` hasn't yet re-read the
  admin-promoted copy.

On that transient the old code rendered the overlay immediately, then
removed it a beat later when the server doc (real role) arrived — a
visible flash right after sign-in.

## Approach

Debounce the overlay. In `_updatePendingOverlay()`:

- signed out → clear timer + remove overlay;
- profile still loading (`!_profile`) → clear timer, decide later;
- role **not** guest → clear timer + remove overlay (this is the branch
  that fires when the settled server profile arrives, so nothing shows);
- role **is** guest → if not already shown/scheduled, schedule the render
  after a **3 s settle**; when it fires, re-check the role is *still*
  guest before rendering.

Any subsequent `_updatePendingOverlay()` call with a non-guest role cancels
the pending timer, so a member/admin never sees the overlay. A genuine
guest still gets it, 3 s after sign-in. `firestore.rules` remains the true
access gate (a guest reads no lab data during the grace window), so the
delay leaks nothing.

New module-scope `_pendingOverlayTimer` + `_clearPendingTimer()` helper.

## Files

- `rm/js/firebase-bridge.js` — `_pendingOverlayTimer`, `_clearPendingTimer()`,
  rewritten `_updatePendingOverlay()`.

## Data model / rules

None. No Firestore, rules, index, or function change.

## Out of scope

- Reworking `profile-bootstrap`'s create-then-refresh (the debounce covers
  its window; a `merge:true` guest write can't clobber an existing role
  because bootstrap only runs when `_loadProfile` returned `profile: null`,
  i.e. the doc genuinely doesn't exist under the public-read rule).
- A dedicated "confirming access…" interstitial (the debounce is enough;
  My Day already renders normally for a confirmed member).
