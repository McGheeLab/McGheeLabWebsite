# V3.584 — Voice call answer surface (inline ring banner)

## Goal

V3.525's voice call notifies callees (FCM push + green header 📞), but
there is **no surface to answer or decline** — the callee has to know to
click the tiny header button. Add an inline banner in chat: "**{name} is
calling · #channel — [Join] [Decline]**".

## Approach

**Banner placement (inline with the chat chrome):**
- Desktop: first child of `.chat-sticky-top` (above the channel header)
  — pinned, always visible, and `updateStickyOffsets()` already measures
  the sticky block so date separators shift down automatically.
- Mobile: `#chat-callring-slot` between the tab bar and
  `#chat-mobile-content`.
- Shows for ANY answerable call in a channel the user belongs to, not
  just the active channel (you're being called — you shouldn't have to
  already be looking at that conversation). Join from another channel
  `selectChannel()`s there first, then joins.

**Ringing lifecycle:** banner pulses ("X is calling") for the first 60s
(`CALL_RING_MS`), then calms to "X started a call" with the same
Join/Decline (doubles as a call-in-progress surface, and neutralizes
ghost call docs from crashed solo callers — calm, dismissible). One
`setTimeout` re-render at the ring-window edge; no polling.

**Model (voice-call.js owns it):**
- `getIncomingCalls()` — active calls minus: the call I'm in, calls I
  started, calls whose `declinedUids` contains me, calls I dismissed
  this session. Channel-membership filtering stays in chat.js
  (`amRecipientOfCall`: DM `members[]` / channel `subscriberUids[]`,
  falling back to `_userMeta.subscribedChannels` — mirrors who the FCM
  push targets).
- `decline(channelId)` — sessionStorage dismissal (keyed to the call's
  `startedAt` millis so a NEW call in the same channel rings again)
  + `declinedUids: arrayUnion(uid)` on the call doc (stops ringing on
  the user's other tabs/devices; caller-side "declined" UI possible
  later). Covered by the existing lab-member update rule — **no rules
  change**.
- `open()`/`leave()` now `emitChange()` — joining an existing call
  doesn't touch the call doc, so the banner needed a local event to
  hide; leaving also locally dismisses that call instance so you aren't
  re-rung by the call you just hung up on.

## App parity (Ourlab mobile — same release)

The Capacitor app bundles this rm/ tree offline (`sync-rm.mjs`), so the
whole feature rides the next app build. App-specific pieces:

- **`OurlabMobile/ios/App/App/Info.plist`** — `NSMicrophoneUsageDescription`
  added. Without it, iOS TCC-kills the app the instant `getUserMedia`
  runs. WKWebView getUserMedia needs iOS 14.3+; the app targets 15.0.
  The OS mic prompt fires automatically on first Join — no plugin needed.
- **`OurlabMobile/android/.../AndroidManifest.xml`** — `RECORD_AUDIO` +
  `MODIFY_AUDIO_SETTINGS` (Capacitor's WebChromeClient routes the page's
  mic request through the runtime dialog when declared).
- **`rm/js/mobile-shell.js`** — `body.ourlab-app #vc-panel` bottom offset
  `calc(72px + safe-area)` so the call panel floats above the app's
  bottom tab bar (`.md-composer` precedent). No-op on the web.
- **`rm/js/voice-call.js`** — capability guard before `getUserMedia`:
  a missing `navigator.mediaDevices` (old webview / non-secure context)
  now says "not available in this app view" instead of the misleading
  "access denied" toast.
- **Ring push**: `onVoiceCallCreate` → `sendToUsers` → `users/{uid}/pushTokens`
  — mobile-push.js registers native tokens in the same collection and
  deep-links taps, so app users ring through the existing pipeline.
- `www/` re-synced (91 pages). **Build/upload deliberately NOT done from
  this session** — a parallel session owns the next TestFlight push; its
  `npm run build` re-syncs and picks all of this up.

## Verification

1. Two browsers, user A and B sharing a DM. A clicks 📞. B (on the chat
   page, any channel) sees the pulsing banner within ~1s; Join connects
   audio and switches B to the DM; banner disappears for B.
2. Decline instead: banner disappears, `declinedUids` gains B's uid in
   Firestore, banner does NOT reappear on B's reload (same call), and
   A hanging up + calling again DOES re-ring B (new `startedAt`).
3. Wait 60s without answering: banner stops pulsing, text flips to
   "started a call", Join still works.
4. B in a call in channel X while a call starts in channel Y: Y's banner
   shows; Join hangs up X (open() leaves first) and joins Y.
