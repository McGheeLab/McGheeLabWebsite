## What deleted it (from the code; the hub read was refused in auto mode)

The V3.899 share relay copies a shared project into each member's hub and treats a shared record MISSING from a
collaborator's hub as that collaborator deleting it — on a live push (`inbound`) and in the hourly safety pass
(`sharePass` step 1, which compares each member's hub with their shadows). Gabe's desktop sync can empty his hub of the
copies (scientia-cloud.py replaces the side whose sid changed; a first run with `--prefer local` replaces the cloud with a
desktop that never had them), so the relay deleted Alex's originals within the hour. The lit review was not in the
shared project, which is why it survived. `scripts/scientia-project/hub-deletions.js` (read only) reads the tombstones
(`dev`, `name`, `seq`) to confirm the device and time; Alex runs it.

## Fix

`inbound()` (`functions/scientia-share-core.js`): a collaborator's deletion reaches the owner only for a record that
came from them (the owner's row was last written by `share:<their uid>`), and never for the share's root (the project or
review itself); anything else they lost is put back in their hub (`fanOut` to that member). Covers both paths. Four
fixtures in `functions/test/scientia-share.test.js` (fail on the old relay, pass now): a desktop that empties a
collaborator's hub, deleting the shared project, the hourly pass, and a collaborator deleting their own note (still
allowed). scientiaHub health V3.923. Needs `firebase deploy --only functions:scientiaHub` (refused for me; Alex runs it,
before the project is shared again).

4. **The parameter set** — instrument and optics / detector and read / assay and plate: each value with its source

No wires inside the note: Scientia loops a vertical wire out by its span, and the parameter set sits thousands of pixels
from what sets it and what tests it (first render: 30 long arcs). The parameter lines carry the provenance instead.

  per objective (the % where the signal falls 5 % below the slope-1 line, the same at every level, or it is the detector) and
  the responsivity k = DN per MESF per %. Model-based: the µW-equivalent per % = (k / DN per photoelectron) / (simulator
  photoelectrons per PE per frame per µW, ≈0.09 at 20x/0.80, 2 µs, 0.43 µm), ±30–50 % from the collection and QE constants.
  Session check = the MESF wells at the operating % at the start and end (within 5 %).
- **Exp 10**: the MESF beads ARE the calibration of the bead standard — signal → MESF per bead with each plate's own MESF wells,
  read exactly as the capture beads; geometry transfer (simulator) or a 5-plane sum if size or label geometry differ; flow
  cytometry only as a cross-check. Exp 12's curve is in MESF per bead (one curve per analyte and lot; the paper's TF1→TF2→TF3).
- Every "µW at the sample" elsewhere (Exp 02, 04, 05, 07, the simulator hints, the set-up diagrams, the note) is the MESF
