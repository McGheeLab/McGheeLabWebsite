## New scanners (rm/js/paper-citations.js `_matchItemsOnPage`)

- **Ref-word numerics** (`numeric:refword`): `Ref. 12`, `Refs. 12–14`,
  `reference 3`. Rides the bracket family for detection; passes gating in
  EVERY numeric family (unambiguous prose mention); ref-validated like all
  matches.
- **Flattened superscripts** (`numeric:flat-super`): digit runs glued to a
  word tail (`cells12`, `shown3,7`) — how some PDFs export superscripts at
  body height. Triple-gated: enabled per scan only when the detected
  family is super/none AND refs exist (`scanOpts.flatSuper`, set by
  `_flatSuperOpts()`; style detection runs flat-BLIND so the scanner can't
  vote for its own family); the glued word must end lowercase (rejects
  STAT3/CDK4 gene symbols); years and glued ranges excluded; downstream
  ref validation. Watch its precision in the audit before trusting it.
- **Year-letter lists** (`authoryear:multiyear`): bare suffixes in
  `(Smith et al., 2020a, b)` → `2020b`; comma-required + boundary-
  terminated so ", and" can't fire.
- **Corporate author-year** (`authoryear:corporate`): the whole-group
  RE_AY_INNER gate becomes a cheap year gate, and non-standard segments
  like `(WHO, 2020)` / `(The UniProt Consortium, 2019)` emit the phrase's
  LAST word as the surname candidate — matching Semantic Scholar's own
  surname extraction, so `_matchedRef` resolves real ones and validation
  drops the rest.
- Superscript-bracketed `word^[12]` needs no new scanner — V3.335's
  tiny-run merging + gap joining reassemble it for the bracket scanner.

## Tuning state (was R5)

- Style thresholds: link short-circuit at ≥50% ref coverage (V3.335);
  textual families need ≥3 validated hits, two families within 20% →
  mixed (both gated in). Revisit only with audit evidence.
- **Backlog** (fixtures = papers the audit flags): ligature-damaged author
  names (not 1:1-normalizable — needs a lookup-side alias, not scan-side);
  page-granular link dests (no y → first entry of page; ordinal alignment
  fallback unimplemented); scanned PDFs with no text layer (OCR out of
  scope); `_pickFamily` per-family thresholds if flat-super precision
  disappoints (per-paper opt-out flag is the escape hatch).
