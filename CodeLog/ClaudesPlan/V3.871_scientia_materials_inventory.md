## What this version does (web build only; `scientia/src` untouched)

- **The note's "+ material" picker** (`MATS.pick`) opens with *From the lab inventory* — a search box over RM's
  inventory through the hub — above *Your materials* (Gabe's resource notes). Picking an inventory item **finds or
  makes the resource note for it** (`inventoryId`, `rm: true`, `header.kind` guessed from RM's category, supplier,
  catalogue number, first location) and links it on the note exactly as Gabe's picker does. Actions: *Done*,
  *+ New material (note)* (his), *+ Add to the lab inventory* (RM's inventory page).
- **The Materials page** keeps Gabe's page (lots, passages, the barrier axis) and adds *The lab inventory* above it:
  search, then *Make a material note* (creates or opens the resource note and goes to its sheet) or *Open in RM*.
- **The material sheet** (`#/mat/<id>`) of a note made from an item carries *In the lab inventory* with *Open in RM*
  and *Log a use in RM* (`inventory.html?item=<id>` — RM's own dial, ledger and user-actions do the logging; the
  notebook never writes stock).
- An item already in your materials says *in your materials*; picking it again reuses the same note.

## Design

### Hub: `GET api/rm/inventory?q=&limit=&ids=`

RM's inventory is one Firestore collection of ~3,500 docs (items and chemicals, `kind` discriminator), about a
megabyte on the wire. The function keeps a **compact list per instance** (`FirestoreHub._inv`, ten minutes;
`rmInventoryRow`: id, kind, name, description, category, subcategory, vendor, catalogue_number, quantity,
stock_status, condition, use_mode, is_consumable, locations (list or map keys), updatedAt; retired / disposed
dropped) and **searches server-side** (`searchInventory`: every word must match name + description + vendor +
catalogue + category + subcategory; name-prefix matches first, then newest; `limit` ≤ 200, default 40). A keystroke
costs one small response. Nothing is written. `MemoryHub.inventory` serves `hub.rmInventory` for fixtures.

Why not log usage from the notebook: RM's scan-to-use (`inventory-use.js` + `inventory-qty.js` + `user-actions.js`)
is a ledger with per-use / package modes, measures, and attribution — one code path, reached in one tap from the
note. Re-implementing it server-side would be a second ledger. The V3.866 plan's "used 2 coverslips logs usage
through RM's actions" is met by the link, not by a write.

### Lab mode (`rm/scientia/lab-mode.js`, section 5)

- `inventory(q)` — `fetch('api/rm/inventory?q=…')` through the shim (signed), cached two minutes per query.
- `kindFor(item)` — chemical → `chemical`; antibody / cell line / plasmid / medium / instrument / gel batch /
  reagent by category, subcategory and name; else `other` (the keys of Gabe's `MATKIND`).
- `resourceFor(item)` — the resource note with that `inventoryId`; `useInventory(item, d)` — find or
  `M.createDoc({type: 'resource', …})` + `inventoryId`, link on `d.materials`, `M.touchDoc`, `changed()`.
- `invSearch(onUse, label, opts)` — the shared search block (input, note line, `.opts` rows with *Use…* /
  *Open in RM*), debounced 160 ms, ignores a stale response.
- `MATS.pick` replaced (the original kept at `MATS.pick._orig`); `VIEWS.materials.render` wraps Gabe's and inserts
  the card after the stand-first paragraph; `VIEWS.mat.render` wraps the sheet and prepends the RM line.
