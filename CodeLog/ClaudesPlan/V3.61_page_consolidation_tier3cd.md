# V3.61 — Page consolidation Tier 3c + 3d: cv-overview → cv-editor tab, important-people → people tab

## Goal

Tier 3c + 3d of the V3.57–V3.62 sweep, bundled into one PR. Two more
separate pages collapse into tabs of their primary sibling. Reduce 4
pages → 2.

## Approach

Identical dual-block / per-tab `document.write` pattern from V3.59 +
V3.60. Both shells embed their two DOM variants; CSS hides the
inactive one based on a `<html data-X-tab>` attribute set in the early
head script; only the active tab's renderer scripts load.

### CV merge

- [rm/pages/cv-editor.html](../../rm/pages/cv-editor.html) becomes
  the unified shell. Tabs: `My CV` (default) / `Lab Overview`.
- `?tab=lab` → loads `cv-overview.js` (203 LOC). Lab-wide read-only
  table.
- Default → loads `cv-importers.js` + `cv-export.js` +
  `cv-editor.js` (680 LOC). Personal editor.
- Both blocks share the `<div class="page">` wrapper; the editor
  modal (`#cve-modal`) lives inside `.cv-mine-block` so CSS hides it
  automatically on the lab tab.

### People merge

- [rm/pages/people.html](../../rm/pages/people.html) becomes the
  unified shell. Tabs: `Lab Roster` (default) / `Important People`.
- `?tab=important` → loads `important-people.js` (410 LOC, with its
  own four sub-tabs Regents/Donors/Initiatives/Collaborators).
- Default → loads `people.js` (361 LOC). Lab roster.
- The two renderers both query `#tabs` and `#content`. Since only
  one is loaded per page hit, no conflict. The inner containers
  (`#tabs` / `#content` / `#context-area` / `#filters`) are shared
  in the DOM. CSS hides `#context-area` + `#filters` on the roster
  tab so empty containers don't leave gaps.
- The `.dossier-*` / `.convo-*` / `.relevance-badge` /
  `.context-banner` / `.filter-*` styles from former
  important-people.html are inlined into the unified shell's
  `<style>` block (~80 LOC; scoped, harmless on the roster tab).

### Why merge cv-overview into cv-editor instead of vice versa

Both renderers are similar size (203 vs 680 LOC). The `cv-editor.html`
shell is the more complex one (modal, sidebar, layout grid). Keeping
it as the host means less HTML rewriting; the lab-overview content is
just `<div class="page-header"> + <div id="content">` which embeds
trivially.

### Why merge important-people into people instead of vice versa

Same reasoning. people.html is the simpler shell; important-people
has the dossier styles + extra containers. The unified shell hosts
both; the dossier styles are scoped to `.dossier-*` selectors that
only exist in the important-tab DOM (rendered by
important-people.js).

  - Lab Admin group: "Important People" repointed to `people.html?tab=important`.
- **Changed:** [rm/js/dashboard.js:406](../../rm/js/dashboard.js#L406) — CV Status card href updated to `cv-editor.html?tab=lab`.

## Untouched

- **All four renderers** (`cv-editor.js`, `cv-overview.js`,
  `people.js`, `important-people.js`) — unchanged. Each one's
  `DOMContentLoaded` boot fires at the natural time and finds its
  expected DOM elements.
- **CV-related Firestore paths** — `cvData/{uid}` reads/writes
  unchanged.
- **People-related Firestore paths** — `people/*` and
  `important-people/*.json` reads unchanged.
- **`rm/pages/career.html`** — stays separate. PI tenure dossier is
  distinct PI-only data.

## Trade-offs

- **CV editor's old separate "+ Edit My CV" button** in cv-overview.html
  → user now switches via the tab bar instead. Slightly less
  prominent but no functional loss.
- **CV editor's `cve-*` styles** stay in the unified shell; they're
  ~50 LOC of inline CSS that always loads. No big deal — they only
  apply to elements with `.cve-*` classes which only exist in the
  My CV tab DOM.
- **People's inner `#tabs` + `#content` + `#context-area` +
  `#filters` containers shared between renderers** — only one
  renderer is active at a time so there's no DOM-element collision.
  But it's a small "be careful here" footnote: a future renderer
  edit that renders into these IDs from a different code path could
  conflict.
