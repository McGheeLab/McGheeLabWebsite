# V3.483+ — Reference-import workflow (references → library → cited in the editor)

> Parse a paper's references (BibTeX or a DOI list) into **library citation
> entries**, then **attach + cite** them from the paper editor so `[@key]`
> resolves and the bibliography auto-generates. Two surfaces share one parser.

## Why (the model, confirmed by exploration)

- The library **already** supports citation-only entries (no PDF):
  `LIBRARY_METADATA.buildPaperItem(meta, null, null)` — exactly what the
  existing "Add by DOI" button creates. **No `meta.library` schema change.**
- The editor resolves `[@key]` by **string-match against the whole library**
  (`loadCitationIndex`/`_loadFullCitations` → `byKey[citation_key]`) and
  auto-generates the bibliography at compile (`buildBibtex` → `references.bib`
  → `\bibliography{references}`). A `references`-kind section body is
  **skipped** on export — so flat reference paragraphs never become the bib.
- **Gaps this fills:** (1) no bulk references→library importer; (2) citation
  keys aren't collision-safe (`citationKey` can repeat → `byKey` last-writer
  drops a paper); (3) no "map numeric [N] markers to [@key]".

## Decisions (from Alex)

- **Surfaces:** BOTH — a library-page bulk importer AND a paper-editor
  import-and-attach, sharing one parser/ingest core.
- **Input:** **BibTeX (.bib)** paste/upload + **DOI list** (one id/line;
  DOI/arXiv/PMID). (No free-text-citation parsing.)
- **Numeric markers:** **auto-rewrite `[N]`, `[N, M]`, `[N–M]` → `[@key]`** in
  the editor flow, mapped by import order. Verified 1:1 before applying.

## Architecture

### NEW `rm/js/reference-import.js` — `window.REFERENCE_IMPORT` (core + shared dialog)

Pure/logic (unit-tested headlessly):
- `parseBibtex(raw)` → `[{title, authors:[{family,given}], year, journal,
  volume, issue, pages, doi, arxiv_id, source:'bibtex'}]`. Own BibTeX→unified
  parser (the field regex mirrors `cv-importers.js:170-180`, but emits the
  `meta.library` author shape `{family,given}` and keeps the entry `@key` as a
  key hint). LaTeX-cleaned.
- `parseDoiList(raw)` → `[{id, kind}]` — one identifier per line; tolerant of
  `https://doi.org/…` prefixes, `arXiv:` / bare `10.` / numeric PMID; strips a
  leading `[n]`.
- `resolveDois(ids, {onProgress})` → unified[] via `LIBRARY_METADATA.lookup`
  (sequential, throttled, **partial-tolerant** — a failed lookup yields a stub
  `{doi, source:'doi', _error}` kept in order so numeric mapping never shifts).
- `dedupeAndKey(unified[], existingItems)` → `{ entries:[{meta, status:'new'|
  'existing', existingId?, key}], keyByOrder:[key,…] }`. Dedup by lowercased
  DOI, then arxiv_id, then normalized title (reuses the `cv-importers.js:260`
  `findDuplicates` idea). **Collision-safe keys:** base `citationKey(meta)`;
  if it already exists in the library OR earlier in this batch, append
  `a`/`b`/`c`… `keyByOrder` preserves input order for the marker rewrite.
- `buildItems(entries)` → `LIBRARY_METADATA.buildPaperItem(meta, null, null)`
  with `meta.library.citation_key` overridden to the disambiguated key,
  `source` preserved.
- `commitToLibrary(newItems)` → **direct single-doc** `db.collection('items')
  .doc(id).set(row)` per new item (rules: `items` create = `isLabMember()`;
  avoids the whole-array clobber the adapter would cause from the editor).
- `rewriteNumericMarkers(text, keyByOrder)` → replaces `[N]`, `[N, M]`,
  `[N–M]`/`[N-M]` ranges, mixed `[N–M, P]` with `[@k1; @k2; …]`; leaves
  non-numeric `[@…]` / `[!sec:…]` untouched; out-of-range N left verbatim +
  reported.

Shared UI: `REFERENCE_IMPORT.open({ mode:'library'|'editor', draftId?,
existingItems, onCommit })` — modal (reuses `.pe-cite-popover`/`RM_DIALOG`
styles): a BibTeX textarea + `.bib` file input, and a DOI-list textarea; a
**Parse → preview** table (title · authors · year · key · new/dup badge · DOI
lookup progress); Commit calls `onCommit({ builtItems, keyByOrder, entries })`.

### Library surface (`rm/js/library.js` + `rm/pages/library.html`)
- Button `#library-import-refs` "⇪ Import references" beside `#library-add-doi`.
- `onCommit`: `REFERENCE_IMPORT.commitToLibrary(builtItems)` → push into
  `_libraryPapers` + `_load()` + `_render()`; toast N added / M skipped-dupes.

### Editor surface (`rm/js/paper-editor.js` + `rm/css/paper-editor.css`)
- Toolbar button "⇪ Import references" (near the citation controls).
- `onCommit`: commit to library → **link** each to this draft
  (`LIBRARY_LINKS.toggleDraftLink(itemId, state.paperId, true)`) → refresh
  `loadCitationIndex()` → if the operator opted in, `rewriteNumericMarkers`
  every paragraph/subheading/figure-caption body in one Yjs transact (guarded
  to run only when `keyByOrder` covers the max [N] in the doc; reports
  unmapped). `CITED_SYNC` then stamps `cited_in_drafts` from the new `[@key]`s.

## V3.484 follow-up — automatic on paper import

Test feedback: importing the GELS paper added nothing to the library and left
the references unlinked — because V3.483's import-and-attach was a **manual
button**, and the re-cut bundle carried no reference data. Fix (Alex chose
"automatic on paper import"): references now travel *with* the paper.

- **Bundle** carries `references[]` (unified metadata in citation order);
  narrative keeps its `[N]` markers.
- **`_materializeBundleReferences(bundle)`** at the end of `_hydrateBundle`
  (fresh-import only) reuses the V3.483 core against the LIVE library:
  `dedupeAndKey` → `commitToLibrary` new → `toggleDraftLink` all → refresh
  index → `_rewriteNumericCitations` (no confirm). Best-effort try/catch.
- **GELS** re-cut: 105 refs resolved offline via CrossRef (102 direct, 1
  fail→text, 2 no-DOI overrides) baked into `references[]`. `GELS-references-
  DOIs.txt` retired. Offline dry-run: 105 unique keys, 106 markers map, 0
  unmapped.
- The manual editor button stays for ad-hoc lists.

## V3.486 follow-up — fix white page on import

Test feedback: importing the paper showed a white page until a manual refresh.
Two independent causes, both fixed (sw →459):
1. **Stale projects cache (root).** Import writes the row via a DIRECT
   single-doc `set` (owner-scoped rule) that bypasses `api.save`'s cache-clear
   → the adapter's stale-while-revalidate `projects/papers.json` missed the new
   paper on the editor's immediate load → "not found" near-empty state (reads
   as white) until the background revalidate landed one load later. Added
   `api.invalidate(path)`; `importBundleFile` busts the cache before nav; the
   editor's `loadMeta` busts+refetches once before giving up.
2. **Reference work entangled with first paint.** `_materializeBundleReferences`
   is now deferred + isolated off the hydrate critical path; the rewrite is
   per-block guarded.
