# V3.472 — Paper import: the real NSF CAREER Project Description, editable

> Follows the grant-unification program (V3.463–V3.471). Turns the R9 representability
> proof into a real, one-click import: the GELS NSF CAREER proposal opens as a fully
> editable grant paper. Establishes the reusable **paper-import seam** the user's
> bidirectional markdown/JSON import-export will build on.

## The import mechanism (reusable)

- **Bundle format** — `rm/data/grant-imports/<id>.json`:
  `{id, title, paper_type, grant_subtype, target_journal, sectionNumbering,
  source_note, tree:{meta, sections:[…]}}`. `tree.sections` is the plain paper-tree
  shape `appendSectionFromTree` already rehydrates (custom sections → subheading/
  paragraph/figure/list children).
- **Trigger** — `paper-builder.html?import=<id>` → `paper-builder.js importPaper()`:
  fetches the bundle, writes a `papers.json` row carrying `import_seed:<id>`
  (paper_type/grant_subtype from the bundle, template_id `nsf-career`), navigates to
  the editor. Re-importing the same id just reopens the existing paper — never
  duplicates.
- **Hydration** — `paper-editor.js hydrateFromImport()`: on first open of an EMPTY doc
  carrying `import_seed`, fetches the bundle and one-transacts the full section tree via
  `appendSectionFromTree` (origin `seed-import`). Runs in place of `seedFromTemplate`;
  the empty-doc guard means it never clobbers an edited paper; falls back to the
  template if the bundle can't be fetched. A best-effort toast suggests setting
  Numbering → Off (imported subheadings carry their verbatim `3.1.1`/`Aim 1` numbers).

## The GELS NSF CAREER bundle (rm/data/grant-imports/nsf-career-gels.json)

Extracted from the proposal's markdown source (`GELS CAREER/Working docs/sections
working/`) — chosen over the PDF because the markdown has correct paragraph/heading/
figure boundaries the PDF text layer loses (it drops compound hyphens and marks no
paragraph breaks). Figure **captions** are the polished ones from the submitted
`NSF_CAREER_ProjectDescription2.pdf`. Contents: **12 sections** (11 narrative custom +
References Cited), **129 paragraphs**, **40 subheadings** (12 L2 + 28 L3, verbatim
numbering), **11 figure blocks** (caption-only; images attach via the normal figure UI
— alt text names the source `Figures/imageN.jpg`), **65 references**. Citations stay as
literal `[N]` text keyed to the References Cited section (live-citation conversion is a
later option).

Known deltas (documented in the bundle's `source_note`): the markdown is a slightly
later working revision than the submitted PDF, so a few section titles differ (e.g. Aim
1 wording); figure images are attached by hand (one drag from the GELS repo).

## Extractor

`scratchpad/extract-nsf-career.js` (kept in scratchpad, not shipped) parses the 11
section markdown files → the bundle: `## N.` → custom section (number stripped —
auto/off numbering handles it), `###`/`####` → subheading L2/L3 (verbatim text),
blank-line paragraphs → paragraph blocks, Pandoc inline cleaned (`[x]{.underline}` → x),
FINAL-PDF figure captions injected per section, references.md → the References section.

## The bidirectional vision (next, not in this release)

The user wants this to go both ways — **export** a paper to markdown + JSON, and a
general **import** (settings, sections, figures, equations, bibliography) — so papers
port in and out of the editor. This release is the import half's foundation (the bundle
format + hydration seam). A general import/export is worth its own planned program:
export walks the Yjs tree → per-section markdown + a manifest JSON (config, authors,
equation library, figure assets, bibliography) → a .zip; import reverses it (reusing
`hydrateFromImport`), with figure/equation assets bundled. Flagged here; to be planned
separately.
