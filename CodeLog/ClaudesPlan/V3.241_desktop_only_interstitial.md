# V3.241 — Desktop-only interstitial (Phase 4 of mobile compatibility)

> Final phase of the original mobile plan (`~/.claude/plans/i-want-to-make-rosy-scott.md`). Some RM pages genuinely cannot be made phone-usable without rebuilding them — multi-pane iframes (split-view, workflow-shell), admin matrices, financial dashboards with charts, grant/CV editors with form-heavy layouts, kanban-style boards. Forcing them into a phone viewport would degrade the desktop experience without delivering a usable phone experience. V3.241 ships a small interstitial that asks the phone user to switch to a wider screen — with a "Try anyway" escape hatch so the page is never truly unreachable.

## Goal

A phone user landing on a tier-C page sees a friendly card explaining the page is desktop-first, with two actions: "← Back to RM home" or "Try anyway" (which dismisses for the session and reveals the underlying page). The interstitial is opt-in per page via a `rm-desktop-only` body class — every other RM page is unaffected.

## Adopters

Eleven pages opt in:

| Page | Why it's desktop-only |
|---|---|
| `split-view.html` | Two side-by-side iframes; phones can't fit both. |
| `workflow-shell.html` | Iframe + 460px-wide popouts; the popouts overlay the main iframe on tablet already (V3.233). |
| `admin-migrate.html` | Multi-step admin migration tool with table-heavy progress UI. |
| `admin-permissions.html` | Permissions matrix — user × page checkbox grid. |
| `admin-tracker-migrate.html` | Similar admin migration tool. |
| `budget.html` | Multi-column financial table + filter chips. |
| `finance.html` | Financial dashboard with charts. |
| `analytics.html` | Charts + time-range filters. |
| `grants.html` | Grant editor (multi-section form, similar density to paper-builder but heavier per-row). |
| `cv-editor.html` | CV builder with reorder-by-drag sections. |
| `lab-tasks.html` | Cross-user kanban — admin-only multi-user task grid. |

The list maps to the master plan's Tier C list. Other admin/heavy pages can opt in later by adding the body class + script tag.

## Approach

Three small additions, no removals:

1. **`rm/js/desktop-only-guard.js`** (new) — ~90-line IIFE that, at DOMContentLoaded, checks `<body class="rm-desktop-only">` + `window.innerWidth ≤ 640px` + `sessionStorage rm_desktop_only_dismissed != '1'`. When all three are true, it injects a `.rm-desktop-only-overlay` card with two actions. "Try anyway" sets the sessionStorage flag and removes the overlay; "Back to RM home" navigates to `/rm/`. Resize-back-to-desktop tears down the overlay automatically; resize-down-to-phone re-shows it (unless dismissed). Escape key acts the same as "Try anyway" (escape hatch for keyboard users).

2. **`rm/css/style.css`** — `.rm-desktop-only-overlay` + `.rm-desktop-only-card` + title/body/actions/btn rules (~80 lines) appended at the end. The overlay is `position: fixed; inset: 0` with a dimmed-modal backdrop and a centered 360px card. Card padding uses `var(--safe-top)` / `var(--safe-bottom)` so notched phones don't clip it. The two buttons hit the `var(--tap-min)` 44px minimum.

3. **11 Tier C HTML files** — `<body>` gets the `rm-desktop-only` class (preserving any existing classes on `split-view.html` and `workflow-shell.html`); `<script src="/rm/js/desktop-only-guard.js">` loads immediately after `nav.js`.

## Why an opt-in body class vs URL matching

A URL-matching approach (e.g. checking `location.pathname` against a hardcoded list inside the guard) would let the guard run on every page and self-route. But that scatters the "desktop-only" decision across the codebase. The body-class approach keeps each page's tier-C status visible in its own HTML — easier to audit, easier to revoke (just drop the class), no central registry to maintain.

## Why sessionStorage opt-out vs localStorage

Per-session dismissal means a returning user sees the warning again on a fresh tab. The intent is to **discourage** phone use of tier-C pages, not permanently silence the warning. A user who explicitly chooses to work on a phone can dismiss it once per session, but the warning surfaces the next time they hit the page after a context switch.

## Verification

1. **Desktop ≥1024px** — Open each of the 11 pages at 1440px: no overlay. `document.body.classList` includes `rm-desktop-only` but the guard sees `window.innerWidth > 640` and doesn't inject.
2. **Phone 390px (DevTools)** — Open each page: overlay appears immediately on DOMContentLoaded. Card content readable, both buttons hit 44px+ height, focus lands on "Try anyway" for keyboard users.
3. **"Try anyway" flow** — Tap → overlay disappears → the page underneath renders (cramped but accessible). Reload the page → overlay returns (sessionStorage dismissal is one-time). Open a new tab and navigate to the same URL → overlay returns (sessionStorage is per-tab).
4. **Resize teardown** — At 390px overlay shown → resize to 800px → overlay removed (it doesn't make sense on tablet). Resize back to 390px → overlay returns (unless dismissed in this session).
5. **Escape key** — overlay open + Tab to focus the overlay + press Escape → dismisses + records sessionStorage.
6. **Other pages unaffected** — Open `/rm/pages/tasks.html` or any non-tier-C page at phone width: no overlay. The guard script is not loaded on those pages.
7. **`/rm/pages/lab-tasks.html` only allowed for admins** — the desktop-only guard runs regardless of role; an admin on a phone sees the overlay, taps "Try anyway", and the page's own admin gate logic runs. No double-gating conflict.

## Out of scope

- **Per-page custom message** — every tier-C page shows the same card text. If a specific page warrants a tailored message ("This admin tool is dangerous on phone — really go to desktop"), the guard could read a `data-desktop-only-message` body attribute. Deferred until needed.
- **Permanent opt-out** — by design. localStorage would silence the warning forever; sessionStorage is the right strength for "discourage phone use without preventing it."
- **Other admin pages** (`email-review.html`, `chemicals.html` admin tabs, etc.) — not on the master plan's tier-C list. Easy to opt in later if user feedback warrants.
- **Edge-swipe gestures** to dismiss — overkill for an interstitial.
- **Pre-fade animation** — only the simple `fade-in` keyframe on appearance. Disappearance is instant on click/Escape.

## Rollback

`git revert` of this commit restores V3.240. To revert just the interstitial without touching the version bump: drop the `rm-desktop-only` class from the 11 body tags (or remove the script tags) — the CSS rules + the JS file are dormant without the body class.
