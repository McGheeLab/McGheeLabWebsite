# V3.489 — Body-text line density (grant "lines per inch")

## Goal

Let a user cap **body text** at a lines-per-inch metric (the standard grant
constraint — NSF: no more than 6 lines/inch) and have the body **font size +
line spacing auto-adjust** to hit it, in the preview and the compiled PDF.
Headings, the title, abstract, and captions are NOT resized.

Prompted by: "control the number of lines of text that can fit on the page, and
the font size automatically adjusts … many grants have a lines per inch metric."

## Scope (confirmed with the user)

- **Both input modes**: lines-per-inch (the compliance metric) and
  lines-per-page (convenience). Lines-per-inch is canonical.
- **Clamp the font with a warning**: keep body font in a readable range
  (default 9–12 pt); if the target can't be met inside it, honor the range and
  warn — but the *leading* (= the lines-per-inch metric reviewers check) is
  always held exactly.
- Body text only.

## Approach

**Canonical metric = lines per inch (`bodyLpi`)**, stored on
`paperExports/{paperId}`. Lines-per-inch fixes the leading (`72 / lpi` pt),
which is geometry-independent and is the actual compliance number. The
lines-per-page input mode converts to lpi at entry using the current text
height (`bodyH / 96` px→in), so the stored value stays margin-independent.
Body font = `leading / 1.2` (single-spaced ratio → 6 lpi ⇒ 12 pt leading ⇒
10 pt font, the NSF canonical), clamped to `[fontMin, fontMax]` (default 9–12);
when the font clamps, the leading is left exact so compliance holds.

### Shared derivation — `rm/js/paper-layout-rules.js`
`PaperLayout.resolveBodyDensity({lpi, fontMin, fontMax})` → `{lpi, leadingPt,
fontPt, clamped, warning}` or null. DOM-free; used by preview + export + node
harness.

### Export — `rm/js/paper-export-tex.js`
`buildBodyDensityPreamble(opts)` injects (on demand, in `buildBundle` beside the
package-flag injections) `\AtBeginDocument{\renewcommand\normalsize{\@setfontsize
\normalsize{F}{B}}\normalsize}`. Only `\normalsize` (body) changes; `\section`,
`\Large`, `\small`, the title keep their class sizes (article/journal classes
key those to the class option, not the live font). Clamp warning → `_layoutWarnings`.
`_buildBundleNow` in `paper-export.js` passes `bodyLpi`/`bodyFontMin`/`bodyFontMax`.

### Preview — `rm/js/paper-doc-view.js`
- Config: `bodyLpi` / `bodyDensityMode` / `bodyDensityValue` in defaults + load
  (also in `paper-export.js`).
- `_applyBodyDensity()` (before `_measureItems`): sets `--pdv-body-font` /
  `--pdv-body-lh` (px) on the overlay + probe and toggles `.pdv-density-on`, so
  the mounted sheets AND the measurement probe carry the new line box →
  pagination follows.
- Body paragraphs (`.pdv-bodypara`) + body lists get a `.pdv-density-body`
  marker (split continuations keep it via cloneNode). CSS:
  `.pdv-density-on .pdv-density-body { font-size: var(--pdv-body-font);
  line-height: var(--pdv-body-lh); }`.
- Toolbar **Lines** control: mode select (Off / Per inch / Per page) + numeric
  value + readout (`≈10pt · 6/in · ≈52/pg`, ⚠ + tooltip on clamp).
  `_onBodyDensityChange` converts lpp→lpi via `state.lastGeom.bodyH/96`,
  persists set-merge, re-renders. `_paintDensityReadout` re-runs post-render
  (lines/page needs the packed geometry).

## Key decisions

- **lpi is canonical** (not lpp): it's the compliance metric and is
  margin-independent, so changing template/margins can't silently break it.
  lpp is a convenience that converts at entry.
- **Leading fixed, font clamped**: preserves the exact compliance metric while
  keeping body text readable; the warning surfaces the trade-off.
- **`\normalsize`-only export**: body-scoped without touching heading/title
  sizes, using the same `\@setfontsize` primitive the classes use.

## Follow-ups (deferred)

- Expose `fontMin`/`fontMax` in the UI (currently fixed defaults 9–12, editable
  only via the config doc).
- A per-font-family metric (grants sometimes specify a font, e.g. 11pt Arial);
  today we drive size/leading only.
