# V3.320 — Activity overhaul: one activity surface (FuturePlan 04, Release B2)

## Goal

Collapse the double-nested tracker UI into a single glanceable page.
activity-overview.html's `?tab=` shell keeps overview / timeline /
email / lab-stats, but the **tracker tab becomes one surface**:

- GitHub-style calendar heatmap — 53 weeks, one cell per day, shade =
  per-day work-event count (0 / 1 / 2–3 / 4–6 / 7+).
- Current + best streaks (consecutive days with ≥1 work event; current
  streak tolerates an empty today).
- Per-category counts for the selected range (7/30/90 days) — category
  = `categoryPath[0]`, falling back to a prettified `source`. This is
  the taxonomy prune FuturePlan 04 open question 2 asked for: the
  hierarchical category tree, ML classifier, and category manager are
  gone; grouping is whatever the producers stamp.
- Recent-activity feed (last 30 events, newest first) + a "Coming up"
  lane for schedule events dated today or later (tasks/meetings still
  produce those).
- Minimal quick-log input ("+ note what you did") → a `manual` work
  event. No hours anywhere.

## Approach

[rm/js/activity-tracker.js](../../rm/js/activity-tracker.js) is
**rewritten from scratch** (2152 → ~400 lines): one
`ActivitySignals.listEvents(uid, {from: today−53w})` load, pure-DOM
heatmap (no Chart.js), self-injected styles (legacy
activity-tracker.css untouched for the deferred-view shell it also
serves). Deleted with the rewrite: daily hours view, pending banner
call sites, voice input, AI bulk-parse, Anthropic categorize, Naive
Bayes ML train/predict, weekly drag-drop planner, analytics charts,
category manager, hours-centric settings, huddle/calendar integrations.

Day-count rule: an entry counts as work when `kind == 'work'`, or (no
`kind`, legacy) when it isn't a pending schedule marker
(`scheduled_for` set + status `pending`). Legacy dismissed entries are
already filtered by listEvents.

[rm/pages/activity-overview.html](../../rm/pages/activity-overview.html):
tracker tab's document.write script list shrinks to just
activity-tracker.js (rm-categories.js, Google GSI, calendar-service.js
no longer needed).

[rm/pages/training-rm-daily-research.html](../../rm/pages/training-rm-daily-research.html):
the "Auto-pending / confirm hours" explainer block is reworded to
describe zero-click auto-tracking.
