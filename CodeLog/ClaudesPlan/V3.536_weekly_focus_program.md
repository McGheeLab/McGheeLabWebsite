# V3.536 — Weekly Focus program (My Day II): mentor↔mentee focus loop + composable plans + drag scheduling

> **Program doc** for V3.536–V3.541 (Alex test feedback on the V3.526–535
> My Day program, 2026-07-25). Slimmer per-release notes live in this one
> doc — the releases are tightly coupled around one new data model.

## Goal

Turn My Day from a fan-out composer into a **clarity engine**: the
student's day is planned against mentor-agreed weekly focus areas, plan
items are built by COMBINING ingredients (focus + protocol + equipment +
task) instead of picking one exclusive type, equipment time is picked by
dragging on a multi-day availability strip, and the loop closes through
the lab notebook (success/failure reports) into PMR weekly/monthly review.

## Decisions (locked with Alex, 2026-07-25)

1. **Mentor surface = new Team Focus page** (`rm/pages/team-focus.html`):
   mentor picks a mentee, assigns/edits/confirms that week's focus areas.
   PMR gets the read-only weekly/monthly rollup.
2. **Weekly focus pill** (renames the old "Work" pill): student picks one
   of this week's mentor-confirmed focus areas OR types freeform — the
   freeform path creates a student-proposed focus area
   (`source:'student'`, `status:'proposed'`) so mentors see drift.
3. **Time picker = stacked day bars**: the next 7 days as stacked
   horizontal availability bars (existing bookings gray, posted window
   hatched); drag on any day's bar selects that day + time range, snapped
   to 15 min. One selection at a time; the time inputs stay as fine-tune.
4. **Composability = ingredients on one plan**: 🎯 Focus, 📋 Protocol,
   🔬 Equipment, ✅ Task are toggleable ingredients that stack on a single
   plan-of-action item (title ghost-suggested from the combo). Meeting /
   Reading / Order / Help stay simple standalone types.
5. **Mentor↔mentee workflow** (the spec's core loop):
   mentor drafts focus (`proposed`) → mentee may edit the description
   (`mentee_edited`, back to mentor) → mentor signs off (`confirmed` —
   the expectation is set) → mentee reports success/partial/failure with
   the LAB NOTEBOOK as the narrative surface (`reported`) → everything
   rolls into PMR for weekly and monthly review.

## Data model

### `userData/{studentUid}/focusAreas/{focusId}` — NEW collection

```js
{ id: 'fa-<ts36>-<rand4>',
  weekId: 'YYYY-Wnn',              // ISO week, same math as huddle/day-distribute
  title: '',                        // short focus name ("PEGDA gel repeatability")
  description: '',                  // what to do — plain text, editable by BOTH sides
  status: 'proposed'                // drafted (by mentor OR student-freeform)
        | 'mentee_edited'           // mentee changed the description → mentor re-confirms
        | 'confirmed'               // mentor signed off — expectation set
        | 'reported',               // outcome recorded
  source: 'mentor' | 'student',
  created_by, assigned_by,          // assigned_by = mentor uid (null when student-proposed)
  updated_by,
  confirmed_by: null, confirmed_at: null,
  report: null | { outcome: 'success'|'partial'|'failure',
                   summary: '', notebook_entry_ids: [], reported_at },
  // Hierarchy (Alex, mid-program): a focus CONTAINS tasks. Focus = the
  // week's WHY (mentor-agreed outcome area); tasks = the concrete WHAT
  // under it. Kept in the focus doc — deliberately NOT in the buckets
  // system — so the two concepts never blur.
  tasks: [ { id: 'ft-<ts36>-<rand4>', text, done: false, done_at: null,
             created_by, planned_item_ids: [] } ],
  created_at, updated_at, ownerUid: studentUid, schema_version: 1 }
```

**Hierarchy surfacing:** Team Focus renders the task checklist nested
under each focus card (mentor AND mentee can add/check). My Day's Task
ingredient picker lists **this week's focus tasks first, grouped under
their focus** — picking one auto-attaches the parent focus to the plan
item (`details.focusId` + `details.focusTaskId`) — with loose bucket
subtasks in a second group. Confirming a planned item done checks off
its focus task (stamps `done_at`, appends the item id to
`planned_item_ids`).

**Rules** (the program's only rules change — deploy BEFORE FTP):

```
match /userData/{userId}/focusAreas/{focusId} {
  allow read, write: if isOwner(userId) || isMentorOf(userId) || isAdmin();
}
```

Reuses the existing V3.243 `isMentorOf()` helper (`users/{menteeUid}
.mentor_uids[]`, assigned on the permissions page). Status-transition
enforcement (only mentors confirm) is client-side, matching the repo's
admin-trusted convention. The owner side is already granted by the
`userData/{userId}/{document=**}` wildcard; this block ADDS mentor/admin.

### My Day item extensions (`dayPlans` — no migration)

`details` gains `focusId`/`focusTitle`, `subtaskId`/`subtaskText`
alongside the existing `equipmentId`/`protocolId`. `type` derivation for
composed items: equipment ingredient present → `'equipment'`, else →
`'work'` (so every V3.526 adapter keeps working unchanged).

## Verification

1. **Assign loop:** as mentor, open Team Focus → pick mentee → assign
   "Gel repeatability" with description → mentee sees it on My Day
   (proposed) → mentee edits description → mentor sees `mentee_edited`,
   signs off → chip flips confirmed on both surfaces.
2. **Compose:** student toggles 🎯+📋+🔬 → picks focus, protocol,
   confocal; drags Thu 14:00–16:00 on the stacked strip → ghost title
   "Protocol X on Confocal — Gel repeatability" → Add → booking + huddle
   + notebook stub (with protocol_run) + tracker all land; item chip row
   shows the focus.
3. **Drag picker:** drag across a gray block → selection turns red +
   submit blocked with reason; drag a clean range on a different day →
   date + times update; fine-tune via the time inputs stays in sync.
4. **Report:** confirmed focus → Report → partial + summary + create
   notebook entry → notebook opens on the stub; focus flips `reported`;
   Team Focus shows the outcome.
5. **PMR:** open the student's PMR as mentor → "Weekly focus review"
   block groups the period's focus areas by week with outcomes + entry
   links; comments work.
