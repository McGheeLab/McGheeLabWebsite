## Phase 1 — primary chrome, by hand

Done by hand because it carries the structural traps.

- **`nav.js` — the label regex is gone.** `makeTopLink` parsed the icon off
  the front of a label with `/^(\S+)\s+(.+)$/`, which existed *only* to
  split an emoji. An SVG string is full of spaces and would have been
  shredded into `<svg` plus the rest. Signature is now
  `makeTopLink(icon, label, href, isActive)`; the `.nav-label` span stays so
  the ≤640px icon-only rule keeps working.
- **`'⊟ Split'` is a group KEY, not decoration.** `all-pages.js:193`'s
  `order[]` is compared against `p.group`, which comes from the NAV_ITEMS
  label. Both were changed to `'Split'` in the same commit; changing one
  alone silently breaks grouping.
- **`all-pages.js` — `escHtml(icon)` removed** for that one interpolation
  (it would have printed the markup), and all 53 `PAGE_ICONS` values became
  Heroicon names.
- **`mobile-shell.js`** — 6 tabs, 4 More-sheet links and sign-out. The
  active tab is now **solid**, which also fixes an existing WCAG SC 1.4.1
  failure (active state was colour-only); `aria-current="page"` added.
- **`firebase-bridge.js:675`** — the hand-drawn signed-out user glyph became
  `user-circle`. Done first: SVG→SVG, zero layout risk, proves the pipeline.
- **`page-registry.js`** — the 5 `DEFAULT_WORKFLOWS` seed icons.

## Phases 2-7 — two codemods

`scripts/icon_codemod.py` and `scripts/icon_codemod_ternary.py`, both
committed. They only touch shapes where the transform is unambiguous,
because a wrong rewrite here is **silent** — valid JS, wrong output.

```
A. text sink   el.textContent = '✓ Done'   -> ICON.label(el, 'check', ' Done')
B. markup      '<button>✕</button>'        -> '<button>' + ICON.svg('x-mark') + '</button>'
C. template    `<b>✕</b>`                  -> `<b>${ICON.svg('x-mark')}</b>`
D. ternary     open ? '▾' : '▸'            -> ICON.svg(open ? 'chevron-down' : 'chevron-right')
```

Refused on sight: comments, text-only channels (`.title=`, `aria-label`,
`alt`, `placeholder`, `TOAST.*`, `console.*`, `alert()`), comparisons
(`=== '✓'`), `case` labels, `icon-picker.js`, and every glyph in the
manifest's `keep{}` block.

### Three bugs the codemods hit, all caught before shipping

1. **Nested strings inside `${…}`.** The first pass rewrote
   `${pinned ? ' 📌' : ''}` into `'${ICON.svg('pin')}'` — broken quoting,
   and a `${}` inside single quotes isn't interpolated anyway. Fixed by
   splitting template bodies into text spans and expression spans and
   never touching the latter. Found by `node --check`.
2. **Orphaned variation selectors.** `'☀️'` is `'☀'` + U+FE0F; matching the
   glyph alone left the selector stranded beside the new `<svg>`. The glyph
   regex now consumes an optional `️`.
3. **★ Ternary output landing in a text sink.** The ternary pass rewrote
   `btn.textContent = (open ? '▸' : '▾') + ' barriers (…)'` into an
   `ICON.svg()` call assigned to `.textContent` — the exact trap phase 0's
   gate exists for, and **the gate caught it**, twice. Both sites fixed by
   hand and the pass now refuses any line that writes to a text sink.

A fourth was caught by grep, not the gate, and the gate was then taught it:
`paper-figure-board.js` had an icon concatenated into a `title="…"`
attribute — a tooltip is a text channel, so it would have painted raw SVG
source in the tooltip. Reverted to the glyph, and `--scan` now fails on
`(title|alt|aria-label|placeholder)="…ICON.`.

### Config maps: consumers, not maps

`NOTIF_ICONS`, `ITEM_OUTCOME_META`, `MYDAY_TYPE_ICONS` and friends still
hold **emoji**. Instead of rewriting them, their 21 consumers were routed
through `ICON.render()`, which resolves a known glyph to its Heroicon via
the reverse map. This is strictly safer: a map and its consumer cannot drift
out of sync, there is no migration, and the kill switch still works.

## What is deliberately NOT converted

880 glyphs remain. The breakdown is the point:

| count | why |
|---|---|
| 440 | prose / plain strings — *"Click "✓ discussed" on any item above"* is copy, not an icon |
| 120 | text channels and comparisons — correctly excluded |
| 102 | config-map values — **already render as icons** via `ICON.render()` |
| 98 | markup the codemod declined as ambiguous |
| 75 | inside a `${…}` code expression |
| 45 | `icon-picker.js`'s palette — that IS the data |

This matches the program's own guidance: 268 distinct glyphs are in use but
105 appear exactly once, and past the top ~60 an outline SVG is usually
worse than the emoji it replaces. The long tail is a deliberate stop, not an
oversight.

`rm/pages/*.html` inline glyphs (149) are page copy and were not touched.
The 11 CSS `content:` glyphs remain a documented won't-fix (a pseudo-element
can't take inline SVG; the mechanism would be `mask` + a data URI, for 11
occurrences across five stylesheets).

## Phase 7 — the public site

`index.html` loads **the same** `/rm/js/icons.js` (same origin from
mcgheelab.com), so there is no second icon system. Not deferred: `app.js`
renders on DOMContentLoaded and calls `ICON.svg()` during that first paint.
`styles.css` gets its own copy of the `.hi` block — the public site and RM
have completely separate stylesheets, and the two blocks must stay identical
or an icon looks different depending on which half of the site you are on.
