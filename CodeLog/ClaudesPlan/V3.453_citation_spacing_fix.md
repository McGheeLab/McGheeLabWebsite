# V3.453 — doc view: citation clusters no longer gain space under justification

> Test feedback on Paper Builder III (fix 1 of 7): "citations look correct in the first
> paragraph, but in all following paragraphs the citations have too much space between
> each number."

## Root cause

`.pdv-para` is `text-align: justify` (paper-doc-view.css:543). The V3.393 packed-comma fix
killed the main stretch vector for numeric clusters, but three survived:

1. **`.pe-cite-sep` padding leaked into the sheet.** The editor rule
   `.pe-cite-sep { padding: 0 2px }` (paper-editor.css) is not in the doc view's
   chip-flatten selector list, so every comma carried ~4px of padding in the sheet and
   the measurement probe.
2. **The non-numeric separator contained a real space** (`"; "` — paper-editor.js
   `renderCitationChip`), and the sheet's `white-space: nowrap` re-assertion covered only
   the three numeric families — a justification opportunity inside author-year clusters.
3. **Adjacent citation tokens** (`[@a] [@b]`) render as separate `.pe-cite-group` spans
   joined by a bare space that justification stretches hard in narrow 2-column
   paragraphs. The first paragraph sits in (or next to) the wide full-width block where
   lines barely stretch — which is why it looked correct.

Plus a repaint gap: the citation FAMILY resolves from the export template after first
paint, but the doc view only re-rendered on `paper-citations-loaded` /
`paper-panel-changed`, never on `paper-equations-changed` (the event
paper-cite-style.js fires when the family lands).

## Fix

- **rm/js/paper-editor.js** — non-numeric separator is now `;` + `<wbr>` (no raw space;
  the `<wbr>` preserves the line-break opportunity so long author-year clusters still
  wrap). Editor look restored via CSS padding.
- **rm/css/paper-editor.css** — `padding-right: 6px` on non-numeric-group separators
  (editor surfaces only).
- **rm/css/paper-doc-view.css** — in sheet + probe (identical selectors so measurement
  matches): separators get `padding: 0; margin: 0` with numeric families fully packed
  ("[1,2]" like the compiled PDF) and non-numeric groups getting a `margin-right: 0.3em`
  gap (margins are not justification opportunities); chips + separators forced
  `display: inline` (inline-block survived the flatten and sat as rigid boxes in
  justified lines); new fixed-width `.pdv-cite-join { display:inline-block; width:.28em }`.
- **rm/js/paper-doc-view.js** —
  - `_joinAdjacentCites()` post-mount pass (called beside `_resolveSecRefs()`): TreeWalker
    over `.pdv-para` text nodes; whitespace-only nodes BETWEEN two `.pe-cite-group`
    elements are replaced with `.pdv-cite-join` (~space-width, so measured heights stay
    valid; inline-blocks remain soft-wrap points so lines can still break there).
  - `state.onEqPanelChanged` listener on `paper-equations-changed`: diffs
    `PaperCiteStyle.getFamily()` against the last seen value and only then forces a
    render (the event fires for every panel change — the diff prevents re-render
    thrash). Detached in `_detachLive`.

## Verification

- `node --check` clean (paper-editor.js, paper-doc-view.js); CSS braces balanced;
  harness suite 347 green (no tex changes).
- Browser (Alex): 2-col paper with multi-key clusters + adjacent single-key tokens in
  paragraphs 2+ — gaps are now constant everywhere; author-year template: clusters read
  "(Smith 2024; Lee 2025)" with fixed gaps and still wrap at separators; slow-reload a
  paper and confirm the sheet flips from author-year chips to numbers when the template
  family resolves (no manual nudge needed).
