## What shipped

1. **PaperEditor headless section API** (paper-editor.js exports):
   - `addSection(kind, label, {special, special_render, atIndex,
     seedParagraph})` → id — appends via appendSectionFromTree, then
     walks into `atIndex` with the existing moveSection machinery
     (append-then-reorder; the old `addSectionPrompt` now funnels here).
   - `deleteSection(id, {skipConfirm})` (caller may own the confirm),
     `moveSection(id, delta)` (existing fn, now public),
     `getSectionsSummary()` → [{id, kind, label, special, index}].
2. **Doc-view "＋ Insert ▾"** (toolbar, editable-gated via open()):
   - **This journal** — the current template's `special_sections`
     catalog: ▣ box / ¶ heading icons, hint lines, singletons greyed
     "already added" (via getSectionsSummary).
   - **🌐 Other journals' sections…** — lazily fetches every
     KNOWN_TEMPLATES catalog (PaperExportConfig.KNOWN_TEMPLATES +
     PaperExportTex.fetchTemplate) and lists them grouped by journal;
     dropping a foreign style stores its key + special_render, so it
     keeps its look via the R6 fallback (box → rmcallout) with no
     warnings. Status line: "…it is a real section in the editor too."
   - **Custom style** — ▣ Boxed callout… (special 'custom-box' +
     render 'box' → rmcallout everywhere) and ¶ Plain section….
   - Landing honors the entry's `default_position`: 'front' → after
     abstract/keywords, 'back' → before references, else end
     (`_insertIndexFor`).
   - Origins `add-section`/`delete-section`/`move-section`/
     `rename-section` joined LAYOUT_ORIGINS; every insert forces its own
     re-render (structure changes must repaint).
3. **Section heading popover** — headings (`data-section-id`, stamped in
   R7) and boxed specials are click targets (branch after the equation
   popover in the desk delegation): ✎ Rename (Y.Text label rewrite,
   origin 'rename-section') / ↑ ↓ / ⤒ start / ⤓ end / 🗑 Delete
   (confirm). Shares the .pdv-fig-pop shell + popEl lifecycle (Esc /
   outside-click behave like the other popovers).
4. **CSS** — `.pdv-ins-menu/head/item/note/hint` dark dropdown,
   heading hover affordance (amber dashed outline), popover action rows.
5. **Deliberate cuts (stated):** desk drag-reorder of sections (headings
   aren't atomic packer nodes; the popover's up/down/start/end covers
   the need) and "convert to special" (delete + re-insert covers it).
   The EDITOR's add-section button keeps its (now addSection-backed)
   prompt flow — the catalog picker lives in the Document view where
   Layout Mode lives; sections created there are ordinary editor
   sections either way.
