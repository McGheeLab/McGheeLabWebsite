# V3.284 — BME 295C group response routing fix

## 1. Root cause

Two independent docId-construction mismatches silently drop every BME 295C group response: (a) `bmeSpeakerDay` returns `"Monday, June 8"` while `dailyGroups` is keyed by `"Monday"`, so group lookup always falls through; and (b) the save path uses `bmeEffectiveCampus(entry, _bmeProfile)` while admin readers use raw `student.campus`, so any campus override writes a doc the gradebook + live monitor never read.

## 2. Fix list

### Fix 1 — Strip date suffix from speaker day (Bug 1)

**File:** `class-builder.js:3398-3401`

```js
function bmeSpeakerDay(speakerSlug) {
  const sp = (_bmeContent?.speakers || []).find(s => s.slug === speakerSlug);
  return sp?.day || null;
}
```

→

```js
function bmeSpeakerDay(speakerSlug) {
  const sp = (_bmeContent?.speakers || []).find(s => s.slug === speakerSlug);
  const raw = sp?.day || null;
  if (!raw) return null;
  // V3.284 — content.json stores "Monday, June 8"; dailyGroups + schedule
  // are keyed by the bare weekday. Normalize at the boundary.
  const weekday = raw.split(',')[0].trim();
  const validDays = bmeCourseDays();
  if (validDays.length && !validDays.includes(weekday)) {
    console.warn('[bme295c] speakerDay', weekday, 'not in course days', validDays, '— check content.json');
  }
  return weekday;
}
```

Also fix the two `sp.day || bmeSpeakerDay(sp.slug)` sites that bypass normalization:

- `class-builder.js:5821` — `const day = sp.day || bmeSpeakerDay(sp.slug);` → `const day = bmeSpeakerDay(sp.slug);`
- `class-builder.js:8608` — same replacement.

### Fix 2 — Unify campus resolution (Bug 2)

Add a single helper near `bmeEffectiveCampus`:

```js
// V3.284 — every admin docId lookup must match what the student writes.
function bmeStudentCampus(student) {
  return bmeEffectiveCampus(student, bmeProfileFor(student));
}
```

Replace at every admin-read docId site:

- `class-builder.js:5796` — `roster.filter(s => s.campus === campus)` → `roster.filter(s => bmeStudentCampus(s) === campus)`
- `class-builder.js:5827` — already uses `col.campus` (built from filter above) — OK once filter is fixed.
- `class-builder.js:6450` — same `s.campus === campus` → `bmeStudentCampus(s) === campus`
- `class-builder.js:8466` — `bmeResponseDocId(student.campus, ...)` → `bmeResponseDocId(bmeStudentCampus(student), ...)`
- `class-builder.js:8611, 8626, 8632` — same replacement (`student.campus` → `bmeStudentCampus(student)`).

`bmeProfileFor(student)` already exists in V3.272's override scaffolding; if not, look up `_bmeStudentProfiles?.get(student.id)` directly.

## 3. Migration

Existing draft/submitted docs are at `${rosterCampus}-${oldGroupOrUndefined}-${slug}`. Two paths:

1. **One-shot migration script** (preferred): add a hidden admin button "Repair V3.283 response routing" in the Grade discussions panel. Ship (2) immediately and (1) once schema is verified — `migratedTo` keeps the old doc inert without losing audit history.

## 4. Defensive guards

- `bmeSpeakerDay` warns when its normalized output is absent from `bmeCourseDays()` (already in Fix 1).
- `saveBmeGroupResponsePrompts` (class-builder.js:5222): before the `if (!auth?.currentUser || !entry || !dayGroup || !effCampus) return;`, add `if (!dayGroup) console.warn('[bme295c] save dropped — no group for', entry?.id, 'on', day, 'dailyGroups=', entry?.dailyGroups);` so the silent-drop failure mode is visible in DevTools.
- `bmeResponseDocId` (wherever defined): if `campus` is falsy or not in `['Tucson', 'Phoenix']`, `console.warn` and return a deterministic sentinel — surfaces both bugs immediately.
- Add a one-shot integrity check in `loadBme295cData` that iterates the roster and asserts `bmeStudentCampus(s)` matches `s.campus` OR `_bmeProfile.campus` for the signed-in student; log mismatches.
