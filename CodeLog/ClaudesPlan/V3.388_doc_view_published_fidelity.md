# V3.388 — Document view: published-look fidelity + speed pass

## Context

Adversarial review of the V3.387 Document view (against the real LaTeX
templates via `paper-export-tex.js` + the 9 template JSONs) plus direct
user feedback. Two goals: **(1) make the preview look like the eventual
PUBLISHED paper**, and **(2) remove odd bugs that get in the way of
speed.**

Key correction from the user: the Document view should show **what the
paper will look like when published** (camera-ready, two-column where the
journal prints two columns) — not a single-column submission manuscript.
Hand-rolled LaTeX is chosen precisely to control that final typeset
output, so the viewer designs toward it.

Ground-truth check (from the templates) confirmed the divergences:
- Only IEEE's template currently compiles two-column; the rest are
  single-column. `DOC_HINTS` marked only IEEE 2-col → every other journal
  previewed single-column.
- Font sizes in `DOC_HINTS` were wrong vs the templates (mebp 10 vs 11,
  nature/science 11 vs 12, elsevier 10.5 vs 12).
- No template sets `\parindent`/`\parskip` → every journal compiles to
  **first-line-indented, no-gap, justified** paragraphs. The preview used
  web-style block paragraphs (blank-line gap, no indent).
- The bibliography was one generic format for all four citation families.
- The exporter never emits `figure*`, and table captions are always
  below the tabular (matches the preview — no change needed there).

## Scope of THIS release (viewer only — zero compile risk)

All changes are in `rm/js/paper-doc-view.js` + `rm/css/paper-doc-view.css`
plus a small additive tweak to the citation index in `rm/js/paper-editor.js`.
No template `.tex` changes, no Firebase deploy.

### Fidelity

1. **Published column counts (`DOC_HINTS`).** Nature / Science / IEEE /
   ACS / Elsevier → **two-column**; PLOS + both preprints → single-column
   (genuinely single-column even when published); mebp (lab SLAS style)
   left single-column. Margins tightened + `colGapIn` added for the new
   2-col journals. Font sizes set to published body sizes (2-col journals
   ~9–9.7pt). Column COUNT is the load-bearing value; sizes/margins are
   tunable approximations. Documented in the map's header comment that
   this targets the published look, not the current submission templates.
2. **Full-width abstract atop the columns** for 2-col journals (published
   pattern); IEEE keeps its in-column run-in "*Abstract*—". (`_buildFlowItems`
   pushes the abstract as a `full` item when `cols===2 && !abstractRunIn`.)
3. **Journal paragraph typography.** New `pdv-bodypara` class: first line
   indented `1.6em`, **no** inter-paragraph margin, justified; the first
   paragraph after a heading is flush-left (`.pdv-heading + .pdv-bodypara`).
   Applied identically in the sheet and the offscreen probe so measurement
   stays honest.
4. **Per-family references.** `_formatBibEntry(entry, family, number)` now
   renders four real styles: `numeric-bracket` (IEEE/Elsevier/PLOS:
   `[n] A. B. Author, "Title," Journal, vol., no., pp., Year.`),
   `numeric-paren` (Science), `superscript` (Nature/mebp/ACS: numbered
   list, `Surname, A. B. & …. Title. Journal Vol, Pages (Year).`), and
   `author-year` (APA-ish, unnumbered, alphabetical). Author initials via
   `_authorName`; `_authorList` handles et-al thresholds + last-separator.
5. **Plain-English figure popover.** Width + placement dropdowns show
   meanings ("Full column width", "Full page width (spans columns)";
   "Right here (fixed in place)", "Top of the page", "On its own page",
   …). The `<option value>` stays the LaTeX spec (`\linewidth`, `H`) so the
   Figures panel + LaTeX export round-trip is unchanged.

To support (4), the citation index projection in `paper-editor.js`
(`loadCitationIndex`) now additively carries `authorsFull` ({family,given},
≤10), `volume`, `issue`, `pages`, `doi`. The existing flat `authors`/
`authorCount` stay untouched for the other consumers.

5b. **Inline citations render correctly (follow-up fix — editor AND doc
    view).** Root cause: `PaperCiteStyle.init` (`paper-cite-style.js`) read
    *only* `paperExports.templateId` with no fallback, so a paper that never
    saved an Export config had no family (`getFamily() → null`) and every
    `[@key]` chip fell back to the legacy "Author Year" label (or a bare key
    when the ref isn't in the library) — everywhere, including the live
    editor. `init` now resolves `paperExports.templateId ||
    meta.template_id || 'mebp-journal'` (the same chain as paper-export.js:389
    and the Document view). `state.meta` is set before the `init` call
    (paper-editor.js:141 vs :204) so the meta fallback is populated. Two
    doc-view-specific fixes ride along: (i) the chip-flatten
    `font: inherit !important` wiped the superscript `font-size: 0.72em`
    (full-size raised numbers) — re-asserted for `.pe-cite-family-superscript`
    in `.pdv-sheet` AND `.pdv-probe`; (ii) `open()` awaits
    `PaperCiteStyle.init` so family + numbers are ready before first render.
    (`getNumber` recomputes from the tree on demand and numbers any cited
    key — including refs not in the library — but `getFamily` is null until
    `init` resolves a template.)

### Speed / odd bugs

6. **Two-column clipping fixed (critical now).** The 2-col engine set a
   fixed segment height + `overflow:hidden`, so an unsplittable item
   (column figure/heading) could push content past the segment bottom and
   be **silently clipped**. Now the mounted 2-col segment has no fixed
   height/overflow — columns **balance** to natural height (which also
   matches how a real journal balances columns around a full-width
   interruption); `seg.height` is purely a pagination estimate
   (`max(ceil(sumH/2), tallestItem)+gap`, no clamp). Nothing is dropped.
7. **Render-skip signature guard.** `renderDocument` builds a cheap
   signature (paper tree JSON + templateId + family + authors/affiliations
   + cited keys) and bails when it matches the last render. This collapses
   the churn where `yDoc.on('update')` fired a full rebuild (KaTeX per
   paragraph + offscreen measure + full DOM teardown) for writes that
   don't change visible content (presence, title/status sync, cache
   stamps). `paper-citations-loaded` sets a one-shot force flag so the
   bibliography still refreshes when library metadata lands late.
   `lastRenderSig` resets on close so reopening re-renders.
8. **Measurement-probe race guard.** `_measureItems(items, geom, seq)`
   bails after the first-render image-decode await if a newer render
   superseded it, so two renders can't drive the shared probe at once.
9. **Popover scroll-dismiss + resize refit.** The figure popover (fixed
   coords) dismisses on desk scroll; window resize (debounced 120ms)
   refits "fit" zoom and dismisses the popover. Both listeners tracked +
   removed in `_detachLive`.
10. **Pagination gap model.** Because body paragraphs lost their margin,
    measurement now adds each block's real `marginTop+marginBottom`
    (getComputedStyle) instead of a flat 10px — over-counts collapsed
    margins slightly, the safe direction (a little whitespace, never a
    clipped line).

## Deliberately NOT done

- **Double-spacing from the `setspace-double` add-on.** It's a *submission*
  convention; the published look is single-spaced, so applying it would
  move away from the target. Belongs to a future "submission vs published"
  mode, not here.
- **Aligning the compiled `.tex` to two-column camera-ready.** Making the
  actual PDF two-column (spanning title/abstract, `figure*` wide figures,
  achemso `journal` layout, elsarticle `5p`) changes real output and must
  be compile-tested on Cloud Run — the natural next step so the built PDF
  matches the viewer, kept out of this pass to avoid regressing the
  working export. The viewer is the design target ahead of that work.
