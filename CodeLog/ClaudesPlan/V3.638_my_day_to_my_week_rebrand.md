# V3.638 — "My Day" → "My Week" rebrand

## Goal

Alex: *"rebrand my day to my week everywhere."*

The unified student entry surface shipped in V3.526 as **My Day**. V3.563
added Day / Week / Month horizon tabs to it, and in practice the week is
the horizon that matters — PMR periods are weekly, Team Focus is weekly,
`focusAreas` are weekly, and `⤓ Assemble my week` (V3.532) pulls a week.
The name is now the odd one out. This release renames the surface and
flips its default horizon to Week.

## Decisions (confirmed with Alex before implementing)

Three layers were on the table; Alex picked the middle depth plus the
behavior flip.

### 1. Visible labels — RENAME

Every string a lab member reads becomes "My Week": nav entry, page
`<title>`/`<h1>`, the phone app's bottom tab, the PMR "My Day ledger"
block heading, the home-feed tile, the surface-guide blurbs on
huddle/tracker/tasks/notebook/PMR, and the retirement banners on the
tracker and tasks workspaces.

Code **comments** are renamed too. A comment describing "the My Day
composer" would send the next reader looking for a surface that no
longer exists. Version citations inside those comments (`V3.526`,
`V3.532`) are the durable pointer to the plan docs and are left intact —
the plan-doc filenames on disk (`V3.526_my_day_program.md`, …) and the
shipped CHANGELOG entries are **history and are not rewritten**.

### 2. URL + filenames — RENAME, with a redirect stub

```
rm/pages/my-day.html  →  rm/pages/my-week.html
rm/js/my-day.js       →  rm/js/my-week.js
rm/css/my-day.css     →  rm/css/my-week.css
```

A stub stays at `rm/pages/my-day.html` that `location.replace()`s to the
new path **preserving `search` + `hash`**, with a `<noscript>` meta
refresh fallback. It cannot be dropped, because `/rm/pages/my-day.html`
is baked into data that is already written and is not migrated:

- `day-distribute.js` stamps `reference_links: [{ label: 'Planned in
  My Day', url: '/rm/pages/my-day.html?date=…' }]` onto **every notebook
  stub** it has ever created (line ~516);
- notification/feed docs written by past releases carry the same path;
- lab members have it bookmarked, and the iOS app's saved start path
  points at it until the new build lands.

The `?date=` and `?view=` params must survive the hop, hence the
script-first stub — a bare `<meta http-equiv="refresh">` drops the query
string.

### 3. Stored data keys — UNCHANGED

Renaming these buys nothing a user can see and costs an admin-migrate
sweep, so they stay exactly as they are:

| Identifier | Where |
|---|---|
| `userData/{uid}/dayPlans/{itemId}` | the hub collection (day-distribute, pmr, home-feed, huddle) |
| `source: 'my-day'` | stamped on every distributed record; `pmr-week-assemble.js:104` filters on it |
| `myday_ledger` | PMR block key, persisted in per-user PMR block config |
| `myday_retire_huddle_composer` / `_tracker_manual` / `_task_add` | `labConfig/featureFlags` |
| `myday-<itemId>` | `paper-figures/` pseudo-id for outcome images (V3.623) |
| `myday` | native tab key (`TabKey.myday`) + presence surface key compared server-side in `functions/helpers/notify.js` |
| `md-*` | the CSS class prefix throughout `my-week.css` |
| `#myday-root` | the page's mount node |

Consequence to accept knowingly: the code now says `My Week` in prose
and `myday`/`dayPlans` in identifiers. That seam is deliberate and is
documented here and in ARCHITECTURE so it doesn't read as an oversight.

### 4. Default horizon — Day → Week

`my-week.js` `state.view` seeds `'week'` instead of `'day'`. The
`[ Day ][ Week ][ Month ]` tabs are untouched and `?view=day` still
overrides, so nothing is lost — the page just opens on the horizon it is
now named after.

Knock-on inside the same file: the composer is a pop-up sheet on the
planning horizons (day/week) and stays available; `renderDatebar()` is
day-only and simply doesn't paint on first load; `loadWeek()` runs on
boot where `loadDay()` used to. All three already existed as tab-switch
paths, so this is a seed change, not new code.

## The mobile app must ship in the same batch

`OurlabMobile` is **not** a URL wrapper — `scripts/sync-rm.mjs` bundles
the whole `rm/` tree into the app, and the native multi-WebView shell
(V3.585) routes tabs by **literal filename**:

```swift
// TabRoute.swift
static let startPaths: [TabKey: String] = [ .myday: "rm/pages/my-day.html", … ]
static func key(forPath path: String) -> TabKey {
    if file == "my-day.html" { return .myday }
```

Left alone, the renamed page would land in `.misc` instead of `.myday` —
the primary tab loses its highlight *and* its pinned push-notification
bridge (`TabBridgeViewController.isPrimary`). So the Swift side changes
here, and the three filename matchers that are already documented as
"KEEP IN LOCKSTEP" move together:

1. `rm/js/mobile-shell.js` — `TABS[0].href` + `match`
2. `rm/js/tab-lifecycle.js` — `selfCheck()` file→key map
3. `ios/App/App/TabRoute.swift` — `startPaths` + `key(forPath:)`

All three match **both** filenames (`/\/my-(day|week)\.html$/`) so an app
build running against the redirect stub, or a deep link from an old
notification, still resolves to the My Week tab rather than `.misc`.

Also updated: `TabShellViewController.swift`'s hardcoded fallback path
and `sync-rm.mjs`'s generated `www/index.html` redirect (the app's entry
point lands directly on this page, V3.574).

## Deploy

**FTP-only** on the web side — no rules, indexes, or functions change
(the `firestore.rules` edits are comment text only, so no
`firebase deploy` is required; the file ships with the next rules deploy
whenever one happens for another reason).

The TestFlight build is **not optional this time**. An FTP-only push
would leave phone users on a build whose Swift router still expects
`my-day.html`; they'd hit the redirect stub and — without the Swift
change — land in `.misc`. `scripts/release_push.py` ships both, and the
announcement names the build. `--minor` is appropriate: native Swift
files changed.
