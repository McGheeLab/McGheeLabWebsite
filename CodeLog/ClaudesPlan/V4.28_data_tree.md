# V4.28 — The Data tab leaves; the data tree in a component

## Goal
Gabe (18 Nov 2026): "Remove the data tab. Instead, data used in the experiment gets logged in the note component as a list of folders or files as a directory, appearing as a data tree."

## Approach
- **No Data tab in any build.**
  - `data` leaves `TABS` (`scientia/src/11-shell.js`). The web build already dropped it (lab-mode §1).
  - The desktop lab build re-added it after the lab layer ran (`23d-desktoplab.js`, `DESKLAB.KEEP`). It now keeps the app's own pages (`VIEWS.activity`, `VIEWS.data`) but re-adds no tab (`KEEP_TABS: []`), so `#/data` still opens the app's page there instead of lab-mode's "Desktop only" pointer.
  - The old page stays reachable at `#/data` and with the new `/datasets` command. It opens with a notice saying where data goes now. Nothing registered before is lost.
- **`DTREE` (`scientia/src/13zzyc-datatree.js`, new):**
  - **The record.** `b.dtree = { items, mig }` lives on the component itself, so it syncs with the note. The `datasets` store never left a computer (`13zc-sync.js` SKIP).
  - **An entry** is a folder (`dir`, `k`, `more`) or a file (`s` bytes, `m` modified). A top-level entry also has `id`, `at` (logged), `via` (folder / files / drop / dataset), and `h` (a device kept its handle). After a rescan it can carry `st` (new / changed / gone) and `was`.
  - **Listings.** `fromDir` reads a FileSystemDirectoryHandle; `fromEntry` reads `webkitGetAsEntry`; `fromFiles` reads `<input>` files with `webkitRelativePath`. Each goes six folders deep and caps at 1500 entries per logging, with an "n more not listed" note. Hidden files are left out. Folders come first, sorted by natural name.
  - **Drawing.** `el` draws under the component's text, before its chips:
    - the header: "Data", a summary ("2 folders · 41 files · 3.4 GB"), "as logged <day>" when this device cannot read the folder again, the pending changes with Accept, ⟳ Rescan, + and × for an empty tree;
    - indented rows with folder or file icons (inline Heroicons, monochrome), each folder's files and size, each file's size and date. The tooltip has the full path.
  - **Folding.** A click folds or unfolds a folder, redrawn in place (no refresh of the note), and the state is kept on this device (`_ls dtOpen`). A logged folder shows its first level; folders inside it start folded ([[scientia-nothing-opens-uninvited]]). A folder shows 12 entries, then "+ n more".
  - **× and undo.** × takes an entry out. `save` makes each change one undo step together with the moves it causes: the note's settle and the reflow write in later groups of their own, merged afterwards as `13zz4` merges a split. Without the merge, Undo kept undoing a fresh settle and never reached the change.
  - **Rescan.** The handle is kept on this device only (`blobs` `dth:<id>`, like `DATA`'s folders). `rescan` re-reads every entry it can (asking for read access after a restart), and `diff` marks new, changed (with `was`) and gone. `accept` clears the marks and drops the gone.
  - **Ways in:**
    - ⋯ → **Log data…** (before "Data, materials & code…"; on a run, before "Materials & data of this run…"): Add a folder… / Add files…;
    - **/data** (`CMD.add`): in a component, its tree; without one (the navigation bar), a new component labelled "Data";
    - **drops** (document capture listeners, ahead of 13zzs's): on a tree, or on a component with Alt held. A drop holding a folder goes anywhere on a component, or onto the paper as a new "Data" component. Files alone are placed as before.
    - The pickers are `showDirectoryPicker` / `showOpenFilePicker`, falling back to `<input type=file multiple webkitdirectory>` (the listing without a rescan).
  - **The datasets bound before** (`binds.datasets`, and a dataset's `producedBy` step) come into the component's tree once, grouped by folder (`migrate`, run with `ensureStandardTemplates`). `b.dtree.mig` remembers which were taken in, so an entry taken out does not come back. `binds` stays for provenance.
  - **Elsewhere:** `M.removeEmptyBlock` keeps a component holding a tree (Backspace), and the notebook folder's Markdown lists the tree (`VAULT.component`).
- **Settings → Widgets → Data tree** (`datatree`, in Simple too):
  - the switch: off, the trees hide and the ways in go; the records stay;
  - "A folder you log shows": Its first level / Only its name;
  - a live preview: a component with a tree whose folders fold.
  - "Data & plots" no longer claims the Data tab (`tab: 'data'` gone) and says where data goes now.

## Decisions where the request was silent
- **No + Insert row.** The lab layer gives every + Insert row its own icon (`INS_PICS` in lab-mode.js), and the v3869 harness fails on a row without one. lab-mode.js is the lab's to edit, so `/data` (also from the navigation bar) makes a "Data" component instead.
- **Drops:** a drop on a tree, Alt on a component, or a folder anywhere on a component or the paper. Files dropped plainly keep their old meaning (a picture, a PDF, a page).
- **Runs too:** a protocol run's box can hold a tree (its "Materials & data of this run…" menu gains Log data…).
- The tree has no scroll box of its own (on the canvas a nested scroll would catch the wheel). Folders start folded and show 12 entries, so a component stays a sensible size.
