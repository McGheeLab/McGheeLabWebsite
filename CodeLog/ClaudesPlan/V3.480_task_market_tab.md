# V3.480 — Task Market becomes a tab in the Tasks page

## Goal

Fold the standalone Task Market board (`task-market.html`) into the
unified Tasks page as a fifth tab (`tasks.html?tab=market`), matching the
V3.58 consolidation pattern that already absorbed inbox / archive / add.

## Why this is nearly free

`task-market.js` is *already loaded* in `tasks.html` (V3.317) in
"embedded / composer-only" mode: its `init()` bails early when there is no
`#tm-board` in the DOM, exposing only `TASK_MARKET.openComposer`. All we
have to do is render the board's mount points (`#tm-board`,
`#tm-assignments`, `#tm-tabs`, and the `tm-new` / `tm-need-work` buttons)
when the `market` tab is active — then the same `init()` that runs on the
standalone page boots the full board here. No JS logic changes needed.

The board's `?view=assignments` deep-link already reads `location.search`,
so `tasks.html?tab=market&view=assignments` lands on the Assignments view
for free.

## Files to modify

1. **`rm/css/task-market.css` (NEW)** — extract the board `<style>` block
   verbatim from `task-market.html` into a shared stylesheet
   (`.tm-board` grid, `.tm-col`, `.tm-card`, `.tm-tabs`, `.tm-arow`,
   composer/modal). Linked by `tasks.html`.

2. **`rm/pages/tasks.html`** —
   - `validTabs` / `TITLES` / `HUB` tab bar gain `market`.
   - `HEADERS.market` = `<h1>` + `🙋 I need work` / `＋ New post` buttons
     (ids `tm-need-work` / `tm-new`, which `task-market.js` binds).
   - `CONTAINERS.market` = hint + `#tm-tabs` (Board | Assignments) +
     `#tm-board` + `#tm-assignments`.
   - `SCRIPTS.market` = none — guard the `document.write` so it only fires
     when a per-tab script exists (task-market.js is already loaded on the
     page; re-loading it would double the Firestore listeners).
   - Link `task-market.css`.

3. **`rm/pages/task-market.html`** — convert to a `<meta refresh>`
   redirect → `tasks.html?tab=market` (preserving `?view=assignments`),
   the same bookmark-survival treatment the old tasks-inbox/archive/add
   pages got.

4. **`rm/js/nav.js`** — repoint the "Task Market" Activity child to
   `/rm/pages/tasks.html?tab=market`.

5. **`rm/js/page-registry.js`** — the derived page id changes from
   `task-market` to `tasks__tab__market`; update the `task-scheduling`
   default workflow's `pageIds` so the implicit-baseline access set still
   includes it. (Admins always pass; lab-members get it via baseline.
   Collaborators with an *explicit* legacy `task-market` grant would need
   a re-grant — acceptable, low-blast-radius.)

6. **`sw.js`** — `CACHE_VERSION` 449 → 450.

7. **CHANGELOG + ARCHITECTURE** — record the move.

## Key decisions

- **Reuse, don't fork.** No new renderer; the market tab drives the same
  `task-market.js` already on the page.
- **Standalone page redirects** rather than staying a duplicate board, so
  there is one source of truth for the board UI.
- **`document.write` guard** is the only load-order subtlety: the per-tab
  container HTML is written synchronously during parse (before
  `DOMContentLoaded`), so `#tm-board` exists by the time
  `task-market.js`'s `init()` runs.
