# V3.611 — Mentor access to mentees' papers + Figure board per-card threads (program R3 of 4)

## Goal

Advisors can now open their mentees' papers — read-only manuscript, full
write on the 🧭 Figure board — and every board card carries a 💬 discussion
thread where student and mentor debate the figure flow and the right set of
experiments. Per Alex: "mentors should always have access to their mentees'
papers" (they're usually coauthors anyway; this closes the gap when they're
not).

## Problem

`papers/{id}` read required `authorUids[]` membership; `isMentorOf()`
existed in rules but was only wired into PMR/notebook/focusAreas. A mentor
who wasn't listed as a coauthor could not open the editor at all — and
Firestore rules can't chain `get()`s over an author array to check
mentorship, so the fan-out has to happen server-side.

## Approach

### Mentor access (server-materialized, same trust model as authorUids)
- **`functions/paper-author-sync.js`** — `onPaperAuthorSync` now also writes
  `mentorUids[]` = deduped union of every author's
  `users/{uid}.mentor_uids` (Admin SDK; never client-writable). Clears both
  arrays when a doc stops being a paper.
- **NEW trigger `onMentorRosterSync`** (same file, registered in
  `functions/index.js`) — on `users/{uid}` writes, if `mentor_uids`
  changed, re-syncs `mentorUids` on every paper where that uid is an
  author. Early-returns on the (frequent) users-doc writes that don't touch
  the roster.
- **`firestore.rules`** — new `isPaperMentor(paperId)` helper beside
  `isPaperAuthor` (reads the SAME doc — Firestore dedupes the get, so
  `author || mentor` still costs one read). Grants:
  - `papers/{id}` read (resource.data check, mirroring the author path)
  - `yjs_snapshot` / `yjs_updates` / `blocks` / `snapshots` **read** —
    the existing read-only editor path (`firebridge.canEditPaper` is false
    for non-coauthor mentors → read-only banner + read-only blocks) works
    with zero permission errors
  - `presence` read + own-doc write (heartbeats don't error)
  - `comments` read + create (author-pinned)
  - `boardItems` full write (the board is the advisor's review surface —
    the focusAreas mentor-read+write convention)
  - **NEW `boardComments`** block (below)
  - Manuscript writes (`yjs_updates` create, `blocks` write) stay
    author/admin-only.

### Per-card threads
- **`papers/{paperId}/boardComments/{commentId}`** via the existing
  `SECTION_COMMENTS.mount` (`rm/js/section-comments.js`, now loaded by
  paper-builder.html in editor mode). Doc shape = `{item_id}` scope +
  `{body, authorUid, authorName, parentId, createdAt, modifiedAt,
  resolved}`. Rules mirror PMR comments: read/create for
  author|mentor|admin with `authorUid` pinned, update/delete
  owner-or-admin.
- **`rm/js/paper-figure-board.js`** — every card's footer 💬 button opens a
  right-side discussion panel (SECTION_COMMENTS lazy-mounts per card — the
  PMR pattern, so N cards ≠ N listeners). One collection-wide listener
  maintains per-card open-comment counts on the 💬 badges and newest-comment
  times (feeds R4's change review). Panel stops pointer/wheel propagation so
  it doesn't pan the canvas.

## Data model

- `papers/{id}.mentorUids: string[]` — Cloud-Function-materialized.
- `papers/{paperId}/boardComments/{commentId}` — new subcollection; single
  unfiltered listener client-side, **no composite indexes**.
- `onMentorRosterSync`'s `papers.where('authorUids','array-contains',uid)`
  is a single-field query — auto-indexed, no composite entry needed.

## Files modified / added

- `functions/paper-author-sync.js` — mentorUids aggregation + new trigger
- `functions/index.js` — register `onMentorRosterSync`
- `firestore.rules` — `isPaperMentor` + grants + `boardComments` block
- `rm/js/paper-figure-board.js` — 💬 badges, counts listener, thread panel
- `rm/css/paper-figure-board.css` — panel styles
- `rm/pages/paper-builder.html` — load `section-comments.js` in editor mode
- `sw.js` — CACHE_VERSION 580 → 581

## Release ritual

**Deploy BEFORE FTP, in this order:**
1. `firebase deploy --only functions:onPaperAuthorSync,functions:onMentorRosterSync`
2. `firebase deploy --only firestore:rules`
3. FTP (batched per the ledger)

**Backfill:** existing papers have no `mentorUids` until their projects doc
is next written. After the functions deploy, run a one-off touch of each
`projects` doc where `type=='paper'` (e.g. re-save `updatedAt`) — or simply
accept lazy materialization; the paper's next metadata save fixes it. The
V3.612 release ships an admin backfill note if needed.

## Rollback

Remove the mentor grants from rules + redeploy (mentorUids on papers docs
becomes inert data). Functions revert to the previous author-only sync.
boardComments docs are additive.

## Open questions

- `mentorUids` = mentors of ALL authors (not just the lead) — deliberate;
  revisit if it over-shares.
- Mentor discovery UX: mentors find the paper via the Papers list (projects
  reads are lab-wide) or PMR's paper-writing block; no dedicated "my
  mentees' papers" shelf yet.

## Verification

1. As a mentor (not coauthor) of a student with a paper: open the paper →
   read-only banner, content renders, no console permission errors; 🧭
   Figure board fully editable; post a 💬 comment on a card.
2. As the student: see the mentor's comment live; reply; badge counts
   update on both screens.
3. Edit a user's mentors on the Permissions page → that student's papers'
   `mentorUids` update (check Firestore) and the new mentor can open them.
4. A lab member who is neither author nor mentor still gets no access.
