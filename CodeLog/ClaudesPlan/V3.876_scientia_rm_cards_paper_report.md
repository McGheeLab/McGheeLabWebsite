## The design choice: run RM's own UI in the notebook that hosts Scientia

The Lab Notebook's card renderers (`notebook-canvas.js` `renderProtocol / renderInventory / renderAction`, the paper card
in `canvas-paper-reader.js`) are bound to that page's state — embedding them inside Scientia's document is not practical,
and re-implementing their writers (My Week's `saveOutcome` cascades to copies, the PMR ledger and the activity record)
would be a second copy of each. But the web app always runs **inside** `notebook.html`, which already loads
`CANVAS_PAPER_READER`, `MYWEEK_REPORT`, `DAY_DISTRIBUTE`, `USER_ACTIONS`. So Scientia's cards keep their data in
Scientia's blocks (which sync, to the desktop too) and **ask their host to run RM's UI**, over the V3.864 postMessage
bridge:

```
Scientia (iframe)                                         notebook.html (notebook-scientia.js)
  {sis, type: 'rm-read',   reqId, paper, focus}     ──▶   CANVAS_PAPER_READER.openReader(item, api, {focus})  — RM's reader over the notebook
  {sis, type: 'rm-report', reqId, card, point}      ──▶   MYWEEK_REPORT.open({card, point → notebook coords, onReported})
                         ◀── {sisCmd: 'rm-ack', reqId, ok}            (no ack within 0.9 s = not inside the notebook → fall back)
                         ◀── {sisCmd: 'rm-reported', reqId, blockId, step: {id, title, date}}
                         ◀── {sisCmd: 'rm-reader-closed', paperId}    (the reader's element is gone → cards refresh highlights)
```

## What this version does (web build; `scientia/src` untouched)

- **Paper card** (`+ Insert → Reading → Paper from the library…`, block kind `rmpaper`, `paperId`): the paper's sigil,
  title and APA line, *pdf in RM / pdf here / no pdf*, **Read**, **Open in RM**, **Refresh**, and your RM highlights in
  RM's colours (yellow note, green evidence, red critique, blue method, purple investigate, orange quote) — "N highlights
  of yours · M from the lab", eight rows, each opening the reader at that highlight. The block's text is
  `Paper: <title>\n<APA>` so the desktop app, which has no paper card, shows it readably. ⋯ → Read / Open in RM /
  Change the paper…
- **Reading in place**: *Read* on a paper card, on the Library tab and on `#/read/<paper>` opens **RM's reader over the
  Lab Notebook** (highlight, snip; highlights are RM's own `papers/{id}/annotations`). Outside the notebook it falls back
  to the paper's page in a new tab.
- **✓ on every component** (in its header, before ⋯): *Report this as the result of a My Week step* → RM's report picker
  in the notebook (four weeks of steps, "Needs a result" first) → RM's writer marks the step done with this component as
  its result link (`kind 'scientia_block'`, the note's Lab Notebook URL); the step comes back onto the block
  (`myweek: [{stepId, title, date, at}]`) and the ✓ fills. Outside the notebook: a hint, nothing written.
- **The material card for an inventory item**: `+ Insert → Material…` now opens *From the lab inventory* (search, *Place
  its card here* — makes or reuses the material note with `inventoryId` and places Gabe's material card) with *Pick one of
  your materials…* for his own picker; a material card whose material came from the inventory shows *In the lab inventory
  · Open in RM · Log a use in RM*.

## Design details

- Hub: `GET api/rm/annotations?paperId=` — `visibleAnnotations(docs, uid)` (the Firestore rule's read: visibility `lab`
  or the creator) → `rmAnnotationRow` `{id, color, type, page, exact, comment, mine, by, at}`, by page; ≤ 300.
  `FirestoreHub.annotations` reads `papers/{paperId}/annotations` with the Admin SDK; `MemoryHub` serves `rmAnnotations`.
  **Deployed**; health string V3.876.
- Host (`rm/js/notebook-scientia.js` `onFrameMessage`): `openReaderFor(paper, focus)` (a minimal item `{data: {paperId,
  title, cite, journal, pdf}}`, an api with `canEdit: true` and no-op writers; a 700 ms watch for the reader's element
  posts `rm-reader-closed`), `openReportFor(card, point, reqId)` (point translated by the frame's rect).
- Lab mode §8 (`rm/scientia/lab-mode.js`): `ORIGIN` (a `srcdoc` test frame has `location.origin === 'null'`),
  `hostRequest(type, payload, ms)` → `{id, ack}`, a message listener for `rm-ack / rm-reported / rm-reader-closed`;
  `readPaper(r, focus)`; `WIDGETS.rmpaper` + `INSERTS 'rmpaper'`, `placePaper`, `pickPaper` (Gabe's `modal` +
  `optionPicker`, sections *The lab's library / Only in this notebook*); `highlights(paperId)` (60 s cache), `fillHl`,
  `refreshPaperCards`; `reportBlock(b, e)` + `DocView.box` wrapped (panes are `Object.create(DocView)`, so every pane gets
  it); `MATS2.cardBody` wrapped and `WIDGETS.matcard.body` re-pointed (a captured reference); the `material` INSERT's
  `run` wrapped by `materialFromInventory`; a small `<style id="lab-mode-css">`. `SIS_LAB.version` V3.876.
- Figure cards are **mapped, not ported**: Gabe's image panel (`13x-figure`) already stores its images through the hub's
  media (Storage) — the notebook's Figure card has nothing it lacks.
