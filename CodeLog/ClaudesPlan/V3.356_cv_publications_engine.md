# V3.356 — CV publications engine (FuturePlan 11, Release 4)

**Goal:** nobody hand-types their publication list. Pull it from the lab
library, let ORCID imports arrive complete, and make citation refresh fast.

## What shipped

1. **📚 Pull from library** — NEW
   [`rm/js/cv-library-pull.js`](../../rm/js/cv-library-pull.js). Loads
   `api.load('library/papers.json')` (lab-scope items route), keeps
   `meta.library.is_library_entry` rows. Library entries carry **no
   author↔uid link**, so matching is by NAME (family match + given-initial
   agreement; `splitName`/`authorMatches`) against the member's CV/RM
   profile name — always behind a review checklist: matches pre-checked,
   `CVImport.findDuplicates` rows flagged "[already on CV]" and unchecked,
   "show all library papers" reveals non-matches. Import maps
   `meta.library` → journals entries (authors formatted "Family GI",
   journal/year/volume/issue/pages/doi, status Published) through the
   editor's `savePayload` (so profile-sync + preview refresh fire).
2. **ORCID enrichment** — ORCID works arrive with empty
   authors/volume/pages; after selection, each entry with a DOI is
   completed from CrossRef (`CVImport.enrichEntryFromDOI` — existing
   values always win) with live progress in the dialog.
3. **Batched CrossRef** — `CVImport.runBatched(items, worker, onProgress,
   concurrency=4)`: small worker pool with a 150ms per-lane stagger;
   failures resolve null instead of aborting.
   `fetchCitationCountsBatched` replaces the strictly-sequential
   350ms/DOI citation-refresh loop (progress chip counts through).
