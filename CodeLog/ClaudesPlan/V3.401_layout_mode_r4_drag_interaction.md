# V3.401 — Layout Mode R4: drag & drop interaction

> Release 4 of the Layout Mode program (R1 V3.395 foundation, R2 V3.397
> float engine, R3 V3.399 region overlay). The ⬒ Layout overlay becomes
> an interactive SESSION for editors: press-and-drag any figure/table
> to move it between page bands and the text flow; tables gain the
> layout popover. R5 (resize handles + replace image) remains.

## What shipped (rm/js/paper-doc-view.js + rm/css/paper-doc-view.css)

1. **Layout session** — for editors, toggling ⬒ Layout now also enters
   `state.layoutSession`: drags enabled (`.pdv-session` grab cursors +
   `touch-action:none`), and the live loop becomes
   **origin-discriminated**: `onYUpdate(update, origin)` ignores this
   view's own transact origins (`LAYOUT_ORIGINS` — fig/tab intent
   writes, figure-upload, the two block-move origins; each manipulation
   schedules its own 150 ms render), while any OTHER origin — a
   collaborator's edit — raises a "exit ⬒ Layout to refresh" banner and
   defers the refresh to session exit (a mid-drag re-render would
   destroy the dragged node). `paper-panel-changed` is suppressed
   in-session (echoes of our own writes). Exit with pending remote
   edits → forced full render.
2. **Session measure cache** — during a session, document CONTENT is
   frozen (own writes touch only layout attrs; remote edits defer), so
   `_measureItems` memoizes heights keyed on
   `blockId|type|width|innerHTML.length` in `state.measureCache`.
   Gated STRICTLY on the session (the live loop must never trust
   length-keyed heights — same-length edits could alias). A
   manipulation re-render probes ~only the manipulated item.
3. **Drag & drop** — protocol-graph-editor pointer pattern: delegated
   `pointerdown` on the desk (session-gated, primary button, 5 px
   threshold so plain clicks still select/popover) → fixed-position
   half-scale ghost + status chip; **geometric drop resolution** (sheet
   under pointer via elementFromPoint → sheet-local y ÷ `state.zoomK`
   → top strip / bottom strip / flow block), drop-zone strips per sheet
   (pure affordance, shown only while dragging), `.pdv-drop-before`
   accent on flow targets, desk auto-scroll within 48 px edges, Esc
   cancels. On release, ONE set of writes:
   - **band drop** → `anchor` transact; if the target page differs,
     `PaperEditor.moveBlockToPosition` reorders the block to just
     before that page's first real block (`page.firstFlow`, recorded by
     the packer) so the deterministic packer lands it there;
   - **flow drop** → `anchor='flow'` + reorder before the target block
     (paragraphs/equations now carry `data-block-id`/`data-block-kind`
     for targeting). Src/dst resolved against the LIVE tree at drop
     time (`_locateLiveBlock`).
4. **Tables get the layout popover** — clicking a table opens the shared
   popover in anchor/span/lock-only form ("Table layout"; no width/
   placement/centering — LaTeX tables size to content), writing
   `tab-anchor`/`tab-span`/`tab-lock` origins. Popover re-anchor after
   re-renders finds table wraps too.
5. Teardown: `close()` cancels drags, clears session/banner/cache;
   sheet elements carry `data-page-idx`.

## Deliberate choices / deviations

- **Pin snapshot skipped** (was in the master plan): during a session
  content is frozen, so page assignments only shift as a CONSEQUENCE of
  the user's own manipulation — which is real feedback, not noise; the
  FLOAT_MAX_FRAC budget already bounds oscillation. Revisit only if
  band-drops feel jumpy in practice.
- Column-slot targeting (dropping into the empty half of a paired row)
  is implicit — the packer pairs column floats automatically; span
  changes stay in the popover until R5's resize crossover.
- Band drop on a page with no addressable first block (float-only
  pages) sets the anchor but skips the reorder.
