# V3.285 — BME 295C submit reliability hardening

Synthesizes the V3.285 audit (Workflow `wf_622dff3f-796`, 4 trace + 2 verify + 1 synthesize agents) that traced every failure mode causing student submits to silently drop or partially write. Ranks 1-2 are the live causes of "groups couldn't submit"; ranks 5-6-8-12 are correctness hazards that were silently corrupting state.

## Fix 1 — visible early-return reasons in `saveBmeGroupResponsePrompts`

Pre-V3.285, four early returns ([class-builder.js:5290-5309](class-builder.js#L5290-L5309)) hit `console.warn` + `return;` with no user-visible feedback. The student clicked submit, the button didn't change, no toast, no banner — only DevTools showed the drop. **Source of every "I clicked submit and nothing happened" report.**

Move `statusEl` lookup ABOVE the early returns; replace each `return;` with `statusEl.textContent = 'Cannot submit — <reason>'` + flash the parent card's submit button red via a new `.cb295-response-submit-failed` class that auto-clears after 6s. The console.warns stay (they're for the admin debugging).

## Fix 2 — drop legacy `groupNumber` fallback + add visible "no group" banner

`bmeGetGroupForDay` ([class-builder.js:3456-3463](class-builder.js#L3456-L3463)) falls back to `entry.groupNumber` when `dailyGroups[day]` is missing. If admin auto-assigned only Monday, every Tue-Fri submit lands at `${campus}-${MondayGroup}-${tueWedThuFriSlug}` — admin's live monitor for Tue reads `dailyGroups[Tuesday]` (undefined → no T-column for the student), so submitted docs appear missing.

- Drop the fallback: `return null` when `dailyGroups[day]` is missing.
- In `buildBmeResponseShell` ([class-builder.js:4378](class-builder.js#L4378)), add a new branch for `eligibleToEdit-except-dayGroup` (i.e. `signedIn && entry && entry.campus && !dayGroup`): render a `.cb295-response-no-group` callout ("Your group for this day hasn't been assigned yet — ask your instructor"). This is the visible side of the silent-routing bug.
- The auto-assigner that already populates `dailyGroups[day]` per day is unchanged; this is purely a *defensive removal of a routing path that was masking missing assignments*.

## Fix 3 — submit handler: clearTimeout + in-flight guard + cancel callback

Submit handler ([class-builder.js:5048-5063](class-builder.js#L5048-L5063)) has three race conditions:
1. **Autosave race (rank 8)**: 800ms autosave debouncer can fire mid-submit and `merge: true`-overwrite `status: 'submitted'` back to `'draft'`. Signature: `status === 'draft'` AND `submittedAt` non-null AND `lastEditedAt` within seconds of `submittedAt`.
2. **Double-click (rank 12)**: button isn't disabled during in-flight; `openBmeAttendanceModal` calls `closeBmeAttendanceModal` first, so a second click wipes the first modal and confuses the user.
3. **Modal-close-without-confirm**: cancel/X/overlay click closes the modal but never re-enables the button.

Fix:

```js
const _bmeSubmitInFlight = new Set();

btn.addEventListener('click', () => {
  const slug = btn.dataset.speakerSlug;
  if (_bmeSubmitInFlight.has(slug)) return;
  _bmeSubmitInFlight.add(slug);
  btn.disabled = true;
  // Kill the pending autosave so it doesn't race the submit's merge:true.
  clearTimeout(_bmeResponseSaveTimers[slug]);
  _bmeResponseSaveTimers[slug] = null;
  const release = () => {
    _bmeSubmitInFlight.delete(slug);
    btn.disabled = false;
  };
  const safetyTimer = setTimeout(release, 30000); // never strand the button
  const finish = () => { clearTimeout(safetyTimer); release(); };

  const current = _bmeGroupResponses?.get(slug) || null;
  const prompts = bmeReadPromptsFromDom(slug);
  if (current?.status === 'submitted') {
    saveBmeGroupResponsePrompts(slug, prompts, 'draft', null).finally(finish);
    return;
  }
  openBmeAttendanceModal(slug, prompts, (attendance) => {
    saveBmeGroupResponsePrompts(slug, prompts, 'submitted', { attendance }).finally(finish);
  }, finish); // onCancel — fires when user dismisses modal without confirming
});
```

Extend `openBmeAttendanceModal(slug, prompts, onConfirm, onCancel)`: set `confirmed = true` flag inside each confirm path; the close() helper fires `onCancel` only when `!confirmed`.

## Fix 4 — `schedules/{scheduleId}` onSnapshot listener for live gate state

Pre-V3.285 the schedule doc is loaded once at page entry and goes stale. When admin clicks Open / Lock in the discussion-gate panel ([class-builder.js:6585](class-builder.js#L6585)), students on the modules tab keep seeing the previous gate state until they manually reload. Outcomes:

- **Open → Pending** while student composes: their textarea is still mounted; autosave + submit succeed against the gate-bypass path (rank 6). Submitted text appears in Firestore but the student can't see it after their next refresh.
- **Pending → Open** during a talk: students keep seeing the "Discussion not yet open" callout until they reload — they think submitting is impossible.
- **Open → Locked** after a talk: students keep editing, submits succeed past the gate (rank 14).

Fix:

```js
let _bmeScheduleUnsub = null;

function attachBmeScheduleListener() {
  if (_bmeScheduleUnsub) return;
  _bmeScheduleUnsub = McgheeLab.db.collection('schedules').doc(_scheduleId)
    .onSnapshot((doc) => {
      if (!doc.exists) return;
      const next = doc.data();
      // Splice in only the fields that admin commonly flips mid-session
      // (gate state, daily attendance, groups, instructors). Avoid blowing
      // away the current user's local edits — _classData is also written
      // by persistAll on admin-side edits, so a full replace would race.
      if (!_classData) return;
      _classData.discussionState = next.discussionState || {};
      _classData.dailyAttendance = next.dailyAttendance || {};
      _classData.studentRoster   = Array.isArray(next.studentRoster) ? next.studentRoster : _classData.studentRoster;
      _classData.instructors     = next.instructors || _classData.instructors;
      _classData.classAdminEmails = next.classAdminEmails || _classData.classAdminEmails;
      _classData.testMode        = !!next.testMode;
      // Re-render the modules tab if it's the active tab so the gate
      // strip flips immediately.
      refreshCanvas();
    }, (err) => console.warn('[bme295c] schedule onSnapshot error', err));
}

function detachBmeScheduleListener() {
  if (_bmeScheduleUnsub) {
    try { _bmeScheduleUnsub(); } catch (e) {}
    _bmeScheduleUnsub = null;
  }
}
```

Attach in `wireClassPage` after `loadBme295cData`. Detach in `cleanupListeners`. Skip the attach in admin view (admin's own edits already trigger refreshCanvas locally via persistAll; the snapshot would echo their own writes and cause stutter).

## Fix 5 — gate check + `gateStateAtWrite` payload stamp

Add a gate check at the top of `saveBmeGroupResponsePrompts` (after the precondition branches):

```js
const gateState = bmeGetDiscussionState(speakerSlug);
if (gateState !== 'open') {
  if (statusEl) statusEl.textContent = 'Cannot submit — discussion is ' + gateState;
  console.warn('[bme295c] save blocked — gate is', gateState, 'for', speakerSlug);
  return;
}
```

And stamp the gate state on every payload for forensic audit:
```js
payload.gateStateAtWrite = gateState;
```

This lets admin retroactively detect any gate-bypass writes (filter `groupResponses` for `gateStateAtWrite !== 'open'`).

Combined with Fix 4's live snapshot, students whose gate flipped mid-session see the new state at most a couple seconds later, and the save path won't write past a closed gate even with a stale cache.
