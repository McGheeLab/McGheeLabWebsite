## What this version does

- **Reminders and chores reach My Week.** Each upcoming occurrence of a Scientia chore (every N days after it was last
  done, or on chosen weekdays) and of a deadline, meeting or reminder (one-off, or daily / weekly / monthly) becomes a
  dated item in the person's RM list, labelled *Scientia · Chore / Deadline / Meeting / Reminder*. My Week holds each
  back until its week, exactly like a lab chore. Ticks flow both ways: done in My Week → the chore's day is ticked /
  the reminder is done for that date in the notebook; ticked in the notebook → the My Week item is done. Stopping a
  chore or deleting a reminder dismisses its open items. Two weeks ahead at most; one-off reminders up to a week overdue.
- **The notebook counts as activity.** Every note worked on — edited, or timed with Scientia's timer, from the web or
  from Gabe's computer — is one entry per note per day in RM's tracker (*Scientia: Gel run 3 · 1 h 50 min timed*),
  the same shape the Lab Notebook's own entries use. No hours are asked for (RM dropped hours in V3.319); the minutes
  ride along on the event for anyone who wants them.
- **Reconciliation never waits for someone to open the app.** Every connected device's pull now runs the throttled
  syncs (library 5 min; tasks, reminders/chores, activity 2 min each), so while Gabe's desktop bridge or a browser is
  connected, RM and the notebook stay in step. A tick in the web app asks for the reminders/chores and activity syncs at
  once, after its change has reached the hub.
- The meeting chore board stays RM's: it is the lab's rota; Scientia's chores are a person's own bench routine
  (passaging, media changes). Both now land in the same My Week inbox, labelled apart.

## Design

### Hub (`functions/scientia-hub-core.js` pure logic; `functions/scientia-hub.js` Firestore)

**Dates** are the lab's local days (`LAB_TZ = 'America/Phoenix'`; `todayIn`, `nowIn`, `localDayOf` for RM's ISO-with-Z
times); day arithmetic on `YYYY-MM-DD` strings (`addDays_`, `wdayOf`).

**Occurrences** (`whenOcc(store, rec, day)` → `{valid, done}`; `whenCandidates({chores, reminders, today})`):
- chore, weekdays: valid on its weekdays from `start`; done when `done` holds the day;
- chore, interval: the open occurrence is `choreNext` = last done (or start) + every; done when any done day ≥ it;
- reminder (not `kind: 'task'`, not `rt_*` — task reminders are V3.872's): one-off valid on the day of `at`, done when
  `done` is set; repeating valid on its stepped days, done when the day is in `skip` (Scientia's per-date done).
- Offered: weekday chores and repeating reminders from today to +13 days; an interval chore's open occurrence;
  one-off reminders −7 … +13 days.

**The RM item** (`rmWhenTask`): `userData/{uid}/tasks/sis-<ch|rm>-<id>-<day>` — `text` (chore title; *Deadline:* /
*Meeting:* prefix and time for reminders), `bucket: 'assigned'`, `due_date` = the day, `source: 'scientia'`,
`source_ref: {kind: 'scientia-when', label, scientia: {store, id, date}}`, `sis_done`. Created with `create()` (an
existing doc is never overwritten). Tracked on the hub doc as `rmWhen: {taskId: {store, id, date}}`.

**Done, three-way on a boolean** (`planWhen`): `sis_done` on the RM doc is the value both sides last agreed. Scientia
moved away from it → patch the RM doc; RM moved → edit the chore / reminder (weekday: add/remove the day; interval:
add the lab day it was done, never earlier than the occurrence; remove the day that satisfied it; one-off: `done`;
repeating: `skip`) and push it as device **RM My Week**; both moved → they agree, record it. An occurrence no longer
valid → its open item is dismissed (`dismissed_reason: 'gone from Scientia'`) and untracked; an item dismissed in RM
leaves the notebook alone; a deleted RM doc is untracked; done items older than a week are untracked. Occurrences are
offered AFTER the edits, so a chore ticked in My Week shows its next occurrence in the same pass.

**Activity** (`activityGroups`, `planActivity`): changed `sessions` (closed segments, by the day each began) and
`documents` (`modified`) of the last 3 days → one event per note per day, id `auto-scientia-note-<docId>-<day>` (the
ActivitySignals id scheme), fields `date, text, categoryPath ['research','notebook'], kind 'work', source 'scientia',
source_ref {kind 'scientia-note', id, path → the note in the Lab Notebook}, scheduled_for null`, plus
`scientia_sessions {sessionId: seconds}` (merged, so two devices' sessions add up), `scientia_minutes`,
`scientia_edited`, `scientia_type`. An unchanged event is not rewritten; an hours-era decided doc is left alone. The
Firestore hub reads only the ops since `actCursor` (falls back to scanning the rows on the first run or after ops
were trimmed).

**When it runs**: `quietSyncs(who, {force, only})` — one read of the hub doc decides which syncs are due; called on
hello, state and **every pull**; `POST api/rm/sync?only=when,activity` forces named ones. Health string V3.874.
**Deployed** before the client.
