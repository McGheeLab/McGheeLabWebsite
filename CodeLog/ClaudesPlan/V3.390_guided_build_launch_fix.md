# V3.390 — Fix: guided-build tour blinks away / demo opens pre-populated

## Context

After V3.389, launching a demo lesson misbehaved: the tour card
"blinked at the top-right then vanished, and the demo contents fully
loaded automatically." Two distinct causes:

1. **Boot remount race.** A freshly-loaded protocol hydrates its Yjs
   tree, which fires several *structural* `observeDeep` re-renders during
   boot. Each `render()` → `renderNodesView()` **remounts** the graph
   editor (new instance, old one destroyed → its tour torn down). The
   V3.389 auto-start consumed `state._pendingTour` on the *first* mount,
   so the tour attached to an editor that was immediately destroyed by
   the next boot render and never restarted → the card flashed and
   disappeared. (Normal editing does NOT remount — `observeDeep`
   re-renders only on Y.Array deltas, and a design block's node/edge
   writes are `attrs` map changes — so this was strictly a boot-time
   race.)
2. **Reuse opened a pre-V3.389 copy.** The reuse-first loader opens an
   existing demo copy; copies created before V3.389 hold the old
   *pre-populated* graph, so "the contents fully loaded" and the build
   tour had nothing to walk.

## Fix

### 1. Debounce the auto-start past the boot remount storm (`protocol-editor.js`)
`renderNodesView` no longer fires the tour inline. It (re)schedules a
250 ms timer that starts the tour on the **surviving** mount: each
remount `clearTimeout`s the prior timer and reschedules with its own
live `handle`, and `_pendingTour` is consumed only when the timer
actually fires. A stale handle can't misfire — `startTourById` now bails
when the editor is `destroyed`.

### 2. Already-built graphs get a choice, not a silent skip (`protocol-graph-tours.js`)
Build tours are flagged `build: true`. `start()` checks whether **every
do-step condition is already satisfied** (a pre-populated / already-built
copy); if so it shows a **"This copy is already built"** card offering
**↺ Rebuild from scratch** or **Just explore**, instead of auto-skipping
to the end. The done card of a build tour also carries **↺ Rebuild from
scratch**. Rebuild calls a new `attach({resetGraph})` hook — wired in the
graph editor to `graph.nodes=[]; graph.edges=[]; persist(); render()`
(an `attrs` change, so no protocol-editor remount; the tour handle
survives) — then restarts the tour on the now-empty canvas. This gives
anyone with a legacy populated copy a one-click path to the real
walkthrough, non-destructive until they ask for it.

## Verification
- `scratchpad/test-tours.js` (130 asserts): the 4 build tours (and only
  those) are `build:true`; a fully-built lesson-1 graph satisfies **all**
  do-steps (→ prebuilt card path) while an empty graph does not (→
  walkthrough path).
- Full regression suite + `node --check` on the three touched JS files.
- Pending (browser): load a FRESH demo → empty canvas, ring appears
  after ~¼s and STAYS, steps advance as you build; load a lesson you
  already built (or a legacy copy) → "already built → ↺ Rebuild from
  scratch / Just explore"; Rebuild clears the canvas and walks it.

## Note for users with old demo copies
Copies created before V3.389 are pre-populated. Either use **🎓 Demos →
🗑 Remove my demo copies** then re-open a lesson (fresh empty copy), or
open the copy and click **↺ Rebuild from scratch** on the tour card.
