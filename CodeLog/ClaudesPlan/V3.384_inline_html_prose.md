# V3.384 — Inline HTML formatting in protocol prose

## Context

Protocol block bodies (steps, callouts, table cells, captions, …) render
through `ProtocolFormulas.renderProse`, which HTML-escapes everything and
supports only a small inline grammar (`` `code` ``, `~sub~`, `^sup^`, and
`[!var:]`/`[!inv:]`/`[!pill:]` tokens). But the GELS **gold-standard**
protocol and the V3.382 node-lesson demos were authored with inline HTML
(`<b>`, `<code>`, `<br>`) expecting it to render — so in the document view
and the section-complete preview those tags showed as **literal text**
("all the words still have their syntax modifiers there").

## Fix

Make `renderProse` pass through a fixed allowlist of **attribute-less
inline formatting tags**, while still escaping everything else and
applying the existing token/pill/code grammar.

- New `_allowInlineHtml(escaped)` runs inside `_renderInlineMarkup` (so it
  applies only to the plain segments between tokens, after escaping). It
  restores exactly `<b> <strong> <i> <em> <u> <s> <code> <sub> <sup>
  <mark> <small>` (open + close) and `<br>`/`<br/>`.
- **Safe by construction:** only the exact escaped forms `&lt;tag&gt;` /
  `&lt;/tag&gt;` are un-escaped. Any attribute puts text between the tag
  name and `&gt;` (e.g. `&lt;b onclick=…&gt;`), so it never matches and
  stays escaped — no `href`/`src`/`style`/event-handler/`<script>`/`<img>`
  can survive. Bare `<`/`>` (e.g. `a < b`) stay escaped.
- `textHasProse` now also returns true when a body contains an allowlisted
  tag, so the block editor renders it on blur / read-only surfaces use the
  HTML path (not `textContent`).

This fixes the demos, the GELS gold standard, and any future
HTML-authored protocol in one place — the doc view, the editor's
section-complete preview, and the editable blocks' rendered mode all go
through `renderProse`.

## Verification
- `scratchpad/test-prose-html.js` (16 asserts): b/i/code/br render; `~sub~`
  `^sup^` `` `code` `` grammar intact; tokens substitute and coexist
  inside `<b>`; `<script>`, a tag WITH an attribute, `<a href>`, and
  `<img onerror>` all stay escaped; bare `<`/`>` stay escaped;
  `textHasProse` detects tags.
- Demo bodies use only `b`/`br`/`code` (all allowlisted), no bare
  brackets. Existing suites (units/graph/gels/runtime/router/code/
  recipes/demos) unchanged.
- Pending (browser): open a lesson (or GELS) in Document view and via a
  completed section → `<b>`/`<code>` render as bold/monospace, not
  literal tags.
