# V3.572 — Seamless app navigation + Ourlab branding + lab-group login

> Alex feedback (2026-07-26): "clicking on any page causes a brief loading
> screen — this should not happen since it is a native app. Make the UI as
> seamless as possible." + "we have a logo for the splash page" (icon-gen
> commands) + "each lab is a separate instance of the ourlab interface;
> McGheeLab is the first; a login should specify which lab-group name."

## Diagnosis (from a 6-audit workflow)

A background workflow ran 6 parallel read-only audits (loading-indicator
audit, Firebase/CDN cost, service-worker strategy, Capacitor/iOS flash,
persistent-shell feasibility, instant-signed-in signal). Consensus, by
visual impact:

1. **The auth "Loading…" splash flashes on every navigation** — the
   dominant artifact and a V3.571 regression. `ensureAuthGate()` calls
   `showAuthOverlay('loading')` unconditionally on every page; it's only
   removed when `firebridge.onAuth` fires, which is async and chained
   behind a live Firestore profile read. Because each tab is a separate
   HTML document (full reload), this repeats on every tap.
2. **White/black inter-page flash** — no `backgroundColor` set, so
   WKWebView paints `UIColor.systemBackground` during the document swap;
   Capacitor's `isOpaque=false` anti-flash only runs on first load.
3. **Firebase SDK loaded from gstatic on every page** — a network
   dependency that prolongs init (and can hang the splash forever offline);
   `_loadProfile()` also does a live Firestore GET before notifying auth.
4. **Inherent MPA re-parse** of ~1.5MB Firebase compat JS per navigation —
   only removable with a persistent shell (deferred endgame).

The service worker is **not active in-app** (registered only by the PWA
root; Capacitor serves `www/` locally) — so `sw.js` tuning is moot for the
app. The fixes live in the web tree (bundled by `sync-rm.mjs`) + native
config.

## Changes (what we did NOW — all low/no-risk)

### 1. Kill the splash on navigation for signed-in users
- `firebase-bridge.js` `onAuthStateChanged`: write `localStorage
  ['ourlab-authed']='1'` in the user branch (before the async profile
  read); `removeItem` in the else branch; also clear at the top of
  `signOut()` (covers all three sign-out call sites synchronously).
- `mobile-shell.js` `ensureAuthGate()`: read the hint synchronously. If
  `'1'`, show NO loading splash — the page paints immediately and
  `onAuth` reconfirms silently (if it resolves to null — expired session —
  the handler swaps in the sign-in screen). If not `'1'`, cover content
  with the loading splash right away (no chrome flash before sign-in).
- Safety: the hint is a PAINT decision only, never an auth/security
  boundary — `firestore.rules` is the gate and renderers still await
  firebridge before user-scoped reads. Optimistic no-splash render can at
  worst show an empty skeleton for the same async gap that exists today.

### 2. No white/black inter-page flash
- OurlabMobile `capacitor.config.json`: `backgroundColor` +
  `ios.backgroundColor` = `#f5f6fa` (RM `--bg`), so the inter-document gap
  paints the app color.
- `sync-rm.mjs`: inject `<meta name="theme-color" content="#f5f6fa">` +
  `<style id="ourlab-parsetime-bg">html,body{background:#f5f6fa}</style>`
  right after `<head>` on every page, so the first frame already matches.
- `ios/App/App/Info.plist`: `UIUserInterfaceStyle=Light` (RM ships no dark
  CSS) — prevents the dark-mode black flash.

### 3. Vendor Firebase locally (fast init + offline)
- Copied the 4 `firebase-*-compat.js@10.14.0` (app/auth/firestore/storage)
  into `rm/vendor/firebase/10.14.0/`.
- `sync-rm.mjs` rewrites `https://www.gstatic.com/firebasejs/<ver>/
  firebase-*.js` → `/rm/vendor/firebase/<ver>/…` at bundle time. The app
  loads Firebase from local disk (no per-nav network; offline-capable).
  Web source is untouched (PWA keeps gstatic + its SW caching).

### 4. Ourlab branding + splash + lab-group login
- App icon + native splash: `assets/icon-only.png` + `assets/logo.png`
  (from `brand/ourlab-icon-1024.png`) → `npx @capacitor/assets generate
  --iconBackgroundColor '#0A1730' --splashBackgroundColor '#0A1730'`.
- Sign-in overlay (`mobile-shell.js`): inlined `brand/ourlab-mark.svg`
  (the microwell mark) replaces the 🌞 emoji; background switched to the
  brand "Deep Well" navy `#123058 → #0A1730` (matches the native splash);
  title "Ourlab"; a **Lab group** field (default `McGheeLab`, persisted to
  `localStorage['ourlab-labgroup']`, captured on sign-in). Each lab is a
  separate Ourlab instance; the login specifies which one.

## Deferred (flagged, higher risk / bigger)
- **Persistent iframe shell** — host the four tabs in one long-lived shell
  (model on `rm/js/workflow-shell.js`) so Firebase + `/rm/js/*` parse ONCE
  and tab switches are a DOM/iframe swap. The only thing that removes the
  inherent MPA re-parse and makes nav truly instant. High risk/effort;
  push-tap routing + deep-links must move into the shell. Not needed for
  the visible-flash fix.
- **Firestore `enablePersistence`** — offline/cached reads (medium risk,
  app-wide semantics change).
- **PWA-only** `sw.js` gstatic → cache-first (helps the browser PWA only).

## Rollback
- Web changes app-gated / additive; the auth-hint is inert on desktop
  (nothing reads it there). Native config + Info.plist revert by removing
  the added keys; vendored SDK + sync-rm rewrite revert by dropping the
  rewrite (pages fall back to gstatic).
