# V3.101 — Citation hover: per-digit reverse hover + pixel-perfect rects

## Goal

Two related issues left over from V3.99 (cluster expand + narrowed
flash) and V3.100 (per-row token):

Reported:
> *"when we hover over a citation link on the page, the citations are
> not individually selectable with hover. however the highlighs are
> separated, if i go to the citations pannel and hover over them they
> are individually highlighted on the right index of a citation block.
> Also the highlights are not in the correct spot, they are slightly
> off but are better overlaid when the citation is closer to the left
> side of the page."*

1. **Reverse hover (PDF → panel) doesn't separate cluster digits.**
   `_wirePageTokenHover` bound listeners to each pdf.js text-layer
   *span* with a `__citeHoverBound` flag. When `[1,2,3]` lives in one
   span (the common case — pdf.js groups glyphs into runs), the
   first match wins the binding and refs 2 / 3 are skipped. Hovering
   any of the three digits in the PDF only highlighted row 1 in the
   sidebar.
2. **Flash rect drifts off the digit, more on the right side.** V3.99
   used a char-fraction approximation
   (`localStart / itemLen * item.width`) which assumes uniform glyph
   width across each text-item. Real PDFs use proportional fonts +
   kerning + sometimes justified text, so the approximation
   accumulates error with x-offset — exactly matching what the user
   observed (better near the start of a run, worse further right).

## Approach

Both bugs share a fix: use the DOM `Range` API on each text-item's
underlying text-layer span (`item.domSpan`, already exposed by
[rm/js/pdf-viewer.js](../../rm/js/pdf-viewer.js)'s `_collectTextItems`).
`Range.getClientRects()` returns the actual rendered glyph rects —
pixel-perfect, no approximation.

### `_rectForRange` rewritten

Two paths:

- **`_rectForRangeViaDom(ranges, rangeStart, rangeEnd, wrapRect)`** —
  primary. Finds the first/last overlapping item ranges, builds a
  DOM Range across their text nodes
  (`range.setStart(span1.firstChild, localStart)` / `.setEnd(...)`),
  reads `range.getClientRects()`, subtracts the page wrap's viewport
  rect to get wrap-local coords. Pixel-perfect for any text the
  text layer renders.
- **`_rectForRangeViaFraction(...)`** — fallback (V3.99 char-fraction
  math) for the rare case `domSpan` or its first-child text node is
  missing.

`_scanPage` captures `node.wrap.getBoundingClientRect()` once per
scan and threads it through.

### `_wirePageTokenHover` rewritten

Instead of binding hover listeners directly to text-layer spans
(per-span = 1 listener for the whole `[1,2,3]` cluster), render one
**transparent hit-rect div** per match into the page's existing
`pv-cite-overlay` layer. Each hit-rect is positioned at the match's
narrowed rect with `pointer-events: auto`, so its `mouseenter` /
`mouseleave` fire independently for ref 1, ref 2, ref 3.

Existing flash-rect logic is unchanged — `_flashRect` still appends a
`.pv-cite-flash` div to the same overlay. `_wirePageTokenHover` only
clears its own `.pv-cite-hit` children on re-bind, so flashes are not
disturbed.

### Side effects

- **Native text selection over a citation marker is now blocked.**
  `pointer-events: auto` on the hit-rect means clicks/drags on the
  digit `[1,2,3]` itself don't reach the text-layer span. Selection
  on the surrounding sentence is unaffected (hit-rects are tight to
  the match). Acceptable trade — selecting `[1,2,3]` glyphs is rare,
  and the hover affordance for finding/jumping to references is the
  primary value.
- **Cursor cue moves from "whole sentence" to "just the digit"** — the
  old code set `cursor: help` on the entire pdf.js text-run, which
  was overly aggressive. New cue is on the actual hit-rect only.

## Files changed

- **`rm/js/paper-citations.js`** —
  - `_rectForRange` split into `_rectForRangeViaDom` (DOM Range,
    pixel-perfect) + `_rectForRangeViaFraction` (V3.99 fallback);
    primary entry point falls through if DOM path returns null.
  - `_scanPage` captures `node.wrap.getBoundingClientRect()` once and
    passes it to `_rectForRange` for every match.
  - `_wirePageTokenHover` no longer binds to text-layer spans; renders
    transparent `.pv-cite-hit` divs per match into
    `pv-cite-overlay` with `pointer-events: auto`. Clears prior
    `.pv-cite-hit` divs on re-bind so re-renders / page nav don't
    leak listeners.
- **`sw.js`** — `CACHE_VERSION` 75 → 76.

## Verification

1. Hard reload (evict SW cache `mcgheelab-shell-v75`).
2. Open a paper with cluster citations like `[1, 5, 9]` near both
   the left and right edges of a page.
3. **Reverse hover (PDF → panel):** hover over the digit `5` in the
   PDF — only the sidebar row for ref 5 should highlight (and
   scroll into view), not refs 1 or 9.
4. **Position accuracy:** the highlight should land precisely on
   the digit, both for citations near the left edge and citations
   near the right edge of the page.
5. **Forward hover (panel → PDF):** hovering each sidebar row still
   flashes its specific digit (V3.99 + V3.100 behaviour preserved).
6. **Other things still work:** native text selection on the
   surrounding sentence, the `+ Add to library` button in expanded
   rows, the `[n]` per-row token from V3.100.
