# V3.621 — Annotation lifecycle hardening + delete cascade + dead-code purge

**Release 3 of 4** in the paper-reader highlight→comment overhaul (after
V3.619 data loop, V3.620 create popover). Invisible-but-load-bearing: the
tab-switch races, wrong-paper writes, silent failures, and zombie code the
2026-08-12 investigation surfaced.

## Changes

### Tab-switch generation guard (rm/js/library-paper.js)
- `_attachGen` counter; `_detachActive()` bumps it; `_attachActive`
  captures it and re-checks after every await (PAPER_OVERLAYS.init, the
  drafts load inside `_mountAnnotations`, the mount itself).
  `_mountAnnotations(item, gen)` takes the item as a PARAMETER — it used
  to read module-global `_item` after its awaits, which a fast A→B tab
  switch had already reassigned, so A's continuation overwrote B's
  `_unsubscribeSync` (leaked Firestore listeners, duplicated onChange
  renders, cross-paper mounts).

### Capture modules can't write into the wrong paper
- figure-capture.js + equation-capture.js: `destroy()` (null module state,
  close an open dialog, remove `.fc-hotspot-layer` nodes) — called from
  `_detachActive`; the save handlers bind `paperId` at dialog-OPEN time
  instead of dereferencing module state at click time.
- Hotspot click guard: the per-hotspot `down` origin is consumed per click
  (it used to persist forever, so a text drag ENDING over a figure could
  open the capture dialog on top of the create popover) and a click with
  no pointerdown on the hotspot is ignored.

### Overlay singleton safety
- `ANNOTATION_OVERLAY.destroy()` now nulls `_viewer`/`_container`/
  callbacks and resets `_filterFn`/`_focusedId` — redraws landing between
  detach and the next init become no-ops instead of painting into the old
  tab's page nodes.
- The per-viewer setZoom wrapper only calls `ANNOTATION_OVERLAY.redraw()`
  when its viewer is still the ACTIVE one (the singleton points at the
  active tab; background panes' zoom paths must not repaint it).

### Zoom-race fix (rm/js/geom-selection.js)
- `saved_scale` is stamped from `node.itemsZoom` (the zoom the rects were
  MEASURED at) instead of `viewer.zoom` — pdf-viewer.setZoom flips
  `state.zoom` before its sequential page re-renders, and a drag in that
  window permanently mis-scaled the highlight. Applies to both text and
  marquee anchors (`_scaleForPage`).

### Sync error handling
- annotation-sync.js: `onError(err, which)` — 'lab' | 'private'; the
  write-only `state.ready` flags are gone.
- library-paper onError: **non-destructive banner** prepended inside
  `#lp-annotations` (cleared on detach). The old handler set innerHTML on
  the parent of the live panel root, permanently detaching the panel and
  toolbar for the session. A failed private listener now says "your
  private highlights aren't syncing" instead of being indistinguishable
  from nothing.
- Popover save offline guard (annotation-overlay.js): the create promise
  races a 4s timer — if unsettled, treat as queued (persistence has
  already painted the highlight), close up, and surface any LATE
  rejection via alert. Previously an offline create left the popover
  stuck busy forever.

### Delete cascade
- `CLAIMS.removeEvidenceForAnnotation(ann)` (rm/js/claims.js) — queries
  each draft in the annotation's `cite_in_drafts` for evidence entries
  (`array-contains {paperId, annId}`, both stance fields; the V3.619
  fieldOverride indexes cover it) and calls `removeEvidence` per hit.
  Wired into BOTH readers' onDelete (best-effort before the delete) —
  `removeEvidence` finally gains a caller; dangling claim links stop
  accumulating.
- functions/library.js `deletePaper`: also deletes the
  `paper-figures/{itemId}/` Storage prefix (reader figure captures were
  orphaned; only builder papers cleaned that prefix).
  **Deploy: `firebase deploy --only functions:deletePaper`** (or all).

### Small fixes
- library-comments.js: `#ann=` → `#ann-` (feed links now actually focus
  the highlight in the reader); async listener failures update the
  visible status line (the failures array was write-only — a rules
  rejection landed after the synchronous check and vanished).
- claims-panel.js: reader URL was missing the `/rm` prefix → 404 in prod.
- paper-evidence-inbox.js: failed per-paper queries are counted and
  surfaced ("N paper(s) could not be queried") instead of silently
  rendering an empty inbox.
- firebase-bridge.js `loadAccessGrant`: non-permission-denied failures no
  longer memoize the null grant for the whole session (a transient read
  error silently downgraded capped guests to read-only until reload).

### DELETE list (verified zero callers)
- rm/js/evidence-tag-dialog.js (264 lines, EVIDENCE_TAG_DIALOG never
  invoked; script tag already dropped in V3.620).
- rm/js/annotation-groups.js (no loaders left after V3.620; the
  labConfig/annotation_groups DATA stays).
- PAPER_OVERLAYS bucket-named aliases (`getActiveBucketIds`,
  `getLinkedBuckets`, `getColorForBucket`) + their last two call-site
  fallbacks (annotation-overlay stripes, paper-overlay-import).
- annotation-panel's `!parent_id` render filter (threading never shipped;
  a non-null parent_id rendered on the page while being invisible and
  uneditable in the panel).
- Dead `onSelect` overlay option (both readers).

### Deliberately kept
- annotation-overlay's DATA-level `ann.bucket_ids` stripe fallback stays
  until the V3.619 admin sweep has been run against prod (it renders
  legacy docs correctly in the meantime). Remove it in the release after
  the sweep is confirmed.

## Verify
- Rapid A↔B tab switching: no duplicated cards, listener count stable.
- Open figure dialog on A, switch to B, click Capture → lands on A.
- Zoom while pages re-render, drag-select mid-transition → highlight
  correct after reload.
- Kill network → create → popover closes ~4s (highlight painted);
  reconnect with a rules-rejecting doc → loud alert, rect vanishes.
- Delete an evidence-tagged highlight → the claim's evidence arrays lose
  the entry (builder claims panel).
- Comments-feed row click → reader opens focused on that highlight.
