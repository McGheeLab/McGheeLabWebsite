# V3.322 — PMR guided periods (FuturePlan 04, Release C1)

## Goal

Creating a PMR period stops being a raw `window.prompt` that demands
the user know the id format. A guided dialog offers suggestion chips
(the existing-but-unused `suggestedPeriods()` finally gets a caller), a
custom-slug field, and **copy-forward checkboxes** (goals, project
overview, reference links carry over from the latest period). The
"Add a weekly entry first" dead-end dies: the current week is
auto-created on period open and on task pull.

## Changes ([rm/js/pmr.js](../../rm/js/pmr.js) + [rm/pages/pmr.html](../../rm/pages/pmr.html))

- `wireNewPeriodButton` → `openNewPeriodDialog()`: overlay modal with
  - **chips** for the current + previous 4 semesters (already-created
    ones render disabled with "exists"),
  - a **custom slug** input (→ `custom-<slug>`),
  - **copy-forward checkboxes** (goals / project overview / reference
    links, all pre-checked) shown when the user has at least one
    existing period. Source = most-recently-updated index row.
- `createPeriodGuided(id, period, copyOpts)`: index row + `switchToPeriod`
  (unchanged creation path), then deep-copies the selected sections
  from the source doc into the fresh doc — `discussed_at` is reset to
  null on copied items so they land in the active lists — and saves.
- **Auto-week**: `switchToPeriod` appends the current week (existing
  `addWeek()`) when the doc is editable, has zero weekly entries, and
  the period hasn't ended (guards against polluting old archives).
  `openPullIntoWeek` auto-creates instead of alerting (anchor rect
  captured before the re-render).
