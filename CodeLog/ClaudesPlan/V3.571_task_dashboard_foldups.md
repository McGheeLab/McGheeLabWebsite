# V3.571 — Task dashboard + market fold-ups, app no-zoom, header spacing

> Alex feedback (2026-07-26), continuing the Ourlab app UX pass.
> "Redo the task dashboard. The add task button should do the fold-up
> style input. Send to teammate should also have a fold-up surface. For
> the task market, make the fold-up style for new post, and I-need-work
> buttons. Also when I click on something on the task market something
> zooms in and I can't interact with the page." + a second note: "the top
> nav for each page has the McGhee Lab header with the stale indicator —
> this should be at the top of the page, currently there is a lot of white
> space. The My Day header gap between the header and the Day/Week/Month
> buttons is very large."

## Goal

In the phone app, the Task Dashboard's **+ Add Task** and **Send to
Teammate** and the Task Market's **＋ New post** / **🙋 I need work**
should all open the standard fold-up bottom sheet (`APP_SHEET`), not the
centered desktop modal. Tapping anything on the Task Market must not zoom
the viewport into an un-interactable state. And the top chrome should sit
flush at the top with tight, native-feeling spacing.

## Approach

### 1. All app forms → the standard fold-up (`APP_SHEET`)

`forms.js` `openForm()` is the shared modal builder behind **+ Add Task**
(and dozens of other callers). Rather than special-case one button, route
`openForm` itself through `APP_SHEET` whenever we're in the app — so every
form across the app becomes the same fold-up, matching the earlier
directive that the fold-up be *standard for the entire app*.

- Factored field-building into `_buildFormField(f, values)` and
  value-collection/validation into `_collectFormData(fields, inputs)` so
  the desktop modal and the app sheet share identical logic.
- `_openFormSheet(...)` renders the fields into an `APP_SHEET` body with
  Cancel / Save buttons; `openForm` branches to it when `_ourlabAppForm()`.

### 2. Send to Teammate → fold-up (`task-assign.js`)

`open()` builds a `formHTML` string once; a shared `wire(scope, dismiss)`
attaches submit / cancel / focus. In-app it renders that HTML into an
`APP_SHEET` body; on desktop it keeps the centered overlay. Input
font-sizes bumped 14px → 16px.

### 3. Task Market composer → fold-up (`task-market.js`)

`openComposer()` similarly builds a `formHTML` string + a shared
`wireComposer(scope, dismiss, prefill)` (kind-toggle, prefill, submit).
In-app → `APP_SHEET`; desktop → the `.tm-overlay` modal. `injectStyles()`
now runs before building the form (the sheet reuses `.tm-form`/`.tmf-*`
layout). `.tm-form` input font-size 14px → 16px.

### 4. Kill the iOS zoom app-wide (OurlabMobile `sync-rm.mjs`)

The "tap zooms in and I can't interact" bug is iOS focus/double-tap zoom.
The robust fix is at the viewport layer: the bundler now injects
`maximum-scale=1, user-scalable=no` alongside `viewport-fit=cover` at
parse time. WKWebView honors this and a native app shouldn't pinch-zoom
its own chrome anyway. The 16px input bumps are a belt-and-suspenders
that also keep browser-preview (`?mobileShell=1`) zoom-free.

### 5. Top nav fixed at the top + My Day header gap (`mobile-shell.js`)

Follow-up feedback: "the McGhee Lab / stale / AM bar should always be
fixed in place at the top of the screen on all pages," and "there's a lot
of white space above it."

- The RM top nav on app pages is actually `.top-nav` (not the blue
  `.workflow-strip`, which only renders in shell mode). It's now
  `position:fixed; top:0` with its background filling the status-bar inset;
  the body reserves space via `ourlab-has-nav`
  (`padding-top: calc(56px + env(safe-area-inset-top))`).
- The blank band was a **timing race**: nav.js prepends `.top-nav` only
  after firebridge auth resolves, later than mobile-shell's single 400ms
  snapshot, so `ourlab-no-nav` (body top-padding) was added AND the sticky
  nav also padded → double offset. Replaced the snapshot with a poll that
  detects a *visible* nav (`getClientRects().length > 0`, so a chat-style
  page that hides its `.top-nav` is skipped) and adds `ourlab-has-nav`;
  falls back to `ourlab-no-nav` only if no nav appears after ~3s.
- `.page-title` and `.page-header` each carry `margin-bottom:20px`, which
  doubled into a ~40px gap before My Day's Day/Week/Month tabs. App-gated
  to `.page-header{margin-bottom:8px}` + `.page-title{margin-bottom:0}`.

### 6. Full-screen auth gate (`mobile-shell.js`)

Follow-up feedback: "if the user is not logged in, do not show any pages,
it should just be an overlay surface that has the sign in screen."

- `ensureAuthGate()` shows a loading splash on boot, subscribes to
  `firebridge.onAuth`, and — when auth resolves to signed-out — renders a
  full-screen overlay (🌞 · "McGhee Lab" · "Sign in with Google", native
  `firebridge.signInWithGoogle()`), removed the moment a user is present.
  Covers the tab bar + any page's own sign-in card (z-index 99998). Guests
  still fall through to firebridge's pending-access overlay (99999).
- **Trap hit + fixed:** the first cut used `window.firebridge`, which is
  ALWAYS undefined (firebridge is a lexical const — see the
  `window.firebridge dead-checks` memory), so the gate never fired.
  Switched to the bare `firebridge` global with `typeof` guards; also
  fixed the same latent bug in `openMoreSheet` (name/email/sign-out).

## Data model changes

None. No Firestore/rules/indexes/functions/storage change.

## Out of scope

- Redesigning the Task Dashboard's card layout itself (only the two header
  buttons were called out; the dashboard body is unchanged).
- The Task Market board cards' own tap behavior (claim/detail) — the zoom
  fix is viewport-level and covers them regardless.

## Release ritual

- sw.js CACHE_VERSION 545. Web changes are FTP-only and app-gated
  (`body.ourlab-app` / `?mobileShell=1`) — desktop RM untouched.
- OurlabMobile: commit + push `sync-rm.mjs`, then `npm run sync` +
  rebuild so the new viewport takes effect on device.

## Rollback

All web changes are app-gated and revert cleanly (desktop paths are the
original code). The viewport `user-scalable=no` is additive in the
bundler and reverts by removing the injected tokens.
