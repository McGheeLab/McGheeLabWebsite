# V3.295 — paper reader: robust two-column gutter detection

## Goal

Fix the reported bug: in the RM library paper reader
([rm/pages/library-paper.html](../../rm/pages/library-paper.html)), **some
papers still don't recognize two-column pages with a gap in the middle**, so a
highlight drawn inside one column spans across the gutter into the other
column.

## Root cause

Reading order for drag-selection is computed in
[rm/js/pdf-viewer.js](../../rm/js/pdf-viewer.js)'s `_clusterAndSort`. It used a
single DBSCAN flood-fill: two text items are linked when their bounding-rect
x-gap ≤ 1.5×lineH. Flood-fill is **fragile to bridges** — any one element that
touches both columns collapses the two columns into a single cluster:

- a gutter narrower than 1.5×lineH (adjacent words across it become neighbors);
- a full-width element flush against the body (title, spanning section heading,
  wide figure/table/equation, running header/footer) — its own internal links
  bridge left↔right even when the gutter itself is wide.

Once merged, items sort line-by-line (`y` then `x`), so each visual row
interleaves column-1 then column-2 items. `geom-selection`'s
`items.slice(lo, hi+1)` (which selects the contiguous reading-order range
between two items) then pulls in the opposite column → the highlight spans both
columns. The same defect widened search-result flash rects in
`paper-search.js`.

## Approach

Make reading order **column-major within horizontal bands**, derived from page
geometry rather than from flood-fill connectivity (which a single full-width
element can collapse). All logic stays pure (operates on `{x,y,width,height}`
item objects) so it is unit-testable without a DOM.

1. **`_detectColumnGutters(items, lineH)`** — find the vertical whitespace
   channels:
   - x-occupancy projection: `coverage[bin]` = how many rows have text over
     that x. A gutter is a deep valley flanked by the two columns. The valley
     ceiling is anchored to the valley **floor**, not zero — full-width content
     crossing the gutter raises the floor uniformly but the valley stays deep
     (this is the fix for heading/abstract-heavy papers that previously read as
     one column). Very fine bins + a boundary-erosion term so a narrow gutter
     isn't lost to column word-edges rounding into its boundary bins. The band
     is centred on the valley's emptiest plateau so a ragged column edge
     doesn't drag it sideways.
   - per-row clean test: a row is *full-width* (not clean) only when text fills
     ≥ 70% of the band; otherwise it's a clean inter-column row. Two
     median-smoothing passes drop isolated misclassifications (a stray page
     number, a lone long ragged line, a lone abstract line whose word-gap
     aligned with the band).
   - consistency guard: keep a gutter only if it is clean across a long
     contiguous run (≥ 8 rows) AND a large fraction of rows (≥ 55%) AND splits
     content into two substantial slabs (each ≥ 20% of width) — so a
     typographic "river" inside a single column is not mistaken for a gutter.

2. **`_orderByColumns(items, gutters)`** — split the page into horizontal bands
   of consecutive same-kind rows (full-width vs. multi-column). Full-width bands
   read line-by-line; multi-column bands read one column slot fully before the
   next. Concatenating top-to-bottom yields natural reading order AND guarantees
   columns never interleave in index space.

3. **`_orderByFloodFill(items, lineH)`** — the original DBSCAN, kept verbatim
   for pages with **no** detected gutter (single-column, figure-dominated), so
   that behavior is byte-identical to before.

`_clusterAndSort` now just detects gutters and dispatches to one of the two.

4. **Pixel-projection pass (`_makePixelProbe`)** — the text layer is blind to
   figures/equations/images. `_collectTextItems` downsamples the rendered page
   canvas once into an ink grid and passes a `pxInk(x1,y1,x2,y2)` probe into
   detection. The per-row clean test treats a row as full-width when non-text
   ink spans the gutter band there (ink at **both** band edges, so a thin
   vertical column rule — inked only at the centre — is ignored). This is the
   projection-profile idea applied to actual pixels, used as a refinement on
   top of the text-coverage projection; it falls back to text-only if the
   canvas is unavailable or `getImageData` throws. NOTE: for born-digital
   papers the text-coverage projection already handles the leak on its own
   (including pure-image figures, which leave the body columns correctly
   ordered around them); the pixel probe adds the canvas-ink signal for rows
   that carry text AND have a figure crossing the gutter, and hardens detection
   against text-layer quirks.

## Files

### Edited
- `rm/js/pdf-viewer.js` — `_clusterAndSort` rewritten as a dispatcher; new
  module-level `_lineSort`, `_orderByColumns`, `_orderByFloodFill`,
  `_detectColumnGutters`. The pure geometry helpers were lifted to module scope
  (out of the `create()` closure) so they are unit-testable.
- `sw.js` — `CACHE_VERSION` 266 → 267.

No consumer changes: the `{index, cluster}` contract on text items and the
`getTextItems()` API are unchanged, so `geom-selection.js`,
`paper-citations.js`, `paper-search.js`, and `paper-overlay-import.js` are
unaffected (and benefit from the corrected ordering).

## Key decisions

- **Geometry-derived banded order, not patched flood-fill.** An earlier attempt
  only suppressed cross-gutter DBSCAN links; it still leaked when a full-width
  element bridged the columns through its own internal links. Banded
  column-major order is robust to every bridge type.
- **Floor-anchored valley ceiling.** Anchoring the gutter ceiling to the valley
  floor (not an absolute near-zero) is what makes heading/abstract-heavy papers
  detect correctly — the most likely cause of "some papers still not
  recognized."
- **Single-column = original behavior.** No gutter detected → original DBSCAN,
  so single-column and figure pages are unchanged.
- **Ragged columns are best-effort.** Published papers are overwhelmingly
  *justified* two-column; the detector is tuned for that and degrades
  gracefully on the rare ragged-right two-column layout.

## Verification

Pure-geometry logic was exercised by a synthetic Node harness (not committed):
clean / narrow / title-bridged / heading-bridged / figure-bridged two-column,
single-column, ragged single-column, three-column, full-width abstract; plus
randomized fuzz with realistic typesetting metrics (font 7–16px, gutter
0.5–2.5em, justified & ragged, multi-section with title/abstract/headings).

Results on realistic geometry:
- Justified two-column: **0% undetected**, **~0.07%** residual in-column
  drag-leak (section-boundary edge cases only; was effectively 100% before).
- Single-column false-gutter rate: ~1.6% (recoverable, selection-order only).
- Three-column: ~96% detect both gutters.
- Performance: ~0.6 ms for a 1200-item page (runs once per page render).
