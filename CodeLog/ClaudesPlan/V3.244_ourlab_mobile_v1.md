# V3.244 — Ourlab mobile app v1 (Capacitor, TestFlight + Play internal)

> First version of the **Ourlab** mobile app — a Capacitor shell that wraps the existing `rm/` web codebase, adds three native screens (Today digest, Receipt capture, Voice notebook), exposes camera / barcode / voice / push to four enhanced-WebView surfaces, and ships to TestFlight + Play internal beta. McGheeLab is tenant #1; the app is branded **Ourlab** from day one. **Depends on V3.243 shipping first** (Ourlab rebrand + `rm/js/branding.js` seam in the web app).
>
> This is a strategy + scaffolding plan — it covers the decisions, the repo, the auth/push/data-layer plumbing, and the bottom-tab shell. Each of the six phone-wins features will get its own follow-up plan (V3.245 through V3.250) once the scaffold is in place.

## Goal

Lab members install **Ourlab** from a TestFlight invite (iOS) or Play internal-testing link (Android), sign in once with Google or Apple, and get a phone-native shell with a bottom tab bar `[Today] [Tasks] [Tracker] [Scan] [More]`. The "phone-wins" features — camera receipt capture, barcode-augmented inventory, push for tasks/PMR, voice-to-text lab notebook, in-the-moment activity tracking, chemical-safety lookups — work better on the phone than they do in the desktop web app. Everything else in `rm/` is reachable via the "More" tab as a phone-responsive WebView (V3.235–V3.241 already shipped the phone layouts).

- **V3.243 must ship first.** That plan introduces `rm/js/branding.js` (a one-file abstraction holding `platformName: 'Ourlab', tenantName: 'McGhee Lab', logoUrl, primaryColor, ...`) and reroutes every header/title/footer/manifest reference in `rm/` through it. ## The shell

**Bottom tab bar** — five tabs:

| Tab | Behavior |
|---|---|
| Today | Native screen — digest of "due today" tasks, recent PMR items, recent activity, queued offline writes. Push notification tap lands here. |
| Tasks | Enhanced WebView — `rm/pages/tasks-inbox.html` (phone layout from V3.238) inside a WebView fragment. |
| Tracker | Enhanced WebView — activity tracker page + native quick-log overlay accessible from the tab. |
| Scan | Native sheet — asks "Receipt or barcode?" and routes to receipt capture (native screen) or barcode scan (native scanner → returns to last-visible Chemicals/Equipment WebView). |
| More | WebView portal — links into Papers, Library, Protocols, CV editor, Calendar, Settings, etc. |

Above the tab bar: a small **sync indicator** dot, lit when any local write is queued (see Offline section). Top-right: avatar that opens Settings.

Deep-link routing: push notification payloads carry `{ kind: 'today-digest' | 'subtask' | 'chat-mention' | 'pmr', targetId, route }`. Tap always lands on Today; from Today, the relevant item is highlighted and tapping it routes into the appropriate WebView with the target scrolled into view (`#anchor-<targetId>`).

## Auth model

Native sign-in, WebView inherits via shared session storage.

- Shell uses `@capacitor-firebase/authentication` plugin → native Google SDK on iOS/Android, native Apple Sign-In on iOS (App Store requirement when any third-party social login is offered). On Android, Google sign-in only (no Apple SDK on Android).
- Two Firebase OAuth client IDs registered (iOS bundle ID + Android SHA-1). One reversed-client URL scheme registered in each platform's Info.plist / AndroidManifest.
- On successful native sign-in, Firebase Auth state persists to the WebView's IndexedDB via the shared WKWebView storage (iOS) / WebView storage (Android with `setDomStorageEnabled(true)`). Any `rm/` page loaded in the WebView calls `getAuth().currentUser` and sees the signed-in user immediately — no re-login.
- Existing web sign-in flow (Google popup at `https://ourlab.app/rm/`) is untouched. Apple Sign-In is **mobile-only**; the web app stays Google-only.
- Auth state for the native shell itself: kept in the Capacitor side via `@capacitor/preferences` (encrypted), refreshed on cold start.

## Push notification topology

**Device tokens.** Per-user, per-device.

```
users/{uid}/devices/{deviceId}
  ├── platform: 'ios' | 'android'
  ├── token: <FCM token>            # APNs token relayed through FCM on iOS
  ├── appVersion: '0.1.0'
  ├── lastSeen: <serverTimestamp>
  ├── enabledChannels:
  │     subtaskDueToday: true
  │     chatMention: true
  │     pmrMeetingTomorrow: true
  │     trackerEntryStale: true
  └── locale: 'en-US'
```

`deviceId` = Capacitor's stable per-install ID (`@capacitor/device`'s `Device.getId()`). Stale device docs (lastSeen > 90 days) get pruned by the daily scheduled function.

**Hybrid send architecture.**

- **Per-event sends** (time-of-event triggers, added to existing `functions/`):
  - `functions/chat.js` — when a message contains `@uid`, fan out a push to that user's active device tokens (subject to their `chatMention` pref).
  - `functions/tasks.js` — when a subtask's `dueAt` is set/changed and the new value is "today" in the user's timezone, push to assignee (subject to `subtaskDueToday`).
  - **New** `functions/pmr-trigger.js` — Firestore trigger on `pmrSessions/{sessionId}` writes; if `scheduledFor` falls in the next 24h and a notification hasn't been sent, push to all attendees (subject to `pmrMeetingTomorrow`).
- **Scheduled digest** — **new** `functions/push-digest.js`, runs once daily at 07:00 user-local (via per-user scheduled topic or one global function that fans out with per-user timezone math):
  - Today's tasks summary
  - Tracker entries stale > 24h (subject to `trackerEntryStale`)
  - Catches anything per-event sends missed (e.g. tasks edited overnight)

Both paths use the Firebase Admin SDK's `messaging().sendEachForMulticast({ tokens, notification, data })`. The `data` payload carries the deep-link route so the shell can land the user on Today with the right item highlighted.

**Settings UI** (per-channel prefs):

- New section in `rm/pages/settings.html` — "Push notifications" with four toggles per channel, plus a per-device list showing each registered phone (platform, last-seen, "remove this device" button).
- Mirror UI in the mobile shell's Settings (native screen reachable from the More tab or the avatar).

## Native screen #1 — Today digest

The "home" screen. Push-tap target. Read-only aggregation.

Sections, top to bottom:
- **Due today** — subtasks with `dueAt` today, ordered by assignee priority.
- **Recent PMR** — last 24h of PMR activity affecting the user.
- **Tracker pending** — entries > 24h old without a follow-up log.
- **Queued sync** — any local writes still pending upload (receipts, voice notes).
- **Quick actions** — buttons: "📸 Capture receipt", "🎙️ Record voice note", "✅ Log activity".

Data: reads from existing `tasks/`, `pmr/`, `activityTracker/` collections via `firebase-bridge.js`. No new collections.

## Native screen #2 — Receipt capture

Workflow: tap "📸 Capture receipt" (from Today, Scan tab, or "More → Procurement"); camera opens; user snaps photo; on-device OCR (`@capacitor-community/text-recognition` wrapping iOS Vision / Android ML Kit) runs immediately; extracted fields (vendor, total, date, line items) populate a form; if any field is missing or low-confidence, a "🤖 Use AI to parse" button calls a new Cloud Function (`functions/parse-receipt.js`) that invokes Claude's vision model with the image and returns structured JSON; user confirms/edits; tap "Save" writes to Firestore + Storage.

**Cloud Function** (`functions/parse-receipt.js`):

- Input: Storage path to the uploaded image.
- Calls Claude (`claude-opus-4-7` or `claude-sonnet-4-6` depending on cost/quality tradeoff — likely Sonnet for receipts) with a "extract receipt fields" prompt.
- Returns `{ vendor, total, currency, date, lineItems: [{ description, qty, unitPrice }], confidence }`.
- Cost: ~$0.005-0.01 per receipt. Cached by image hash so re-parsing the same image is free.
- Requires `ANTHROPIC_API_KEY` env var in Firebase Functions config (`firebase functions:config:set anthropic.key=...`).

**Data layer.**

```
users/{uid}/receipts/{receiptId}
  ├── createdAt
  ├── imagePath: 'receipts/{uid}/{receiptId}.jpg'   # Storage
  ├── vendor, total, currency, date, lineItems
  ├── parsedBy: 'on-device' | 'claude' | 'manual'
  ├── confidence: <0-1>
  ├── linkedOrderId: <procurement/{orderId}> | null  # set when user attaches to an order
  └── status: 'inbox' | 'linked' | 'archived'

procurement/{orderId}/receipts/{receiptId}
  └── reference to users/{uid}/receipts/{receiptId}   # written only when user links
```

**Storage rules** ([storage.rules](../../storage.rules)): new block `match /receipts/{uid}/{file}` — read+write only `request.auth.uid == uid`.

**Firestore rules** ([firestore.rules](../../firestore.rules)): new block `match /users/{uid}/receipts/{id}` — read+write only `request.auth.uid == uid`. Cross-write to `procurement/{orderId}/receipts/` gated by existing `isLabContributor()`.

## Native screen #3 — Voice notebook

Workflow: tap "🎙️ Record voice note" (from Today, Lab Notebook WebView, or a global shortcut); native screen with big mic button and live-caption text area; user holds-to-talk or taps-to-start; iOS `SFSpeechRecognizer` / Android `SpeechRecognizer` streams partial transcripts to the caption area (instant feedback even offline); on stop, audio file uploads to Storage; **new** `functions/transcribe-voicenote.js` runs Whisper Large-v3 for the authoritative transcript, then Claude for scientific-vocab cleanup; final transcript writes to `users/{uid}/notebook/{id}`; audio file deleted on success.

**Cloud Function** (`functions/transcribe-voicenote.js`):

- Input: Storage path to audio (.m4a, ~64kbps mono).
- Whisper pass (via OpenAI API or self-hosted): `whisper-1` model, $0.006/min.
- Claude cleanup pass: prompt = "this is a lab notebook entry; normalize chemical names, fix typos in reagent/protein names, preserve numbers/units exactly; output only the cleaned transcript, no preamble."
- Returns `{ transcript, language, durationSec }`.
- On success, deletes the audio file from Storage. On failure, keeps it for a retry job.
- Cost: ~$0.007 per minute of audio (Whisper $0.006 + Claude $0.001).
- Env vars: `OPENAI_API_KEY` for Whisper, reuses `ANTHROPIC_API_KEY` for cleanup.

**Data layer.**

```
users/{uid}/notebook/{entryId}
  ├── createdAt
  ├── source: 'voice' | 'text' | 'imported'
  ├── transcript: <cleaned>
  ├── liveTranscript: <native, pre-cleanup>      # kept for traceability
  ├── audioPath: 'voicenotes/{uid}/{entryId}.m4a' | null  # null after successful cleanup
  ├── durationSec
  └── status: 'recording' | 'transcribing' | 'final' | 'failed'
```

**Privacy.** Path is `users/{uid}/notebook/{id}` — read+write strictly `request.auth.uid == uid`. **No admin override.** Voice notes are personal to the recording user. If the user wants to publish a note to the shared lab notebook, that's an explicit copy action, not a default.

**Storage rules.** `match /voicenotes/{uid}/{file}` — read+write only `request.auth.uid == uid`. Audio files auto-delete on successful transcription (no retention).

## Enhanced WebView surfaces

Four features that work as the existing `rm/` page + a JS-to-native bridge call.

### `OurlabBridge`

A global JS object injected into every WebView, exposing the native capabilities:

```ts
window.OurlabBridge = {
  scanBarcode(): Promise<{ code: string, format: string }>,
  logActivity(payload): Promise<void>,            // mirrors existing activity-tracker write
  registerPushChannel(channelId, enabled): void,  // toggles prefs from settings page
  getDeviceId(): string,
  hapticFeedback(style): void,
  isCapacitor(): true,                            // gates "show native chrome" branches in rm/ JS
};
```

Implementation: a Capacitor plugin that runs on shell startup, injecting `OurlabBridge` into every WebView via `WKWebView.evaluateJavaScript` / Android's `WebView.addJavascriptInterface`. Web app `rm/` checks `if (window.OurlabBridge?.isCapacitor())` to enable native-only affordances (e.g., the scan button on the Chemicals page).

### Tasks / PMR push deep-link

No code change beyond push payload handling. Tap notification → shell routes to Tasks tab → WebView loads `tasks-inbox.html?focus=<subtaskId>` → existing inbox JS scrolls to the focused item and highlights it. The `?focus=` param needs to be added to `rm/js/tasks-inbox-buckets.js` if not already present.

### Activity tracker quick-log

Bottom of every native screen (when on the Tracker tab or contextually elsewhere): a "✅ Log now" floating button. Tap → opens a small native sheet with category + free-text → calls `OurlabBridge.logActivity({ category, note })` → bridge writes to `activityTracker/{uid}/entries/{id}` directly via `firebase-bridge.js` → Today digest's "Tracker pending" section refreshes.

### Barcode-augmented Chemicals / Equipment

`rm/pages/chemicals.html` and `rm/pages/equipment.html` gain a `📷 Scan barcode` button (visible only when `OurlabBridge.isCapacitor()`). Tap → calls `OurlabBridge.scanBarcode()` → returns `{ code, format }` → page fills the SKU field and auto-runs the lookup. Native plugin: `@capacitor-community/barcode-scanner` (wraps ML Kit on Android, AVFoundation on iOS).

### Chemical safety lookup at the bench

No new code beyond exposing `rm/pages/chemicals.html` via the More tab (or directly via a "🧪 Safety" shortcut from Today). The page already does what's needed; barcode scan augments lookup.

## Offline behavior

**Firebase IndexedDB persistence enabled globally** in `firebase-bridge.js` (likely already is — verify before this plan ships). Storage uploads use resumable mode (survives app restarts and network drops).

**Visible sync indicator.** Small dot above the More tab when any local write is queued. Tap → modal shows queued items per category (receipts, voice notes, activity logs) with "retry" / "discard" actions.

**Worst-case duration:** user-confirmed ~2 hours offline (basement BSL-2). Cache strategy stays moderate: no full collection prefetch on cold start. Only the most-recently-touched docs per collection are cached.

**Two write surfaces with explicit queue UI** (everything else uses silent Firebase queueing):

- **Receipts** — captured offline lands in `users/{uid}/receipts/{id}` with `status: 'queued'`. Storage upload happens whenever online. List view shows a "📤 queued" badge.
- **Voice notes** — captured offline lands in `users/{uid}/notebook/{id}` with `status: 'recording'` → `'transcribing'` once audio uploads → `'final'` after Cloud Function completes. List view shows progress per state.

## Release ritual

**No FTP, no `sw.js` bump (for the mobile app itself — the web changes in this plan still need a CACHE_VERSION bump).** App releases go through Apple + Google.

**Beta-only in v1.** No public store release. TestFlight invite link + Play internal testing link distributed to lab members. Apple TestFlight allows 10k external testers with a brief review (24-48h); Play internal testing has no review.

**Release cadence.**

- Patches via **Capacitor Live Updates** (`@capgo/capacitor-updater`). Any JS/CSS/HTML bug in the WebView or in the React shell ships as an OTA bundle — no store submission. Bundle hosted from a Cloud Function or static path.
- Native code changes (new plugins, Info.plist edits, native screens added) require a real build → TestFlight + Play internal upload. Cadence: ~once per major native milestone (estimate one upload per 2-4 follow-up plans).
- Build numbers: monotonic integer per platform. Marketing version (`0.1.0`, `0.1.1`, ...) bumps per shipped feature.

**Deploy order** when a plan touches both repos:
1. **First:** Firestore rules + Storage rules + indexes (`firebase deploy --only firestore:rules,firestore:indexes,storage`).
2. **Second:** Cloud Functions (`firebase deploy --only functions`).
3. **Third:** FTP the web app (`rm/` changes, sw.js bump).
4. **Fourth:** App build + TestFlight/Play upload.

Order matters: if (4) ships before (1), early testers get 403s on the new paths.

## Rollback

**Three layers, increasing pain.**

1. **Live Updates rollback (instant).** Capacitor Live Updates supports versioned bundles with rollback. If a JS/CSS/HTML bug ships in the WebView or shell, push a previous bundle as the active one — every install picks it up on next cold start.
2. **Remote Config feature flag (instant).** Every native feature (camera receipt, voice notebook, barcode scan) is gated by a Remote Config boolean (`enableReceiptCapture`, `enableVoiceNotebook`, `enableBarcodeScan`). Flip to `false` if a native bug emerges — feature disappears from the UI on next config fetch (~minutes).
3. **Apple expedited review (24-48h).** For a native bug that Remote Config can't contain. Submit a fixed build with "Request Expedited Review." Google has no equivalent — for Android, push the fixed build via Play internal testing immediately; the queue is fast (~hours).

**Web side rollback** is unchanged from the existing ritual: `git revert` + re-FTP + `firebase deploy --only firestore:rules` (if rules changed). Cloud Functions rollback: redeploy previous version with `firebase functions:deploy --force`.
