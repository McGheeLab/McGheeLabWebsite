# V3.232 — Mobile/tablet design tokens (Phase 1 of mobile compatibility)

> Phase 1 of the broader RM mobile/tablet compatibility plan (full plan: `~/.claude/plans/i-want-to-make-rosy-scott.md`). This version is the **foundation only** — adds CSS custom properties + global touch rules with zero behavior change. Phases 2–4 (shell adaptation, Tier A page rewrites, Tier C interstitial) follow in later versions.

## Goal

Establish a single source of truth for spacing, font scale, breakpoints, touch sizing, page padding, and iOS safe-area insets across the RM tree. Add the two iOS-Safari fixes (16px input font to prevent zoom, `touch-action: manipulation` to drop tap delay) and `@media (hover: none)` rules that suppress sticky `:hover` highlights on touch devices. Every RM page loads the tokens *before* `style.css` so downstream CSS in subsequent phases can reference them.

The audit found ~2,017 px declarations vs. only 5 rem / 10 vw/vh, and **6 scattered breakpoints** (640 / 700 / 720 / 800 / 860 / 880 / 900px) across 21 CSS files. Codifying tokens now means later phases standardize on **two** breakpoints (`640px` phone, `1024px` tablet) instead of inventing a seventh.

## Approach

**New file:** [rm/css/tokens.css](../../rm/css/tokens.css)

- `:root` block defines `--sp-1..10` (8-pt spacing grid), `--fs-xs..3xl` (font scale), `--bp-phone/tablet/desktop` (breakpoints for documentation + JS `matchMedia`), `--tap-min` (44px Apple HIG), `--tap-min-compact` (36px), `--page-pad-mobile/tablet/desktop`, `--page-max-w`, `--safe-top/bottom/left/right` (env(safe-area-inset-*)), and a `--z-nav..toast` z-index ladder.
- `input, select, textarea { font-size: max(16px, var(--fs-base)); }` — prevents iOS Safari auto-zoom on input focus.
- `button, .btn, .top-nav a, .dropdown-menu a { touch-action: manipulation; }` — eliminates the 300ms tap delay on touch devices.
- `@media (hover: none)` block suppresses the visible sticky-highlight states on `.card`, `.top-nav a`, `.dropdown-menu a`, `.yr-line`, `.ch-line`, `.lib-line` — paired with explicit `:active` states added in Phase 3.
- `@supports (padding: env(safe-area-inset-top))` pads `body` with `--safe-top` / `--safe-bottom` so the home indicator / notch don't clip content on iOS.

**Load order on every page:** `tokens.css` → `style.css` → page-specific CSS. The link tag is inserted *before* the existing `style.css` link.

**Files modified:** 66 HTML files — all `rm/pages/*.html` that load `style.css`, plus [rm/index.html](../../rm/index.html). Inserted:

```html
<link rel="stylesheet" href="/rm/css/tokens.css">
```

immediately before each existing `<link rel="stylesheet" href="/rm/css/style.css">` line, preserving indentation. **Skipped:** 14 redirect-stub pages that meta-refresh to a unified shell (activity-tracker, tasks-inbox, tasks-archive, tasks-add, year-review, paper-editor, library-comments, library-public, important-people, funding, email-review, cv-overview, activity-summary, purchase-requests) — these load no CSS at all.

## Why now

- **Zero behavior change.** Tokens are defined but no existing CSS references them yet. Layout is byte-for-byte identical to V3.231.
- **Unblocks Phase 2+.** Later phases reference `var(--page-pad-mobile)`, `var(--tap-min)`, `var(--safe-bottom)`, etc.; they can land surgically without re-introducing the scattered-breakpoint problem.
- **iOS-Safari fixes are independently valuable.** Even before Phases 2–4 ship, the 16px input rule and the `@media (hover: none)` hover-suppression eliminate the two most visible mobile bugs (input zoom on tap, stuck card highlight after tap).

## Verification

1. **No layout drift on desktop.** Load each of the four most-trafficked pages (`/rm/index.html`, `/rm/pages/tasks.html`, `/rm/pages/calendar.html`, `/rm/pages/paper-builder.html`) at 1440px and compare against V3.231 — should be pixel-identical.
2. **tokens.css loads first.** Open DevTools Network, filter to `*.css`, confirm `tokens.css` precedes `style.css` in the network waterfall on every page.
3. **CSS variables resolve.** In DevTools Console: `getComputedStyle(document.documentElement).getPropertyValue('--sp-4')` returns `"16px"`. `getPropertyValue('--tap-min')` returns `"44px"`.
4. **Input zoom fix.** On a real iPhone (or Chrome DevTools iPhone emulation with the "Touch" cursor), tap an input on `/rm/pages/profile.html` — viewport should NOT zoom in.
5. **Hover suppression.** In Chrome DevTools, toggle Rendering → "Emulate CSS media feature hover: none" then hover a card on `/rm/index.html` — no lift / shadow change. Untoggled: hover works as before on the same page.
6. **Service worker invalidation.** After deploying, a returning user reload picks up tokens.css fetched via the existing network-first RM path. No SHELL_URLS edit needed — `/rm/*` is network-first per [sw.js:109-112](../../sw.js#L109).

## Out of scope (Phase 2+)

- Migrating existing `px` values in `style.css` to tokens (deferred to a "touchpoint pass" in Phase 2 — only layout-critical px values get migrated; cosmetic px stays).
- Standardizing the 6 scattered breakpoints to 640/1024px (Phase 2).
- Top nav narrow-screen overflow `⋯` menu (Phase 2).
- `.page` padding migration to `--page-pad-*` tokens (Phase 2).
- Tier A page rewrites (tasks inbox, lab notebook, calendar, chat, huddle, training, people, paper-builder, library-paper) — Phase 3.
- Tier C desktop-only interstitial — Phase 4.

## Rollback

`git revert` of this commit restores V3.231 behavior. Tokens.css can be deleted; the 66 page edits unwind cleanly because each just adds one line. No data-model changes, no Firestore touches.
