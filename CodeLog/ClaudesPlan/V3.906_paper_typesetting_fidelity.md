# V3.906+ — Paper writer: journal-quality output, measured against real papers

Alex (2026-10-25): "the paper writer needs a lot of work, use a set of papers from pdfs of journal papers as a ground
truth … use a local copy of the paper writer … make it into a journal quality output in browser, then ensure the latex
compiler also works end to end and outputs a file that is very close to the original … come up with different
solutions for the input → paper quick view → latex workflow … ensure the preview file is accurate and does not have
weird text gaps … keep me in the loop with an output image."

## Goal

1. What a lab member writes in the paper builder comes out of **Export → Compile** looking like the journal's own
   published page, close enough to lay side by side with a real paper from that journal.
2. The **Document view** (the in-browser quick view) predicts that PDF: same page count, same column breaks, figures on
   the same pages, no blank holes in the text.
3. Both are **measured** against real published papers, not eyeballed.

## Ground truth: the Paper Lab (V3.906)

A local copy of the real paper writer that never touches Firebase:

**The corpus is copyrighted journal content, so it lives OUTSIDE every git repo**: `../PaperLab-corpus/` (bundles,
originals, `truth.json` layout facts, runs, the lab workspace). `serve.py` refuses a workspace inside the repo. Nothing
from it is committed, uploaded, or deployed.

Corpus (7 papers, 7 templates): PNAS 2013 (Legant, 2.5D TFM) · Nat Commun 2019 (microparticle TFM) · PLOS ONE 2015 ·
JACS 2026 · Elsevier *Mechanobiology in Medicine* 2024 · bioRxiv 2023 (pdfTeX, REVTeX-style) · PRX 2015 (REVTeX).
Each was rebuilt verbatim as a `.paperbundle.zip` (text, equations, figures, tables, references) by a helper agent.

## Baseline findings (first runs)

Export / compile (the PDF a student would submit):
1. **Prose was never escaped.** `%` commented out the rest of the paragraph (every paragraph is one source line),
   `& # _` broke the compile.
2. **Inline math was not protected** from the markdown passes: two `$…^…$` spans in one paragraph paired their carets
   into `\textsuperscript{…$…$…}` — compile error.
3. **7 of 14 templates drop the author list** (`{{LEAD_AUTHOR}}` only) — the PDF says "Lead Author" while the Document
   view shows every author.
4. **Fonts**: templates load pdfTeX's `[T1]{fontenc}`; Tectonic is XeTeX, so ’ – ć ń ğ μ and friends are silently
   dropped ("Missing character" only in the log).
5. Text after a display equation always restarts as an indented paragraph; the equation is preceded by a paragraph
   break (extra vertical space above it).
6. Narrow figures squeeze their caption to the image width (journals run captions across the column).
7. Most templates compile a single-column **submission manuscript** while the Document view draws the published
   two-column page — they cannot agree by construction.

Document view:
8. Big blank bands at page feet (paragraphs that should split jump whole to the next page), 20–35 % of a page.
9. Georgia at 1.32 leading for every journal — never the PDF's font, size or leading, so line and page breaks drift.

## Four ways to run input → quick view → LaTeX (the solutions compared)

| | how | fidelity | speed | cost / risk |
|---|---|---|---|---|
| **A. Twin renderer, one spec** | each journal gets a structured *look* (page, margins, columns, fonts, sizes, leading, heading/caption/abstract styles, float rules). The LaTeX preamble AND the Document-view CSS are generated from it; the preview uses the SAME font files and TeX's own line-breaking (Knuth–Plass + TeX hyphenation patterns) and LaTeX's float rules | high; same fonts + same breaks ⇒ same line counts | instant, interactive (drag/resize stay) | a typesetter in JS — biggest build |
| **B. Compile-calibrated preview** | every compile also returns where LaTeX put each paragraph/float (positions read back from the PDF/synctex); the Document view snaps its page/column breaks and float pages to that until the next edit | exact after a compile | needs a compile (≈3–8 s) | server change for production; free in the Lab |
| **C. TeX in the browser (WASM)** | compile the real .tex client-side (SwiftLaTeX/BusyTeX), show it with pdf.js | exact | 5–15 s per compile, tens of MB first load | hosting a TeX tree on the FTP site; mobile unrealistic |
| **D. Print the preview** | the Document view itself is the PDF (print CSS) | as good as A | instant | journals still want LaTeX; a second output to keep honest |

**Decision:** A is the core (it is the only one that keeps the interactive layout tools and works offline/on phones),
with the Paper Lab doing B continuously during development to *measure and calibrate* A against real Tectonic output.
B in production (the Cloud Run service returning positions) is a later, optional step; C is recorded as evaluated, not
built (the existing Cloud Run compile already gives the exact PDF); D falls out of A for free once the preview is
faithful.

## Phases

- **P1 (V3.906)** Paper Lab + corpus + exporter correctness: escaping + math protection (1, 2), author block on every
  template (3), equation continuation (5), caption width (6).
- **P2 (V3.907)** Journal looks: a `look` block per template; one emitter writes the layout preamble (fontspec fonts with
  a pdfLaTeX fallback, geometry, columns, sizes, titlesec/caption/abstract styles, float parameters, `\frenchspacing`)
  for spec-driven journals; class-driven journals (PNAS, IEEE, ACS, Elsevier, APS) describe their class's layout,
  measured by `scripts/paper-lab/calibrate.py`. Published two-column look by default; the submission manuscript is a
  toggle. Fonts vendored once in `rm/vendor/fonts/` (TeX Gyre, Latin Modern: GUST licence; STIX Two, Libertinus: OFL)
  and shared by both renderers. New template: APS / REVTeX.
- **P3 (V3.908)** Document-view typesetter: look-driven CSS; `paper-typeset.js` = Liang hyphenation (TeX's en-US
  patterns, vendored with their notice) + Knuth–Plass with TeX's demerits/tolerances, rendering each paragraph as exact
  lines; deterministic heights; column splits at line boundaries; LaTeX float placement (top/bottom/page, `figure*` to
  the next page, fractions); flush-bottom columns.
- **P4** Calibration loop on the corpus until preview ≈ compiled ≈ original (page count ±1, ≥90 % of paragraphs with
  identical line counts, no in-column gaps > 2.5 lines that LaTeX doesn't also have).
- **P5** Shaping tools: loose/tight line and widow/orphan finder with one-click fixes (paragraph `looseness`), figure
  fit (size a figure to close a gap or hit a page budget), page-budget meter, table cells with math/citations.

## Acceptance (per corpus paper)

- compiles with zero errors and zero "Missing character" warnings;
- compiled page count within ±1 of the original (same journal look), preview within ±1 of compiled;
- figures on the same page in preview and compiled for ≥ 80 % of figures;
- no preview gap > 2.5 lines inside a column that the compiled PDF does not have.

## What was built (V3.906–V3.909) and what it measures

**Two kinds of look.** A *spec* look (Nature, PLOS, ACS, Elsevier, preprints, APS) writes the whole layout preamble
from its numbers. A *class* look (PNAS, IEEE) leaves the journal's class alone and describes the page that class makes
(measured from a compile with `calibrate.py`), adding only TeX's line-breaking settings, so the Document view can
predict it. Sizes of a class look are the class's TeX points converted to bp.

**What the Document view had to learn from TeX to agree with it** (each one found by a corpus mismatch):

| TeX behaviour | where |
|---|---|
| Knuth–Plass with TeX's passes, demerits and en-US patterns; breakable inline math with TeX's math glue | `paper-typeset.js` |
| per-font inter-word glue from the TFM (Helvetica 0.6/0.24 of the space), IEEEtran's retuned spaces (0.35 em) | `look.glue` → `--pts-*` |
| `\sloppy` inside floats and parboxes (`\@parboxrestore`): captions, fact box, boxed abstracts | `_lineBreakParams` |
| the class's penalties (IEEEtran `\hyphenpenalty 750`, `
elpenalty 800`, `inoppenalty 1000`) | `look.linebreak` |
| Latin Modern optical sizes (9 pt text is LMRoman9) and fonts loaded scaled (helvet 0.95) | `lm9`/`lm8`/`lm7`, `font_scale` |
| baselines `skip + \baselineskip` apart; the first box line at its glyph height; `\topskip` in a column's capacity | `texGap`, `topGap`, `geometry` |
| float placement: `[t]` backwards to the column top, `figure*` from the next page, strict order, float pages first, **float columns** at every column start, `dbl` fractions | `_packPages` |
| natbib "(5, 6)", IEEEtran "[2], [3], [4]" | `_typesetParagraphs` |

**Where it stands (preview vs compiled, published look):** Nat Commun 14/14 pages, JACS 11/11, bioRxiv 13/13 (94 % of
body line ends shared), PNAS 7/7 with every figure on the same page and in the same position (float column, float page),
IEEE (the Nat Commun paper re-set) 18/18 at 75 %, PLOS 14 vs 13 and Elsevier 13 vs 14 (a few reference lines). The rest
of the line-end disagreement is TeX's whole-paragraph optimum flipping on sub-point width differences (TFM kerning vs
the OpenType face's), which no browser rendering removes; it does not move figures or page counts.

**Not done:** the journal labels (Alex labels the 33-paper set in the labeler; `journal_style.py` turns them into
profiles and look drafts), Science look (no ground truth), submission-mode preview look, IEEE/REVTeX table caption
styles.

**P5 (V3.910) — the layout check.** The Document view's **Check** panel reads the typesetter's per-paragraph result and the
mounted pages: loose lines (badness > 500, emergency pass, overfull), widows and orphans, floats ≥ 2 pages after their first
mention, how full the last page is, and which paragraphs `\looseness=-1` would shorten. Tighten / Loosen / Reset write
`attrs.looseness`; the exporter writes the same `\looseness`, so the PDF follows the preview. Still to come: figure-size
suggestions (shrink a figure to pull a float back to its citation page) and a page budget per journal.
