# V3.144 — Dashboard "+ Add Task" button creates a task instead of navigating

## Why

User report: "the add task button on the task page is misleading
currently this is just a link to the add task page. we should change
this. the intent of this button is to add a task to something."

The Dashboard tab's "+ Add Task" button at
[rm/pages/tasks.html:91](../../rm/pages/tasks.html#L91) is a plain `<a>`
link to `?tab=add` — it changes tabs, it doesn't add anything. The
intent is "add a task to a task builder right now," matching the
[task-quick-builder.js](../../rm/js/task-quick-builder.js) flow used
inside email + calendar items but reachable from the dashboard header.

## What it should do

Open a modal that asks:

- **Task builder** — dropdown of all task builders, with `+ New task builder…` at the bottom. Defaults to the currently-focused card if any (V3.130 `state.focusedTaskBuilderId`); otherwise the first non-inbox builder.
- **Title** — required, focused immediately.
- **Due date** — optional date picker.
- **Hours estimate** — optional number, step 0.25.
- **Priority** — select (low / normal / high / urgent), default normal.
- **Notes** — optional textarea.

On save:

1. Resolve the task builder (or create a new one if `__new__` was picked).
2. Ensure a default sub-bucket exists (`buk-{builderId}-default`,
   created if missing — same `ensureDefaultBucket` shape as
   `tasks-buckets.js` and `task-quick-builder.js`).
3. Push a fresh subtask into that bucket with the form values.
4. `scheduleSave()` (the existing dashboard's debounced save).
5. Re-render so the new subtask shows up in the card immediately.

User can re-pin into a more specific sub-bucket later via the V3.130 pin
menu — the goal here is fast capture, not full taxonomy.

## Implementation

### `rm/pages/tasks.html`

Replace the dashboard header's `<a>+ Add Task` with a `<button>` whose
click is wired by `tasks-dashboard-buckets.js`. Keep the "Send to
Teammate" peer button unchanged.

```diff
- '<a href="/rm/pages/tasks.html?tab=add" class="btn btn-primary" style="text-decoration:none">+ Add Task</a>'
+ '<button type="button" class="btn btn-primary" id="btn-add-task">+ Add Task</button>'
```

### `rm/js/tasks-dashboard-buckets.js`

- Expose `window.DASH_ADD_TASK = { open: openAddTaskModal }`.
- `openAddTaskModal()` reuses `openForm` from [forms.js](../../rm/js/forms.js)
  with the seven fields above.
- Save handler creates the subtask in-place against `state.doc`, calls
  `scheduleSave()`, and `render()`s.
- Bottom-of-file boot wires the existing click handler so the button
  doesn't depend on tasks.html knowing about the dashboard module.

### Wiring

`rm/pages/tasks.html` already has a `DOMContentLoaded` listener that
wires `btn-assign-task`. Extend that listener to also wire
`btn-add-task` to `DASH_ADD_TASK.open()`.

## Out of scope

- Sub-bucket picker inside the modal. Defaulting to `buk-{id}-default`
  is the V1; users can re-pin via the existing pin menu.
- Persisting the modal across reloads / draft preservation.
- Adding the same modal to the inbox/archive tab headers (those tabs
  don't have an "+ Add Task" button today; if the user wants one there
  it's a follow-up).
