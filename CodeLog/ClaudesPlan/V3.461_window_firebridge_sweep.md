# V3.461 — `window.firebridge` dead-check sweep (9 modules)

## Goal

Finish the systemic follow-up opened by V3.392 (citations) and V3.460
(Lab Themes): eliminate every remaining `window.firebridge` read-check in
`rm/js/`. `firebridge` is `const firebridge = (function(){…})()` in
`firebase-bridge.js:4` — a lexical global, reachable by bare name but
**never** assigned to `window` (repo-wide grep for `window.firebridge =`
is empty). So `window.firebridge` is permanently `undefined`, and every
`window.firebridge && …` branch is dead, every `!window.firebridge` guard
always fires.

Each site was verified individually (not blind search-replaced) — several
had redundant bare-`firebridge` paths nearby, and one was a
**privilege-escalation trap** that a naive swap would have activated.

## Per-file findings + fixes

All fixes use the safe pattern `typeof firebridge !== 'undefined' &&
firebridge.X` (matches V3.392 / V3.460; the `typeof` guard is strictly
safer than the old `window.firebridge` — identical behavior when
firebridge is absent, correct behavior when present).

### library.js — 3 sites, one a security trap

- **`_isAdminAny()` (was 1322/1324).** ⚠️ The dead block ended with
  `if (window.firebridge && firebridge.isReady && firebridge.isReady())
  return true;`. `isReady()` returns `_ready` — "**auth resolved**," NOT
  "is admin" (confirmed `firebase-bridge.js:236`). A mechanical
  `window.` → bare swap would have made `_isAdminAny()` return `true` for
  **every signed-in user**, exposing admin-only shelf controls to
  everyone. Fix: the isReady clause is **dropped**, replaced by a single
  correct `firebridge.isAdmin()` check (reads `_profile.role==='admin'`).
  The stale "or firebridge's _ready boolean" comment is corrected. Admin
  detection still also works via the pre-existing `_ownProfileCache` path
  (line 1321, untouched), which is what has been carrying it all along.
- **`_renderAccountDiagnostic()` (1395/1396).** The diagnostic trace line
  always printed `firebridge.isReady=false` / `firebridge.profile.role=
  (no profile)` regardless of real state — misleading exactly when you're
  debugging auth. Now reads the live firebridge state.
- **`init()` onAuth block (1727).** ⭐ Highest-impact. The whole
  `firebridge.onAuth(...)` registration was dead → only the `else`
  (`_runCaptureSync()`) ran. Consequences, all now restored:
  `firebridge.requireSignIn('Sign in to view the lab library.')` never
  fired; **`LIBRARY_PREFS.load()` never ran** (per-user view prefs never
  loaded — these are their *only* call sites, confirmed by grep);
  **`LIBRARY_GROUPS.loadShared()` never ran** (V3.363 shared-groups shelf
  never populated); and the post-auth `_render()` never fired. No
  double-execution risk: initial `_render()` at init:1648 stays, the
  post-auth `_render()` is idempotent, and `_runCaptureSync` has its own
  once-per-session gate.

### library-paper.js — 2 sites, both real bugs

- **`_renderAssignWidget` (613).** `isMember` was always falsy → the
  "Send to teammate / Assign reading" widget was always hidden. (Line 619
  right below already used bare `firebridge.isAdmin` — the redundant-path
  tell.) Now shows for lab members.
- **`_maybeAutoImport` (1681).** `!window.firebridge` guard always
  returned early → the one-shot `?import=<overlayId>&draft=<grantId>`
  overlay auto-import never ran. (Line 1683 already used bare
  `firebridge.db()`.) Now runs.

### profile.js — 3 sites, real bug: Google card stuck "Not signed in"

- **DOMContentLoaded onAuth (16), `googleCard()` (56, 58).** `getUser()`
  was always undefined → the Google sign-in card always rendered its
  "Not signed in" branch, and the onAuth re-render listener never
  registered, so it never corrected even after auth resolved. The
  profile page's own Google card now reflects real sign-in state and role.

### tasks-inbox.js — 2 sites, feature fully dead

- **`checkFirebridge` (209) + `openDailyTrackerDialog` guard (1174).**
  `INBOX.firebridgeReady` was always false → the "➕ Log to daily
  tracker" button (render:631) never appeared; and the dialog guard
  always alerted "Sign in as admin." Both dead. Now admins get the
  button and the dialog.

### citation-audit.js — 1 site, whole page dead

- **`_isAdmin()` (26).** Always returned false → `_boot()` (195) always
  rendered "Admin only — the audit downloads every PDF" and bailed, for
  **everyone including admins**. The citation-audit tool was completely
  inaccessible. Now admins reach it.

### claims.js (71), annotation-groups.js (99), annotation-sync.js (101) — display-name degradation

- Identical pattern: `const profile = (window.firebridge &&
  firebridge.getProfile()) || null;` was always null → the created
  claim/group/annotation stamped `creator.displayName` from the raw
  Google account name instead of the lab profile's preferred `name`.
  Not a functional break (nothing gates on it), but the intended value
  was lost. Now reads the firebridge profile name.

### external-links.js — 1 site, attribution lost

- **`getMyUid()` (37).** Always returned `''` → every external link was
  stamped `addedByUid: ''`. No gating depends on it (grep: only written
  + read-back), so data-quality only. Now stamps the real uid.
