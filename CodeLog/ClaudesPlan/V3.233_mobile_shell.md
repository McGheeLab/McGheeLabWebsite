# V3.233 — Mobile/tablet shell adaptation (Phase 2 of mobile compatibility)

> Phase 2 of the broader RM mobile-compatibility plan (full plan: `~/.claude/plans/i-want-to-make-rosy-scott.md`). Phase 1 (V3.232) shipped the design tokens; Phase 2 makes the **global shell** — `.page` wrapper, top nav, dropdown menus, and modals — actually use them. Standardizes the 6 scattered shell breakpoints to the two canonical values (640px phone, 1024px tablet). Phase 3 (Tier A page rewrites) follows in later versions.

## Goal

Wire the V3.232 tokens into the actual layout surfaces every RM page shares. Three concrete user-facing improvements on phone/tablet:

1. **Page padding adapts to device size** — 24px on desktop, 16px on tablet, 12px on phone (via the `--page-pad-*` tokens).
2. **Top nav collapses to icons on phone** — at ≤640px, the four link labels (`Workflows`, `All Pages`, `Split`, `My Workflows`) hide, leaving just the emoji icons (`🗂`, `⊞`, `⊟`, `⭐`). Saves ~260px of horizontal room; the brand + 4 icon-only links + dropdown caret fit comfortably on a 390px iPhone.
3. **Dropdown menus become bottom sheets on phone** — anchored to the viewport bottom, full-width, padded for the iOS home indicator. Less aim-required than the current absolutely-positioned top-aligned menu.

Plus: standardize the 6 scattered breakpoints (640px / 700px / 720px / 720px / 720px / 800px / 860px / 880px / 880px) across `style.css`, `workflow-shell.css`, `split-view.css` to the two canonical values (640px phone, 1024px tablet).

**Modal scroll caps** — three modal classes get `var(--safe-top) + var(--safe-bottom)` subtracted from their max-height so close buttons stay reachable above the iOS home indicator on notched phones:

- `.modal`: `max-height: 85vh` → `calc(85vh - var(--safe-top) - var(--safe-bottom))`
- `.pin-modal`: `max-height: 80vh` → `calc(80vh - var(--safe-top) - var(--safe-bottom))`
- `.ev-modal`: `max-height: 88vh` → `calc(88vh - var(--safe-top) - var(--safe-bottom))`

## Why this approach

- **Label-span wrap vs. CSS-only icon-extraction.** The CSS `font-size: 0` / `::before content: attr(data-icon)` trick was considered but breaks the dropdown caret pseudo-element rule and fragmentes browser support. Two tiny JS edits to wrap labels in spans is more robust and adds ~6 lines total.
- **Bottom-sheet dropdowns vs. full-screen sheet.** Bottom-anchor preserves visual continuity with the trigger button at the top and is the iOS-native pattern; a full-screen modal would feel disconnected for a 5-link menu.
- **Tablet padding at 1024px, not 768px.** iPad Pro 11" is 1194px wide — at a 768px breakpoint it would still get the desktop 24px padding even when the user reads in portrait. 1024px catches iPad-portrait while leaving 12.9" iPad Pro landscape (1366px) on the desktop padding.

## Verification

1. **Desktop unchanged at ≥1280px.** Load `/rm/index.html`, `/rm/pages/tasks.html`, `/rm/pages/library-paper.html?id=…` at 1440px — pixel-identical to V3.232.
2. **Tablet at 1024px.** Same pages: `.page` padding shrinks from 24px to 16px; `.buk-layout` collapses to single column; `.lp-split-3` library-paper stacks; workflow-shell popouts become 88vw overlays.
3. **Phone at 390px.** Open in Chrome DevTools iPhone emulation:
   - Top nav shows `[McGhee Lab] 🗂 ⊞ ⊟ ⭐▾` (labels hidden, all four links + brand fit comfortably).
   - Tap any nav dropdown — menu slides up from the bottom, full-width, padded above the home indicator.
   - `.page` padding shrinks to 12px.
   - Calendar `.yr-line` and tasks `.buk-layout` already stack (style.css existing rules, untouched in this phase).
4. **Modal close-button reachability.** On an iPhone 14 Pro (430×932 with notch), open a modal that fills the height (e.g. pin-picker on tasks page) — close button visible above the home indicator.
5. **`.nav-label` span exists.** In DevTools console after loading any page: `document.querySelectorAll('.top-nav .nav-label').length` ≥ 3 (Workflows + All Pages + Split, plus My Workflows if user has custom workflows).
6. **No `@media` queries between 641px and 1023px on shell files.** Grep for shell-scope breakpoints — should report only 640px and 1024px (page-specific files still carry their own; they'll standardize in Phase 3).

## Out of scope (Phase 3+)

- Per-page CSS file breakpoint standardization (21 files still have non-standard breakpoints — chat.css 600/700/400, equipment.css 768, etc.). Each gets standardized when its page is rewritten in Phase 3.
- Tier A page rewrites (tasks inbox sticky composer, calendar `.yr-line` 2-row card layout, library-paper 3-tab phone view, paper-builder drawer + bottom sheet).
- Tier C desktop-only interstitial.
- Existing scattered `:hover` rules getting `:active` companions (only the ones inside `@media (hover: none)` block of `tokens.css` are suppressed today).

## Rollback

`git revert` of this commit restores V3.232 behavior. The changes are layout-only — no Firestore touches, no data-model edits. The `.nav-label` spans added by `nav.js` are inert when the matching CSS rule isn't loaded (they just render as inline text, same as before).
