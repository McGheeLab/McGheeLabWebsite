# V3.371 — Shared page-layout engine + headless adoption (layout R2)

> Plan: robust page-layout segmentation, R2 of 5 (2026-07-14).

## Changes

- **NEW `rm/js/page-layout.js`** (`window.PAGE_LAYOUT`): the segmentation
  engine moved VERBATIM out of pdf-viewer.js — `_lineSort`,
  `_clusterAndSort`, `_orderByColumns`, `_orderByFloodFill`,
  `_detectColumnGutters` — plus a public `segmentPage(items,
  {pageWidth, pageHeight, inkProbe}) → {items, blocks}`. `segmentPage`
  stamps each item with `index`/`cluster`/**`column`** (0-based slot, −1 =
  full-width) and derives `blocks:[{id, bbox, itemIdxs, column, bandKind}]`
  from the cluster assignment. One engine now serves the viewer, the
  headless path, and the layout-audit harness.
- **`rm/js/pdf-viewer.js`** delegates: `_clusterAndSort` is now a thin
  wrapper over `PAGE_LAYOUT.segmentPage` (naive (y,x) fallback + warning if
  the engine script is missing); the 5 functions are deleted from here.
  `_makePixelProbe` stays (canvas/DOM-bound). **`extractTextItemsFromPdf`
  now segments each page** instead of sorting (y,x) — fixing the naive
  headless order that `paper-citations` ref parsing and `paper-search`
  snippets silently inherited (they bridged columns).
- **Hardening (this release):** flood-fill x-eps 1.5→1.2×lineH so a
  narrow-gutter page that falls through to flood-fill is less likely to
  merge columns.
- Script include `page-layout.js` **before** pdf-viewer.js on all five
  pages that load the viewer (library-paper, library, citation-audit,
  paper-export, layout-audit).

## Measured (node, truth-runs through PAGE_LAYOUT)

Bridge rate vs the V3.370 baseline (100% on all multi-col):
0% on 01-2col-tight, 03-fig-span, 06-3col, 07-sidenote, 08-1col, 09-refs,
10-equations, 12-multipage. Remaining: 02-frontmatter 30%, 04-fig-onecol
20%, 05-footnote 13% — gutter detection falls through to flood-fill when a
big full-width band (abstract) or a figure hole shrinks the clean-row
fraction below the 55% guard. **R4's selection clamp closes these
independent of segmentation accuracy** (a drag can't leave the anchor's
cluster); further gutter-threshold tuning is R5 backlog, best done against
the live browser harness (real pdf.js extraction differs from the
truth-run proxy).
