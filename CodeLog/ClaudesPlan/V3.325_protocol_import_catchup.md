# V3.325 — Protocol importer + skill catch-up for all new kinds (FuturePlan 03, Release 5)

## Goal

Final release of FuturePlan 03: teach the page-side importer
(`rm/js/protocol-import.js`) and the `/protocol-import` Claude skill
about every block kind added in Releases 1–4 (heading, callout, table,
kv, timeline, calculator, builder, layoutMap, docHeader) so Claude can
still generate fully-featured importable protocols.

## Importer changes (`rm/js/protocol-import.js`)

- **`validate`**: extend the per-block checks. Today it only special-
  cases `formula`. Add:
  - `callout` — `attrs.type` must be one of the four (warn + default
    note if missing/unknown).
  - `calculator` — warn if no inputs and no outputs; each output needs
    `name` + `expr` (error).
  - `builder` — warn if no dims; `dataset` should be non-empty (warn).
  - `layoutMap` — `dataset` should be non-empty (warn).
  - Kind must be in the known set — unknown kinds get a warning (they'd
    coerce to `step` on normalize, so it's non-fatal).
- **`summarize`**: count the new kinds so the pre-import preview shows
  them.
- No pipeline change: `createFromJson` already runs the tree through
  `normalizeTree`, which now defaults all the new kinds correctly, and
  through figure-image upload (unchanged).

## Skill changes (`.claude/skills/protocol-import/SKILL.md`)

- Update the closed kind list.
- Add a "Document-chrome & widget kinds (V3.315–V3.324)" section
  documenting each new kind's attrs with a compact JSON example, plus
  the inline vocabulary grammar (`[!pill:]`, `` `code` ``, `~sub~`,
  `^sup^`).
- Note the callout fold: emit `callout` (not `note`/`safety`) for new
  protocols; the legacy kinds still import but are deprecated.
- Extend the calculation-extraction guidance: a multi-input calculation
  panel is now a `calculator` block (inputs + outputs), and a
  parameter-sweep / condition-matrix is a `builder` + `layoutMap` pair.
- Update the validation checklist.
