# V3.509 — Huddle R3: rundown → plans data migration + join-request pushes

## Goal

Finish the Plans/Rundown merge started at the UI level in V3.508: move the
actual `huddleRundown` documents into `huddlePlans` (as untimed "anytime"
plans) and give the new plan join-request flow push notifications on par
with the legacy rundown flow.

## What shipped

1. **One-time admin migration** ([rm/js/huddle.js](../../rm/js/huddle.js)
   `migrateRundownToPlans`, button in Huddle Settings → "Legacy Rundown
   Migration (Admin)"):
   - Reads ALL `huddleRundown` docs (every week), skips docs already stamped
     `migratedTo` → **idempotent, safe to re-run**.
   - Each task becomes an untimed `huddlePlans` doc: text/notes/owner/weekId/
     category/project/`joinRequests` copied verbatim; status mapped
     `open→planned`, `done→completed`, `scheduled→planned` (keeping
     `scheduledPlanId` as a cross-ref); original `createdAt` preserved;
     `migratedFrom: <taskId>` stamped for traceability.
   - Source docs are NOT deleted — stamped `migratedTo: <planId>`; a purge
     button lands in R5. Batched at 200 tasks (400 ops) per commit, toast
     progress.
2. **`subscribeRundown` filters out `migratedTo` docs** client-side, so after
   the migration the legacy cards disappear from "Anytime this week" and the
   migrated plans (delivered by the plans listener) take their place.
3. **Push notifications** ([functions/huddle.js](../../functions/huddle.js)
   `onHuddlePlanUpdate`): two new diffs —
   - a new `pending` entry in `joinRequests[]` → notifies the plan owner
     ("X wants to join: …");
   - an entry flipping `pending → accepted/declined` → notifies the
     requester. Both deep-link `?kind=plan&item=<planId>`.

## No rules change

`huddlePlans` and `huddleRundown` both already `allow update: if
request.auth != null` (firestore.rules ~544–596), and admins create the
migrated plan docs under the existing create rule. Nothing to deploy there.

## Deploy

1. `firebase deploy --only functions` (join-request notifications)
2. FTP (rm/js/huddle.js, sw.js)
3. Then Alex (admin) opens Huddle → Settings → "⇪ Migrate legacy rundown
   tasks" once.

## Verify

- Seed a couple of `huddleRundown` docs locally (or use real ones), run the
  migration: cards reappear as untimed plans with join state intact; owners
  keep accept/decline; re-running reports "Nothing to migrate".
- Second account requests to join a migrated plan → owner gets a push that
  deep-links to the card; accept → requester gets "Request Accepted" push.
