# V3.128 — Rename "projects" → "task builders" in the bucket-tasks model

## Why

The tier-1 entity in [rm/js/tasks-buckets.js](../../rm/js/tasks-buckets.js)
is called `projects` in code and "Project" in UI, but it is **not** a
research project — it is a free-form task-grouping card that holds
sub-buckets and subtasks. The McGhee Lab uses "Project" for actual
research projects (papers, courses, infrastructure, tools) — the canonical
list lives in `projects/{papers,courses,infrastructure,tools}.json` and is
managed in [pages/projects.html](../../rm/pages/projects.html). The
collision is confusing and was called out by the user.

Rename the bucket-tasks tier-1 to **task builder** everywhere in code +
UI, and leave the research-projects pages alone.

## Storage shape — what does and doesn't change

The Firestore docs at `userData/{uid}/buckets/{id}` are unchanged. The
adapter wraps the per-doc array under `wrapKey: 'projects'` purely as the
in-memory shape; flipping the wrapKey to `'taskBuilders'` is a code-only
change with no Firestore migration. The reserved inbox doc keeps its ID
`proj-inbox` (renaming the doc would require a Firestore copy + delete);
likewise existing per-task-builder ID prefixes `proj-...` stay opaque.

## Scope of rename

**Code (in-memory only):**
- `wrapKey: 'projects'` → `'taskBuilders'` in [rm/js/api-routes.js:272](../../rm/js/api-routes.js#L272)
- `state.doc.projects` / `doc.projects` → `state.doc.taskBuilders` / `doc.taskBuilders`
- `state.activeProjectId` → `state.activeTaskBuilderId`
- Local helpers: `findProject(id)` → `findTaskBuilder(id)`, `rollupProject` → `rollupTaskBuilder`, `renderProjectHead` → `renderTaskBuilderHead`, `renderProjectsCol` → `renderTaskBuildersCol`
- CSS class names `.buk-proj-*` are kept for now — they're internal and the rename is mechanical noise; renaming them would also touch [rm/css/style.css](../../rm/css/style.css) for no user-visible benefit.
- ID prefix `proj-...` for new task-builders → keep as-is; new cards continue to use `proj-` slugs. (Avoids a two-tier ID scheme.)
- `proj-inbox` reserved ID stays.

**UI strings (user-facing):**
- "+ New project" → "+ New task builder"
- "Pick a project from the left, or create a new one." → "Pick a task builder from the left, or create a new one."
- "(across all projects)" search hint → "(across all task builders)"
- Pin button: "→ project" → "→ task builder", title "Add this task to a project bucket on the dashboard" → "Add this task to a task builder on the dashboard"
- Pin menu header "Add to project on dashboard" → "Add to task builder on dashboard"; "+ New project…" → "+ New task builder…"; "Existing projects" → "Existing task builders"; "No projects on the dashboard yet." → "No task builders on the dashboard yet."
- Move-to button: "Pin to project…" / "Move to project…" → "Pin to task builder…" / "Move to task builder…"
- Edit button title "Edit project metadata" → "Edit task builder metadata"
- Rename prompt "Project title:" → "Task builder title:"

**Cross-page:**
- [rm/js/tasks-dashboard-buckets.js](../../rm/js/tasks-dashboard-buckets.js), [rm/js/tasks-archive-buckets.js](../../rm/js/tasks-archive-buckets.js), [rm/js/tasks-inbox-buckets.js](../../rm/js/tasks-inbox-buckets.js), [rm/js/task-quick-builder.js](../../rm/js/task-quick-builder.js) all consume `doc.projects` — flip them to `doc.taskBuilders`.
- [rm/js/pmr.js](../../rm/js/pmr.js), [rm/js/projects.js](../../rm/js/projects.js), [rm/js/tasks-inbox.js](../../rm/js/tasks-inbox.js) read the tasks doc — update their bucket-walk paths.
