# V3.677 — Live Whiteboard (lecture drawing streamed to the class page)

> Planned as V3.676; a parallel session claimed that number (BME466 Boltzmann
> move), so this shipped as **V3.677**, sw.js CACHE_VERSION **651 → 652**.
> IMPLEMENTED 2026-08-27 — see the resolution notes in Open questions below.

## Goal

Alex draws on an iPad (Apple Pencil, Safari) during lecture and every student
watching the class page — plus the classroom projector — sees the ink appear
live, sub-second, as he talks. Boards are named and persistent so students can
review them after class. Built as a **generic class-builder capability** (a new
section component any class can add), enabled first for BME/AME 466/566.

## Problem

There is no way to sketch live during lecture through the site. The class page
already streams *data* live (V3.251 groupResponses Q&A, V3.285 schedule-doc
onSnapshot) but has no drawing surface. Alex currently has no tablet→students
inking path at all; anything drawn in class dies on the room whiteboard.

## Decisions locked with Alex (grill session 2026-08-27)

- **Placement:** generic tool for any class-builder class, not a BME466
  one-off. Surfaced as a new section component (`whiteboard`) in the section
  registry; BME466 gets a "Whiteboard" tab.
- **Who draws:** class admins only (`classAdminEmails` + global admin +
  ownerUid — the existing schedules gate). No pen handoff to students in V1.
- **Who views:** world-readable, same contract as `schedules/{id}`
  (`allow read: if true`) — zero sign-in friction at lecture start. Nothing
  student-identifying is ever drawn (same rule as the schedule doc).
- **Lifecycle:** named boards, kept. Board list per class; create/open/rename/
  delete (admin); students can review past boards anytime.
- **V1 tools:** pen (colors + widths + Apple Pencil pressure), stroke eraser,
  undo, clear page, **multiple pages per board** (viewers auto-follow the
  admin's page), **background templates** (blank / grid / ruled / axes).
- **Out of scope V1:** laser pointer, text boxes (both explicitly deferred).
- **Input:** iPad + Apple Pencil in Safari. `pointerType === 'pen'` draws;
  touch scrolls/pinches — true palm rejection, pressure → line width.
- **Live entry:** going live sets a flag on the schedule doc; students on any
  tab of the class page see a "🔴 Whiteboard is live" banner, one tap to jump.
  No forced navigation.
- **Projector:** yes — a chrome-free fullscreen viewer route for the podium PC.

## Approach

### Data model (Firestore only — no RTDB, no Cloud Functions)

```
schedules/{classId}/whiteboards/{boardId}
  { name, createdAt, updatedAt,
    pages: [ { id, background: 'blank'|'grid'|'ruled'|'axes' } ],
    activePageId,          // the page the admin is on; viewers follow
    strokeSeq }            // monotonic counter the drawer increments locally

schedules/{classId}/whiteboards/{boardId}/strokes/{strokeId}
  { pageId, seq, color, width,
    pts: [x0,y0,p0, x1,y1,p1, ...],   // flat, normalized 0..1 in board space
    done: true|false }                 // false while the pen is still down
```

- **Streaming:** while the pen is down the drawer flushes the in-progress
  stroke every ~300 ms with `set({...}, {merge:true})` rewriting the full
  `pts` array (strokes are small; array-append doesn't exist in Firestore and
  full rewrite is fine at this size), then a final flush with `done:true` on
  pen-up. Very long strokes split at ~1000 points into chained docs.
- **Viewers:** one `onSnapshot` on the strokes collection
  `orderBy('seq')` (single-field — **no composite index needed**), client-side
  filtered by the visible page. Incremental canvas paint: only new/changed
  strokes redraw; a `done:false` stroke repaints live as its `pts` grow.
- **Coordinates:** normalized to a fixed 16:10 board space so iPad, laptops,
  and the projector render identically at any pixel size (devicePixelRatio-
  scaled canvas).
- **Undo** = drawer deletes their last stroke doc (local id stack).
  **Eraser** = hit-test stroke polylines, delete the doc (stroke-level, syncs
  for free). **Clear page** = batched delete of that page's stroke docs
  (admin-confirmed).
- **Live flag:** `liveWhiteboard: { boardId, since }` merged onto
  `schedules/{classId}` when the admin taps "Go live" (cleared on "End").
  Admins can already write the schedule doc under existing rules — no new
  rule needed for the banner. Page-follow rides `activePageId` on the board
  doc, not the schedule doc, so page flips don't spam schedule-doc listeners.

### UI

1. **Section component `whiteboard`** (new entry in the class-builder section
   registry, generic like `files`/`modules`, NOT a 466-specific one): renders
   the board list (name, updated, page count, 🔴 live badge). Admin extras:
   New board, rename, delete, Open to draw. Everyone: Open to watch.
2. **Board view** — full-viewport overlay (precedent: module viewer):
   - *Viewer mode* (default, incl. logged-out): canvas + page dots +
     "following live" chip. Flipping back through pages pauses follow; a
     "jump to live page" chip re-engages.
   - *Draw mode* (class admins, same route): toolbar — pen colors (4) +
     widths (3) via pressure baseline, eraser, undo, clear page, page
     add/flip, background picker per page, Go live / End live.
     Pen-only inking (`pointerType === 'pen'`, `getCoalescedEvents()` for
     smooth curves); touch pans/zooms and never inks.
   - *Projector mode* — same route + `projector=1` param: no site header, no
     toolbar, no page dots; high-contrast ink on white; auto-follows live page.
3. **Live banner** — the class page's schedule-doc onSnapshot (V3.285 pattern,
   currently wired for bme295c) is generalized so any class page reacts to
   `liveWhiteboard` appearing: sticky banner "🔴 Whiteboard is live — tap to
   watch" above the tab strip on every tab.
4. **Route** — `#/classes/{classId}/whiteboard/{boardId}` in app.js (precedent:
   `#/classes/{classId}/modules/{filename}`), with optional `projector=1`.
   Deep-linkable for the podium PC bookmark.

## Files modified / added

- **`whiteboard.js` (NEW, root)** — the whole feature: board list renderer,
  canvas engine (draw + view + projector), Firestore sync (stroke flusher,
  onSnapshot painter), toolbar. Loaded from index.html alongside
  class-builder.js. class-builder.js only *delegates* to it.
- **`class-builder.js`** — section registry entry
  `whiteboard: { label: 'Whiteboard', component: 'whiteboard' }`; the
  component case delegates to `window.Whiteboard.renderSection(...)`;
  generalize the V3.285 schedule-doc onSnapshot from bme295c-only to any
  class so the live banner works; teardown added to cleanupListeners().
- **`app.js`** — `#/classes/{classId}/whiteboard/{boardId}` route (+ projector
  param parse) → `window.Whiteboard.openBoard(...)`.
- **`index.html`** — `<script defer src="whiteboard.js">`.
- **`styles.css`** — whiteboard styles appended (board list, toolbar, canvas
  overlay, banner, projector mode) — cb- styles already live here.
- **`firestore.rules`** — new nested block inside `match /schedules/{scheduleId}`:

  ```
  match /whiteboards/{boardId} {
    allow read: if true;
    allow write: if request.auth != null
      && (isAdmin()
          || get(/databases/$(database)/documents/schedules/$(scheduleId))
               .data.ownerUid == request.auth.uid
          || (request.auth.token.email != null
              && request.auth.token.email in
                 get(/databases/$(database)/documents/schedules/$(scheduleId))
                   .data.get('classAdminEmails', [])));
    match /strokes/{strokeId} { /* same read + same write gate */ }
  }
  ```

  (Same `get()`-the-parent pattern as the V3.247 Q&A / assessments blocks.)
- **`sw.js`** — CACHE_VERSION 650 → 651 (re-verify head at implementation).
- **BME466 enablement** — add a "Whiteboard" tab (one `whiteboard` section) to
  the class. ⚠️ NOT via the seeded def alone: `resolveSchedule()` prefers
  Firestore, and if `schedules/bme466` already exists there the seed edit is
  invisible. Enable via the class editor UI (the registry entry makes the
  section available) or a one-time admin merge. Seed def updated anyway so
  offline fallback matches.

## Data model changes (summary)

- New: `schedules/{classId}/whiteboards/{boardId}` + `strokes` subcollection
  (shapes above). World-read, class-admin write.
- Changed: `schedules/{classId}` gains optional `liveWhiteboard` field
  (admin-written under existing rules).
- No composite indexes (single-field `orderBy('seq')`). No storage.rules
  change (no uploads). No Cloud Functions. No shadowJson (main-site direct
  Firestore, not the rm adapter).

## Out of scope (V3.676)

- Laser pointer (transient pointer trail) — deferred.
- Text boxes / typed labels — deferred.
- Pen handoff to a student; student drawing of any kind.
- Draw-over-slides / image backgrounds (templates only).
- Export to PNG/PDF; embedding boards into learning modules.
- Ourlab mobile native tab work — the class page isn't part of the rm/ bundle;
  no app build is required beyond the normal batch ritual.

## Rollback

- **Instant, no redeploy:** remove the Whiteboard section/tab from the class
  in the class editor — the feature disappears for students; board data sits
  inert and world-readable-but-unlinked.
- **Code:** git revert + re-FTP + sw bump. No schema migrations; `strokes`
  docs and the optional `liveWhiteboard` field are additive and harmless. If
  a live flag is stranded, clearing `liveWhiteboard` on the schedule doc kills
  the banner.

## Open questions — resolved at implementation

1. **`schedules/bme466` exists in Firestore** (confirmed: the live class page
   serves 3 tabs from the doc, not the seed). Resolved with a V3.674-style
   migration in `wireClassPage` that appends the Whiteboard tab on the next
   admin visit — no manual UI edit needed.
2. Firestore stroke-flush latency over campus wifi — 300 ms flush cadence is
   the starting point (`FLUSH_MS` in whiteboard.js); if viewers report >1 s
   lag, drop to 150–200 ms (write volume still fine: a heavy 75-min lecture ≈
   low thousands of writes). STILL OPEN — tune after first lecture.
3. **The banner got its own narrow listener** (`attachLiveBanner` in
   whiteboard.js) rather than generalizing the V3.285 bme295c splice listener
   — zero risk to the 295c keystroke-flush logic.
4. Board aspect: 16:10 (`BOARD_AR` in whiteboard.js); confirm the room
   projector isn't 4:3 before first use. STILL OPEN.
