# V3.859 — One 📑 Collection: quotes, lit reviews and collections become one card

**Date:** 2026-10-23
**Alex:** *"quote, lit review, and collection cards can probably be combined. for example quote card and lit review card is
really just going to come from a paper anyways, so these can be combined into a single system."* Asked three questions, he
answered: *"1) yes, lit reviews must be linked to the paper we are writing, and we can connect multiple papers we are
writing to any collection. 2) one per section yes so the user can split up claims an ideas 3) no these can be separate
things."*

## Goal

Everything that comes from a paper lives in one card kind, `collection` (V3.856). A **quote** is a collection holding one
passage, a **lit review** is a collection of papers with key points and notes, a **claim** is a collection bound to a draft's
claim. Any collection can be **linked to one or more papers you are writing**: every library paper it touches is then linked
to each of those drafts (`linked_drafts`), and the draft's figure board lists it first. Figures (the notebook's figure card,
the figure board's reference figure) stay separate.

## Design

### The collection's data
```
data: {
  items: [entry],          // highlight | figure | card (V3.856) + paper | quote (new)
  keyPoints: [string], notes_html: string, query: string,     // from the lit review
  drafts: [{ id, title }], linkedPairs: ['paperId|draftId'],  // papers we are writing (decision 1)
  claim: null | { draftId, draftTitle, claimId, statement }, claimSetup: bool,
  shape: 'quote' | undefined                                  // a one-passage collection reads as a quote
}
```
- **`paper` entry** `{ id, type:'paper', paperId, title, cite, year, journal, why, rel:'informs', wireId? }` — from the
  library search, or a wire from a 📖 Paper card's own side port.
- **`quote` entry** `{ id, type:'quote', quote, cite, paperId?, page?, rel:'quote' }` — a passage typed or taken as text
  ("Add as text"); editable. A highlight from the reader stays a `highlight` entry (read-only text, the annotation owns it).

### Two shapes, one renderer (`renderCollection`)
- **Quote shape** — `shape === 'quote'` and exactly one `quote` / `highlight` entry, no papers, key points, notes or claim.
  A `quote` entry renders as the old editable passage (`textarea.nbc-quote-in` + `input.nbc-cite-in`), a `highlight` as a
  blockquote + citation; both with the reader link. Anything else landing on it turns it into the list shape (computed, not
  stored). ⋯ offers "Show as a list" / "Show as a quote".
- **List shape** — claim head · *Linked to* chips · **Papers** (title link, citation · journal, a "why it matters" input, ×) ·
  the typed groups of V3.856 · **Key points** (`[data-kp]` inputs, Enter adds the next) · **Notes** (contenteditable, shown once
  used) · a foot: a library search (`input.nbc-lit-q`, results inline under it, `[data-add]` rows), then small buttons
  ＋ Key point (`[data-kpadd]`) · ＋ Note · ❝ Quote · ✎ Link to a paper you're writing… · ◆ Make this a claim….
  (Class names kept from the lit review so the V3.833 / V3.852 harness selectors keep meaning the same controls.)

### Linked drafts (decision 1)
- Chips `✎ <draft title> ×` and "✎ Link to a paper you're writing…" → an anchored menu of my drafts (`papers where
  authorUids ∋ me`, not library entries). Several drafts per collection.
- On a figure board a new collection is linked to the board's paper from birth (`make()` reads `H.draftId()`); making a claim
  links the claim's draft.
- `syncDraftLinks(col)`: for every draft × every library paper the collection touches (paper entries + the `paperId` of
  highlight / figure / quote / card entries) call `LIBRARY_LINKS.toggleDraftLink(pid, draftId, true)` once, remembered in
  `linkedPairs`. Unlinking a draft (or removing the card) removes the pairs this collection made unless another collection
  or `litref` on the same board still holds them.
- The notebook mirror carries `draftIds`; the figure board's 📚 tool ("Add a collection from your notebook") lists the ones
  linked to this paper first; placing one there also writes this draft into the notebook card's `drafts` (read-modify-write
  of the item, owner only) and the mirror's `draftIds`.

### Mirror
Every notebook collection writes `userData/{uid}/litReviews/{itemId}` (the V3.838 path, so placed `litref` cards keep
working): `kind:'collection', title, boardId, entryId, query, paperIds, keyPoints, papers, entries (light, ≤ 60), claim,
draftIds, ownerUid, updated_at`. Written when a collection's title or data changes (`onItemsChanged` keeps a per-card
signature; the first sight of a card only seeds it), deleted with the card. The figure board's `litref` card shows the claim
badge, the key points (`.fbc-lit-points li`, unchanged) and a count line ("2 papers · 3 highlights · 1 figure").

### Adopting the old kinds (decision 2: one collection per section)
`paperquote`, `quote` and `litreview` stay registered (hidden from ＋ Insert) and render through `renderCollection` via
`asCollection(it)`, which converts their data in memory: a quote → quote shape with one entry (a `highlight` when it carries
`annId` + `paperId`, else a `quote`); a lit review's **first section** → this card (papers, key points, notes, query), its
**other sections** → pending collections. Nothing is written on render. **The first edit adopts the card**: sections 2…N
are added as new collection cards beside it with deterministic ids (`<id>_s2` …, so a second tab adopting at the same time
writes the same docs), titled by their section, then the card itself is rewritten to `kind:'collection'` with its new data,
then the edit is applied. A multi-section review also shows a banner, "This lit review has N sections — Split into N
collections", which adopts on demand. `widgetToBlock` (PMR / the block mirrors) gains a `collection` case; the old cases
stay for cards nobody has edited.

### Entry points
- ＋ Insert: one row, **📑 Collection** — "a quote, a lit review of papers, or a claim; fill it by connecting highlights,
  figures and papers, or search the library" (the picker's search matches quote / lit review).
- Notebook / figure board paper picker: a highlight → a quote-shaped collection with a `highlight` entry; "𝑇 Add as text" → a
  quote-shaped collection with a `quote` entry.
- 📚 on a note's selection → a collection titled "Lit review: <words>" with `query` set; its search runs at once.

## Decisions
- **Adopt on first edit, never on render** (the V3.833 lesson: a render-time write raced the migration and wiped blocks).
- **Deterministic ids for split sections** so two tabs adopting the same review converge instead of duplicating.
- **Keep the mirror path** `litReviews/{id}`: placed figure-board cards and the rules already use it; the collection is a
  lit review in everything but name. A split moves sections 2…N to new mirrors; a `litref` placed from the old review keeps
  showing section 1 (its paper links are never removed by a split).
- **Paper entries carry no stance**: the claims model ties evidence to an annotation, so a whole paper is listed, not
  counted for / against.
- **No auto-placement on figure boards**: linking from the notebook links the papers and lists the collection first in the
  board's picker; placing stays the author's choice.
