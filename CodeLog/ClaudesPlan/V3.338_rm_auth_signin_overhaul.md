# V3.338 — RM Auth / Sign-in Experience Overhaul

## Goal

Fix the four structural auth-UX problems in RM: (1) ~30 pages rendered
**silently blank** to logged-out deep-link visitors (the only sign-in surface
was the avatar-glyph dropdown); (2) a single failed profile read left
`whenAuthResolved()` unresolved **forever** (permanent spinner, nav chip
stuck on "setting up profile…"); (3) mid-session permission-denied errors
were silently converted to empty data by the adapter's catch-all; (4) the
old `gateSignedIn` notice destroyed the page DOM, so signing in required a
reload. Companion release to V3.332 (main-site login overhaul).

All changes are UX-layer; `firestore.rules` remains the security boundary.

## Approach

### Shared sign-in component (firebase-bridge.js)
`_signInFormHtml()` / `_wireSignInForm(rootEl)` extracted from the dropdown's
signed-out branch — class-based selectors (`.fb-signin-*`) so the dropdown
and the new gate card coexist. Errors go through `_friendlyAuthError()`
(mirror of the parent site's code→copy map; shared wrong-password /
user-not-found message).

### Non-destructive gate card
`_renderGateNotice` now stashes the page's existing DOM in a hidden
`#fb-gate-stash` and appends a `#fb-gate-card`; `_clearGateNotice()`
restores. `level === 'signin'` renders the shared sign-in form inline —
a logged-out deep link gets a working Google + email/password card, not a
dead end.

### `firebridge.requireSignIn(reason)` — the default gated entry
Drop-in replacement for `await firebridge.whenAuthResolved()`:
- Signed out → shows the gate card, resolves only after sign-in succeeds
  (via `_whenSignedIn()`), restores the stashed DOM — the page's boot
  continues **without a reload**.
- Arms a once-per-page sign-out watcher (`_watchSignOutRegate`) that
  re-shows the card if the user signs out mid-session.
- Returns `{ allowed: true, user, profile, degraded }`.
- `gateAdmin` now builds on it (signed-out admins get the sign-in card,
  then the admin-only notice if the account isn't admin). `gateSignedIn`
  kept for compatibility.
- Deliberately NOT folded into `whenAuthResolved()` itself — nav.js,
  sync-status.js, local-cache.js, all-pages.js/home-feed.js (gated by
  workflow-chooser on the same page) legitimately consume it ungated.

### Stuck-load fixes
- `_loadProfile`: 3 attempts (0/800/2400ms backoff); missing doc is not an
  error (fresh-user bootstrap case); permission-denied breaks immediately;
  `_profileError` tracks final failure.
- `_whenAuthResolved` / `_whenSignedIn`: 10s degraded-resolution timeout
  when `user && !profile` persists — pages render instead of spinning
  forever; `degraded: true` flags it.
- Nav chip (`_statusTitle`) + dropdown show "Profile failed to load" +
  **Retry** (`firebridge.retryProfile()` → `PROFILE_BOOTSTRAP.retry()` +
  `refreshProfile()`).
- `profile-bootstrap.js`: guest-doc `set()` retries with the same backoff;
  `window.PROFILE_BOOTSTRAP.retry()` clears the one-attempt-per-uid latch.

### Permission-denied visibility
- New `firebridge.notifyAccessIssue(context)`: singleton dismissible amber
  banner (`#fb-access-banner`, below the pending overlay) with Retry /
  Sign-out; 20s re-show suppression after dismissal; auto-removed when the
  live profile snapshot changes (role promotion).
- `api-firestore-adapter.js` `api.load`: permission-denied **while signed
  in** → banner + typed-empty result (no legacy-JSON fallback, which would
  serve single-tenant seed data locally). Other errors keep the fallback.
- `api.subscribe`: all three `onSnapshot` calls gained a shared `_snapError`
  handler (they had none); `firebridge.onSnapshot`'s error path also routes
  permission-denied to the banner.

### Per-page sweep (one-liners)
- **A1 (await-style `gateSignedIn` → `requireSignIn`)**: activity-overview,
  calendar, classifier-settings, email-review, year-review, pmr,
  lab-notebook, protocol-doc, protocol-editor.
- **A2 (fire-and-forget pair → single `requireSignIn`)**: activity-tracker,
  chat, equipment, huddle, meetings, procurement.
- **B (whenAuthResolved-only, silently blank — the core fix)**: analytics,
  budget-model, career, chemicals, compliance, dashboard, finance, grants,
  inventory, important-people, people, projects-grants, projects, receipts,
  service, settings, tasks-buckets, tasks-dashboard-buckets,
  tasks-inbox-buckets, tasks-archive-buckets, task-market,
  classifier-review, workflow-chooser (makes `/rm/` itself the sign-in
  landing), workflow-shell.
- **C (no auth handling — gate added at boot)**: item-explorer,
  library, library-paper, paper-builder, paper-export, cv-editor,
  grant-builder, grant-biosketch, grant-facilities, lab-tasks,
  admin-migrate, api-usage, protocols.
- **D (training)**: training.js + all 17 training-*.js modules.
- **Unchanged**: library-public (deliberately public), pcard-helper (pure
  calculator), citation-audit (own admin check), nav/sync-status/
  local-cache/oauth-connections (infrastructure consumers), redirect stubs.

## Files

- `rm/js/firebase-bridge.js` — everything above; new exports
  `requireSignIn`, `retryProfile`, `notifyAccessIssue`.
- `rm/js/api-firestore-adapter.js` — permission-denied handling in load +
  subscribe.
- `rm/js/profile-bootstrap.js` — retry loop + `PROFILE_BOOTSTRAP.retry()`.
- `rm/css/style.css` — `#fb-gate-card`, `#fb-access-banner`.
- ~60 page modules — mechanical gating swaps per the sweep above.
- `sw.js` — CACHE_VERSION 309 → 310.

## Key decisions

- Centralize in `requireSignIn` rather than auto-gating
  `whenAuthResolved()` (would break infrastructure consumers) or a
  per-page HTML attribute (~50 HTML file edits).
- Stash/restore instead of innerHTML-destroy so in-card sign-in continues
  the page's existing boot promise chain — no reload.
- Degraded resolution (10s) trades a rare wrong-empty render for the
  guaranteed elimination of the infinite spinner; the retry affordance
  lives in the nav chip either way.
