# V3.641 — Heroicons v2, phase 0: the seam

## Goal

Alex: *"Throughout the entire website and mobile app lets use Heroicons v2
icons."*

Every icon in the product today is an emoji typed into a JS string. Emoji
render differently on every OS, can't be recolored, can't take a hover or
active state, and sit on a different baseline from the text beside them.
**Heroicons v2** — MIT, 324 icons, every SVG already using `currentColor` —
replaces them, so an icon inherits `--text-muted` / `--primary` and gets
active states for free.

This is a multi-phase program. **Phase 0 ships the machinery and changes
nothing on screen.**

## Measured scale (the plan's first number was wrong)

An initial count said 3,643 emoji in `rm/`. A re-count shows that was
inflated ~2.5×: the bulk is **box-drawing** — `─` appears 41,642 times and
`═` 19,242 — in ASCII comment banners and training-page diagrams.
`training-confocal.html` looked like 723 emoji; it is 708 `═` and two real
ones.

The real addressable surface, live JS code only:

| | |
|---|---|
| occurrences in `rm/js/*.js` (non-comment) | **1,567** |
| distinct glyphs | 268 |
| glyphs appearing exactly once | 105 |
| top 10 glyphs | 31% of occurrences |
| top 64 glyphs | 74% |

So the manifest ships **81 icons covering the top ~64 glyphs**, not 268.
Past that, an outline SVG is usually worse than the emoji it replaces.

## Decisions Alex made before implementation

| Question | Decision |
|---|---|
| Scope | **Chrome + UI controls** — app furniture, not prose, not user-picked icons |
| Glyphs Heroicons lacks | **Draw custom SVGs** in Heroicons house style |
| Emoji stored in Firestore | **Leave as emoji** — no migration, render-time shim |
| Weight | **24px outline default, solid for active/selected** |

## What phase 0 contains

### 1. Vendored source, at the repo root on purpose

```
vendor/heroicons/          LICENSE (MIT), 24/{outline,solid}/*.svg  (v2.2.0)
  custom/24/{outline,solid}/    our 7 gap icons
  custom/make_custom_icons.py   their source of truth — the icons are generated
```

**Root `vendor/`, not `rm/vendor/`.** `OurlabMobile/scripts/sync-rm.mjs`
rsyncs *all* of `rm/` into the phone bundle, and ~650 unused source SVGs
have no business travelling with it. Only the generated `rm/js/icons.js`
ships.

### 2. `scripts/gen-icons.mjs` + `scripts/icons.manifest.json`

The manifest is the source of truth for which icons ship, and carries the
**emoji each icon replaces** — that reverse map is what powers the kill
switch. The generator:

- strips `xmlns` / `aria-hidden` / `data-slot` / `stroke-width` from the
  wrapper (CSS owns stroke-width so it stays overridable; `ICON` owns aria)
  but **keeps `fill-rule` / `clip-rule` / `stroke-linecap` / `stroke-linejoin`**
  on the paths — dropping `fill-rule="evenodd"` visibly corrupts solid icons;
- hard-fails on a manifest name with no source file, a source without
  `currentColor`, or **one glyph claimed by two icons** (this caught 📑
  mapped to both `bookmark-square` and `table-cells` on the first run);
- `--check` fails if the committed `icons.js` is stale;
- `--scan` fails on a call site naming an unshipped icon **and on the trap
  class below**.

This is **not a build step** — nothing the browser does depends on it, and
the site works from the committed `icons.js` alone. It is a *release gate*,
wired into `scripts/release_push.py` preflight.

### 3. `rm/js/icons.js` — 42 KB, 81 outline + 11 solid

```js
ICON.svg(name, opts)   // markup string, for innerHTML — the dominant call site
ICON.el(name, opts)    // SVGElement, for textContent/appendChild sites
ICON.render(value)     // emoji | image URL | icon name  (the storage shim)
```

Two contracts that keep a partial migration safe:

- **An unknown name never throws and never renders blank** — it returns
  `question-mark-circle`, warns once, and marks the element
  `data-icon-missing="1"` so QA can assert on it in the DOM rather than
  scraping console output.
- **`label` drives aria, mutually exclusively.** No label →
  `aria-hidden="true" focusable="false"`. Label → `role="img" aria-label`
  and *no* `aria-hidden`; emitting both is a WCAG failure.

### 4. The custom gap icons — 7, drawn and visually verified

Heroicons has no microscope, target, thumbtack, compass, stacked-books,
barricade or helix, and those land on the most brand-critical chrome
(🔬 Research, 🎯 the Focus tab, 📚 the Library tab, 📌 at 29 uses).

**Every design was rendered at 16/20/24/56px and looked at before being
kept.** Rejected on sight, recorded so nobody redraws them:

| attempt | read as |
|---|---|
| books as three upright bars | a bar chart |
| books as a horizontal stack | a list / table |
| microscope as tube + stage | a pen, then a highlighter |
| **handshake, two attempts** | **a squiggle at every size — DROPPED** |
| construction solid, 4 stripes | stripes ate the rail; 3 × 1.2 kept |

🤝 maps to upstream `user-group` instead. A near-miss that reads beats a
custom icon that doesn't.

### 5. CSS — `.hi` in `style.css`, `--hi-*` tokens in `tokens.css`

Three details are load-bearing and should not be "cleaned up":

- **`width: 1em`** resolves against the element's *own* font-size, so a bare
  `.hi` tracks its context. Every existing icon wrapper already sets one —
  `.ws-icon` 18px, `.ap-card-icon` 20px, `.ourlab-tab .ot-icon` 22px — so
  those three call sites reproduce their old emoji dimensions with **no CSS
  change at all**.
- **`vertical-align: -0.125em`** — an emoji is a text glyph placed by font
  metrics; an inline SVG is a replaced element whose *bottom edge* sits on
  the baseline, so it hangs ~6px low next to 14px text without this. Inert
  inside flex rows, so it only matters for raw-string `innerHTML` sites.
- **`flex: none`** — without it an icon in a flex row beside a long label
  collapses to zero width and silently vanishes. Layout-dependent, so it
  only shows up with long text.

### 6. Loading — 78 pages

`<script src="/rm/js/icons.js">` immediately after `runtime-mode.js`, which
has the widest coverage (78 pages vs 75 for `nav.js`/`util.js`), is already
first in `<head>`, is parser-blocking, and has no dependencies. Verified on
all 79 files that `icons.js` sits **after** `runtime-mode.js` and **before**
`nav.js`.

The 16 pages without it are `<meta refresh>` stubs. `library-public.html` is
a real standalone public page but has no icons yet — it gets the tag when
the library phase reaches it, rather than paying 42 KB parser-blocking for
nothing.

**`sw.js`: `CACHE_VERSION` 613 → 614, and nothing added to `SHELL_URLS`.**
That array holds no `/rm/` paths — RM is covered by the `/rm/` networkFirst
branch. Adding one would be actively dangerous: `install` uses
`cache.addAll`, which is **atomic**, so a single 404 in the window between
the git commit and the Cyberduck FTP would break service-worker
installation *for the entire site*.

## ★ Correction: 203 text sinks, not 9

Planning said ~9 `.textContent = '<glyph>'` sinks across 6 files. A precise
scan against the manifest's mapped glyphs found **203 across 54 files**.

That changes the approach. Hand-converting 203 sites is not a phase-0 task,
and converting them *would itself be the visual change phase 0 exists to
avoid*. Instead `--scan` now **fails the release** on the whole class:

```
.textContent / .innerText  =  … ICON.svg|render …     → use ICON.el()
esc|escHtml|escapeHtml( ICON.…                        → trusted markup, don't escape
.setAttribute('title'|'aria-label'|'alt'|'placeholder', … ICON.…)  → pass {label}
```

All three were proven to fire against a planted trap file, and a commented-
out example correctly does *not* trip them. Mechanical enforcement across
54 files beats a one-time hand-audit of 6.

## ★ The `maxlength="2"` blocker

`admin-permissions.js:551` (and the add-workflow form at `:520`) edited a
workflow icon through `<input maxlength="2">` — an admin physically could
not type `beaker`. Both are now `maxlength="40"`, 92px wide, with a title
pointing at `/rm/pages/icon-audit.html`. The `|| '📁'` default is unchanged,
because phase 0 changes no glyphs.

## Storage: nothing migrated, ever

`ICON.render()` accepts all three shapes because they are **provably
disjoint** — emoji are never ASCII, URLs always carry a scheme, names are
always lowercase-ASCII-with-hyphens:

```
/^(https?:|data:)/i        → <img>          uploaded labIcons artwork
/^[a-z][a-z0-9-]{1,40}$/   → Heroicon       new picks
otherwise                  → the glyph      what users chose years ago
```

So `research` foci `.icon`, `labConfig/defaultWorkflows[].icon`, and every
`labIcons` upload are byte-identical before and after, and a full revert
leaves zero orphaned data. Same seam V3.638 documented rather than migrated.

## Rollback

`ICON.setMode('emoji')` renders the glyph each icon replaced, at render
time. Set `window.RM_ICON_MODE='emoji'` before `icons.js` loads, or
`localStorage.rm_icon_mode`. **This is the only rollback that reaches phones
already running a shipped TestFlight build** — reverting the web tree does
not. Verified working in both directions.

## Deploy

**FTP + TestFlight. No `firebase deploy`** — no rules, indexes or functions
are touched. The app must ship in the batch: `sync-rm` bundles `rm/`, so an
FTP-only push would leave phone users without `icons.js` while their cached
HTML asks for it.
