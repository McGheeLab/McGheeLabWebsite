# V3.294 — Paper Reader Tabs (multiple papers open at once)

## Goal

Let the user keep **multiple papers open simultaneously** in the library
paper reader (`pages/library-paper.html`) via a **tab strip**, capped at
**10 open papers**. Switching tabs is **instant in-place** — no full page
reload, no PDF re-render for an already-visited tab, scroll position and
zoom preserved per tab.

User decision (asked 2026-06-27): chose **instant in-place swap** over the
lower-risk reload-on-switch. That commits us to keeping each visited tab's
PDF viewer alive and to tearing-down / re-attaching the singleton annotation
stack cleanly on every switch.

## Why this is non-trivial

The reader is a strict singleton page. `PDF_VIEWER.create()` and
`ANNOTATION_SYNC.start()` are already instance-based (good), but the rest of
the stack — `ANNOTATION_OVERLAY`, `ANNOTATION_PANEL`, `GEOM_SELECTION`,
`PAPER_OVERLAYS`, `PAPER_OVERLAY_TYPES`, `PAPER_OVERLAY_IMPORT`,
`PAPER_SEARCH`, `PAPER_CITATIONS`, `PAPER_CITED_BY` — are `window.*`
singletons that serve one paper at a time and share DOM mount points
(`#lp-viewer`, `#lp-annotations`, `#lp-citations`, the side rail). Several
**leak `document`-level listeners** or **accumulate callback arrays** when
`init()` runs a second time:

| Module | Leak on re-init | Fix |
|---|---|---|
| `paper-overlays.js` | anonymous `document` click (L319) re-added every `_render()` | named handler, bind once, remove in `destroy()` |
| `paper-search.js` | anonymous `document` click (L130) every `init()`; stale `_debounceT` | named handler bound once + `destroy()` clears timer/listener |
| `paper-overlay-import.js` | 4 drag/drop listeners on the viewer el every `init()` | track wired el + handler refs; unwire-then-wire; `destroy()` |
| `paper-overlay-types.js` | `_changeCallbacks` never cleared | reset in `init()` + `destroy()` |
| `annotation-panel.js` | `_filterCallbacks` stacks; per-card Maps grow | reset all at top of `init()` |
| orchestrator `copy` listener (L679) | re-added every `_mountAnnotations` | hoist to once-only named handler |
| orchestrator tag-editor `click` (L145) | re-added every `_renderTagEditor` | named handler bound once |
| orchestrator `setZoom` monkey-patch (L813) | double-wraps on re-attach to same viewer | guard with per-viewer flag |

`ANNOTATION_OVERLAY`, `GEOM_SELECTION`, `PAPER_CITATIONS` already expose a
`destroy()` that removes their own listeners — the orchestrator just has to
**call** them on detach (today nothing does except `beforeunload`).
`ANNOTATION_GROUPS` is refcounted and multi-tab-safe; the orchestrator must
capture and call its `subscribe()` unsubscribe on detach (today it's
dropped). `ANNOTATION_ANCHOR`/`ANNOTATION_SYNC` need no change.

## Approach

### DOM / layout
- `.lp-main` gains a new first child `.lp-tabs#lp-tabs` (the strip) above
  the mobile bar.
- The single `<div class="lp-viewer" id="lp-viewer">` becomes a **host**
  `<div class="lp-viewer-host" id="lp-viewer-host">`. Each visited tab gets
  its own pane `<div class="lp-viewer lp-viewer-pane" data-paper-id="…">`
  appended to the host. Only the active pane is shown.
- **The active pane carries `id="lp-viewer"`** (the id moves on switch). This
  means every existing `getElementById('lp-viewer')` (annotation-overlay
  scroll-centering L239, paper-overlay-import dropzone, library-paper viewer
  mount) automatically resolves to the active pane's scroll container — no
  edits to those lookups needed.

### Tab model (in `library-paper.js`)
- `_tabs = [{id, title}]`, capped at `MAX_TABS = 10`. Persisted to a new
  localStorage key `rm_lp_open_papers` = `{tabs, activeId}`.
- `_viewers = Map<id, {viewer, pane}>` — created **lazily** on first
  activation. Boot only creates the active tab's viewer (fast boot).
- Opening an 11th paper evicts the **least-recently-active** non-active tab
  (its viewer destroyed, pane removed) to stay ≤10.

### Lifecycle refactor of `library-paper.js`
Split the monolithic `init()` into:
- `bootOnce()` — one-time wiring: layout, toolbar keydown, mobile drawers,
  the hoisted `copy` + tag-editor `click` listeners, tab-strip event
  delegation, `beforeunload`.
- `loadLibraryOnce()` — load `items.json` once → `_allItems`, tag index,
  drafts pool.
- `activateTab(id)` → `detachActive()` then `ensurePaneActive(id)` (create
  viewer if cold, else show existing pane) then `attachActive(id)`.
- `detachActive()` — unsub sync + groups; `destroy()` overlay / geom /
  citations / overlays / search / types / import. Viewer is **not**
  destroyed (stays warm); its pane is hidden.
- `attachActive(id)` — render side panels for `_item`; init the singleton
  stack against the active viewer + pane; start annotation sync; guard the
  `setZoom` wrap per viewer.
- `closeTab(id)` — destroy that tab's viewer (if any), remove pane, drop
  from `_tabs`, activate a neighbor; if none left, show empty state.

### Entry-point integration (no caller changes)
All ~11 existing links navigate to `library-paper.html?id=X` (full page
nav). On boot the reader ensures `X` is in `_tabs` (adds/focuses) and
activates it. So opening a paper from anywhere = "add/focus a tab" for free.
The in-reader cross-paper links in `paper-citations.js`/`paper-cited-by.js`
already use `target=_blank`; left as-is for v1 (they open a fresh reader
window that restores the persisted tab set). In-app open of those as new
tabs without a window = follow-up.

URL: on switch we `history.replaceState` to `?id=<active>` so refresh /
bookmark / the in-page filter-param writer (`annotation-panel`, which only
mutates its own author/color/stance/mine keys) stay consistent. The deep
link `?import=&draft=` auto-import flow runs only for the initially-opened
paper.

## Key decisions

1. **Instant swap via live per-tab panes** (user choice), not reload.
2. **Lazy viewer creation** — only visited tabs hold a viewer; memory bounded
   by views, hard-capped at 10. Eviction by least-recently-active. (Eager
   pre-render of all tabs rejected: 10 PDF downloads at boot.)
3. **`id="lp-viewer"` on the active pane** — zero edits to existing
   `getElementById('lp-viewer')` lookups.
4. **Detach/re-attach the singleton stack each switch** rather than making
   every module instance-based (the latter is a multi-thousand-line refactor
   of `annotation-panel`/`paper-citations`). Hardening their `destroy()` is
   the bounded, correct cost.
5. **No new Firestore paths / rules / functions** — this is a client-only
   change. Deploy = FTP `rm/` + `sw.js`, hard reload.

## Risks / verification

- Listener double-bind is the classic failure mode here — verify by opening
  3+ papers, switching repeatedly, and confirming a single highlight-copy,
  single overlay-popover-close, single search-dropdown-close per action.
- Annotation sync must point at the active paper only (no cross-paper writes)
  — verify a highlight created on tab A lands on paper A after switching.
- Memory — 10 large PDFs is the ceiling; documented follow-up: LRU eviction
  of warm viewers below the 10-tab cap if it bites.
