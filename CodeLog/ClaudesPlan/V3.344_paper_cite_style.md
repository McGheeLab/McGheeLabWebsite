# V3.344 — Editor-side citation styling + narrative citations

**Part of:** [FuturePlan 07 — Paper builder upgrade](../Feature%20requests/FuturePlan_07_paper_builder_upgrade.md) (Release 4 of 7).

## Goal

Citation chips in the paper editor render the way the paper's selected
export template will typeset them — superscript ¹ (Nature/SLAS/ACS),
`[1]` (PLOS/IEEE/elsarticle/preprint), `(1)` (Science), or
`(Smith 2024)` author-year — with numbers in first-appearance order,
live-renumbering as citations move. Plus a **narrative citation** token
`[@*key]` ("Smith et al. (2024) showed…") that exports as the template's
`narrative_command` (`\citet`).

## What shipped

- **New `rm/js/paper-cite-style.js`** — `window.PaperCiteStyle`:
  `init(paperId)` reads `paperExports/{paperId}.templateId` and fetches
  the template (static file via `PaperExportTex.fetchTemplate`), caching
  `citation.render_family`; `getNumber(key)` assigns first-appearance
  numbers by a doc-order walk of the Yjs tree (bodies, skeleton bullets,
  figure/table captions), cached and invalidated on
  `paper-panel-changed`. Non-blocking: until it loads, chips render the
  legacy Author-Year labels. Loaded in `paper-builder.html` after
  `paper-export-tex.js`; `paper-editor.js` boot calls `init()`.
- **`renderCitationChip`** (paper-editor.js) — family-aware labels:
  numeric families show the live number per key, join with ", ", and
  wrap the group (`[…]` / `(…)` / raised via
  `.pe-cite-family-superscript`); author-year wraps in parens. The
  existing chip-invalidation listener re-renders bodies containing `[@`
  so numbers stay current.
- **Narrative token `[@*key]`** — single key only. Written by a new
  "Narrative" checkbox in the citation popover footer (insert AND
  chip-edit flows; chips stamp `data-cite-narrative` so editing
  restores the checkbox). Renders as `Author (Year)` inline. Both
  tokenizer validation regexes accept the leading `*`;
  `getCitedKeysInPaper` and export-side `collectCitationKeys` strip it.
- **Export** (`paper-export-tex.js`) — the citation pass moved BEFORE
  the markdown passes (protected-fragment mechanism): the narrative
  `*` would otherwise pair with a later asterisk in the italic pass.
  `[@*key]` emits `template.citation.narrative_command` (falls back to
  the plain command in numeric styles).

## Verification

Headless: export mapping (`[@*smith2024]` → `\citet` in author-year /
`\cite` in numeric, italic in the same sentence untouched, keys
collected without `*`); PaperCiteStyle numbering (first-appearance
across paragraphs + table captions, `*` stripped, dirty-flag
recompute on panel-changed). Syntax-checked all four edited files.
Browser pass (chips + popover checkbox) pending local server review.
