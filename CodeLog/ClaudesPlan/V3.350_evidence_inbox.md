# V3.350 — Evidence Inbox + live #ann- deep links

**Part of:** [FuturePlan 09 — Builder ↔ library ↔ reader bridge](../Feature%20requests/FuturePlan_12_builder_library_bridge.md) (Release 1 of 3).

## Goal

Close the reader→builder loop. The reader lets a student flag any
highlight "Cite in draft X" (`annotation.cite_in_drafts`) and tag
highlights as claim evidence — but the builder never read either signal.
Now the References tab opens with **"Reading evidence for this draft"**:
every flagged highlight, grouped by paper, with quote/comment/stance/type,
one-click Insert-citation, and an Open-highlight deep link that actually
lands on the highlight.

## What shipped

- **New `rm/js/paper-evidence-inbox.js`** (`window.PaperEvidenceInbox`).
  Fan-out set = papers linked to this draft ∪ already cited ∪ referenced
  by claims evidence. Per paper, TWO one-shot Firestore queries mirroring
  ANNOTATION_SYNC's split (the annotations read rule only *proves*
  `visibility=='lab'` or own-uid, so a bare array-contains query fails
  for non-admins): lab-visible + own-private, both filtered
  `cite_in_drafts array-contains draftId`. Claims evidence
  `{paperId, annId}` (via new `PaperBulletClaims.getAllClaims()`) fetched
  by id, rules rejections silently skipped. Dedupe by `paperId|annId`.
  **No firestore.rules change; no live subscriptions** (tab-open load,
  5-min staleness, ↻ button, debounced `paper-citations-loaded`).
  Rows dim (`--used`) once the paper's key is cited.
- **References tab** (`paper-equations.js` `_buildPanel`): the inbox is
  the first section, so the tab reads evidence-to-use → cited → linked →
  bibliography. `_refreshReferencesSection` delegates rendering.
- **`#ann-{annId}` deep links live** (`library-paper.js`): the hash is
  captured at boot keyed to the deep-linked paper; on each
  ANNOTATION_SYNC onChange, when the target annotation arrives →
  `ANNOTATION_OVERLAY.focus(annId)` (gotoPage + focused ring; 250 ms
  second nudge for lazy page renders), then cleared. This also makes the
  pre-existing claims-panel and bullet-claims evidence pills land.

## Index contingency

The two queries are single-collection `==` + `array-contains` — expected
to be served without a composite index. If the console throws
`failed-precondition`, add to `firestore.indexes.json`: annotations
`(visibility ASC, cite_in_drafts CONTAINS)` and `(creator.uid ASC,
visibility ASC, cite_in_drafts CONTAINS)`, then
`firebase deploy --only firestore:indexes`.
