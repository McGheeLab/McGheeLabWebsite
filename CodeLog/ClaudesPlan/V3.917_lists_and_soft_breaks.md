# V3.917 — Lists inside paragraphs and hard-wrapped text in journal looks

**Reported (Alex, 2026-10-25, screenshot of the live ME3B paper in a two-column look):** "the top right and bottom
left have text that is overlaying on existing text".

## What the screenshot showed

1. **Section 2.4's requirement list** (a lead-in sentence, then "- item" lines in the same paragraph): items drawn over
   each other, continuation lines prefixed "- •".
2. **Words glued together** mid-line: "theME3B", "compatiblecondenser-turret", "workingdistance", "therequired".

## Causes (reproduced in the Paper Lab, `_examples/listtest`)

1. A list block rendered correctly; a paragraph body with list lines did not. `renderParagraphBodyHtml` puts a `<ul>`
   inside the `<p>`, and under a look `_typesetParagraphs` lays the whole `<p>` out as one Knuth–Plass paragraph. Line
   cuts (`Range.cloneContents`) through `<ul><li>` cloned a list per line; the hyphen added at a hyphenated break sat
   outside the clone ("- •").
2. A single `\n` inside a paragraph (hard-wrapped text from an import) rendered as `<br>`. The typesetter turned the
   `<br>` into a forced break, and `breakLines` ended the pass at ANY forced break — in a test paragraph the text after
   the first `<br>` vanished; where the break fell at a line end, the space was simply gone. LaTeX reads a single
   newline as a space, so the PDF was right.

## Fix

- `_buildBlockNode` (paragraph): with `PaperSchemas.bodyHasList`, one page item per run — prose (typeset), list
  (`.pdv-list-block`, `_listItemsHtml`), prose after a list continues without indent. The caller pushes `node.more`.
- `softBreaks`: single newlines → spaces in the page view (blank lines and list lines untouched).
- `breakLines`: only the paragraph's last item ends the pass; a mid-paragraph forced break is a line end.
- Typesetter whitespace class gains U+2028, U+2029, U+000B, U+0085.

No corpus paper has paragraph lists or forced breaks; regression run p8 compares previews with the p7 compiles.

- List items (`.pdv-list-block li` without a nested list) join the typesetter: justified and broken like `itemize`.

## Not done

An item that holds a nested list is still laid out by the browser.
