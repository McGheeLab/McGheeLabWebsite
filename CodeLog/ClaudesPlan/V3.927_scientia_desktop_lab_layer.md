# V3.927 — Scientia: the desktop app runs the lab layer

## Goal

Gabe relaunched the desktop app from this repo's `scientia/` and found no Lit reviews tab, pills or Quick cast, and none of
the RM-backed features the website's Scientia has. They live in `rm/scientia/lab-mode.js`, which returned at once unless
the build was the web target. He asked for all of them on the desktop: the Lit reviews tab, the pills / Quick cast / PDF
cards on demand, and the RM-backed data (inventory, tasks, assigned work, share) through the lab hub.

## Approach

- `lab-mode.js` (V3.927): the guard now accepts the desktop target. `on(name)` is always true on the web, so every
  section behaves as before there; on the desktop only the sections the build lists in `window.SIS_LAB_SECTIONS` run.
  The effectful statements of the other sections carry `if (on('…'))` (a function declared inside the `if` would be
  block-scoped in strict mode, so only the statements are guarded). RM links are absolute (`https://mcgheelab.com/rm/…`)
  on the desktop; the host-page bridge already falls back when there is no host (RM pages open in a new tab).
- `scripts/scientia_build.py`: the desktop file is Gabe's `build.py` output plus the target flag, `DESKTOP_LAB` and
  `lab-mode.js` inline (a literal `</script>` in it is escaped). The web file still derives from the plain build.
- `scientia/serve.py`: `/api/rm/*` is forwarded to the lab hub as this computer's sync key (the one `scientia-cloud.py`
  saves in `cloud.json` next to the config) and only for requests from this computer; `/api/lab/status` says whether
  a key is saved. The key never reaches the browser. Without a key the proxy answers `{ok: false, offline: true}`.

## Sections on the desktop

On: portfolio (10), pills and Quick cast (11), lit reviews (13), share (15), inventory (5), tasks (6), reminders (7),
RM cards (8), protocols (9). Off: tab row and pointer pages (1-2), library and reader (3-4: his own, with groups), recorder
(12: his own, with Whisper), PDF cards on demand (14: his `13zk-docs.js` already does it), install banner, equations read
from a PDF (16: needs a Firebase sign-in for another function; on the desktop the person types the equation).

## Key decisions

- One lab layer, two targets, not a copy for the desktop: the policy is one of everything.
- Data that RM mirrors into the record (library rows, assigned projects) already reaches the desktop through the
  bridge; the proxy only serves the live calls (inventory, tasks, members, protocols, collections, annotations, sync).
- Not done: the recorder to the cloud, equation OCR from a PDF, and replacing Gabe's Library or reader.
