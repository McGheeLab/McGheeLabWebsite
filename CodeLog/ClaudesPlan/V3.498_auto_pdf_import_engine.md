# V3.498–V3.500 — Auto-import PDFs when Unpaywall's direct fetch fails

## Problem

Unpaywall's client-side auto-fetch fails often because most publisher/repository
domains **CORS-block** the browser from downloading the PDF bytes, and the
same-origin policy means the RM page can't "open the DOI tab and capture the
PDF" either. The user wants more automatic ways to pull PDFs — for many papers
at once — and, where OA truly doesn't exist, a route to grab papers behind the
lab's UArizona subscription.

## The hard constraint (why "open tab + auto-capture" can't be client-side)

A page cannot read another origin's tab (same-origin policy) — the exact wall
that CORS-blocks `_fetchPdfBlob`. So the fix must move the fetch **off the page**:
to a server (no CORS) or into the user's own logged-in browser context (a
bookmarklet running *on* the publisher page).

## Chosen approach (user decisions)

- **OA engine:** plain **server-side fetch first**, **Cloud Run headless
  fallback** second.
- **Paywalled papers:** a **bookmarklet** the user clicks on the publisher page.

## Phase 1 — `fetchPaperPdf` Cloud Function (V3.498)   ← this release

A v2 `onRequest` function, same shape/auth/CORS as
[functions/library-lookup.js](../../functions/library-lookup.js) (Bearer ID
token → `users/{uid}.role != 'guest'`). Body:
`{ paperId, doi?, pmid?, arxiv_id?, url?, candidateUrl? }`.

Tries candidate PDF URLs **in priority order**, deduped, each fetched
server-side with a browser UA + redirect-follow + `%PDF` magic validation +
size guard, behind an **SSRF guard** (`http(s)` only; blocks
localhost/private/metadata hosts):

1. `candidateUrl` (client's Unpaywall best, if any)
2. **arXiv** — `arxiv.org/pdf/{id}.pdf`
3. **Unpaywall** — *all* `oa_locations[].url_for_pdf` (not just best)
4. **Europe PMC / PMC** — `fullTextPDF` endpoint + `fullTextUrlList` pdf links
5. **Semantic Scholar** — `openAccessPdf.url`
6. **Landing-page scrape** — fetch the DOI HTML, extract
   `<meta name="citation_pdf_url">` (Highwire/Google-Scholar standard) +
   `<link type="application/pdf">`

First hit → sha256 → upload to `papers/{paperId}/{short}.pdf` via Admin SDK
(bypasses Storage rules) → return
`{ ok, storage_path, hash, full_hash, size_bytes, source, source_url }`.
Miss → `{ ok:false, error, tried:[{url,source,reason}] }`.

Client: `LIBRARY_UPLOAD.serverFetchPdf(item)` POSTs to the function and returns
the pdfInfo (same shape `uploadPdf` returns, so existing stamp/attach code
consumes it). Wire it into the existing PDF-getters, replacing the CORS-limited
client Unpaywall path (fall back to client Unpaywall only if the function is
unreachable):
- `library.js` `_retryPdf` → button relabeled "Auto-fetch PDF"
- `library-paper.js` `_renderNoPdfActions` retry button
- `library-refresh.js` `fullRefresh` step 3
- `library-upload.js` `fromDoi` attach path (V3.497)

**Bulk runner** — new `library-fetch-pdfs.js`: a progress-modal sweep (mirrors
[library-recheck.js](../../rm/js/library-recheck.js)) over every PDF-less entry
with an identifier, calling `serverFetchPdf` per paper (polite spacing), stamping
+ `_saveOne` on success, logging misses with their candidate URLs. Entry point:
a "🔎 Fetch missing PDFs" button in the library toolbar / missing-PDF view.

Deploy: FTP + `firebase deploy --only functions:fetchPaperPdf`. sw 470→471.
No rules/indexes changes (Admin SDK bypasses Storage rules).

Files: NEW `functions/fetch-paper-pdf.js`, NEW `rm/js/library-fetch-pdfs.js`;
edit `functions/index.js`, `rm/js/library-upload.js`, `rm/js/library.js`,
`rm/js/library-paper.js`, `rm/js/library-refresh.js`, `rm/pages/library.html`,
`rm/pages/library-paper.html`, sw.js, CHANGELOG, ARCHITECTURE.

## Phase 2 — Bookmarklet grabber + `uploadPaperPdf` function (V3.499)

For papers with **no** OA copy (paywalled). The bookmarklet runs on the
publisher page (its origin), so it can fetch the PDF bytes without CORS using the
user's subscription. Auth bridge: RM mints a **per-user upload token**
(`uploadTokens/{token} → {uid, created, label}`), embedded in the generated
bookmarklet. On the publisher page the bookmarklet:
1. finds the PDF (`citation_pdf_url` meta, or the current page if it *is* a PDF),
2. fetches the bytes (same-origin), reads `citation_doi`/`citation_title` meta,
3. POSTs `{token, pdf(base64/blob), doi, title, ...}` to `uploadPaperPdf`.

`uploadPaperPdf` (v2 onRequest): validates the token → uid, runs the same
identity match server-side (`findExistingEntry` port) → attaches to the matching
PDF-less entry or drops it into a per-user "capture inbox" for assignment.
Generator UI: a small "🔖 PDF grabber" panel in the library that renders the
draggable bookmarklet + a token rotate/revoke control. Rules: new
`uploadTokens` collection (Admin-SDK-only). Deploy: FTP + functions + one
`firestore:rules`.

## Phase 3 — Cloud Run headless fallback (V3.500)

When `fetchPaperPdf` returns `{ok:false}`, the client calls a Cloud Run endpoint
that loads the DOI page in headless Chrome (Puppeteer), runs page JS, finds +
downloads the PDF, uploads to Storage, and returns the same pdfInfo shape.
Scaffold: `functions/paper-pdf-fetch/` (Dockerfile + Express + Puppeteer) +
`paperPdfFetchProxy` function; client `serverFetchPdf` gains a
`{ok:false} → headless` fallback behind a capability flag. **Deploy gate:**
Alex's `gcloud run deploy` (like the paper-compile service) — code ships dormant
until then. Still can't beat paywalls (that's Phase 2's job).

## Cross-cutting decisions

- **Politeness / cost:** per-source timeouts (20 s); bulk runner spaces requests;
  Unpaywall/S2 called with a mailto UA. `fetchPaperPdf` memory 512 MiB, 120 s.
- **SSRF:** every outbound URL passes `_safeUrl` (http/https only, no
  localhost/private/metadata). Only role≠guest users can call it.
- **No paywalled scraping server-side** — the function only fetches OA URLs and
  the publisher's own advertised `citation_pdf_url`; institutional-only content
  is exclusively the Phase-2 bookmarklet's job (user's own access).
- **Idempotent:** `papers/{id}/{hash}.pdf` is content-addressed, so retries and
  re-runs don't re-bill or duplicate blobs.
