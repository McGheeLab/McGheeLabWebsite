**Date:** 2026-10-22 · **Builds on:** V3.821 · **Backend:** none · **Site files:** none · **Extension:** McGhee Lab
Capture 0.3.1 → **0.4.0** (new permission `downloads`, new content script `pdf-links.js`)

> many papers are now difficult to capture the pdf. somewhere on the journal page is a download pdf button. we can use

## 1. Why the worker fails where the button works

MDPI (and Wiley, Elsevier, T&F behind Akamai/Cloudflare) answer the extension's background worker with 403 "Access
Denied" — curl and a headless browser get the same wall. The worker's `fetch` does not look like the person's click:
no page origin, no Referer (`Sec-Fetch-Site: none`). The E2E server log shows exactly that pair of requests: the
worker's (`site: none, referer: ""` → 403) and the page's (`site: same-origin, referer: …/journal` → PDF).

## 2. The ladder (`capture.js` `obtainPdf`, DOM-free, strategies injected)

1. **direct** — `_fetchPdf` on `citation_pdf_url`, then up to two more routes found on the page.
2. **page** — `pdf-links.js` `__mcgheeFetchPdf(url)` injected into the tab: `fetch` with the page's origin, cookies
   and Referer, `%PDF-` magic check (walls answer 200 + HTML), bytes returned base64 (executeScript awaits the
   promise). Up to two routes.
3. **download** — `pdf-fetch.js` `browserDownloader()`: `chrome.downloads.download({ url, saveAs:false,
   conflictAction:'uniquify' })`, poll `downloads.search` to `complete` (120 s), refuse non-PDF mime (removeFile +
   erase), read back with `fetch(file://…)` → `{ blob }`; without file access → `{ needsFileAccess, filename, path }`.
4. **unpaywall** — as before, then direct on its URL.

Order rationale: the download has a visible side effect (a file in Downloads — what Alex asked for), so it comes
after the two silent routes; Unpaywall last because it may be a preprint. A download that landed but cannot be read
is reported last as `error.code = 'needs-file-access'` with the filename, only once Unpaywall also failed.

Routes on the page: `pdf-links.js` `__mcgheePdfLinks()` — `citation_pdf_url` 100, `<link type=application/pdf>` 90,
embedded `.pdf` viewer 80, anchors scored by href (`.pdf` 60; `/pdf/`, `epdf`, `/download/`, `pdfft`, `article-pdf`
50) + `download` attr 15 + text ("download … pdf" 25, "pdf" 10, "download"/"full text" 5), floor 20; supplements,
permissions, citation exports, figures sunk by −60; cross-origin −10; dedupe by URL, six at most.

## 3. Wiring

- `background.js` `capture`: `candidates = pdfLinksOnTab(tabId)`, `strategies = { page: pageFetcher(tabId),
  download: browserDownloader() }`; the catch maps `needs-file-access` → `{ ok:false, needsFileAccess, filename,
  path, tried }`. `get-detection` adds `pdf_candidates` (top 3) when a DOI page has no `citation_pdf_url`, so Capture
  is enabled. New `pdf-probe` (diagnostic: candidates + what each route returns, nothing uploaded) and
  `open-extension-details` (`chrome://extensions/?id=…`, where "Allow access to file URLs" lives).
- `popup.js`: `hasPdf` counts `pdf_candidates`; "PDF link" row; `_renderCaptureFailure` — needs-file-access block
  (Open extension settings · Upload file…, Manual options unfolded) or the first line as status with the attempts
  under "What was tried"; `_sourceLine` puts `pdf_source` in words. `manifest.json`: `downloads`, `pdf-links.js`
  first in `content_scripts`, 0.4.0.
- A pasted URL (`pdfUrlOverride`) skips the page's links and Unpaywall but still climbs direct → page → download.
