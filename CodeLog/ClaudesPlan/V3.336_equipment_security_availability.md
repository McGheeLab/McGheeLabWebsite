# V3.336 — Equipment Scheduler: security hardening + availability enforcement

**Phase 1 of the FuturePlan 08 equipment-scheduler upgrade**
(`CodeLog/Feature requests/FuturePlan_08_equipment_scheduler.md`).

## Goal

Make booking data trustworthy and make devices' posted hours/days real:

1. `firestore.rules` allowed ANY signed-in user to create/update ANY
   `equipmentBookings` doc with no field validation — every booking
   policy (ownership, status machine, duration, training) lived only in
   client JS and was console-bypassable.
2. `availableHours` / `availableDays` were saved on each device but never
   enforced anywhere; `availableDays` was hardcoded `[1,2,3,4,5]` on
   every device save with no admin UI.

## Approach

### firestore.rules — diff-constrained clauses per client mutation

Replaced the wide-open `equipmentBookings` block with one OR'd clause per
verified client write path in `rm/js/equipment.js`, each constrained by
`request.resource.data.diff(resource.data).affectedKeys().hasOnly([...])`
(`EDB.updateBooking` always stamps `updatedAt`, so every list includes
it):

| Clause | Actor | Mutation |
|---|---|---|
| create | self (`uid == auth.uid`) | shape-validated; status `confirmed`\|`pending-approval`; `maintenance` priority admin-only |
| owner edit | booking owner | reschedule fields only, status untouched |
| owner cancel | booking owner | `status → cancelled` only |
| owner re-confirm | booking owner | `needs-rebooking → confirmed`, clears `displacedBy` |
| **displacement** | ANY lab member | active booking `→ needs-rebooking`, must sign `displacedBy = auth.uid`, nothing else |
| approve/deny | equipment manager (`managers[]` on the equipment doc) | `pending-approval → confirmed`\|`cancelled` |
| gcal stamp | owner or manager | `gcalEventId` only (admin syncAll covered by the isAdmin arm) |
| admin | admin | full edit |

The displacement clause is the deliberate carve-out preserving the lab's
displacement model: anyone can book over an occupied slot (client shows
the "I have permission" checkbox), but the displaced-booking write can
change nothing except the status flip and the honest `displacedBy`
signature — which the FCM notification trigger depends on.

Sibling collections (`equipment`, `equipmentTraining`,
`equipmentSettings`) read-tightened from `request.auth != null` to
`isLabMember() && collabMay('<coll>')`. This drops `role:'guest'` users
(correct per RM policy); collaborators keep access via the existing
page-collections mapping.

**Deliberately NOT rule-enforced:** durationMin vs maxDurationMin,
availability windows, and overlap/conflict detection — these need
equipment-doc reads plus arithmetic beyond practical rules. The threat
model is "students gaming the UI," not console attackers forging times;
rules guarantee identity, status-machine integrity, and field isolation,
and the client remains the policy layer.

### Client — availability enforcement (`rm/js/equipment.js`)

- New helpers next to the permission checks: `availabilityRestrictions`
  (normalizes a device's window; null = unrestricted),
  `availabilityLabel` ("Mon–Fri, 8 AM–6 PM"), `checkAvailability`
  (booking-range validation; admin/manager bypass for maintenance and
  supervised after-hours), `isSlotClosed` (per-30-min-slot test for the
  grid).
- Submit handler enforces the window after the min-duration check, both
  create and edit paths; error names the window.
- Booking modal shows a live `#eq-bk-avail-msg` line (posted window;
  turns warning-colored when the current selection violates it),
  refreshed on equipment/date/time change.
- Week view greys closed slots (`eq-wk-cell--closed`, striped) when a
  device filter is active; drag-to-book can't start in or extend into
  closed cells (admins/managers bypass). Month view tints fully-closed
  days (`eq-month-cell--closed`).
- Device admin modal gains 7 weekday checkboxes (`.eq-dev-day`);
  the hardcoded `availableDays: [1,2,3,4,5]` is replaced by the
  selection. Zero boxes checked saves as all 7 days (no accidental
  bricking).
- `showToast` now delegates to the shared `TOAST.success`
  (`rm/js/toast.js`, already loaded by equipment.html); local fallback
  + `.eq-toast` CSS kept as safety net.

### Indexes

`firestore.indexes.json`: added `equipmentBookings (status ASC, date
ASC)` composite — required by the admin Sync All query
(`.where('status','==',...).where('date','>=',...)`), previously missing
from the file.

## Key decisions

- **Displacement model preserved** (user decision) — enforced narrowly in
  rules rather than removed.
- **Manager/admin bypass availability windows** — someone has to be able
  to book maintenance blocks and supervised after-hours sessions.
- **Multi-day bookings on an hours-restricted device are refused** for
  non-privileged users — an overnight run is by definition outside posted
  hours.
- **ScheduleUtils dedup deferred to Phase 2** — touches the whole
  calendar renderer; doesn't belong in a security release.

## Deploy notes

- `firebase deploy --only firestore:rules` and
  `firebase deploy --only firestore:indexes` from repo root; FTP the
  static tree as usual.
- **Deploy-day pass:** every existing device doc carries `[1,2,3,4,5]`
  from the old hardcode — enforcement makes that live and blocks all
  weekend bookings. Re-save each device intended as 7-day with the new
  day picker.
- Stale-SW clients are safe: no write payload shapes changed, only who
  may send them; every old-client write matches a carve-out.

## Residual holes (accepted, documented)

- Owner can console-edit `durationMin` past `maxDurationMin`
  (client-only policing).
- Conflict check remains read-then-write (non-transactional); the
  displacement model makes a lost race socially recoverable.
- GCal token stays in sessionStorage until Phase 5.
