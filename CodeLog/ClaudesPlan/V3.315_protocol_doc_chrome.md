# V3.315 — Protocol builder: document chrome (FuturePlan 03, Release 1)

## Goal

First release of the FuturePlan 03 widget-parity roadmap: give the
Protocols Builder the document chrome of the gold-standard interactive
protocol — stage headings, generalized callouts, a branded document
header, inline vocabulary (pills / code / sub / sup), and a read-only
**document view** with print-to-PDF export.

## Decisions (closing FuturePlan 03's open questions)

1. **note/safety → callout migration**: grep confirmed only the protocol
   modules themselves (schemas templates, blocks renderers, importer
   summary counters) touch raw `kind:'note'|'safety'` — no external
   consumer. Chosen approach: **render-level folding**. `note` and
   `safety` stay legal kinds in `PROTOCOL_BLOCK_KINDS`; the dispatcher
   routes all three kinds through the one callout renderer with a type
   mapping (`note/info|tip → note`, `safety → critical`). Changing the
   type select rewrites that block to `kind:'callout'` (an explicit
   edit); stored docs are never bulk-rewritten. The "+ add block" menu
   offers `callout` instead of note/safety.
2. **docHeader is a block, not tree.meta**: a block is visible and
   position-controllable in the editor with zero new sidebar UI, and it
   dehydrates/hydrates through the existing block pipeline. Brand text
   falls back to `labConfig/branding` (`{name, sub}`) when the block's
   own brand field is empty — reading that doc is best-effort (it
   doesn't exist yet; FuturePlan 05 will author it).

## New block kinds

| kind | body | attrs |
|---|---|---|
| `heading` | stage title (Y.Text) | `{code: '01', rule: true}` |
| `callout` | text (Y.Text, var/inv tokens ok) | `{type: 'critical'\|'note'\|'assume'\|'timing'}` |
| `docHeader` | subtitle (Y.Text) | `{brand, title, chips: [{text, var}]}` (chips is a plain JSON array value) |

`chips[].var` optionally names a symbol-table variable; the doc view
renders the live value next to the chip text.

## Inline vocabulary (prose grammar)

Extends the existing `[!var:name]` / `[!inv:id]` token family, rendered
on blur / in doc view, raw while editing:

- `[!pill:functional:some text]` → styled tag span; `functional` /
  `inert` get the gold standard's colors, unknown pill kinds get a
  neutral style.
- `` `code` `` → `<code class="proto-code">`
- `~text~` → subscript, `^text^` → superscript (applied to plain
  segments only, never inside tokens).

Implementation: `ProtocolFormulas.renderProse(raw)` becomes the single
prose renderer (tokens + inline markup, single pass, HTML-escaped
outside matches). `protocol-blocks.js`'s `bindYTextWithVars` and the new
doc view both call it — the old private `renderBothTokens` merge in
protocol-blocks.js is deleted.

## Document view + print

- Route: `pages/protocols.html?protocol=<id>&view=doc` — third mode
  next to `list`/`editor` in the mode bootstrap script.
- New `rm/js/protocol-doc.js`: loads `protocols/{id}` (one Firestore
  read — renders the **projected JSON tree**, no Yjs), same
  signed-in + lab-member gate as the editor, builds the symbol table
  with mathjs (plain-tree walker + existing `buildSymbolTable`).
  Formula inputs render as live number fields — editing recomputes
  locally (nothing is written), so the doc view is already a working
  calculator ahead of Release 3.
- Section labels render as numbered stage headers (`01 · Setup`);
  `heading` blocks render their own `code · title` rule inside a
  section.
- New `rm/css/protocol-doc.css`: gold-standard look (860px column,
  branded header band, stage rules, color-coded callouts, timing pill)
  + `@media print` (toolbar hidden, page margins, no shadows) so
  browser print-to-PDF is the export.
- Toolbar: doc view gets a fixed `🖨 Print / PDF` button; the editor
  topbar gets a `📄 Doc view` link.
