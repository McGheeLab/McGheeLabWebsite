# V3.515 — User-selected cheat-sheet contents (point-of-use, per user + protocol)

## Goal

V3.503 shipped the protocol cheat sheet with a **hardcoded keep-set**. Make the
contents **user-chosen at the point of use** instead: category pills + a per-line
tri-state override, decided in the lab-notebook run (and the standalone
`?view=cheat` page), persisted **per (user, protocol)** and reused across runs.

## Decisions (confirmed with user)

- **Scope/persistence:** per (user, protocol) — `userData/{uid}/protocolCheatPrefs/{protocolId}`.
- **Category pills:** Materials / Safety / Figures & maps / Timing. Steps + stage
  headings are structural and always on.
- **Per-line:** tri-state override — Default (follow category) / Force-include /
  Force-exclude.
- **Defaults:** steps always; figures/maps + timing on; materials + safety off
  (== the old V3.503 keep-set, so behavior is unchanged until customized).

## Data model

`userData/{uid}/protocolCheatPrefs/{protocolId}` (owner-only via the
`userData/{userId}/{document=**}` rule — **no rules/route/functions change**):

```
{ categories: {materials,safety,figures,timing}, overrides: {blockId:'in'|'out'}, updated_at }
```

`categoryOf(block)`: step/heading→steps; materials→materials; figure/layoutMap→
figures; timeline + callout:timing→timing; callout:critical + legacy safety→
safety; everything else→other (off unless override 'in').
`resolveKeep(block,prefs)`: override wins; else steps→in, other→out, else the
category pill.

## Files changed

- **`rm/js/protocol-cheat-render.js`** — replaced the hardcoded keep-set with the
  selection model. Added `DEFAULT_PREFS`/`defaultPrefs`, `normalizePrefs`,
  `categoryOf`, `resolveKeep` (+ `keepBlock` back-compat alias);
  `renderSectionsInto(container, tree, ctx, opts)` now takes `opts.prefs`
  (default = old keep-set, so the existing 3-arg call is unchanged);
  new `renderChecklistInto` (per-line tri-state checklist), `buildConfigBar`
  (pills + Customize/Reset), and `loadPrefs`/`savePrefs` (direct firebridge ref,
  debounced) — shared by both surfaces.
- **`rm/js/lab-notebook.js`** — cheat branch of `_renderProtocolDocInto` loads
  prefs into a module `_cheatState` (async, cached per protocol id; never saved
  onto the run doc), renders the config bar + view/checklist, and persists on
  toggle via `savePrefs`. New `_protocolHasSteps` relaxes the Document/Cheat
  toggle gating (offered for any protocol with steps, not just authored-cheat
  ones) at both the live and frozen render paths.
- **`rm/js/protocol-cheat.js`** — standalone page loads prefs in `boot()` and
  renders the same config bar + view/checklist, persisting on toggle. Both
  surfaces share the one per-user+protocol selection.
- **`rm/css/protocol-cheat.css`** — `.prc-configbar` / `.prc-pill` (+`.on`) /
  `.prc-customize-btn` / `.prc-reset`, the checklist rows (`.prc-check-row`,
  category-colored `.prc-check-tag`, `.prc-check-preview`), and `@media print`
  now hides the config UI + never prints `.is-excluded` rows.
- **`sw.js`** — CACHE_VERSION bump (shared counter; 488 at time of writing).
- Docs: this plan, CHANGELOG, ARCHITECTURE.

## Key decisions

- **Extend the shared module, don't fork.** One `ProtocolCheatRender` drives the
  notebook run and the standalone page identically; both read/write the same
  prefs doc, so a change on either surface is reflected on the other.
- **Selection ≠ run state.** Prefs are per (user, protocol), so they are NOT
  written to the notebook run doc (`scheduleSave`); they live in their own
  owner-only doc and are loaded lazily.
- **Back-compatible default.** `DEFAULT_PREFS` reproduces the V3.503 keep-set, so
  a first-time viewer (no saved prefs) sees exactly today's sheet.

## Deploy

**FTP-only** + service-worker bump. No Firestore rules/indexes/routes/functions.

## Verification

Static + unit (done): `node --check` on all edited JS; a sandbox harness over the
real module asserts `categoryOf`, `resolveKeep` (defaults / category toggles /
tri-state overrides), and `normalizePrefs` junk-rejection (45/45). Browser E2E
(manual, needs Firebase sign-in):
1. Notebook run → 📋 Cheat sheet (toggle shows even without authored cheat lines).
   Default = steps + figures/maps + timing.
2. Toggle Materials on / Timing off → sheet updates; reopen a second run of the
   same protocol → choices restored (per user+protocol).
3. Customize → force-include a note/materials row, force-exclude a step; Done →
   sheet reflects both; persists across reload; ↺ Reset restores defaults.
4. Standalone `?view=cheat` shows the same saved selection; changes there appear
   in the notebook run.
5. 🖨 → config bar + checkboxes gone, only included lines print.
6. `[!var:]` values still resolve. `?view=doc` / editor unchanged; a no-prefs user
   sees the old default sheet.
