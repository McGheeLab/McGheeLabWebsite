# V3.454 — doc view: Spacing and Fill presets now visibly do something

> Test feedback on Paper Builder III (fix 2 of 7): "spacing (tight vs loose) and Fill
> (tight vs loose) don't do anything."

## Root cause (scope, not wiring)

Both controls were correctly wired (write config → persist → forceRender). But:

- **Spacing** (`paperExports.floatSpacing`) was only read by `baseGapPx()`/`gapForFloat()`
  — consumed exclusively by BANDED floats (anchor top/bottom/float-page). The default
  figure/table anchor is `'flow'`, so on a typical paper nothing consulted the preset,
  and paragraph rhythm never did.
- **Fill** (`paperExports.columnFill`) was read at exactly one spot — `_splitColItem`'s
  entry guard — as a 1-vs-2-vs-3-line break threshold at column feet. Real but visually
  nil.

## Fix (rm/js/paper-doc-view.js + rm/css/paper-doc-view.css)

**Spacing → whole-preview vertical rhythm.**
- New `GAP_SCALE {tight:.7, normal:1, loose:1.6}` (matches the 7/10/16px float presets)
  + `_applySpacingScale()`: sets `--pdv-gapscale` on the overlay AND the measurement
  probe; called in the render path right before `_measureItems`.
- CSS: the flow-rhythm margins multiply by `var(--pdv-gapscale, 1)` via `calc()` —
  `.pdv-para`, `.pdv-keywords`, `.pdv-heading`, `.pdv-subheading`, `.pdv-list-block`,
  `.pdv-abstract`, `.pdv-figure`, `.pdv-table-wrap`, `.pdv-eq`, `.pdv-titleblock`.
  Because `measureBatch` reads computed margins from the probe, pagination follows the
  new density automatically — no packer change needed. `normal` = ×1 → untouched papers
  render pixel-identical. (Body paragraphs keep `margin: 0` + indent by design; the
  visible effect is heading/figure/table/equation/abstract gaps.)
- Float bands keep `baseGapPx()`/`gapForFloat()`; the existing export mapping
  (`\textfloatsep` presets) is untouched.

**Fill → real dynamic range.**
- `COLUMN_FILL_LINES.loose` 3 → **4** (needs 4 free lines at a column foot before a
  paragraph may break there).
- New widow rule in `_splitColItem`: in `loose`, if the carried-over tail would be a
  single line (< 1.9 × lineH), don't split — move the whole paragraph. tight/normal
  keep any real tail (filling the foot is their point).
- Both selects' tooltips updated to state their actual scope (Spacing: preview density +
  PDF float separation; Fill: preview-only, 4-line loose threshold + no stranded lines).

## Harness

`test-packer.js`: the `'loose' → 3 lines` expectation updated to 4 (deliberate widening).
