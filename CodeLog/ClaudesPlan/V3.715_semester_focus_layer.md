# V3.715 — Semester Focus layer: Team Focus goes semester-first

## Goal

Team Focus was purely weekly (V3.536 loop, weekId-keyed focusAreas).
Alex: redesign it around a **semester focus** that connects to a
**research focus** — each student holds MULTIPLE semester foci per
admin-set semester, each linkable to a researchFoci CARD, negotiated
through the same proposed → mentee_edited → confirmed → reported loop
(plus an end-of-semester outcome report). In My Week, the semester foci
appear in the 🎯 weekly-focus dropdown; picking one creates/reuses a
weekly focus nested under it, and Team Focus shows those weeklies as a
running list under each semester focus.

## Decisions (locked with Alex, 2026-09-01)

1. Semester foci LAYER ABOVE the weekly loop (weekly keeps working;
   attribution happens via My Week and via the Team Focus week view).
2. Semesters are ADMIN-SET date ranges, not auto-computed — with a
   computed UA-term fallback (pmr.js math) so the page works before an
   admin seeds dates.
3. Semester alignment is CARD-level only (`focus_ref` without
   analysis keys) — the analysis level stays a weekly concern, which
   also keeps the roadmapClaims mirror entirely out of the semester path.
4. Same sign-off workflow at semester granularity.

## Data model

**Semester focus** — same `userData/{uid}/focusAreas` collection,
discriminated by **omitting `weekId` entirely** (docs missing the field
can never match `listForWeek`'s equality or `listForRange`'s range
filter, so every weekly consumer — My Week, PMR focus_review + health,
research-progress, project-health, Month tab — is structurally blind to
them with ZERO guards):

```
{ id: 'sf-…', horizon: 'semester', semesterId: 'sem-fall-2026',
  …same title/description/status/source/report/tasks/paper_refs…,
  focus_ref: null | { id, title, level } }        // card-level only
```

**Weekly focus** gains `semester_focus_id: null | 'sf-…'`. One-shot
inheritance on attribution: a weekly with no `focus_ref` inherits the
semester focus's card-level ref (never overwrites, never claims).
Deleting a semester focus leaves attributed weeklies dangling → they
render in the "Unattributed" group (accepted; documented in the
focus-areas.js header).

**Semester calendar** — `labConfig/semesters` single doc
(`{ semesters: [{id, label, start, end}], updated_at, updated_by }`)
through new route `settings/semesters.json`. Existing labConfig rule
(auth read / admin write) covers it.

**No Firestore deploy**: no rules change (focusAreas rule at
firestore.rules:3031 and labConfig rule at :2009 already cover both),
and the new queries are single-field equalities (no composite index).
