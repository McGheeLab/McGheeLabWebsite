# V3.110 — Protocols Builder MVP

## Goal

Add a protocols.io-style "Protocols Builder" page to the RM dashboard so
lab members can author, browse, and edit reusable lab protocols inside RM
instead of as scattered `.md` / `.docx` files in
[Data/protocols/](../../Data/protocols/).

This is **Phase 1 of 5** (see `~/.claude/plans/we-want-to-make-idempotent-pixel.md`
for the full roadmap). Phase 1 ships a working list+editor with five block
kinds. Formulas, inventory linking, lab-notebook/paper cross-linking,
versioning, and public publish are all reserved for later phases — the
schema is laid out so those can land without a migration.

## User-locked decisions (2026-05-08)

- **Formula engine:** mathjs now, Pyodide later. Phase 1 has no formula
  block; the closed list of block kinds reserves room for `formula` and
  `python` so adding them later is additive only.
- **Visibility:** lab-shared with opt-in public publish. Phase 1 only uses
  the lab-shared half — the rule branch for `status == 'published'` is
  added now so Phase 5 doesn't need a rules migration.
- **Scope:** Phase 1 MVP only. No formulas, no integrations.

## Approach

### New files

- `rm/pages/protocols.html` — dual-mode shell cloned from
  [paper-builder.html](../../rm/pages/paper-builder.html); `?protocol=<id>`
  activates the editor.
- `rm/js/protocol-schemas.js` — closed vocabularies + tree builders.
  Mirrors [paper-schemas.js](../../rm/js/paper-schemas.js)'s public surface.
- `rm/js/protocols.js` — list-mode controller (load + render cards, "+ New"
  modal with template picker).
- `rm/js/protocol-editor.js` — editor controller (title input, block list,
  add-block menu, save state, Yjs hookup).
- `rm/js/protocol-blocks.js` — per-kind renderers
  (`renderStep`, `renderMaterials`, `renderNote`, `renderFigure`,
  `renderSafety`).
- `rm/js/protocol-yjs.js` — Yjs ↔ Firestore provider for
  `protocols/{id}/yjs_*`. Clone of [paper-yjs.js](../../rm/js/paper-yjs.js)
  with the collection swapped. (A follow-on cleanup phase will dedupe by
  parameterizing paper-yjs.)
- `rm/js/protocol-figures.js` — Storage uploader for `protocol-figures/{id}/`.
  Clone of [paper-figures.js](../../rm/js/paper-figures.js) with the path
  prefix swapped.
- `rm/css/protocol-editor.css` — imports `paper-editor.css` for the
  shared chrome (status pills, save-state, layout) and adds protocol-only
  rules (materials table, safety callout, step number badge).

### Modified files

- `rm/js/api-routes.js` — register `protocols/list.json` →
  `{scope:'lab', collection:'protocols', wrapKey:'protocols', cache:MEDIUM}`.
  No `shadowJson` (new collection, no legacy JSON file).
- `rm/js/nav.js` — add nav entry under Research, after Lab Notebook.
- `rm/js/dashboard.js` — add "Recent protocols" summary card.
- `firestore.rules` — add `match /protocols/{protocolId}` block (lab-member
  read OR `status==published` public read; owner/admin write) plus the
  `yjs_snapshot`, `yjs_updates`, `presence` subcollection rules mirroring
  the paper rules.
- `firestore.indexes.json` — add two composite indexes for the standard
  list queries.
- `storage.rules` — add `protocol-figures/{protocolId}/{...}` path mirroring
  the existing `paper-figures` block.
- `sw.js` — bump `CACHE_VERSION` per
  `feedback_version_control` memory.
- `CodeLog/Updates/CHANGELOG.md` — `Added` entry.
- `CodeLog/Architecture/ARCHITECTURE.md` — document the new collection +
  page.

### Block kinds (closed list, Phase 1)

| Kind | Body | Notable attrs |
|---|---|---|
| `materials` | structured `attrs.rows`, no Y.Text body | `rows: [{qty, unit, free_text, item_ref?}]` |
| `step` | Y.Text rich text | `step_number` (auto via render) |
| `note` | Y.Text | `flavor: 'info' \| 'tip'` |
| `figure` | Y.Text caption | `image_url`, `image_alt`, `width_pct`, `storage_path` |
| `safety` | Y.Text | `severity: 'caution' \| 'warning' \| 'danger'` |

The closed list reserves `formula` (Phase 2) and `python` (later) but
doesn't render them. `normalizeTree` coerces unknown kinds to `step` so a
future-version doc still loads.

### Document shape (`protocols/{id}`)

```js
{
  id, title, ownerUid, authorUids: [uid],
  status: 'draft',                  // | 'published' | 'archived'
  category, tags: [], summary,
  tree: { meta: {}, sections: [{id, label, order, children:[block]}] },
  created_at, updated_at,
  schema_version: 1,
  // Reserved-but-unused in Phase 1:
  current_version: 1,               // Phase 5 (versioning)
  published_at: null,               // Phase 5
  symbol_table_cache: {},           // Phase 2 (formulas)
  inventory_refs: [],               // Phase 3
  linked_buckets: [],               // Phase 4
}
```

## Key decisions

1. **Clone, don't refactor, paper-yjs.js + paper-figures.js.** They
   hardcode `papers/` in 3+ places. A parameterization touches the
   shipping paper builder; cloning isolates risk to the new files.
   Documented as tech debt for a follow-on phase.
2. **Editor is leaner than paper-editor.js.** Skip claims, equations,
   citations, comments pane, view filters, status filters — none of those
   apply to protocols. Just title + block list + add-block menu + Yjs.
   ~600 lines vs. paper-editor's 2664.
3. **Materials block is structured, not free-text.** Rows have explicit
   {qty, unit, free_text} fields so Phase 3 can light up `item_ref`
   inventory linking without a data migration.
4. **The `huddleProtocols` collection is unrelated.** That's an existing
   collection for a different feature (group huddle protocols). The new
   collection is plain `protocols`.

Hand-port [Data/protocols/Agarose LLS -Sieves.md](../../Data/protocols/Agarose%20LLS%20-Sieves.md)
into a real protocol document via the new UI. Every step renders, every
