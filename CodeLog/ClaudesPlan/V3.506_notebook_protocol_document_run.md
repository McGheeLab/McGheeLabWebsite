# V3.506 — Lab notebook: load a protocol as its real output document (live + finalizable)

> Numbered V3.506 (not 504) due to concurrent-session version collisions —
> V3.503/504/505 were claimed by parallel sessions while this was in flight;
> re-checked CHANGELOG head + sw.js right before release.

## Goal

When a lab-notebook entry pulls in a protocol (📋 Protocol → click a row,
the "full" action), it currently renders through
`_renderProtocolTreeHtml` / `_renderProtocolBlockHtml` as bare
`<p>` / `<blockquote>` / `<ul>` markup — "a bunch of text with embedded
links." The user wants the inserted protocol to **look and feel like the
protocol output document** (`protocols.html?...&view=doc`) *and* to be
**live + "used"**: interactive widgets work, and a **Finalize** button
locks the values used into the entry as an immutable record.

Decisions (from the user):

1. **Live interactive mount** (not a static snapshot), reusing the
   existing FuturePlan-06 protocol-run machinery
   (`state.doc.protocol_run` mounted outside the sanitized body in
   `#ln-protocol-run`).
2. **Finalize button** freezes the run — the values used are locked for
   that entry (the existing `freezeProtocolRun` snapshot, surfaced as a
   first-class button rather than only firing on entry End-run).
3. **Replace** the full-insert (the picker's three actions stay: full /
   ref only / 🧮 calc — only "full" changes behavior).
4. **Cheat-sheet awareness** — if the protocol's steps carry the V3.503
   per-step `attrs.cheat` one-liner, offer a **📋 Cheat sheet** view
   toggle alongside the **📄 Document** view.

   > **Correction during implementation:** I first assumed no `?view=cheat`
   > renderer existed and hand-rolled a condensed `<ol class="ln-cheat-list">`.
   > On closer inspection V3.503 had already shipped a full cheat-sheet page
   > (`?protocol=<id>&view=cheat`, `rm/js/protocol-cheat.js` +
   > `rm/css/protocol-cheat.css`) with a real keep-set + `condenseStepText`.
   > To avoid two divergent cheat renderers I **extracted that logic into a
   > shared `window.ProtocolCheatRender` module** (`protocol-cheat-render.js`)
   > and made BOTH the cheat page and the notebook consume it — so the
   > notebook cheat sheet is byte-for-byte the same render as the page. The
   > hand-rolled `ln-cheat-list` / `_cheatTextOf` path was removed.

## Key insight

`window.ProtocolDocRender.renderBlock(block, ctx, opts)` — the single
renderer the real output document uses — already renders the full
document look (masthead-less; steps/callouts/materials/figures/tables/kv/
timeline) **and** mounts the live interactive widgets
(formula/calculator/builder/layoutMap/design) via `ProtocolWidgets` off
the same `ctx`. So "mount the protocol as its output document, live"
= build a `ProtocolWidgets` context whose `overrides` are
`run.inputs`, then render every block through `ProtocolDocRender` into a
`.prd-doc` card inside `#ln-protocol-run`. The `.prd-doc` /
`.prd-masthead` CSS (protocol-doc.css, already lazy-loaded by
`_ensureProtocolRunDeps`) styles it as the same white document card,
masthead clipped to rounded corners.

The frozen/finalized render reuses the identical path with
`readOnly: true` + `overrides = snapshot.inputs`, so the locked document
renders with values substituted and every input disabled.

## Key decisions

- **Single protocol-run slot per entry** (unchanged). The picker's "full"
  action loads into that slot; if a *different* protocol is already
  loaded, confirm before replacing.
- **No protocol-side schema change.** Cheat lines are read from the
  existing `attrs.cheat`; cheat view falls back to the step body's first
  line when blank (matches the V3.503 comment's stated fallback).
- **Frozen = immutable.** Reopen explicitly clears `frozen` and re-mounts;
  the snapshot is retained until values change, so an accidental reopen
  is recoverable.
- **Materials Used panel** still auto-populates via the appended
  inventory chips, exactly as the old full-insert did.
