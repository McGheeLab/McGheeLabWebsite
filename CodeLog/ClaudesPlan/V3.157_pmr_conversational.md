# V3.157 — PMR: Conversational Project Review

## Goal

Turn PMR (Project Management Report) at `rm/js/pmr.js` from a one-way student
worksheet into the canonical 1:1 conversation surface between admin (PI) and
student. Compose primitives that already exist elsewhere in the codebase
(threaded comments from paper-builder, cross-user task assignment from
task-assign.js, figure uploads from paper-figures.js) instead of building from
scratch.

## What's new

1. **Threaded comment helper** — new `rm/js/section-comments.js` extracts the
   comment-thread pattern from `paper-editor.js:1901-2047`. Generic over
   `(rootPath, scopeKey)`, used by every PMR block.
2. **Barriers block** — first-class section with status lifecycle
   (open → discussing → resolved), rich-text description (contentEditable +
   sanitize), optional figure attachments via `PAPER_FIGURES`, threaded
   discussion, and "+ Assign task" button.
3. **Paper-writing block** — surfaces drafts where the student is in
   `authorUids` and `is_library_entry != true`. Each row shows title, status
   pill, link to paper-builder, comment thread, and "+ Assign task" button.
4. **Comment threads on every existing block** — Project overview, Open
   tasks, Weekly entries, Discussion all gain a "💬 N" toggle that mounts an
   inline thread.
5. **"+ Assign task" wiring** — `task-assign.js` accepts new optional
   `source`, `pmrPeriodId`, `pmrSectionId`, `pmrTargetId` fields. Tasks
   created from PMR carry these so the back-link chip can render.
6. **Admin cross-user view** — replace the `renderUnsupportedAdminView`
   placeholder with a real read of `userData/{otherUid}/pmr/...` via direct
   `firebridge.db()` calls (the existing per-route adapter is hard-coded to
   the signed-in uid; PMR does its own scoped reads when viewing another
   user). Admin can read + comment + assign tasks but cannot edit weekly
   entries / project overview / barriers (matches scope decision).

## Data model

```
userData/{studentUid}/pmr/{periodId}                  (existing — fields added)
  + barriers: [{
      id, title, description_html, status, created_at, resolved_at,
      figures: [{storage_path, hash, mime, ...}], linked_task_ids: []
    }]
  + paper_writing: [{
      id, paper_id, status_note          // cached; canonical status from papers/{id}
    }]

userData/{studentUid}/pmr/{periodId}/comments/{commentId}   (NEW)
  fields: section_id ('barriers'|'paper_writing'|'project_overview'|...),
          target_id (e.g. barrier id or weekly_entry id, optional),
          body, authorUid, authorName, parentId, createdAt, modifiedAt, resolved
```

## Cross-user permission summary

| Action                             | Owner | Admin (other user) |
|---|---|---|
| Read PMR doc                       | ✓ | ✓ (existing rule) |
| Edit PMR sections                  | ✓ | ✗ (skipped per scope) |
| Read comments                      | ✓ | ✓ |
| Post comments                      | ✓ | ✓ |
| Edit / delete own comments         | ✓ | ✓ (admin can delete any) |
| Assign tasks to owner              | n/a | ✓ |
