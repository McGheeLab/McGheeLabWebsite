## 2. The two data models (what the mappings in Phases 1 and 3 rest on)

**Scientia (one record per person, stores in `02-schema.js`)**
- `library` rows: `{id, doi, cslType, title, authors:[{family, given}], container, publisher, year, volume, issue, page,
  issn, url, isPreprint, csl, pdf: <media id>}`; the PDF is `images/<mediaId>.pdf` in the notebook folder (media row
  `{id, kind:'pdf', ext, name, size, path}`).
- a **highlight** = a block on the paper's *literature note* (`READER.litDoc(lib)`): `{docId, label:'p. N', body:{text,
  marks}, anchor:{type:'TextQuoteSelector', source: libId, page, exact, prefix, suffix, rects:[[x, y, w, h]…] as
  FRACTIONS of the page box, color}}`; with a kind it is also an `items` structure (claim / evidence / question …) with
  `sourceRef:{type:'library', id, page, selector}`. Colours `yellow · green · blue · pink · orange`.
- `materials` (13j/13r): resources as notes of type `resource` (kind, lot, passage, concentration, supplier, location).
- tasks (23-tasks): a task is a block (`kind:'task'`: done, due, priority, repeat, subtasks) wired to components; dated
  tasks show in Reminders. `reminders` store: deadlines/meetings. `sessions`: timer segments. `flags`/`reviews`: the
  weekly review. Activity (19-activity): a heat-map derived in memory from sessions + blocks.
- `datasets` (13i): folder handles (File System Access, localhost only) — desktop-only by nature.

**RM**
- library: `items/{id}` `{type:'paper', title, meta:{library:{is_library_entry, doi, pmid, arxiv_id, authors, year,
  journal, volume, issue, url, citation_key, tags, themes, references, linked_drafts, pdf:{storage_path, hash,
  filename_safe, size_bytes, uploaded_at, uploaded_by}, pdf_status, pdf_candidate_url}}}`; the PDF in Storage.
- highlights: `papers/{paperId}/annotations/{id}` (`paperId` = the item id) `{type:'Annotation',
  motivation:'highlighting', visibility, color_id, annotation_type (colour IS the category: yellow note · green
  evidence · red limitation · blue method · purple question · orange quote), comment, target:{pages:[{page,
  selectors:{textQuote:{exact, prefix, suffix}, textPosition:{start, end}}, rects:[{x, y, width, height}] in page-wrap
  CSS px, saved_scale}]}, creator, created, modified, cite_in_drafts, evidence_for_claim_ids, evidence_stance,
  marked_for_investigation}`.
- inventory: `inventory/items.json` + chemicals; tasks: `userData/{uid}/tasks` + buckets (`tasks` collection);
  activity: `trackerEntries` + `ActivitySignals.recordWork`; My Week: `dayPlans`; protocols: `protocols`.

## 5. Phase 3 — the desktop pulls from RM (library both ways, highlights compatible)

The desktop stays Gabe's app. Through the existing bridge (`scientia-cloud.py`, a device of both hubs) plus two new
hub routes, the desktop gets RM's library and gives back its own:

1. **RM → desktop (papers)**: the Phase 1 mirror puts RM library rows into `hub/rows` `library__<itemId>`; sync carries
   them to the desktop `library` store unchanged. New route `api/rm/library/pdf?id=<itemId>` streams the PDF from
   Storage; the bridge downloads it into the notebook folder as `images/<mediaId>.pdf` and sets `lib.pdf` (one media
   row per paper, hash-checked, ≤ the function's 32 MB) so "Read" works offline.
2. **desktop → RM (papers)**: a `library` row created on the desktop (DOI / BibTeX / RIS paste) with no RM id is pushed
   by the bridge to `api/rm/library/import` (DOI → RM's `libraryLookup` import path, else CSL-JSON → a new `items`
   doc with `meta.library`), its PDF uploaded through `uploadPaperPdf`'s receiver; the hub rewrites the row's id to
   the RM id and the bridge updates every cite mark (ids live in block `marks`).
3. **Highlights, both ways** — the mapping:
   - page: same. text: `anchor.exact/prefix/suffix` ↔ `selectors.textQuote` (RM's `textPosition` is optional).
   - rects: Scientia fractions of the page box ↔ RM CSS px at `saved_scale`. Convert with the page size:
     px = fraction × (pagePt × k × saved_scale) where k is the viewer's px-per-pt (**verify in `rm/js/pdf-viewer.js`
     before building: pdf.js `scale` 1 = 1 pt = 1 px unless `PixelsPerInch` is applied**); the bridge reads pagePt
     with `pypdf`. Scientia can also re-anchor by text when rects are missing (`17b-reader.js` line 98), so RM →
     desktop may send text-only when the conversion is in doubt.
   - colour / category: yellow↔yellow (note), green↔green (evidence), blue↔blue (method), orange↔orange (quote),
     pink↔red (critique); RM purple (investigate) → Scientia pink with `marked_for_investigation` kept on the RM side
     (lossy; or Gabe adds purple to `READER.COLORS` — DECISION).
   - structure: a Scientia claim/evidence made from a highlight ↔ RM `annotation_type` evidence + `evidence_for_claim_ids`
     (RM claims = `claims.js`); barriers/questions ↔ `annotation_type` question.
   - identity: one `annotations/{id}` per Scientia highlight block; the block keeps `anchor.rmId`; the annotation keeps
     `scientia_block_id`. Last writer wins per field through the hub's merge; deletes propagate.
   Stored where RM already reads: `papers/{itemId}/annotations` (so the RM reader, comments feed and figure boards see
   desktop highlights with no change). The hub writes them from the bridge (`api/rm/annotations`), and a trigger on
   `papers/*/annotations` writes the matching Scientia block into `hub/rows` for sync down.
4. **Materials / tasks / activity on the desktop** read the same mirrors (inventory → `hub/rows` `inventory__<id>`,
   read-only on the desktop; task done-state through the hub).
