# V3.528 — My Day R3: notebook stub + protocol link + full cascade + retry

Part of the **My Day program** — see `V3.526_my_day_program.md`.

## Goal
Work/equipment plans create a plan-phase Lab Notebook entry so results
have a home; picking a protocol mounts it as a live `protocol_run`.
Failed distributions become tappable ⚠ retry chips.

## Approach
- **notebook adapter** in `rm/js/day-distribute.js`: entry doc
  `userData/{uid}/notebook/{itemId}` built with `notebookEmptyEntry()`
  (notebook-schemas.js), `phase:'plan'`, project/protocol from the
  composer; `protocol_run` seeded with the FuturePlan-06 shape when a
  protocol is chosen. `_index` rows upsert inside a **transaction** so an
  open lab-notebook session can't be clobbered.
- **The orphan rule** (program decision 5): `hasUserContent(entry)` =
  body_text ∥ observations ∥ summary ∥ attachments ∥ protocol_run inputs
  ∥ plan content. Once true, cascade updates stop following (the entry
  became the real record) and cascade delete keeps the entry, prepending
  a `nb-orphan-note` paragraph instead.
- **my-day.html** loads `notebook-schemas.js`; composer gains the
  protocol picker (`protocols/list.json`, same source as the notebook's
  own picker). Item cards render per-surface status chips:
  ✓ created / ⚠ failed→retry / 🔗 orphaned / ◌ excluded.

## Deploy
FTP only.

## Verify
- Equipment item with protocol → notebook rail shows the plan-phase entry
  with the protocol run mounted (open via the 📓 chip).
- Edit the item title before touching the entry → entry title follows.
- Type an observation, then edit the item → entry stops following.
- Delete: pristine stub → entry + index row gone; entry with content →
  kept with the orphan note, chip flips 🔗.
- Kill network mid-distribute → ⚠ chip → retry succeeds without dupes.
