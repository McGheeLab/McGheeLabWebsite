# V3.881 — Procurement: load receipts and requisition printouts, kept for a later read into the inventory

**Date:** 2026-10-23
**Request (Alex):** *"on the procurement page, we need a way for the person doing the procurement to load in the receipt
or requisition printout to the site, later we can collect these and use them to auto injest the items into the
inventory."*

## What was there

Procurement v2 (V3.813) could carry two files per request, each tucked inside one transition:
- the **Order** form's *PO / confirmation* file → `procurement/{ticketId}/po-…`, `t.poUrl` / `t.poStoragePath`;
- the **Receive** form's *Receipt / packing slip* → `procurement/{ticketId}/receipt-…`, `t.receiptUrl`.

So a file could only be added at that one moment, on that one request (an order on one PO covering five requests got
the file on one of them), never afterwards, and nothing collected them. A requisition printout had no place at all.

## What this adds

**A `procurementDocs` collection: one document per uploaded file**, the single place a later step reads from.

```
procurementDocs/{docId}
  kind            receipt | requisition | invoice | packing_slip | po | quote | other
  fileName, contentType, size, storagePath ('procurement/docs/{docId}/{file}'), url
  ticketIds[]     the requests it covers (0..50)
  poNumber, vendor, docDate (YYYY-MM-DD), note
  source          upload (Receipts tab or a request's Attach) | order | receive
  uploadedBy, uploadedByName, uploadedAt, updatedAt
  ingestStatus    'pending' — until the later step reads it into the inventory
  ingestedAt, ingestedItemIds[], ingestNote   (for that step; nothing writes them yet)
```

Files go to Storage at `procurement/docs/{docId}/{name}`, already covered by `storage.rules`
`match /procurement/{docId}/{allPaths=**}` (signed in, PDF or image, < 20 MB). **No Storage rules change.**

### Where people use it

1. **A Receipts tab** (purchasers `procurement:order`, approvers `procurement:approve`, admins): drop or pick one or
   many files (PDF or photo; on a phone the picker offers the camera), say what they are, optionally the PO #, vendor,
   date and which requests they cover (a search over approved / ordered / arrived requests and anything put away in the
   last 60 days; choosing a request fills the PO # and vendor when blank), and a note. Below, every document, newest
   first: kind, file (opens it), date, vendor, PO, the requests (links), who uploaded it, and *Not yet in inventory*.
   Search across all of it; a document can be edited (kind, PO, vendor, date, requests, note) or deleted by its
   uploader or an admin, with an in-page "Delete? Yes / No", never a browser dialog. The V3.813 per-request PO and
   receipt files show in the same list, marked as attached to a request, so this one list is everything there is.
2. **On a request's card:** a *Documents* list (everyone who can see the request sees its files) and, for purchasers /
   approvers at approved → put away, **Attach receipt / requisition**: an inline form (kind, files, note) that links
   the files to this request and, ticked by default, to the other requests on the same order (same `orderGroupId` or
   PO #).
3. **The Order and Receive forms** now file their PO / receipt through the same path: the file lands at
   `procurement/docs/…`, gets a `procurementDocs` record linked to the request (and, for a batch order, every request
   on it), and still sets `t.poUrl` / `t.receiptUrl` as before. If the record cannot be written, the request keeps its
   file (as before) and a warning says so.

### Rules (`firestore.rules` `match /procurementDocs/{docId}`)

- read: any lab member (requests are readable by every lab member, and their PO / receipt links already were).
- create: a lab member writing `uploadedBy == self`, a known `kind`, `storagePath` under `procurement/docs/{docId}/`,
  `ticketIds` a list ≤ 50, `ingestStatus == 'pending'`; and either a purchaser / approver / admin, or the file covers at
  least one request (that is how the Receive form, open to any member, files its receipt).
- update: a purchaser / approver / admin, or the uploader; only `kind`, `ticketIds`, `poNumber`, `vendor`, `docDate`,
  `note`, `updatedAt` and the `ingest*` fields; identity, file and path frozen.
- delete: an admin, or the uploader.

Deployed **before** the page change, from the LIVE ruleset plus this block if the local file carries another session's
undeployed hunks ([[feedback_rules_deploy_foreign_hunks]]).
