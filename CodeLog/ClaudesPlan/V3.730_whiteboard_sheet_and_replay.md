# V3.730 / V3.731 — Whiteboard: continuous snap-sheet, then recorded lectures with synced replay

> Two releases, one plan. **R1 (V3.730)** turns the board's pages into one vertically
> stacked sheet that snaps page-to-page, adds the thumbnail rail, and turns pinch-zoom on
> for the drawer. **R2 (V3.731)** records the instructor's voice from the device that
> presses Go live and replays it with the ink, page snaps, erases and snapped figures
> exactly as the room saw them. R1 must ship first: the replay records the sheet.
>
> **STATUS 2026-09-03: BOTH BUILT.** R1 = V3.730 (sw 702), R2 = V3.731 (sw 703). Firestore rules
> DEPLOYED. FTP pending in the batch. Deviations from the text below: the MP3 (lamejs) fallback was
> NOT vendored — Chromium and Safari both record `audio/mp4` natively, so the fallback chain is
> mp4 → WebM/Opus, and playback falls back from blob-concat to MediaSource; local recorder actions
> (erase, add-page) log their events directly because the snapshot diff cannot see them; skew is
> sampled only from fresh, un-erased final flushes. Still owed: the real-browser fragmented-MP4
> playback check and a real lecture on device.
>
> Planned 2026-09-03 with Alex via /grill-then-plan. Builds on V3.677 (engine), V3.684
> (panel + viewer-local lens), V3.685 (student boards), V3.727 (outline ink).

## Goal

Alex teaches from a learning module on the projector with the iPad as the pen. After
class, a student opens the board from the class page and **replays the lecture**: the
audio plays and the board reproduces what the projector showed at every second — strokes
growing as they were written, the sheet snapping to a new page when Alex added one, the
erase that happened at 14:32, the figure snapped from the module. Before that can exist,
the board itself changes from separate pages to **one continuous sheet** of stacked
pages that snaps to whichever page is centred, with the neighbours peeking in above and
below and a thumbnail rail on the left for jumping.

## Problem

- Pages are discrete: flipping a page replaces the whole canvas, so there is no sense of
  where you are in the lecture, and the previous page's tail is out of sight.
- Pinch-zoom does nothing on the iPad's class-page board — `wireWhiteboardPage` mounts
  with `view:{enabled:false}` (V3.684 decision, "the page/projector never zooms"), and
  the module panel, where the lens *is* on, cannot mount on the live site today
  (root files half-deployed — see V3.727 ledger note).
- Nothing about a live session is kept except the ink that survives it. Erased strokes
  are hard-deleted; page flips, undo and clears are not timestamped; strokes have only a
  pen-down time (`seq`).

# R1 — Continuous snap-sheet (V3.730)

## Approach

### Geometry: the sheet is the pages, stacked

Nothing about stored data changes. A stroke keeps `pageId` and per-page coordinates
(x∈[0,1], y in board-width units, ~[0,0.625] for a 16:10 page). The renderer places page
`i` at a vertical offset

```
pageTop(i) = i * (BOARD_H + PAGE_GAP)        // PAGE_GAP ≈ 0.02 board widths, grey desk shows through
```

and paints every stroke at `(x, pageTop(page) + y)`. Because strokes may overhang
(decision 13), a point's `y` may be < 0 or > BOARD_H; it still renders relative to its own
page, so the sheet looks continuous no matter which page is centred. `exportBoardPNGs()`
clips to the page rect.

**Layout rule** (`sizeCanvases`): the page width `w` is the largest value such that
`1.5 × BOARD_H × w ≤ stageHeight` and `w ≤ stageWidth − railWidth`. The canvases cover
the whole stage (not just the page), so the quarter-neighbours are drawn on the same
bg/ink/live canvases. A new `S.sheet = { pageW, originY }` maps sheet coordinates →
canvas px; `originY` is the sheet y (board-width units) at the top of the stage.

**Centring**: `centreOn(pageIndex, animate)` sets the target `originY` so that page's
centre sits at the stage's vertical centre, and tweens `originY` there over ~260 ms
(rAF; `S.sheetAnim`). Every tween frame calls `redrawAll()` — it repaints bg + ink + live,
which V3.727 made cheap (one fill per stroke).

### Shared state stays `activePageId`

The thing that syncs is unchanged: the admin's centred page. `goto-page`, `add-page`,
thumbnail click and a settled two-finger scroll all end in `setActivePage(id)` → admin
writes `activePageId` on the board doc → viewers/projector `centreOn()` with animation.
The follow/"Follow live" chip logic is untouched. Intermediate scroll positions during a
drag are **not** synced (decision 12: snap, not free scroll).

### Input

- **Pen / mouse**: unchanged (`normPoint` gains the sheet transform: screen → sheet →
  `{pageId, x, y}` where `pageId` is the page whose rect contains the pen-down point,
  nearest page if in the gap; subsequent points of that stroke stay relative to that page).
- **Two-finger drag at scale 1**: scroll `originY` live (unsnapped, viewer-local while the
  fingers are down); on release, snap to the nearest page centre; if that page differs
  from `S.pageId` → `setActivePage`. Momentum is not needed; snapping reads as intent.
- **Pinch**: existing lens (`zoomAt`) — now enabled on the page route too (decision 14).
  While `scale > 1`, two-finger drag pans the lens (existing behaviour) rather than
  scrolling the sheet; `⌂` resets to scale 1 and re-centres on `S.pageId`.
- **Wheel / trackpad** on laptops: vertical wheel scrolls the sheet with the same
  snap-on-settle (150 ms quiet); pinch-gesture wheel (`ctrlKey`) zooms.
- **Single-finger touch**: still ignored everywhere in draw mode (palm rejection). For
  *viewers* (not admin), single-finger drag scrolls — they have no pen.
- **Keyboard**: PageUp/PageDown, ↑/↓ snap to the previous/next page.

### Thumbnail rail

`.wb-rail` — a column left of the stage, `railWidth` = 96 px desktop / 64 px tablet;
on phones (`max-width: 700px`) it collapses to the existing page dots under the board.
One `<canvas class="wb-thumb">` per page, rendered by the same `paintBackgroundInto` +
`paintStroke` at thumbnail width (throttled: re-render a page's thumb at most every 400 ms
after its strokes/items change, and only for pages whose thumb is visible in the rail).
Active page has a ring; the live page (when following) a red dot. `+ page` button at the
bottom. **Hidden on the projector** (chrome-free) and in the panel when narrower than
480 px (dots instead).

### Migration / compatibility

- Stored strokes are untouched. Strokes drawn under R1 that overhang a page render fine
  in R1; an old client (pre-FTP SW) would clip them at the page edge for a load or two —
  acceptable.
- `exportBoardPNGs` output per page is unchanged for non-overhanging ink.

- Projector mount: no rail, no lens, follows `activePageId` with the tween.

# R2 — Record & replay (V3.731)

## Approach

### Recording (the device that pressed Go live)

`live-toggle` (Go live) gains three steps before writing `liveWhiteboard`:

1. `navigator.mediaDevices.getUserMedia({ audio: { echoCancellation:true, noiseSuppression:true, autoGainControl:true } })`
   — inside the click handler (the permission gesture). Denied/unavailable → go live
   anyway, toast "Live without recording — microphone not available", no recording doc.
2. Create `recordings/{recId}` with `{ startedAt: serverTimestamp(), startedAtMs: Date.now(),
   status:'recording', recorderClientId, startPageId, mime, pages:[…snapshot of board.pages],
   name: '<board name> — <date>' }` and write `liveWhiteboard: { boardId, boardName, since,
   recId }` on the schedule doc. `recorderClientId` (sessionStorage id, per V3.596) marks
   *this tab* as the recorder; other admin tabs see `recId` and show "🎙 recording on another
   device".
3. Start the encoder (below) and the **event log**.

**Clock.** Every timed value is `Date.now() − rec.startedAtMs` in ms (`t`). The
recording device's clock is the reference; strokes written by the iPad carry the iPad's
`Date.now()`, so the recorder also stores `clockSkewMs` per contributing client —
computed from the first stroke doc it sees whose `seq` it can compare to its own receipt
time (`Date.now() − seq`, min over the first ten strokes ≈ skew + min latency). Applied
on replay. Practically the two devices are NTP-synced within tens of ms; this guards the
case where they are not.

**Encoder — auto-detected**
- `MediaRecorder.isTypeSupported('audio/mp4')` (Safari, Chrome ≥ 126 on macOS) →
  `new MediaRecorder(stream, { mimeType:'audio/mp4', audioBitsPerSecond: 64000 })`,
  `start(60000)` → one Blob per minute. Each `dataavailable` chunk uploads to
  `classes/{classId}/whiteboards/{boardId}/recordings/{recId}/chunk-{NNN}.m4a` and appends
  `{ n, path, bytes, tStart, durationMs }` to `rec.chunks` via `arrayUnion`.
  ⚠ MP4 chunks from `MediaRecorder.start(timeslice)` are **not independently playable**
  (the moov atom is only in the first chunk): playback concatenates them into one Blob
  (`new Blob(chunks)`) before handing it to `<audio>`. Verify this on Safari in the
  harness step below; if a browser's fragmented MP4 does not survive concatenation,
  fall back to the MP3 path for that browser.
- Otherwise → **MP3 via `lamejs`** (vendored, ~120 KB, `rm/vendor/lamejs.min.js` copied to
  `vendor/`): `AudioContext` + `AudioWorkletNode` (fallback `ScriptProcessorNode`) feeds
  PCM to a Worker running the encoder at 64 kbps mono; the worker posts a Blob every
  60 s of audio → same chunk upload, `.mp3`. MP3 chunks concatenate trivially.
- Both paths: `mime` recorded on the doc; total for a 75-min lecture ≈ 36 MB across ~75
  chunks, each far under the 50 MB Storage rule.

**Wake lock.** `navigator.wakeLock.request('screen')` while recording (Safari 16.4+,
Chrome). Re-request on `visibilitychange` → visible. If the page is hidden/suspended,
`MediaRecorder` pauses; on resume the gap is recorded as `{ type:'gap', t, durationMs }`
in events and the replay inserts silence of that length so ink stays aligned.

**Event log** — `recordings/{recId}/events/{autoId}`, one doc per event, batched every
2 s by the recorder (`writeBatch`; each doc `{ t, type, … }`):

| type | payload | source |
|---|---|---|
| `page` | `{ pageId }` | board doc `activePageId` change (the recorder observes it — works whichever device flipped) |
| `add-page` | `{ pageId, background }` | board doc `pages` grew |
| `erase` | `{ strokeIds:[…] }` | strokes listener: doc gained `erasedAt` |
| `clear` | `{ pageId, strokeIds:[…] }` | same, grouped when ≥ 5 erased in one snapshot |
| `item-add` / `item-move` / `item-remove` | `{ itemId, x, y, w }` | items listener |
| `gap` | `{ durationMs }` | recorder suspended |

Strokes need **no** event: they carry their own times (below). The recorder observes
everything through the same listeners every viewer already has, so the iPad needs no
knowledge that a recording is running.

**Strokes gain two fields** — written by whichever client draws (whiteboard.js
`flushStroke`): `t0` = pen-down `Date.now()` (equal to `seq` today) and `t1` = pen-up
`Date.now()` (final flush only). Replay uses `t0/t1 − startedAtMs + skew`.

**Soft-delete during a recording.** `eraseAt`, `undo`, `clear-page` currently `.delete()`
stroke docs. Under R2 they write `{ erasedAt: Date.now() }` instead **whenever
`S.live?.recId` is set** (i.e. a recording is running on this board); live views filter
`erasedAt` strokes out in `repaint()`, `eraseAt()`, thumbnails and exports. Outside a
recording the hard delete stays (keeps docs small for scratch boards). `strokeHit`/undo
stacks skip erased strokes.

**Ending.** `live-toggle` (End live) → `recorder.stop()` → final chunk upload → doc
`{ status:'ready', endedAtMs, durationMs, chunks }` → clear `liveWhiteboard`. **Auto-end**:
a 20-min timer reset by any stroke/page/item event; on expiry, same path + toast
"Recording ended after 20 minutes of no board activity" on the recorder. **Tab closed
mid-lecture**: `beforeunload` attempts the final flush; chunks already uploaded are kept;
a recording left in `status:'recording'` with no chunk for > 5 min is shown to admins as
"Interrupted — N min saved" with a **Finalize** button that sets `ready` from the chunks
present (no Cloud Function needed).

### Replay (students, class page)

**Entry**: the Whiteboard section on the class page lists, under each board, its
`ready` recordings: name, date, duration, "▶ Replay". Route
`#/classes/{classId}/whiteboard/{boardId}?replay={recId}` mounts the board in **replay
mode**: `mountBoardView(root, { replay: recId, view:{enabled:true}, items:{enabled:true} })`.

**Replay engine** (`whiteboard-replay.js`, new root file, ~500 lines — loaded by
`index.html` after `whiteboard.js`; keeps the engine file from growing past what it is):
1. Load the recording doc, all `events` (ordered by `t`), all strokes of the board
   (including `erasedAt` ones), all items. Fetch chunks in order and build one Blob →
   `URL.createObjectURL` → `<audio>`. Trim offsets (`trimStartMs`, `trimEndMs`) clamp
   the scrubber and start the audio at `trimStartMs`.
2. **Initial frame** = board as it was at `t = 0`: strokes with `t0 < start` and
   (`erasedAt` absent or `erasedAt > start`), items existing at start, `startPageId`
   centred.
3. On each `timeupdate`/rAF while playing, compute `t = audio.currentTime × 1000` and
   render the state at `t`:
   - stroke visible iff `t0 ≤ t` and (`!erasedAt || erasedAt > t`); if `t < t1`, draw the
     **prefix**: `fillStrokeOutline` on the first `k` points where `k` interpolates
     linearly along the stroke's arc length by `(t − t0)/(t1 − t0)` — V3.727's renderer
     takes any point prefix, so the stroke grows.
   - centred page = last `page`/`add-page` event with `t_evt ≤ t` (else `startPageId`);
     changes go through `centreOn(idx, animate=true)` so the sheet snaps like the room
     saw it; a scrub jump uses `animate=false`.
   - items at their last `item-*` state ≤ t.
   - the sheet layout is the **projector's** (no rail interaction; lens allowed, local).
4. Controls bar under the board: ▶/⏸, scrubber with page-change markers (from `page`
   events) and hover time, speed 1× / 1.5× / 2× (`audio.playbackRate`; the ink follows
   because everything derives from `audio.currentTime`), elapsed/total. Keyboard: space,
   ←/→ 5 s. Mobile: controls wrap; the board keeps the snap layout; the rail collapses to
   dots that follow the replay.

**Admin controls** (topbar, admins only, in replay mode): rename (inline form, no
prompt), delete (two-tap confirm: doc + events + chunks via Storage delete), **trim**:
"Set start here" / "Set end here" at the current scrubber time → `trimStartMs/trimEndMs`
on the doc; "Reset trim". Never re-encodes.

### Data model (R2)

```
schedules/{classId}/whiteboards/{boardId}/recordings/{recId}
  name, status: 'recording'|'ready', startedAt, startedAtMs, endedAtMs, durationMs,
  recorderClientId, startPageId, pages:[{id,background}], mime, chunks:[{n,path,bytes,tStart,durationMs}],
  clockSkewMs:{ [clientId]: ms }, trimStartMs, trimEndMs, createdBy
schedules/{classId}/whiteboards/{boardId}/recordings/{recId}/events/{eventId}
  t, type, …payload
schedules/{classId}/whiteboards/{boardId}/strokes/{strokeId}
  + t0, t1, erasedAt          (additive; old strokes lack them → treated as "before start")
schedules/{classId}  liveWhiteboard: { boardId, boardName, since, recId }
Storage: classes/{classId}/whiteboards/{boardId}/recordings/{recId}/chunk-NNN.(m4a|mp3)
```

**Rules** (`firestore.rules`, inside `match /whiteboards/{boardId}`, restating the gate in
full because rules do not cascade):
```
match /recordings/{recId} {
  allow read: if true;
  allow write: if wbClassAdmin(scheduleId);
  match /events/{eventId} {
    allow read: if true;
    allow write: if wbClassAdmin(scheduleId);
  }
}
```
Strokes/items rules unchanged (new fields are inside the same docs). `notesBoards` /
`hwBoards` get **no** recordings block — students' boards do not record (no Go live).
No composite index: events are read with a single-field `orderBy('t')`; recordings listed
with `orderBy('startedAtMs','desc')` — single-field.

**Storage**: the existing `classes/{classId}/**` rule (read all, signed-in write < 50 MB)
already covers chunks. As with items (V3.684), the access boundary is the recording doc,
not the bytes.

## Out of scope (both releases)

- Live audio streaming to students during the lecture (playback only).
- Per-point stroke timing; continuous free-scroll sync; synced zoom.
- Cloud transcoding, waveform display, chapter titles, transcripts/captions (a natural
  R3: send the audio to the `equationOcr`-style AI function for a transcript synced to
  page markers).
- Recording on `notesBoards` / `hwBoards`.
- Editing ink after the fact inside a recording (a later erase after `endedAtMs` hides
  the stroke live but the replay keeps it — correct, by design).

## Release ritual

- **R1**: FTP-only. `sw.js` bump. No Firebase deploy. Ship inside the current batch **only
  if** the root files finally go up together (see V3.727 ledger note) — R1 is useless
  without `whiteboard-board.css`.
- **R2**: `firebase deploy --only firestore:rules` **before** FTP (a client on the new
  code without the rules gets `permission-denied` on Go live and records nothing — the
  toast path covers it, but do the rules first). No indexes, no functions, Storage rules
  unchanged. `sw.js` bump; add `whiteboard-replay.js` and `vendor/lamejs.min.js` to the
  precache list.
- Both: one PENDING_RELEASE line each; `version_push.py` default minor bump.

## Rollback

- **R1**: git revert + re-FTP. Data is untouched, so old and new clients coexist; the
  only visible seam is overhanging ink clipping on the old client.
- **R2**: git revert + re-FTP. Rules blocks can stay (harmless). Strokes carry extra
  fields the old client ignores — **except `erasedAt`**: an old client would show
  soft-erased strokes again. If R2 must be rolled back, run a one-off admin sweep that
  hard-deletes strokes with `erasedAt` set (small script, `scripts/`), or accept it for
  the two loads until the SW catches up. Recordings and chunks can be deleted per
  recording from the admin control or left inert.
- No irreversible writes: chunks are append-only files; trims are offsets.

## Open questions

1. **Fragmented MP4 concatenation** from `MediaRecorder.start(60000)` — Safari produces
   a single moov in chunk 0 and `moof` fragments after; concatenating and playing via
   `<audio src=blob>` is expected to work but must be proven on real Safari + Chrome
   before choosing MP4 over MP3 for that browser. Fallback is already in the design.
2. **Clock skew** between iPad and recorder — the min-latency estimate is cheap; if it
   proves noisy, a second signal is the recorder's own receipt time of each stroke's
   *first* flush (300 ms cadence) as an upper bound on `t0`.
3. **Thumbnail rail cost** with many pages (20+) — per-page mini canvases are fine; if a
   board grows large, virtualise the rail (render only visible thumbs).
4. **Wheel + trackpad** snap timing (150 ms quiet) may feel sticky on Mac inertial
   scrolling — tune on the laptop.
5. Should the projector corner control also show a **recording timer**? Cheap; decide at
   build time with Alex.
6. `lamejs` vendoring — confirm licence (LGPL) is acceptable for the site; alternatively
   `mp3-mediarecorder` (MIT). Only matters if a browser lacks `audio/mp4`.
