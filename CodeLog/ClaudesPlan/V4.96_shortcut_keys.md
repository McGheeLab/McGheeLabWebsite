# V4.96 — rebind the keys a person really presses (Scientia, on V4.89)

## Why
Gabe, 20 Nov 2026: "Have the option for users to customize shortcut keys while on canvas or in lab notebook. Ones that are taken by the browser or another should be brought up and provide alternative of Alt+key the user wanted."

The key list (SHORT, V4.79) showed every key but only two could be changed (the structure and term keys, on their own Features pages). The other handlers tested their keys in place (`mod && k === 'k'`), so a person could not move one, and a person who wanted Ctrl+T or Ctrl+W (which the browser keeps) found out only by it not working.

## What changed
- **`src/20g-keymap.js` (new): `KEYS`.** One lookup, `KEYS.is(e, 'search')`: the person's binding (`settings().keymap = { actionId: 'Alt+K' }`, synced like the other settings) or the default. `structure` and `term` keep `settings().structKey` / `termKey`, so nothing set before moves. A combination is a string, `Ctrl+Shift+Z` (Cmd counts as Ctrl; letters by the physical key when Alt makes another character; named keys Enter, Esc, ArrowLeft, F5…).
- **Rebindable (19):** Search, command palette, quick switcher, capture to the day note, New note, Undo, Redo (and its second key Ctrl+Y), Focus mode, Back, Forward, the command bar `/`, `?`, New component `N`, the Move tool `P`, Fit `Ctrl+0`, Mark a moment (recording) `Alt+M`, the structure key, the term key. Handlers changed: `11-shell.js` (the document keydown), `99-boot.js` (`N`, Ctrl+0), `11c-navbar.js` (`/`, Alt+←/→), `13zzh-hands.js` (`P`), `13zn-rec.js` (mark), `09-editor.js` (`ED.matchKey` now reads through `KEYS.match`; `keyLabel` writes through `KEYS.label`). Hint texts that named a key (palette rows, the Fit menu row, the recorder's title) show the binding.
- **Conflicts: `KEYS.check(spec, id)`.** Refused, never silently accepted: a key another action of the app holds now; a fixed shortcut of the list (Bold, Italic, Copy, Esc, the tab digits…, read from `SHORT.items()` so a new one is covered); the browser (a table: new tab / window / private window, tab switching, address bar, history, downloads, reload, view source, developer tools, clear data, zoom, F-keys, Alt+F/E/D menus…); the computer (Alt+Tab, Alt+F4, Ctrl+Shift+Esc…); and a bare letter for an action that fires in text (needs Ctrl or Alt). Keys the app owns by default (Ctrl+P, Ctrl+O, Ctrl+K, Ctrl+0, Alt+←/→) are the browser's only when no action holds them. The offer is Alt+<same key>, then Alt+Shift+, Ctrl+Alt+, Ctrl+Alt+Shift+ — the first one that is free by the same rules.
- **The capture box** (`KEYS.box`, opened by Change in a row of the list, in Settings and in the ? dialog): press the new keys; Esc cancels; a free combination is taken at once; a refused one says why plainly with "Use Alt+T" as one click, Try another, Cancel. It listens on `window` in the capture phase (before the app's handlers) and focuses itself, so it works the same inside the Lab Notebook's iframe as on its own; Esc inside it does not close the ? dialog.
- **The list (SHORT):** a rebindable row (`act: id`) shows its binding, "default X", a "changed" mark (teal key and outline), Change and Reset; the ? dialog is the same view. Search finds "changed" and the default key too.
- **Settings → Features → Shortcuts:** two new tunes — "Let me change keys" (off: every key is its default, what was set is kept) and "Suggest Alt+key when a key is taken" (off: still refused, no offer). The preview shows a rebound row (a sample, Alt+N) and the box's answer for Ctrl+T (the browser) and Ctrl+K (another shortcut), with their Alt offers. Shortcuts off = defaults.
- Not rebindable here (said so): the keys of one view (calendar letters, the review's J K X, widgets, the Library), text editing (Ctrl+B, Alt+I, Ctrl+U, Ctrl+I), Esc, Enter, Delete, the tab digits. There is no timer key in the app to bind.
