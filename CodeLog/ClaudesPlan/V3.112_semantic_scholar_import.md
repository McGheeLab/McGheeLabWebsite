# V3.112 — Import-time Semantic Scholar enrichment

## Goal

Reported:
> *"we should use this api to also gather all the needed information
> about the papers we are importing, all of the references attached to
> the paper, in addition to the cited by. This should be done on
> import."*

V3.111 added a Cited-by panel that hits Semantic Scholar live on every
paper-reader open. This change extends the integration to **import
time**: a single SS call after each new paper is saved fetches the
full enrichment payload (references + citations + abstract + tldr)
and persists it onto the item, so the reader pages don't need to
refetch every time.

User-confirmed defaults:

1. **Augment, not replace.** CrossRef stays primary for the
   bibliographic basics (title / authors / journal / year); SS runs
   in parallel and adds structured `references[]` (with per-ref
   DOIs), `cited_by[]`, abstract (when CrossRef missed it), tldr.
2. **Background after save.** Item appears in the library
   immediately with CrossRef metadata; SS enrichment lands ~1–3s
   later as a non-blocking write — same pattern V3.93 already uses
   for `parseAndCacheRefs`.
3. **Prefer SS references over the regex parser.** SS gives clean
   structured refs with per-ref DOIs, so `+ Add to library` works for
   *every* reference the panel surfaces. The PDF-text-layer regex
   parser (V3.93) stays as the fallback when SS doesn't have the
   paper or returns no references.
4. **Backfill is out of scope.** Old library items don't get an
   automatic SS sync; they fall through to the live API on next open
   (cited-by panel) or stay on regex-parsed refs (citations panel).
   A "Refresh metadata" button or a one-time admin migration can
   handle backfill in a later change.
5. **Cited-by persists** to `meta.library.cited_by` (V3.111 was
   in-memory only) — no extra API call on subsequent paper-reader
   opens.

## Approach

### New shared module — `rm/js/paper-semantic-scholar.js`

Single wrapper around the SS Graph API used by all callers (import,
paper-cited-by panel, future refresh tools).

Exposes:

- `PAPER_SS.lookupId(lib)` — picks `DOI` → `arXiv` → `PMID` from
  `meta.library`. Returns `{ kind, value, url }` or `null`.
- `PAPER_SS.fetchPaperEnrichment(idSpec)` — fires
  `GET /paper/{ID}?fields=title,authors,year,venue,abstract,
  externalIds,tldr,references.*,citations.*` and returns the full
  payload.
- `PAPER_SS.fetchCitations(idSpec, limit)` — citations-only fetch
  (used by the cited-by panel when no cache exists).
- `PAPER_SS.normalizeReferences(ssRefs)` — maps SS reference shape
  to the V3.93 regex-parser shape (`{ n, raw, title, firstAuthor,
  year, doi, arxiv, journal, source: 'semantic_scholar' }`) so
  paper-citations.js's panel doesn't need to branch.
- `PAPER_SS.normalizeCitations(ssCitations)` — flattens the
  `{ citingPaper: {...} }` envelopes the `/citations` endpoint
  returns into the same flat object shape the persisted `cited_by`
  cache uses, so `paper-cited-by.js`'s `_renderRow` doesn't branch.

Includes one retry on 429 with a 1.5s backoff before surfacing the
error (free-tier rate limit is ~1 req/sec, so background imports of
multi-paper batches can hit it).

### `library-upload.js` — `enrichItemFromSemanticScholar(paperId)`

New best-effort helper that:

1. Loads `items.json`, finds the item by id, picks an SS lookup id.
2. Fires `PAPER_SS.fetchPaperEnrichment`.
3. Re-loads `items.json` (so concurrent edits aren't stomped) and
   writes onto `meta.library`:
   - `semantic_scholar_id` = the SS paperId
   - `semantic_scholar_fetched_at` = today (YYYY-MM-DD)
   - `abstract` — only set if not already present (CrossRef wins
     when both have it)
   - `tldr` — set when `payload.tldr.text` is present
   - `references` — replaced with the normalized SS refs when SS
     returned any. Stamped with `references_source:
     'semantic_scholar'` so the V3.93 regex parser knows not to
     overwrite.
   - `cited_by` — always set from SS citations
   - `cited_by_fetched_at` = today
4. Saves `items.json`.

Wired into both import paths:
- **`fromDoi`** (used by paper-citations panel's `+ Add to library`):
  fired in the background right after the existing `await
  api.save('items.json', ...)`.
- **`library.js _processFile`** (manual PDF drag-drop): same
  background fire, alongside the existing V3.93 `parseAndCacheRefs`.

### Race condition with V3.93 regex parser

Both `parseAndCacheRefs` (regex) and `enrichItemFromSemanticScholar`
(SS) write to `meta.library.references`. SS is usually faster (one
API call) but PDF parsing can also finish first if SS rate-limits.
Both writers now check `references_source` before writing:

- SS always writes (it's preferred).
- Regex skips its write if `references_source === 'semantic_scholar'`
  is already set.

So whichever finishes last respects the other.

### `paper-cited-by.js` reads cache first

`init` now checks `meta.library.cited_by` before doing anything —
when it's a cached array, render directly with no API call. Falls
through to the live `PAPER_SS.fetchCitations` for items imported
pre-V3.112 or where SS had nothing at import time. Live response is
normalized via `PAPER_SS.normalizeCitations` so `_renderRow` works on
both the cached shape and the live shape.

The standalone `_lookupId` and `_fetchCitations` helpers in
`paper-cited-by.js` now delegate to `PAPER_SS` — single source of
truth for ID picking and HTTP, only kept as fallbacks if `PAPER_SS`
fails to load.

## Files changed

- **`rm/js/paper-semantic-scholar.js`** (new) — shared API wrapper
  + normalizers.
- **`rm/js/library-upload.js`** — new `enrichItemFromSemanticScholar`
  helper exported on `LIBRARY_UPLOAD`; fired from `fromDoi` after
  save; `parseAndCacheRefs` guarded with `references_source ===
  'semantic_scholar'` skip.
- **`rm/js/library.js`** — manual upload path (`_processFile`) also
  fires `LIBRARY_UPLOAD.enrichItemFromSemanticScholar(item.id)` in
  the background, alongside the existing V3.93 ref parse.
- **`rm/js/paper-cited-by.js`** — reads `meta.library.cited_by` first
  (no API call when present); delegates to `PAPER_SS` for ID picking,
  HTTP, and citation normalization.
- **`rm/pages/library.html`** — adds
  `<script src="/rm/js/paper-semantic-scholar.js">` to the
  `papersScripts` array (loaded before `library-upload.js` so
  `PAPER_SS` is on window when the import-time enrichment fires).
- **`rm/pages/library-paper.html`** — same `<script>` tag added
  before `library-upload.js`.
- **`sw.js`** — `CACHE_VERSION` 87 → 88.

## Out of scope

- **Backfill of pre-V3.112 library items.** No automatic migration.
  Cited-by falls through to live API on open; references stay on
  regex-parsed output until a manual re-import or a future
  "Refresh metadata" button is added.
- **A "Refresh metadata" button on the paper reader.** Useful for
  papers imported before SS had indexed them — out of scope here.
- **Persistent caching beyond `cited_by` + `references` + `abstract`
  + `tldr`.** SS also returns embeddings, openAccessPdf URLs,
  publication date, etc. — only the fields we actively use are
  stored.
- **Title-only fallback when no DOI/arXiv/PMID is set on the
  imported paper.** SS's `/paper/search` endpoint could resolve by
  title but adds an extra round-trip and is fuzzy. The current "skip
  enrichment" path is fine for the small number of items in this
  state.

## Verification

1. Hard reload the library tab (evict SW cache `mcgheelab-shell-v87`).
2. **Import via DOI** — open the paper-reader on a paper that has a
   citation panel `+ Add to library` button. Click it. The new paper
   appears in the library. Check console:
   - `[library-upload] cached N refs for {id} at import time` (V3.93
     regex), or
   - `[library-upload] SS enriched {id}: M refs, K cited-by` (V3.112
     SS — usually first to finish).
3. Open the imported paper's reader page. The Cited-by panel should
   render **without a network call** (cached). The Citations panel
   should show structured references — every row with a DOI gets
   the `+ Add to library` button (richer than V3.93's regex output).
4. **Import via PDF drag-drop** — drop a PDF onto `library.html`,
   confirm the same `[library-upload]` log lines fire and the same
   cached behaviour on next open.
5. **Pre-V3.112 paper** — open a paper imported before this version.
   Cited-by panel falls through to the live API call (visible as a
   network request to `api.semanticscholar.org/.../citations`),
   citations panel still works on regex-parsed refs.
6. **Paper SS doesn't have indexed** (very recent or obscure
   venue) — Cited-by shows the V3.111 empty state, citations panel
   stays on regex output, no errors.
