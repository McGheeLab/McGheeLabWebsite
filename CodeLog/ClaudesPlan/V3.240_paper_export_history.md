# Paper Export — Compile History + Staleness Detection (V3.240)

## Context

V3.231 shipped the Paper Export Workspace with one viewer pane and no memory. Every Compile button click produced a new PDF, but:

- The old compiles lived in `paperExports/{paperId}/compiles/{compileId}` Firestore docs + `gs://mcgheelab-f56cc.firebasestorage.app/paperExports/{paperId}/compiles/{compileId}.pdf` Storage objects, and the UI surfaced none of them. Users had to re-compile every time they wanted to look at "the latest PDF."
- Nothing told the author whether the PDF they were looking at matched the *current draft*. They could open the workspace days after a compile, see a stale PDF, not realize it, and ship the wrong build.
- Compile artifacts accumulated forever with no UI affordance to delete them.

V3.240 adds the three missing pieces in one ship.

## Approach

### 1. Compile history panel

New section in the left config column of `paper-export.html`, between "LaTeX add-ons" and "Figure defaults":

```
Compile history
[staleness banner — green/amber]
• 12m ago    [View] [✕]
• 2h ago     [View] [✕]
• yesterday  [View] [✕]
…up to 50 entries…
```

Backed by an `onSnapshot` subscription to `paperExports/{paperId}/compiles` ordered by `triggeredAt desc, limit 50`. Live-updates as new compiles land (multi-tab, collaborator triggers, etc.).

Click **View** → mints a fresh download URL via `firebase.storage().ref(compile.pdfStoragePath).getDownloadURL()` and mounts in the right pane. The 1h signed URL on the compile doc may have expired; this fresh mint sidesteps that.

Click **✕** → confirm dialog, then delete Storage object first, then Firestore doc. Soft-fail on missing Storage (already gone). If the deleted compile was active, the snapshot listener auto-mounts the next newest one.

### 2. Auto-load newest PDF on page open

When the workspace mounts, if `state.compiles[0]` exists and no PDF is active yet, `_viewCompile(state.compiles[0])` runs automatically. User sees the most recent build without clicking Compile.

### 3. Staleness detection via bundle hash

**Hash function** (must be identical on Cloud Run + browser):

```
sha256 of:
  files
    .map(f => f.relpath + '\n' + f.content)
    .sort()
    .join('\n---FILE---\n')
```

- **Cloud Run** (`functions/paper-compile/server.js`): `crypto.createHash('sha256').update(parts).digest('hex')`. Computed before Tectonic runs, persisted as `bundleHash` on the compile Firestore doc.
- **Browser** (`rm/js/paper-export.js`): `crypto.subtle.digest('SHA-256', new TextEncoder().encode(parts))`. Recomputed on demand against the current Yjs draft via the existing `PaperExportTex.buildBundle()`.

Banner state:
- No compiles → banner hidden.
- Newest compile has `bundleHash` and matches local hash → **green** "✓ Latest PDF matches the current draft."
- Newest compile has `bundleHash` and differs → **amber**, clickable to re-compile.
- Newest compile lacks `bundleHash` (pre-V3.240 compile) → neutral "Re-compile to enable change-detection."

Yjs `update` event observer with 800ms debounce flips the banner amber immediately when the author types.

## Deploy steps

1. `firebase deploy --only firestore:rules,storage:rules`
2. `cd functions/paper-compile && gcloud run deploy paper-compile --source . --region us-central1 --port=8080 --no-allow-unauthenticated --memory 1Gi --timeout 90 --max-instances 3 --set-env-vars FIREBASE_STORAGE_BUCKET=mcgheelab-f56cc.firebasestorage.app`
3. Cyberduck-FTP the rm tree (`rm/pages/paper-export.html`, `rm/css/paper-export.css`, `rm/js/paper-export.js`, `sw.js`).

## Verification

1. **Open workspace on a paper that has prior compiles** — verify compile list renders, newest PDF auto-mounts in right pane, staleness banner shows "Re-compile to enable change-detection" (pre-V3.240 compiles lack bundleHash).
2. **Click Compile to PDF** — new entry appears at top of list, banner flips to green "✓ Latest PDF matches the current draft" within a snapshot tick.
3. **Edit a paragraph in another browser tab** (or wait for a collaborator) — banner flips to amber "⚠ Draft has changed" within ~800ms of the Yjs update reaching this tab.
4. **Click amber banner** — re-compile triggers, banner flips green again after.
5. **Click ✕ on the active compile** — confirm dialog → delete → snapshot listener auto-mounts the next newest. PDF + Firestore doc both gone (verify via Firebase Console).
6. **Click ✕ on a non-admin user** — V3.231 left `paperExports/{paperId}` write to `isLabContributor()`; verify a guest or non-contributor signed in sees the Delete buttons hidden (via `state.canEdit` check) and gets a permission denied if they try to call `_deleteCompile` from the console.

## Out of scope

- Scheduled cleanup of ≥30-day-old compiles (Phase 2 plan, still open).
- Per-user daily compile quota (Cloud Run's `--max-instances 3` is the current cap).
- Compile-history pagination beyond the first 50 entries.
- Diff view between two compile bundles ("what changed since the last compile?").
