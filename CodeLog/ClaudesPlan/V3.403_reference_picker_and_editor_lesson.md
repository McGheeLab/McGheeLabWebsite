# V3.403 — 🔗 Reference variable picker + lesson 1 continues into the page editor

## Context

Alex: a reference should be SELECTABLE — a topbar button opening a
popout "just like how the paper builder works", so the user never has
to enter or see `[!var:total_volume]` syntax. And after the node build
finishes, the lesson should continue on the page editor showing how to
integrate a node output into the protocol via this reference.

## Design

### 🔗 Reference picker (`rm/js/protocol-editor.js`)
- Topbar button `#pre-refvar-btn` ("🔗 Reference", `.btn.pre-action-btn`,
  inserted after the view segment; editor view + canEdit only, hidden
  elsewhere via `updateViewSeg`). Disabled until a prose block has been
  focused (tooltip explains).
- Popover reuses the paper builder's `.pe-cite-popover` shell —
  paper-editor.css is already loaded on protocols.html, so look & feel
  are literally the same component styles. Contents: title, search
  input, rows (mono name · label · LIVE value · computed/input badge),
  hint foot. Rows come from `ProtocolFormulas.getSymbolTable()` (cached
  by `rebuild`, document order) + `formatSymbolValue`.
- Insertion: `bindYTextWithVars` (protocol-blocks.js) stamps each bound
  element with `el._preVarsYText`; focusin/keyup/mouseup delegation on
  `#pre-content` tracks the last-focused prose block + caret offset
  (range-before-caret → text length — raw text maps 1:1 to Y.Text).
  Picking a variable inserts `[!var:name]` at the remembered offset
  (space-padded when the neighbors aren't whitespace) via
  `yText.doc.transact` + `markDirty`. The block is blurred first so the
  Y-observe repaints — the user sees the CHIP appear, not the token.
  Editing the raw token remains possible on focus (source view), but
  nobody has to type or read it.

### Page-level tour host (`pageTours()` in protocol-editor.js)
Tours were owned by the graph-editor mount, so a Nodes → Editor switch
destroyed them ('detached'), and the re-arm only ran in renderNodesView
— a tour could never continue in the editor view. New host attaches
ONCE to stable elements (`document.body` + `#pre-content`): `getGraph`
reads the design block's attrs directly (works in any view),
`resetGraph` clears the attrs (+ re-render when in nodes view so the
rebuild starts visibly blank), `onEnd` keeps the V3.394 bookkeeping.
The renderNodesView debounce now starts tours on this host (skipping
when one is already active), and the graph editor's 🎓 menu routes here
via new mount `opts.startTour` (`startTourById` short-circuits;
mount-owned attach remains the fallback for notebook design blocks).
Net: tours survive view switches, remounts never blank the card, and
lessons can walk from the canvas into the page editor.

### Lesson 1 finale (protocol-graph-tours.js) — 15 → 17 steps
Replaced the doc-view closing step with:
1. **Now put it in the write-up** — rings `.pre-viewseg-btn[data-view="editor"]`,
   completes when the editor view is active (DOM-checked, Node-safe
   `document.querySelector &&` guard), `practice: true`.
2. **Reference the total** — rings `#pre-refvar-btn`; completes when a
   `.proto-var[data-var="total_volume"]` chip exists in the document,
   `practice: true`. Why: references are picked, never typed.
3. **It's alive** — closing info step (rings 📄 Document).

### Lesson 1 content (`rm/data/protocol-demos/lesson-1-…json`)
The payoff block no longer ships the pre-inserted token — its prose now
explains the 🔗 Reference flow and ends with the anchor sentence
“Total volume to prepare:” that the tour tells the user to complete.
(The chip-detection condition would otherwise be satisfied on load.)
