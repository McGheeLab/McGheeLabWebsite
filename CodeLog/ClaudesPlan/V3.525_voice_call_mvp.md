# V3.525 — Voice Call MVP (Slack-style huddle in chat)

## Goal

A lightweight, one-click **group voice call** launched from inside a chat
channel — what Slack calls a "huddle." (Unrelated to RM's Huddle page,
which is a planning board; same Slack-borrowed word, different feature.)

MVP mandate: get one real multi-party call working end-to-end at **$0 and
zero new vendors**, so audio quality and connect reliability can be
evaluated before investing further.

## Approach

- **Media:** WebRTC **mesh** — every peer holds one `RTCPeerConnection`
  per other participant. Audio only. Sized for 3–6 people (a mesh does
  not scale past that; a bigger lab call would need an SFU/managed SDK).
- **Signaling:** Firestore + `firebridge.onSnapshot`. No signaling
  server. New ephemeral collection:

  ```
  voiceCalls/{channelId}                       one live call per chat channel
    { startedBy, startedByName, channelName, startedAt, active }
  voiceCalls/{channelId}/participants/{uid}    in-call presence
    { uid, name, muted, joinedAt, lastSeen }   lastSeen heartbeat every 5s
  voiceCalls/{channelId}/signals/{autoId}      addressed SDP/ICE
    { from, to, kind: offer|answer|candidate, payload(JSON), createdAt }
  ```

  All docs are ephemeral: signals are deleted on consumption, the
  participant doc on hang-up, the call doc by the last leaver.
- **ICE:** free Google STUN only (`stun:stun.l.google.com:19302`).
  **Known limitation:** no TURN relay, so peers behind strict/symmetric
  NATs (~10–20% of networks, some campus VPNs) won't connect; the UI
  surfaces a per-peer "restrictive network" toast on `connectionState
  === 'failed'`. Adding a managed TURN service later is a drop-in
  (credentials function + extra `iceServers` entry).
- **Glare avoidance:** per pair, the lexicographically smaller uid is the
  initiator (creates the offer). Deterministic mesh setup, no rollback.
- **No composite index needed:** the signals listener is a single
  equality (`where('to','==',uid)`); snapshots are sorted client-side and
  ICE candidates arriving before the remote description are queued
  per-peer and flushed after `setRemoteDescription`. (The original plan
  budgeted an index for `to`+`createdAt` orderBy; the queue makes
  ordering irrelevant, so the index — and its deploy step — was dropped.)
- **Ringing:** new Cloud Function `onVoiceCallCreate`
  (`voiceCalls/{channelId}` onCreate) pushes FCM to the channel's
  recipients — `members[]` for DMs, `subscriberUids[]` for channels
  (chat's targeted-lookup pattern), minus the starter, respecting
  `mutedChannels`. Deep link `?channel=<id>` lands in the channel where
  the live 📞 button joins. `APP_KEY='chat'` (rides chat's push toggle).
- **On-page cue:** voice-call.js watches `voiceCalls where active==true`
  for everyone on the chat page and dispatches a `voice-call-change`
  window event; chat.js re-renders the header so the 📞 button turns
  green/pulsing ("Join the call in progress").

## Key decisions

1. **Firestore as signaling transport** — proven pattern; reuses auth,
   rules, and onSnapshot infra; zero new services. Trade-off: ~100–300ms
   extra call-setup latency vs a websocket, irrelevant for an MVP.
2. **Mesh, not SFU** — right-sized for a small lab; documented ceiling.
3. **Mic before writes** — `getUserMedia` is requested before any
   Firestore doc is touched, so a denied mic never creates a ghost call.
4. **Stale-peer tolerance** — 5s heartbeat, 25s staleness window,
   client-side filtering + any-member participant delete in rules, so a
   crashed tab can't wedge a call.
5. **Poison-signal safety** — a signal doc is deleted even if handling
   throws, so one malformed doc can't loop the listener.

## Deploy

1. `firebase deploy --only firestore:rules`
2. `firebase deploy --only functions:onVoiceCallCreate`
3. FTP the repo (Cyberduck) — rm/ tree + sw.js.

## Verification

- Two browsers/profiles, same channel: start in one, join in the other →
  two-way audio; watch `voiceCalls/...` docs appear and drain.
- Third participant → all three hear each other (mesh: 2 pcs per peer).
- Hang up / close tab → tile disappears for others; last leaver removes
  the call doc.
- Mute → local track disabled, 🔇 shows on the peer's tile.
- Test once from a restrictive network (campus VPN) to characterize the
  no-TURN failure rate before deciding on a relay.
