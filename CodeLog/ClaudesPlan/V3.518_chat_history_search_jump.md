# V3.518 — Chat: full-history search, jump-to-message, open-at-bottom fix

**Release 6 of 7** in the chat upgrade program. Client-only; the one
Firebase artifact is a new composite index that rides the already-pending
R2 deploy.

## 1. Open-at-bottom fix (Alex's report)

Chat opened mid-history instead of at the newest message. Root cause:
`scrollToBottom()` fired once on the first snapshot, then images/
attachments finished loading and grew `scrollHeight` — stranding the
view. Fix is belt-and-braces:
- `scrollToBottom()` now double-rAFs (second pass catches late layout).
- `wireFeedScroll` adds a CAPTURE-phase `load` listener on the feed
  (`load` doesn't bubble): every inner `<img>` completing re-pins the
  feed to the bottom while `_autoScroll` holds and the feed is live.
  The moment the user scrolls up, `_autoScroll` flips off and pinning
  stops.

## 2. Progressive full-history search

Old search substring-filtered the ≤50 loaded messages (and weirdly also
filtered the live feed while the modal was open — removed). New engine
(`runProgressiveSearch`):
- Pages backward through `chatMessages` 200/batch — channel scope uses
  the existing `(channelId, createdAt DESC)` index; "All channels" is a
  plain `orderBy` (no composite needed). Client-side `messageMatches`
  filter (text / author / file name), results stream into the modal.
- Stops at 20 results or 2,000 docs per run with a live "Searched N
  messages · M results" status; "Search older messages" continues.
- `_searchCache` keeps scanned docs per scope+channel so refining the
  query re-filters WITHOUT re-reading; a generation counter cancels
  superseded scans on each keystroke (400 ms debounce).
- Modal gains a This channel / All channels scope toggle; result rows
  show author + channel + absolute date.
- Rejected alternatives: callable-function scan (same linearity + cold
  starts), `searchTerms[]` array-contains (whole-token only, 30-term
  cap, write-path churn + backfill) — wrong trades at lab scale.

## 3. jumpToMessage + history mode

`_feedMode: 'live' | 'history'`. `jumpToMessage(msgId, channelId?)` is
the single entry point (search results, pinned items' new "Jump to
message ↗" affordance, any `[data-goto-msg]`):
- Ensures the chat view is showing; fast path scroll+flash if the target
  is already in `_messages`.
- Thread replies: jump to the parent, then auto-open its thread panel.
- Cross-channel jumps switch context WITHOUT a live subscribe.
- `enterHistoryMode(targetSnap)`: live listener detached, window queries
  25 before (existing desc index) + 25 after (`createdAt ASC` — NEW
  composite `(channelId ASC, createdAt ASC)` added to
  firestore.indexes.json; on failed-precondition the client falls back
  to the live tail with a toast), target centered + 2s amber flash.
- In history mode: `markChannelRead` is gated off, autoscroll and the
  "New messages" pill are suppressed, upward pagination reuses
  `loadOlderMessages` unchanged, and new `loadNewerMessages()` (scroll
  near bottom or the "Load newer messages" button) walks toward the
  tail. Catching the tail (<50 returned) transitions to live.
- Persistent "Viewing message history · Jump to latest ↓" banner above
  the feed (`updateHistoryBanner`, survives feed re-renders). Exits:
  banner click, tail catch, sending a message, channel switch
  (`subscribeMessages` resets mode).

## Verification

Open chat on a channel with image posts → lands at the newest message
even before images finish. Search a term only in old history (both
scopes); click a result in another channel → history window opens
centered + flashed; scroll up (older) and down (newer); reaching the
tail flips to live; banner click jumps to latest; sending from history
returns live first. Pinned view → Jump lands in context. Thread-reply
search hit opens the parent's thread. Mobile: banner above composer,
search tab works, jump switches to the chat tab.
