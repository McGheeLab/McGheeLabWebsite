# V3.933 — Merged changes to review, coloured by person until you have looked

## Goal (Alex)
"If you both change the same line differently, both versions stay there, one after the other. if this happens color the
variations per user" — then: "upon review the colors can go to normal. this color variation should be for quick review
scans only not persistent for all time. after a user reviews the change it should not be colored any more. users can
accept all changes, or run through a group of changes at a time (with a next button). changes need not be super
granular, we can cluster them by area. and just bring the user to the next area of change to accept or comment on."

## Approach
- **Marks, not a new store.**
  - The merge (V3.932) already knows which lines are each side's version. It marks them `{type:'fmt', s:'by<n>', who}`.
  - The editor already draws any `fmt` mark as `span.f<s>` and keeps it through edits (by id), so nothing in Gabe's
    `src/` changes.
  - A version moved to the end of the card is marked too.
- **One colour per person.**
  - Six hues, chosen by the person's name, so each person keeps their colour on every card.
  - The two sides of one merge never get the same hue.
  - Names are people, not devices: `personOf()` reads `share:<uid>` / `share` writes as the collaborator / owner, and
    anything else as the hub's owner (`users/{uid}` name, cached).
- **Areas.**
  - One card = one area; that is the clustering.
  - Ordered note by note (most recently changed first), then in card order.
- **Review (lab-mode §18).**
  - A chip with the count. Its bar opens each area in turn (`App.openBlock`) and outlines it with a generated CSS
    rule, which survives re-renders.
  - Accept · Comment (a card wired `comments`) · Next → · Accept all.
- **Reviewed is per person.**
  - Note only you have: accepting removes the marks.
  - Shared note: the mark ids go in your `settings.reviewedMerges` (your hub, your devices; pruned to marks that still
    exist), and a generated rule hides those colours for you. The collaborator still sees theirs until they review.

## Not done
- Marks reviewed by everyone in a shared note stay in the record (invisible to those who reviewed). A later clean-up
  could drop them once every member has reviewed.
- A comment is a card wired to the area, not a threaded comment; Scientia has no thread type.
