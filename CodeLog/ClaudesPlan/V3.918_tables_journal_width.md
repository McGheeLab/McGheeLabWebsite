# V3.918 — Tables the way journals set them: page width when too wide, continued when too long

**Reported (Alex, 2026-10-25, screenshot of the live ME3B paper, ACS look, page 6):** "the table looks crazy.
typically journals dont do the table along the entire column they will do full width for tables unless the table is
small enough to fit within a column."

## What was wrong

- The bill-of-materials table (five columns: Designation, Component, Units, Cost/unit, Source) sat in one 8.5 cm
  column. Built tables wrap by default (V3.652, `wrap` on unless turned off), and an untouched table splits the line
  into equal shares, so each column was ~33 pt wide and the page view broke words letter by letter ("Des ign atio n",
  `overflow-wrap:anywhere`). The PDF did the same with `p{share\linewidth}` columns (overfull boxes instead of
  letter breaks).
- A table only ever went across the page when `span:'page'` was set, and every table was created with
  `span:'column'`.
- The table ran off the bottom of the page: a float cannot break, and nothing continued it.
- Imported LaTeX tables passed through verbatim — a `longtable` (the MEBP HardwareX BOM is one) does not compile in
  two columns at all.

## Rules (both sides)

1. **Width.** In a two-column layout a table whose span is `auto` is set across the page when its natural width (no
   wrapping; each column as wide as its widest cell; fixed columns — `p{3cm}`, a width in mm — at their width) is
   wider than a column. `PaperLayout.tableSpan(attrs)`: `'page'` → page, `'one-column'` → column, anything else
   (including the old default `'column'`) → auto. New tables store `'auto'`; the Table layout popover offers Fit /
   One column / Full page width.
2. **Length.** A table taller than the page is cut at row boundaries: a piece holds the rows that fit under the
   caption, the header and two lines of slack; every later piece starts "Table N (continued)" and repeats the header.
   Caption on the first piece, notes on the last.

## PDF (`paper-export-tex.js`)

- `RM_TABLE_TEX` (preamble, injected when used): `\rmTable{\rmTR{<rules above>}{<row \\>}…}` reading per-table
  `\def`s (`\rmTspan`, `\rmTplace`, `\rmTplaceStar`, `\rmTnat`, `\rmTspec`, `\rmTsetup`, `\rmTtop`, `\rmThead`,
  `\rmTbottom`, `\rmTcaption`, `\rmTcapmeasure`, `\rmTcapAbove`, `\rmTnumbered`, `\rmTnotes`, `\rmTbefore`,
  `\rmTafter`) inside a group. TeX boxes the natural tabular and compares it with `\columnwidth`, then measures each
  row as a one-row tabular at the printed width and flushes a float (`table` / `table*`, placement expanded through an
  `\edef`) when the next row would pass `\textheight` − caption − `\abovecaptionskip` − 2`\baselineskip` − header.
  A piece's first row drops the rules above it (no doubled rule under the repeated header).
- Used for every table in a two-column template (built tables: natural spec = alignments + mm widths; printed spec =
  the existing colspec). One-column output is unchanged (byte-identical; the row code became `rowCellsTex(r)`).
- Imported tables: `PaperProseTex.splitTable(raw)` → env, spec, setup (size, `\setlength`, `\arraystretch`,
  `\rowcolors`), caption (as written, with position), label, top / head / bottom rules, rows with the rules above
  them; longtable markers give the header, its footers are dropped (the closing rule is restored). Refuses `tabularx`,
  `\resizebox`, other environments, `#` → verbatim.
- `packagesFor` also loads `array` (`\arraybackslash`, `>{\raggedright}`) and `longtable`, and `float` when
  `\rmTplace` is `H`.

## Document view (`paper-doc-view.js`, `paper-look.js`)

- `_buildBlockNode` records `data-tspan`, `data-nhead`, `data-tnum`; `_layoutTables(items, geom)` runs after
  `_applyLookCss` (the blocks are built before the look's CSS and fonts are applied — measuring at build time gave
  rows 40 % too tall) and before `_measureItems`: `_tableNaturalW` (clone with `.pdv-tbl-natural`: `max-content`,
  nowrap, shares released, fixed widths kept), then `_tablePieces` (rows measured at the printed width; pieces get
  `data-piece`, which joins the measure-cache key).
- Look CSS sets a table as TeX sets a tabular: body size, 6 pt `\tabcolsep`, one look leading per row, booktabs rule
  spacing (0.65ex under a rule, 0.4ex over one), density as `\arraystretch` (0.7/0.3 of the extra above/below), plain
  header row, `overflow-wrap:normal` (an unbreakable word sticks out, as TeX's overfull box does, instead of adding
  lines), caption above when the look says so (`.pdv-tabcap-above`, caption package `position=top` skip).
- Imported tables: `p{…}` widths (+ the padding TeX adds outside them), `l/c/r` unwrapped (`.pdv-tbl-tex`),
  `\multicolumn` → merged cells, the source's size step (`parseTabular().size`), caption where the source wrote it.
- `getAllTables`: an imported table with no `\caption` takes no number (TeX does not number it).

## Verified (Paper Lab, `PaperLab-corpus/_examples/tabletest`)

A test paper with a small built table, a 34-row built BOM (five columns, wrapping, group rows merged, Component
0.45), a small imported table, the April MEBP BOM (`p{3cm}…`) and the HardwareX longtable, under ACS: PDF 5 pages —
small table in the column; the BOM across page 2 with "Table 2 (continued)" on page 3 (2 rows); the April table
across a page; the longtable on one page. The Document view cuts the BOM at the same row ("Printed parts") with the
same 2-row continuation and draws every table at the same width and line breaks. IEEE, PNAS, APS (class looks),
Nature, Elsevier (two-column) and PLOS / Science (one column, unchanged) all compile. Corpus regression (8 papers,
Paper Lab runs p8 → p11): every compiled PDF keeps its page count and is text-identical except JACS (its abbreviation
list goes through `\rmTable` and, with the ⅓-column rule, stays in its column as in the published article); NSF
page starts 16/16 against the real proposal. The ⅓-column rule came from that check: without it the JACS list jumped
to page width.

Known: the Document view can still set a page-wide float one page earlier than TeX when the paragraph before it ends
a line or two differently at a page foot (the test paper's April table: page 3 here, page 4 in the PDF) — the
anchor rule is the same, the text flow is the approximation.

## Not done

- Column shares for auto columns in a wrapping table stay equal (a "Units" column gets as much as "Source"); sharing by
  content (tabulary-style) would change every existing wrapped table, so it is left for its own change.
- A `\multirow` cut by a piece boundary is not kept together.
