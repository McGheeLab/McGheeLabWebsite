# V3.858 — The Capture extension for every lab member (and a download that works)

Gabe (relayed by Alex, 2026-10-23): *"Can you add me to the McGhee Lab Capture Chrome
extension? It doesn't allow me to download it since I don't have permissions."*
Alex: *"all my students should be able to use this extension."*

## What was actually wrong (two things, neither specific to Gabe)

1. **The download never worked in production.** The Library page's "↓ Download extension
   (.zip)" button pointed at `/api/extension/download.zip`, a route of the local dev server
   (`ResearchManagement/server.py` zips the folder on each request). mcgheelab.com is a static
   host: no `/api/`, so GoDaddy answers 403 Forbidden — which reads exactly like "you don't have
   permission". CHANGELOG V3.819 had recorded this as a known gap ("lab members get the zip from
   the dev server or from Alex").
2. **Nobody but an admin has ever been allowed to capture.** `pending_captures` / `paper_index`
   were gated on `isExtensionMember()` = admin OR email in `labConfig/extensionMembers`. That
   allowlist has been **empty since 2026-04-29** (library-sync.js's V3.583 comment says so). So
   a student who did get the zip was refused by Firestore after signing in.

## Goal

- Every lab member — `users/{uid}.role != 'guest'` — can download, install and use the
  extension. Guests (class students, visitors) cannot. The email allowlist stays for accounts
  WITHOUT a lab role (an outside collaborator, a second Google account).
- Gabe specifically: his `gabrieldeclercq@arizona.edu` account is `role: editor`, so the rule
  covers him; his email is ALSO on the allowlist now (belt and braces, and it took effect the
  moment it was written, before any deploy).

## Approach

| Layer | Change |
|---|---|
| `firestore.rules` | `isExtensionMember()` = `isLabMember() \|\| email ∈ allowlist`. `isAdmin()` dropped from the OR: admins are lab members, and `isAdmin()` RAISES for a caller with no `users` doc (an allowlisted collaborator who only ever used the extension), which denied the whole OR. `isLabMember()` is `exists()`-guarded. Comments at the helper, `pending_captures`, `labConfig/extensionMembers` updated. |
| Deploy | From a scratch copy = LIVE ruleset + only this hunk (`--config`), because the repo file still carries V3.806 (self-role guard), V3.835 (`use_mode`) and V3.836 comment renames that are NOT live. Proven first with the firebaserules `:test` API (10 cases: member create / spoofed uid / guest / allowlisted guest / allowlisted-no-users-doc / paper_index read both ways / editor flips status / allowlist doc read / admin). |
| `scripts/build_extension_zip.py` (new) | Deterministic zip of `../ResearchManagement/extension` → `rm/downloads/mcgheelab-capture-extension.zip` (sorted, fixed timestamps, `extension/` root folder, excludes `key.pem`/`*.pem`/`.DS_Store`/`__pycache__`/`.git`/`test/`). `--check` exits 1 when stale. `rm/**` is already in `deploy/site.json`, so the ordinary deploy ships it. |
| `rm/pages/library.html` | Button → `/rm/downloads/mcgheelab-capture-extension.zip`; "Access is by invitation" → "Who can use it: every lab member…"; admin list retitled "accounts without a lab role". |
| `rm/js/library.js` | `_isLabMemberAny()`; `_updateExtensionMemberStatus` says ✓ (lab member) before consulting the allowlist. |
| `rm/js/library-sync.js` | `_isCaptureMember()` returns true for `firebridge.isLabMember()` — otherwise the sync would never run for members and their captures would never leave `pending_captures`. |
| Firestore data | `labConfig/extensionMembers.emails += gabrieldeclercq@arizona.edu` (REST, as the project owner). |
| `rm/pages/procurement.html` | Follow-up: the same download link in the page header, top right (Alex: "add another one of the links to the procurement page at the top"). |
| `sw.js` | 839 → 840, then 841 for the Procurement link. |
