# V3.444 — E2 of Paper Builder III: in-doc "⧉ Visual" equation overlay

> Extends E1's visual editing to display-equation BLOCKS in the write page. The block's
> LaTeX contenteditable is bound via `bindYTextToContentEditable`, whose focus handler
> replaces innerHTML with chip-mode and whose serializer walks the DOM — an inline
> `<math-field>` would be destroyed on focus and misread on input. So visual editing
> happens in an overlay.

## Changes

- **`rm/js/paper-blocks.js`** — `renderEquation` toolbar gains **⧉ Visual** (editors only,
  gated on the shared `ensureMathlive` loader). `_openEqVisualOverlay(yBlock)`: a fixed
  overlay (z 4500 — above modals, below the math keyboard) with one `<math-field>` seeded
  from `body.toString()`; **Apply** = a single transact clobber (delete-all + insert,
  origin `eq-visual`) — the existing binding observer repaints the KaTeX render; Cancel /
  Esc / backdrop-click close without writing. Fidelity guard: `dirty` flag — Apply is
  disabled (and writes nothing) until the user actually edits.
- **CSS (`rm/css/paper-editor.css`)** — `.pe-eq-visual-btn`, `.pe-eqviz-overlay/-card/
  -head/-host/-actions` (larger 21px math field in the modal).

## Verification

- `node --check` clean; CSS balanced; harness suite unchanged (338 green — no export
  changes).
- **Browser (Alex):** write page → any display-equation block → ⧉ Visual → edit → Apply →
  the block re-renders (and collaborators see it); open + immediately Esc → stored LaTeX
  untouched (Apply stays disabled); virtual keyboard renders above the overlay.
