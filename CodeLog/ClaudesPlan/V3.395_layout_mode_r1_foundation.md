# V3.395 — Layout Mode R1: foundation + LaTeX round-trip

> Release 1 of the Layout Mode program (master plan approved 2026-07-17:
> interactive figure/table layout in the Document view — drag/anchor/lock/
> resize/replace on color-coded page regions, per-journal rules, everything
> round-tripped to the LaTeX build). Staging: R1 foundation (this), R2 float
> engine, R3 region overlay + ⬒ Layout toggle, R4 drag interaction, R5
> resize + replace-image. Designed by two Opus plan agents + three Opus
> explorers; adversarially reviewed by an Opus workflow.

## Goal

Give every figure/table block a **layout intent** that both the Document
view and the LaTeX exporter interpret identically, plus the **build-target
toggle** that decides how intent maps to journal reality:

- `anchor: 'flow' | 'top' | 'bottom' | 'float-page'` — where on its page
- `span: 'column' | 'page'` — one column vs full page width (→ figure*/
  table* in two-column classes)
- `lock: bool` — pin exactly (honored in preprint builds)
- `size_key` (figures) — canonical-size slot, consumed by R5 resize snap
- `paperExports.buildTarget: 'submission' (default) | 'preprint'` —
  submission = the journal's own float conventions, never [H]; preprint =
  we publish the PDF (arXiv/local), locks become [H], anchors forced (!t/!b)

## What shipped

1. **NEW `rm/js/paper-layout-rules.js`** (`window.PaperLayout`) — the single
   source of truth: `resolveFloat(attrs, template, kind)` →
   `{env, place, width, captionAbove, warnings[]}`; plus `placementToAnchor`
   (legacy spec → intent), `anchorToPlacement`, `resolveWidth`
   (span='page' → \textwidth), `getRules` (render_hints.layout over
   defaults). Encodes the starred-float constraints (figure*/table* accept
   [t]/[p] only; bottom/lock on starred → 't' + warning), the
   [H]-needs-float-package rule, and per-target mapping tables.
2. **Exporter** (`rm/js/paper-export-tex.js`): `figureToTex`/`tableToTex`
   call `resolveFloat` **only when `attrs.anchor` is present** — legacy
   blocks emit byte-identical output (regression-tested). `tableToTex` now
   honors `caption_position: 'above'` (IEEE table captions go above the
   tabular — long-standing bug). `buildBundle` stashes
   `effectiveTemplate._buildTarget` (the `_use_cref` pattern) and collects
   `_layoutWarnings` (module collector, same lifecycle as
   `_exportEqLibrary`) into `bundle.warnings`.
3. **Factories** seed `anchor/span/lock(/size_key)`:
   `paper-schemas.js newFigure`, `paper-editor.js addFigure /
   createUnplacedFigure / addTable / createUnplacedTable / insertBlockAt`
   (figure + table branches). `normalizeTree` deliberately untouched —
   the back-compat contract is that legacy blocks never gain `anchor`.
4. **Template JSONs** (all 9): `figure_environment.compiled_columns`
   (2 = ieee only — compiled reality, distinct from the preview's
   DOC_HINTS cols), `table_environment.caption_position` ('above' ieee),
   NEW `render_hints.layout` per-journal rules — canonical figure widths
   (nature 89/136/183 mm maxH 247; science 55/120/183; ieee 88.9/181.9;
   acs 84.6/177.8 maxH 241; elsevier 90/140/190; plos 66.8–190.5 maxH
   222.3; mebp/preprints fractions 0.5/0.7/1.0), `allowed_placements`,
   `allow_here`, ieee `default_placement: '!t'`. `acs.json` preamble
   gained `\usepackage{float}` (was the only template missing it — [H]
   would not compile).
5. **Build-target toggle**: `paper-export.js` config plumbing
   (default/load/save/build/POST) + a "Build target" select on the Export
   page; Document-view toolbar gained a matching select next to
   "Compile PDF →" (`_onBuildTargetChange`, set-merge on paperExports,
   mirrors `_onTemplateChange`). No Firestore rules change needed
   (isLabContributor, no field validation).
6. **Doc-view popover** gained Anchor / Span / 🔒 Lock controls (origins
   'fig-anchor'/'fig-span'/'fig-lock'); a legacy block's selects display
   intent derived from its stored placement, and the first change opts it
   in. Placement changes (popover + Figures panel + doc-side block form)
   now write placement AND derived anchor/lock **in one transact** via
   `placementToAnchor`, so the two vocabularies never diverge. New
   `_writeFigAttrs` multi-key transact helper.
7. **Preview width parity**: the figure branch derives its width through
   `PaperLayout.resolveWidth` when anchored (span='page' → \textwidth →
   full-width item), and `parseWidth` now parses absolute units
   (`89mm`/`cm`/`in`/`pt` → px @96dpi) for R5's canonical-size specs.
8. Script order: `paper-layout-rules.js` loads before `paper-export-tex.js`
   on paper-builder.html + paper-export.html. Every call site guards
   `window.PaperLayout` (pages that load the writers without the module
   just skip intent syncing).

## Verification

- `node --check` on all 8 touched JS files ✓.
- 55-case node harness (scratchpad `test-layout-rules.js`): full
  resolveFloat matrix (submission/preprint × anchors × span × lock ×
  1-col/IEEE), placementToAnchor round-trip, **legacy figure + table
  emission byte-identical**, caption-above ordering + emitted exactly
  once, real template JSONs through getRules/resolveFloat, acs float pkg,
  plus regressions for all four review fixes. 55 passed, 0 failed ✓.
- All 9 template JSONs re-parsed + field-asserted after patching ✓.
- Adversarial Opus review workflow (3 dimensions, each finding verified
  by a skeptic): 10 raised / 4 refuted / 4 distinct confirmed, all fixed:
  1. `resolveFloat` top-anchor matched any placement CONTAINING 't'
     (an 'htbp' override silently defeated the anchor) → `/^!?t$/`.
  2. Popover Span/Lock wrote single keys — on legacy blocks (no anchor)
     a silent no-op in both export and preview → every intent change
     writes full anchor+span+lock in one transact (`_currentIntent`).
  3. `allowed_placements`/`allow_here` were loaded but never consulted →
     submission target now warns (never clamps) when the derived spec
     violates the journal's rules (e.g. bottom on Nature → [b] + warning).
  4. Doc-view build-target select usable before config loaded
     (TypeError + silent revert) → disabled until loadConfig resolves,
     plus a null-guard in `_onBuildTargetChange`.
