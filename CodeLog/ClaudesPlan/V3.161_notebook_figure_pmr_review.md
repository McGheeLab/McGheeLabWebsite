# V3.161 — Notebook images flagged for PMR review

## Goal

A student looking at a lab notebook entry can flag any uploaded image
"review at next PMR." That image then appears as a card in the student's
upcoming PMR period with the image preview, surrounding caption,
threaded conversation, and a "+ Create follow-up task" button. Admin can
discuss the figure during the 1:1 and create follow-up tasks straight
from the card.

## Why

Today notebook figures are invisible to PMR — the admin has no way to
say "show me what your microscopy looked like this week" without the
student pasting images into the PMR weekly entry manually. Flipping the
direction (student flags during normal notebook work → PMR card shows up
automatically) means the figure-review surface stays warm without
ceremony.

## Approach

### Schema (additive, backward-compatible)

**Notebook entry** ([rm/js/notebook-schemas.js](../../rm/js/notebook-schemas.js)) gains:
```
+ pmr_review_figures: [{
+   storage_path:      string,         // attachment.storage_path key — stable across reorders
+   period_id:         string,         // PMR period id this figure is flagged for
+   flagged_at:        ISO timestamp,
+   figure_review_id:  string,         // id of the matching entry in pmr.figure_reviews[]
+ }]
```

**PMR doc** ([rm/js/pmr.js](../../rm/js/pmr.js)) gains:
```
+ figure_reviews: [{
+   id:                string,         // matches notebook.pmr_review_figures[].figure_review_id
+   storage_path:      string,         // Storage path so the card can resolve a download URL
+   image_url:         string | null,  // cached https download URL; refreshable
+   notebook_entry_id: string,
+   notebook_title:    string,
+   notebook_date:     YYYY-MM-DD,
+   caption:           string,         // editable; defaults to ''
+   flagged_at:        ISO timestamp,
+ }]
```

`storage_path` is the join key. Reading the figure's image at PMR render
time uses `firebase.storage().ref(storage_path).getDownloadURL()` — same
pattern as the existing Attachments thumbnail strip in
[lab-notebook.js:773-796](../../rm/js/lab-notebook.js#L773-L796).

### Notebook UI

Reuse the existing Attachments strip in
[lab-notebook.js:773](../../rm/js/lab-notebook.js#L773). Each image
thumbnail gains a small `📌 PMR` toggle badge anchored to the
top-left corner. Click toggles the flag:
- Off → on: resolves next PMR period (via `userData/{uid}/pmr/_index`),
  writes a `figure_review_id` into both `notebook.pmr_review_figures`
  AND the matching PMR period doc's `figure_reviews[]`.
- On → off: removes from both arrays.

If no PMR period exists, the click surfaces a toast linking to the PMR
page so the student can create one first.

### Cross-doc write

The student is the owner of both their notebook entry AND their PMR
docs. Writes to `userData/{uid}/pmr/{periodId}` go through
`firebridge.db().collection('userData').doc(uid)...` directly — same
pattern PMR itself uses for cross-user reads at
[rm/js/pmr.js:127-135](../../rm/js/pmr.js#L127-L135). No new
firestore.rules needed; the existing `userData/{userId}/{document=**}`
rule already allows the owner to write.

### PMR block

New `renderFigureReviewsBlock()` in
[rm/js/pmr.js](../../rm/js/pmr.js), registered in `renderBody()`
between **Paper writing** and **Discussion**. For each entry in
`state.doc.figure_reviews`:
- Image preview (click → fullscreen modal)
- Editable caption (`contentEditable`, saves on blur via
  `scheduleSave`)
- "📓 From notebook entry: {title} ({date})" link to
  `lab-notebook.html?entry={notebook_entry_id}`
- Threaded comment thread via
  `SECTION_COMMENTS.mount({scope:{section_id:'figure_reviews',
  target_id:fr.id}, label:'Figure discussion'})`
- "+ Create follow-up task" button → `TASK_ASSIGN.open({source:'pmr',
  pmrPeriodId:state.currentPeriodId, pmrSectionId:'figure_reviews',
  pmrTargetId:fr.id})`

Image URLs are resolved once on first render; cached in
`state._figureUrlCache` so re-renders don't trip the Storage SDK
repeatedly.

### V1 zoom/pan

Native browser image scroll inside the modal — `max-width:90vw;
max-height:90vh; object-fit:contain`. The wishlist asked for explicit
zoom + pan controls; if the lightweight modal feels limiting we'll
layer a pinch-zoom library on later. V1 is "click image → expanded
view," which is what every other modal-image surface in RM does.

## Verification

1. Open a lab notebook entry with an image attachment. Click `📌` on the
   thumbnail. Toast confirms "Flagged for PMR: {period label}."
2. Navigate to `/rm/pages/pmr.html`. The new "Figure reviews" block
   shows the image. Caption is editable; saves on blur.
3. Click the image → expands in modal; click outside to close.
4. Click "+ Create follow-up task" → task-assign modal pre-fills with
   PMR backref. Created task lands in `userData/{uid}/tasks` with
   `bucket:'assigned'`, `source:'pmr'`, `pmrSectionId:'figure_reviews'`.
5. Post a comment on the figure card; second tab (admin view-as) sees
   the comment land via `SECTION_COMMENTS` live-sync.
6. Toggle `📌` off on the notebook side → PMR card disappears.
7. Admin viewing the student's PMR sees the figure reviews block; can
   comment + assign tasks; cannot toggle the flag (read-only view).
