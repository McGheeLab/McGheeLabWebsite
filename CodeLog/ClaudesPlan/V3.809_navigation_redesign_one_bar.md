# V3.809 — Navigation redesign: one bar, pinned + recent pages, "Go to", workflows as a switcher

**Date:** 2026-10-19
**Alex:** *"we need to update how users navigate the pages … one idea may be to add a most commonly
used and last used pages as a top bar"* → *"ok lets do a full redesign of the navigation and
workflows system to make this as user friendly as possible"*.

## What was wrong

Since V3.74 the top bar on every RM page carried only **Workflows · All Pages · Split** (plus a
"My Workflows ▾" dropdown when the user had saved one). The six group dropdowns were removed in
favour of the All Pages tile grid on the dashboard, so reaching any of the 58 registered pages from
any other page was a two-hop trip: back to the dashboard, find the tile, click.

Workflows were a *mode*. Clicking a workflow card navigated to `workflow-shell.html` (an iframe
host) and nav.js replaced the whole bar with a blue "workflow strip" of a different shape; "Leave
workflow" reloaded the page. The strip was the only one-click jump list in RM, and you had to enter
a mode to get it. Inside the strip there was no profile chip and no sync status (both inject into
`.top-nav`, which the strip wasn't).

There was no recent-page tracking, no page search, and no keyboard navigation.

## The design

**One bar, every page, same shape.** `nav.top-nav` always renders:

```
[McGhee Lab] [⌕ Go to…  ⌘K] │ [chip][chip][chip][chip][chip] [+] │ [Workflows ▾] [⊟] [sync] [avatar]
```

- **Chips are the user's pages.** Pinned pages first (user order), then recent pages by *frecency*
  (frequency decayed by recency, half-life 7 days). The current page is always among them and is
  highlighted. A ResizeObserver hides chips that don't fit (never the active one); hidden chips are
  still in the palette. `⌥1`–`⌥9` jumps to the nth visible chip. Hover a chip → a small ★ toggles
  its pin; the trailing **+** opens the palette ("star a page to pin it").
- **When a workflow is active** the same chip row shows the workflow's pages (× to remove, drag to
  reorder, + to add, **Save** when dirty — all the V3.65/V3.66 mechanics, unchanged). The bar gets a
  `top-nav--workflow` tint and the Workflows button shows the workflow's icon + name. There is no
  separate strip component any more.
- **Go to… (⌘K / Ctrl+K / `/`)** is a command palette (`rm/js/nav-palette.js`, lazy-loaded on
  first use, prefetched on idle). Empty query lists Pinned · Recent · This workflow · Workflows ·
  every group. Typing filters label + group + description with a word-start > substring >
  subsequence score, and also matches workflows ("Switch to …"). ↑↓ Enter, ⌘Enter opens in a new
  tab, Esc closes. Each row has a ★ pin toggle. Mode-aware: in the workflow shell a chosen page is
  added to the workflow and shown (ensureFrame handles any registry page); in split view it swaps
  the active pane; everywhere else it navigates.
- **Workflows ▾** replaces the Workflows link, the My Workflows dropdown and the strip's brand
  dropdown: default workflows (accessible ones), My workflows, "+ New workflow", "Manage on Home".
  While active it adds × Leave, + Add page, Save, Open in split. Picking one still opens the
  shell (state preservation + popouts are the point of the shell); inside the shell it switches
  in-place via the existing `rm:shell:switch-workflow` event. Leave in the shell goes to the active
  page's real URL (remembered `pageState` or canonical href) instead of reloading the shell.
- **Home** (`rm/index.html`) stops being a two-tab chooser. One scrolling page: My Lab Today feed
  (existing) → **Jump back in** (pinned + recent tiles) → **Workflows** (existing cards + builder) →
  **All pages** (grouped grid with a filter box and ★ on every tile). `?view=all-pages` still works
  (scrolls to the section and focuses the filter). The nav label "Dashboard" becomes "Home"; the
  page id stays `dashboard`.

## Data

| What | Where | Why |
|---|---|---|
| Recents | `localStorage['rm.nav.recent.v1']` = `{pages:{id:{s,t,n}}, seeded}` | Sync read → chips render before auth; per device on purpose (lab iPad ≠ office desktop). |
| First-run seed | `trackerEntries/{uid}/entries` where `date >= today-30d`, client-filtered `source=='rm-page-time'` | The page-time tracker has logged one doc per page per day since V3.226; owner read is allowed; single-field range query needs no index. Makes the bar useful the first minute after shipping. |
| Pins | `userData/{uid}/navPrefs/pins` = `{pageIds, updatedAt}` + local mirror `rm.nav.pins.v1` | Cross-device, intentional. Covered by the blanket owner rule at firestore.rules:3364 — **no rules deploy**. Defaults when no doc and no local pins: `my-week`, `tasks`, `chat`. |
| Workflow state | `sessionStorage['mcgheelab.activeWorkflow']` | UNCHANGED shape; workflow-shell.js / split-view.js / workflow-state.js keep reading it. |
| Workflows | `labConfig/defaultWorkflows`, `userData/{uid}/customWorkflows` | UNCHANGED; admin matrix untouched. |

Recording happens only in the **top frame** of a real page: not in `rm-embed`/`rm-shell` iframes
(the existing embed check), not on the shell/split host pages, only for URLs that map to a registry
id (path + `?tab`). Deep pages (a specific paper) are not registry pages and are not recorded.

Frecency: on visit `s = s·0.5^(Δdays/7) + 1`; on read `s_eff = s·0.5^(Δdays/7)`.

## Access

Chips carry `data-gate` so `applyNavGates` hides them on a role change, and after `loadAccessGrant`
non-admins lose chips that fail `canAccessPage`. The palette and the home tiles filter with the
same `_navPageAllowed` (the V3.632 `_splitPageAllowed` logic, renamed and shared).

## Mobile app

Every new bar element carries `nav-app-hide`; the app keeps its own tab bar + curated More sheet.
Keyboard shortcuts are inert there.
