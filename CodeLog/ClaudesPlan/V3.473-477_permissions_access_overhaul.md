# V3.473–V3.477 — Permissions & access overhaul

Program that (a) fixes three real access failures a lab member ("gabriel",
role `phd`) hit, and (b) redesigns the admin Permissions page. Shipped as five
releases in one working-tree batch. Ships to the RM tree (FTP) + Firebase
(rules + one new function).

## Why

`gabriel` should have been able to coauthor a paper and annotate library
journals, but was denied on both, and the "make a highlight into evidence for a
paper" workflow appeared broken. Root causes (each pinned to an exact line by
read-only tracing — none was a misconfigured setting):

1. **Coauthor access.** The parent `papers/{paperId}` doc is never created (only
   its Yjs subcollections), so the read rule keyed on `authorUids`
   (firestore.rules) always failed for non-admins, and the subcollection rules
   were hard-locked to `isAdmin()`. A correct coauthor got `permission-denied`
   on editor connect. Side effect: PMR's "Paper writing" block (queries
   `authorUids array-contains uid`) was silently empty for everyone.
2. **Library annotation + claims.** Annotation `create` and claim `create`
   required `isLabContributor()` — an email allowlist (extensionMembers /
   guestEditors) that no RM role grants. A promoted PhD member failed it; the
   UI showed the buttons, then the write errored.
3. **Evidence picker empty.** The reader's "Tag as evidence" draft dropdown was
   filtered to only drafts already linked to the open article via
   `meta.library.linked_drafts` (V3.103). On an unlinked paper it rendered
   "(no drafts)" — by design, not permissions.

## What shipped

### A1 (V3.473) — Paper coauthor access
- New `functions/paper-author-sync.js`: `onDocumentWritten('projects/{projectId}')`
  materializes `papers/{id}` with `authorUids = dedupe(lead + co_first +
  coauthors)` + `title/status/is_library_entry`. Registered in `functions/index.js`.
- `firestore.rules`: new `isPaperAuthor(paperId)` helper; parent `papers/{id}`
  read allows `authorUids.hasAny([uid])`; all Yjs subcollection gates changed
  from `isAdmin()` to `isAdmin() || isPaperAuthor(paperId)` (self-constraints
  preserved; `yjs_snapshot` write + `yjs_updates` update/delete stay admin-only;
  `presence delete` relaxed to own-doc; `snapshots` read+create added for
  authors).
- `admin-permissions.js`: "Recompute paper author grants" button
  (`recomputePaperAuthorGrants`) — one-time backfill that *creates* the parent
  docs for existing papers. Clone of `recomputeAllCollaboratorGrants`.
- Deploy: `firebase deploy --only firestore:rules` + `--only functions:onPaperAuthorSync`, run backfill once, FTP.

Known minor limitations (by design):
- **Restore version** stays admin-only (it wipes `yjs_updates`). A non-admin
  coauthor now sees the "Versions" button (they *can* Save a snapshot), but
  clicking **Restore** returns a permission error rather than a graceful
  "admin-only" message. Not worth editing the hot `paper-editor.js` for; the
  destructive action is correctly gated.
- The Cloud Function clears `authorUids` only when a project *was* a paper
  (checked via `event.data.before.type`), so non-paper project writes
  (courses/tools/infrastructure) never mint phantom `papers/{id}` docs.

### A2 (V3.474) — Annotation/claim creation for lab members
- `firestore.rules`: annotation `create` and claim (`drafts/{id}/claims`)
  `create` changed from `isLabContributor()` → `isLabMember()`. Allowlists stay
  for extension capture + external guest editors.
- Deploy: rules only.
- Known limitation (deliberately deferred, per user): attaching evidence to a
  claim you did NOT create still fails (claim `update` is creator/admin-only).

### A3 (V3.475) — Evidence draft picker
- `library-paper.js`: new `_draftShortlist(linkedIds)` — the evidence/cite
  pickers now list ALL active paper/grant drafts (linked-first via a `linked`
  flag), not only linked ones. New `onEnsureDraftLinked` panel callback
  auto-links the chosen draft on evidence-tag (reuses `LIBRARY_LINKS.toggleDraftLink`).
- `annotation-panel.js`: `_draftSelectOptions` groups "Linked to this paper" /
  "Other drafts"; evidence-save calls `onEnsureDraftLinked`.
- `evidence-tag-dialog.js` (orphaned): `_loadDrafts` unioned with
  `projects/papers.json` for consistency.
- Deploy: FTP.

### B1 (V3.476) — "Everyone" matrix redesign
- `admin-permissions.js` / `.html`: role-grouped collapsible row sections
  (`buildGroupHeaderRow`, `toggleGroup`, persisted `collapsedRoles`); tri-state
  cells grant/baseline/none (`refreshRowStates`, mirrors `canAccessPage`, loads
  `category` for the exact collaborator gate); cell-state legend; density toggle
  (persisted); group-aware filter + visible-only "Select all". Sort dropdown
  repurposed to within-role secondary key. Save pipeline unchanged.
- Deploy: FTP.

### B2 (V3.477) — "Per-user" editable tab
- New `?tab=user` tab: left rail of lab members (pmr.js rail pattern) + right
  panel with **Pages** (editable, reuses `onUserCellChange` + `pendingEdits` +
  `saveAll`), **Papers** (editable coauthor role select + status badge +
  add-to-paper picker; edits join `pendingEdits` as `paper-role`, flushed in a
  new `saveAll` step that mirrors `_onCoauthorRoleChange`/`syncPaperMembers` and
  writes `projects/papers.json` — the A1 trigger syncs `authorUids`), and
  **Derived actions** (read-only capability list from role/ownership/coauthor/
  mentor/annotation gates).
- Deploy: FTP.
