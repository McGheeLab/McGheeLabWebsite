# V3.406 — Layout Mode II R2: washed content + per-type color tints + legend

> Release 2 of 8. Alex: "the text and figures should be washed out so the
> layout pops more. When I make sections or figure blocks or tables
> everything is a different color code to what it is."

## What shipped

- **Wash** (rm/css/paper-doc-view.css, keyed on the existing
  `.pdv-regions-on` class — zero new state): sheet ink mutes to slate
  (`color: #64748b`) and images get `grayscale(.55) opacity(.8)`.
  Deliberately NOT element opacity — that would fade the tints, the
  resize handles, and the selection glow along with the content.
- **Per-TYPE tints applied directly to the elements** (backgrounds +
  inset box-shadows only — never intercept pointer events, pixel-aligned
  for free): figures blue rgba(37,99,235,.10/.30), tables purple
  rgba(147,51,234,…), equations teal rgba(20,184,166,…), paragraphs
  neutral slate rgba(100,116,139,.06), headings amber rgba(245,158,11,.12),
  front matter (title block / abstract / keywords) rose rgba(244,63,94,.08).
  Special sections join the rose family in R7.
- **Column accuracy (Alex's caution):** because tints attach to the
  elements — which live inside the CSS multicol — a 2-col page tints each
  block within its own column; an equation or paragraph never paints a
  false full-width band. Spanning ('full'-item) blocks tint across both.
  Inherent to direct tinting; no overlay geometry involved.
- **Legend** — `.pdv-legend` chip row (Figure/Table/Equation/Text/
  Heading/Front matter) appended to the overlay in `_buildShell`
  (unscaled + unwashed: the wash is scoped to `.pdv-sheet` under
  `.pdv-scale`), bottom-left, pointer-events:none, toggled with the viz
  in `_syncLayoutViz`.
- The `.pdv-regions` overlay keeps margins / column guides / footnote
  strip / float-area boxes exactly as in R3 (V3.399) — the element tints
  complement it (the region box shows the RESERVED band area; the tint
  shows the block itself).
