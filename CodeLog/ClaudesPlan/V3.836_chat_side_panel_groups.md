# V3.836 — Chat side panel: open further, close, frozen header, and groups anyone can make

**Date:** 2026-10-22 (re-checked version/sw right before claiming: V3.833 / sw 814 were the parallel session's)
**Alex:** *"chat side menu needs some revision: currently when we click on the tab it opens the last
active chat, i need a side tab for open further to reveal people, groups etc. another button to close the
chat pannel. the top of the chat should have the top buttons as a frozen pannel the chat text goes behind.
anyone should be able to make groups of people as a special group and we need a easy way to combine
multiple people from the chat into a group."*

## What is wrong today

- The Chat popout (`shell-popouts.js`, page mode since V3.810) opens an iframe of `chat.html?embed=1` at
  460 px. Inside, chat.js sees a width ≤ 700 px and renders its **phone** layout: a tab bar
  (Overview · Chat · Files · Search), the "Lab Chat" page title, and the document as the scroller. The
  conversation list is the "Overview" tab — not a side tab, and not discoverable as "people, groups".
- The channel header is `position: sticky` against the **document** scroll. In the iframe that works only
  while nothing clips it; the composer is `position: fixed` (≤ 640 px) and the page title scrolls. Alex
  wants the header buttons frozen and the messages scrolling **behind** them: a true pane.
- Widening the popout past 700 px would silently flip chat into its desktop layout (own sidebar) —
  `isMobile()` is width-based.
- Groups do not exist. Channels are public (`#name`, subscribe), DMs are 1:1. `createDM` accepts several
  uids, but every "find the DM with this person" lookup matches *any* DM whose members include both of us,
  so a multi-member DM would hijack the 1:1 rows. Only chat admins can change a channel's membership
  (`chatChannels` update rule).

## Design

### 1. Host: three-state popout with side tabs (`rm/js/shell-popouts.js`, `rm/css/workflow-shell.css`)

State per side gains `<side>Wide`. The open-state pill becomes a vertical **side-tab cluster** at the
viewport edge (same anchor as before):

- **Open further** — toggles `wide`: the panel grows by 300 px and the iframe is told
  (`postMessage {type:'rm-popout-state', open, wide}`). The iframe may name the tab
  (`{type:'rm-popout-caps', wideLabel, wideIcon}` → chat says "People & groups" / `user-group`).
- **Close** — `togglePopout(side, false)`; the header ✕ stays too.

Width = stored base width + (wide ? 300 : 0); dragging while wide stores base = total − 300. The wide
toggle never rebuilds the iframe (a rebuild would reload chat). Iframes can ask the host:
`{type:'rm-popout-request', wide:bool}` (chat collapses the list after you pick a conversation),
`{close:true}`, `{state:true}` (send me the current state — chat asks at boot). Same-origin only; the
side is identified by `e.source === iframe.contentWindow`.

### 2. Chat panel mode (`rm/js/chat.js`, `rm/css/chat.css`)

`_IS_POPOUT` = `window.name` starts with `rm-shell-popout-` (the host names its iframes). Panel mode is a
third shell mode, **independent of width**: `isMobile()` returns false, `renderShell()` mounts

```
.chat-panel
  aside.chat-panel-list        ← the conversation list (channels, groups, people), hidden unless wide
  section.chat-main.chat-panel-main
    .chat-sticky-top            ← FROZEN: call banner + channel header + Messages/Pinned/Files tabs
    #chat-content-slot          ← feed scrolls INSIDE (.chat-feed flex:1 overflow-y:auto) + composer
  #chat-thread-slot             ← overlay
```

reusing the desktop region updaters (`updateHeader/updateViewTabs/updateMainContent/updateThread`). The
feed is the scroller (already supported: `feedAtBottom`, `pinFeedToBottom`, the feed scroll listener);
`renderMessages` now keeps the distance-from-bottom when older messages are prepended into an internal
scroller. `html/body` lose their scroll, the page title is hidden, the composer is static. The header's
☰ button (dead `#chat-hamburger` until now) asks the host to open/close the list. No active
conversation → the panel asks the host to open wide so the list is the first thing you see.

### 3. Groups (`type: 'group'` on `chatChannels`)

```
{ name:'group-<slug>-<rand>', displayName, type:'group', createdBy, members:[uids], subscriberUids:[same],
  memberCount, description:'', category:'', isDefault:false, isAnnouncement:false, pinnedMessageIds:[],
  lastMessage:null, lastActivityAt, messageCount:0, createdAt }
```

- **Who:** any non-readonly chat user (create rule's non-DM branch already allows it; the hunk adds
  "the creator must be in `members`"). **Update:** new rule clause — a *member* may change
  `members / subscriberUids / memberCount / displayName / description` (rename, add, remove, leave);
  identity fields stay frozen by `hasOnly`.
- **Delivery:** the Cloud Function's non-DM path reads `subscriberUids`, so push and mention fan-out work
  unchanged (title shows `#Name` for now — functions untouched this turn). `healDmMemberships` also adopts
  groups I'm in into `subscribedChannels`, so a member added by someone else sees the group on their next
  channels snapshot. Alerts: group → `members` includes me. Calls: group → `members`.
- **Where they show:** a **Groups** section in the conversation list (panel list, phone Overview) and the
  desktop sidebar, with unread badges; excluded from Browse Channels; header shows `👥 Name · N members`,
  a **Members** button (edit/rename/leave), no Subscribe toggle. 1:1 DM lookups now require
  `members.length === 2`.
- **Easy combine:** the People section gets **Select** — rows become checkboxes, a bar at the bottom says
  "N selected · Create group". Create opens the group form with those people pre-checked (name + search +
  checklist, inline error, no browser prompts). Also: a DM header's **Make a group** pre-checks the other
  person; **＋ New group** in Groups, the desktop sidebar, and the phone menu.

## Decisions

- Panel mode keys off the **popout iframe name**, not `?embed=1`: split-view panes and the workflow shell's
  main frames keep their width-based layouts (they are wide; nothing changed for them).
- Picking a conversation from the list **collapses** the list (it is a picker, not a sidebar); Select mode
  keeps it open. One line to flip if Alex prefers it to stay.
- Groups are a channel **type**, not multi-member DMs: DM lookups are keyed by person, and the function's
  DM path would title pushes with the author instead of the group.
