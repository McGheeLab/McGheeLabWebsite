# V3.769 — Teaching hub split into four tabs

## Goal

Alex: *"the current teacher hub is hard to navigate, lets split everything up
we can do here into tabs."* Four tabs, specified as:

1. **Dashboard** — read only, with links to the right tab. An overview of
   current modules assigned, dates for engagement, students enrolled etc.
2. **Students** — student enrollment, send invites, monitor student progress.
3. **Modules** — module review: preview learning modules and assign them.
4. **Engagement** — give time and date availability, student size expected
   and student level.

## Problem

V3.669-673 grew the hub one release at a time and it showed. Navigation was
three surfaces deep and split across two pages:

- `#/teach` was a **class-list page** you had to pass through every visit.
- Each class then drilled into **five tabs** (Modules / Assignments /
  Gradebook / Engagement / Students) whose names described the *code* that
  built them, not the job a teacher came to do — "Engagement" meant student
  module-time, while the outreach hub of the same name lived somewhere else.
- The **engagement hub** was a separate page (`#/engage`) reached from a card,
  so classroom availability was never next to the class it belonged to.
- A persistent head card (join code, enrolment toggle) sat above every tab
  whether or not it was relevant.

There was also no overview anywhere: nothing answered "what needs me today?"

## Approach

**One tab bar, one class, one load.**

- `wireTeachPage` resolves the class from the URL or, with none, picks the
  **most recent** class; a **class switcher** in the header reaches the
  others and the Dashboard lists them. The class-list page is gone — the
  thing it did is now a `<select>`.
- `loadHub(schedule)` fetches the teacher's world **once** (join codes,
  roster, assignments, submissions, module stats, engagement requests — all
  teacherUid-keyed, which is what the list rules can prove) and every tab
  renders from that one snapshot. Fewer reads than the old per-tab fetches,
  and the **tab badges** (ungraded submissions, pending visit requests) can
  never disagree with the tab they point at. Any mutation calls
  `ctx.refresh()`, which re-reads the schedule too (module edits live on it).
- Old tab names stay valid through `TAB_ALIASES` (`gradebook`→students,
  `assignments`→modules, …) so V3.671's submission notification deep link
  (`/#/teach/{id}/gradebook`) still lands somewhere sensible.

**Tab 1 — Dashboard** (`renderDashboardTab`), strictly read-only (asserted:
zero inputs/selects/textareas in the tab body): four stat tiles that are
links; a **Needs your attention** list (ungraded work, waiting visit
requests, quiet students, no join code, closed enrolment, no modules) where
each row carries the button that fixes it; a **Coming up** list merging
module due dates, assignment due dates and confirmed visits into one
chronology; **Class access** (code + link, read-only); and **Your other
classes**.

**Tab 2 — Students**: enrolment controls (code create/regenerate/disable,
enrolment toggle) moved down from the old head card; a new **invite block** —
class link, code, copy buttons, "Copy joining instructions", and an
**email composer** that builds a `mailto:` with the addresses in **BCC** and
the three joining steps pre-written (mailto because this project has no
outbound mail server by design). Then the roster, which now merges the old
Students tab with the old Engagement tab: each student row shows last-active
(quiet >7 days flagged), modules touched, minutes, assignments handed in,
and expands to per-module progress bars **and** the per-student overrides.
Gradebook follows in the same tab.

**Tab 3 — Modules**: assigned list (order, due date, visibility, remove) then
the **module library** with **inline preview** — the real lesson in an iframe,
built **on first open** rather than rendered with the row (the library runs to
~70 modules; 70 dormant sandboxed iframes are a heavy DOM and two console
warnings each for a preview nobody opened). Previewing records nothing: it is
not the class module-viewer route, so the V3.672 engagement beacon never
fires. Course assignments move here too, behind a `<details>` for the create
form, since "what work is set" belongs with "what modules are set".

**Tab 4 — Engagement**: the teacher side of the hub is **mounted from
engage-hub.js** (`ML.mountEngageTeacherPanel`), not rebuilt — `#/engage` and
this tab are one implementation and cannot drift. `renderTeacherHub(root,
opts)` gained `embedded` (skip its own page header), `classHint` (pre-fill a
new slot's class context from the class being managed) and `onChange` (refresh
the host after a mutation so the tab badge keeps up). The slot fields are
relabelled to the words Alex used: **Student level** and **Expected
students**, pre-filled from the listing.

## Files

- `teacher-teach.js` — the four-tab shell replaces the class-list page and the
  five-tab drill-in (~740 lines out, ~900 in); `#/teachers` landing untouched.
- `engage-hub.js` — `renderTeacherHub(root, opts)` + `ML.mountEngageTeacherPanel`;
  slot labels/pre-fill.
- `styles.css` — tab badges, class switcher, dashboard tiles/lists, invite
  block, on-demand preview, mobile tab-bar scroll.
- `teacher-demo.js` — the "2 classes, 15 students" persona now opens `#/teach`.
- `sw.js` — CACHE_VERSION 740 → 741.

## Out of scope

No data-model change, no new collection, **no firebase deploy** — this is a
navigation rebuild over the V3.669-673 backend. Per-student invite tokens
(still one class code, per Alex's V3.669 decision); drag-and-drop module
ordering (arrows stay).

## Deploy

FTP only, in the batch. No rules / indexes / functions.

## Rollback

Previous `teacher-teach.js` + `engage-hub.js` + `styles.css`. Nothing written
differently, so no data to unwind.

## Verification (all run headless against the demo fixtures)

1. Four tabs render with badges (Students 2 = ungraded, Engagement 1 = pending).
2. Dashboard: tiles read "10 students enrolled / 17 modules assigned /
   2 assignments open / 1 engagement visit"; attention list and Coming up
   populate; **zero edit controls** in the tab body; other-classes strip present.
3. Students: link + code + roster (11 rows) + progress and settings panels +
   gradebook; typing two addresses flips the compose button to "Compose invite
   to 2 students" and puts both in BCC.
4. Modules: **zero iframes** in the DOM before a preview is opened, exactly one
   after; button flips to "Hide preview".
5. Engagement: panel mounts with **no second page header**; labels read
   "Student level" and "Expected students"; confirming the pending request
   drops the tab badge and keeps you on the tab.
6. Old deep links: `/gradebook` → Students, `/assignments` → Modules.
7. Phone width (390px): zero horizontal overflow on all four tabs; tab bar scrolls.

Note: a COLD load of any AUTH_GATED route sits on app.js's V3.332 auth spinner
until Firebase resolves — pre-existing, not from this change (verified: the
same navigation renders fully once auth has settled).
