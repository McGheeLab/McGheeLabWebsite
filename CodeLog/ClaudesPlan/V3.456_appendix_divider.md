# V3.456 — appendix divider replaces the per-section § buttons

> Test feedback on Paper Builder III (fix 4 of 7): "I don't like the appendix button
> being on every section, it just adds clutter. This should be a special document
> splitter that the user can place and drag or move up and down."

## Design

**The model is unchanged** (`appendix` boolean on the section Y.Map). Critical
simplifier discovered in exploration: BOTH consumers already treat the first flagged
section as a one-way boundary — export emits `\appendix` once before it
(paper-export-tex.js) and the doc-view numbering walk flips `inAppendix` once and never
back. So one divider is the honest UI for the model that already existed;
paper-export-tex.js, the doc-view numbering, and paper-schemas.js are untouched.

The UI normalizes to **exactly one flagged section = the boundary**: placing/moving the
divider transacts `appendix` true on the target section and deletes it everywhere else
(also cleans legacy multi-flag docs — harmless before, since consumers stopped reading
after the first flag).

## Files

- **rm/js/paper-editor.js**
  - Per-section `apxBtn` block DELETED from `renderSection` (the clutter).
  - `_appendixBoundaryIdx(sections)` → first flagged index (or -1);
    `_setAppendixBoundary(targetIdx|null)` → single transact, origin `appendix-divider`.
  - `renderMain` inserts a `.pe-appendix-divider` bar before the boundary section:
    "§ Appendices start here" + ▲ (boundary to previous) / ▼ (to next; past the last =
    remove) / ✕ (clear). The section-map observers already trigger a full `render()`
    on scalar changes, so the bar re-places live for local and remote edits.
  - `§ Appendices` placer button beside `+ Add section` (declared `pe-appendix-btn`;
    hidden while a divider exists; places the boundary before the LAST section).
  - Public API: `getAppendixBoundaryIdx()` / `setAppendixBoundary(idx|null)`.
  - Known quirk (documented in the bar's tooltip): moving the boundary SECTION itself
    carries the divider with it; moving any other section across the divider moves it
    in/out of the appendices (position-based) — the bar re-renders immediately either
    way.
- **rm/pages/paper-builder.html** — the `#pe-appendix-btn` button in the outline
  sidebar actions.
- **rm/js/paper-doc-view.js** — `_openInsertMenu` gains an "Appendices" group with a
  `§ Appendix divider` item (greyed "already placed" when one exists; placement lands
  before the last section; the write page's bar is the move surface).
- **rm/css/paper-editor.css** — `.pe-appendix-divider` (dashed rule + label + ctrls);
  `.pe-section-apx-btn*` rules removed (no consumers remain).

## Verification

- `node --check` clean (paper-editor.js, paper-doc-view.js); CSS balanced; suite 347
  green (no tex/schema changes).
- Browser (Alex): legacy doc with several flagged sections shows ONE divider before the
  first; any ▲▼/✕ interaction normalizes to single-flag; `§ Appendices` places the bar
  before the last section and the button hides; doc view numbering flips to A./B. below
  the bar; compile emits `\appendix` at the divider; moving a section across the bar
  changes its zone; ✕ restores plain numbering everywhere; section headers no longer
  show § buttons.
