# V3.971 — Scientia: websites as a component, saved as they are

**Date:** 2026-11-10 · **Branch:** `scientia/web-capture` · **Gabe:** "I want to be able to add websites as a component, and should
behave like a PDF/HTML viewer. The website should not be visited, but instead saved as a mere copy of what that webpage is, so that
if it ever gets taken down, then it will remain in the note as it was the moment it was captured."

## Approach

A browser cannot read another site's page, so the capture runs on the app's server: `serve.py` on the computer that runs the app,
for it and the devices paired with it. `webcap.py` (standard library only) fetches the page once and writes one self-contained
HTML file into the notebook's `images/`, as any media file. The component is then an ordinary HTML page component (13g, with 13zw's
quoting and 13zze's snips and ink labels) or a PDF component, carrying `web { url, final, title, at, size, missing, icon }`.

- **Never visited again:** the site's scripts, frames and media sources are taken out, and a Content-Security-Policy in the copy
  forbids any request to the network (`default-src 'none'`; `data:` and `blob:` for images, fonts and media; inline styles and
  scripts, so the app's own injected scripts still run). Tested: the Wikipedia copy shows its six pictures with zero network
  requests.
- **Who may capture what:** http(s) only; loopback, link-local and multicast refused always; private and other non-global
  addresses only from this computer itself, so a paired device cannot reach this computer's own services through it; each redirect
  is checked again.
- **Small answer:** the file goes straight to `images/`; the answer carries only its facts. Sending the whole page back to the
  app was reset now and then by `serve.py` on Windows. The same happened once in ten for the 5 MB app page, so it is older than
  this change; it is noted for a separate look.
- **Capture again** makes the next version on the deck (V3.967/V3.970), the earlier copy beneath.
- **The lab website:** the hub has no capture route and answers 404; the app says the capture needs the computer, and a page saved
  there arrives with the sync. A capture route in the hub (a Cloud Function fetching arbitrary addresses) would need its own review.
