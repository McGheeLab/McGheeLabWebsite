# V3.373 — Block typing (layout R3)

> Plan: robust page-layout segmentation, R3 of 5 (2026-07-14).

## Change

- **`PAGE_LAYOUT.classifyBlocks(blocks, items, {pageWidth,pageHeight})`**
  ([rm/js/page-layout.js](../../rm/js/page-layout.js)): deterministic
  feature-based decision list (no ML) → `block.type` ∈ {body, heading,
  abstract, keywords, caption, footnote, sidenote, header, footer,
  pagenum}. Features: y-band (top/bottom page margins → header/footer/
  pagenum), median height vs body median (small → footnote/caption), width
  vs page width, item count, and keyword anchors (Abstract / Keywords /
  Fig.|Table|Scheme|Supplementary / References…). `segmentPage` calls it
  and stamps `it.blockType` on every item.
- **Furniture-skip in the selection clamp**
  ([rm/js/geom-selection.js](../../rm/js/geom-selection.js)): a cross-block
  body drag now drops items whose `blockType` ∈ `FURNITURE_TYPES`
  (header/footer/pagenum/caption/footnote/sidenote) unless an endpoint is
  itself in that furniture (selecting the caption still works). Same-
  cluster drags are unaffected.

## Honest scope

Typing is a foundation; it does NOT fix the 02/04/05 fixtures on its own —
verified (node) that on those pages the furniture is **merged into body
clusters at segmentation** (`{footer,body}`, `{footnote,body}`,
`{header,body}`), so the merged cluster types as `body` and there's nothing
for the furniture-skip to drop. Typing delivers value on cleanly-clustered
pages (headings/captions/abstract as their own blocks) and gives the clamp
the skip capability for when R5 peels furniture into its own clusters.
Strictly safe: same-cluster selections never filter by type; a mistyped
block only affects cross-block drags (drop, not corruption).
