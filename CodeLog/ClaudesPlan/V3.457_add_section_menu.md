# V3.457 — "+ Add section" becomes a typed dropdown

> Test feedback on Paper Builder III (fix 5 of 7): "adding new sections is not great —
> it should be a dropdown list of typical section types, and a custom one that the user
> can add their own labeling to."

## What changed

`addSectionPrompt` (rm/js/paper-editor.js) was two stacked `window.prompt()`s (type a
kind string from a comma list, then a title). It is now an anchored popover menu —
the function keeps its name, so both existing wire-ups (the outline sidebar's
`#pe-add-section-btn` and the empty-state "+ Add a section") work unchanged:

- **Body sections** — abstract, keywords, introduction, background, methods, results,
  discussion, conclusions, acknowledgements (labels from `SECTION_KIND_LABELS`, e.g.
  methods → "Materials and Methods"). `references` is omitted (autoGenerated).
- **Submission documents** — cover letter / suggested reviewers / response to reviewers
  (same kinds the S-α work registered; the 📨 banner and manuscript exclusion apply as
  before).
- **Custom** — inline title input + Add (Enter submits) → `kind: 'custom'`.
- One-per-paper kinds (abstract, keywords, acknowledgements, the three submission docs)
  grey out with an "already added" note when present; body kinds stay repeatable.
- Picks call the existing `addSection(kind, label)` and scroll the new section into
  view. Esc / outside-click closes; the menu flips above the anchor near the viewport
  bottom.

CSS: `.pe-addsec-menu/-head/-item/-note/-custom` in rm/css/paper-editor.css
(fixed-position card, z-index 3600).

## Verification

- `node --check` clean; CSS balanced; suite 347 green.
- Browser (Alex): + Add section opens the menu; Methods → creates "Materials and
  Methods" and scrolls to it; abstract greys out once present; Custom + typed title +
  Enter creates it; Esc/outside click closes; empty paper's "+ Add a section" opens the
  same menu; no `window.prompt` in the flow.
