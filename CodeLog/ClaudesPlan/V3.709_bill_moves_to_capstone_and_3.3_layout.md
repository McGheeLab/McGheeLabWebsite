## 2. §3.3's layout

**What was odd:** two full-width canvases stacked, the upper one a 660×200 banner
holding a single tube on the far left with 60% of its area empty. AUTHORING §4 asks for
"a physical-picture canvas *beside* a plot canvas" and this was neither — it was a
picture canvas above a plot canvas, both too wide for what they held.

Rebuilt as a `.chart-row` (CSS already present), **both canvases authored at the same
460×320 aspect** so the row is not ragged — a grid row whose two cells resolve to
different heights is exactly the raggedness that made the old version look unfinished.

The picture was redesigned for the narrower frame, vertically stacked, everything on one
left margin:

1. **the tube rank** — left-aligned, width capped so it never exceeds 55% of the canvas,
   so the column beside it always exists;
2. **the arithmetic** in that column — on the bench / used / reaches a cell, the last one
   coloured by verdict;
3. **a key** (used / binned / back in the fridge) replacing the annotation that used to
   float to the right of one tube;
4. **the consequence, as a bar** — sessions the stock still gives you, one tick per
   session where the ticks are ≥ 5 px apart, green when nothing is lost.

That fourth element is new and is the point of the redesign: "26 of 50 sessions — 24
lost to what stays in the tube" was a stat row, and is now a picture.

Chart changes: margins tightened for half-width (`l:56 r:14 t:20 b:54`); the m-band
labels **measure themselves and fall back to the bare number** when their band is
narrower than "3 tubes"; legend text shortened.

Stats reworked so the box complements the picture instead of repeating it. "Reaches a
cell" is in the picture in colour, so its row became **"Exact fit — 10.0 mL ·
1/session"**: the actionable answer, which previously only ever appeared buried in a
verdict paragraph.

## A harness gotcha worth recording

`python3 -m http.server` sends `Last-Modified` and the headless browser **honours it**:
two consecutive renders after an edit returned the identical old picture, and I read a
stale screenshot as a failed fix. Append a cache-busting query (`?v=$(date +%s)`) to
every render after an edit — the failure mode is a screenshot that looks like your
change did not work.
