# V3.818 — FTP automatically at the end of every Claude turn

**Date:** 2026-10-21
**Ask (Alex):** "every time we make changes to the site, please ftp automatically" → "test it"

## Decision: the trigger is the END OF A TURN, not every edit

A feature is several files. Uploading after each `Edit` would put half-edited
states on the live site (an HTML page that calls a function the not-yet-saved
JS doesn't have). Claude Code's `Stop` hook fires when Claude finishes a
turn — the point at which the working tree is meant to be consistent — so
that is where the upload runs. Alex's own VS Code edits are not covered
(there is no Claude turn); ⇧⌘B remains the one-key upload for those.

## Mechanism

`.claude/settings.json` → `hooks.Stop` → `python3 scripts/deploy.py autodeploy`
(timeout 900 s). `cmd_autodeploy()`:

1. Kill switches: `MCGHEELAB_AUTODEPLOY=0` or `"autoDeploy": false` in
   `deploy/site.json` → exit silently (use during a live lecture: V3.775).
2. Hash the site, diff `deploy/manifest.json`; nothing changed → exit
   silently (~0.3 s, so the hook costs nothing on ordinary turns).
3. **Gate**: `node --check` every changed `.js`/`.mjs` (an ES module saved as
   `.js` is re-checked as `.mjs`), `json.loads` every `.json`. ANY failure
   holds the WHOLE upload and reports the file + the real error line — a
   feature ships whole or not at all. It retries at the next stop.
4. `sw_warning()`: a changed file is in `sw.js SHELL_URLS` but `sw.js` is not
   among the changes → append a warning (installed-app users keep old copies).
   `rm/` and `modules/` are network-first in the SW, so only root shell files
   trigger it.
5. `cmd_ftp(yes=True)` → `verify` → one JSON line on stdout:
   `{"systemMessage": "Deployed N file(s) to mcgheelab.com via …"}`.
   Everything else goes to stderr so the hook's stdout stays parseable.
6. No TTY: `get_password()` raises instead of calling `getpass` (a prompt in
   a hook would hang until the timeout). Password order is unchanged:
   `MCGHEELAB_FTP_PASSWORD` → Keychain (`security find-internet-password`,
   macOS asks **once** — *Always Allow*) → prompt (interactive only).
7. Always exits 0; a failure is reported in the message, never blocks Claude
   from stopping, never loops.

## Interaction with the release ritual (CLAUDE.md)

- **FTP is no longer a batched manual step.** The *announcement* (ledger →
  `release_push.py` → 📣 Send) and the phone build stay batched at 5+.
- The per-change `sw.js CACHE_VERSION` bump matters MORE now: a change goes
  live within the turn, so a missed bump reaches installed apps immediately.
  The hook warns when it detects one.
- Backend deploys (rules/indexes/functions) are unchanged — and they must
  go out BEFORE the client edit is made, because the client edit is live at
  the end of the turn. Sessions must order their work accordingly.
