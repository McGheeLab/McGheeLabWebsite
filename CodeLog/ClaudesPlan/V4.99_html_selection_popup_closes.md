# V4.99 — Scientia: an HTML page's selection popup closes on a click outside, like a PDF's

## Why
Gabe, 20 Nov: "Clicking out of a highlight in HTML removes the popup, just like in PDF."

Select words in a PDF and a small menu opens (a structure, a colour, Quote, Connect to…, Make it…). Click anywhere else and it closes: it is a `popover()` (08-ui) and one `mousedown` listener on the document closes it for a click outside. An HTML page runs in a sandboxed iframe, and a click inside a frame never reaches the app's document, so the same menu stayed open until you used it. Every HTML page — a note's page card, beside the note (reader dock), maximised, in a popup window, a captured web page (an html component) — is one frame built by `EMBED.frame` and filled by `QUOTE.fill` (13zw), with one reporter script and one `sel` message handler, so one change covers all of them.

## What changed
- **One rule, shared** (`08-ui.js`): the document's `mousedown` listener is now `popAway(target)`, the same call a PDF's click makes.
- **The page tells the app** (`13zw-quote.js`, the reporter script in the page's copy): a `pointerdown` anywhere in the page posts `away`; a highlight that goes (it was there, now it is not: a click on the same words, the app clearing it) posts `away` with `gone`; Esc is always posted (it used to be sent only while words were highlighted). The app answers `away` with `popAway(frame)`: the menu closes unless the click was in the menu.
- **Esc** closes the menu (the highlight stays).
- The menu's own buttons are not "outside": a click on ❝ Quote or a structure still works.
- **Settings → Reading → Selection popup** (`selpop`, `20a-features.js`): *A click outside the highlight closes the menu* and *Esc closes the menu* (both on), with a live preview. Off: an HTML page's menu stays until used, as before (Esc still closes it). A PDF's behaviour is unchanged.
