# V3.455 — section status pill: Editing / Completed / Needs revision

> Test feedback on Paper Builder III (fix 3 of 7): "on the top of each section there is a
> pill that says complete and at first glance it looks like it means that we already
> marked that section as complete. That button should say 'editing section' and be in
> yellow, then when we click on it it should say 'completed section!' and be in green.
> The first author or PI can mark the section as 'needs revision' and that's in red."

## What changed

The V3.369 "✓ Complete" ACTION button (green while the section was still draft — the
misread) becomes a STATE pill that reflects where the section is and advances on click:

| status (Y.Map) | pill | lock | click → |
|---|---|---|---|
| `draft` | amber `✎ Editing section` | unlocked | complete |
| `complete` | green `✓ Completed section` | locked (`completed_at`, final form — unchanged mechanics) | reopen (draft) |
| `needs-review` | red `⚑ Needs revision` (tooltip: who/when) | unlocked | complete |

**⚑ send-back button** beside the pill — rendered only for
`firebridge.isLeadAuthor(state.meta) || firebridge.isAdmin()` (lead author = papers.json
`lead_author_uid`; the PI's `pi` category maps to the admin role) and only when not
already in needs-review. Sets `needs-review` + `revision_by`/`revision_at`, and unlocks
a completed section.

**Zero schema changes:** `'needs-review'` was already in `PaperSchemas.BLOCK_STATUSES`
(shared vocabulary with block pills), so `normalizeTree` passes it and status copies
verbatim through every tree path.

## Files

- **rm/js/paper-editor.js** — `_setSectionCompleted(id, bool)` generalized to
  `_setSectionStatus(id, status)` (one transact, origin `section-status`; complete sets
  `completed_at/completed_by`, needs-review sets `revision_by/revision_at`, each state
  clears the others' extras); pill + ⚑ in `renderSection`'s actions row; red
  `pe-revision-banner` under the header (read-only viewers see it too);
  `revision_by`/`revision_at` added to all three tree round-trip functions
  (`appendSectionFromTree` / `sectionMapToTree` / `hydrateSectionFromTree`) so a section
  move preserves the flag.
- **rm/css/paper-editor.css** — `.pe-section-status-pill` + `-editing` (amber
  #fef3c7/#92400e) / `-complete` (green #ecfdf5/#047857) / `-revision` (red
  #fee2e2/#b91c1c) variants; `.pe-section-flag-btn`; `.pe-revision-banner`. Old
  `.pe-section-complete-btn*` classes removed (no other consumers).
- Block-level `.pe-status-pill` (paper-blocks.js) untouched.
- Harness: the three round-trip tripwire regex windows in test-section-tex.js widened
  900→1400 chars (the revision fields legitimately grew the blocks the tripwires span).
