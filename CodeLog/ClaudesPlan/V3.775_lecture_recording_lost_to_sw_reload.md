## Root cause 1 — the recording: a service-worker update reloads every open tab

`index.html` registers `sw.js` and:
- calls `reg.update()` every 30 minutes **and on every `visibilitychange` to visible** (switching
  back from Cyberduck to the browser is enough);
- on `controllerchange` does `location.reload()`;
- `sw.js` calls `self.skipWaiting()` in `install` and `clients.claim()` in `activate`.

The browser also runs its own update check after any in-scope **navigation** the worker handles —
and a simulation page is an `<iframe>` navigation into `/modules/**`, which `sw.js` serves
network-first since V3.738. So the moment the 4.0.1 page was added (10:01:47), 29 s after the new
`sw.js` landed, the worker updated, took control, and index.html reloaded the recorder tab.

The reload is invisible to the room: the board comes straight back (maximize, follow and leader
state are all persisted), the live flag still names the recording, and the recordings list says
"Recording now" because `r.id === liveRecId`. Only the 🎙 timer badge disappears — nothing says
*this tab was the recorder and is no longer recording*.

## Root cause 2 — the simulation: an ordinal fallback that counts the pretest

`resolveSimRef("4.0.1")` looks for a lesson whose filename starts `0*4[a-z]?[-_.]`. During the
lecture the class listed `hw-00-pretest, 01, 02, 03` — 04c was not on the list yet — so the prefix
search failed and the fallback `lessons[n - 1] = lessons[3]` returned **module 03**. The page was
labelled `4.0.1` (the ref is the typed number) but its `src` was
`03-binding…?embed=0.1&sim=1` — "A cell in a gradient", i.e. 3.0.1. Confirmed by the recorded
`add-page` event payload. V3.774 had fixed the `04c-` prefix match that morning, but the fallback
itself is what fired, and it fires whenever a module is missing from the list *or* the list has a
non-lesson (the pretest) ahead of the numbered lessons.

## Fix (this version)

1. **index.html** — `lectureRecording()` (= `window.Whiteboard.isRecording()`) gates all three:
   the 30-minute `reg.update()`, the visibility `reg.update()`, **and the `controllerchange`
   reload** (the browser-initiated update can't be prevented, so the reload gate is the one that
   matters). A held-back reload sets `window.__swReloadDeferred`; `stopRecording()` toasts
   "A site update was held back during the recording — reload this page when convenient."
2. **whiteboard.js — lost-recording detection.** The recording doc's `recorderClientId` is a
   per-tab `sessionStorage` id, which survives the reload that destroys `REC`. On each schedule
   snapshot, when the board is live with a `recId` and `REC` is null, read that recording once:
   `status === 'recording'` and `recorderClientId === recClientId()` ⇒ `S.recLost = recId`, a red
   **🎙 Recording lost — record again** button replaces the badge, plus a toast. Tapping it
   finalizes the orphan (below), starts a new recording from this tab's mic (the tap is the
   gesture), and points `liveWhiteboard.recId` at it. The lecture becomes two recordings rather
   than one and 42 minutes of silence.
3. **whiteboard.js — `finalizeInterrupted()` rebuilds the timeline from the ink.** Duration is the
   LAST of audio chunks / recorder events / stroke `t1` (+3 s), never 0. Pages the recorder never
   saw get `add-page` 2 s before their first ink; page flips after the last recorded event are
   inferred wherever consecutive strokes change page (`synth: 'ink'` marks them). Erases already
   ride the strokes' own `erasedAt`. Audio that never uploaded stays lost — nothing can change that.
4. **whiteboard.js — `arming`.** The remote-end check (`stopRecording('remote-end')` when the flag's
   `recId` ≠ ours) had a latent race: a schedule snapshot between `startRecording()` and the flag
   write would kill a brand-new recording. `REC.arming` is true until the flag write lands.
5. **whiteboard.js — `resolveSimRef`.** The ordinal fallback only applies to a class whose lesson
   filenames carry no numbers. Otherwise a missing module is an error that names what IS listed:
   *"Module 4 is not in this class's Learning Modules list (listed: 1, 2, 3). Add it on the class
   page first."*

## Recovery of the 2026-09-15 recording

- **Audio:** not recoverable. It never left the tab. There is no Storage object, no server log, no
  browser cache for MediaRecorder buffers.
- **Ink:** fully recoverable — 2,645 strokes with `t0/t1` on 17 pages, 09:45:04 → 10:43:51. The
  read-only script `repair_recording_analyze.py` (session scratchpad) produced a 21-event plan:
  `remove-page` for the deleted sim page, `add-page` + `page` for the 10 pages the recorder never
  saw, `durationMs 3541475` (59.0 min). `repair_recording_commit.py` applies it through the
  Firestore REST API with Alex's gcloud credentials (IAM, bypasses rules). **Not run — writes to
  production need Alex's go-ahead.** After it runs, ▶ on "Week 4 Lecture 1 — Sep 15" replays the
  whole lecture's ink with no audio ("No audio was saved with this recording — replaying the ink
  only.").
