# V3.140 — Fix toolbar reference buttons silently no-op'ing

## The bug

User report: "when I have my cursor in a paragraph and i want to put an
inline equation, reference or anything in the paragraph, i try to click
on one of our buttons to put one in, and i click on one of them and
nothing happens."

## Root cause

The V3.120/V3.136 toolbar reference buttons (`+ Inline Eq`, `+ Cite`,
`+ Eq`, `+ Fig`, `+ Table`) save the caret on **mousedown** via
`_saveCaretFromCurrentFocus()`, which only succeeds when:

```js
var active = document.activeElement;
if (active && active.isContentEditable) {
  _state.savedEl = active;
  _state.savedRange = sel.getRangeAt(0).cloneRange();
}
```

In several common situations `document.activeElement` is *not* a
contenteditable when the user clicks the toolbar:

- Fresh paper, paragraph never clicked into → focus is on `<body>`.
- User opened the side panel and clicked something there → focus moved
  to the panel.
- User clicked the title input or section label → focus is on a regular
  `<input>`.
- Browser stripped selection on some other interaction.

In all these cases:
1. `_state.savedEl` stays `null`.
2. The toolbar action fires (e.g. `_openInlinePicker`); the picker opens.
3. User picks a row → `_insertAtSavedCaret(text)` runs → hits
   `if (!el || !range) { console.warn(...); return; }` and silently
   no-ops.
4. From the user's perspective: button click → nothing visible →
   "broken."

For `+ Cite` the failure mode is even worse: `openCitationPopover({
anchorEl: null })` either centers the popover or doesn't open it at
all, depending on what `_state.savedEl` was last set to.

## The fix

Two layers of defense:

### Layer 1: caret-save fallback

`_saveCaretFromCurrentFocus()` now tries three things in order:

1. **`document.activeElement.isContentEditable` + selection inside it**
   (existing path — works when the user clicked the button immediately
   after typing in a paragraph).
2. **`document.activeElement.isContentEditable` + no selection** — the
   user clicked into the paragraph but the selection got stripped
   somehow. Build a collapsed range at the end of the element so the
   picker still has somewhere to insert.
3. **PaperEditor's `lastFocusedEditable` tracker** — newly exposed via
   `getLastFocusedEditable()` / `getLastFocusedCaret()` on
   `window.PaperEditor`. The tracker is updated on every
   `keyup`/`mouseup`/`input` event on contenteditables created via
   `bindYTextToContentEditable` ([rm/js/paper-editor.js:2955-2957](rm/js/paper-editor.js#L2955-L2957)),
   so it persists across blur. The new `_rangeFromCharOffset(el, offset)`
   helper reconstructs a Range at the saved character offset.

### Layer 2: explicit alert when no caret exists

Every toolbar reference action (`_toolbarInsertInlineEquation`,
`_toolbarInsertEquation`, `_toolbarInsertFigure`, `_toolbarInsertTable`,
`_toolbarInsertCitation`) gains a leading `_ensureCaretOrAlert()`
guard:

```js
function _ensureCaretOrAlert() {
  if (_state.savedEl && _state.savedRange) return true;
  if (_saveCaretFromCurrentFocus()) return true;
  alert('Place your cursor in a paragraph first, then click the button to insert.');
  return false;
}
```

If neither the mousedown save NOR the PaperEditor tracker fallback
yields a caret, the picker is NOT opened and the user gets immediate
feedback. Eliminates the "picker opens silently, picking an item
silently no-ops" failure mode entirely.

`_insertAtSavedCaret(text)` also calls `_saveCaretFromCurrentFocus()`
as a last-chance recovery before its early-return path, then `alert()`s
"Place your cursor in a paragraph first, then try again."

## Verification

1. Open `/rm/pages/paper-builder.html?paper=<id>` in a fresh tab. The
   paragraph hasn't been clicked into yet → `document.activeElement` is
   `<body>`. Click `+ Inline Eq` → alert appears: "Place your cursor in
   a paragraph first, then click the button to insert."
2. Click into a paragraph → click `+ Inline Eq` → picker opens. Pick a
   row → `[!eqi:<id>]` token inserts at the caret.
3. Type in a paragraph → click into a different paragraph → click the
   side panel pill bar (focus moves to the panel) → click `+ Cite` →
   citation popover opens anchored to the second paragraph (recovered
   via PaperEditor tracker).
4. Click the title input → click `+ Fig` → alert appears (title input
   is not a contenteditable; PaperEditor tracker has no entry).
5. Right-click context-menu path is unchanged: right-click in a
   paragraph → Insert inline equation → picker still uses the
   right-click element directly.
6. Hard-reload to evict SW cache `mcgheelab-shell-v115`.

## Out of scope (deferred)

  "user did something wrong" interruption.

  empty-state click-to-focus-then-click-toolbar is still confusing
  after the alert is in place.
