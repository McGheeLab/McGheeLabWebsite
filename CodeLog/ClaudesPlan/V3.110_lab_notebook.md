# Plan — ELN (Electronic Lab Notebook) page for RM

## Context

The lab needs an Electronic Lab Notebook on `mcgheelab.com/rm/` that's competitive
with LabArchives but tailored to how grad students actually work at the bench:
quick daily entries, photos of handwritten pages from a phone or laptop, project
tagging, and attachments. The slot already exists — `'lab-notebook'` is reserved
in `page-registry.js`'s `DEFAULT_WORKFLOWS` — so workflow chips on RM home will
auto-populate once the page is registered.

V1 has to be **bench-ready**, not just a stub: filters, tags, project linking,
and photo capture must work day one. Privacy is owner-only (matches PMR; matches
LabArchives' default); sharing comes in Phase 3. Editor is WYSIWYG
(contentEditable) so pasting/dropping a phone photo "just works." Witnessing /
co-signing is **out of scope entirely** — not needed for this lab.

Integration target is the existing PMR page at [rm/pages/pmr.html](rm/pages/pmr.html);
its `reference_links[]` field already supports `kind: 'notebook'`, so Phase 2
just wires up the picker. Protocol Developer doesn't exist yet — the schema
reserves a `protocol_id` field for forward-compat but the UI control stays
hidden until that page ships.

## Phase 1 — V1 (bench-ready)

### Files to create

- [rm/pages/lab-notebook.html](rm/pages/lab-notebook.html) — page shell. Mirror the script-load order in [rm/pages/pmr.html](rm/pages/pmr.html) but **also include `firebase-storage-compat.js`** because we upload images. Mount `<div id="ln-app">` and a hidden `<input type="file" accept="image/*" capture="environment">` for the camera button.
- [rm/js/lab-notebook.js](rm/js/lab-notebook.js) — IIFE controller. State: `{ user, entries:[], currentId, dirty, saveTimer, filters:{tag,project,from,to,q} }`. Renders the three-pane layout, owns autosave, owns the upload pipeline.
- [rm/js/notebook-schemas.js](rm/js/notebook-schemas.js) — modeled on [rm/js/cv-schemas.js](rm/js/cv-schemas.js). Exports `ENTRY_STATUSES`, `DEFAULT_TAG_VOCAB` (`['microscopy','hydrogel','bioprinting','cell-culture','imaging','analysis','prep','meeting']`), `ATTACHMENT_KINDS`, and a header comment documenting the **never-inline-base64** invariant (Firestore 1 MB doc limit).
- [rm/js/notebook-figures.js](rm/js/notebook-figures.js) — thin wrapper over the SHA-256 + dedup primitives in [rm/js/paper-figures.js](rm/js/paper-figures.js) but writing to `notebook-figures/{uid}/{shortHash}.{ext}`. Exposes `window.NOTEBOOK_FIGURES.uploadImage(blob)`.
- [rm/css/lab-notebook.css](rm/css/lab-notebook.css) — three-pane layout, attachment thumbnail strip (96×96 cover), drag-over hover state, contentEditable styling.

### Files to modify

- [rm/js/nav.js](rm/js/nav.js) — inside the **Research** group `children`, add `{ label: 'Lab Notebook', href: '/rm/pages/lab-notebook.html', gate: 'lab-member' }`. The page-registry will auto-flatten and the existing `lab-notebook` placeholder in `_WF_DEFAULT_SEEDS` resolves automatically. **No edit to `page-registry.js` needed.**
- [rm/js/api-routes.js](rm/js/api-routes.js) — register two routes in the personal-data block:
  - `notebook/_index.json` → `{ scope:'user', subcollection:'notebookIndex', doc:'index' }` (lightweight summary list for left rail).
  - `notebook/entries.json` → `{ scope:'user', subcollection:'notebook', wrapKey:'entries', orderBy:'date', orderDir:'desc' }`.
  - Per-entry routes registered lazily via `api.registerRoute('notebook/' + entryId + '.json', { scope:'user', subcollection:'notebook', doc: entryId })` — mirror PMR's pattern at the existing `userData/{uid}/pmr` lazy registration.
- [firestore.rules](firestore.rules) — **no new rule needed.** The existing blanket `match /userData/{userId}/{document=**}` (currently ~line 748) already covers `userData/{uid}/notebook/*` and `userData/{uid}/notebookIndex/*` as owner-only. Add a comment block referencing `notebook` so future readers find it.
- [firestore.indexes.json](firestore.indexes.json) — add composite indexes on the `notebook` collection: `(date desc, project_id asc)` and `(date desc, tags array-contains)` so filter queries don't degrade past ~100 entries.
- [storage.rules](storage.rules) — add a sibling block to the existing `paper-figures` block. **Critical difference from paper-figures**: read is owner-only, not lab-wide.
  ```
  match /notebook-figures/{uid}/{allPaths=**} {
    allow read:  if request.auth != null && request.auth.uid == uid;
    allow write: if request.auth != null && request.auth.uid == uid
                 && request.resource.size < 15 * 1024 * 1024
                 && (request.resource.contentType.matches('image/.*')
                     || request.resource.contentType == 'application/pdf');
  }
  ```

### Firestore schema — `userData/{uid}/notebook/{entryId}`

```js
{
  id: 'nb-2026-05-08-microscopy-imx',   // kebab slug; collision suffix -2,-3
  title: 'IMX live-cell imaging — Day 3 hydrogels',
  date: '2026-05-08',                    // YYYY-MM-DD
  body_html: '<p>Mounted samples at...</p>',  // contentEditable HTML, sanitized
  body_text: 'Mounted samples at...',    // plain mirror for search
  status: 'open',                         // 'open' | 'closed' | 'archived'
  tags: ['microscopy', 'hydrogel'],
  project_id: 'prostate-gels-r01',        // nullable
  protocol_id: null,                      // Phase-2 forward-compat, hidden in V1
  attachments: [
    { kind: 'image', storage_path: 'notebook-figures/{uid}/abc123ef.jpg',
      hash: 'abc123ef', mime: 'image/jpeg', size_bytes: 2_341_021,
      caption: 'page 14 of bench notebook',
      uploaded_at: '...', uploaded_by: 'mcgheealex@arizona.edu' }
  ],
  reference_links: [],                    // [{kind,label,url}] — same shape as PMR
  comments: [],                           // reserved for Phase 2
  reference_count: 0,                     // Phase 2 backlink badge
  created_at: '...', updated_at: '...',
  ownerUid: '{uid}', schema_version: 1,
}
```

Index doc `userData/{uid}/notebookIndex/index` holds `[{id,title,date,tags,project_id,attachment_count,status,updated_at}]` so the left rail loads in a single read. Updated on every entry save.

### Editor UX

```
┌── toolbar ────────────────────────────────────────────────────┐
│ [+ New entry] [Tag▾] [Project▾] [Date from→to] [🔎 search]    │
└───────────────────────────────────────────────────────────────┘
┌─ left rail (240px) ─┐  ┌──────── editor pane (flex) ─────────┐
│ ─ 2026-05-08         │  │ Title (h1, autosaves)               │
│   • IMX imaging   ★ │  │ Date · Project▾ · Status▾           │
│ ─ 2026-05-07         │  │ Tags: [microscopy ×] [hydrogel ×] + │
│   • Cell prep        │  │ ┌─ contentEditable body ─────────┐  │
│ ─ 2026-05-06         │  │ │ paste/drop images inline        │ │
│   • Bioprint trial   │  │ └────────────────────────────────┘  │
│                      │  │ Attachments: [📷] [📷] [📄] [+ 📷]   │
│                      │  │ Reference links (PMR ref-row UI)    │
│                      │  │ "saved 14:42"                [Delete]│
└──────────────────────┘  └─────────────────────────────────────┘
```

**Photo upload — three input paths** all funnel through `NOTEBOOK_FIGURES.uploadImage(blob)`:

1. **Drag-drop** anywhere over the editor pane.
2. **Paste** — `paste` listener on the contentEditable reads `e.clipboardData.items`, intercepts default for image MIME, uploads, inserts `<img src="...firebasestorage...">` at the caret.
3. **Camera capture** — visible `📷 Capture` button triggers a hidden `<input type="file" accept="image/*" capture="environment">`. On phones, this opens the rear camera directly. **This is the killer feature for handwritten notebooks** — the user explicitly called it out.

Body images are always Storage URLs, **never base64**. Document this invariant in the schema header.

**Autosave**: 800 ms debounced `api.save(...)` after each keystroke. Use PMR's `_suppressUntil` recipe to gate the live-sync subscription so the user's own keystrokes don't bounce back. Display "saving…" / "saved HH:MM" in the toolbar.

## Phase 2 — RM integration + competitive parity

- **Cross-linking entries**: `[[entryId]]` syntax in body. On save, scan body, populate `mentions[]`, render as `.chip` linking to `lab-notebook.html?entry=<id>`. Toolbar "Link entry" button for non-typists.
- **PMR backlink**: PMR already has `kind: 'notebook'` in `REF_KINDS` ([rm/js/pmr.js](rm/js/pmr.js)). Extend the ref-row UI so when `kind === 'notebook'` the URL becomes a picker that dropdowns from `userData/{uid}/notebookIndex/index`. On the ELN side, render a "referenced in PMR" badge by maintaining `reference_count` via a Cloud Function trigger in [functions/](functions/) (avoid per-render queries).
- **Templates**: `notebook-schemas.js` exports `TEMPLATES = [{id,label,body_html,default_tags}]`. `+ New entry` becomes split-button: `Blank` / `From template ▾`. Initial templates: `cell-culture-day`, `microscopy-session`, `bioprinting-run`, `reagent-prep`, `meeting-notes`.
- **Protocol reference field**: surface the `protocol_id` form control once Protocol Developer ships. Until then, hidden.
- **PDF export**: client-side via `window.print()` with a `@media print` stylesheet for single entry; "Bundle export" iterates filtered entries into a hidden printable doc for thesis-chapter / SI assembly.
- **Comments thread**: append-only `comments[]` of `{author_uid,author_name,body,at}`. Owner can delete; other lab members can comment if entry is shared (precondition: Phase 3 sharing exists, so comments wait on Phase 3 OR ship as owner-only self-notes).

## Phase 3 — advanced

- **Yjs collab editing** — reuse [rm/js/paper-yjs.js](rm/js/paper-yjs.js) provider with per-entry Yjs doc id. Confirm the lab's existing Yjs relay can host an additional doc namespace.
- **Reagent / sample / equipment widgets** — structured `widgets[]` block alongside `body_html`. Each widget `{type, payload}` renders as a card and is queryable across entries ("find every entry that used compound X").
- **Server-side OCR for handwritten photos** — Cloud Function on Storage `notebook-figures/` write → Google Vision OCR → write text into `attachments[].ocr_text`. Search index built via the pattern in [rm/js/paper-search.js](rm/js/paper-search.js).
- **Mobile capture page** — `/rm/pages/lab-notebook-capture.html`, single big "+ Capture" button, camera-first, optional voice memo via Web Speech API, appends to today's open entry or creates one. PWA install hint.
- **Lab-wide sharing** — top-level `labGroup/notebook` collection with `shareWith[]`. Mirror the `userData` `isShared(...)` predicate from existing rules.
