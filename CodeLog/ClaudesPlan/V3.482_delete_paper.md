# V3.482 — Delete a paper from the builder (full cascade)

> Add a per-card **Delete** control to the paper-builder list that permanently
> removes a builder paper (`projects/{id}`, `type=='paper'`) and everything it
> owns, mirroring the existing library-paper cascade (`functions/library.js`).

## Why a Cloud Function

A builder paper is state spread across four Firestore collections + Storage +
cross-collection references owned by *other* users. A client-only delete can't
touch cross-user annotations or the Storage prefix (storage.rules exposes no
client-deletable path under `paper-figures/`), and the api adapter's
whole-array `projects` save would fail the per-doc rule for a non-admin owner.
So the cascade runs server-side under the Admin SDK — one auditable request —
exactly like `deletePaper` for library items.

## Decisions (from Alex)

- **Who can delete:** admin **OR** the paper's lead author
  (`projects/{id}.lead_author_uid == uid`). Mirrors library delete
  (admin OR uploader) and the import feature's owner-scoped rules.
- **Evidence highlights on linked library PDFs:** **unlink, keep the
  highlight.** The highlight doc survives on the library PDF; only its link to
  the deleted paper is removed (arrayRemove). Preserves annotation work on
  shared PDFs.
- **Confirm UX:** a simple `confirm()` dialog (matches library delete). Hard
  delete — no soft-delete/trash exists.

## Cloud Function — `functions/delete-builder-paper.js` (NEW; Alex deploys)

`deleteBuilderPaper` (v2 onRequest, cors, 120s; mirrors `deletePaper`'s gate):

- **GET** → `{ ok:true, service:'deleteBuilderPaper' }` — health probe (the
  client gates the Delete button on it, so the client FTP ships safely before
  the function deploys; the button stays hidden until it's live).
- **POST** `{ paperId }` + Firebase Bearer token →
  1. Verify token → `uid`.
  2. Read `projects/{paperId}`. **Idempotent:** if missing, still best-effort
     `recursiveDelete` orphan `papers/{paperId}` + `drafts/{paperId}` trees and
     return `{ ok:true, alreadyMissing:true }`.
  3. **Auth gate:** admin (`users/{uid}.role=='admin'`) OR
     `projects/{paperId}.lead_author_uid == uid`. Else 403.
  4. Collect claim ids from `drafts/{paperId}/claims/*` **before** deletion
     (needed to unlink evidence annotations).
  5. **Storage:** `bucket().deleteFiles({ prefix: 'paper-figures/'+paperId+'/' })`
     (best-effort; logged, non-fatal).
  6. `recursiveDelete(papers/{paperId})` → comments, annotations, yjs_snapshot,
     yjs_updates, presence, snapshots.
  7. `recursiveDelete(drafts/{paperId})` → claims + their evidence links.
  8. `paperExports/{paperId}` delete.
  9. **Unlink sweep (keep the docs):**
     - `items` where `meta.library.linked_drafts` array-contains `paperId`
       → `arrayRemove(paperId)`; same for `meta.library.cited_in_drafts`.
     - `collectionGroup('annotations')` where `cite_in_drafts` array-contains
       `paperId` → `arrayRemove(paperId)`.
     - annotations whose `evidence_for_claim_ids` reference a collected claim id
       (chunked `array-contains-any`, ≤10/query) → remove those claim ids; if
       the array empties, null `evidence_stance`.
  10. Delete `projects/{paperId}` doc **last** (so an upstream failure never
      leaves a row pointing at half-deleted state).
- Registered in `functions/index.js`.

## Client — `rm/js/paper-builder.js`

- **Health probe:** `ensureDeleteAvailable()` — memoized GET to the function;
  on success sets `_deleteReady=true` and re-renders. Pre-deploy the probe
  fails silently and no Delete control renders.
- **`renderCard`:** when `_deleteReady && (firebridge.isAdmin() ||
  firebridge.isLeadAuthor(p))`, append a `🗑` `.pb-card-del` button. The card is
  an `<a>`, so the button handler calls `e.preventDefault()` +
  `e.stopPropagation()` to suppress navigation.
- **Handler `deletePaperRow(p)`:** `confirm(...)` (spells out figures, comments,
  reader highlights, and evidence-unlink; "cannot be undone") → `getIdToken()`
  → POST `{ paperId:p.id }` → on `{ok:true}` drop the row from `papers` +
  re-render + `setStatus` success; on failure `setStatus` the error.
- CSS: `.pb-card-del` in `rm/css/paper-editor.css` (absolute top-right of the
  card, hover-revealed, red on hover).

## No rules / storage / index change

Everything runs under the Admin SDK; the client only POSTs to the function.
`firestore.rules`, `storage.rules`, and indexes are untouched.

## Verification

- `node --check` on `delete-builder-paper.js`, `index.js`, `paper-builder.js`;
  CSS brace balance; full scratchpad suite green.
- Scratchpad harness `test-delete-cascade.js`: a fake Firestore/Storage double
  fed a paper with comments/annotations/claims/figures/linked library items →
  run the cascade → assert every owned path is deleted, the Storage prefix is
  cleared, and library `linked_drafts`/`cited_in_drafts` + annotation
  `cite_in_drafts`/`evidence_for_claim_ids` are unlinked (docs still present).
- Browser (Alex, after deploy): create a throwaway paper with a figure + a
  comment, tag a library highlight as evidence for one of its claims, delete it
  → card disappears; the projects row, paperExports, `papers/{id}` tree,
  `drafts/{id}`, and `paper-figures/{id}/` are gone; the library highlight
  still exists but no longer lists the paper. Non-owner non-admin sees no
  button and a direct POST returns 403.
