# V3.962 — Scientia: menus keep out of each other's way, "Snip figure" on the HTML card, Iteration

## Goal

Gabe asked for three things:

1. **Menus that overlap.** His two examples: the text editor bar with the Alt+click options, and a Ctrl+click on a component's text box to select it. He wants this fixed in general ("etc.").
2. **The HTML snip:**
   - a snip button outside the maximised page as well;
   - a snip brings you out of the maximised page;
   - a snip ends clip mode.
3. **Iteration:** a new component kind that links to a new version of the same component. The new version is a blank component of the same type as version 1, with a request to explain how it improved underneath it, like an image panel's caption.

## What was found (headless Chrome, the desktop build)

- **Alt+click on a structure while writing.**
  - The structure's hover card (z 170) stayed open over the new menu (`.pop`, z 150).
  - Near the bottom of the window the menu opens upward. There the text editor bar (`.fbar`, z 160) covered it.
- **Ctrl+click on a component's text while writing.** The text kept the caret and the editor bar stayed, beside the selection's bar.
  - The selection's bar was 95 px wide and 346 px tall: a column of buttons. It is absolutely placed in the paper's `.world`, which is 0 × 0. Since `flex-wrap: wrap` was added, its shrink-to-fit width has been the widest button.
  - The column covered the next component, so a Ctrl+click on that component's text hit a button of the bar and selected nothing.
- **The HTML card had no scissors.** V3.961 wrapped `EMBED.body`, but the card is drawn by `WIDGETS.html.body`, which still held the original. The V3.961 test snipped from the badge and from the maximised bar, never from the card's scissors.

## Approach

### 1 · Layers (new `13zzn-layers.js`)

One rule: something that floats over the paper gives way to what was opened over it.

- **A menu** (every `popover`, so every `ctxMenu`) puts the hover card away. A hover card does not open while a menu or the Ctrl+Enter strip is open, unless its anchor is inside it.
- **The text editor bar** yields: hidden while a menu that is not its own, a hover card or the selection's bar overlaps it, or while its component is selected. It comes back when they go.
  - Hiding was chosen over moving the menu: a menu moved off its click point (an Alt+click near the bottom) could leave the screen.
  - The bar's own menus (∑, +) are moved clear of it instead.
- **The selection's bar** is `width: max-content` (one row, wrapping at its 560 px maximum). It goes under the selection, else right, left or above, at the first place that covers no other component and is on screen.
- **A Ctrl+click that selects a component** blurs the text it landed in.

### 2 · The HTML snip (13zzm)

- **Snip figure in the card's header.** It is the card's toolbar, docked by `SLIM` like every widget's (`SLIM.BARS.html = '.hs-bar'`), so it sits outside the page with the label and the time.
  - The wrapper moves to `WIDGETS.html.body`.
  - The old place on the card's hover tools is gone. Those tools are hidden in a note with pills unless the card is selected.
- **`HSNIP.after`.** After a picture is made:
  - clip mode ends;
  - the maximised page it came from closes (`MXHL.close`). The page read beside the note stays open, since the note is already in view.
- **An equation** ends clip mode when the editor opens, and closes the maximised page on Done (`CLIP.eqEdit` gains `done`). Cancelling leaves you in the page.
- **The PDF** keeps its clip mode after a snip, as before. Gabe asked about HTML pages.

### 3 · Iteration (new `13zzo-iterate.js`)

- **What a version is:** `iter` { of, root, v, why } on the new block. Version 1 carries nothing; it is v1 once a later version names it as its root.
  - An index (root → versions) is rebuilt after each `changed()`, so the header's tag costs no scan per box.
- **Blank, of the same type.** + Insert's own code makes it, so each type is blank in its own way:
  - text keeps the kind;
  - an image panel keeps its grid;
  - a table starts as the empty table;
  - an equation has no TeX;
  - a plate keeps its format;
  - an HTML page, a PDF or slides ask for the new file (a version of a file is a new file).

  Kinds where a version makes no sense are left out: recordings (the insert starts recording), timers, calculators, ink, references, protocols and runs (they have their own registration).
- **Recognising the component it makes.** The new component is caught where every component is made (`M.addBlock`, wrapped) while one is pending: the same note and kind, within 60 s. This follows `KINDX.pending` (13zzi).
  - A file dialog disarms the pending version until a file is chosen. Closing the dialog leaves nothing armed that a later insert could be taken for.
- **The kind.** Iteration is listed among the component kinds (the kind label's list, Settings, `/collection`). It is not a kind a component keeps: choosing it makes the next version, which keeps the kind of version 1, so a Hypothesis's v2 is still a Hypothesis.
- **How it improved** is plain text under the version, styled like an image panel's caption.
  - It cannot be the block's body, which is the component's own text, or an image panel's caption, or a table's summary.
  - It is `contenteditable="true"` (not `plaintext-only`), because the app's shortcuts treat only `true` as typing.
  - A redraw while you write keeps the words and the caret.
- **The wire** is a new relation `iterates`: "next version", from the version before to the new one.
