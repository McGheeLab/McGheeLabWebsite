# V3.442 — M2 of Paper Builder III: graphical abstract

> One image per paper, uploaded on the Export page. Elsevier renders it on the first page
> (`\begin{graphicalabstract}` — elsarticle's native slot); every other class bundles it as
> a `figures/` file with a build warning saying so. Completes the Authors & metadata
> workstream (M1 V3.441 + this).

## Changes

- **Config:** `paperExports.graphicalAbstract = {storage_path, download_url, hash, mime}` —
  plumbed through `_defaultConfig`/`_loadConfig` (validated on `storage_path`)/
  `_saveConfigNow` + the `buildBundle` opts (`rm/js/paper-export.js`).
- **Upload card** (`#px-graphical-abstract`, `rm/pages/paper-export.html` +
  `_bindGraphicalAbstract` in paper-export.js): thumbnail preview + file input (png/jpeg/
  webp) + Remove; uploads through the existing `PAPER_FIGURES.uploadImage` (content-hash
  dedup, `paper-figures/{paperId}/` folder — `rm/js/paper-figures.js` now loaded on the
  export page). Contributors only; viewers see the thumbnail.
- **Export (`rm/js/paper-export-tex.js` buildBundle):**
  - EXPLICIT `{{GRAPHICAL_ABSTRACT}}` substitution (an image — the text-stash sweep doesn't
    fit): templates carrying the token render
    `\begin{graphicalabstract}\includegraphics[width=\linewidth]{figures/<basename>}\end{graphicalabstract}`
    or `''`; templates WITHOUT the token push a warning ("no in-PDF slot — bundled as
    figures/<basename> for separate submission") into the bundle warnings.
  - The asset joins `figureAssets` (deduped) so the compile service downloads it and the
    .zip includes it.
- **Template:** `rm/data/paper-templates/elsevier.json` main_template gains
  `{{GRAPHICAL_ABSTRACT}}` inside frontmatter (after keywords, before `\end{frontmatter}`).
