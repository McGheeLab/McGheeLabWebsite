# V3.507 — Chat: server-side fan-out, lifecycle destroy(), XSS pass

**Release 2 of 7** in the chat upgrade program (R1 = V3.505 incremental
rendering).

## Goals

1. Stop the Cloud Function scanning the ENTIRE `chatUserMeta` collection
   on every message (functions/chat.js did this twice — DM and channel
   branches).
2. Move mention-badge fan-out + channel counters server-side, shrinking
   message send to ONE client round trip and clearing the path for R4's
   `chatReadState` owner-only rules lockdown.
3. Give chat a real `destroy()` (it leaks listeners across split-view /
   popout mounts today).
4. Close the XSS nits.
5. Add the long-missing thread-query composite index.

## Schema

- **`chatChannels.subscriberUids: string[]`** — authoritative subscriber
  list for non-DM channels (DMs keep `members[]`). Maintained by the
  client on subscribe/unsubscribe/create/default-auto-subscribe;
  backfilled once via the new endpoint; self-healed lazily by the
  function for any channel where the field is missing entirely (a scan
  computes + persists it — an EMPTY array is valid, not a heal trigger).
- **`chatMessages.fanout: 'v2'`** — written by upgraded clients. The
  function performs mention increments + counter bumps ONLY for v2
  messages; older clients keep their own client-side writes. Correct in
  both directions, indefinitely — no deploy-window race:
  old client + new function → client writes, function skips = 1×;
  new client + new function → client skips, function writes = 1×.

## functions/chat.js (rewritten)

- `getCandidateUids(db, channelId, channel)` — members / subscriberUids
  / lazy self-heal. Deletes both full-collection scans.
- `getMetaForUids(db, uids)` — `db.getAll` chunked ≤100, candidates only.
- `applyMentionFanout(...)` — one WriteBatch of
  `set({uid, channelId, mentionCount: increment(1)}, {merge: true})` on
  `chatReadState/{uid_channelId}`. Targets = (`@channel` ? candidates :
  mentions ∩ candidates) − author. Behavior deltas (intentional):
  `@channel` badges hit SUBSCRIBERS only (old client looped every lab
  user); set-merge also creates readState docs for subscribers who never
  opened the channel (old loop silently skipped them).
- `applyChannelCounters(...)` — channel `lastMessage`/`lastActivityAt`/
  `messageCount` or thread parent `threadReplyCount`/`threadLastReplyAt`
  (blind increment; the old client did read+write). Sidebar `lastMessage`
  now arrives with ~1s function latency — the active feed is unaffected
  (it listens to chatMessages directly).
- FCM recipient filter now iterates candidates only; DM notifications go
  to `members` minus author (previously required the member to carry the
  channel in their own meta — strictly more reliable now).
- **`chatBackfillSubscribers`** (onRequest, Bearer-token; same gate
  pattern as `restorePaperComments`): site admin OR `chatConfig.chatAdmins`
  member; ONE `chatUserMeta` scan inverted into `subscriberUids` on every
  non-DM channel (batch-chunked at 400 ops). GET = health probe.
  Idempotent — safe to re-run.

## rm/js/chat.js (client)

- `sendMessage`: adds `fanout: 'v2'`; DELETED the channel lastMessage
  block, the thread-parent get+update, and the whole mention get+update
  loop. Send = one `add()`.
- `subscribeToChannel` / `unsubscribeFromChannel`: arrayUnion/arrayRemove
  self on `subscriberUids` alongside the memberCount bump; `createChannel`
  and first-boot seeding stamp `subscriberUids: []`; the default-channel
  auto-subscribe path mirrors self onto each default channel.
- **destroy() lifecycle** (precedent: `window.ANNOTATION_OVERLAY`):
  `_unsubs[]` registry (subscribeConfig/subscribeUsers previously dropped
  their unsubs entirely); named + removable document gesture handlers,
  swipe handlers, resize handler; clears draft/toast/resize timers;
  `saveDraft()` on teardown. Exposed as `window.CHAT_PAGE = { destroy }`
  + self-hooked on `pagehide` (split-view iframes / popouts detach the
  page without navigation).
- **XSS**: `msg.authorPhoto` now escaped in the avatar `src` (was the
  one raw `src` injection — any signed-in user controls that field);
  `getInitials()` escapes at the source (covers ~11 raw call sites);
  `escHTML` gains `'` → `&#39;`.
- First-boot `chatConfig` seeding gated behind `role === 'admin'`
  (rules already rejected the write for others; the code just didn't
  know). Non-admin on an uninitialized DB gets read-only defaults.
- Admin settings modal gains a **Maintenance → "Backfill subscriber
  lists"** button (raw-fetch Bearer POST to the endpoint, toast with
  channel/user counts).

## firestore.indexes.json

New composite: `chatMessages (threadParentId ASC, createdAt ASC)` —
the thread listener's primary query has never had its index, so it
always fell into the unordered fallback branch. (Fallback stays in the
client until R4 removes it, after the index is confirmed ENABLED.)
