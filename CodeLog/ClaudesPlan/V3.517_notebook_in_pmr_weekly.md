# V3.517 — Lab notebook entries under PMR weekly entries + reviewer access

## Goal

On the PMR (Project Management Report), surface each student's **lab
notebook entries under the Weekly entries section**, and let a "manager"
(the PI, and any assigned mentor) view them — the same way they already read
the PMR itself.

Two requests, one core problem:

1. Notebook entries appear under the PMR weekly entries.
2. A mentor (grad→undergrad, postdoc→grad) sees their mentee's PMR the way
   the PI sees everyone's.

## What already existed (so we didn't rebuild it)

- **Mentor→PMR access is from V3.243.** `mentor_uids[]` on the mentee's
  `users/{uid}` doc, `isMentorOf()` in `firestore.rules`, the admin Mentors
  tab (`admin-permissions.html?tab=mentors`, already allows grad→undergrad /
  postdoc→grad with no seniority restriction), and mentee-scoped
  rail/read/comment in `pmr.js` (`loadMyMentees`, `canViewUid`,
  `isReadOnlyView`). A mentor viewing a mentee is already functionally
  identical to the PI viewing anyone. **No new mentor plumbing needed** —
  the only gap was that the *notebook* read had to include mentors + admins.
- **PMR already reads the notebook `_index` cross-user** in
  `autoFillReferenceLinks()` (owner-only path) — the exact db-ref pattern we
  generalized.

## Key constraint reversed

The lab notebook was deliberately the one per-user area kept **owner-only
even from admins** (`firestore.rules` blanket `userData/{userId}/{document=**}`
rule; the figure-flag flow works around it by resolving Storage URLs while
the student is signed in). This release intentionally relaxes that — but
**read-only** and only for the **same reviewer set that can already read the
PMR** (admin + assigned mentors).

Chosen behavior (confirmed with Alex): **"Full entry, inline."** Reviewers
see a read-only list per week; expanding shows the full entry (text +
figures) inline. No change to the notebook page.

## Approach

Association is **by date**: an entry whose `date` (`YYYY-MM-DD`) falls in a
week's `date_range_start .. date_range_end` shows under that week. No new
fields on either side. Project filtering is deliberately *not* applied (a PMR
period spans all of a student's projects).

Cross-user reads go direct via `firebridge.db()` (the api adapter hard-codes
the signed-in uid), exactly like the PMR's existing cross-user reads.

## Changes

### `firestore.rules` (deploy FIRST)
New override next to the PMR block:
```js
match /userData/{userId}/notebook/{entryId} {
  allow read:  if isOwner(userId) || isShared(resource.data)
               || isMentorOf(userId) || isAdmin();
  allow write: if isOwner(userId);
}
```
Coexists with (ORs against) the blanket rule → can only grant more read,
never restrict; write stays owner-only. Single-segment `{entryId}` covers
entry docs + `_index` + `_templates`. Reuses `isMentorOf`/`isAdmin`/`isOwner`.
Reviewer reads are single-doc gets → no composite index.

### `rm/js/pmr.js`
- `notebookIndexDocRef(uid)` / `notebookEntryDocRef(uid, entryId)` — direct
  db refs (next to `pmrIndexDocRef`).
- `loadNotebookIndex()` → `state.notebookIndexRows` (+ resets
  `state.notebookEntryCache`); added to the `boot()` and `switchToUser()`
  parallel load batches.
- `notebookEntriesForWeek(wk)` — lexicographic date-range filter, sorted;
  undated entries skipped.
- `loadNotebookEntry(entryId)` — lazy-load + cache one full entry (`uid|id`).
- `renderWeekNotebook` / `renderWeekNotebookRow` / `renderNotebookEntryBody`
  — the read-only `📓 Lab notebook (N)` sub-block (hidden when N=0): title +
  date + phase/status pill, click-to-expand full `body_html` (trusted-render,
  same as barrier descriptions; tokenized Storage-URL images render for
  reviewers). Owner-only `open ↗` deep-link. Called from `renderWeek()`.
- `state.notebookIndexRows` / `state.notebookEntryCache` fields.

### `rm/pages/pmr.html`
`.pmr-week-notebook` / `.pmr-wn-*` styles (rows, twist, title, date,
phase/status pills, expand body, rich images/tables).

### Version/docs
`sw.js` CACHE_VERSION 490→491; CHANGELOG V3.517; ARCHITECTURE version line.

## Deploy sequence
1. `firebase deploy --only firestore:rules` **first** (reviewers can't read
   the notebook until live).
2. FTP the `rm/` tree to godaddy. No build step.
3. Not needed: indexes, Cloud Functions, storage rules.

## Verification
Local: `RM_WRITE_ALLOWLIST=mcgheealex@gmail.com python3 rm/server.py` →
`/rm/pages/pmr.html`.
1. **Owner** — entries dated inside a week's range list under it, expand to
   full body + figures, `open ↗` opens the entry.
2. **PI/admin cross-user** — open another member's PMR from the rail; their
   notebook entries render + expand (exercises the new rule).
3. **Mentor cross-user** — assign self as mentor via the Mentors tab, sign in
   as mentor, open mentee PMR, confirm entries readable.
4. **Negative** — a non-admin non-mentor gets no notebook read for others
   (list empty / swallowed error); write still owner-only.
5. Weeks with no matching entries show no notebook sub-block.
