# V3.824 — A capture's outcome outlives the popup: last capture per tab, '!' badge, capture log

**Date:** 2026-10-22 · **Builds on:** V3.823 · **Backend:** none (writes go under the existing owner-only
`userData/{uid}/{document=**}` rule) · **Site files:** none · **Extension:** 0.4.1 → **0.4.2**

Alex: *"i just injested this paper 'Active Erk Regulates Microtubule Stability in H-ras–Transformed Cells' it
downloaded the pdf to the computer. i went to check for it in the library but it is not there"*.

## 1. Forensics first

- Firestore `pending_captures`: **0 documents**. `paper_index/doi_10_1038_sj_neo_7900180`: not found.
- Storage `papers/**`: nothing dated 2026-10-21/22 (144 paper folders in all).
- Chrome `Profile 1/History` `downloads`: the only download in the last six hours is the MDPI PDF at 08:32 (a manual
  click, `by_ext_id` empty, saved to the Desktop — Chrome's download folder here is the Desktop, not Downloads). No
  ScienceDirect download, by the extension or by hand.

So the capture never reached the upload: it failed while getting the PDF (or never ran), and whatever the popup said
was lost — the popup closes the moment focus moves, while the worker is still climbing the ladder, and the service
worker's console is not persisted. "It downloaded the pdf" most likely describes the View PDF tab opening.

## 2. Fix: the outcome is kept, shown, badged and logged

- `background.js` `_setCaptureState / _getCaptureState / _clearCaptureState` on `chrome.storage.session`, keyed
  `capture:<tabId>`: `{ status: running|done|failed, stage, outcome, url, at }`. `onStage` writes the stage and tells
  the popup (`capture-stage`); success and failure write the outcome (`capture-done`), failure also sets the badge
  to a red **!** whose title is the first line of the error. New `last-capture` message. `tabs.onRemoved` clears.
- `_logCapture(entry)` → `userData/{uid}/captureLog/{autoId}` (owner-only, readable by the PI's admin token):
  `at, version, ok, url, source, doi, title, paper_id, pdf_source, size_bytes` or `error, tried[], needsFileAccess,
  filename, pdfUrlOverride, pdfBuffer`.
- `popup.js` `_showLastCapture(d)` after the detection renders: "Capture in progress (11:52): Asking Chrome to
  download it…" while running; "Last capture on this tab, 11:52:" + the success or failure rendering afterwards.
  `chrome.runtime.onMessage` follows `capture-stage` / `capture-done` live while the popup is open.

## 3. Tests

`extension-e2e.mjs` 37 (was 32): a signed-out capture fails fast, the worker keeps the outcome for the tab, the badge
reads **!**, a reopened popup shows "Last capture on this tab", a never-captured tab has no state.
