# V3.409 — Swap a formula variable in place

## Context

Alex (following V3.407's formula pad): "i also want the user to be able
to modify the equation in the equation editor block by clicking on a
variable and changing it to another."

## Design

In `_formulaPad`'s expression strip
(`rm/js/protocol-graph-editor.js`), variable chips become buttons when
editable. Tapping one opens a small `.pge-fpad-swap` menu (fixed,
body-appended, clamped to the window, closed on outside-click — with a
`document.contains(wrap)` guard so a pad that re-rendered away can't
strand it) listing every wired alias — **V1** name (unit) — with the
chip's current variable shown but disabled. Picking another sets that
token's name in place and commits through the existing
`serializeTokens → params.expr → persist → render` path, so the swap
obeys everything the pad already guarantees (real-name storage, live
recompute, no remount).

Notes:
- "Loose" chips (names in the expr that aren't wired in — legacy
  formulas) are swappable too: tapping one lets you retarget it onto a
  wired variable, which is the natural migration path for old exprs.
- Numbers/operators are not swappable (⌫/AC + append cover those);
  variables were the ask.
- The declaration order inside `_formulaPad` was reshuffled (tokens/
  commit/swap machinery now precede the strip render) so chip click
  handlers can close over them; read-only mode renders inert spans as
  before.
- Exploratory equation tour's "Build the formula" step now mentions
  the swap ("tap any variable chip in the strip to swap it").

## Verification
- `node --check`; full suite re-run **534 ok / 0 FAIL** (swap is
  DOM-side over already-tested serialize/commit primitives).
- Pending (browser): build V1 × X1, tap the V1 chip → menu lists the
  wired variables with V1 disabled → pick X1 → formula becomes
  X1 × X1 and the live value updates; outside-click closes the menu.
