## Design

### 1. The feature registry — `CodeLog/features.json`

64 entries (RM 38, the parent site 5, Scientia 20, shared 1), each with `id`, `name`, `side`, `summary`, `keywords`
(what it is ABOUT), `paths` (anchored globs: `*` stays inside one segment, `**` crosses) and, where relevant, a
relation: `extends` (built on), `merges_into` (folding into; `status: retiring`), `related` (uses; not a duplicate),
`distinct_from: {id: reason}` (looks alike, reviewed, kept apart). `status` may also be `decision` (Alex's call pending)
and `desktop_only: true` marks what never ships in the web build. `feature_dirs` lists where a new file counts as a
new module and must be registered. The Scientia ↔ RM relations from the V3.866 plan are encoded here (library →
rm.library, reader → rm.paper-reader, materials → rm.inventory, tasks → rm.tasks, activity → rm.activity; Review and
the protocol blocks are `decision`). The registry was seeded from `nav.js` (60 nav pages + descriptions), the file
naming in `rm/js`, `functions/`, and Gabe's `TABS` / `STORES` / numbered sources.

### 2. The merge checker — `scripts/merge_check.py`

One script, four questions, one report; exit 1 holds the push.

1. **Registry lint** — schema, dangling relations, and every pair of features that look alike (shared distinctive
   name/keyword tokens above a threshold) must have a declared relation. Passing on the seed registry needed 14
   declarations, one of which the checker *found*: Scientia chores overlap RM meeting chores.
2. **Overlap** — the identity signals a push adds are tokenised (camel/kebab/snake split, stop-words, light stemming)
   and scored against every OTHER feature's profile (name + keywords at weight 1, file stems at 0.6, times an IDF over
   the registry). Signals: a new file; a Scientia tab (`TABS` in `11-shell.js`) or store (`STORES` in `02-schema.js`);
   an RM nav item; a canvas widget registration; a Cloud Function export; a `window.X =` global; an `api/…` route; a
   UI label; and, in NEW script files only, top-level functions and upper-case globals. Entries removed and re-added
   on the same line (an array that merely grew) are compared as sets, so only the new tab counts. A signal's owner is
   the file's registered feature, or a same-side feature that fits it better (a newly registered `scientia.tasks`
   claims the Tasks tab added to the shell). A hit = score ≥ 1.5 with a distinctive token (labels: 2.0), or — for
   entry kinds — distinctive name tokens covering more than half of the signal (`tasks` → Tasks; `notebook-board` ↛
   Figure board). The report names the pair, the signals, and the fix: `extends` / `merges_into` / `related` /
   `distinct_from`. **That is "flagged to combination": the push cannot land until the author has said how the two
   relate, and the answer is in the registry for the reviewer to see.** Lines added to a `retiring` feature warn.
3. **Merge** — `git merge-tree --write-tree origin/main HEAD` after a fetch; a conflict holds with the file list.
4. **Gates** — `node --check` on changed scripts (worktree mode), the Scientia build when `scientia/` changed, the hub
   tests when the hub changed, the icon/emoji gate when site files changed.

Commands: `range <base> <head>`, `worktree` (uncommitted work — a preview), `pre-push` (git protocol on stdin; base =
the remote's sha for `main`, else the merge-base with `origin/main`), `ci`, `lint`, `queue` (the combination queue),
`install` (hooksPath + the manifest merge driver). `MERGE_CHECK_DONE=1` lets `git_autopush.py` run the check once and
capture the report. Calibrated on the real backlog (630 changed files): 0 holds, 5 expected warnings (Gabe's retiring
tabs). Tuning that got there: anchored globs (`*.js` no longer matched `functions/test/x.js`), entry patterns scoped to
the files they belong to, strict owner adoption (only a better score than the file's own feature), the >½ name-cover
rule, and a stop-list that includes `report`, `note`, `editor`, `live`, `boot`.

### 3. The hooks

- **`.githooks/pre-push`** (tracked) → `merge_check.py pre-push`. Installed per clone by
  `python3 scripts/merge_check.py install` (`core.hooksPath .githooks` + `merge.deploy-manifest.driver`). Works on
  Gabe's Windows Git Bash (`python3` or `python`).
- **GitHub Actions** `.github/workflows/merge-check.yml` — the same check on every pull request and push to `main`,
  plus the Scientia build, hub tests and the checker's own fixtures. `git push --no-verify` skips the local hook; the
  Action does not. Branch protection requiring "merge check / gate" is owed (§7).
- **Claude Code Stop hook** (`.claude/settings.json`) now runs **`scripts/git_autopush.py` BEFORE
  `deploy.py autodeploy`**: commit the turn → fetch → rebase onto `origin/main` (so a change Gabe merged reaches this
  computer and the deploy that follows) → the push gate → push → rebuild Scientia if the rebase touched it. Guards:
  key material / credentials / `.env` / payroll / ledgers / grant documents / rosters / bundles are never staged (path
  patterns + a content scan for private keys, service-account JSON, API tokens, Scientia keys); files > 50 MB; a batch
  above `autoPushMaxFiles` (80) waits for `python3 scripts/git_autopush.py --batch` run by a person who looked at the
  list; a conflicting rebase is aborted and reported, the commit kept local. Commit subject = the CHANGELOG head
  (`V3.868: …`, `(cont.)` when the same version continues); the `Co-Authored-By` trailer when run from Claude. The
  message is one JSON `systemMessage` line, like autodeploy's. Pause: `"autoPush": false` or `MCGHEELAB_AUTOPUSH=0`.

### 4. Two deployers — `scripts/deploy.py`

- `MCGHEELAB_FTP_USER` / `MCGHEELAB_FTP_PASSWORD` / `MCGHEELAB_FTP_HOST` from the environment or `scripts/.env`
  (git-ignored) override `site.json`'s login — Gabe's own FTP account, never the lab's password.
- `git_guard()`: `ftp` and `autodeploy` refuse (HELD) when the tree is on a branch other than `deployBranch` (`main`)
  or behind `origin/main` — a stale tree would put older files over the other person's newer ones. `--any-branch`
  overrides `ftp`; offline, the guard steps aside.
- `scientia_build_if_stale()`: the web Scientia build is rebuilt before hashing when a source is newer, so a merged
  change from Gabe ships from either computer.
- `merge-manifest` subcommand = the git merge driver for `deploy/manifest.json` (`.gitattributes`): the union of both
  records, the newer `deployedAt` per file, a file one side dropped stays dropped. `deploy/manifest.json` is tracked
  from the batch commit on, as its .gitignore comment always said it should be.
