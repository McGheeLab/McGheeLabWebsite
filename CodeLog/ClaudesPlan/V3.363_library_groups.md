# V3.363 — Library groups shelf (FuturePlan 09, combined with FuturePlan 12 linkage)

## Goal

Make the growing library navigable at a glance. A collapsible "shelf" above the
existing papers table shows: **📖 Open in reader** (this browser's reader tabs),
**📌 Pinned** (per-user), and **📁 Groups** — reconfigurable named paper groups that
are manual (hand-picked), smart (saved search query, auto-updating), or **draft-linked**
(papers whose `meta.library.linked_drafts` — the FuturePlan 12 / V3.352 linkage —
contains a chosen draft). Groups are per-user, plus admin-published lab-shared groups
everyone can see.

## Problem

The library list is one flat sorted table; finding "the papers in my current workflow"
means re-searching every visit. The reader knows which papers are open
(`localStorage['rm_lp_open_papers']`) and V3.352 made paper↔draft links first-class on
the list page ("→ N drafts" badge), but neither drives any grouping.

## Approach (user-approved in the 2026-07-12 planning interview — see FuturePlan_09)

- Shelf renders above `.lib-toolbar`, sections collapsible, collapse state per-device
  (`localStorage['rm_lib_shelf_collapsed']`). Whole shelf hides while a search query or
  tag filter is active (search results stay the focus).
- Paper entries are compact chips (title + year), click → `library-paper.html?id=`.
- **Open in reader:** read-only view of `rm_lp_open_papers` (payload
  `{tabs:[{id,title}], activeId}`), live-updates via `storage` + `visibilitychange`.
  Hidden when empty. Per-browser by design.
- **Pinned:** `pinned_papers: []` in `LIBRARY_PREFS` (`userSettings/{uid}.library`) —
  per-user, cross-device, zero rules changes. 📌 toggle in each table row; ✕ unpin on
  chips. Distinct from the shared `starred` flag.
- **Groups:** `paper_groups: [{id, name, kind:'manual'|'smart'|'draft', paper_ids?,
  query?, draft_id?}]` in LIBRARY_PREFS, array order = display order (↑/↓ reorder).
  - manual: papers added via a 📁 row-action picker modal (checkbox list).
  - smart: raw search-grammar string evaluated with library.js `_parseQuery`/`_matches`
    at render; created via a "💾 Save as group" toolbar button that appears while a
    filter is active (captures search text + active tag chip as a `tag:` token).
  - draft: membership = `linked_drafts.includes(draft_id)`; created via "＋ From draft"
    (lists paper drafts from `_draftTitleById`; grant drafts excluded for now — titles
    need full items.json, same limitation as the V3.352 badge tooltip).
  - Lab-shared groups: new top-level collection `librarySharedGroups` (docs shaped like
    a group), route `library/shared_groups.json` `{scope:'lab',
    collection:'librarySharedGroups', wrapKey:'groups'}` (no shadowJson), rules
    `read: isLabMember(), write: isAdmin()`. Rendered after user groups with a `lab`
    badge; admins get edit controls + "＋ Lab group" (manual kind this version).
- Dangling paper ids (deleted papers) are skipped at render, never auto-cleaned.
- Customize modal gains three widget toggles (`shelf_reader`, `shelf_pinned`,
  `shelf_groups`) via the existing DEFAULTS-driven checkbox loop.

## Data model changes

- `userSettings/{uid}.library.pinned_papers` / `.paper_groups` — covered by the
  existing owner-write rule (firestore.rules:183). `_hydrate` back-compat safe.
- New collection `librarySharedGroups/{groupId}` — lab-member read, admin write. No
  composite indexes (unfiltered read).

## Out of scope

Drag-and-drop; cross-device reader-tab sync; member-to-member group sharing; smart/draft
lab groups; grant drafts in the from-draft picker; group colors/icons.

## Release ritual

1. `firebase deploy --only firestore:rules` **before** FTP (new collection read).
2. FTP repo to GoDaddy (Cyberduck). sw.js bump forces client refresh.
3. `python3 scripts/version_push.py` at commit time.

## Rollback

Git revert + re-FTP. Rules block additive-safe to leave. Prefs keys inert under old
code; `librarySharedGroups` docs harmless if orphaned.
