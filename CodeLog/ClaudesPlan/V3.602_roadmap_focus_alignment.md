# V3.602 — Research Roadmap R3: a week aligns to an analysis, not just a paper

## Goal

Make roadmap progress real rather than a wall chart. Since V3.550 a weekly
focus area could align to a `researchFoci` **card** (`focus_ref`), but "GELS
paper" is a quarter of work — the unit a week actually lands on is a single
analysis: *void space over time*. This release lets the alignment name that
analysis, and makes the choice visible lab-wide.

## Approach

### `focus_ref` grows two optional keys

```js
focus_ref: { id, title, level, analysis_id?, analysis_title?, experiment_id? }
```

Purely additive. Every existing consumer (`team-focus.js:280,397`,
`my-day.js:631`, `pmr.js:2626,2641`) reads only `.id` and `.title`, and
`.title` deliberately stays the **card** title so nothing downstream changes
meaning. No rules change — `focusAreas` already allows owner ∥ mentor ∥ admin.

### One flattened picker instead of two coupled selects

`FOCUS_AREAS.listFociForPicker()` already did a whole-collection
`researchFoci` get, so every roadmap arrives in that same read for free. It now
returns **card rows and analysis rows in one list**, each with a composite
`key`:

| key | row |
|---|---|
| `gels-paper` | the card |
| `gels-paper::an-2` | one analysis on its roadmap |

The key is necessary because a card and all of its analyses share the card's
`id`, so `<option value>` had to become composite. Analysis rows render
indented (`  ↳ Void space over time`) so a flat `<select>` reads as a tree —
this beats a second dependent select, which would need change-wiring at both
call sites and an empty state when a card has no roadmap.

Analyses with status `done` are dropped from the picker: a finished
measurement is not something to plan a week around.

### The `roadmapClaims` mirror

`setFocusRef` writes `roadmapClaims/{uid}__{analysisId}` when an analysis is
named, moves it on re-alignment, and deletes it on unalign or on focus-area
deletion. This is what lets R4's student band show the whole lab who picked up
what — `focusAreas` is owner-or-mentor-or-admin readable, so a student cannot
see a peer's focus directly.

Two deliberate limits, both consequences of the self-write rule:

- **A mentor aligning a mentee's week cannot mirror it** (only the owner may
  write their own claim). The band shows nothing for that student rather than
  writing something false. `syncClaim` short-circuits on `studentUid !== me()`.
- **Mirror failures never fail the alignment.** The claim is a convenience,
  never the source of truth.

## Files

- `rm/js/focus-areas.js` — `setFocusRef` passthrough + `syncClaim`;
  `listFociForPicker` flattening; new `focusRefLabel(rf)` (`"card › analysis"`);
  `remove(studentUid, focus)` now accepts the doc (not just an id) so it can
  drop the claim.
- `rm/js/team-focus.js` — option values → `rf.key`, lookup by key, chip shows
  the analysis and deep-links to `#rmap-<analysisId>`; `remove` passes the doc.
- `rm/js/my-day.js` — same for the composer's align select; the freeform-focus
  create path stamps the claim itself (it writes `focus_ref` through `create`,
  not `setFocusRef`).
- `rm/js/pmr.js` — the focus-review chip shows `card › analysis` ungrouped, and
  narrows to the analysis alone when grouped by thrust (the card name is
  already the group head).
- `rm/js/research-progress.js` — each student's row lists the analyses their
  weeks actually hit, linking into the roadmap.
- `rm/pages/{my-day,team-focus,pmr}.html` — `roadmap-data.js` before
  `focus-areas.js`.
- `rm/css/research.css` — `.rf-prog-an`.

## Verification

`scratchpad/t2.js` stubs `firebridge` and asserts: done analyses excluded,
closed cards excluded, keys unique, specialties sort first, analysis rows carry
the card id + experiment title, `focus_ref.title` stays the card title,
claim written / moved on re-align / cleared on unalign, and a card-only
alignment writes no claim at all. All pass.
