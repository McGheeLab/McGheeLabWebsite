# V3.830 — Lab Notebook v2: block entries + a personal whiteboard block (voice, paper figures/text)

**Date:** 2026-10-22
**Status:** built this turn; site files auto-upload at turn end (sw 810 → 811). Backend deployed FIRST:
`storage.rules` (new `notebook-boards/{uid}/**` clause) and `firestore.rules` (new
`userData/{uid}/notebookBoards/{bid}/**` reviewer-read block, deployed from a scratch copy = live + this block,
because the repo file still carries V3.806's undeployed self-role hunk).

Alex: *"on the lab notebook, i want a fully new version which uses widget add blocks, students can add blocks
that are calculators, typed notes, protocols followed etc, each one of these blocks can be collapsed. A new block
called whiteboard should be added. This whiteboard should follow exactly the class whiteboard, except there is no
leader and follower, there is only continuous scroll mode, there is the ability to record voice as you go. we
should enhance the whiteboard with the ability to imput figures and text from papers (instead of simulations) so
users can take notes on the papers they are reading if they want."*

## Goal

A new notebook page where an entry is a stack of collapsible **blocks** — typed note, calculator, protocol
followed, figure, checklist, and **whiteboard** — instead of one rich-text body. The whiteboard block is the
class whiteboard engine (`whiteboard.js`) mounted on a personal board under the student's own `userData`, with
no leader/follower, continuous sheet only, a 🎙 Record button that records the mic while you draw (replayable with
the existing lecture replay), and **＋ From paper** in place of ＋ Simulation: pick a library paper, snip a figure
(click a detected figure hotspot or drag any region) or grab a passage of text (drag over text, or pick one of your
highlights) and drop it on the board as an image or text item to annotate.

## Approach (decisions)

1. **New page, same data.** `rm/pages/notebook.html` + `rm/js/notebook-blocks.js` + `rm/css/notebook-blocks.css`
   is the "Lab Notebook" nav target. Entries stay in `userData/{uid}/notebook/{entryId}` (same index doc
   `_index`), so My Week stubs, PMR week views, focus reports and the classic page all keep working. The classic
   editor (`lab-notebook.html`, untouched) stays reachable from a "Classic editor" link.
2. **Entry schema v2 = `blocks[]` on the same doc.** `schema_version: 2`,
   `blocks: [{id, type, title, collapsed, created_at, data}]`. Types: `note {html}`, `calc {spec, inputs, context}`,
   `protocol {run}` (the V3.506 `protocol_run` object, one per block), `whiteboard {boardId, name}`,
   `figure {url, storage_path, caption}`, `checklist {items:[{text,done}]}`.
   **Mirrors kept on every save** so readers that never learned about blocks keep working: `body_html` /
   `body_text` (note blocks' HTML + one line per other block) and `protocol_run` (the first protocol block's run).
   An entry without `blocks` is migrated **in memory on open** (body → note block, protocol_run → protocol block,
   summary/observations/plan → read-only note blocks) and only written back when the person edits it.
3. **Index writes are transactional** (`runTransaction` on `_index`) — the classic page's whole-array rewrite
   raced My Week's transactional rows (mapped this session); the new page never overwrites rows it did not touch.
   Delete really deletes (classic's `save({})` merge left the doc behind).
4. **One board per iframe.** `whiteboard.js` is a one-board-per-document singleton (module-level `S`, `REC`).
   Each whiteboard block hosts `rm/pages/notebook-board.html?board=…&owner=…` in an iframe (the module-panel
   precedent: same origin ⇒ Firebase auth is already shared, no token bridge). Two whiteboard blocks = two
   documents = two engines. The host page loads `/firebase-config.js` (sets `McgheeLab.db`), installs the same
   `McgheeLab.Auth` shim as `whiteboard-panel.js`, then mounts the engine with `collection: 'notebookBoards'`.
5. **Engine: a `notebookBoards` family, not a fork.** `boardsCol(classId, coll)` gains the branch
   `notebookBoards → userData/{classId}/notebookBoards` (the "classId" slot carries the owner uid, so every
   existing call site — strokes, items, recordings, events, replay — routes correctly with no further edits).
   Notebook mode skips the schedule get/listener (there is no class), never publishes `viewY`, never claims a
   lead; the Continuous/Pages toggle, ＋ Simulation and the live column are not rendered; `canGoLive` stays
   false. Board ids keep the `{key}_{uid}` shape so `computeCanDraw()` is unchanged.
6. **Recording decoupled from "Go live".** `startRecording()` / `stopRecording()` are exposed on the mount
   handle; in notebook mode the recording/event/chunk paths use the board's own collection and Storage
   `notebook-boards/{uid}/{boardId}/recordings/{recId}/chunk-NNN`; `recordingActive()` is "this tab records this
   board" (soft erases while recording, as in class); the 20-minute idle stop no longer touches a schedule
   flag; scroll positions are logged from the LOCAL scroll (`recScroll` in `publishView`/`setActivePage`) since
   no `viewY` is written, and page events carry `y` so the replay follows the drawer's scroll. Interrupted
   recordings (`status:'recording'` after a reload) are finalized by the host on mount via the existing
   `finalizeInterrupted`.
7. **Replay in the same host document.** `WhiteboardReplay.mount` gains `coll`, `isAdmin`, `noHash`, `onExit`
   — the host tears the live board down, mounts in replay mode, and "← Back to board" restores it.
8. **Items grow up.** New item `type:'text'` (quote + citation card rendered under the ink, exported to the
   PNG/WebP flatten as wrapped text). New **Arrange** mode (owner toolbar toggle; `.wb-arrange` lifts
   `.wb-items` above the ink and gives each item a drag surface, a corner resize handle and ×) — off by default
   so pens never fight items; class boards get the same Arrange button (additive, same gate as the other tools).
   `handle.addTextItem(meta)` joins `addImageItem`; both place at the page under the viewport centre in
   notebook mode.
9. **From paper = a picker in the host, not in the engine.** `rm/js/notebook-board.js` lists library papers
   (`items` where `type=='paper'` + `is_library_entry`, cached per tab), opens the PDF with `PDF_VIEWER.create`
   (the same viewer the reader uses; `PAGE_LAYOUT` gives figure regions → hotspots), supports a drag marquee
   with "Add as figure" / "Add as text" (text = text-layer items inside the rect in reading order), and lists the
   paper's figure annotations (`kind=='figure'`, already-snipped images) and highlights (`textQuote.exact`).
   Snips are resized to webp medium/full like the module panel and uploaded to
   `notebook-boards/{uid}/{boardId}/items/{itemId}/`.
10. **Calculator block** = a protocol `formula` block object authored inline (label, variables, expression,
    output) and rendered by the real `ProtocolWidgets.renderFormula`, or copied from a protocol's formula /
    calculator blocks (with that protocol's formula entries as `context` so cross-references still resolve).
11. **Protocol block** ports V3.506's run panel (document / cheat views, Finalize / Reopen / Unload, frozen
    record tables) on the plain `protocols/{id}.tree` (no Yjs). Only ONE protocol block is live at a time (the
    widgets' dataset registry + event bus are page-global by design) — expanding one collapses the others.
12. **No browser popups anywhere** (feedback rule): inline forms, two-tap deletes, toasts.

## Rules

```
match /userData/{userId}/notebookBoards/{boardId}/{document=**} {
  allow read:  if isOwner(userId) || isMentorOf(userId) || isAdmin();
  allow write: if isOwner(userId);
}
```
(owner access already came from the `userData/{userId}/{document=**}` catch-all; this adds the V3.517 reviewer
read so a mentor opening a mentee's notebook can see the board.)
Storage: `notebook-boards/{userId}/**` — any signed-in read (the Firestore item/recording doc is the gate, the
`paper-figures` precedent), owner write ≤ 100 MB, `image/*` or `audio/*` (a Safari recording arrives as ONE blob).

## Out of scope / owed

- Real iPad + mic + Safari check of record → replay inside the iframe (headless Chromium cannot open a mic).
- The classic page is unchanged and still writes the whole index array.
