# V3.680 — Teacher onboarding front door + admin invites + classes-page grid

## Goal

Alex: the teacher/student self-identification buttons scattered over the
login/guest surfaces must go; the Classes page gets a teacher-focused section
linking to the class-request flow (no student surfaces); and admin can INVITE
teachers to a ready-made setup. Plus (same message thread): the Classes page
becomes a 2-up grid (1-up on phones), most recent class on top, with the
teacher card as a small spanning card at the top.

## Problem

V3.304 onboarded teachers by self-identification: every fresh Google sign-in
landed on a guest dashboard carrying "Are you a teacher?" (flipped
`category:'teacher'` on click) and "Have a class code?" cards — noisy, and it
put student/teacher chooser UI on every login path. The classes-page pitch
dumped teachers at `#/login` with no explanation. And there was no way for
Alex to hand a known teacher a ready class — everything went through
request → approve.

## Approach

1. **Guest dashboard stripped** (`user-system.js`): profile card only. The
   `guest-become-teacher` category flip and the guest join form are deleted.
   Students join through the class LINK their teacher shares — the class
   page's code gate (unchanged) still flips category on success. The #/teach
   code-hint copy now tells teachers to share the class link + code.
2. **`#/teachers` landing** (`teacher-teach.js`: `renderTeachersLanding` /
   `wireTeachersLanding`; app.js route, AUTH_GATED): program pitch → Google
   sign-in → the class-request form (school/grade/size/subject/module-set
   interest) + request history (withdraw = armed confirm; deny reason;
   approved links #/teach). Existing teachers see dashboard links + may
   request another class. ZERO student surfaces.
3. **Admin invites** (`teacherInvites/{token}`, admin-only rules; redemption
   server-side): admin creates an invite from a new panel at the top of
   admin-teachers ?tab=requests (name / optional email lock / school / class
   title / pre-fill module sets from the catalog) → copyable link
   `mcgheelab.com/#/teachers?invite=TOKEN` + mailto compose + revoke +
   status list. NEW `functions/teacher-invite.js` `redeemTeacherInvite`
   (onRequest + Bearer, the releaseAnnounce pattern): validates
   pending/unexpired/email-match, then in ONE TRANSACTION provisions
   schedules/{tc-…} (owner = caller), joinCodes/{code},
   users/{uid}.category:'teacher', invite → redeemed. Modules pre-fill reads
   the PUBLISHED teacherCatalog (Firestore — the Admin SDK can't read
   modules/manifest.json). Client-side a guest can never create a
   teacher-class doc (the V3.635 lesson) — that's why this is a function.
4. **Classes page grid** (`app.js` renderClasses/loader + `styles.css`
   `.classes-grid`): `repeat(2, 1fr)` desktop / 1 column ≤768px; teacher
   card built FIRST as a compact flex row spanning `1 / -1`; class cards
   sorted by `classDates.startDate` descending (undated sink).

## Files

app.js, user-system.js, teacher-teach.js, teacher-demo.js (persona note),

functions/teacher-invite.js (new), functions/index.js, styles.css, sw.js
(654 → 655).

## Out of scope

Email delivery (mailto compose only, per program rule); invite preview
before sign-in; migrating the old category:'teacher' self-flips (existing
teachers keep their category).

## Deploy

`firebase deploy --only firestore:rules` →
`--only functions:redeemTeacherInvite` → FTP batch.

## Rollback

Previous JS + rules; delete/ignore the function. Un-redeemed invite docs are
inert admin-only data. Redeemed invites leave normal teacher classes behind
(indistinguishable from approved ones) — nothing to unwind.

## Verification

1. Sign in with a fresh Google account → guest dashboard shows ONLY the
   profile card.
2. #/classes: teacher card spans the top, classes 2-up desktop / 1-up
   phone, newest start date first.
3. #/teachers signed-out: pitch + sign-in; signed-in guest: request form;
   submit → pending chip; withdraw works; teacher account: dashboard links.
4. Admin: create invite (with + without email lock), copy link, open in a
   second Google account → "Set up my class" → class + code appear, #/teach
   works, invite shows redeemed with the schedule id; revoked/expired/reused
   links all show their specific error; email-locked invite refuses the
   wrong account.
