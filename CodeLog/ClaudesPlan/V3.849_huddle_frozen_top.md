# V3.849 — The Huddle: frozen top, flowing calendar

**Date:** 2026-10-23
**Alex:** *"the top part of the huddle page should be frozen, and only the calendar times should flow.
the top part includes the date and the user pills. the options for week, day, month view should be
moved so that the frozen section doesnt take up too much room, we want it to be mostly calaner"*

## Goal

On This Week, the date navigation and the member pills stay put while only the calendar's time rows
scroll. The frozen part is as small as it can be, so the view is mostly calendar.

## What was actually happening (measured)

`huddle.css` already had a "calendar freeze-pane layout": `.hud-layout { height: 100% }`,
`.hud-main:has(.hud-cal-layout) { overflow: hidden }`, `.hud-cal-body { flex: 1; min-height: 0 }`,
`.hud-grid-wrap { height: 100%; overflow-y: auto }`. None of it engaged, because `#huddle-root` had no
height: `height: 100%` on `.hud-layout` resolved to `auto`, the grid wrap grew to its content
(48 half-hour rows × 20 px ≈ 1000 px) and the **document** scrolled. Measured at 1280×720 with the
harness: the main column was 1812 px tall, the calendar header alone 146 px (three rows: view toggle,
week nav, zoom row), plus the pills row and the composer above it.

## Approach

- **A viewport-high column.** `huddle.html` gets `html.hud-html` / `body.hud-body`; CSS makes
  `html, body { height: 100% }`, the body a flex column, `.page` `flex: 1; min-height: 0; width: 100%`
  (the V3.845 lesson: a column-flex item with `margin: 0 auto` is fit-content wide without an explicit
  width), `#huddle-root` `flex: 1; min-height: 0`. Now `.hud-layout`'s `height: 100%` resolves, the
  sidebar and main get the viewport remainder, and the original freeze-pane rules do their job.
- **One compact bar.** `renderThisWeek` builds `.hud-week-top` = `.hud-week-bar` (the view's nav:
  `weekNavHTML()` / new `dayNavHTML()` / new `monthNavHTML()`, then the Day/Week/Month toggle, then
  `zoomControlsHTML()` for Day and Week) + `.hud-week-filters` (the member pills with the composer's
  collapsed one-liner on the same row, restyled as a pill). The open composer form renders below the
  pills while editing. `renderMyWeekly` / `renderMyDaily` lose their `.hud-cal-header` and return
  `calBodyHTML(gridHTML, below)`; `renderMyMonthly` lifts its nav into `monthNavHTML()` and wraps the
  month grid in `.hud-month-scroll`.
- **Everything below the grid rides in the scroller.** "Anytime this week" and the open-help strip
  are passed in as `below` and rendered in `.hud-below-grid` after the grid inside `.hud-grid-wrap`
  (or `.hud-month-scroll`), so scrolling past midnight reaches them and the document never scrolls.
  `wireTimeSlider` measures its extent from the grid's own height (`.hud-time-grid.offsetHeight`), so
  the thumb reaches the bottom at midnight and rests there while the extra content scrolls by.
- **The plan popup overlays.** `.hud-week-body` is `position: relative`; `.hud-popup` inside it is
  absolute, centred, `min(560px, 94%)`, with a shadow — tapping a plan no longer pushes the grid down.
- `.hud-main:has(.hud-week-body)` is a flex column with `overflow: hidden` and small padding for all
  three views; the Help / Team / Settings tabs keep `.hud-main`'s own `overflow-y: auto`, which now
  also works because the column is bounded.

## Verification

Harness (real `huddle.js` on the stub Firestore, in the real page shell with a 52 px stand-in for the
RM nav, 1280×720): the document does not scroll in Week, Day, Month, with the popup open, with the
composer open, or on Settings; the grid wrap is the only scroller and opens at 8 AM; the bar holds nav
+ toggle + zoom on one row; pills + composer one-liner share the second row; the frozen part is
under 110 px and under 30 % of the column (measured 83 px of 622); the calendar takes ≥ 60 %;
scrolling the grid leaves the date and pills in place and the day headers stick to the scroller's
top; "Anytime this week" and the help strip are inside the scroller below the grid; the slider thumb
is at the bottom at midnight and stays there past it; the popup is absolute and the grid does not
move; Day and Month views use the same bar (Month without zoom) and their own scrollers; Settings
scrolls inside the main column; no popups, no `<svg` in innerText. 31/31. The V3.848 accordion
harness still passes (26/26). Screenshot reviewed.

## Decisions

- Fix the height chain rather than switch to a sticky toolbar over a document scroll: the zoom,
  scroll-preservation, pinch and time-slider code all assume the grid wrap is the scroller.
- The composer's one-liner lives on the pills row to save a row; the open form still gets the full
  width (it is transient).
- Anytime + help strip go inside the scroller rather than a side column; a right rail for them on
  wide screens is a possible follow-up now that the page is page-wide.
