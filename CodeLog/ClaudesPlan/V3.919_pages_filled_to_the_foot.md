# V3.919 — Every page filled to the foot

**Asked (Alex, 2026-10-25, while V3.918 was being built):** "ensure that the text always fills out the page. we
should never have a situation where the text is hanging with a bunch of white space."

## Where white space at a page foot came from

- **The PDF, under `\raggedbottom`.** PLOS, NSF and the numeric preprint looks compiled ragged-bottom: when the next
  heading (kept with its first lines) or the next float did not fit, TeX ended the page where the text stopped.
- **`[H]` floats.** An imported figure or table written `[H]` (Alex's LaTeX sources use it throughout) cannot move: when
  it does not fit, the page ends early and the float opens the next one.
- **The Document view** never stretched anything: whatever room a page could not use stayed at its foot, even where
  the PDF (`\flushbottom` looks: ACS, Nature, Elsevier, APS, PNAS, IEEE) spread it through the page.

## Changes

1. `paper-look.js`: `texPreamble` writes `\flushbottom` for every spec look; class looks (PNAS, IEEE) add it at
   `\AtBeginDocument`. Templates without a look get `\flushbottom` from `paper-export-tex.js` (end of the preamble).
   `\flushbottom` stretches only glue that has stretch: the looks wrote `\parskip` fixed, so a column of plain
   paragraphs kept its room at the foot, and a page whose only stretch was `\textfloatsep` put it all under the float
   (NSF p. 7). `\parskip … plus 1bp` (article's own default) spreads it. Grant looks keep rigid headings (wrapfig
   reads `\pagestretch` only when a wrapped figure does not fit: the threshold moves by ≈1 bp per paragraph).
2. `paper-export-tex.js` `_floatRawTex(raw, template)`: under a look, `\begin{figure|table}[…h…|…H…]` in imported LaTeX
   becomes `[tbp]` (`[tp]` starred) — the same placement built floats already get, and what the Document view models
   (region `auto`). Explicit Lock (preprint target, `[H]`) is left alone.
3. `paper-doc-view.js` `_flushBottoms()` (after `_mountSheets`, before the layout report): per sheet marked
   `data-flush`, the room between the text region and the page foot (or a bottom float band) goes to the last
   one-column run; in a two-column page the last column strip is extended to the foot and each column's room (above
   its bottom float slot) is spread through its blocks in proportion to TeX's stretch in each gap (after the block
   above + before the block below: `\parskip` 1, titlesec heading 2 before / 1 after, rigid grant headings 0, display
   2 / 2, list 2 + parskip / 2, in-text float 2 / 2, none between a display and the paragraph it resumes); the gap
   above a bottom float keeps its `\textfloatsep` share (2), as TeX's does. Added as
   `padding-top` (collapsing margins would swallow a margin increase). The packer marks a page before a forced break
   (`breakBefore`, a stand-alone front page) `noFlush`; the last text page is left as it ends, except a left column
   whose text continues in the right one. CSS-column (non-look two-column) pages are skipped; no template uses them.
4. Found on the way (PLOS ran a page long in the Document view after V3.918's table CSS): TeX keeps "Numerical
   Aperture" (82.1 pt) on one line of an 82 pt `p{}` column by shrinking the interword space; a browser cannot, so the
   header wrapped, the table grew a line and "Discussion" moved to the next page. Wrapping / `p{}` cells under a look
   get 1 pt more on their right.

## Verified

Paper Lab corpus (all eight papers, Document view and compiled PDF; runs p9 → p11): page counts unchanged; PLOS's
Document view back to 13 pages (it had run to 14 after V3.918's table CSS; "Discussion" now at 522 pt on page 9, the
PDF's at 525 pt); NSF 16/16 page starts and line-end agreement unchanged (0.871), its page 7 no longer puts all the
room under Figure 4; JACS page-start agreement 0/11 → 3/11. No page in any paper ends its text above white space;
the remaining ≥2-line "gaps" the metric reports are float separations (a page-wide figure in Elsevier, the table at
the top of a JACS column, the Nature Communications front page) or a figure-only PNAS column, as in the originals.
