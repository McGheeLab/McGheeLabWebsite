# V3.600 — Research Roadmap R1: experiments → analyses → figures

## Goal

Give an OUTPUT card on the research map a structured answer to *how do we
actually get this paper written* — the experiments that must run, the analyses
each experiment yields, and the figure each analysis is destined to become.

Alex's driving example:

> experiment = confocal time-point measurements of granules in various
> conditions; analysis = 1) void space over time 2) compaction of the
> functional phase over time 3) compaction or relaxation of the inert phase
> 4) permeability of the resulting tissue 5) phase map of the tissue

Today that lives in Alex's head. The card has a Description, Media, links, and
attached people, but nothing between "we're writing the GELS paper" and a
student's weekly task. `grep -r roadmap rm/` returned nothing before this
release; "milestones" existed only as prose inside `description_html`.

## Approach

Three storage shapes, chosen by *who writes them* rather than by what they
contain:

| Path | Writer | Why there |
|---|---|---|
| `researchFoci/{fociId}.roadmap` | admin | Inline, like `media[]` / `links.patents[]` / `overview_blocks[]`. The hub already renders the whole map from one `listAll()` get; a subcollection would add an N+1 read for structure only the PI writes. |
| `researchFoci/{fociId}/refs/{refId}` | any lab member | The card doc is admin-write-only, so member-editable paper attachments **must** be a subcollection. Exact `labThemes/{id}/groups/{key}` shape and rule. |
| `roadmapClaims/{uid}__{analysisId}` | self | The hub band (R4) must show every student who is on what, but the `focusAreas` rule is owner-or-mentor-or-admin. A flat lab-readable mirror gives one whole-collection get with no `collectionGroup` and no composite index. |

### Roadmap shape

```js
roadmap: {
  intro_html,
  experiments: [{
    id, title, description_html, status, owner_uids, order,
    analyses: [{
      id, title, method_note, status, owner_uids,
      figure: { needed, kind, caption_target, status, figure_ref, media_id }
    }]
  }],
  updated_by, updated_at
}
```

**Roadmap statuses are their own vocabulary** (`planned` / `running` /
`blocked` / `done`) rather than an extension of `RESEARCH_DATA.STATUS_META`.
A card is never "running" and an analysis is never "awarded_published";
merging the two sets would make both pill vocabularies lie.

### Ref shape

`refId = ${itemId}__${targetId || 'root'}` — deterministic, so attaching the
same paper to the same target twice updates the note instead of creating a
duplicate row.

```js
{ item_id, target: {kind:'roadmap'|'experiment'|'analysis', id}, note,
  relevance: 3|2|1, title_snapshot, authors_snapshot, year_snapshot,
  added_by, creator_name, added_at, last_editor, modified_at }
```

The **note** is the payload — "why is this paper appropriate here" — and it
renders inline on the roadmap, never behind a tooltip. `relevance` reuses the
library's Core/Supporting/Tangential 3/2/1 scale so a student reads one scale
across the app.

`meta.library.roadmaps: [fociId]` is the reverse index, written by a new
`LIBRARY_LINKS.toggleRoadmap()`. It rides the V3.309 items rule — no rules
change — and lets the reader answer "which roadmaps is this paper on?" with a
field read instead of a `collectionGroup` scan.

## Key decisions

- **Output cards only.** A specialty is a capability and a concept is an idea;
  neither ships, so neither has experiments to run.
- **Whole-tree save, full re-render editor.** The editor keeps a working copy
  and re-renders wholesale on every structural change, with `collect()`
  reading live inputs back into the draft first. The doc is admin-write, so
  there is no concurrent writer to merge against and a single `update()` is
  safe.
- **"⤵ Paste a list"** per experiment, tolerating `1.` / `1)` / `-` / `•`
  prefixes — Alex's five analyses arrive as a numbered list, and typing them
  one row at a time is the difference between using the feature and not.
- **`data-ed` for editor buttons**, distinct from the page's `data-act` and
  `data-expand` handlers, so nothing collides with the concept-card inline
  expansion.
- **Add-a-paper buttons only render when `ROADMAP_ATTACH` is loaded** (R2), so
  R1 never shows a button with nothing behind it.

   `researchFoci/{id}/refs` fails closed.
