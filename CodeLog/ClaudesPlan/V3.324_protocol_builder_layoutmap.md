# V3.324 — Protocol builder: interactive builder + plate map (FuturePlan 03, Release 4)

## Goal

Fourth release of FuturePlan 03: the `builder` block (parameter sliders
with monotonic cross-constraints, an editable tag list, and a
combination assembler producing a **named dataset**) plus the
`layoutMap` block (dataset → well-plate grid). Together with the
Release-3 calculator these reproduce the gold-standard design panel:
build conditions → compute volumes per condition → see the plate.

## Honest scope (per the FuturePlan doc)

This generalizes the *class* of design-panel builders — parameters +
list + assembled table + grid viz — not arbitrary bespoke logic. Domain
quirks are expressed as declarative config (mathjs expressions) where
they fit and deferred otherwise.

## Block shapes (attrs all plain JSON)

```
kind: 'builder'
attrs: {
  label, description,
  dataset: 'conditions',            // output dataset name (registerDataset)
  params:  [{name, label, min, max, step, default, unit, lt}],
           // sliders; publish into the shared symbol table like
           // calculator inputs. `lt` names another param this one must
           // stay strictly below (the Lₛ<L_M<L_L monotonic chain) —
           // enforced by clamping on input, chained one pass per change.
  dims:    [{field, label, source:'params'|'list', options:[...], editable}],
           // one segmented picker per dim. source:'params' picks WHICH
           // param (row gets field=<param name/label> + field_value=
           // <param value>); source:'list' picks a string option, and
           // editable:true lets doc-view users add/remove options (the
           // ratio editor).
  derived: [{field, expr}],         // per-row computed fields (mathjs,
                                    // row scope over symbol table)
  dedupe:  {when: '<expr>', ignore: ['field', …]},
           // rows where `when` is truthy get `ignore` fields blanked
           // before identity-keying, then identical rows merge — covers
           // the gold standard's f=1 inert-merge.
}

kind: 'layoutMap'
attrs: {
  label, dataset,
  rows: 4, cols: 6,                 // 24-well plate default
  cellLabel: '<expr>',              // per-row mathjs expr (strings ok)
  cellSub:   '<expr>',              // optional second line
  colorField: '',                   // distinct values → palette classes
  spareLabel: '—',                  // unused wells
}
```

## Where the interactivity lives

Doc view (like the calculator): sliders, segmented pickers, tag-list
editing, `+ Add` / `Add all` (cartesian product) / row remove / clear.
Assembled rows are **session-local** and pushed through
`ProtocolFormulas.registerDataset(dataset, rows)` on every change, so
Release-3 computed tables and layoutMap grids refresh live via the
existing `protocol-vars-changed` bus. Nothing writes to Firestore from
the doc view. The editor renderer is the authoring surface: config
grids for params / dims / derived / dedupe + dataset name.

Builder params publish to the symbol table via a new
`builderToFormulaEntries(block)` (sibling of
`calculatorToFormulaEntries`), wired into both the Y walker and the doc
view's plain walker — so calculators can reference `L_M` etc. directly.
