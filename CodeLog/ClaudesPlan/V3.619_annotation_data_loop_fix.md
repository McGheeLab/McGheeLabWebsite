# V3.619 — Annotation data loop fix (highlight → draft → builder)

**Release 1 of 4** in the paper-reader highlight→comment overhaul (Alex,
2026-08-12: "the highlight to comment workflow has so many bugs… we may
need to simplify"). Program: V3.619 data loop → V3.620 one-popover create +
panel diet → V3.621 lifecycle hardening → V3.622 comments-page
categorization workspace + reader Groups/Focus widget.

## Goal

Make the workflow's central promise actually work: a highlight filed to a
draft must reach that draft's Evidence Inbox in the paper builder. Three
independent breaks prevented this, likely since V3.103:

1. **Split-brain field pair.** `onCreate` stamped the active draft
   overlays into `bucket_ids` (retired), while every consumer — the
   overlay filter (`paper-overlays.js`), the panel draft chips, and the
   builder's Evidence Inbox (`paper-evidence-inbox.js`) — reads
   `cite_in_drafts`.
2. **Missing composite indexes.** `firestore.indexes.json` declared ZERO
   annotation indexes; the Evidence Inbox's equality + array-contains
   queries need composites and their failures were swallowed by
   `.catch(() => null)` → silently empty inbox.
3. **Rules rejections.** Non-owner `cite_in_drafts` updates and
   cross-author claim-evidence updates were outside the rules carve-outs,
   so the panel's own controls alert-failed for everyone but the creator.

## Changes

### Backend (deploy BEFORE FTP)
- **firestore.indexes.json** — two composites on `annotations`
  (COLLECTION scope): `(visibility ASC, cite_in_drafts CONTAINS)` and
  `(creator.uid ASC, visibility ASC, cite_in_drafts CONTAINS)`. Plus
  fieldOverrides for `cite_in_drafts` and `evidence_for_claim_ids` with
  CONTAINS at both COLLECTION and COLLECTION_GROUP scope (overrides
  replace defaults, so COLLECTION is restated) — the COLLECTION_GROUP
  entries also fix `deleteBuilderPaper`'s silently-failing unlink queries.
- **firestore.rules** —
  - annotations update: non-owner carve-out widened to
    `hasOnly(['evidence_for_claim_ids','evidence_stance','cite_in_drafts','modified'])`.
  - claims update: new lab-member carve-out
    `hasOnly(['supporting_evidence_ids','counter_evidence_ids','modified'])`
    (the "plan A2" note) — CLAIMS.addEvidence's transaction no longer
    rolls back when a member tags evidence on someone else's claim.

### Client write path
- **rm/js/library-paper.js** — `onCreate` writes `cite_in_drafts` from
  `PAPER_OVERLAYS.getActiveDraftIds()` (bucket_ids stamp removed), stamps
  `annotation_type` from the new `COLOR_TO_TYPE` map (yellow→note,
  green→evidence, red→limitation, blue→method, purple→question,
  orange→quote), accepts optional `{comment, draftIds}` (the V3.620
  popover's payload), and returns the new annotation id. `onUpdate`
  re-stamps `annotation_type` when an owner changes `color_id` (captures
  with `kind` keep their own type).
- **rm/js/annotation-sync.js** — create defaults drop `group` (write-only
  field), `bucket_ids` (retired), `parent_id` (threading never shipped);
  add `annotation_type: 'note'`. Snapshot reads use
  `{serverTimestamps: 'estimate'}` so a just-created annotation sorts
  stably instead of jumping top→bottom on server ack.
- **rm/js/claims.js** — `addEvidence` also unions the draftId into the
  annotation's `cite_in_drafts` inside the same transaction (evidence for
  a claim on draft X implies the highlight cites into X).
- **rm/js/paper-overlay-types.js** — new `quote` type (orange, #fb923c).
  Saved type-filters are versioned (`{v:2, types}`); legacy plain-array
  saves union `quote` in once so pre-existing filters don't hide every
  quote highlight.
- **rm/js/paper-overlay-import.js** — `quote` added to VALID_TYPES.

### Overlay persistence fix
- **rm/js/paper-overlays.js** — `init()` used to call
  `_refreshLinkedDrafts()` (which force-activated every linked draft and
  `_saveActive()`d) BEFORE `_loadActive()`, so the per-paper active-overlay
  selection in `rm_lp_drafts_<paperId>` was clobbered to "all on" on every
  load. Split into `_fetchLinkedDrafts()` (fetch/enrich only) +
  `_refreshLinkedDrafts()` (prune to live ids, auto-activate only NEWLY
  linked ids, persist). `init()` now fetches, then loads the saved set,
  then prunes. `_saveActive()` also skips persisting during a `?draft=` /
  `?grant=` URL-focused session, honoring `_loadActive`'s documented
  contract that the override leaves the saved set intact.

### Migration
- **rm/js/admin-annotation-sweep.js** (new) + card on
  **rm/pages/admin-migrate.html** — "Annotation consolidation (V3.619)":
  dry-run + live sweep, admin-run from the browser. Per annotation:
  `cite_in_drafts = cite_in_drafts ∪ bucket_ids ∪
  draftIds-resolved-from-evidence_for_claim_ids`; delete `bucket_ids`;
  delete `parent_id` when null (non-null logged and left alone — deleting
  would surface deliberately hidden docs); backfill `annotation_type` from
  `color_id` where missing (skips `kind:` equation/figure captures).
  Iterates library items and queries each `papers/{itemId}/annotations`
  subcollection — collectionGroup queries are NOT used because the rules
  match the concrete path only. Batched at 400 ops, idempotent. Claim→draft
  resolution covers `projects/papers.json` drafts (grant-draft claims are
  skipped; nothing consumes them today).

## Not in this release (later releases)

`bucket_ids` read-fallbacks and the back-compat `getActiveBucketIds` /
`getLinkedBuckets` / `getColorForBucket` aliases stay until the sweep has
run (removed in V3.621). The reader's group picker, "Tag as information",
and the create popover are V3.620. The onBucketToggle handler in
library-paper.js is orphaned (its chips never render) and is deleted in
V3.621 rather than touched here.

## Deploy

1. `firebase deploy --only firestore:rules`
2. `firebase deploy --only firestore:indexes` (wait for index build)
3. Run the admin-migrate sweep (dry run → live) as admin.
4. Client JS joins the next FTP batch (sw 590 → 591).

## Verify

- Create a highlight with a draft overlay active → Firestore console
  shows `cite_in_drafts: [draftId]`, `annotation_type` set, no
  `bucket_ids`/`group`/`parent_id`.
- Builder → that draft → References pill → Evidence Inbox lists the
  highlight (plausibly the first time this has ever worked in prod).
- Toggle a draft overlay off, reload the reader → it stays off.
- As a non-owner lab member, add a draft chip to a teammate's lab
  highlight → no alert.
- Sweep dry run reports counts; live run; re-run reports 0 to patch.
