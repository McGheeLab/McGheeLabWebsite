# V3.987 — Protocols that are an HTML file

## Goal

Alex, 2026-11-13: "On RM protocols, I want students to be able to post HTML files as protocols as well, for example
*Spot-Anchored Hydrogels on Glass — Interactive Protocol.html*. I want this to be a protocol that is viewable on RM,
and students should be able to upload files like this and submit them to the public page as well."

The example is a single self-contained page (142,656 bytes): inline CSS, one inline script that drives live
calculators and a Simple / Advanced switch (remembered in `localStorage`, guarded by try/catch), SVG drawings,
in-page `#section` links. Nothing external.

## The constraint that shapes it

The file's scripts have to run (that is what makes it interactive), but a file a student uploaded must never run as
`mcgheelab.com`: in that origin a script can read the visitor's Firebase sign-in from IndexedDB. So the file is
drawn with `srcdoc` in `<iframe sandbox="allow-scripts allow-modals allow-popups allow-popups-to-escape-sandbox
allow-downloads">`:

- no `allow-same-origin` → an opaque origin (`window.origin === 'null'`): no access to the page around it, its
  storage or its cookies (verified in both RM and the public site);
- no `allow-forms`, no `allow-top-navigation`;
- `allow-modals` for print / alert, popups so its outside links open normally, downloads for files it offers.

Same rule as research-overview HTML embeds (`research-media.js`, V3.547). A helper is injected at the top of the
file's `<head>`:

- `<base href="about:srcdoc">` — **found in testing:** a srcdoc document resolves links against the PARENT page's
  URL, so the file's own `href="#s05"` loaded RM into the frame instead of scrolling. With the base, `#…` is a
  same-document jump.
- `localStorage` / `sessionStorage` that work in memory (an opaque origin has none; a page using them unguarded would
  stop with an error).
- Print on request from the page around it, and Ctrl/Cmd+P inside the frame prints the file, not RM.

## Storage: Firestore pieces, not Storage

- `protocols/{id}`: `kind: 'html'`, `html_file {rev, chunks, size, name, uploaded_at, uploaded_by,
  uploaded_by_name}`, `html_revisions[]` (earlier files, newest first). The file is **not** on the doc, so the
  protocols list (which loads every doc) stays light.
- `protocols/{id}/html/r{rev}-{n}` = `{rev, n, data}` — 300,000-character pieces (≤ ~900 KB in UTF-8, under
  Firestore's 1 MiB). Lab read; owner / admin write.
- Posted: `publicProtocols/{id}/content/html-{n}` beside `content/current {kind:'html', html_chunks}`; the card says
  `kind: 'html'`, `html_chunks`, `html_size`. Already covered by V3.986's `content/{docId}` rule.

Why not Firebase Storage (what research media uses): it would need a storage-rules deploy as well as the Firestore
one, and an `<iframe src>` of a Storage URL can't take the injected helper (fetching it for srcdoc needs bucket CORS).
Firestore text goes straight into srcdoc. Limit 7.5 MB, so a post (card + current + every piece) fits one 10 MiB
batch and a visitor never sees half a file.

Replacing the file writes a new revision and keeps the old pieces; earlier files are downloadable from Details.

## RM

- **List:** "Upload HTML" → modal (file, title from `<title>`, slug, summary from `<meta name="description">`, tags;
  warnings for files beside it, other websites, forms, size) → `ProtocolHtml.createProtocol` writes the doc, then
  the file (the pieces' rule reads the doc's owner); if the file write fails the doc is removed again. Cards show an
  "HTML" chip and open `&view=html`.
- **`?protocol=<id>&view=html`** (`protocol-html-view.js`): the file fills the page below a bar — Details (title,
  summary, tags, status; open by default until there is a summary and tags), Replace file, Download, Print, Post to
  website. Other lab members read, download and print. The editor, doc and cheat views send an HTML protocol here.
- **Post to website:** the same dialog as block protocols (contributors, "How it will be listed"); for a file it
  notes the size, that it runs in a closed frame, and any warnings. A shorter re-post drops the pieces it no longer
  has; taking it down removes all of them. Deleting the protocol deletes its `html` pieces.

## Public site

`#/protocols/{id}` for an HTML protocol: `getPublicProtocol` joins the pieces; the page loads
`/rm/js/protocol-html.js` only then, mounts the same sandboxed frame one window tall (it scrolls itself, so the file's
fixed controls and anchors work), with "Made by … · Posted …" and **Download the page** below. Print / PDF and
Ctrl/Cmd+P print the file. The list card says "Interactive page" instead of a step count.

## Not in this version

- Lab-notebook protocol runs and Scientia read a protocol's steps; an HTML protocol has none, so a run of one is
  empty. Opening the file from a run would be the follow-up.
- Posting still has no approval step (same as block protocols): a student posts their own protocol directly. The
  frame keeps a file from touching the site; it does not vet what the file says.
