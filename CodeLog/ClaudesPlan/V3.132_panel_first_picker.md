# V3.132 — Panel-first authoring + doc-side picker (figures/tables/equations)

## Goal

User report: "when we add a section, we need to be able to pick equations
figures or tables that are built in the pannels into the document. we
should not build anything in the page."

Pre-V3.132 the inline `+ Add` menu in [rm/js/paper-editor.js](rm/js/paper-editor.js)
created blank figure / table / equation blocks directly in the doc and
then deep-linked to the panel for editing. That meant:

1. New figures had to be *placed* before they were *authored* — there was
   no concept of "built but not yet placed."
2. Switching where a figure lives in the doc required deleting it +
   re-creating it.
3. The doc-side preview shows the same data the panel shows; users couldn't
   tell which surface was the source of truth (V3.127 made the doc-side
   preview read-only, but the create-then-edit ordering still flowed
   through the doc).

V3.132 inverts the model. Figures and tables are now *first-class library
items in the panel*, and the doc only holds *placement*. Authoring is
panel-only.

## Approach

### New schema

Two new Y.Arrays on `paperMap` (idempotent bootstrap on first connect
after V3.132):

| Path | Type | Contents |
|---|---|---|
| `paperMap.figure_unplaced` | Y.Array<Y.Map> | Each entry has the same shape as a section.children figure block (id, kind: 'figure', skeleton/body/attrs Y.Texts + Y.Maps) |
| `paperMap.table_unplaced`  | Y.Array<Y.Map> | Same shape as section.children table block |

Equations already have `paperMap.equation_library` (V3.109/V3.124) — main
equations live there with `type: 'main'`. The picker treats library main
equations as "unplaced" and uses `insertBlockAt(... 'equation', {...})`
to create the placed doc-block.

### New PaperEditor APIs

| API | What it does |
|---|---|
| `getUnplacedFigures()` / `getUnplacedTables()` | Returns plain-JS snapshot rows for panel rendering |
| `getUnplacedFiguresArr()` / `getUnplacedTablesArr()` | Live Y.Array access |
| `findUnplacedYMap(kind, blockId)` | Live yBlock lookup so panel-side editors work on unplaced items |
| `createUnplacedFigure()` / `createUnplacedTable()` | Returns new blockId |
| `deleteUnplaced(kind, blockId)` | Removes from library |
| `placeUnplacedAt(kind, blockId, sectionId, idx)` | Snapshot → delete from library → hydrate into section.children at idx |
| `unplaceBlock(sectionId, blockId)` | Reverse: from doc back to library |
| `moveBlockToPosition(srcSecId, blockId, dstSecId, dstIdx)` | Cross-section move; defers to `moveBlockWithinSection` if same section |

Cross-container Y.Map moves go through new helpers
`_snapshotBlockMap(srcMap)` + `_hydrateBlockFromSnapshot(m, snapshot)`,
factored from V3.127's `moveBlockWithinSection` so all four mutators
(`moveBlockWithinSection`, `placeUnplacedAt`, `unplaceBlock`,
`moveBlockToPosition`) share one code path. Y types can't be detached
from one parent and reattached, so every move goes through the
recursive snapshot (`_snapshotYValue`) + attach-then-mutate hydrate
(`_writeAttrValue`) path. Subfigures (Y.Array<Y.Map>), table cells
(Y.Map<Y.Text>), and table caption (Y.Text) all survive losslessly.

### New PaperEquations APIs

| API | Used by |
|---|---|
| `openFigurePickerAt(sectionId, idx, anchorBtn)` | `+ Add → Figure` in the doc inline inserter |
| `openTablePickerAt(...)` | `+ Add → Table` |
| `openEquationPickerAt(...)` | `+ Add → Equation` |

Each opens a `.pe-doc-picker` popover anchored to the click button. The
popover has:

- A search input (filter by label / caption / latex)
- A green `+ New …` row at the top (creates fresh unplaced + immediately
  places at the inserter position; for equations, opens the V3.124
  create modal)
- An "Unplaced (built in panel)" section listing items not yet placed
- An "Already placed in document" section listing items currently in the
  doc — clicking a placed row re-positions it via `moveBlockToPosition`

### Panel UI

- **Figures tab.** New `+ Figure` button at the top (mirrors V3.124's
  `+ Equation`). Two lists: `Unplaced (panel-only)` with amber accent +
  Place-in-section action, and `Placed in document` with the existing
  V3.131 controls plus a new `Unplace` action that returns the block to
  the library while preserving content.
- **Tables tab.** Same pattern with `+ Table` button.
- **Equations tab.** Unchanged — already has `+ Equation` (V3.124).
- **Unplaced rows.** Get an amber `Unplaced` badge in place of the
  number badge, and primary action is `Place in section…` (opens
  `_openPlaceUnplacedPicker(kind, blockId, anchorBtn)` — a section
  picker that places the item at the END of the chosen section's
  children).
- **Placed rows.** Get a new `Unplace` action between Insert reference
  and Delete. Removes the block from the doc and re-adds it to the
  unplaced library, preserving all content (image, caption, label,
  subfigures, etc).

### CSS

New selectors (see [rm/css/paper-editor.css](rm/css/paper-editor.css)):
- `.pe-fig-num-badge-unplaced` / `.pe-tab-num-badge-unplaced` (amber)
- `.pe-fig-row-unplaced` / `.pe-tab-row-unplaced` (left-side accent)
- `.pe-place-picker` + rows (panel place-at-section popover)
- `.pe-doc-picker` + search + section heads + grid-laid-out rows + green
  `+ New …` row + dimmed badge / title / subtitle styles
- `.pe-doc-picker-empty` (italic gray center-aligned)

## Backward compat

- Existing pre-V3.132 in-doc figure/table blocks remain in section.children
  with their full attrs and continue to participate in numbering — the
  walkers (`getNumberedFigures`, `getNumberedTables`, `getAllFigures`,
  `getAllTables`) walk doc-side only and never visit the unplaced
  libraries. Unplaced items are only rendered by the panel.
- `_findFigureBlock` / `_findTableBlock` were extended to also search
  the unplaced libraries after exhausting sections.children, so V3.131's
  panel-side editors (caption Y.Text binding, subfigures chip editor,
  table cell editor) work identically on placed and unplaced items.
- The V3.125 inline `+ Add` menu falls back to the V3.125 direct-create
  behavior if `PaperEquations` isn't loaded yet (defensive — the picker
  is the canonical path now).

## Verification

1. **Bootstrap.** Open a paper that's never been touched by V3.132 →
   `figure_unplaced` and `table_unplaced` Y.Arrays appear at top of
   `paperMap` (idempotent — re-opening doesn't duplicate).
2. **Create unplaced figure.** Open the side panel → Figures tab. Click
   `+ Figure` → a new row appears in the `Unplaced` section with an
   `Unplaced` badge in place of `Fig. N`. Upload an image, edit caption,
   set label `fig:demo`. Refresh → row persists in unplaced.
3. **Place from doc.** In a paragraph, click `+ Add → Figure` → the
   `.pe-doc-picker` opens with `+ New figure` (green) at top + `Unplaced`
   section + `Already placed` section. Click the unplaced row → the
   figure moves to the inserter position; panel updates so it now shows
   in the `Placed in document` section with `Fig. 1` badge.
4. **Re-position placed.** `+ Add → Figure` again at a different position
   → picker shows the figure under `Already placed`. Click it → figure
   moves to the new position.
5. **Unplace.** In the panel, on a placed row click `Unplace` → row
   moves back to `Unplaced` section; doc no longer renders the figure
   block; subsequent figures renumber.
6. **+ New from picker.** `+ Add → Figure` → click `+ New figure` →
   creates a fresh unplaced figure + immediately places it; panel
   focuses the new row in the `Placed in document` list.
7. **Equation picker.** `+ Add → Equation` → picker shows main equations
   from `equation_library`. Pick one → `insertBlockAt` creates the
   numbered display block at the position. `+ New equation` opens the
   V3.124 modal pre-targeted (V3.125 behavior).
8. **Tables.** Same flow as figures, mirrored. Y.Map<Y.Text> cells +
   caption Y.Text round-trip through place/unplace lossless (V3.127
   reorder helpers do the work).
9. **Backward compat.** Open a pre-V3.132 paper → existing in-doc
   figures/tables show under `Placed in document`; numbering unchanged.
10. **Hard reload** to evict SW cache `mcgheelab-shell-v108` and pick up
    the new picker UI.

## Out of scope (deferred)

- **Migration of pre-V3.132 in-doc figures/tables to the unplaced
  library.** Existing data continues to work as-is; users can opt into
  the new model by `Unplace`-ing existing figures/tables one at a time.
  An auto-migration walker could land later if the parallel models prove
  confusing.
- **Doc-block thin reference (kind: 'figure-ref' / 'table-ref').** The
  cleaner schema would be a doc-block that's *only* a `library_id`
  pointer with rendering pulled from the library. V3.132 keeps the
  doc-block as the full Y.Map (just moved across containers via
  snapshot/hydrate), which is simpler and avoids a renderer rewrite.
- **Drag-from-panel-into-doc.** Right-click + Picker is sufficient; drag
  would add complexity without much new capability.
- **Unplaced-equation library.** Main equations are already in
  `equation_library`; no schema change needed there.
