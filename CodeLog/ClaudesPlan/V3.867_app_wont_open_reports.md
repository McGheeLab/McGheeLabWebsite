# V3.867 — When the app won't open, it still gets the report out (native, no page needed)

**Date:** 2026-10-23
**Alex:** *"on gabes phone, the app doesnt even open"*

## What we know
- Build 17 broke the app for Gabe; builds 16 and earlier worked. Build 17 changed **no native code** (a web-bundle refresh),
  and TestFlight counts **0 crashes** for him — so this is most likely the first page (My Week, the landing tab) dying or
  hanging every time on his phone, not the iOS app crashing. A page whose web process dies is reloaded by Capacitor, dies
  again, and the person sees a blank screen: "it doesn't open".
- V3.865 (build 19) already RECORDS this on the phone (`webcontent` reports per death, `app-exit`, MetricKit), but every way
  OUT goes through the page: the upload and the Share banner are web code. A page that never comes alive delivers nothing.
- V3.865 also misses a crash DURING start-up: the marker says `launching` there, and only `foreground` was reported.

## Design (native, `OurlabDiagnostics.swift`)
- **Start-up crash:** a previous run that ended in `launching` (same build, not a background launch) is reported too —
  "Ourlab closed while starting". A background launch (push / fetch) starts as `background`, never `launching`.
- **The page never came alive:** 20 s after the app first becomes active, if no page has called `claim()` (a working page
  always does, ~2 s after load) a `no-start` report is written (what the marker knows: which tabs reported a page, how many
  web-process deaths).
- **The page keeps dying:** 3 web-process deaths within 90 s while in use = a crash loop.
- In either case — or when reports from an earlier run are still on the phone and no page has claimed them by 20 s — the app
  shows ONE native alert per run: "Ourlab isn't starting properly — it wrote a report. Send it to the lab?" **Send report**
  opens the iOS share sheet with every pending report file (Messages, Mail, AirDrop — nothing to type); **Not now** closes
  it. A working page never triggers it (it claims within seconds and shows its own banner).

## Web
- `rm/js/my-week.js` `monthGridDays`: a malformed date turned the day loop infinite (`'NaN-NaN-NaN' <= 'NaN-NaN-NaN'` is
  always true) — guard the input and cap the grid at 42 days. Not proven to be Gabe's cause; a latent hang of exactly this
  shape.
