# V3.355 — CV curation: reorder + audience variants (FuturePlan 11, Release 3)

**Goal:** let users curate — order entries within a year, and cut tailored
CVs per audience — without ever duplicating or deleting data.

## Key design decisions

- **Reorder = canonical array order.** The entry list is now year-grouped
  (same 4-digit-year bucketing as the export, newest first, "Undated"
  last); INSIDE a group the section array's own order is shown. ▲/▼ and
  drag rewrite the canonical array (splice by `_id`). Every consumer
  (parent app, biosketch, exports) re-sorts by year with a *stable* sort,
  so within-year manual order propagates everywhere with **zero schema
  additions and zero consumer changes**. A `_order` field was rejected —
  consumers would ignore it.
- **Variants share the parent's `cv_versions[]` contract** —
  `{_id, name, created, hiddenSections[], hiddenEntries{sec:[_id]}}` — so
  variants made in RM appear in the public-site app's Versions tab and
  vice-versa.

## What shipped

1. **Year-grouped list** (`groupEntriesByYear`) with `.cve-yr-head` labels.
2. **Reordering** — ▲/▼ buttons per card (disabled at group edges; the
   touch path) + HTML5 drag within the same year group (`dragover` guard:
   same section + same group; drop position above/below by cursor half).
   `moveEntryRelative(movedId, refId, after)` → splice + `saveSection`.
3. **Audience variants** — toolbar variant `<select>` ("Full CV" +
   variants; persisted `localStorage['cve-variant']`) feeds
   `exportOpts().variant`, so the live preview and every export
   (MD/HTML/Word/print) render the filtered cut via
   `CVExport.applyVariant`. "⚙ Variants" dialog: create/delete variants,
   per-section visibility checkboxes with per-entry checklists, counts,
   immediate `savePayload({cv_versions})` on every toggle.
