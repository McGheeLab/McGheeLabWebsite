# V3.609 — Figure Board: planning canvas in the paper editor (program R1 of 4)

## Goal

Students starting a paper need to work out what experiments to run and what
their figures should show *before* they can write methods and results. This
release gives every paper a dedicated **🧭 Figure board** page inside the
paper editor: a freeform pan/zoom canvas where the student lays out planned
figures, the experiments that feed them, reference images, and sticky notes,
then connects them with arrows to describe the narrative flow. Students and
advisor discuss the plan on it (comments arrive in R3 of this program).

Program map (planned with Alex 2026-08-11):
- **R1 (this)** — pill + canvas + 4 card types + arrows + image upload
- **R2 (V3.610)** — reader marquee figure capture + "from reading library" board picker
- **R3 (V3.611)** — mentor access to mentees' papers (`mentorUids`) + per-card comment threads
- **R4 (V3.612)** — changed-since-last-visit highlighting + single collapsed notification

Explicitly deferred (on the record): promoting a board card into a real
manuscript figure block (`figure_unplaced` + `placeUnplacedAt` is the future
seam); any linkage to the Research Roadmap board (`researchFoci`); arrow
labels/routing; multi-select; undo.

## Approach

**Pill registration** follows the Grant Docs 6-edit pattern
(`rm/js/paper-grant-docs.js:1-27` documents the contract):

1. `rm/pages/paper-builder.html` — `'figure-board'` added to `PAGES` +
   `PAGE_TITLES`; CSS link; script tag in `editorScripts` before
   paper-equations.js.
2. `rm/js/paper-equations.js` — `TABS` entry `🧭 Figure board` (no
   `visibleFor` — shows for journal papers and grants), lazy scaffold
   `#pe-figure-board-root` in `_buildPanel()`, dispatch branch in
   `_refreshPanel()` calling `window.PaperFigureBoard.buildTabContent(root)`.

**The board module** (`rm/js/paper-figure-board.js`, new):

- World div transformed by `translate(tx,ty) scale(s)`; background drag +
  plain scroll = pan, ctrl/⌘-scroll or two-finger pinch = zoom (0.25–2×,
  zoom anchored under the cursor). View persists per paper in localStorage.
- Card types: `figure` (status planned→expected→collected),
  `experiment` (planned→running→done), `snip` (reference image + future
  source-paper link), `note` (sticky). Title input + auto-growing body
  textarea edit in place (700 ms debounce + blur flush); status pill click
  cycles; × deletes card **and its arrows** (batched delete).
- Arrows: ↗ Connect toolbar toggle → click source, click target. Rendered as
  slightly-bowed quadratic paths in one SVG layer under the cards, arrowhead
  clipped to the target card's edge (segment/rect intersection). A wide
  transparent hit-path makes them clickable to delete. Esc cancels connect.
- Drag: 5 px threshold (paper-doc-view's constant); position/size writes to
  Firestore only on pointerup; z-order bumps on grab and persists with the
  next position write.
- Live sync: `onSnapshot` reconciles per doc-change; a card being dragged or
  holding focus locally keeps its local position/text over a remote echo
  (origin-discrimination, per paper-doc-view). Optimistic local echo on
  create so cards appear instantly.
- Images: existing `PAPER_FIGURES.uploadImage(paperId, blob)` →
  `paper-figures/{paperId}/{hash}.{ext}` (storage rule already allows
  `image/*` — no storage.rules change).
- `.pfb-comment-slot` in each card's footer is the R3 mount point.

## Data model

`papers/{paperId}/boardItems/{itemId}`:

```js
{ type: 'figure'|'experiment'|'snip'|'note'|'arrow',
  x, y, w, z,                        // world px (arrows omit)
  title, body, status,
  image: {storage_path, download_url} | null,
  source: {item_id, ann_id, page} | null,   // R2 stamps these on library snips
  from_id, to_id,                    // arrows only
  created_by, createdAt, updatedAt, updated_by }
```

New `firestore.rules` block (after `papers/{paperId}/comments`):
read/update/delete `isAdmin() || isPaperAuthor(paperId)`; create additionally
pins `created_by == request.auth.uid`. No composite indexes (unordered
listener; z-order client-side).
