# V3.960 — Scientia: the edge pan starts at the edge; the mouse's movement past it speeds it up

**Date:** 2026-11-05 · **Branch:** `scientia/edge-push` · **Asked by:** Gabe, after V3.959 (PR #32) was merged.

> "The edge pan is not working how I want it to. At the edge should be the start of the pan speed, and continuing to register mouse movement beyond that increases the speed."

His earlier words (V3.959) still hold: barely touching the edge advances slowly; the more the cursor keeps travelling that way, the faster; holding still holds the speed; backing out stops it at once.

## The problem

V3.959 put the border 48 px inside the note's edge. The reason: once the cursor is stopped at the screen's edge, it no longer moves, so the browser fires no pointer event and hears nothing of the hand that keeps pushing. Gabe wants the start at the edge itself, with the movement beyond it counted.

On this computer the note fills the window below the header: its left and right edges are the screen's, its bottom is the window's (the taskbar below), its top meets the header (72 px of tabs and buttons).

## The approach

1. **The start is the edge.** The pan starts when the pointer reaches the note's edge (within 2 px) moving toward it, at 60 px/s. A dashed line on the edge fades in over the last 40 px before it.
2. **The push is the movement past the edge.** Speed = 60 + 2340 · (push / 360)² px/s, so 360 px of push gives the top speed of 2400 px/s.
   - Where the pointer can go on (over the header, the other pane, the sleeping navigation bar), the push is how far past the edge it has gone.
   - Where it cannot, Windows still reports the mouse's own movement (raw input). A small module in the desktop server, `rawmouse.py`, listens while the app asks. The app asks `GET /api/edge-push` every 30 ms while it pushes at the window's limit, or after the pointer has left the window through the pushed edge, and adds the counts.
3. **Hold and back.** Without movement the push stays, and with it the speed. Any move back stops the pan at once: the pointer coming back 2 px, or the mouse's counts going back while the pointer is stopped or outside.
4. **Where nothing can be read.** The website has no server on the computer, and a pen cannot go past the screen. There, the push grows with the time the pointer stays at the limit (240 px a second), and leaving the window stops the pan.
5. **The header.** It is nearly all tabs and buttons. Past the edge, the pan goes on over a control only while the pointer moves on outward. Resting on it 150 ms or sliding along it is reaching for it, so the pan stops: reaching for a tab moves the note about 13 px.
6. **The bottom.** The sleeping navigation bar (24 px, fixed) covers the note's bottom. The bottom edge is the bar's top, and the bar no longer blocks the pan while asleep.

## Decisions

- **Raw input, not pointer lock.** Pointer lock would also report movement past the screen's edge, but it needs a click first, hides the cursor and shows Chrome's "Press Esc" banner. Raw input on the desktop server is invisible and works on hover.
- **What the module reads.** Relative mouse movement only, as counts. No buttons, keys, windows or cursor position. It registers on the first question and lets go after 3 s without one. Absolute input (a pen, a touch screen, a remote session) is skipped.
- **Counts to pixels.** Counts ÷ `devicePixelRatio`, so 1 count is about one screen pixel at Windows' default pointer speed.
- **Counting starts afresh** each time an axis reaches the window's limit, so the way there, already counted by the pointer, is not counted twice.
- **Guarded import.** A server whose folder lacks `rawmouse.py` still starts, and the app falls back as on the web.
- **The window's own `blur`, the document's own `mouseleave`.** The window-capture `pointerleave` listener of V3.959 fired for every element the pointer left. It is gone.
- No lab-layer change (`lab-mode.js`, `cloud-sync.js`, `scientia-cloud.py` untouched). `serve.py` and `rawmouse.py` are the desktop server's (Gabe's). `scripts/scientia_build.py` gains one file in `BUNDLE_APP`.
