# V3.333 — Citation extraction robustness + link-annotation API (coverage R2)

> Coverage-expansion R2 of 5 (2026-07-12). Fixes CLASSES of misses in the
> extraction layer (not individual styles), and adds the PDF link-annotation
> extraction API that R3's authoritative link scanner consumes.

## Changes

### rm/js/paper-citations.js — `_matchItemsOnPage`
- **Gap-aware joining**: pdf.js frequently splits one visual token (`[12]`)
  across text items; the old unconditional space-join produced `[1 2]` and
  every regex missed it. Items on the same line with an x-gap under
  ~0.35× char width now join with NO separator. The `ranges` offset map
  stays exact, so `_rectForRange` placement is unchanged.
- **Offset-preserving normalization**: scan against `scanText` where
  em-dash (—), minus-sign (−), U+2010 hyphen → ASCII/en-dash and NBSP →
  space (1:1 swaps only; offsets identical to `fullText`). Ligature
  expansion is NOT 1:1 and stays a documented backlog item.
- **Superscript-run merging**: a superscript cluster (`1,4–6`) often
  arrives split across several tiny-height items; the geometric-superscript
  scanner now merges the x-adjacent same-line tiny run before testing, so
  the whole cluster matches (previously single-item only).

### rm/js/pdf-viewer.js — Link annotations (R3 groundwork)
- Shared `_resolveDest(pdfDoc, dest)` — explicit-array and named
  destinations → `{targetPage, rawY}` (XYZ / FitH / FitBH y forms).
- **Viewer**: `_renderPage` captures each page's Link annotations once
  (natural scale-1 top-down coords + resolved internal targets);
  `viewer.getLinkAnnotations(page)` rescales to the current zoom so rects
  and `targetY` sit in the same coordinate basis as `getTextItems`.
- **Headless**: `extractTextItemsFromPdf(source, {withAnnotations:true})`
  returns `{items, links}` — links carry `{page,x,y,w,h,url?,targetPage?,
  targetY?}` in the same top-down scale-1 coords as the items. Default
  call shape (no flag) is unchanged for all existing callers.
