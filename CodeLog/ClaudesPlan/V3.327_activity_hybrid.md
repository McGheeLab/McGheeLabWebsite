# V3.327 — Activity hybrid: manual categorized hours + automated page-time + Overview glance

## Why (scope change)

FuturePlan 04 Workstream B locked "hours are dead — no durations, counts
only." User direction on 2026-07-11 **overrides that**: keep the ability
to *manually* track work into categories with hours (like the
pre-overhaul tracker — hierarchical categories, ML + Claude
categorization, weekly analytics), and automate ONLY page-time. Hours
must be consistent ("smooth") across the tracker, PMR, dashboard, and
lab-stats.

So B1/B2/B3 are partially revised:
- **Kept from B1**: page-time + producer auto-capture write lightweight
  hours-free *events*; no pending-confirm loop anywhere.
- **Reverted from B2**: the 400-line counts-only tracker rewrite —
  restored the rich manual tracker.
- **Reverted from B3**: PMR Stats / lab-stats / dashboard show **hours**
  again (kept B3's PMR heatmap strip as an addition).

## Model (coherent hybrid)

`trackerEntries/{uid}/entries` holds two entry flavors, both counted as
"activity", neither confirmed:
- **Manual** (source `manual`/`ai`): carries `duration` (minutes) +
  `categoryPath` — real logged hours. Entered complete on save.
- **Auto** (source `rm-page-time`, `rm-notebook`, `rm-protocols`,
  `rm-paper-editor`): `kind:'work'`, `categoryPath`, NO `duration` —
  presence. Populates heatmap/streaks/counts; contributes 0 logged hours.

Every surface renders hours as `duration/60` and buckets by
`categoryPath[0]`. Schedule markers (`kind:'schedule'` or legacy pending
`scheduled_for`) and legacy `dismissed` are excluded from work views.

## Existing-data port-in (read-only, no migration)

Legacy `trackerEntries` are never rewritten — they render + aggregate
under the new rules:
- **Missing/legacy `categoryPath`** → "Uncategorized" (all category
  helpers guard `!path || !path.length`); lab-stats falls back to the
  flat `category` string.
- **`status:'pending'` (confirm-era auto-estimates)** → treated as
  *presence*, not logged hours. The shared rule `count duration only
  when status !== 'pending'` is applied in the tracker's `_loggedMins`
  (used by every analytics/weekly sum), PMR Stats, dashboard, and
  lab-stats. This is the principled mapping: old unconfirmed page-time
  estimates are the pre-overhaul equivalent of the new hours-free
  presence events, so they count as activity (heatmap/streak) but not
  as hours — and no surface inflates. It also matches the original PMR
  "confirmed only" behavior.
- **`status:'confirmed'`** → logged hours everywhere (unchanged).
- **`hours` (very old field, no `duration`)** → lab-stats still honors
  it as hours; the tracker/PMR use `duration` only (such rows predate
  V3.49 and are effectively absent from this collection).

## Unrecoverable-history caveat

The pre-V3.320 rich tracker (with ~2 years of uncommitted V3.107–V3.319
refinements) was committed over by the `V3.325` batch commit and is not
in git history or any dangling blob. The restore base is therefore the
V3.49 original port; interim tracker fixes not re-derived here are lost.
`activity-signals.js` + `page-time-tracker.js` keep the V3.319 event
model (unchanged this release).
