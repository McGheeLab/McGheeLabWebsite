## S-γ — submission-document service compiles (`rm/js/paper-export.js`)

- The Submission-documents card's **Compile** buttons enable when
  (contributor && section has content && gate detected); click →
  `_compileSubdoc(doc)`: `PaperSubdocs.buildSubdocBundle` → POST with
  `docKind: 'cover_letter'|'rebuttal'` (+ the subdoc templateId, NO manuscript addons) →
  the PDF opens in a new tab. Because the service stamps `docKind`, the compile lands in
  history WITHOUT touching the main staleness banner / auto-mount (the D1 `mainCompiles`
  guard).
- Each doc row shows **↗ last PDF** (newest compile of that kind; URL re-minted via
  `firebase.storage().ref(pdfStoragePath).getDownloadURL()` — `_openCompilePdf`).
- `_bindSubdocs` re-runs on every compiles snapshot, so the buttons unlock live.

## D2 — marked-up revision diffs

- Compile-history card gains **"Marked-up diff vs ⌄"** (`#px-diff-row`): the picker lists
  MAIN compiles that stored their flat source (`flatStoragePath`); empty state explains
  "compile once". A template mismatch between base and current prompts a
  may-be-unreliable confirm. **Compile diff** POSTs
  `{mode:'diff', baseCompileId, flatSource (current, client-flattened), files,
  figureAssets, docKind:'diff'}` → the underline/strikeout PDF opens; the status notes the
  latexdiff limitation (bibliography changes aren't marked).
- **Marked-up diffs list** (`#px-diff-list`): compiles with `docKind:'diff'` — "Δ when ·
  vs <base>" + open. Both the picker and the list track the compiles snapshot
  (`_bindDiffUI` wired into `_subscribeCompiles`).
