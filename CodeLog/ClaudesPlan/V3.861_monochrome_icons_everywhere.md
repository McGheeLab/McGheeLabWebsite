# V3.861 — Monochrome icons everywhere: no colour-emoji images left in the UI

Alex, 2026-10-23: *"go through the entire site, and ensure the icons we use are
the solid color type not the colored images i really dont like that. look
everywhere and replace with a standard library"*

## Why this is needed again

V3.641/642 built the Heroicons seam and converted the **chrome** (675 call
sites), then stopped on purpose: Alex's decision at the time was "chrome + UI
controls only, not prose, not user-picked icons", and 880 glyphs were left as
DONE. Two months and ~200 versions later, a scan of every shipped file found
**~2,000 colour-emoji sites in 175 files** (1,420 outside comments): new
features (notebook canvas, My Week, protocols graph, training pages, course
modules) kept adding emoji because nothing failed when one was added. The new
instruction supersedes the "chrome only" scope: *look everywhere*.

## Decisions

1. **Library: Heroicons v2 stays the base (don't re-litigate V3.641), Lucide
   fills the gaps.** Heroicons has no droplet, brain, atom, rat, keyboard,
   flask, thermometer, dice… V3.641's answer was hand-drawn customs; Alex now
   asks for "a standard library", so gaps come from **Lucide** (ISC, 1,500
   icons, same 24-grid round-cap outline family). The generator drops each
   source's root `stroke-width` and `.hi` sets it, so both libraries draw at one
   weight — checked by rendering all 203 side by side. Vendored at
   `vendor/lucide/` (repo root, NOT `rm/` — same reason as `vendor/heroicons/`).
2. **"Solid color" = monochrome (`currentColor`), not Heroicons' filled
   weight.** Outline stays the default, solid for active/selected (V3.641).
3. **Colour that IS meaning stays colour, as a solid shape.** 🔴🟢🟡… status
   markers and user-picked markers render as a tinted solid dot
   (`manifest.tint{}` → `ICON.render`), not as an image.
4. **Text-only channels lose the emoji.** A tooltip, `placeholder`, `<option>`,
   toast (`TOAST` renders `textContent`), `alert/confirm`, `document.title`,
   exported text/markdown and persisted HTML cannot hold an SVG; the words stay,
   the picture goes.
5. **Exceptions, marked `emoji-ok`:** the chat **reaction** set (20 faces and
   gestures people react with — content, not iconography; most have no icon
   equivalent) and user-typed text. The public site's five story reactions are
   NOT an exception: a fixed row of buttons, each with an exact icon
   (`key` — what Firestore stores — unchanged). Gabe's
   Scientia build (`rm/scientia/`) is a vendored collaborator app (served
   unchanged except the V3.857 one-line patch) and is out of scope like
   `rm/vendor/`.
6. **Stored values keep working.** Every glyph that can be stored (V3.555 icon
   picker palette, config maps) is in `BY_GLYPH`, so `ICON.render()` draws
   stored emoji as icons with no migration. The picker now offers icon NAMES.
7. **Course modules stay self-contained** (modules/AUTHORING.md §0): they get
   an inline `<symbol>` sprite of exactly the icons they use, generated by
   `scripts/module_icons.py`, not a dependency on `/rm/js/icons.js`.
8. **A gate, so it can't creep back:** `gen-icons.mjs --emoji` fails on any
   colour emoji in shipped JS/HTML/CSS outside comments; `release_push.py`
   runs it beside `--check --scan`.

## The swap

Six disjoint file batches (research/My Week · notebook/canvas/whiteboard ·
protocols/training · library/paper/chat/rest of rm/js · the six large bme466
homeworks · rm/pages + public root + remaining modules), each converted by
reading context rather than by codemod — the V3.642 codemods stopped exactly
where context decides (text sinks, `${}` expressions, persisted strings, maps
with consumers in other files). Rules per context are in the brief that drove
the batches; the important ones:

- markup → `ICON.svg(name)` / `<i data-hi>` / module `<use href="#hi-…">`
- text sink → `ICON.label(el, name, text)`; never ICON markup into textContent
- config map → icon names + every consumer through `ICON.render()`
- canvas → `ICON.draw` / `HI.draw`; `<text>🪨</text>` in SVG → nested icon
- comparisons, keys, persisted data → leave the data alone, change the render

## Result

**~1,450 sites converted in 192 files**, gate at **0 colour emoji across 692
shipped files**. Batches: research/My Week/PMR 204 · notebook/canvas/whiteboard
220 · protocols/training 233 · library/paper/chat/rest of rm/js 205 · six BME
466 homeworks 242 · rm/pages + public root + 22 modules ~250, then 54 written as
escapes (`'\u{1F4C5}'`, `'\uD83D\uDCCC'`, `&#128279;`) the first gate missed —
it now decodes them, and scans `deploy/site.json`'s whole include list instead
of four folders (it had skipped `rm/js/` subfolders, `rm/index.html`, `poster/`).

Things the context-reading caught that a codemod would not have:

- **Persisted strings stay data.** Notebook mirror HTML, calculator results,
  `retry.last_error`, the protocol demo lessons (imported as the user's own
  protocol prose, which escapes HTML) — emoji dropped, no SVG stored.
- **Shared maps became icon names** (`RESEARCH_DATA.LEVELS`, `ITEM_OUTCOME_META`,
  the canvas-widgets registry, `NODE_ICONS`, `CALLOUT_META`, …) with every
  consumer on `ICON.render`; three consumers in other files
  (`library-collapse.js`, `actions.html`, `scan.html`) were found by the
  batches' cross-file grep and fixed before deploy.
- **SVG inside `<option>` renders as nothing** — task-market's Importance select
  had shown five blank options; options now use words / ★.
- **GHS pictograms** were glyph-for-glyph wrong (Flammable drew ☢, Corrosive ☠):
  now bomb · fire · fire · cylinder · droplet · skull · exclamation ·
  heart-pulse · fish, in both `chemicals.js` and `lab-notebook.js`.
- **A module variable named `HI`** (01-diffusion `const LO=-9, HI=0.35`) hid the
  sprite helper and a canvas marker silently vanished; renamed, and
  `module_icons.py` now refuses a module that declares `HI`.
- Pre-existing bug fixed in passing: research-progress.js escaped a joined HTML
  string, printing raw `<span>` markup in the weekly trail.

Coordination: a parallel session (V3.860, whiteboard pen modes) owned five
regions of `whiteboard.js` and wrote them icon-clean itself. Its two manual
`deploy.py ftp` runs (which ignore `autoDeploy:false`) put ~23 mid-sweep files
live; every live copy was fetched back and syntax-checked (all parse), and the
worst interim state was cosmetic.
