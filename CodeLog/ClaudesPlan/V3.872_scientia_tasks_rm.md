## What this version does (web build only; `scientia/src` untouched)

- **A task component written in a note on the web becomes a task in your RM list** (`userData/{uid}/tasks`, bucket
  *assigned*, the document `TASK_ASSIGN.writeTaskFor` writes), so it shows in My Week's inbox, on the phone and to
  your mentor. The block carries `rmTaskId`; its text, due time and priority follow it to RM as you edit them.
- **Done flows both ways.** Tick the block → the RM task is done. Finish it in My Week → the block is done on the next
  sync (the hub reconciles on every hello and every two minutes; the later change wins), with a log entry marked
  *via RM*. Reopen on either side the same way.
- **Remove the block** (or the note) → the RM task is dismissed (My Week hides it) and the pairing is dropped.
- The block shows an **RM** chip (opens RM's Tasks) once paired; the `#/tasks` pointer page lists the note's task
  components with their RM state and a *Send to RM* for ones made before this version.

## Design

### Hub (`functions/scientia-hub-core.js`, `functions/scientia-hub.js`)

- `rmTaskFromBlock({uid, name, b, now})` — the RM document: `id 'task-<ts36>-<4>'`, `text` (first line), `bucket:
  'assigned'`, `status: 'pending'`, `done: false`, `due_date` (`YYYY-MM-DD` or `TBD`), `priority` + `self_importance`
  (high 2 / normal 0 / low −1), `notes`, `assignedToUid/Name`, `assigned_by_uid/name` (yourself), `created_at`,
  `source: 'scientia'`, `source_ref: {scientia: {docId, blockId}, docTitle, projectName}`. `rmTaskPatch(u)` — what
  `update` may change (text, due, prio, notes, done + done_at).
- The pairing lives on the hub doc: `rmTasks: {taskId: blockId}` (one RM task per block; `createTask` is idempotent).
- `planTaskSync({state, pairs, now})` — pure: for each pairing, compare the block's `task.done` with the RM doc's
  `done`; when they differ the later timestamp wins (block: `task.done` or `modified`; task: `done_at` /
  `updated_at` / `updatedAt`) → either an RM patch or a block op (`task.done`, `task.rmDoneAt`, a log entry
  `{via: 'rm'}`), pushed through the hub's own `push` as device **RM tasks**. A block that is no longer a live task
  → the RM task gets `dismissed_at` + `dismissed_reason` and the pairing is dropped; a task deleted in RM → dropped.
- Routes: `POST api/rm/tasks` {blockId, docId, text, due, allDay, prio, notes, docTitle, projectName} → {id, task};
  `POST api/rm/tasks/update` {id, text?, due?, prio?, notes?, done?, doneAt?}; `GET api/rm/tasks?ids=`;
  `POST api/rm/tasks/sync` (forced). `hello` / `state` run `syncTasks` quietly, throttled (`taskSyncAt`, 2 min).
  `MemoryHub` keeps `rmTaskDocs` / `rmTasks` for fixtures.
- `FirestoreHub`: `_taskRef`, `_pairs`, `createTask` (set + `rmTasks` merge), `updateTask` (only paired ids),
  `getTasks` (`getAll`), `syncTasks` (`getAll` the task docs and the block rows, plan, push, patch, prune with
  `FieldValue.delete()` on `rmTasks.<id>`). **Deployed** before the client.

Why the hub, not the browser, reconciles: the desktop app syncs through the same hub, so a task ticked in My Week
reaches Gabe's desktop record too, and a block ticked on the desktop reaches RM on the next hello — without the
desktop knowing RM exists (Phase 3 territory, had for free).

### Lab mode (`rm/scientia/lab-mode.js`, section 6)

- `TASK.create` wrapped: after Gabe's create, `sendTask(b)` → `POST api/rm/tasks` → `b.rmTaskId = id` (`DB.put`).
- `TASK.save` wrapped: a paired block's text / due / allDay / prio go to `api/rm/tasks/update` (debounced 800 ms,
  only when one of them changed since the last send — a shadow map).
- `TASK.done` / `TASK.undo` wrapped: after Gabe's, `update {done, doneAt}` for a paired block.
- `TASK.body` wrapped: a paired block gets an **RM** chip (`↗ RM`, opens `/rm/pages/tasks.html`); an unpaired live
  block on the web gets *Send to RM*.
- `VIEWS.tasks` (the V3.869 pointer) now also lists the live task components with their RM state and *Send to RM*.
- `window.SIS_LAB.tasks = { send, pending }` for the harness.
