# V3.332 — Main-Site Login Experience Overhaul

## Goal

Fix the accumulated UX debt in the main site's `#/login` flow: the login-page
flash on every authenticated reload, the missing password-reset path (a hard
dead end for lab members), raw Firebase error strings, no popup-blocked
fallback for Google sign-in, silently swallowed profile-load failures, and a
latent `ReferenceError` in the login error path. RM's auth surface is a
separate release (V3.333).

## Approach

### Router auth gate (kills the login flash)
`Auth._authStateResolved` existed since its introduction but was never read
by the router. `app.js render()` now short-circuits `dashboard` / `admin` /
`cv` / `login` to a spinner until the first `onAuthStateChanged` fires; the
existing `Auth.onChange` handler in app.js re-renders once it does. Companion
fix: `lastAuthUid` starts `undefined` (was `null`) so the first resolution
for a *logged-out* visitor (`uid === null`) still triggers the re-render —
otherwise the spinner would never clear. `apps` is excluded (lab-apps.js
self-handles via the same flag); `logout` is excluded so it stays reachable.

### Friendly errors
New `AUTH_ERROR_MESSAGES` map + `friendlyAuthError(err)` (exported as
`McgheeLab.friendlyAuthError`). `user-not-found` / `wrong-password` /
`invalid-credential` share one "Incorrect email or password." so the form
can't probe which emails have accounts. Non-`auth/*` errors pass through
`err.message` so `Auth.register`'s human-written invitation errors survive.

### Password reset
`Auth.sendPasswordReset(email)` (compat `sendPasswordResetEmail` with a
continue-URL back to `#/login`). UI is a "Forgot password?" link-button under
the Lab Members form reusing the email field — no modal. Success and
`auth/user-not-found` show the same generic confirmation (anti-enumeration).
30s resend cooldown.

### Popup-blocked fallback
Guest-doc creation extracted to `Auth._ensureGuestDoc(user)`. On
`auth/popup-blocked` (or `operation-not-supported-in-this-environment`),
`googleLogin()` stores `mcghee_google_redirect_pending` + a default
`mcghee_login_redirect`, then `signInWithRedirect`. Return leg in
`Auth.init()` calls `getRedirectResult()` → `_ensureGuestDoc` → profile load;
errors are stashed in `mcghee_google_redirect_error` and shown by
`wireLogin`. **Known limitation:** `authDomain` is
`mcgheelab-f56cc.firebaseapp.com`, so the redirect round-trip can fail under
Safari/incognito storage partitioning — the mapped popup-blocked message is
the honest fallback there.

### Profile-load resilience
- `Auth.init` keeps the fast first profile read; on failure it keeps the user
  signed in with a null profile (never drop auth — see
  `feedback_auth_bridge_null_profile`) and starts `_retryProfileLoad(uid)`:
  3 background attempts at 1.5s/3s/6s. Success re-fires listeners, updates
  nav, and forces one router pass (`HashChangeEvent`) to upgrade the open
  gated page past app.js's uid-dedupe. Exhausted retries show a dismissible
  fixed banner (`.profile-load-notice`) with a Retry button.
- `wireLogin`'s eager post-login profile loads are wrapped in an 8s
  `withTimeout` so a hung read can't freeze the "Please wait…" button.

### Misc
- `const fd` hoisted out of the `try` in `wireLogin` — reading `fd` in the
  `catch` threw a `ReferenceError` on any login failure (button stuck
  disabled with "Please wait…").
- Lab-member login success now honors `sessionStorage['mcghee_login_redirect']`
  (previously Google-only), as does `renderLogin`'s already-authed branch.
- All six bare `<p>Redirecting…</p>` placeholders replaced with
  `authLoadingHTML()` (spinner + label; reduced-motion safe).

## Files

- `user-system.js` — error map, `withTimeout`, `authLoadingHTML`, Auth
  changes (`init` return-leg + retry, `_ensureGuestDoc`, `googleLogin`,
  `sendPasswordReset`, `_retryProfileLoad`, `_showProfileNotice`),
  `renderLogin` (forgot-password UI, redirect consume), `wireLogin`
  (fd hoist, friendly errors, timeouts, redirect restore, reset wiring,
  null-user tolerance), exports.
- `app.js` — render() auth gate; `lastAuthUid` sentinel fix.
- `user-styles.css` — `.auth-notice`, `.auth-link-btn`, `.auth-loading` /
  `.auth-spinner`, `.profile-load-notice`.
- `sw.js` — CACHE_VERSION 303 → 304.

## Key decisions

- Gate in the router (one place) rather than per-render-function guards —
  the per-function `if (!Auth.currentUser) redirect` guards stay as the
  post-resolution behavior.
- Reset flow is inline on the login card, not a separate route/modal
  (focused single-purpose tool, minimal surface).
- No email verification added — accounts are invitation-only or Google.
