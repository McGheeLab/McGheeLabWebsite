# V3.469 — Grant unification R7: bridges to the existing tools

> Seventh release. Keeps the existing biosketch + facilities tools reachable from the
> Grant Docs page rather than reimplementing them.

## What shipped (rm/js/paper-grant-docs.js + rm/css/paper-editor.css)

- The **Biosketch** section card gains a "🧬 Manage variants ↗" link → opens
  `grant-biosketch.html` (the mechanism-aware editor with live `cvData` pulls —
  untouched) in a new tab. Draft/edit variants there; pull the Personal Statement in
  via R5's "📥 Insert biosketch prose".
- The **Facilities** section card gains a "🏢 Manage / regenerate ↗" link → opens
  `grant-facilities.html` (auto-generate from inventory / equipment / people, with the
  keep-my-edits stale-detection — untouched) in a new tab. Regenerate there; pull it in
  via R5's "📥 Insert facilities boilerplate".

## Design note

The plan floated an *inline* "regenerate from inventory" on the builder. In practice
`grant-facilities.js`'s auto-generators depend on its own data pipeline (loading the
`inventory`/`equipment`/`users` collections + `LAB_USERS` visibility), so calling them
from the builder would duplicate that whole pipeline or load a page-controller into the
editor. The R5 insert-picker already delivers the end value (regenerate on the
Facilities page → insert here); R7 just adds the discoverability link both directions.
Inline regenerate remains a possible later refactor (extract the auto-generators into a
shared pure module) but is deliberately deferred — the bridge is complete without it.
