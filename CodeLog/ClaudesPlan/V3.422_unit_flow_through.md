# V3.422 — Mixed units flow THROUGH the graph (compose, cancel, print)

## Context

Alex: mixed units produced by one calculation node didn't plug into
other nodes as what they are — downstream variables showed no colors,
lettered X on the pad, and further math ignored them. Requirements:
composite units must carry into the next node, keep combining there,
CANCEL back to a single unit when the math does ("this needs to be
robust"), and the document must print those units so the user knows
what a number is.

## Root cause

Unit knowledge was per-node-local. `producedVars` derives category from
the DECLARED unit string only, so an equation result with no declared
unit is `category:'none'` everywhere downstream; the V3.417 dim checker
started from declared units each time and could not see a quantity an
upstream formula had computed.

## Kernel (`rm/js/protocol-graph.js`)

- **Unit-name algebra**: every quantity now carries `units` — an
  exponent map over canonical unit NAMES ({µL:1, mol:-1}) — alongside
  dim/scale/kinds. `canonicalUnit()` (+ `_CANON_UNITS`, µ/² preferred
  spellings scored) unifies uL/µL and um2/µm² so names cancel exactly
  regardless of typing. Only dimensional units enter the map;
  ratio/custom units stay out (mirrors dimOfUnit). `checkTokenDims`
  composes `units` through ×/÷/^ with the same dimMul/dimDiv/dimPow
  used for dims, and returns it.
- **`resolveQuantities(graph)`** (exported): topo-order walk producing
  {varName → quantity} for every produced variable. Declared units
  resolve directly (marked `declared`); an undeclared equation result
  gets the quantity its formula computes from its already-resolved
  operands (`computed:true`) — earlier results resolve before later
  ones, so composite units chain node → node → node and collapse when
  divided back out. Unresolvable (raw exprs, cycles) → unknown
  unitless, as before.
- **Labels**: `unitsLabel({µL:1, mol:-1}) → 'µL / mol'` (²/³
  superscripts, category-wheel + name ordering, stable);
  `quantityLabel(q)` prefers the composite unit, falls back to
  dimLabel for dim-only quantities.
- **`equationAliases(graph, node, upto, qtys?)`**: letters/colors now
  come from RESOLVED quantities — a computed pure-volume input letters
  **V** (was X), a mixed one letters **Q** with `cats` for pie
  coloring; each alias carries `qty` + `unitLabel`. Declared-unit
  behavior (R for %, X for custom) unchanged. Optional `qtys` arg
  reuses a caller's per-render resolution.
- **compile**: resolves quantities once; an undeclared equation
  result's `output.unit` is FILLED with the computed label and flagged
  `unitComputed:true` — so `buildSymbolTable` stamps it on the symbol
  and `formatSymbolValue` (doc `[!var:]` tokens, 🔗 picker rows,
  calculator cards via designInputsOutputs, node badges) prints
  "100 µL·mol" everywhere with ZERO renderer changes. Declared units
  are never overridden.

## Editor (`rm/js/protocol-graph-editor.js`)

- `qtysCache = resolveQuantities(graph)` once per render; `_varCats`
  (pie cats for computed multi-category vars — replaces the node-local
  `_eqResultCats`, and now sees mixing that arrives from UPSTREAM),
  `_computedUnitOf` (composite label).
- Resolved colors everywhere: output-row swatches/out-dots (pie),
  bound-row in-dots + chips (pie via new makeInDot `cats` opt), alias
  tags and pad variable buttons/strip chips (Q badge wears the conic
  pie, `unitLabel` shown instead of raw unit), swap-menu rows,
  `_edgeCategory` (computed single-cat vars get their true color).
- **Wire gradient**: a mixed-unit wire's stroke is a userSpaceOnUse
  linearGradient of its constituent dimension colors along the run
  (SVG strokes can't take conic pies) — colors match the dots at both
  ends.
- Pad dimensional note consumes `a.qty` (resolved), so warnings fire
  correctly on mixed inputs; the quiet info line prefers the composite
  unit ("computes to µL·mol", and shows honest ratios like mL/µL).
- Node value badge prefers `sym.unit` — computed composite labels show
  live on the card.
