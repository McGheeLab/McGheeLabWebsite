# V3.526 — My Day program: unified student input surface + cross-surface distribution

> **Program doc.** V3.526 is release R1; later releases (R2…R10) get slim
> plan docs that reference this one. Approved by Alex 2026-07-24 after a
> grill-then-plan interview; the full interview record and design lives in
> the session plan (`~/.claude/plans/students-have-multiple-surfaces-soft-minsky.md`).

## Goal

Students enter the same information on multiple RM surfaces — "what I
plan/did this week" lands in Huddle plans, PMR weekly entries, and the
activity tracker; task state is reported in tasks/huddle/PMR separately;
and nobody knows which page to open first. This program gives students
ONE mobile-first "start here" page (**My Day**) whose entries fan out to
every surface they belong on, makes every existing composer offer the
same cross-post suggestions, and finishes by retiring the redundant
composers and regrouping the nav.

## Problem

- Duplicate typing: the same planned experiment is described in the
  huddle composer, again in the PMR week, again in the tracker.
- No coordination: a booked instrument, the plan announcement, the
  notebook record, and the activity log are four unrelated actions.
- No entry point: `rm/index.html` is a workflow chooser, not a work
  surface; students bounce between 6 nav groups.

## Decisions (locked with Alex)

1. New **mobile-first** `rm/pages/my-day.html` — unified entry point and
   future Ourlab phone home screen.
2. **Fan-out distribution.** Canonical flow: "confocal 2–4pm for
   experiment X" → inline equipment-availability check at selection time
   → creates the `equipmentBookings` booking + `huddlePlans` post +
   notebook entry stub (optional protocol linked as `protocol_run`) +
   tracker schedule event.
3. **Every surface double-dips** — after any native composer succeeds it
   offers cross-post chips via the same shared module.
4. **Auto-distribute**: persistent per-user toggle, ON by default,
   per-surface exclusion list; manual destination chips when off.
5. **Full cascade** via backrefs: edits propagate, deletes remove copies
   — except notebook entries with user content, which orphan with a note.
6. **Notebook is canonical** for "what I did"; PMR gains "Assemble my
   week" + a summary field (R7).
7. **Retirements are feature-flagged and reversible** (R8/R9): huddle
   plan composer, tracker manual entry, task quick-add CTA.
8. **Nav/guidance cleanup ships last** (R10).

## Data model

### `userData/{uid}/dayPlans/{itemId}` — per-item docs

Covered by the existing `userData/{userId}/{document=**}` wildcard rule
(firestore.rules:1544) → **zero rules changes** for the core collection.
No composite indexes (owner subcollection single-field date ranges).

```js
{ id: 'day-<ts36>-<rand4>',
  type: 'equipment'|'work'|'task'|'meeting'|'reading'|'order'|'help',
  title, notes, date: 'YYYY-MM-DD',
  startTime: 'HH:MM'|null, endTime: 'HH:MM'|null,
  status: 'planned'|'done'|'skipped'|'cancelled', confirmed_at: null,
  details: { /* type-specific */ },
  categoryPath: [],
  auto_distributed: true, excluded_surfaces: [],
  distributions: { <surface>: { surface, docPath, docId,
      status: 'created'|'pending'|'failed'|'orphaned'|'removed'|'skipped',
      lastSyncedAt, error, meta } },
  origin: null | { surface, docPath },   // set by double-dip import
  created_at, updated_at, ownerUid, schema_version: 1 }
```

Prefs doc `userData/{uid}/dayPlans/_prefs`:
`{ auto_distribute: true, excluded_surfaces: [], schema_version: 1 }`
(absent ⇒ auto ON). Route `my_day/prefs.json` registered for consistency;
the engine itself uses direct `firebridge.db()` refs (task-pmr-sync
pattern) so host pages don't need the route table.

### Verified destination shapes

- **huddlePlans** (`createPlan`, huddle.js:519-537): `ownerUid, ownerName,
  ownerCategory, weekId ('YYYY-Wnn' ISO), plannedDay ('YYYY-MM-DD'|null),
  startTime, endTime, text, notes, protocol ({url,title}|null),
  categoryId/Label, projectId/Name, watchers[], joiners[],
  joinRequests[], status:'planned', statusReason, delayedToWeek,
  seriesId, recurrence, createdAt, updatedAt`. Create/update open to
  authed users; delete owner-only. `weekId==` composite index exists.
- **trackerEntries** via `ActivitySignals` (activity-signals.js):
  `recordSchedule` → doc `auto-<kind>-<id>` (date moves on re-fire),
  `recordWork` → `auto-<kind>-<id>-<date>`, `removeSchedule(sourceRef)`.
- **equipmentBookings** (equipment.js:1759-73): strict `hasOnly` key
  whitelist in rules:749-753 → R2 adds `source_ref`; delete is
  admin-only → cascade CANCELS (`status:'cancelled'`, owner clause).
- **notebook** (notebook-schemas.js): `notebookEmptyEntry()` +
  `notebookIndexRow()`; `_index` upserts run in a transaction.

## Architecture — `rm/js/day-distribute.js`

Page-independent IIFE, `window.DAY_DISTRIBUTE`, fail-soft everywhere,
direct db refs. API: `getPrefs/setPrefs`, `defaultSurfacesFor(item)`,
`distribute(item, surfaces?)`, `cascadeUpdate(item)`,
`cascadeDelete(item)`, `retry(item, surface)`, `suggestFor(ctx)`,
`importAndDistribute(ctx, surfaces)`, `renderChips(el, ctx, onDone)`,
`registerAdapter(key, adapter)`.

Adapters (`{key, appliesTo, create, update, remove, describe}`) use
deterministic destination ids `day-<itemId>` / `auto-dayplan-<itemId>`
for idempotency. Cascade: item doc saves first; fan-out via
`Promise.allSettled`; failures → `{status:'failed', error}` + retry
chips; delete keeps the item as `cancelled` if any removal fails (no
stranded copies). Notebook copies stop receiving updates once they have
user content; deleting their item orphans them with a note.

Type → default surfaces: equipment → equipment+huddle+notebook+tracker;
work → huddle+notebook+tracker; task → task+tracker; meeting → tracker;
reading → tracker; order → tracker; help → huddle.

## Rollback

- Any release: FTP previous tree from git + sw bump. Deterministic
  `day-*` ids make stray fan-out docs cleanable with one query.
- R2 rules change is additive (optional `source_ref` key) — old clients
  unaffected; rollback = redeploy previous rules from git.
- R8/R9 flags default false; rollback = flip flag, zero deploys.
