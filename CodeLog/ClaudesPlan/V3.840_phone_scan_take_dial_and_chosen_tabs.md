# V3.840 — Phone app: scan a label → "how much are you taking?" on the Woodchuck dial; the bottom tabs are the user's choice

**Alex (2026-10-22):** *"this is not right, the purpose of the phone app is to be able to use items easily. we need
a button to scan a qr code, then it asks how much you are taking from inventory. each item has a different
selector unit. use the same radial selector for this that wodcuck uses. the user should be able to choose the
pages that are quick links at the bottom of the app."*

Follows V3.835 (QR labels, scan-to-use, Inventory tab in build 13). What V3.835 shipped on the phone was the
desktop inventory page with a small 📷 Scan button in a wrapped toolbar, and a scan opened a form with a number
box. This version makes the phone flow the two taps Alex described.

"Woodchuck" is the gym app in `MS/apps/gym` (its icon source is `art/woodchuck-1024.png`). Its numeric picker,
`js/picker.js`, is a bottom sheet with a snapping **drum wheel** and a **radial jog dial** (turn the knob for fine
steps, ± buttons, haptic tick). That interaction is ported here verbatim in behaviour; only the tokens change.

## 1. Scan → how much → done

- **A scan button that is the point of the tab.** In the app, `inventory.html` gets a scan hero at the top
  ("📷 Scan a label to use it") and a persistent camera FAB above the tab bar (both app-only via
  `body.ourlab-app`; the desktop keeps the toolbar button). `/l/CODE` on a phone camera (`?code=`) takes the same
  path.
- **The amount picker** — NEW `rm/js/qty-picker.js`, global `QTY_PICKER`:
  `open({ title, unit, value, max, min, step, fine, hint, presets, extraHtml, doneLabel, memo }) →
  Promise<{ value, extra } | null>`. Drum + dial + ±, preset chips, the readout with the unit, a hint line, an
  optional extra block (a note field, a "finished this one" tick). `QTY_PICKER_CORE` (DOM-free, node-tested):
  `niceStep(max)`, `specFor(unit, {max, remaining})`, `range`, `nearest`, `fmt`, `displayUnit`.
- **Each item has its own selector unit** — `INV_USE.pickerFor(item, mode)` (pure):

  | item | unit on the dial | values |
  |---|---|---|
  | package mode, tracked in a count unit (`pack`, `box`, `ea`…) | that unit | 1 … remaining, step 1 |
  | package mode, untracked | `package` | 1 … 50 |
  | per-use, tracked in a measure (`uL`, `mL`, `g`, `mg`…) | that unit | 0 … remaining on a 1/2/5 ladder (≤ ~400 drum rows), dial = ladder/10 |
  | per-use, tracked in a count unit (`vial`, `aliquot`) | that unit | 1 … remaining |
  | per-use, untracked | `use` | 1 … 20 |

  The default is what this device last took of this item (`memo`, localStorage), else 1 for counts, else a
  tenth of the range for measures. `uL`/`ug` display as µL/µg.
- **`INV_USE.plan` grows**, backward compatible (every V3.835 case unchanged):
  - `use` on a tracked item with an amount `n > 0` → via `qty` (delta −n in the item's unit) AND `use_count + 1`
    — "I took 2 µL of the antibody" moves the volume and counts the use. Untracked, or `n = 0` → the old log row.
  - `take` accepts a fractional `n` when the item's unit is a measure; counts and legacy stay integers.
  - `finish` on a tracked measure takes everything that is left (the vial is empty); counts take 1, as before.
- **`INV_USE.take(item, opts)`** is the flow: mode known → picker → plan → run → toast ("Took 2 µL of X · 98 µL
  left", reorder link when low) → `onDone`. Mode unknown → the V3.835 mode pick first (a manager's pick is
  remembered, a member's is for this time), then the picker. `INV_USE.sheet` now delegates to `take` so the
  desktop detail panel's "✓ Use / take" button and the scan share one path.
- `invHandleScan` (inventory.js): resolve → `INV_USE.take` straight away in the app (no table row expansion);
  the desktop still opens the row.

## 2. The bottom tabs are the user's choice

- `mobile-shell.js` gets a **CATALOG** of every page the app can show (the six V3.835 tabs + Notebook,
  Scheduler, Research, Meetings, Protocols, Buying, Equipment, PMR, Settings). A page with a native webview
  (`TabKey`) switches with `OurlabTabs.switchTo`; any other opens in the shell's misc webview via
  `OurlabTabs.open` — no Swift change, so this is a bundle refresh (patch bump).
- **Prefs:** `localStorage['ourlab-tabs.v1'] = { keys, dirty, at }` (read synchronously at mount — the bar renders
  before auth) mirrored to `userData/{uid}/prefs/mobileTabs` (owner-write under the blanket userData rule; no
  rules change). After auth: a `dirty` local copy is pushed up; otherwise a differing cloud copy is adopted and
  the bar re-renders. Default = the V3.835 six. Up to **6 pages + More**.
- **Customize tabs** sheet (More → ⚙ Customize tabs): every catalog page with a tick; ticked pages listed first
  in bar order with ▲ ▼; Save, Reset. No browser prompts. The More sheet lists the catalog pages that are NOT on
  the bar, so nothing becomes unreachable.
- Other warm webviews re-read the prefs on `ourlab:tab-visible` and rebuild their bar when the list changed
  (webviews share localStorage).
- `TABS_CORE` (`CATALOG`, `DEFAULT_KEYS`, `MAX_TABS`, `normalizeKeys`) is exported for node before the app gate.

## Decisions

- The landing tab stays My Week natively (`TabShellViewController.viewDidLoad`); the chosen order only changes
  the bar. Making the first chosen page the landing page needs a Swift change — deferred.
- The picker is used on the desktop too (mouse scroll on the drum, drag on the dial, ± buttons) so there is one
  amount surface, not two.
- A scanned per-use item that is quantity-tracked in a measure now MOVES the measure. V3.835 only counted a
  use; Alex's words ("how much you are taking") make the amount the record.
