# V3.188 — Comprehensive citation-style detection in the paper reader

## Goal

Make the paper-reader's citation-finder (`rm/js/paper-citations.js`)
recognize every common in-text citation style used in the life-sciences
literature we read, so the "Citations on page N" left sidebar populates
correctly for any paper in the library — not just those using the two
styles the V3.100 / V3.101 / V3.105 code originally targeted.

## Trigger

User report (2026-05-12) — the citation finder misses tokens in:

- `https://doi.org/10.1007/s00018-025-06036-6` — *Cell. Mol. Life Sci.*
  (Springer). House style is bracketed Vancouver numbers `[12]` but the
  CMLS body PDF also commonly uses round-paren `(12)` and citation
  clusters `[12, 14–17]`. May also be a refs-parser miss.
- `10.1038/s41598-025-25381-x` — *Scientific Reports* (Nature). House
  style is **superscript numerals** with no brackets — e.g.
  `phenomenon¹,²,³`. Current `RE_NUMERIC` requires `[...]`, so nothing
  matches.
- `10.3389/fncel.2019.00230` — *Frontiers in Cellular Neuroscience*.
  APA-style author-year with semicolon clusters. Current `RE_AUTHOR_YEAR`
  matches *one* author+year ending at `)`, so multi-cite clusters drop
  every cite but the first.

## Citation styles to support

### Already supported (keep / refine)

1. **Bracketed numeric** — `[12]`, `[12, 14]`, `[12–14]`, `[1, 3–5, 7]`
   - Add: allow optional whitespace inside brackets `[ 12 ]`
   - Add: superscript-bracket Unicode `[⁵]` (rare; via super-num pass)

2. **Parenthetical author-year, single cite** — `(Smith, 2020)`,
   `(Smith et al., 2020)`, `(Smith and Jones, 2020)`,
   `(Smith & Jones, 2020)`, `(Smith, 2020a)`
   - Refined to support comma-less variant `(Smith 2020)` (Cell style)

### New

3. **Parenthesized numeric** — `(12)`, `(12, 14)`, `(12–14)`
   - Common in older Springer journals and some Cell-family titles.
   - Risk: collides with enumerated list markers `(1) intro (2) results`
     and equation references `(1)`. Mitigation:
     - Require the numeric cluster to appear **inside a sentence** (not
       at the start of a line, preceded by a word character, no leading
       colon or dash).
     - Require the cluster to reference a *valid* ref number — drop the
       token if the number > `_refs.length` or doesn't match a parsed
       ref. (Soft filter — falls back to `unmatched` row, never crashes.)

4. **Author-year cluster (semicolon-separated)** — `(Smith et al.,
   2020; Jones et al., 2021)`
   - Match the entire parenthetical group, then split inner on `;`
     and run the single-cite extractor on each segment. One row per
     cite, narrowed rect per segment (via `_rectForRange`).

5. **Author-year same-author multi-year** — `(Smith et al., 2019,
   2020)`, `(Smith, 2019a, 2019b)`
   - Inner detector: after extracting `Author, YEAR`, scan for
     additional `\b(\d{4}[a-z]?)\b` tokens *within the same paren*. Each
     extra year becomes its own match against the same author.

6. **Narrative cite** — `Smith et al. (2020)`, `Smith and Jones (2020)`,
   `Smith (2020)`
   - Open-paren wraps the year only; the author is outside the parens.
   - Also handle `Smith et al. (2019, 2020)` — multi-year inside.

7. **Unicode-superscript numeric** — `phenomenon¹,²,³` or
   `phenomenon¹⁻³`
   - Detect runs of `[⁰¹²³⁴⁵⁶⁷⁸⁹]` plus connectives
     `,\-–  `. Translate to ASCII digits, expand cluster.

8. **Geometric superscript numeric** — same as (7) but for PDFs whose
   text layer extracts numbered superscripts as plain ASCII digits
   in a smaller-height span (Nature / Sci Reports often do this).
   Detection:
   - Compute median item height per page.
   - For each text item whose `height < 0.78 × medianH` AND whose text
     matches `^\s*\d+(?:\s*[,\-–]\s*\d+)*\s*$` AND whose immediately
     preceding item (in reading order) is body-height (~median) and
     ends in a *letter or punctuation* (not whitespace, not a digit):
     - Treat as a superscript citation cluster. Expand to one match
       per ref number, rect from the item itself.
   - Conservatively reject if previous item already ends in a digit
     (avoids matching "Table 1 2" → "12").

### Not in scope (yet)

- Roman numerals (`[ii]`, `[IV]`) — vanishingly rare in modern STEM.
- Letter footnotes (`[a]`, `^b`) — usually not bibliographic citations.
- Chinese / Japanese / cyrillic surname cites — out of scope.
- Cite tokens that span multiple lines / pages — keep current
  same-page constraint.

## Implementation

### Refactor `_scanPage`

Today it does two inlined regex passes (`RE_NUMERIC`,
`RE_AUTHOR_YEAR`). Refactor into pluggable scanner functions that all
write into the same `matches` array:

```
_scanPage(pageNum)
  → _scanBracketNumeric(fullText, ranges, ctx, matches)
  → _scanParenNumeric(fullText, ranges, ctx, matches, refs)
  → _scanUnicodeSuper(fullText, ranges, ctx, matches)
  → _scanGeomSuper(items, ctx, matches, medianH)
  → _scanAuthorYearGroup(fullText, ranges, ctx, matches)   // handles single + cluster + multi-year
  → _scanNarrative(fullText, ranges, ctx, matches)
  → _dedupeMatches(matches)
```

`ctx` = `{ pageNum, wrapRect }`. `_dedupeMatches` collapses entries
with the same `(refKey, page)` and overlapping rects — needed because
the unicode-super and geom-super passes can both fire on the same
digit span.

### `_matchedRef` updates

Existing kinds (`'numeric'`, `'authoryear'`) cover the new tokens
semantically:

- `'numeric'`: paren-numeric, unicode-super, geom-super (all look up
  by ref number)
- `'authoryear'`: cluster cites, multi-year cites, narrative cites
  (all look up by surname + year)

So the matching logic stays the same; only the *token* string and
rect differ per kind. We *will* add an internal `kindLabel` field for
debugging in console.info (`numeric:bracket`, `numeric:paren`,
`numeric:super-unicode`, `numeric:super-geom`,
`authoryear:single`, `authoryear:cluster`, `authoryear:multiyear`,
`authoryear:narrative`).

### Robustness fixes to existing patterns

- `\[\s*(\d+(?:\s*[–\-,]\s*\d+)*)\s*\]` — allow padding spaces.
- Author surname char class: extend `[A-Z][A-Za-zÀ-ſ'-]+` to
  `[A-Z][A-Za-zÀ-ɏ'\-]+` to cover full Latin
  Extended-A + Extended-B (e.g. names with `ě`, `ć`, `ş`).
- Author-year: tolerate comma-less form `(Smith 2020)` by making
  the `,` optional in the single-cite regex.

### Diagnostic

Add a one-line debug print at the top of `_scanPage` summarizing
matches per kindLabel — easy to spot which pass surfaced what when
opening a new paper:

```
[paper-citations] p.4 matches: bracket=0 paren=0 super-uni=12
                                super-geom=0 ay-single=0 narr=0
```

## Test plan

Manual against the three reported papers + a fourth (any IEEE paper
for `[N]` regression check):

1. `10.3389/fncel.2019.00230` → multi-cite clusters surface each ref
   as its own row; narrowed flash rect lands on the segment, not the
   whole paren.
2. `10.1038/s41598-2025-25381-x` → superscript clusters surface one
   row per ref; flash rect lands on the small-height digit span.
3. `10.1007/s00018-025-06036-6` → either bracket OR paren detection
   picks up the cites.
4. Any older IEEE paper with `[12]` style → no regression.

Verify in console: `[paper-citations] p.N matches: …` shows
non-zero counts for the expected pass.
