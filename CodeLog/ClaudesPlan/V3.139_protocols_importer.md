# V3.139 — Protocols Builder: importer + component-matching wizard

## Goal

Phase 6 of the Protocols Builder roadmap (master plan:
`~/.claude/plans/we-want-to-make-idempotent-pixel.md`). Two coupled
capabilities:

1. **Import** — convert an existing lab protocol from `.md` / `.docx` /
   `.pdf` into the RM standard format via a new Claude skill, then
   upload the resulting JSON via a new "📥 Import protocol" button on
   the protocols list page. The import flow extracts embedded base64
   images, uploads them to Storage, creates the Firestore doc, and
   auto-saves a v1 snapshot labeled "Imported from <filename>".
2. **Component-matching wizard** — after import (auto-triggered) or
   any time later (via a new "🔁 Match inventory" topbar button), walk
   the materials rows whose `item_ref` is null, score live inventory
   candidates by name + vendor + cat# + CAS, and let the user accept /
   skip / pick-different per row.

## Approach

### New files

- `.claude/skills/protocol-import/SKILL.md` — the skill. Mirrors the
  existing `paper-overlay` skill pattern. Documents the target JSON
  schema, source-format support (`.md` / `.pdf` / `.docx`),
  block-kind-detection heuristics, calculation extraction rules
  (so prose like "5 mL × 2% = 0.1 g" becomes a `formula` block plus
  `[!var:agarose_mass]` references in step bodies), image extraction
  per format (`pdfimages -png`, pandoc round-trip for .docx, direct
  Read for .md), and a lab-notebook compatibility checklist (stable
  snake_case `output.name`s so the V3.116 + V3.127 chip + calculator
  flow works without further glue).
- `rm/js/protocol-import.js` (~360 lines) — page-side importer.
  Public surface: `PROTOCOL_IMPORT.{ parseJson, validate, summarize,
  createFromJson, openMatcher }`. `createFromJson` runs the import
  pipeline (slug uniqueness check → image upload → doc create →
  v1 snapshot via PROTOCOL_VERSIONS); returns `{id, autoMatch}` so
  the caller can navigate to `?protocol=<id>&match=1` when there are
  unlinked materials. `openMatcher` builds the matcher modal
  dynamically; reads the editor's live yTree via
  `window.__PROTOCOL_EDITOR_STATE` (exposed by the editor at boot).
- `CodeLog/ClaudesPlan/V3.139_protocols_importer.md` — this file.

### Files modified

- `rm/js/protocol-inventory.js` — new `findMatches(freeText, opts)`
  helper. Pure scoring function, no UI. Scores each cached inventory
  entry by cat# / CAS exact-match (+15), name substring (+10 either
  direction, +7 for the partial-bigger-than case), vendor (+8),
  formula (+3), category/subcategory (+2). Tie-break by stock_status
  ('full' > 'low' > '' > 'out_of_stock'). Returns top N (default 5)
  with `{entry, score, reasons[]}`.
- `rm/js/protocols.js` — wires the new `📥 Import protocol` button:
  modal with file-picker + paste textarea + auto-suggested slug +
  preview pane (counts of sections / steps / formulas / figures /
  notes / safeties). On Import, calls `PROTOCOL_IMPORT.createFromJson`
  with progress callbacks for slug-check / image-upload / doc-create
  / snapshot. Navigates to `?protocol=<id>&match=1` so the matcher
  auto-opens for unlinked materials.
- `rm/js/protocol-editor.js` — adds the `🔁 Match inventory` topbar
  button (always visible, disabled for read-only viewers); exposes
  `window.__PROTOCOL_EDITOR_STATE = { protocolId, yDoc, yTree, Y,
  canEdit, markDirty }` so `PROTOCOL_IMPORT.openMatcher` can mutate
  the open Y.Doc directly. Detects `?match=1` in the URL on boot,
  strips it via `history.replaceState`, and auto-opens the matcher
  after a 300 ms delay (lets inventory finish loading).
- `rm/pages/protocols.html` — adds the Import button + Import modal
  in list mode; `🔁 Match inventory` button in the editor topbar;
  loads `protocol-figures.js`, `protocol-versions.js`, and
  `protocol-import.js` in BOTH list mode (for create-from-json) and
  editor mode (for the always-available matcher).
- `rm/css/protocol-editor.css` — `.pr-import-modal`, `.pr-import-preview`,
  `.pr-import-progress`, `.pre-matcher-modal` + per-row layout.
- `sw.js` — `CACHE_VERSION` bump.
- `CodeLog/Updates/CHANGELOG.md` — V3.139 entry.
- `CodeLog/Architecture/ARCHITECTURE.md` — version header.

### Schema

The import format is a single JSON file. Top-level shape:

```json
{
  "format": "protocol-import-v1",
  "source": { "kind": "md|docx|pdf|other", "filename": "..." },
  "protocol": {
    "id": "",
    "title": "...",
    "summary": "...",
    "category": "...",
    "tags": [...],
    "tree": { "meta": {}, "sections": [{ "label": "...", "children": [block] }] }
  }
}
```

Figure blocks may carry `attrs.image_data_uri: "data:image/png;base64,..."`
which the importer decodes, uploads, and replaces with `image_url` /
`storage_path` / `hash` / `mime`. All other block shapes mirror the
in-flight V3.113/V3.117/V3.119/V3.121 schemas exactly.

### Auto-snapshot

Last step of `createFromJson` calls
`PROTOCOL_VERSIONS.saveVersion(id, tree, { label: 'Imported from
<source.filename>', message: 'Auto-snapshot taken at import time.
Source format: <kind>.' })` so the user can always return to the
freshly-imported state if they edit destructively.

### Component-matching wizard

`PROTOCOL_IMPORT.openMatcher(protocolId)`:

1. Reads `window.__PROTOCOL_EDITOR_STATE.yTree`.
2. Walks every materials row with `!item_ref && free_text.trim()`.
3. For each row, calls `PROTOCOL_INVENTORY.findMatches(row.free_text)`.
4. Renders a modal: per-row source label + best-match chip + Accept /
   Pick different / Skip buttons + collapsible "Other candidates"
   list.
5. On **Apply**, runs all chosen matches in a single `yDoc.transact`
   so the editor re-renders once. Each accept sets `yRow.item_ref =
   entry.id`; if the row's `free_text` is the original imported
   string, replace it with `formatLabel(entry)` so unlinking later
   leaves a human-readable label.

Trigger paths:
- **Auto-open after import**: `?match=1` in the URL → editor strips
  the param via `history.replaceState` and calls `openMatcher` after
  a 300 ms delay (lets inventory finish loading).
- **Always-available**: `🔁 Match inventory` topbar button.

## Acceptance test

1. Pick `Data/protocols/Agarose LLS -Sieves.md` as the source.
2. In a fresh Claude session, ask: "Convert this protocol to the
   RM import format" — Claude should pick up the
   `protocol-import` skill automatically, read the file, produce a
   `<slug>.protocol-import.json` with at least one `formula` block
   (`expression: "vol * wt_pct / 100"`), step bodies referencing
   `[!var:agarose_mass]`, a materials block with rows for the
   beakers / press / PBS / etc., and safety blocks for the boiling-
   water + autoclave warnings.
3. Open `mcgheelab.com/rm/pages/protocols.html`, click `📥 Import
   protocol`, drop in the JSON, confirm the preview pane shows
   the right counts, click Import.
4. Image uploads happen in sequence; progress bar shows
   "Uploading images (1/3)…" → done.
5. Browser navigates to `?protocol=<slug>&match=1`. The matcher
   modal auto-opens 300 ms after editor load with N rows of
   suggestions.
6. Accept / pick-different / skip per row, click Apply matches —
   chips on the materials block update, free_text is replaced with
   the inventory item's display label.
7. Versions dropdown shows v1 labeled "Imported from
   Agarose LLS -Sieves.md".
8. Reload — `?match=1` stripped from URL, matcher does not re-open;
   matched rows persist; chip + stock badges render correctly.
9. Edit the formula's `vol` from 5 to 12 — every step body
   `[!var:agarose_mass]` chip flips to `0.24 g` immediately.
10. From a lab notebook entry, click `📋 Protocol`, pick the imported
    protocol — chip lands; the V3.116/V3.127 calculator flow surfaces
    the formulas as live inputs.

If all 10 steps pass, V3.139 is done.

## Out of scope

- **Inventory matching INSIDE the skill (at conversion time).** The
  skill emits `item_ref: null` on every materials row; the page-side
  matcher does linking with the user's live inventory context.
- **Step-body inventory mention rewriting.** The matcher only touches
  materials rows. Wrapping `agarose` in step text with `[!inv:<id>]`
  is risky text mutation; deferred.
- **Bulk import.** One protocol per JSON file.
- **Round-trip back to source format.** No `.md` / `.docx` export.
