# V3.303 — viewer3d.html mobile layout fix

## Goal

The V3.301 Data Visualizations viewer works well on desktop but is cramped on
phones: the gimbal is too large, its iso/axis quick-links overlap the open
Controls panel, the preset pill bar overlaps the gimbal, and the colorbar
overlay (a "paper mode" toggle) drifts under other controls because it chases
the projected data bounding box rather than a fixed position.

## Root cause (measured at 390×844)

- `#hud` open width is `min(86vw,330px)` ≈ 330px; `#gwrap` at the old
  `scale(0.72)` rendered ≈114px wide anchored top-right. Their screen regions
  overlapped by roughly 78px horizontally × 116px vertically — real overlap,
  not just visual clutter.
- `#presets`' right gutter (`right:132px`) was tuned for the old 0.72 scale
  and left ~4px of overlap with the gimbal's rendered edge.
- `updateCbarPos()` has no mobile branch; its desktop logic centers the bar
  next to the projected object bounding box, which on a narrow phone
  viewport can land under the gimbal, the `☰ Controls` toggle, or the legend.

## Fix (all inline in `DataIllustrations/viewer3d.html`, mobile media query only — desktop untouched)

- Shrink the gimbal: `transform:scale(0.72)` → `scale(0.56)`.
- **Hide the gimbal outright while Controls is open**:
  `#hud.open ~ #gwrap{display:none}` — the two were never usable
  simultaneously on a small screen, so this removes the overlap entirely
  rather than fighting for a smaller shared footprint.
- Tighten the preset bar's right gutter to match the new gimbal footprint:
  `right:132px` → `right:106px` (gimbal's scaled+offset width is ≈102px;
  this leaves a clean few-px gap, verified zero-overlap at 390px and 375px).
- Colorbar: added a mobile branch to `updateCbarPos()` that pins the bar to
  a fixed safe column (`left:10px`, vertically centered between a top
  clearance of 64px — below the toggle/preset row — and a bottom clearance
  of 96px — above the legend) instead of tracking the projected bounding
  box. Mobile-only CSS narrows the bar (`26px`→`16px`) and its label offsets
  to match.
- `sw.js` `CACHE_VERSION` bumped for the deploy.

## Verification

Headless Chrome (puppeteer-core + system Chrome) at three viewports:
- **390×844 / 375×667 (phones)**: Controls closed by default; gimbal visible,
  shrunk, zero-overlap with the preset bar; opening Controls hides the
  gimbal entirely; toggling the Colorbar overlay control places it in the
  pinned safe zone (left=10px, top≥64px, bottom clears the legend).
- **1400×900 (desktop)**: no media-query match — Controls always visible,
  gimbal unscaled (`transform:none`), colorbar keeps its full 26px width —
  confirming the mobile-only changes don't regress desktop.

All checks pass (see verification transcript in the implementing session).
