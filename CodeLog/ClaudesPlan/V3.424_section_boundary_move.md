# V3.424 — Layout Mode is boundary-driven: grab a section's colored region to move it

> Alex's test feedback, item 3: "the resize handles for any section should be
> applied to the section boundary the colored part. and I should be able to move
> the sections from the colored region. In this layout mode the only thing im
> actually interacting with is the boundaries. All other content is supposed to
> automatically adjust to the boundaries i place."
>
> (Numbered V3.424 — parallel sessions took V3.422 [units flow-through] and
> V3.423 [passthrough connectors] mid-build.)

## What this delivers

In ⬒ Layout, every colored region is now the thing you grab:

- **Figures / tables** already had a boundary frame with resize handles (V3.420)
  and drag-to-move (V3.401). Unchanged.
- **Sections (headings + boxed specials like PNAS Significance)** now:
  - draw a colored **boundary frame** when selected (amber, matching the heading
    region tint), and
  - are **movable by dragging the colored region** — drag a heading/box onto
    another section and drop before/after it to reorder the whole section (and
    its `.tex`).

## Honesty note (why sections don't get width/height handles)

A figure has a real size lever (width, height cap) that maps to LaTeX
(`\includegraphics`), so its boundary resizes. A **text section reflows** — it
has no honest width/height in a constraint-based LaTeX layout (Alex's earlier
choice: no absolute x/y). So a section's boundary is a **move** handle, not a
resize handle: the frame marks what you grab, and the only honest lever is
reorder. Content still "adjusts to the boundary" — the per-column packer
(V3.421) reflows everything around whatever you move. Equations keep their Span
(column ↔ page) popover, which is their honest width lever.

## Changes — `rm/js/paper-doc-view.js`

- `state.layoutSelectedSecId` — the selected section (beside `layoutSelectedId`
  for floats); Esc/deselect clears both.
- Layout-Mode click: selecting a heading/boxed special (`[data-section-id]`)
  sets `layoutSelectedSecId` (clears the float selection) and draws its frame;
  the section popover (rename/move/delete) still opens on a plain click.
- `_applyLayoutSelection` branches: a selected float → resize frame (V3.420); a
  selected section → **`_attachSectionFrame`** (`.pdv-area-frame-move`, no
  handles) + **`_syncSectionFrame`** (sheet-local, zoom-corrected bounds).
- `_onDeskPointerDown` also grabs `.pdv-heading[data-section-id]` /
  `.pdv-significance[data-section-id]` → a `kind:'section'` drag (a no-move click
  still opens the popover; a drag reorders).
- `_resolveDropTarget` resolves a section drag to the target section under the
  pointer — its heading/box, or the section owning the flow block under the
  pointer (`_locateLiveBlock`) — before/after by pointer half.
- `_paintDropTarget` + `_startDragVisuals` + `_onDragUp` handle the section kind;
  `_commitDrop` computes `delta = finalIndex − curIndex` (final index in the
  order with the dragged section removed — matches `moveSection`'s
  delete-then-insert-at-`idx+delta`) and calls `PaperEditor.moveSection`.
- `_cancelDrag` now also clears the `.pdv-drop-after` accent (pre-existing gap,
  now used by section drops).
- `_syncLayoutViz` stamps the session class on the sheet ancestor (`.pdv-scale`)
  too, so editable regions can show a grab cursor.

## Changes — `rm/css/paper-doc-view.css`

`.pdv-area-frame-move` (amber boundary, no handles); grab/grabbing cursor on
`.pdv-session .pdv-heading[data-section-id]` / `.pdv-significance[...]`.
