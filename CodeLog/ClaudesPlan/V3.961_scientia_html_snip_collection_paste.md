# V3.961 — Scientia: snip figures out of HTML pages, /collection in the Atlas, paste from outside and between notes

## Goal

Gabe asked for four things in one message:

1. **Snip a figure out of an HTML page**, as the PDF clip (V3.901, 13zza) does for a PDF. His examples are three exported reports whose figures are drawn by their own scripts: SVG charts in `div.panel` cards (heading, legend, chart, caption), canvas plots in `div.plot` cards (a header with its legend), tables and pictures.
2. **`/collection <types…>`**: the Atlas with just the components of the types named (`/collection HTML`, `/collection HTML image PDF`). Every possible type is listed, and typing the command offers them as a list you click to add to the line, "like how video games do (look at Minecraft)".
3. **Paste from outside**:
   - a copied picture becomes an image panel;
   - a PDF or an HTML file becomes that component;
   - text becomes a block.
4. **Copy components and paste them in another note**: by default they are pulled in.

## Approach

### 1 · The HTML snip (new `13zzm-htmlsnip.js`)

A page runs sandboxed (`allow-scripts`, no same-origin), so the app cannot look inside it. As for its notes and ink (13zze), a script added to the page's copy does the page's side.

- **Finding figures.** The drawings are `svg`, `canvas`, `img`, `video`, `table`, `figure` and display equations. A figure is the box that holds one drawing and nothing else of its size. Walk up from the drawing while the box holds no other drawing, stays within 3.2× its area (340 px taller, 1.8× wider), and has under 700 characters of other text.
  - Its children sort into three groups. Text before the drawing is the label. Other text is the caption. Everything else (the legend, a header with controls) is the art.
  - This fits all three examples (measured by rendering them in headless Chrome first):
    - MESF `div.panel` → heading "Change from Count 0…", legend and chart, caption;
    - the small multiples → "Well B2" and its chart;
    - `div.plot` → header (title and legend) and canvas;
    - `div.step` → image and step caption.
- **Drawing the picture.** The page's frozen copy (13zze `freeze`, already used by Export ink labels) is drawn by html2canvas in a hidden script-free frame. A prototype showed two problems:
  - an SVG drawn by html2canvas loses the page's stylesheet, so the freeze now writes each SVG element's computed styles onto it;
  - a figure on a dark page came out unreadable on white, so the picture is drawn on the colour behind the element.
  The element is drawn alone (`mark`), so a chart wider than its scrolling panel comes out whole. A panel of several parts is drawn whole with its heading and caption hidden (`hide`), so the legend and chart close up. A box is drawn from the smallest element holding it, because a whole 13 000 px document took longer than 30 s.
- **The clip itself** is what a PDF's is: an image panel (or an equation through the same editor, now `CLIP.eqEdit`) lifted on top of the file, wired `c:clipped from`, with `clip.kind = 'html'` and the element's path, so "from …" scrolls the page back to it. KaTeX equations bring their own LaTeX.

### 2 · `/collection` (11b, 11c, 14b)

- The types live with the Atlas (`ATLAS.COLL`: 23 types, each with the words it answers to). Any other widget the build carries (the web build's RM cards) and the component kinds are added after them, so the list is the build's, never one kept by hand.
- The command takes a `many` argument (`CMD.resolve`: every word left, as a list), of a new kind `collect`.
- The Atlas in collection mode keeps the components of those types, coloured by type and all labelled. A row shows each type with its count, × to take it out, + Add, Show everything, and the command it is.
- The navigation bar already completes arguments. The "games" part is three changes in it:
  - the list sits over the word being typed;
  - the rest of the highlighted completion shows in grey (Minecraft's chat), and Tab takes it;
  - a `many` argument keeps its list open after each pick, without the types already on the line.

### 3 · Paste (13zu2, 13zu-lasso2)

- **Files** come from `clipboardData.items` and `files`. Pictures go in one image panel. A PDF, an HTML page, a spreadsheet or slides go through that insert's own code, with the pasted files standing in for the file dialog (`PLATE.pickFiles`), so a pasted file is made exactly as an inserted one.
- **A rich copy** (Word, a web page) brings a picture of itself, so text wins when there is HTML or our own type alongside.
- **Files pasted while writing** go under the component.
- **Components.** Ctrl+C on a selection (or the one clicked) with no text highlighted lets the browser's copy event happen, enabled with nothing selected by cancelling `beforecopy`. There the clipboard gets the components' text and our own type with their ids, so a paste knows them even after a reload. If no copy event comes, the text alone is written.
  - In another note each becomes a `ref` (a pull-in), placed as they sat. In their own note, or with Ctrl+Shift+V, they are copied as before.

## Key decisions

- **The same clip, not a second kind.** An HTML clip is the PDF clip's record (`clip`, the wire, lifted on top, "from …") with `kind: 'html'`. The equation editor is shared (`CLIP.eqEdit`), so the two cannot drift.
- **The page finds its own figures.** Only the page can see its layout. The app gets a description (label, caption, the element's path, the crop, what to hide) and never the page's DOM.
- **Draw the element, not the screen.** A browser page cannot screenshot itself. html2canvas on the frozen copy is what Export ink labels already uses, so the snip reuses it and improves it (SVG colours, fonts, scroll offsets) for both.
- **`/collection` belongs to the Atlas.** The lab's "Collection from the Lab Notebook" insert row (web) gave up the slash and is `/labcollection`; `insert-rmcollection` still works.
- **Pull in by default, copies on request.** Ctrl+Shift+V copies, because pasting into your own note has always copied and still does.
