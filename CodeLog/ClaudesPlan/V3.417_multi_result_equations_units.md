# V3.417 — Multi-result equation nodes + dimensional consistency + pie-wheel dims

## Context

Alex: the equation node should hold MULTIPLE equations/results (multiple
out-connectors), later equations can use earlier results as variables,
results are named independently, units combine through the math with
consistency checks (addition, exponentials …), and a multi-unit
variable's color becomes a pie wheel of its constituent dimension
colors.

## Kernel (`rm/js/protocol-graph.js`)

- **Schema**: `params.results = [{name, label, expr, unit, decimals}…]`;
  `_eqResults(p)` (exported `eqResults`) reads legacy single-result
  params as one result. The editor mirrors results[0] back to the
  top-level fields on every commit, so tours (`_named`), per-item list
  assembly (`sp.expr`), and old JSON keep working verbatim.
- **producedVars**: one produced var per named result → multiple
  out-connectors for free (var-rows already render per produced var).
- **compile** (scalar): one entry per result IN ORDER — the symbol
  table evaluates entries sequentially, so result 2 can reference
  result 1 (intra-node chaining with zero evaluator changes). blockIds
  suffixed `:i` for uniqueness. Per-item equations continue through the
  legacy mirror (multi-results are scalar-only, like the code node).
- **validateGraph**: per-result name/dup/empty-expr checks.
- **equationAliases(graph, node, uptoResultIndex)**: earlier results of
  the same node append as `local: true` aliases (dimension-lettered,
  numbering continues after the wires).
- **Dimension algebra**: dims are exponent maps over the unit
  categories (`{volume:1, amount:-1}`); `dimOfUnit/dimMul/dimDiv/
  dimPow/dimsEqual/dimCategories/dimLabel` (categories in wheel order;
  labels like `volume·amount`, `mass / volume`, `volume^2`).
  Dimension-level only — µL vs mL is one dimension (magnitude
  conversion out of scope).
- **checkTokenDims(tokens, dimByName)**: recursive-descent over the
  formula-pad token grammar. `+`/`-`/min/max demand equal dims (warns
  "adding volume to mass"); `*`/`/` combine; `^` demands a unitless
  exponent and a LITERAL power on united bases (else warns); `sqrt`
  halves exponents (odd → warns); `log`/`exp` demand unitless args;
  abs/round/floor/ceil pass through. Warnings, not hard errors;
  malformed streams return `ok:false` (unchecked).

## Editor (`rm/js/protocol-graph-editor.js`)

- Equation config = `_equationResults`: per result a "Result N" header
  (× removal when >1 — outgoing wires from the removed name are
  dropped), a name/label/unit(`_unitCellSelect`)/decimals row, and its
  OWN formula pad; **+ equation** appends. Renaming a result re-points
  its outgoing edges; `_ensureResults`/`_mirrorEq` maintain the legacy
  mirror.
- `_formulaPad(n, body, resultIdx)`: reads/writes `results[ri].expr`;
  aliases include the node's earlier results (locals). After a complete
  formula, a **dimensional note**: ⚠ warnings for internal mixing and
  for a declared unit disagreeing with the computed dim; otherwise a
  quiet "computes to volume·amount" hint on compound dims.
- **Pie-wheel coloring**: `_eqResultCats` — when a result has NO
  declared unit and its computed dim spans >1 category, its swatch and
  out-dot render `conic-gradient` wedges (equal slices, wheel order)
  of the constituent dimension colors; declared units keep their
  single-category color.
- Exploratory equation tour gains a "One node, many results" step.
