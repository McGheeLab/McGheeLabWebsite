# V3.865 — The phone app writes its own crash report, uploads it, and shares it in one tap

**Date:** 2026-10-23
**Alex:** *"gabe has an iphone 16+ — can we make it so if the app crashes it can log a detailed report, so he can share the
crash data without having to type anything"*

## Why
Build 17 "crashes on Gabe's phone" and we had nothing to go on: no TestFlight crash submission, TestFlight's crash count lags a
day, and the app keeps no log. Two different failures look like "a crash" to the person holding the phone:
1. **The app process dies** (exception, signal, watchdog, memory) — the app closes to the home screen.
2. **A page's web process dies** (WebKit's WebContent, usually memory) — the app survives; Capacitor reloads the page.

## Design
**Native (OurlabMobile, new `ios/App/App/OurlabDiagnostics.swift`, one file so the shell stays small):**
- **MetricKit** (`MXMetricManagerSubscriber`, registered in `AppDelegate.didFinishLaunching`): every `MXDiagnosticPayload` that
  carries crash / hang / CPU-exception / disk-write diagnostics is saved as a report with Apple's full JSON (exception type,
  signal, termination reason, symbolicated-by-Apple call stack trees, OS + device). Delivered on the next launch (iOS 15+).
  `pastDiagnosticPayloads` is read at launch too.
- **Unclean-exit marker** (works even before MetricKit delivers): a `state.json` notes `foreground` on becoming active,
  `background` on entering the background, removed on terminate. At launch, a marker still saying `foreground` means the last
  run ended while in use → a report (`app-exit`) with what the marker knew: when, which tab, the last pages, memory warnings.
- **Web process deaths:** a forwarding navigation delegate in front of Capacitor's `WebViewDelegationHandler` (which still
  reloads the page) records `webcontent` reports — tab, URL, app state, available memory. Deaths while the app is in the
  BACKGROUND are normal iOS housekeeping: counted, not reported.
- **Memory warnings** are counted and timed in the marker.
- **Device facts** in every report: model identifier (`iPhone17,4` = 16 Plus), iOS, app version + build, physical / available
  memory, thermal state, Low Power Mode, free disk.
- **`OurlabDiagnostics` plugin** (per bridge, registered next to `OurlabTabs`): `claim()` (hands pending reports to ONE webview
  — the rest get none), `done({ids})`, `release({ids})`, `info()`, `share({filename, text})` (the iOS share sheet with the
  report as a file — Messages, Mail, AirDrop; nothing to type), `note({page})` (the last page per tab, for the marker).

**Web (`rm/js/app-diagnostics.js`, injected by `sync-rm` into every app page, FIRST in `<head>`; inert outside the app):**
- Breadcrumbs (ring buffer of 80 in `localStorage`, shared by the app's webviews): page loads, visibility, JS errors,
  unhandled rejections, `console.error`, and taps on controls (their action name / label only — never typed text).
- On load: `claim()` → attach the breadcrumbs and device facts → upload to Firestore `crashReports/{id}` once signed in → `done`.
  If the upload fails or nobody is signed in, `release` (the next page tries again).
- A small banner after a foreground crash: "Ourlab closed unexpectedly. A report was sent to the lab. [Share report] [×]" —
  Share opens the iOS share sheet with the full report (JSON).

**Backend:** `crashReports/{id}` — create by the signed-in owner (`uid == auth.uid`, no updates), read / delete by admins.
Deployed BEFORE the app build that writes it, from a scratch copy (the repo file carries other changes' hunks).

**Reading them:** `rm/pages/app-reports.html` (admin): newest first — when, who, device, iOS, build, kind, the one-line cause;
open one for the whole report; Copy (for Claude) and Delete.

## Testing
Browser harness with a stubbed plugin + Firestore (upload, claim / done / release, banner, share, breadcrumbs, no typed text);
the simulator: kill the WebContent process (a `webcontent` report + banner), kill the app with SIGSEGV and relaunch
(`app-exit` report + banner). MetricKit cannot be exercised in the simulator — first real payload comes from a device.
Then TestFlight build 19 (minor: native change).
