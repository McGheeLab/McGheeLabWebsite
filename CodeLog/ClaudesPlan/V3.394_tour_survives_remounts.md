# V3.394 — Guided tours survive editor remounts (the vanishing-tooltip fix)

## Context

Alex's report (third round on this bug): choosing **↺ Start from scratch**
on a demo shows the tour card top-right, then it "just goes away without
me doing anything." The tour is supposed to ring-flash the next control
and walk the whole build.

## Root cause — finally pinned

Two independent killers, both remount-shaped:

1. **The mathjs boot render.** `protocol-editor.js` init runs
   `ProtocolFormulas.ensureMathjs().then(m => { state._math = m; render(); })`.
   That lazy vendor load resolves 0.3–2 s after first paint — comfortably
   AFTER the V3.390 debounced tour start (250 ms) — and the unconditional
   `render()` runs `clearCleanups()` → `handle.destroy()` →
   `toursHandle.destroy()`. Card and ring die with the mount.
2. **One-shot arming.** `state._pendingTour` was consumed when the
   debounce fired, so after ANY later remount (the mathjs render, a late
   Yjs snapshot, a collaborator edit) nothing restarted the tour. The
   V3.390 debounce only protected against remounts *within 250 ms of
   mount* — a network-timed one always won.

## Fix

### 1. Don't render for math in nodes view (`rm/js/protocol-editor.js`)
The graph editor loads its own math instance
(`protocol-graph-editor.js:1471`), so the post-mathjs `render()` is pure
waste in nodes view — skip it there (`if (currentView() !== 'nodes')`).
Editor-view completed-section previews pick `state._math` up on their
next natural render.

### 2. Tours re-arm + resume across remounts (belt and suspenders)
- **Engine (`rm/js/protocol-graph-tours.js`):** `attach()` gains
  `onEnd(reason, {id, stepIdx})` — fired when a run ends by explicit
  close (`'user'`: ×, Close, Just explore, public `stop()`) or by DOM
  teardown (`'detached'`: `destroy()`, viewport-gone loop check). The
  internal start-over-start stop (`'restart'`) stays silent.
  `start(id, {resumeAt})` re-enters at the recorded step, **bypasses the
  prebuilt gate** (that's only for cold launches on legacy copies), and
  fast-skips already-satisfied steps **instantly** (`activate(i, fast)`
  recursion) instead of replaying the 650 ms "already done" flash per
  finished step. `start` now returns a boolean; `stepIdx` may be -1
  (prebuilt card) → the host's `resumeAt >= 0` guard turns that back
  into a cold start, so the prebuilt card correctly reappears.
- **Mount (`rm/js/protocol-graph-editor.js`):** `startTourById(id, o)`
  passes the resume option through and forwards `opts.onTourEnd` into
  `attach()`.
- **Page (`rm/js/protocol-editor.js`):** the mount's `onTourEnd` records
  `'detached'` ends into `state._activeTour`/`_activeTourStep` and
  clears them on `'user'`. The renderNodesView debounce block now arms
  from `_pendingTour || _activeTour`, passing
  `{resumeAt: _activeTourStep}` for re-arms, and consumes `_pendingTour`
  only when a start actually SUCCEEDS (the old code consumed it even
  when the stale handle no-opped). Net behavior: a remount blanks the
  card for ~250 ms and it comes back on the same step; only the user
  closing it ends the walkthrough. Free bonus: manual 🎓 tours survive
  collaborator-edit re-renders, and switching Nodes → Editor → Nodes
  resumes the tour where it left off.
