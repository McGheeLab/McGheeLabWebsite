# V3.965 — Scientia at rest: what a computer that runs it all day stops paying for

**Date:** 2026-11-09 · **Branch:** `scientia/quiet-power` (on `scientia/sync-safety`, V3.964) · **Gabe's request:** "I feel like the
Scientia In Situ is consuming a lot of battery. Find ways to make it more efficient to run with minimal power usage, especially on a
local computer that runs it 24/7. Do not compromise on app performance such as refresh rate, etc."

## What changed

- **`13o-vault.js`** — `DISK.touch(store)`: with sync on and local, no whole-record snapshot (the computer holds every change already); the Markdown mirror only when a store it shows changed (`VAULT_SKIP`: sessions, timers, settings, profiles, journal, blobs, datasets), 8 s after the last edit.
- **`sisync.py`** — `JOURNAL_KEEP = 4000`: the journal trimmed at load and every 200 commits.
- **New `13zzp-quiet.js` (`QUIET`)** — no touch, key or wheel for three minutes, or the tab hidden → `body.quiet`, `QUIET.is()`, `sis-quiet` / `sis-awake`. The first touch wakes everything.
- **CSS** — `beat` and `regpulse` on opacity and transform only (compositor); `body.quiet` pauses every decorative pulse (`21-sync.css`).
- **`13zzj-polish.js`** — `syncing` + "In step" is green and still.
- **`13zc-sync.js` / `serve.py`** — the pull carries `active=0` while quiet; `APP_SEEN` (what the bridge paces by) is only set by an active window. Away ≥3 min: the bridge goes SLOW (15 s) two minutes after the last change and IDLE after half an hour; the first touch brings FAST back within a pull.
- **`03-db.js`** — `DB.rev` / `DB.revOf[store]`; `BACKUP.snapshot` skips an unchanged record.
- **`99-boot.js`, `11-shell.js`, `06-index.js`** — the per-second tick only with a running timer, and no text write when the second did not change; `IX.daysStale()` → the day index only after a write, a running timer, or a new day.
- **`23-tasks.js`, `13w-termscan.js`** — sweeps only after a block changed.
- **`13zn-rec.js`, `sttread.py`** — a minute between looks while Whisper is not installed; the worker's wait doubles up to five minutes.
- **`rawmouse.py`** — `KillTimer` when the listener lets go; `SetTimer` again when asked.
- **`serve.py`** — `serve_forever(poll_interval=2.0)`.

Nothing a person sees while at the app is slower: running timers still count every second, the map, the pen and the notes draw as before, sync pushes at once.

## Left for later (the lab layer, or bigger)

- `labsync.py` `_pace`: IDLE is really 25 s (the server caps a pull's wait) with a 0.25 s sleep loop; `connected()` reads `cloud.json` every pass. The lab's file.
- A whiteboard cell's iframe (800 KB) is rebuilt on every refresh of its note (`12-doc.js` `fill`); PDF cards are reused — boards could be too.
- `VAULT.build` could be incremental (the changed notes only).
- The edge pan asks `api/edge-push` every 30 ms while the mouse rests against a pushed edge, with no time limit.

## Tests

`t_965.mjs` (headless Chrome on the built app with a temporary notebook): quiet flips after the wait and a mouse move wakes it; `DB.rev` counts; the day index is stale after a write and fresh after a build; after an edit with sync on no `api/snapshot` is sent and `kept/` stays empty; the backup skips an unchanged record and runs after a change; no page errors.
