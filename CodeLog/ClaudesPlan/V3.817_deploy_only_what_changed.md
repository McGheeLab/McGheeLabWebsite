# V3.817 — Deploy only what changed (+ Finder folder dates)

**Date:** 2026-10-21
**Ask (Alex):** "when I FTP I often need to upload an entire folder, and since the
RM folder is getting rather large it takes a long time. We need to reorganize
everything so it is easier to make updates. Also when files are updated the
folder is often not showing that there were updates to it, so we need to ensure
the folders also show as recently modified in the Finder." Follow-up: "is there
any solution to FTP straight from VS Code so I don't have to do it manually?"

## Goal

1. A routine update sends the handful of files that changed, not the 500-file
   `rm/` tree, and never sends files that are not the site.
2. Finder shows a folder as modified whenever anything inside it changed.
3. The upload can run from VS Code / the terminal with no Cyberduck session.

## What was actually wrong (measured, not assumed)

- The site is 777 files / 51 MB once `deploy/site.json` says what "the site"
  is. The repo is 66,000 files / 1.6 GB. FTP cost is per file, so dragging a
  tree is slow in proportion to its file count, not to what changed.
- Git cannot tell us what is live: the server is updated from the working
  tree (486 dirty files at the time of writing; the last commit is a batch dump).
  So "what changed since the last deploy" needs its own record.
- **The whole repo had been going to the server.** `audit` found 205 non-site
  paths publicly reachable on mcgheelab.com, 20 of them sensitive:
  `scripts/service-account.json` (Firebase admin key), every file under
  `Data/LOR requests/` (student letters, personal statements, CVs),
  `modules/bme295c/students.md` + the UAccess admissions `.xlsx` (roster with
  IDs and dates of birth), plus `functions/` source, `firestore.rules`,
  `CLAUDE.md`, CodeLog. Handed to Alex with the deletion + key-rotation steps.
- macOS folder dates: tested on the real tree. A folder's mtime changes only
  when an entry is created/renamed/deleted DIRECTLY inside it. In-place saves
  (VS Code, Claude's Edit tool, sed) change nothing; nothing propagates upward.
  `rm/` showed Oct 19 while `rm/js/nav.js` was edited Oct 21.
- Python.org's macOS Python ships without root certificates → every HTTPS
  check failed with CERTIFICATE_VERIFY_FAILED until a fallback was added.
- Root `vendor/heroicons` (665 files) is the icon generator's SOURCE, not a
  served asset — it was the bulk of the "missing on server" list until
  excluded. `rm/vendor/` IS served.

## Approach

**Not** a physical reorganisation of `rm/` (285 JS files referenced by path from
97 pages, the service worker and the mobile bundler — moving them buys nothing
for upload time and risks everything). The reorganisation is of the *deploy
boundary*: an explicit allowlist + a manifest of what is live.

### `deploy/site.json` — what the site is
Allowlist of root files + `icons/ Images/ Videos/ modules/ rm/ poster/
DataIllustrations/`, with excludes for docs (`rm/CLAUDE.md`, `AUTHORING.md`…),
`rm/server.py`, rosters/xlsx under modules, `.DS_Store`. Also FTP host/user (no
password) and `touchDirs`.

### `deploy/manifest.json` — what is live
`rel → {sha256, size, deployedAt, via}`. Tracked in git. Built by `baseline`
(HEAD every site file; same Content-Length as local ⇒ recorded as live),
maintained by `verify`.

### `scripts/deploy.py`
| command | does |
|---|---|
| `status` | hash site files, diff against manifest → to-upload / removed lists (no network) |
| `stage` | copy ONLY changed files into `deploy/upload/` (mirrored tree), write `pending.json`, open Finder |
| `ftp` | upload changed (or pending) files over FTPS→FTP fallback with `ftplib`; password Keychain→env→prompt; `--delete` for removed; then `verify` |
| `verify` | HEAD each pending file; size matches ⇒ record in manifest; else keep pending **and un-record** |
| `baseline` | first run / recovery |
| `audit` | HEAD every non-site repo file; report 200s, sensitive first; `ftp --purge-audit` deletes them |
| `touch-folders` | Finder dates |

Key decisions:
- **Hash, not mtime.** Cyberduck sync compares timestamps; FTP timestamps are
  unreliable and `copy2`/git checkouts change them without content changes.
- **HEAD Content-Length as the live check.** The server returns exact sizes
  (no gzip on HEAD without Accept-Encoding), so a Cyberduck drag can be
  confirmed without FTP credentials. Equal size ≠ equal content, so the
  manifest stores the hash from stage time; a local edit after staging shows
  up as "changed" again.
- **`verify` un-records.** A recorded file that turns out missing/different on
  the server is dropped from the manifest so `status` lists it again (the E2E
  test caught this).
- **FTPS with TLS session reuse** (`FTPS.ntransfercmd` wraps the data socket
  with `session=self.sock.session`) — pure-ftpd/ProFTPD refuse data
  connections otherwise. Falls back to plain FTP (what the Cyberduck bookmark
  uses) when `AUTH TLS` is refused.
- **TLS trust fallback**: default store → `certifi` → `security
  find-certificate -a -p` on the system root keychain.
- **No third-party packages**; `DEPLOY_STATE_DIR` / `DEPLOY_SITE_JSON` env
  overrides isolate tests.

### `scripts/touch_folders.py` + Claude Code hook
`bubble_tree()` raises every folder to its newest descendant (never lowers,
skips `.DS_Store` which Finder rewrites constantly, `.git`, `node_modules`).
`.claude/settings.json` gets a `PostToolUse` hook on
`Edit|Write|MultiEdit|NotebookEdit|Bash` → `--hook` mode reads the tool JSON:
a `file_path` bubbles that file's ancestors; a Bash call runs the configured
tree pass (~50 ms). Proven live in-session: `rm/pages` back-dated to
2026-01-01, one Bash call later it read Oct 19 16:59 (its newest file).
Optional `scripts/launchd/com.mcgheelab.touch-folders.plist` (every 5 min) for
edits made outside Claude Code.

### VS Code
`.vscode/tasks.json`: ⇧⌘B = `deploy.py ftp`; tasks for status / stage /
verify / audit / folder dates.
