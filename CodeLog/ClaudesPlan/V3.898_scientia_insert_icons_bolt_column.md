# V3.898 — Scientia: + Insert rows get their own icons; the Quick cast bolts line up

## Goal

Two things Alex asked for on 2026-10-24, both about Gabe's **+ Insert** list on the web:

1. "the lightning button that is within the + insert menu … should be aligned and right justified": the bolt
   (V3.896, puts a row in your Quick cast) sat right after each row's text, so it wandered left and right.
2. "all the +insert icons for each item should be unique": Gabe's text glyphs repeat (◍ ◍ for the two well plates,
   ⤓ ⤓ ⤓ for the three pulls, ∑ ∑ for the equations, ▤ ▤ ▤ for PDF / A note / Paper, ▦ ▦ for Image panel / Live view,
   ▶ ▶ for the two protocol runs), and two are colour emoji (🖩, 🔔).

## Approach (lab layer only; `scientia/src` is Gabe's and untouched)

- **Bolt column**: `.pop .opt` is a flex row, so Gabe's `.insrow` was only as wide as its text. CSS
  `.opt > .insrow{flex:1 1 auto;min-width:0}` + `.insrow > div{flex:1 1 auto;min-width:0}` stretches the row, and the
  bolt (`flex:none; margin-left:auto`) lands at the right edge, the same x on every row.
- **One icon per row**: `INS_PICS` maps every INSERTS id (Gabe's 23 + the lab's 4) to its own Heroicon (Lucide
  `flask-conical`, our custom `construction` / `books` where Heroicons has none). The path data is added to
  `PILL_ICONS` (extracted from `vendor/heroicons` / `vendor/lucide` with the caps moved to `pic()`'s root `<svg>`).
  Drawn in three places, all from the same map:
  - Gabe's + Insert list: `qcDecorate`'s existing MutationObserver swaps each row's `.insic` glyph (`insIcon`, idempotent).
  - The Quick cast fan / docked row: `pillItems('insert')` uses `pic(INS_PICS[id])`; "Everything…" is `ellipsis-horizontal`.
  - The wire-drop menu (`CHAINDROP.open` wrapped): same rows by label, plus its own "Text component" and
    "A component in another note…".
- A row not in the map (a new one Gabe adds) keeps his glyph; the harness fails until it is given an icon.
