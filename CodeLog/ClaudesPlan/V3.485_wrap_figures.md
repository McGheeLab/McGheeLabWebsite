# V3.485 — Wrap text around a corner figure (single-column)

## Goal

Let a user place a figure in a corner of a **single-column** document with the
running text flowing around it (the LaTeX `wrapfig` layout), and control the
figure's **boundary directly** in the ⬒ Layout overlay — drag to resize, drag
to pick the corner/side. Renders in the doc-view preview *and* compiles to a
real wrapped figure in the PDF.

Prompted by: "I want to move the blue boundary for the figure from the boundary
edge itself … wrap the text around the figure area … a corner image with text
that flows around it."

## Scope (confirmed with the user)

- **Corner/side wrap** — figure floats to the left or right edge of the text
  column; boundary is draggable to resize and to choose the side. Not freeform
  absolute positioning.
- **Preview + PDF export** — works in the editor preview and compiles via the
  `wrapfig` package.
- **Single-column only** — degrade to in-flow (with a warning) in two-column
  templates.

## Approach

New figure layout intent `anchor: 'wrap'` + `wrap_side: 'left'|'right'`,
following the existing presence-of-`anchor` opt-in contract (legacy blocks stay
byte-identical). Reuses the figure box model, resize/area-frame machinery,
popover, drag-drop, and the `PaperLayout` export seam.

### Data model — `rm/js/paper-schemas.js`
`newFigure().attrs.wrap_side = 'right'`. `normalizeTree` unchanged (it never
injects figure attrs, so the opt-in holds automatically).

### Export — `rm/js/paper-layout-rules.js`, `rm/js/paper-export-tex.js`
- `ANCHORS` gains `'wrap'`. `resolveFloat` returns
  `{ env:'wrapfigure', place: wrap_side==='left'?'l':'r', width, height, wrap:true }`
  for single-column figures; two-column / tables degrade to `flow` + warning.
- `figureToTex` wrap branch emits `\begin{wrapfigure}{<l|r>}{<width>}` with
  `\includegraphics[width=\linewidth]` (the env sets the box width), no
  minipage. Block order places it immediately before the paragraph it wraps.
- `_usedWrapfig` per-run flag injects `\usepackage{wrapfig}` on demand in
  `buildBundle` (same pattern as `cuted`/`multirow`) — no template-file edits,
  covers custom templates, and stays out of two-column docs.

### Preview — `rm/js/paper-doc-view.js`
- Figure render branch recognizes `wrap` (single-column) **before** the
  unknown-anchor coercion, sets `data-anchor="wrap"` + `data-wrap-side`, puts
  the pct% width on the `<figure>` (box fills it at 100%), and never sets
  `figFloat`.
- `_groupWrapFigures(items, geom)` (runs after `_rewriteRefPrefixes`, before
  `_measureItems`, 1-col only): wraps the figure + following flow blocks (until
  a section/heading/float boundary — `WRAP_STOP_KINDS`) into one
  `.pdv-wrap-group` (`display:flow-root`). Measured as ONE unit → correct
  wrapped height; summing separately would double-count the space beside the
  figure. Packed atomically (blockKind `wrap-group`, no cross-page split) — the
  first-version constraint. Child els keep their `data-block-id`, so selection,
  refs, cite-join, drag, and resize keep targeting the real blocks. The figure's
  `dataset.w`/`dataset.h` are copied onto the group so the session
  measure-cache can't alias on resize.
- No `_recordRects` change: 1-col in-flow figures already get their blue via the
  `.pdv-regions-on .pdv-figure` tint + the area-frame (not a region box).

### Boundary interaction — `rm/js/paper-doc-view.js`
- **Resize** reuses the E/W/S/SE handles. `_onResizeDown` detects wrap and uses
  the column (`bodyW`) as the container; `_onResizeMove` sizes the `<figure>`
  (not the box); `_cancelResize` restores `figEl.style.width`; `_onResizeUp`
  preserves the `wrap` anchor + `wrap_side` (the `FLOAT_REGIONS` guard was
  widened to accept `wrap`).
- **Move / side** — `_resolveDropTarget` stamps `side` (drop's horizontal half)
  on flow targets; `_commitDrop` keeps a dragged wrap figure wrapped and writes
  `wrap_side` from that side (dropping on a top/bottom band still un-wraps it to
  a band float — intentional).

### Popover — `rm/js/paper-doc-view.js`
`_openFigPopover` adds a **Wrap text around (corner)** anchor option (figures +
single-column) and a **Wrap side** select (shown only while wrapped). Switching
to wrap defaults a full-width figure down to `0.4\linewidth`. `_currentIntent`
carries `wrap_side`.

### CSS — `rm/css/paper-doc-view.css`
`.pdv-wrap-group { display: flow-root; }` and
`.pdv-figure[data-anchor="wrap"][data-wrap-side="left|right"]` float rules.

### Version
`sw.js` `CACHE_VERSION` 455 → 456; CHANGELOG V3.485; this plan doc; ARCHITECTURE.

## Key decisions

- **Wrap group measured as one unit** — the only way to keep the manual packer's
  height accounting honest when text flows beside a float.
- **On-demand `wrapfig` injection** over editing 8 template preambles — robust,
  covers custom/blank templates, never loads the package in two-column docs.
- **Atomic wrap group (no cross-page split)** — accepted first-version limit; a
  group taller than a page overflows like any oversized block.

## Follow-ups (deferred)

- Splitting a wrap group across a page break (long wrap regions).
- Two-column wrap (LaTeX `wrapfig` works in a column, but the per-column packer
  has no beside-float model yet).
- Vertical fine-positioning within the paragraph (LaTeX `wrapfig` line offset).
