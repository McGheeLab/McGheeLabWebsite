# V3.372 — Block-aware drag selection (layout R4, the user-facing fix)

> Plan: robust page-layout segmentation, R4 of 5 (2026-07-14). The hard
> guarantee against "highlight bridges into other sections."

## Change ([rm/js/geom-selection.js](../../rm/js/geom-selection.js))

Selection previously sliced the flat per-page item array between the anchor
and focus `index` values and trusted the ordering — so any segmentation
flaw became a visible bridge. Now the raw slice is **clamped to blocks**
using the `cluster`/`column` fields the V3.371 engine stamps:

- **Same-cluster drag** (the overwhelmingly common sentence/paragraph
  case): keep ONLY the anchor's cluster — a selection physically cannot
  escape its block.
- **Cross-block drag**: keep only the two endpoint columns, dropping any
  full-width band (abstract/caption/footnote) the raw slice spanned.
- **Multi-page drag**: each end page keeps its endpoint's column so the
  first/last page can't grab the neighbouring column.
- **`_itemAtPoint`** gains a soft `preferCluster` penalty (mousemove passes
  the anchor's cluster) so a cursor grazing the gutter snaps back to the
  anchor column; a direct hit still wins, so a deliberate other-column
  click works.
- Degrades to a no-op when items carry no cluster/column (engine absent).
  Stored anchor format (`rects`/`textQuote`/`textPosition`/`saved_scale`)
  unchanged — existing annotations replay identically.

## R3 + R5 BACKLOG — exact root causes (diagnosed 2026-07-14, node harness)

The three residual fixtures are segmentation-quality, best iterated on the
LIVE browser harness (`rm/pages/layout-audit.html`) where real pdf.js
extraction may cluster differently than the truth-run proxy:

- **02-frontmatter** (gutter detected, columns path): cluster merges
  `bodyL` with the full-width `title/authors/abstract/keywords`. Cause:
  short full-width preamble lines (title, authors, one-line keywords) don't
  reach the gutter x, so `_orderByColumns` band logic marks those rows
  "multi" and slots them into column 0. Fix idea: a row is multi-column
  only if text exists on BOTH sides of the gutter (or in a run where the
  far column is populated); a top-of-page run with an empty far column is
  full-width preamble.
- **04-fig-onecol** (flood-fill — no gutter, the figure hole breaks the
  right column's clean-row run below the 55% guard): flood-fill merges
  `R1` (right body) with `capL` (left caption). Fix idea: lower the
  clean-row fraction guard when a large ink region (figure) accounts for
  the missing rows, so the gutter is still accepted; or cap flood-fill
  eps by detected column width.
- **05-footnote** (gutter detected): `footer`/`header`/`pagenum`/`footnote`
  each fold into an adjacent column band. Fix = **R3 block typing**:
  classify by y-band (top/bottom margin → header/footer/pagenum), small
  height + isolation (→ footnote/caption), then emit typed non-body blocks
  as their own clusters that the R4 clamp already skips for body drags.

R3 (`classifyBlocks` in page-layout.js) + these three tuning fixes are the
remaining plan work; R5 = corpus run + citation-audit regression check +
document rotated-text (#11) / borderless-table residuals.
