# V3.481 — Bidirectional import/export E3: comments round-trip

> (Renumbered V3.480→V3.481 — a parallel session claimed V3.480/sw450.)

> Third release. Comments travel with a paper across export→import, restored with their
> TRUE original author + timestamps. One Cloud Function.

## Why a function

Draft comments live at `papers/{id}/comments`, bound by `blockId`. Export already
bundles them (E1 `comments.json`) and import preserves block ids (E2). But the client
comment-create rule pins `authorUid` to the caller, so a client import would
re-attribute every comment to the importer. The Admin SDK bypasses that rule.

## Cloud Function (functions/restore-paper-comments.js — staged; Alex deploys)

`restorePaperComments` (v2 onRequest, cors, 256MiB/120s, mirrors the paperCompile/
equationOcr gate):
- **GET** → `restorePaperComments ok` (health probe — the client gates on it).
- **POST** `{ paperId, comments[] }` + Firebase Bearer token → verify token + lab-member
  role → authorize (admin, OR `projects/{paperId}.lead_author_uid == uid`, OR
  `papers/{paperId}.authorUids` includes uid) → **Admin SDK** batch-writes
  `papers/{paperId}/comments/*` preserving `authorUid`, `authorName`, `resolved`,
  `blockId`, anchors, and `createdAt`/`modifiedAt` as real `Timestamp`s
  (`fromMillis`, not re-stamped) + `imported_from_bundle:true`. Auto-ids (comment ids
  aren't referenced cross-doc). Batches cap at 450; validates count ≤4000 + body length.
- Registered in `functions/index.js`.

## Client wiring (rm/js/paper-editor.js)

`_restoreImportedComments(comments)` — **health-gated** (`_commentRestoreAvailable`
GET probe, memoized): if the function isn't deployed yet, the comment step is silently
skipped (E2's import already succeeded), so this ships before the deploy. Otherwise POST
with the caller's ID token; the editor's live comment subscription then surfaces the
restored docs. Called from `_hydrateBundle` (after figures) via the `typeof`-guard added
in E2. Block-id preservation (E2) is the prerequisite — comments re-bind to the same
block ids the tree carried across.
