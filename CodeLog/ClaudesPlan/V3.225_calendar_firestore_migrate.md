# V3.225 — Calendar page: migrate Outlook Events + Availability to Firestore, retire Full Calendar tab

## Goal

Fix the production 404s reported on `mcgheelab.com/rm/pages/calendar.html`:

```
/api/calendar/outlook-events?days=1  → 404
/api/calendar/outlook-events?days=90 → 404
```

Root cause: three render paths on the Calendar page still call the legacy
`/api/calendar/outlook-events` endpoint that only exists in the local dev
server (`ResearchManagement/server.py`). On the static deploy at
`mcgheelab.com/rm/` there is no `/api/` surface, per
[rm/js/runtime-mode.js](../../rm/js/runtime-mode.js). The History tab
already migrated to the per-user Firestore subcollection
`userData/{uid}/calendarEvents` (populated by the
`scrapeCalendarForAllUsers` Cloud Function in
[functions/calendar-scraper.js](../../functions/calendar-scraper.js)).
Outlook Events, Full Calendar, and Availability never migrated.

## Approach

Source the upcoming-events list from the same per-user
`calendarEvents` subcollection the History tab reads. Same Google
Calendar data; the "Outlook" naming is a legacy artifact from when this
shipped against an ICS feed. Drop the Full Calendar tab — its only
purpose was to iframe an Outlook web embed whose URL came from the dead
endpoint; the Google Calendar replacement doesn't have an analogous
public embed URL stored in Firestore, and the tab provides nothing the
Upcoming Events tab doesn't already cover.

## Files to modify

### `rm/js/calendar.js`

- `renderOutlookEvents()` — replace the `fetch('/api/calendar/outlook-events?days=90')`
  call with a windowed Firestore query against
  `userData/{me.uid}/calendarEvents` for `start_at` in `[today, today+90d)`,
  ordered ascending, capped at 800. Map Firestore fields to the legacy
  event shape the existing render helpers expect:
  - `summary` → `title`
  - `start_at` → `start`
  - `end_at` → `end`
  - `all_day` → `all_day`
  - `location` → `location`
  - `recurring_event_id` truthy → `recurring`
- Rename the user-facing tab label "Outlook Events" → "Upcoming Events"
  in [rm/pages/calendar.html](../../rm/pages/calendar.html) (keep the
  internal `data-tab="outlook"` value to avoid touching `switchTab`).
- Delete `renderFullCalendar()` and the `else if (tab === 'fullcal')` branch
  in `switchTab`.

### `rm/pages/calendar.html`

- Drop the `<button class="tab-btn" data-tab="fullcal">Full Calendar</button>`
  tab.
- Rename the Outlook Events button to "Upcoming Events".

### `rm/js/availability.js`

- `availFetchEvents(daysAheadHint)` — same swap: query
  `userData/{me.uid}/calendarEvents` for the rolling window, map field
  names. Keep the same return shape (`AVAIL_STATE.events` populated with
  the legacy `{title, start, end, all_day, location, recurring}` shape).

## Key decisions

- **Direct Firestore query, not `api.load`.** The route adapter
  registration `calendar_archive/events.json → calendarEvents` returns the
  *entire* subcollection (~1k+ docs). Loading every event ever synced to
  render a 90-day window is wasteful and was already called out as the
  reason the History tab uses windowed queries
  ([rm/js/calendar.js:992](../../rm/js/calendar.js#L992) comment). Same
  rationale here.
- **Field-shape adapter inline.** Two call sites total. A shared mapper
  helper would be premature abstraction; both spots get a tiny inline
  map.
- **No graceful degradation to `/api/`.** On localhost the same Firestore
  data is the source of truth — there's no reason to keep the dead path
  alive for local dev.
- **Tab label change.** "Outlook Events" was misleading even on the local
  dev path after the Google Calendar migration. Rename now while we're
  here.

## Out of scope

- Per-user Google Calendar OAuth onboarding flow — already handled via
  the email-review settings page (the Cloud Function picks up everyone
  with stored credentials). The empty-state message points users there
  if they haven't authorized yet.
- Migrating the Booked Time tab — that reads from
  `tasks/inbox.json` via `api.load`, not from the dead endpoint.

## Verification

- Local: `python3 rm/server.py` and visit `/rm/pages/calendar.html` →
  Upcoming Events + Availability tabs render the same Google Calendar
  events that show up on the History tab. No console fetch to
  `/api/calendar/outlook-events`.
- Deploy: load `mcgheelab.com/rm/pages/calendar.html` → no 404 in
  console; Upcoming Events shows the next 90 days; Availability builds
  text blocks against the same source.
