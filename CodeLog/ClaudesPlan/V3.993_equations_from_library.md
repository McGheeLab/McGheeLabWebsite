# V3.993 — Equations from the website's Library; capture in the app's Library reader

## Goal
Gabe: "the register equation from the website in library should sync to the lab notebook and the RTgabrieldeclercq version". Asked how they should reach his standalone (no link to the lab cloud): "The standalone only gets the code to snip/capture equations from papers, not the syncing."

## Approach
- **The lab side (the hub):** the website's capture (the paper reader's ƒ, `rm/js/equation-capture.js`) saves an annotation `papers/{paperId}/annotations/{id}` with `kind: 'equation'`, `latex`, `name`, `comment`, `snip_data_uri`, `visibility`. The hub already mirrors RM's library into each person's notebook every 5 minutes (`mirrorLibrary`); with it, `mirrorEquations` reads the captures in one collection-group query (RM itself walks papers one by one because its rules don't allow collection-group reads; the hub runs as admin) and keeps read-only `equations` rows (`rm: true`), the same visibility rule as the paper card (V3.875): the lab's, or the person's own. Planned by a pure `planEquations` (tested), as `planMirror` is.
- **Read-only in the app:** a lab-library equation goes into a note as a named copy (`EQ.create`), so editing it never fights the mirror; it is never removed from the registry here.
- **The capture, for both (the app):** the app could snip an equation from a PDF on the canvas (V3.901) but not in its Library reader, where the website does it. The reader gets ∑ Capture equation: a box drawn on the page, the snip, the equation editor (read where the lab's reader is there, typed otherwise; the editor's snip head is now shared, `CLIP.ocrHead`), a name, and a registered equation with its paper, page and a small snip.
- **The standalone** gets the app's part (the capture, the sources in the picker); the hub's mirror and the lab-library wording are taken out in its sync.
