# V3.187 — PMR bucket lifecycle (mark complete + archive)

## Goal

Make the project-management loop close. Today task buckets stay open
forever; even when every subtask is `done`, the bucket sticks around
cluttering the open-tasks roll-up. From the wishlist:

> PMR's open-tasks roll-up should organize as main task buckets →
> subtasks, and when all subtasks in a bucket are done the admin can mark
> the bucket complete, which archives it.

V3.187 adds the completion affordance + archival lifecycle.

## What changes

1. **Schema** (additive — no migration needed):
   - `bucket.archived: boolean` (default false / missing)
   - `bucket.completed_at: ISO string` (set when first archived)

2. **PMR Open Tasks block** ([rm/js/pmr.js](rm/js/pmr.js)):
   - Refactor from project → flat-subtask-rows to project → **bucket** →
     subtask rows, matching the bucket-first organization in the
     wishlist.
   - Each bucket header shows `N/M done` progress.
   - When `N==M` and at least one subtask exists, show a `✓ Mark bucket
     complete` button. Clicking flips `archived=true` and
     `completed_at=now`.
   - Hide archived buckets from the active roll-up.
   - Add a collapsed `▶ Archived buckets (K)` section at the bottom of
     the Open Tasks block listing archived buckets with their completion
     date and an `↶ Restore` button.

3. **Tasks page workspace** ([rm/js/tasks-buckets.js](rm/js/tasks-buckets.js)):
   - Filter `bucket.archived` out of the main per-project bucket list.
   - Append an `▶ Archived buckets (K)` accordion per task builder with
     restore affordance.

4. **Writes:** the existing `api.save('tasks/buckets.json', ...)` route
   already writes per-project docs to `userData/{uid}/buckets/{projectId}`.
   PMR's mark-complete handler does a targeted read-modify-write on the
   single project doc (don't rewrite the whole subcollection).

## Scope (V1)

- **Owner-only** for now. The student can mark their own buckets
  complete from inside PMR or from the Tasks page. Cross-user (admin
  marks a student's bucket from the rail) is deferred — PMR's
  `loadOpenTasks` already short-circuits for cross-user view because
  `userData/{uid}/buckets` isn't admin-readable per the recursive
  `userData/{userId}/{document=**}` rule. Lifting that needs an explicit
  rule + adapter override; track as a follow-up.
- **All-done is the only trigger.** No "abandon bucket" affordance in
  V1 — if a bucket has open subtasks, the Mark-complete button is
  hidden. Restore is always available.

## Verification

1. Open Tasks page → mark all subtasks in a bucket as done →
   re-open PMR → bucket renders with "✓ Mark complete" button.
2. Click "✓ Mark complete" → bucket disappears from active list,
   appears under "Archived buckets" collapse with completion date.
3. Expand archived section → click "↶ Restore" → bucket returns to
   active list with archived=false.
4. Verify Tasks page also hides archived buckets and surfaces them in
   the same collapsed pattern.
5. Bump cache version → reload PMR + Tasks pages → behavior consistent.
