# V3.954 — Working together in Scientia: what the app does, and what the lab's layer needs to do

Phase I of [V3.946_scientia_sis_shaping_program.md](V3.946_scientia_sis_shaping_program.md) §10. The app's side
is built (`scientia/src/13zzk-presence.js`, `23-presence.css`) and runs quietly until the lab's side exists. This
note is the contract between the two — for Alex. Nothing in `lab-mode.js`, `cloud-sync.js`, `scientia-cloud.py`
or the hub was touched.

## 1. What the app does today

- Every 20 s, with a note open, `PRESENCE.beat()` sends **a heartbeat** and takes the answer: who else is here
  (a row of avatars in the header, left of the sync dot: filled while they work, grey when `away`, outlined when
  they are in another note of the project) and **which components are held** (shaded in the holder's colour,
  read-only, "Alex is editing", a button *Ask to take over*).
- A person **holds** a component when the caret is in it or they drag it (`PRESENCE.hold`); they let it go 1.5 s
  after the caret leaves the box, on a note change, and on `pagehide`. The heartbeat carries the held `blockId`.
- Without a transport the module is silent: no row, no locks, no requests. The app standalone never asks.

## 2. The transport (choose one; the app tries them in this order)

### a. `SIS_LAB.presence` — an object the lab layer sets (preferred: it can use the Firestore listener it already has)

```js
SIS_LAB.presence = {
  me()                       → { uid, name } | null          // optional; else the web sign-in / the paired account
  beat(p)                    → Promise<Answer>               // p: { docId, docTitle, projectId, uid, name, hue, blockId|null, blockName|null, away:boolean, at:ISO }
  lock(docId, blockId)       → Promise<{ ok:true } | { ok:false, by:{ uid, name, hue? } }>
  unlock(docId, blockId)     → Promise<any>
  ask(docId, blockId, toUid) → Promise<any>                  // "Ask to take over": a message to the holder
};
// Answer: { ok:true, people:[{ uid, name, hue?, docId, docTitle?, blockId?, blockName?, away?, at }], locks:{ [blockId]: { uid, name, hue?, at } }, asks?:[{ blockId, from:{ uid, name }, at }] }
```

`people` may include anyone in this note **or in another note of the same project** (`docId` ≠ the asked one →
the app shows them outlined, "in “<docTitle>”"). The app filters itself out by `uid`. A person counts as
*away* when the app has seen no input for five minutes (`away: true` in the heartbeat); the hub may also mark
anyone whose last heartbeat is older than 60 s as gone (drop them) and older than 5 min as away.

### b. The hub routes behind the proxy (works for the web and the installed desktop with no app change)

- `POST api/rm/presence` with the heartbeat body → the Answer above (`{ ok:true, people, locks, asks? }`).
- `POST api/rm/lock` with `{ docId, blockId }` → `{ ok:true }` or `{ ok:false, by:{ uid, name } }`;
  with `release: true` → frees it (only the holder's); with `ask: <uid>` → records an ask for that holder, which
  the hub puts into the holder's next Answer as `asks`.
- Today the hub answers `404 { ok:false, error:'no such route' }` and the app goes quiet for the session.
  The desktop proxy (`serve.py rm_proxy`) already forwards any `api/rm/*` with the computer's key.

Suggested storage: `scientiaPresence/{docId}/people/{uid}` (`{ name, hue, blockId, blockName, away, at }`) and
`scientiaLocks/{blockId}` (`{ docId, uid, name, at }`), both written on every heartbeat, with a TTL policy of
10 minutes; a lock older than 60 s is free to take. A lock request against a fresh lock by another is refused with
`by`. The hub's `who` gives `uid` and `name`; `hue` can be `hashHue(uid)` (the app computes the same when absent).

## 3. Three small things the plan leaves to the lab (independent of 2)

1. **Lit reviews shared with everyone** (plan §10): RM's `userData/{uid}/litReviews/{id}` gets `visibility: 'lab'`
   by default and `collaborator_uids`; the rules let members read, the creator and collaborators write; the hub's
   `collections` answer lists everyone's. Scientia's collection card then offers every lab member's reviews —
   no app change.
2. **@Name notifications**: a `person` mark (`{ type:'person', uid, name }` on a block's body — V3.947) → a
   My Week feed item for that member. A hub pass on pull, like the reminders (V3.874), or a route the app
   would call — say which, and the app adds the call.
3. **`LAB.registerPill(def)`** (lab-mode §11, ≈15 lines: a fifth entry in `PILLS` and `pillItems` from the def).
   The app already calls it when it exists:

   ```js
   SIS_LAB.registerPill({ name:'note', icon:'▤', label:'This note — references, Pull in, a collection, Flag, the Atlas',
     side:'left', vert:'up', dock:true, orient:'v', at:(w, h) => [36, h - 38],
     items: pane => [{ icon, label, sel?, run }, …] });   // the rows pillItems(name, pane) would return
   ```

   With the Note pill in place, *Pull in* and *Flag* can leave the Quick cast (they are on the Note pill).

## 4. Tested

Headless Chrome, the desktop build on a static server: the app went quiet (`api/rm/presence` → 404). With a
stand-in transport: three avatars (one away, one in another note), the held component shaded and read-only with
*Ask to take over* (the ask reached the transport with the holder's uid), the caret in a free component took its
lock and the next heartbeat carried it, a release in the answer made the component editable again, a lock taken
over while held blurred the editor and said so, a save into a held component was refused.
