# V3.438 — Plate planner: multi-strategy auto-arrange (Release 2 of 2)

## Context

Release 2 of Alex's plate-planner overhaul (R1 = V3.436 drag-and-drop).
"the layout should be able to be organized in multiple different ways."
V3.377 had explicitly deferred group-by/blocked/randomized placement
beyond the fixed row-major Auto-fill; this delivers it. Alex chose all
four strategies + presets + notebook-run persistence.

## Kernel (`rm/js/protocol-graph.js`) — `plateArrange` (exported, pure)

`plateArrange(items, opts) → { assignment, overflow, warnings, seedUsed }`;
`opts = { grids, reps, keyOf, mode, ...modeOpts }`. Position-only — never
touches quantities, so it's totals-neutral by construction
(`aggregatePrep` keys off well counts, verified in tests).

- **fill** — `direction 'row'|'col'|'snake'`, replicates contiguous.
  `direction:'row'` reproduces the legacy Auto-fill byte-for-byte.
- **factorAxis** — `rowField`/`colField` dim names: condition placed at
  (row=level index, col=level index) on plate 1; reps + out-of-range
  levels stack into the next free wells (row-major); warns when a factor
  has more levels than its axis.
- **spread** — round-robin one rep of each condition per pass (reps land
  a full pass apart); `avoidEdges` excludes the perimeter first, falling
  back to edges + a warning when the interior can't hold them.
- **random** — seeded Fisher-Yates over the slot order via `_mulberry32`
  (reproducible; seed from the caller — the kernel bans `Math.random`);
  `seedUsed` returned for the record.

Helpers `_slotsInOrder(grids, direction)`, `_isEdge`, `_gridDims`,
`_emptyAssignment`. Overflow is counted, not placed, so the UI can prompt
"+ add a plate".

## UI (`rm/js/protocol-widgets.js` `renderPlatePlanner`)

The lone "⚙ Auto-fill" becomes an **Arrange** group: a mode `<select>`
(Fill direction / Map factor→axis / Spread replicates / Randomize), a
contextual options row (direction select; row/col field pickers from
`keyFields`; avoid-edges checkbox; seed number + 🎲 re-roll), and an
**⚙ Arrange** button calling `plateArrange` → writes the assignment in
place (same object ref the totals + grid reads hold), persists, refreshes,
shows overflow + warnings in `.prd-planner-warn`. Plain **Clear** kept.

**Persistence**: state extends to `{ grids, assignment, arrange }`;
`persistState` writes `arrange`, the planner seeds its controls from it on
mount. Absent → `{mode:'fill', direction:'row'}` (back-compat). `arrange`
rides in `run.graph_state[blockId]` (notebook run persists it; graph_state
keeps arbitrary per-block keys, so no schema change needed).

CSS: `.prd-arrange`, `.prd-arrange-mode/-opts/-field/-seed/-check/-die`.
