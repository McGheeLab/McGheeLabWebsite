# V3.862 — Fix: the 📖 Paper card "cannot connect to the library" (`window.firebridge` is undefined in production)

**Date:** 2026-10-23
**Alex:** *"the paper card says it cannot connect to the library (cannot read properties of undefined (reading 'db'))"*

## Cause
`rm/js/canvas-paper-reader.js` (V3.856, kept in V3.859) read the sign-in bridge as `window.firebridge`. `firebase-bridge.js` declares
`const firebridge = (function () { … })()` — a bare global in the script scope, never a property of `window` (the long-known
"window.firebridge dead-check" trap). So on the live site:
- `db()` threw `Cannot read properties of undefined (reading 'db')` — the paper search, the annotation watch, the reader's PDF
  re-check, mirrors and claims all failed (the search showed "Could not reach the library (…)");
- `me()` returned `{}`, so `uid()` was empty — ownership / private highlights / mirror paths were wrong even where no throw happened.

The harnesses never saw it: their stub assigned `window.firebridge = {…}`, which is exactly the shape production does NOT have.

## Fix
- One lookup, `fb()`: the bare global first (`typeof firebridge !== 'undefined' && firebridge`), `window.firebridge` only as a
  test-stub fallback; `db()` / `me()` / the profile read go through it, and `db()` throws a readable message if the bridge is missing.
- The canvas harnesses become production-shaped: after the stub, `const firebridge = window.firebridge; delete window.firebridge;`
  so any code that reads `window.firebridge` fails in the harness as it fails live. Proved by serving the old module through request
  interception: v3856 stops at 0/4; with the fix every canvas harness is green at its previous count.
