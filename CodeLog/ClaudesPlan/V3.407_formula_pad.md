# V3.407 — Click-built formula pad: no free-typed equations

## Context

Alex: on the math (equation) node, users must not write the equation.
The formula should read in dimension aliases — V1, L1, T1 … (V=volume,
L=length, …) — mapped to the variables ported in via wires; unitless
constants can be added directly on the calculator, but a constant WITH
a unit must come in as a wired Constant node. Variables and a row of
math operators are tapped in succession to build the function. Goal:
separate user input from the small mistakes that make building
frustrating.

## Design

### Storage unchanged — the pad is a lens
`params.expr` remains real-name mathjs text, so compile / doc view /
notebook / import / recipes / GELS are untouched. The pad tokenizes
expr for display and serializes clicks back to it. Formulas the
tokenizer can't represent (unknown functions, stray characters) render
read-only with **AC** as the way back — hand-typing is gone entirely
(the `field('expr')` text input and the per-row **↳ insert** buttons
are removed).

### Kernel (`rm/js/protocol-graph.js`) — pure + tested
- `DIMENSION_LETTERS`: volume V · length L · area A · mass M ·
  temperature T · time D (duration) · amount/conc C · ratio R ·
  unitless/other X.
- `equationAliases(graph, node)` → the node's wired math inputs in edge
  order, numbered per letter (`V1`, `X1`, `D1`, `V2`, …) with
  name/unit/category.
- `tokenizeExpr(expr)` → `{ok, tokens}` over identifiers, numbers,
  `+ - * / ^ ( ) ,` and a known-function list (sqrt/abs/round/min/max/
  floor/ceil/log/exp — accepted so existing exprs stay editable; the
  pad itself only OFFERS √). `serializeTokens` is the inverse
  (× ↔ *, ÷ ↔ /; unary-minus spacing normalizes and is idempotent).
- `fpadNextAllowed(tokens)` → `{operand, operator, close, complete}` —
  the click grammar. After an operand: operators/close only. After an
  operator/open/√: operands only. Close needs an open group. Syntax
  errors are therefore UNCLICKABLE.

### Editor (`rm/js/protocol-graph-editor.js`)
`_formulaPad(n, body)` replaces `field('expr', 'Formula')`:
- **Expression strip** — the current formula as chips in alias form
  (variable chips carry the dimension color + a name/unit tooltip;
  names not wired in render as dashed "loose" chips but keep working).
- **Variable buttons** — one per wired math input: big alias (V1) over
  the small real name + unit. Greyed unless an operand is legal.
- **Number slot** — a small `123` input + ↵ appends a unitless literal
  (tooltip: "a constant WITH a unit belongs in a 📌 Constant node,
  wired in" — which is naturally true: typed numbers are unitless by
  construction).
- **Operator pad** — `( ) + − × ÷ ^ √( ⌫ AC`; each button enabled only
  when the grammar allows it (− also at operand position for
  negation). ⌫ removes the last token; AC clears. An unfinished
  formula shows "… unfinished — needs a value / a closing )".
- The bound-variable rows now show the pad alias (`V1`) instead of the
  removed ↳ insert button; every click persists + recompiles (attrs
  map change — no remount).

### Tours
- Lesson 1 "Write the formula" → **"Build the formula"**: tap V1 → × →
  X1; why explains aliases-from-wires, the 123 slot, and wired
  Constants for united values.
- The exploratory equation tour's typing step rewritten the same way.
  Conditions unchanged (they check expr content, which the pad writes
  identically).
