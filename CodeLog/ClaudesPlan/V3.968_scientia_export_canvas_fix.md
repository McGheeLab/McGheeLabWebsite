# V3.968 — Scientia: Export canvas (HTML) works again

**Date:** 2026-11-10 · **Branch:** `scientia/export-term-nests` · **Gabe:** "Export HTML stopped working."

## What was wrong

`CANVASX.export` (21b) builds the file from the app's own page and strips the lab's layer with three patterns. The first,
for the desktop build's `<!--sis-desktop-->` … `<!--/sis-desktop-->` blocks, was a regex literal **written with a whole
opening marker in it**. That literal is part of the app's script, so in the page's text it is itself an opening marker.
Its closing half is escaped (`<!--\/sis-desktop-->`), so it never closes there. Since V3.929 the desktop build ends with a
second marked block (the lab layer inline, after the app). The non-greedy match therefore ran from 21b's own line to that
last marker and cut out everything between: the rest of the app, the viewer (98) and the boot (99). The file downloaded,
the toast said "Canvas exported", and the file opened blank with no error.

The web build had a smaller gap: its flag line has carried `SIS_BOARD_V` since V3.937, so the second pattern
(`<script>window.SIS_TARGET = 'web';</script>`) no longer matched and the export kept the lab's target flag.

## What changed

| File | Change |
|---|---|
| `scientia/src/21b-canvasexport.js` | The markers and the flag are built from pieces (`'<!--sis-' + 'desktop-->'`), as the third pattern already did for `cloud-sync`, so the app's own text never matches. The flag pattern takes any line that starts `<script>window.SIS_TARGET = 'web';`. A check before the download: the file must still hold the viewer and the boot and no marker or flag, otherwise a toast says so and nothing is saved. |

## Tests
