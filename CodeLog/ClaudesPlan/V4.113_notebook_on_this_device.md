# V4.113 — Scientia: the lab notebook kept on a device (offline), syncing back to the lab cloud

## Why
Gabe, 24 Nov: "Look into the most straightforward way to have the lab notebook loaded locally onto a device with sync back to the lab cloud. Research ways of doing it, and let's add it to the settings."

## The ways looked at
| Way | What it takes | Verdict |
|---|---|---|
| **The website build, installed** (Home Screen / Install app) | a manifest, the site's service worker registered from the notebook, its files kept, storage the browser keeps | **chosen**: every device, no app store, and it reuses what is there |
| The Ourlab mobile app (Capacitor, bundles `rm/`) | a TestFlight build per change; Firebase web sign-in is unreliable in WKWebView (native Google sign-in plugin needed) | more work, iPhone only, on Alex's release cycle |
| The desktop app (`23c-thiscomputer.js`, the Windows download) | exists already | computers only, not the iPad |
| Local-first sync libraries (RxDB, PouchDB, Yjs) | replace the app's own outbox and merge | a rewrite with no gain here |

**What the research found** (sources in the PR):
- **Storage:**
  - an iPad Home Screen app keeps storage of its own, separate from Safari's, and has its own 7-day counter, so an app in use is not cleared (WebKit);
  - Safari 17+ grants `navigator.storage.persist()` mostly to installed apps;
  - the quota is a share of the disk.
- **Sign-in:**
  - a page outside the manifest's `scope` opens in a browser sheet, so the site's sign-in must stay inside the scope;
  - Google sign-in (popup or redirect) inside an installed iPad app is unconfirmed, while email and password works.
- **The service worker:** the root `/sw.js` can control `/rm/scientia/` when the notebook registers it.
- **Sync:** Safari has no Background Sync, so the outbox goes on open, `online` and coming back to the app, which the app already does (13zc).

## Where things stood
- **Sync already worked offline:** the website build is a device of the lab cloud (the lab layer), with the app's outbox (13zc).
- **No manifest:** the page linked `manifest.webmanifest`, which did not exist, so Chrome could not offer Install.
- **No service worker from the notebook:** the lab layer switches off the app's own, so the page opened offline only after a visit to the main site, and never in an iPad Home Screen app (separate storage).
- **Caches emptied on update:** the site's worker empties its caches with each new version.
- **Storage not kept:** Settings already said "IndexedDB · evictable".

## What changed
- **`src/13zob-offline.js` (`OFFLINE`)** keeps the notebook on this device:
  - it registers the site's worker (`/sw.js`, scope `/`; on a device of your computer, the computer's);
  - it keeps the notebook's own files in the worker's current cache: the page, what it loaded from its folder, the whiteboard, the manifest, the icons, and the Firebase sign-in scripts from gstatic, without which an offline launch would open signed out;
  - it does this again whenever a new worker takes over (`controllerchange`) and on `online`;
  - it asks for `navigator.storage.persist()`;
  - opened from its icon (installed), it keeps itself (*Keep it when installed*);
  - Stop keeping it takes the page and whiteboard out of the cache; the notes stay.
- **Settings → Notebook & devices → Devices:**
  - a card shows opens offline, kept by the browser, installed, signed in, the lab cloud (in step / offline with N changes waiting), and space used;
  - one button, *Keep it on this device*; then *Refresh its files* and *Stop keeping it*;
  - how to install on this device;
  - the older install card steps aside.
- **The install banner's words on the lab site:** "works offline; what you write goes to the lab cloud" (13zo), not "with the computer off".
- **Settings → Features:** a new group, *This device & sync*, holding *The notebook on this device* (`offline`), with *Keep it on this device* (this device only) and *Keep it when installed*, and a preview.
- **`scripts/scientia_build.py`** writes `rm/scientia/manifest.webmanifest`:
  - `id /rm/scientia/`, `start_url` the notebook, `scope /` so the site's own sign-in stays inside the installed app, standalone, the icons;
  - it lives in the build, not in the app's files, so the lab's paths stay out of Gabe's own repo.
- **`MANUAL.md`** §21: The notebook on this device (offline).

## Not done, and why
- **Pictures and PDFs from other devices offline:** the site's worker leaves Firebase Storage to the network (`sw.js`, V3.583), and caching it would change the site's worker for every page.
- **An in-app sign-in on the iPad:** the lab layer's sign-in card sends people to the site, which `scope /` keeps inside the app. A code-based sign-in would need a new Cloud Function.
- **Not tried on an iPad here.** The test runs the website build end to end in Chrome, against the local stand-in hub.
