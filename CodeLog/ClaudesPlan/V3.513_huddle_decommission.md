# V3.513 — Huddle R5: decommission legacy tabs + purge button

## Goal

Final release of the Huddle UX program (R1–R4 = V3.504/508/509/511). Delete
the dead 11-tab-era code kept through R2 for diff reviewability, and give the
admin a purge button for rundown originals already migrated in R3.

## What shipped

1. **Dead code deleted from [rm/js/huddle.js](../../rm/js/huddle.js)**
   (~476 lines): `renderPlanFeed`/`wirePlanFeed`, `renderMyPlans`/
   `wireMyPlans`, `renderHelpFeed`/`wireHelpFeed`, `renderMyHelp`/
   `wireMyHelp`, `renderRundownFeed`/`wireRundownFeed`/`renderRundownCard`,
   `renderAddRundown`/`wireAddRundown`, `renderMyTasks`/`wireMyTasks`,
   `wireFilters`, `getUniqueMembers`, `createRundownTask`, 8 unused icon
   functions, and the `_editingTaskId`/`_filterRundownCategory` state.
   **Kept** (still load-bearing for This Week / legacy cards):
   `renderMyDaily`/`renderMyWeekly`/`renderMyMonthly` + wires,
   `updateRundownTask`/`deleteRundownTask`/`requestJoinTask`/
   `respondToJoinRequest`, `showJoinTaskModal`/`showScheduleFromRundownModal`.
   File header rewritten to describe the 4-tab architecture.
2. **Dead CSS pruned from [rm/css/huddle.css](../../rm/css/huddle.css)**
   (13 rules): the filter-panel family (`.hud-filters`, `.hud-filter-toggle/
   -panel/-count/-clear/-group/-label` — `.hud-filter-check` stays, the
   composer and settings use it), `.hud-rundown-filters`, `.hud-rd-join-btn`,
   `.hud-mytask-card`.
3. **Admin purge button** (Huddle → Settings → Legacy Rundown Migration):
   deletes `huddleRundown` docs stamped `migratedTo` (batched 400/commit);
   unmigrated tasks are never touched.

## Flagged follow-up (deliberately NOT shipped)

**Rules tightening** — restricting non-owner `huddlePlans`/
`huddleHelpRequests` updates to
`affectedKeys().hasOnly(['watchers','joiners','joinRequests','responses','updatedAt'])`
(owner/admin keep full update). Every current write path was traced and
complies (sign-up/unsign → watchers/joiners; join request → joinRequests;
responses/accept → responses; scheduling/status → owner-only), but it must
be verified in a real browser pass against both accounts before its own
`firebase deploy --only firestore:rules`. Do it as a small standalone
release after the program's browser verification.

FTP only (rm/js/huddle.js, rm/css/huddle.css, sw.js).
