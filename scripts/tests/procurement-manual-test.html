Procurement Test Run

Two people walk two purchase requests through every step: asking, approving, changing the funding, ordering, receiving, putting away, and requesting again. Each slip says who acts, what to press, and what each of you should see. Mark every slip Pass, Fail or Blocked. Marks save in this browser, so keep one copy open as the scorecard. Plan on about an hour.

Alex

The PI, signed in as admin. Approves, asks questions, changes the funding, places the orders and cleans up afterwards.

Tester

Any lab member who is not an admin and has no procurement rights. Files the requests, answers, receives and puts away.

Read before you start

  • Start every item name with [TEST]. Those tickets are real records, and the prefix makes them easy to find and delete at the end.
  • A push is silenced while the person it is for has the Procurement page in front of them, on any device. Before the other person acts, the one waiting for the buzz switches to another tab or locks their phone.
  • Every notice also lands in My Week → Notifications. It keeps only the latest unread notice per ticket, so a later step can replace an earlier one there.
  • Nobody is notified about their own action. Alex is both approver and purchaser, so Alex never gets "Ready to order" after approving.
  • The phone app keeps the old Procurement page until the next app build. Run the tests in a web browser. Pushes still reach the phone.
  • The web site uploads itself at the end of each Claude turn now, so the page you test is always the latest. Only the phone build and the announcement wait for a batch.
  • When a slip fails, write what you saw in its note. At the end press Download results and give the file to Claude to fix what failed.
Marks save in this browser as you press them.
